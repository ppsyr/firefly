## 提示词

```
# 开发任务：`/cd` 切换目录并创建新会话

你是这个 Python Agent 项目的开发 Agent。请先阅读实际代码，在已完成的 thread 持久化、项目目录绑定和 sandbox 控制基础上，实现 `/cd <目录>`。沿用现有项目注册、会话创建和 runtime 切换流程，不要求采用指定文件或类结构。

## 一、核心语义

**`/cd` = 将当前工作范围切到目标目录，并立即创建一个绑定该目录的新 thread。**

执行 `/cd /path/to/project-b` 后：

- 原 thread 保留原 `thread_id`、`cwd`、历史消息和 checkpoint，不搬迁、不删除。
- 创建新的 `thread_id`，立即保存元数据；新 thread 的 `cwd` 为目标目录，并归属该目录对应的项目。
- 当前会话切换到新 thread。新会话没有旧会话的对话历史或 `/add-dir` 追加目录。
- sandbox 随新 thread 的 `cwd` 更新。之后的文件工具和 `@` 引用以新会话的权限为准。
- 使用现有 `/thread switch <旧 ID>` 返回旧会话时，恢复旧会话的历史、项目、`cwd`、追加目录及 sandbox 边界。

即使目标与当前 `cwd` 是同一真实目录，`/cd` 仍创建新 thread；它不是在原 thread 上修改 `cwd`。

## 二、目录与项目规则

- 目标必须是存在且可访问的目录；将 `~`、相对路径和符号链接按项目现有规则解析为规范化的绝对路径。相对路径应以**当前 thread 的 `cwd`** 为基准，而非启动时的进程目录。
- 复用已经注册到该真实目录的项目。新目录尚无项目时，沿用 `--dir` 的默认项目命名规则创建项目；若名称与另一个目录冲突，清楚报错，保持当前会话不变。不要悄悄覆盖原项目绑定。
- 不调用 `os.chdir()`。此处的“工作目录”是当前 thread 的逻辑 `cwd`，不是进程全局状态。
- 旧的无 `cwd` thread 无法作为相对路径的基准；此时要求 `/cd` 使用绝对路径，不为旧 thread 补写绑定。

## 三、切换与失败处理

先校验目标目录及项目关系，再准备新 thread 和对应 runtime/sandbox，最后切换当前会话。任一步失败，都应保持原 thread、历史和 sandbox 可用，并妥善处理这次失败产生的新资源或不完整记录。

新旧会话的 checkpoint、运行日志和产物继续写入各自原有的 session 目录。切换时正确释放不再使用的 runtime 资源，避免旧 sandbox 或尚在运行的任务继续以错误权限处理新会话请求。

现有 `/thread switch` 若允许从项目 B 切回项目 A 的 thread，必须依据**目标 thread 的元数据**同步恢复项目和 sandbox；不能保留当前项目的目录或权限。

## 四、范围边界

本任务只实现“换目录并开新会话”。不在原 thread 上修改 `cwd`，不移动历史数据，不复制消息、checkpoint 或追加目录，不更改项目名称，也不扩大文件权限。CLI/TUI 如共用命令处理链路，应表现一致；补齐 `/cd` 的帮助与适用的路径补全。

## 五、验证流程

使用临时 `storage_root` 和至少两个临时项目目录，先跑针对性及受影响测试，再跑全量测试。至少覆盖：

1. 从 A 执行 `/cd B`：产生新 ID；旧 thread 仍绑定 A；新 thread 绑定 B、历史为空；项目索引分别正确。
2. 在 B 的文件可访问、A 的文件被 sandbox 拒绝；`@文件` 只按 B 的允许目录解析，B 的新 thread 不继承 A 的 `/add-dir`。
3. `/thread switch <旧 ID>` 后恢复 A 的历史、追加目录和权限；再次切回 B 也恢复 B 的状态。独立进程重启后同样成立。
4. 相对路径、`~`、符号链接、同目录再次 `/cd`、不存在的目录、普通文件路径及项目名称冲突。
5. 目录或 runtime 初始化失败时，当前 thread 和 sandbox 不变，不留下可误恢复的半成品会话。
6. CLI 实际执行一次 A → B → 旧 thread 的流程；检查 TUI 对同一命令的基本行为。

完成后报告 `/cd` 的路径解析规则、项目复用规则、失败回退方式、测试命令与结果，并区分新增失败和已有全量测试失败。
```
