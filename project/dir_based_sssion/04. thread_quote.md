## 提示词

```
# 开发任务：同目录会话引用 `@thread-id`

你是这个 Python Agent 项目的开发 Agent。请先阅读实际代码，在已完成的 thread 持久化、项目目录绑定和 `@文件` 引用能力上，实现**引用同一目录下其他 thread 的对话历史**。以实际代码为准，不要求采用指定文件或类结构。

## 一、目标

用户在消息中输入 `@thread-<id>`、`@<thread-id>`，或引用已有的会话标题时，把目标 thread 的历史对话作为参考材料加入**本轮上下文**。当前 thread 不发生切换，目标 thread 也不被修改。

例如，用户在当前会话输入：


`@thread-abc123 继续分析之前讨论的方案`


Agent 应能看到被引用会话中符合条件的历史消息，并回答后面的原始问题。

## 二、功能要求

### 引用与匹配

- ID 引用按现有 thread ID 格式匹配；标题引用使用已保存的会话标题，包括自动生成或手动修改的标题，**不为本功能重新生成摘要或标题**。
- 设计明确的多词标题输入方式，例如带引号的 `@"会话标题"`。与现有 `@文件`、`@目录` 解析规则协同，避免把普通邮箱地址或代码中的 `@` 误识别为引用。
- 标题重名、短 ID 多命中，或标题与文件名冲突时，不得随意选一个。使用现有选择器让用户确认，或明确提示使用完整 ID；非交互终端列出可区分的候选。
- 未找到、目标已删除、历史不可读取或用户取消选择时，给出提示，不注入错误会话的内容。

### 同目录限制

- 只允许引用**其他**且 `cwd` 与当前 thread 相同的会话。比较规范化后的真实目录路径，不能仅比较项目名或路径字符串。
- 不同项目名若指向同一真实目录，按同目录处理；项目名相同但目录不同，不得互相引用。
- 当前或目标 thread 缺少 `cwd` 时拒绝引用，不把旧会话自动绑定到当前目录，也不退回使用进程 `Path.cwd()`。
- 查找候选、展示列表和读取历史时都执行同目录检查，避免通过标题或错误信息暴露其他目录的会话内容。

### 历史提取与上下文

- 从目标 thread **最新已提交的 checkpoint** 读取历史，沿用现有会话目录和 checkpointer；不要通过 `switch_thread` 获取历史，也不要改变当前 runtime。
- 只提取 user 和 assistant 的文本消息，保持原顺序及角色标识。排除 system、tool、工具调用参数与结果，以及非文本内容；确认实际消息类型和 checkpoint 结构后实现过滤。
- 设置可测试的上限，例如最近 **10 轮、最多 4,000 token**。超出时优先保留最近对话，并标注历史已截断。若项目已有摘要或 token 预算机制，优先复用；不要为了此功能额外引入 LLM 摘要调用。
- 将引用内容标明来源 thread 和标题，作为**本轮参考上下文**接入现有 `context_engineering` 预算流程。保留用户原始问题；引用历史不参与当前 thread 的标题生成，也不应在后续轮次重复自动注入。

## 三、实施边界

保持现有 session 目录、checkpoint、项目索引和会话元数据布局。不新增跨目录引用、跨 thread 写入、会话合并、自动总结、长期记忆同步或新的权限命令。CLI/TUI 若共用消息处理链路，应共用解析、同目录校验和历史提取逻辑；交互选择沿用现有组件。

## 四、验证流程

先用临时 `storage_root` 和多个临时项目目录编写针对性测试，再运行受影响测试及全量测试。至少覆盖：

1. **正常引用**：完整 ID、受支持的短 ID、多词标题；注入内容包含 user/assistant 文本且顺序正确，当前 thread ID 和目标 checkpoint 均不变。
2. **隔离**：同目录不同项目名可引用；同项目名不同目录、符号链接或相似前缀目录不能绕过校验；无 `cwd` 的旧 thread 被拒绝。
3. **过滤与预算**：system、tool、工具调用和非文本内容不进入上下文；长历史只保留预算内的最近对话，并明确标注截断。
4. **歧义与失败**：重名标题、同名文件、无命中、已删除会话、损坏 checkpoint、交互取消及非交互终端均有确定行为，不误注入内容。
5. **实际流程**：跨进程重启后引用同目录旧会话；检查现有 `@文件` 引用、thread 切换及 CLI/TUI 不回归。

完成后报告引用语法、歧义处理方式、历史截断规则、测试命令与结果，以及未能覆盖的场景。
```
