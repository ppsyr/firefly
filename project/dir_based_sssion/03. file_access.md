# 功能：文件访问权限（sandbox）+ `@目录` / `@文件名` 引用

## 本部分实现的功能（一览）

> **本部分 = "让会话只能访问绑定 thread 的 dir（+ 追加目录）下的文件 + 用 `@目录` / `@文件名` 把文件塞进本轮上下文"**。
>
> **实现了**：
> 1. **sandbox 根 = `thread.cwd`** —— 从"隐式 `Path.cwd()`"改为"显式绑定 thread 的 dir"；
> 2. **`@目录` 引用** —— 把该目录下文本文件清单塞进本轮上下文；
> 3. **`@文件名` 引用** —— 在 `dir`（+ 追加目录）下搜索同名文件，命中后通过下栏选择；
> 4. **下栏文件选择器** —— `↑`/`↓` 选择，回车确认，`Esc` 取消（复用 `thread_picker` 模式）；
> 5. **路径越界拒绝** —— 必须在 `thread.cwd`（或 `/add-dir` 追加目录）下，不允许 `../` 穿越；
> 6. **大小 / 类型约束** —— 单文件 ≤ 100KB；二进制拒绝；`@目录` 展开总量受限；
> 7. **注入到本轮消息** —— 走现有 `context_engineering` 预算 / 截断；
> 8. **`AppRuntime.thread_cwd`** —— 作为 sandbox 根的来源。
>
> **不做**：
> - ❌ 文件写入（`@` 只读；写走工具）—— 另开；
> - ❌ 文件实时监听（引用一次，不追变）；
> - ❌ 多模态（图片 / 音视频注入）；
> - ❌ 跨 cwd 引用；
> - ❌ 模糊搜索 / 分页 / 多选（多命中只做单选）；
> - ❌ 跨进程会话恢复（功能 1 已覆盖）；
> - ❌ `/add-dir` / `/cd` 本身（消费其产物，不重造）。

## 提示词

```
开发任务：基于 Thread 目录的文件访问控制与 @ 引用
你是这个 Python Agent 项目的开发 Agent。先阅读实际代码，再实施。项目已经完成 thread 持久化与项目目录绑定；请以当前实现为准，不沿用旧版“全局 thread 元数据和共享 checkpoint 数据库”的设计，也不必照下面的功能描述创建指定文件或类。
一、现有基础
- 每个 thread 的元数据、checkpoint、事件和运行产物存放在按创建日期分层的独立 session 目录。恢复 thread 时沿用原目录。
- 新 thread 创建时已在元数据中记录 project 和规范化后的绝对路径 cwd；旧的未绑定 thread 仍可通过全局 /thread 恢复。
- --dir 目前只记录项目绑定，不会改变进程当前目录或 sandbox 行为。
- CLI 和 TUI 已有 thread、项目选择交互。项目 thread 索引是派生数据，不是权限来源。
二、目标与验收行为
本部分完成两件事：让文件访问范围跟随当前 thread 的 cwd，以及让用户用 @文件、@目录 引用项目内容到本轮对话。
1. 从目录 B 启动 poirot --dir A，当前 thread 的文件工具可以访问 A 内文件，不能因进程仍位于 B 就访问 B。重启并恢复该 thread 后，边界仍是 A。
2. 新建、切换 thread 或项目时，文件访问边界随目标 thread 更新。切换失败时，原 thread、runtime 和权限保持有效。旧的无 cwd thread 不得被悄悄绑定到启动目录；需要文件访问时给出明确提示。
3. 输入 @main.py 帮我看看，单一命中文件的文本内容进入本轮上下文；输入 src/main.py 时按指定相对路径查找。保留用户原问题，不让文件正文参与 thread 标题生成。
4. 仅给文件名且有多个同名文件时，下栏展示能区分来源的路径，支持上下键、回车确认、Esc 取消；非交互终端列出候选，不擅自选择。未命中、取消或读取失败均有清楚反馈。
5. 输入 @src 看看这个目录，注入目录中的文本文件清单（相对路径、大小），不批量注入文件正文。清单有条数、文本大小和遍历工作量上限，超限时提示。
6. @ 引用与实际文件工具都遵守同一访问边界。../、越界绝对路径、相似目录名前缀和指向外部的符号链接均不能绕过限制。
7. 单文件上限 100 KiB；二进制、无法解码和超限文件不注入。文件内容作为带来源信息的引用材料，经过现有 context_engineering 的预算与截断流程。
三、实现边界
- 权限来源是当前 thread 的绑定信息，不能用项目名称、项目索引或进程 Path.cwd() 推断权限。读取文件前基于真实路径判断归属，不能只做字符串前缀匹配；读取时也要限制字节量。
- 覆盖现有的读取、写入文件工具及其他实际文件入口。@ 本身只读，不新增写文件功能。检查 sandbox 对 shell、子进程等入口能提供什么保障；若不能限制其文件访问，不要把路径校验描述成完整进程隔离，应在结果中说明。
- 文件和目录按实际类型识别，不能靠“是否有扩展名”区分。明确 @ 解析规则，避免把普通邮箱地址、代码中的 @ 当作引用；带路径引用按用户指定路径解析，仅文件名引用才搜索同名项。
- 有多个允许目录时，当前 thread.cwd 优先。本任务不实现 /add-dir：若代码中已有会话级追加目录授权，就让工具和 @ 共用该授权，并确保不会串到其他 thread；若没有，就只允许 thread.cwd。
- 引用在当前轮读取一次，不做实时监听，也不在后续轮次自动重新注入。不得通过错误信息、候选列表或目录清单泄露允许范围之外的路径和内容。
- 保持现有 session 目录、checkpoint、项目注册表及索引布局。不做 @thread-id、/cd、多模态、模糊搜索、分页、多选或项目级 prompt。
四、建议实施顺序
1. 梳理访问链路：找到 sandbox 的根目录来源、实际文件工具入口、runtime 的 thread 切换流程，以及 CLI/TUI 将用户消息交给 graph 和 context_engineering 的位置。先确认哪些操作能被现有 sandbox 约束。
2. 绑定权限边界：让 sandbox 从当前 thread 的 cwd 获取允许根；处理新建、恢复、切换、失败回退和旧 thread 无绑定的情况。优先完成这一部分并测试，避免 @ 功能先于权限边界开放。
3. 实现引用解析与读取：支持单文件、明确路径、大小与类型限制、越界拒绝，并把引用材料接入现有上下文预算。CLI/TUI 尽量共用解析和安全逻辑。
4. 补齐交互：实现多命中文件选择器及非交互行为，再实现有上限、结果顺序稳定的目录清单。沿用项目中已有的下栏选择方式。
5. 回归检查：确认引用失败不会发送错误文件内容，切换 thread 后不会沿用上一 thread 的文件候选或权限。
五、测试流程
使用临时项目目录和临时 storage_root，至少覆盖：
- 权限与恢复：从 B 启动并绑定 A；A 内读写成功、B 内读写拒绝；两个项目的 thread 来回切换；失败切换保持原权限；独立进程重启后恢复原 cwd；旧无绑定 thread 不获得隐式权限。
- 路径安全：../、绝对路径、同名前缀目录、符号链接指向范围外、目录遍历中遇到外部链接。分别从 @ 和实际文件工具入口验证。
- 文件引用：单命中、多命中、无命中、无扩展名文件、非 UTF 文本或解码失败、二进制、恰好 100 KiB 与超出 100 KiB、读取过程中失败；确认原问题和来源信息进入本轮上下文，且预算生效。
- 交互与目录：方向键、回车、Esc、非交互候选输出；目录清单排序、二进制跳过、条数及大小上限；普通文本中的 @ 不误触发。
- 现有功能：thread 新建、恢复、切换，项目切换，CLI/TUI，以及存储布局不回退。
先运行新增和受影响测试，再运行全量测试；记录具体命令与结果，并将新增失败同已知的全量测试失败区分。手工验证至少包含一次 CLI 文件选择和一次 TUI 基本流程；未执行的验证如实说明。
完成后报告实际权限覆盖到哪些入口、@ 内容如何进入上下文、测试结果，以及仍无法由现有 sandbox 保证的访问场景。
```
