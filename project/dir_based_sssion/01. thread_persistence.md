# 功能：thread 持久化（state + 元数据 + 标题 + `/thread` 完整命令族）

## 本部分实现的功能（一览）

> **本部分 = "让 thread 能跨进程存活 + 有可读标题 + 能列出 + 能交互选择 + 能管理（新建/删除/重命名）"**。
>
> **实现了**：
> 1. **state 持久化** —— `InMemorySaver` → `SqliteSaver`；
> 2. **thread 元数据持久化** —— `user/.poirot/threads/{thread_id}.json`，持久化到user文件夹下，而不是项目文件夹；
> 3. **标题自动生成** —— `{时间}-{标题名}`（第一句对话截断 60 字，不调 LLM），放在thread的参数中；
> 4. **`/thread list` 交互选择** —— 下栏近 10 条，`↑`/`↓` 选择，回车恢复，`Esc` 取消，10 条后继续向下，加载更久远的；
> 5. **`/thread new`** —— 新建 thread（新 UUID `thread_id`，重建 runtime）；
> 6. **`/thread delete <id>`** —— 删除 thread（元数据 + checkpointer state）；
> 7. **`/thread rename <title>`** —— 重命名当前 thread（改 `title`）；
> 8. **`AppRuntime.switch_thread(thread_id)`** —— 重建 runtime，state 恢复。
>
> **不做**：
> - ❌ "thread 绑定 dir"（`cwd` 字段）—— 另开；
> - ❌ "按 cwd 过滤"—— 另开；
> - ❌ `@文件` / `@thread-id` / `/add-dir` / `/cd`—— 另开；
> - ❌ 项目级 prompt；
> - ❌ LLM 生成标题；
> - ❌ 模糊搜索 / 分页 / 多选。

## 3. 存储与元数据规则

### 3.1 State

- 默认数据库为 `~/.poirot/checkpoints.db`，自动创建父目录；不得落在项目目录或随当前工作目录变化。
- 使用当前框架版本支持的 SQLite checkpointer。若项目使用 LangGraph 异步 graph，核查并优先使用兼容的异步 saver，例如 `AsyncSqliteSaver`；不要仅凭名称把 `InMemorySaver` 替换为同步 `SqliteSaver`。
- 核查所需依赖并更新项目依赖声明及项目已有的锁文件，不使用不存在的 saver API。
- 保留完整的框架 checkpoint，包括持久化所需的状态、版本和 pending writes。不要自建聊天记录表来替代 checkpoint。
- 连接必须覆盖 graph 使用期间，并在正常退出、初始化失败和必要的重建路径上正确释放。切换会话不能误关闭仍被其他对象使用的共享连接。
- 存储位置可通过项目已有配置机制覆盖，便于测试和部署。不要另造一套配置框架。
- 保存失败必须明确暴露，不能静默降级到内存后声称持久化成功。

### 3.2 元数据

- 默认位置为 `~/.poirot/threads/{thread_id}.json`，与 checkpoint 属于同一用户级存储配置。
- 四个必需字段必须稳定持久化；必要时可增加少量内部字段，例如自动标题是否已生成，不引入本次范围外的数据。
- 时间存储为带时区的 ISO 8601，建议统一 UTC；界面按本地时区展示。
- `created_at` 创建后不变。`updated_at` 在新建、重命名、开始新一轮对话及该轮结束时更新；失败但已经产生持久化状态的对话也记录活动。列出、查看、选择和单纯切换不修改时间。
- 列表按 `updated_at` 降序排序，同时间使用稳定的次级排序。
- JSON 使用临时文件加原子替换，读取与写入保持线程安全。不要在异步事件循环中持有阻塞锁跨越 `await`。
- 一条损坏元数据不能导致全部会话无法列出；给出可诊断提示，保留损坏文件，不擅自覆盖或删除。
- 校验 thread ID，拒绝路径穿越和非法文件名。新会话用 UUID；已有 ID 的兼容范围根据实际代码确定，不任意破坏已有合法 ID。

### 3.3 标题

- 新会话立即写入元数据，使用可识别的临时标题，例如 `YYYY-MM-DD HH:mm 新会话`，因此空会话也能列出和管理。
- 首次真正提交给 Agent 的非空用户消息生成自动标题，格式统一为 `YYYY-MM-DD HH:mm 标题名`。时间使用会话创建时间的本地展示值。
- 将消息中的换行和连续空白压成单个空格，标题名截取前 60 个 Unicode 字符；时间前缀不计入 60 字，不调用 LLM。
- 管理命令、空输入和系统提示不作为首句。自动标题只生成一次。
- 用户手动重命名后，完整标题使用用户输入，不强加时间前缀；后续对话不能覆盖。即使用户在首句前重命名，也必须保留。
- 拒绝空白标题，清理会破坏终端显示的控制字符，正常保留中文和空格。

## 4. 用户操作与 Runtime 行为

### 4.1 命令契约

| 命令                     | 必须实现的行为                                               |
| ------------------------ | ------------------------------------------------------------ |
| `/thread`                | 显示当前会话 ID 和标题。                                     |
| `/thread info`           | 显示当前会话的完整 ID、标题、创建时间、更新时间。            |
| `/thread list`           | 打开下栏选择器，按最近活动排序显示会话。                     |
| `/thread new`            | 创建新 UUID 和元数据，切换到没有历史 state 的新会话。        |
| `/thread switch <id>`    | 按完整 ID 切换到已有会话并恢复 checkpoint；不存在时报错，不隐式创建。 |
| `/thread rename <title>` | 重命名当前会话，支持含空格的完整标题。                       |
| `/thread delete <id>`    | 删除指定会话的元数据及其全部 checkpoint、相关 pending writes。 |

参数缺失、未知子命令和多余参数应给出明确错误及正确用法。`rename` 的命令后剩余内容按标题解析，不要求用户为普通含空格标题加引号。补全至少覆盖上述子命令。

本次明确以下默认行为，避免实施时留下未定项：

- 保持现有程序启动时的会话选择策略，不新增“自动打开最近会话”设置。保留已有启动指定 thread ID 的能力；若存在这种入口，应恢复对应 state。
- 切换到当前会话是无副作用操作。
- 删除当前会话时拒绝操作，提示先执行 `/thread new` 或切换到其他会话；不隐式删除后再建新会话。
- 未知 ID 不改变当前 runtime。重复删除已不存在的 ID 返回清晰提示，不抛出未处理异常。
- 有运行中的对话时，拒绝新建、切换、重命名以及删除正在运行的会话，提示等待完成或使用已有取消功能；本次不新增取消流程。
- 不为已明确指定的非当前、非运行中会话删除增加强制确认弹窗。

### 4.2 交互选择器

- 使用现有 CLI 交互技术；若已采用 `prompt_toolkit`，优先沿用其非全屏模式，并与异步主循环及 `patch_stdout` 兼容。
- 首次显示最近 10 条；使用 `↑`、`↓` 移动，回车选择并恢复，`Esc` 取消。
- 向下到末尾时继续加载更早的会话，保持可见区域有界。这属于滚动加载，不需要页码、翻页命令、搜索或多选。
- 显示标题及足以辨认的 ID，标识当前会话。标题过长或终端较窄时合理截断，不破坏布局。
- 取消后保持当前会话不变；空列表、单条、超过 10 条、到达首尾都必须正常处理。
- 列表返回的是完整 thread ID；选中后再次校验会话仍存在。不得因为短 ID 展示而产生匹配歧义。
- 选择器关闭后，正常输入、补全和流式输出继续工作；在非交互终端中提供可读列表，并提示用 `switch <id>`，不要挂起等待按键。

### 4.3 切换与失败处理

- 使用目标 thread ID 获取其 state，不复制源 thread 的历史，也不向恢复后的 graph 再追加已经保存的历史消息。
- 对正常对话历史，沿用现有展示机制，让用户能确认恢复了哪个会话；至少明确显示恢复后的标题和 ID。
- 若 runtime 必须重建，先成功创建目标运行上下文，再替换当前引用。失败时原会话仍可使用。
- 刷新 CLI 持有的相关 runtime、服务和状态引用，避免界面显示新 thread、实际调用仍使用旧 thread。
- 按已有边界隔离会话级状态；新的会话不继承旧会话的消息、待处理工具调用、todo 等会话数据。用户级长期记忆遵循现有语义。
- 只重建或重新绑定必要对象；不要求无条件重启所有 MCP 服务、沙箱和后台 worker。
- 对 SQLite 与 JSON 的跨存储操作明确处理部分失败。删除先清除数据库中的目标 thread 数据，再移除元数据；数据库删除失败时保留元数据。元数据删除失败时报告“删除未完成”，支持再次执行删除完成清理，不能报告完整成功。
- 元数据创建失败时不继续提交 Agent 对话；不得制造对用户不可见的新历史会话。后续元数据更新失败应明确报告实际状态。
- 元数据存在但尚无 checkpoint 的新会话可以正常恢复为空会话；已有数据反序列化失败时保留原数据并报错，不能用空 state 覆盖。
- 不删除历史 journal、report、artifact、长期记忆或共享缓存，本次删除范围只包含 thread 元数据和 checkpoint 数据。

## 6. 测试流程与验收

全部自动化测试使用临时存储目录和独立数据库，不能读写开发者真实的 `~/.poirot`。默认路径用注入或 mock 验证。采用项目已有测试框架和运行命令。

### 6.1 元数据与命令单元测试

- 新建元数据、四个必需字段、时间格式及目录自动创建。
- 中英文、多行、连续空白、超过 60 字的首句标题；只生成一次。
- 首句前后手动重命名均不被后续对话覆盖；含空格标题、空白标题和控制字符处理。
- `created_at` 稳定，活动更新 `updated_at`，只读和切换不更新时间；排序稳定。
- 损坏 JSON 不影响正常记录；写入失败不把旧文件截断成半份 JSON。
- 全部子命令的正确参数、缺参、未知命令、非法 ID 和补全结果。
- 当前会话删除保护、运行中操作保护、不存在的目标处理。

### 6.2 Checkpointer 与 Runtime 集成测试

使用真实 SQLite saver 和当前框架的最小 graph，配合确定性模型或工具替身。不要把 saver mock 掉，不依赖付费模型、网络、Docker 或外部 Agent。

- Thread A 连续两轮产生 state，切到 B 后为空，再切回 A 恢复原 state。
- A、B 的消息及代表性的会话级字段互不串用；恢复后追加一次输入没有重复历史。
- 元数据存在但无 checkpoint 的空会话可用。
- 切换初始化失败时原 runtime 仍可继续对话，CLI 调用引用保持一致。
- 删除非当前 thread 后，使用 saver 公共 API 确認无 checkpoint，并检查该版本相关 checkpoint/pending-write 存储中无残留；另一 thread 不受影响。
- 数据库删除失败、元数据删除失败及重试清理的行为符合契约。
- 正常退出、初始化失败和多次切换后连接能正确清理，无重复关闭或使用已关闭连接的问题。
- 不支持或损坏的序列化数据能明确报错且不被覆盖。

### 6.3 真正的跨进程测试：必须通过

同一 Python 进程里重新创建 saver 不算跨进程验收。测试至少启动两个独立子进程，使用同一临时存储路径：

1. 进程 A 创建固定 thread，执行一轮最小 graph，保存用户输入、确定性输出和一个可断言的 state 字段，然后正常退出。
2. 进程 B 重新装配 runtime/saver，用同一 ID 读取 state；断言上述消息和字段均存在。
3. 进程 B 继续执行下一轮，断言历史未重复、状态正确累积、标题未重建、`created_at` 未改变。
4. 可在后续独立进程验证另一会话的隔离及删除后无法再恢复目标 checkpoint。

至少一次通过实际应用装配入口验证持久化，不能只验证 SQLite 库本身。若完整应用需要外部服务，注入替身并说明测试覆盖了哪些实际装配环节。

### 6.4 CLI 交互验证

能自动化的按键行为使用项目现有交互测试工具或 `prompt_toolkit` 的测试输入机制；涉及终端渲染的部分实际运行 CLI 验证：

- 0、1、10、11 条及更多会话，按时间排序，向下加载能选到第 11 条以后。
- 上下边界、回车恢复、`Esc` 取消、当前会话标识。
- 中文长标题、窄终端、选择器退出后正常输入及补全。
- 选择期间目标已被删除时不会创建幽灵会话。
- 非交互输入不会卡住。
- 完整用户流程：对话 → 退出 → 重启 → `/thread list` → 恢复 → 继续对话 → 重命名 → 新建 → 删除旧会话 → 再次重启确认结果。
