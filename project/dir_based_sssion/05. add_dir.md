## 提示词

```
# 开发任务：`/add-dir` 追加会话引用目录

你是这个 Python Agent 项目的开发 Agent。请先阅读实际代码，在现有 thread 持久化、项目目录绑定及 `@文件` 引用功能上，实现会话级的追加引用目录。以当前架构为准，不要求采用指定文件或类名。

## 一、目标

用户执行 `/add-dir /path/to/lib` 后，**当前 thread** 的后续 `@文件` 引用可以在该目录中查找文件。可追加多个目录，并通过 `/add-dir --remove <目录>` 移除。

这是 `@` 引用的额外读取范围，**不改变 `thread.cwd`、项目绑定、进程工作目录或文件工具的 sandbox 权限**。原有 `@文件` 的大小、类型、安全校验和上下文预算继续生效。

## 二、功能要求

- `/add-dir <目录>`：校验目录存在且可访问，将其规范化为真实绝对路径后加入当前 thread。重复添加同一目录，包括通过符号链接添加，不产生重复项。
- `/add-dir --remove <目录>`：移除当前 thread 中对应的目录；未添加时给出明确提示（下拉栏来列出已经add的dir）。目录路径含空格时应支持符合现有 CLI 习惯的引用方式。
- `/add-dir` 不带参数时，显示当前 thread 已追加的目录，方便用户确认权限范围。
- **查找顺序**：对 `@文件名`，先搜索 `thread.cwd`；只有当前目录内无命中，才按添加顺序搜索追加目录。同一优先级有多个命中时，沿用现有文件选择器，不任意挑选。
- 带相对路径的 `@src/foo.py` 沿用相同的目录优先级。绝对路径引用只能落在 `thread.cwd` 或当前 thread 已追加的目录内。
- 添加目录时不读取或注入文件；之后每次 `@` 引用仍按实际文件状态读取。目录被移动、删除或失去访问权限时，引用给出提示，不悄悄扩大查找范围。
- 查找和读取都必须按真实路径检查归属。拒绝 `../` 穿越和指向允许目录之外的符号链接；不能用字符串前缀判断路径是否位于目录内。

## 三、会话作用域与存储

追加目录绑定 **thread ID**：新 thread 从空列表开始；切换 thread 或项目时使用目标 thread 自己的列表，不能继承上一会话的目录。既然 thread 支持跨进程恢复，追加目录也应随该 thread 保存并在恢复时生效；移除后恢复也不得重新出现。

沿用现有会话存储及原子写入方式，保持旧元数据可读取；旧 thread 没有追加目录字段时按空列表处理。不要修改已有 session 目录、checkpoint 或项目索引的布局。

## 四、范围边界

本任务只扩展 `@文件` 的**只读引用范围**。不让文件读取、写入、shell 等工具因 `/add-dir` 获得额外权限；不实现 `/cd`、跨会话共享目录、自动扫描并注入整个目录、实时监听或新的文件类型支持。若当前 `@目录` 已实现，可让它遵守同一查找范围与优先级，但仍使用原有清单上限。

CLI 和 TUI 如共用命令与引用链路，应使用同一份会话目录状态；补齐命令帮助及适用的补全。

## 五、验证流程

使用临时项目目录及临时 `storage_root`，先运行针对性和受影响测试，再运行全量测试。至少验证：

1. 未追加时找不到外部文件；追加后能引用；移除后再次拒绝。
2. `cwd` 和追加目录有同名文件时优先使用 `cwd`；多个追加目录命中时按添加顺序展示并由用户选择。
3. 多次添加、符号链接指向同一目录、路径含空格、无效目录、目录随后被删除，以及移除未添加目录的行为。
4. 两个 thread 来回切换、项目切换及两个独立进程恢复后，追加目录仅属于原 thread。
5. `../`、越界绝对路径和符号链接逃逸均被拒绝；`@` 的 100 KiB、二进制及上下文预算限制仍有效。
6. 追加目录内的文件可通过 `@` 引用，但文件工具的 sandbox 边界仍是原 `thread.cwd`。

实际检查一次 CLI 添加、引用和移除流程。完成后报告存储位置、查找优先级、测试命令与结果，以及未验证的交互流程。
```
