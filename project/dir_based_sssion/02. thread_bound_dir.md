# thread 绑定 dir

## 本部分实现的功能（一览）

> **本部分 = "在 thread 持久化基础上，加'项目'这一层，把 thread 绑定到项目目录"**。
>
> **实现了**：
> 1. **`cwd` / `project` 字段** —— thread 元数据加"项目目录"与"项目名"；
> 2. **`poirot --dir <目录>` 启动** —— 默认项目名 = 文件夹名；不传 `--dir` → 当前目录启项目；`--project_name <名>` 可覆盖；
在这个目录下新建的thread，就绑定在这个目录下；
> 3. **`/project list`** —— 下栏列近 N 个项目 + 上下键选择 + 回车切换；到底部继续按下加载更久远的；
> 4. **`/project_thread list`** —— 当前项目下的 thread 列表 + 上下键 + 回车恢复；
> 5. **`~/.poirot/sessions/{project}/threads.json`** —— 每个项目一份"thread 索引"。

/project delete <name> 
/project rename <old> <new>

>
> **不做**：
> - ❌ `@文件` / `@thread-id` / `/add-dir` / `/cd`（另开）；
> - ❌ 项目级 prompt（`AGENTS.md`）；
> - ❌ 沙箱根改造（本部分只"记录 `cwd`"，**不改 sandbox 行为**）；
> - ❌ 跨项目 thread 引用；
> - ❌ 项目删除 / 重命名。

2. 项目规则
项目由以下字段组成：
project：项目名称
cwd：规范化后的绝对目录
规则：
- --dir 默认使用启动时的 Path.cwd()。
- 相对路径相对于启动目录解析，并展开 ~。
- 目录必须存在且为目录。
- 符号链接指向同一目录时视为同一项目。
- 未指定项目名时使用目录名。
- 项目名不能包含路径分隔符、. 或 ..。
- 同一目录只能对应一个项目。
- 同名项目不能绑定不同目录。
- 显式名称与已有项目冲突时应报错，不得隐式重命名。
- 不得调用 os.chdir()；--dir 只用于项目绑定。
3. 存储
使用现有 storage_root 配置，默认仍为：
~/.poirot
项目元数据：
{storage_root}/projects/{project_name}.json
至少包含：
{
  "project_name": "demo",
  "dir": "/absolute/path",
  "created_at": "...",
  "updated_at": "..."
}
项目 thread 索引：
{storage_root}/sessions/{project_name}/threads.json
索引项至少包含：
{
  "thread_id": "...",
  "title": "...",
  "cwd": "/absolute/path",
  "updated_at": "..."
}
规则：
- 沿用现有 JSON 原子写入方式。
- 项目和 thread 列表按 updated_at 降序排列。
- 索引是派生数据，thread 的 metadata.json 是权威数据。
- 索引缺失或损坏时，应能从 thread 元数据重建。
- 不移动现有 session 目录。
- 不把旧共享 checkpoint 或旧日志迁移到新项目目录。
4. Thread 绑定
现有 session 目录保持不变：
{storage_root}/sessions/{year}/{month}/{day}/
└── thread-{HH-MM-SS}-{thread_id}/
    ├── metadata.json
    ├── checkpoints.db
    ├── thread-events.jsonl
    └── runs/
thread 元数据增加：
{
  "project": "demo",
  "cwd": "/absolute/path"
}
规则：
- 新 thread 创建时立即写入 project 和 cwd。
- /thread new 使用当前项目。
- 项目切换后创建的新 thread 使用目标项目。
- thread 重命名、恢复和后续对话不能改变绑定。
- 旧 thread 缺少这两个字段时视为“未绑定项目”。
- 旧 thread 可继续通过全局 /thread 管理，但不出现在 /project_thread list。
- 每次创建、重命名、更新时间变化和删除都同步更新项目索引。
- RunRecord 或等效运行记录保存本次运行的 project 和 cwd。
5. Runtime 与命令
启动
启动时：
1. 解析并校验项目目录和项目名。
2. 创建或加载项目元数据。
3. 创建绑定当前项目的新 thread。
4. 保留现有 checkpointer、runtime 和生命周期行为。
/project list
- 显示最近 10 个项目。
- 支持 ↑、↓、回车和 Esc。
- 到达底部时继续加载更久远的项目。
- 回车后切换项目。
- 空列表、超过 10 条、非交互终端都必须正常处理。
- 非交互终端输出项目名、目录和可用切换方式。
项目切换要求：
- 成功后 runtime 使用目标项目。
- 不自动恢复目标项目旧 thread。
- 推荐切换后创建一个新的目标项目 thread，历史 thread 使用 /project_thread list 恢复。
- 切换失败时当前项目和 runtime 保持不变。
- 不改变进程 cwd、sandbox 或输出目录。
/project_thread list
- 只显示当前项目的 thread。
- 按最近更新时间排序。
- 支持上下键、回车恢复和 Esc 取消。
- 到达底部时继续加载。
- 选中后恢复对应 checkpoint。
- 目标不存在、项目不匹配或恢复失败时，不改变当前 runtime。
- 不重复追加已保存的历史消息。
现有 /thread
保留现有 /thread 命令族和全局 thread 列表。
- /thread list 继续列出全局 thread。
- /project_thread list 只列当前项目。
- 已绑定 thread 通过全局 /thread switch 恢复时，应同步其项目上下文。
- 未绑定旧 thread 不得被自动绑定。
- 当前 thread 删除保护和运行中操作保护继续有效。
补全和帮助中加入：
/project list
/project_thread list
