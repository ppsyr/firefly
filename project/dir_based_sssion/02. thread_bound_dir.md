# 功能：thread 绑定 dir（项目 + 会话绑定目录）

## 0. 本部分实现的功能（一览）

> **本部分 = "在 thread 持久化基础上，加'项目'这一层，把 thread 绑定到项目目录"**。
>
> **实现了**：
> 1. **`cwd` / `project` 字段** —— thread 元数据加"项目目录"与"项目名"；
> 2. **`poirot --dir <目录>` 启动** —— 默认项目名 = 文件夹名；不传 `--dir` → 当前目录启项目；`--project_name <名>` 可覆盖；
在这个目录下新建的thread，就绑定在这个目录下；
> 3. **`/project list`** —— 下栏列近 N 个项目 + 上下键选择 + 回车切换；到底部继续按下加载更久远的；
> 4. **`/project_thread list`** —— 当前项目下的 thread 列表 + 上下键 + 回车恢复；
> 5. **`~/.poirot/sessions/{project}/threads.json`** —— 每个项目一份"thread 索引"。

/project delete <name> 
/project rename <old> <new>

>
> **不做**：
> - ❌ `@文件` / `@thread-id` / `/add-dir` / `/cd`（另开）；
> - ❌ 项目级 prompt（`AGENTS.md`）；
> - ❌ 沙箱根改造（本部分只"记录 `cwd`"，**不改 sandbox 行为**）；
> - ❌ 跨项目 thread 引用；
> - ❌ 项目删除 / 重命名。

---

## 1. 定义

### 是什么

在 thread 持久化之上，**引入"项目"这一层**：

- **项目 = 一个目录**（有名字：默认 = 文件夹名；可用 `--project_name` 覆盖）；
- **thread 绑定项目** —— thread 元数据加 `project`（项目名）+ `cwd`（项目目录）；
- **项目注册表** —— `~/.poirot/projects/{project}.json`；
- **per-project thread 索引** —— `~/.poirot/sessions/{project}/threads.json`；
- **CLI** —— `/project list`（切项目）+ `/project_thread list`（切 thread）。

### 为什么

- **多项目隔离** —— 不同项目的 thread 互不干扰；
- **按项目列会话** —— `/project_thread list` 只看当前项目的；
- **快速切换** —— `/project list` 下栏选择，像 Codex；
- **为后续 `@文件` / `@thread-id` / `/cd` 提供基础**。

### 成功标准

1. `poirot --dir /path/a` —— 启项目 `a`（默认名 = `a`）；
2. `poirot --dir /path/b --project_name my-proj` —— 启项目 `my-proj`；
3. `poirot`（无 `--dir`）—— 当前目录启项目；
4. `/project list` —— 下栏近 N 个，`↑`/`↓`/回车；
5. `/project_thread list` —— 当前项目 thread，`↑`/`↓`/回车；
6. `~/.poirot/sessions/{project}/threads.json` —— 有 thread 索引；
7. `~/.poirot/projects/{project}.json` —— 有项目元数据。

### 不做什么

- ❌ 不改 sandbox 的 `PathMapping`（沙箱根**仍是 `Path.cwd()`，隐式**）；
- ❌ 不改访问权限；
- ❌ 不改 `output_root` / `logs_root` / `thread_dir`；
- ❌ 不做 `@文件` / `@thread-id` / `/add-dir` / `/cd`；
- ❌ 不做项目级 prompt；
- ❌ 不做项目删除 / 重命名；
- ❌ 不做跨项目 thread 引用。

## 7. 完成情况

### 已完成功能

- 启动时可用 `--dir` 指定项目目录、用 `--project_name` 指定项目名；不传 `--dir` 时使用启动目录。目录会规范化为绝对路径，符号链接指向同一目录时复用项目，并校验目录和项目名冲突。
- 新 thread 的元数据立即写入 `project` 和 `cwd`。`/thread new` 使用当前项目；旧的未绑定 thread 仍能通过全局 `/thread` 恢复，不会被自动绑定。
- `/project list` 可选择项目，切换后创建该项目的新空 thread；`/project_thread list` 只列出并恢复当前项目的 thread。CLI 和 TUI 都支持上下键、回车、Esc，以及超过 10 项时继续滚动；非交互 CLI 直接打印列表。
- 项目元数据、项目 thread 索引和每次运行的 `project`、`cwd` 均已持久化。`--dir` 不改变进程当前目录或 sandbox 行为。

### 实现方式

- `runtime/projects.py` 负责项目注册、目录规范化与冲突校验，写入 `{storage_root}/projects/{project_name}.json`。
- `runtime/threads.py` 在原有 `{storage_root}/sessions/YYYY/MM/DD/thread-.../metadata.json` 中保存绑定信息，并在 thread 创建、更新、重命名和删除时同步 `{storage_root}/sessions/{project_name}/threads.json`。索引是派生数据，缺失或损坏时从 thread 元数据重建；原 session 目录和 checkpoint 布局不变。
- `app/bootstrap.py` 在启动时创建或加载项目，并由 `AppRuntime` 处理项目切换、项目内 thread 恢复及失败时保持原 runtime。CLI/TUI 的命令处理和选择器负责交互；`RunRecord` 保存本次运行的项目绑定。

### 验证

- 功能及受影响的 runtime、CLI、TUI、thread 持久化测试共 **83 项通过**。跨进程测试验证了两个项目的 thread 在重启后可分别恢复并继续对话，checkpoint 和历史消息没有串用。
- 全量测试最近一次结果为 **2739 通过、4 跳过、13 失败**；失败项涉及既有配置断言、环境依赖及平台相关测试，未计入上述通过结论。
