# 功能：SQLite FTS5 报告索引

## 本部分实现的功能（一览）

> **本部分 = "把已持久化的分层报告建成可重建、可定位来源的本地全文索引"。**

**前置功能已完成：**模块一的 `/report [标题]` 已将当前 thread 保存为用户级 `reports/YYYY/MM/DD/` 下的独立快照。每份报告包含来源元信息、L0 概览、L1 结构化及逐轮摘要、L2 `rag` 知识块，并配有仅含 user/assistant 文本的 L3 `conversation.jsonl`。export 模式的自动 `final_report.md` 仍按原逻辑保存在 run 目录。

**本部分实现：**

1. **报告解析**：从 Markdown 的结构化元信息和 L0/L1/L2 章节提取可检索内容，不误收普通代码围栏、日志或工具结果。
2. **本地索引**：使用 SQLite FTS5 索引报告标题、描述、概览、摘要和 `rag` 知识块；保留项目、真实 `cwd`、章节、层级等来源字段。
3. **中文和英文检索基础**：为中英文混合文本提供经过测试的匹配策略，同时保留文件名、配置键、thread ID 等精确词的可查性。
4. **增量更新**：新报告生成后可纳入索引；对同一报告重复建立索引不会产生重复命中。
5. **全量重建与核对**：索引损坏、删除或落后时可从 reports 目录重新生成，并清理不再存在的报告条目。
6. **内部查询接口**：按关键词取出有限数量的候选块与来源，支持项目/真实 `cwd` 过滤，为下一模块的 `/search` 提供基础。

**本部分不做：**

- `/search` 命令、问题意图分析、LLM 回答与逐层展开；
- Agent 原生 `search_reports` 工具或每轮自动检索；
- Embedding、向量数据库、混合排序；
- 把 L3 对话副本、完整 checkpoint、自动 export 报告或其他本地文件直接建入索引；
- 报告生成算法、报告存储布局和 thread/sandbox 行为改造。

## 数据边界

默认索引位置建议为 `{storage_root}/rag/index.sqlite`。`storage_root` 默认为当前用户的 `Path.home() / ".poirot"`，测试时沿用现有配置覆盖。数据库是**派生数据**；报告 Markdown 和与之配对的 `conversation.jsonl` 是本功能的持久化来源，索引丢失不得导致报告丢失。

每份报告可以产生多个检索块。最少保存以下可定位字段：

```text
report_id       同一报告快照的稳定标识；不能只用 thread_id
report_path     相对于 reports 根目录的路径
thread_id       来源 thread 的完整 ID
project         报告生成时的项目
cwd             报告生成时的真实目录；无绑定时保持空值
section         概览、决策、逐轮摘要等章节
level           L0 / L1 / L2
turn_start/end  有轮次时记录；没有时可为空
content_hash    检测报告内容变化和重复索引
created_at      报告生成时间
```

索引正文包括 `name`、`description`、L0、L1 和 `rag` 围栏中的 L2。一个 `rag` 围栏可以是一个独立块；长章节可按可读段落切分，但块必须保留章节和轮次来源。普通 `python`/`text` 等代码围栏不因位于报告中就进入 L2。L3 对话副本只作为后续深度读取的定位来源，不进入本阶段的全文索引。

同一 thread 多次 `/report` 会产生不同快照，应分别索引。报表路径和来源元信息不能从文件名猜测，须解析报告本身。报告路径、`conversation_location` 和 Markdown 中的链接均不能作为索引扫描的任意文件读取指令。

## 索引生命周期

1. **建立**：读取模块一生成的正式 Markdown，校验格式版本与必要来源字段，解析 L0/L1/L2，在一个 SQLite 事务中替换该报告的旧索引块。
2. **增量**：`/report` 保存成功后可以触发一次索引；若索引失败，报告仍然有效，返回或记录清楚的“报告已保存、索引失败”状态，不把报告生成误判为失败。
3. **重建**：扫描 `{storage_root}/reports` 下的正式报告文件，跳过临时文件、对话副本、损坏文件和不支持的版本，重建所有检索块。单份坏报告不阻断其他报告。
4. **核对**：报告被删除或移动后，重建或核对操作移除对应的旧索引。查询时也不应把已不存在或不再可读的报告作为可用结果返回。
5. **并发**：沿用项目已有 SQLite 生命周期和连接习惯；写入使用事务，避免中断后只写入半份报告的块。若已有多个进程读写同一用户级存储，使用 SQLite 的正常忙等待和事务语义，不另造跨进程锁协议。

索引不修改报告正文或对话副本。索引文件损坏时应给出可诊断错误，并允许从报告重建；不得静默改读完整 checkpoint、向量服务或真实用户项目文件。

## 查询接口的边界

模块二提供**内部**查询能力，便于测试索引质量和供模块三复用，但不注册 `/search`：

- 输入关键词和可选的项目、真实 `cwd` 过滤条件，输出有上限的候选块、分数及完整来源字段。
- 过滤条件在查询层明确应用，不能把 `project`/`cwd` 填入 FTS 正文后靠关键词匹配充当范围控制。
- 对不存在、空白或包含 FTS 特殊语法的普通用户输入，给出稳定结果或输入错误，不暴露 SQLite 语法异常；除非显式设计高级搜索，不把用户文本直接作为可信 FTS 表达式。
- `cwd` 相等按规范化真实路径判断；旧报告无 `cwd` 时不自动归入当前目录。
- 排序结果稳定，能区分同一报告的不同章节，也能去除完全重复的块。
- 查询只返回资料，不调用 LLM，不决定摘要是否足够，也不读取 `conversation.jsonl`。

中文不能只靠默认 FTS5 tokenizer 的假设完成验收。实施时先确认当前 Python/SQLite 是否支持合适的 tokenizer；若默认分词无法满足固定中文样本，可在应用层加入一致的中文 2-gram/3-gram 检索字段或项目已有分词能力，同时保留原文供展示与英文精确查询。不要为了通过测试硬编码样本词。

# 开发任务：为分层 Thread 报告建立 SQLite FTS5 索引

你是这个 Python Agent 项目的开发 Agent。请先阅读实际代码，再直接实现并验证模块二，不要只提交方案。下文描述功能和验收行为，不指定必须创建的文件或类名；沿用项目现有配置、存储和测试习惯。

## 已完成的模块一

`/report [标题]` 已能生成当前 thread 的用户级报告快照，默认存于 `{storage_root}/reports/YYYY/MM/DD/`。报告 Markdown 包含 `name`、`description`、thread ID、project、cwd、生成时间和原 session 等来源信息，以及 L0 概览、L1 结构化/逐轮摘要、L2 `rag` 知识块。相邻的 `conversation.jsonl` 仅保存 user/assistant 文本作为 L3 深度来源。原 checkpoint 仍保存完整状态；export 自动报告仍按原逻辑写入 run 的 `final_report.md`。

以实际落盘格式和源码为准核对这些事实。模块二只消费和索引已保存的报告，不重写模块一，也不把对话副本或 checkpoint 当作首层索引语料。

## 目标与范围

实现可重建的本地 SQLite FTS5 报告索引。索引应支持关键词查询、报告/章节/层级定位、项目和真实 cwd 过滤，并为后续 `/search` 提供稳定的内部接口。索引库建议位于 `{storage_root}/rag/index.sqlite`，默认仍属于当前用户的 `~/.poirot`，不能落在项目目录。

必须交付：

- 根据报告格式版本解析 frontmatter/等价元信息和 L0/L1/L2 章节；
- 将标题、描述、概览、摘要、明确的 `rag` 围栏转成有来源的检索块；
- SQLite FTS5 表和结构化元数据存储；
- 新报告增量索引、重复索引去重、全量重建与失效条目清理；
- 有界的内部关键词查询，接受项目/cwd 过滤并返回来源和分数；
- 中英文混合检索的实际测试及可靠的失败处理。

不实现 `/search` 命令、意图分析、LLM 回答、L3 深度展开、Agent 工具、Embedding、向量数据库或本地文件知识源。不改变 `/report` 的内容生成算法、export 自动报告、checkpoint、thread、项目和 sandbox 的行为。

## 开始前核查

简要确认并继续开发：

1. 实际报告文件的 Markdown/frontmatter 格式、章节名称、`rag` 围栏和 `schema_version`；
2. 报告保存的成功返回路径及能否在成功后挂接索引更新；
3. `storage_root`、时区、路径规范化和 SQLite 生命周期的现有实现；
4. Python 随附 SQLite 是否支持 FTS5，以及当前构建对中文 tokenizer 的支持；
5. 项目已有的 Markdown/YAML/JSON 解析依赖和测试夹具。

优先使用已有结构化解析能力。不要以全文件正则替代 Markdown/frontmatter 解析；如项目没有合适解析器，用最小、可测试的解析方式处理本项目确定的报告格式，并明确支持的版本。

## 索引数据契约

- 只扫描 `{storage_root}/reports` 下正式生成的 `.md` 报告。排除临时文件、`conversation.jsonl`、其他 Markdown、自动 export 的 `final_report.md` 和目录外符号链接。
- 从报告正文提取 L0、L1 和明确标记为 `rag` 的 L2。普通代码块和日志不作为 L2；不能因为文本中有三个反引号就自动索引所有内容。
- 报告可以切成多个检索块。每块至少记录报告稳定 ID、相对报告路径、thread ID、project、规范化 `cwd`、章节、层级、可选轮次、内容 hash 和报告时间。
- 同一个 thread 的多次报告是不同快照，不按 thread ID 覆盖旧报告。相同报告重复索引不增加命中条数；报告内容变化时只替换该报告的旧块。
- project/cwd 存为结构化字段，供后续范围过滤。无 cwd 的旧报告保持无绑定状态，不默认归入当前 cwd。
- 索引是可再生的派生数据；损坏或删除数据库不能损失报告和对话副本。

## 建立、重建与查询

- `/report` 两份文件成功落盘后再触发索引。若索引失败，保留报告，给出可诊断状态，并允许以后重试或重建；不要报告“报告保存失败”。
- 索引一个报告时，解析和校验在事务提交前完成；替换旧块及元数据作为一个事务完成，异常不能留下半份报告索引。
- 提供全量重建或核对入口，能从报告目录恢复索引并清理已不存在报告的旧条目。具体入口可用项目已有管理方式或内部维护 API；本阶段不新增 `/search` 命令。
- 损坏报告、缺失字段、不支持格式版本或不可读文件应被跳过并报告具体路径及原因；单份文件不阻断其他报告。
- 内部查询接受普通用户关键词和可选项目/cwd 过滤，返回有限数量的候选块和来源。FTS 特殊字符、空查询和无命中不能抛出未处理的 SQLite 异常。
- 报告已被删除、移动或变得不可读时，候选不得作为可用内容继续传给后续模块；索引清理与查询校验的分工要明确。
- 排序结果在分数相同时有稳定次序；不要把 FTS 排名分数误当作“答案置信度”。

## 中文检索

先用固定的中文、英文和中英混合样本验证实际 SQLite 行为。测试至少包含完整中文词、中文词出现在长句中、英文技术词、文件名/配置键及混合查询。若默认 tokenizer 对中文词边界无效，应采用可复现的分词或 n-gram 辅助索引，并让写入和查询使用同一规范化规则。保留原文用于展示和准确来源；不要只存经过切词的文本。

本阶段不追求语义同义词匹配；这是后续 Embedding 的评估范围。不要引入付费 API、网络服务或向量数据库来补 FTS5 的中文问题。

## 测试与验收

所有测试使用临时 `storage_root` 和临时项目目录，不读写开发者真实 `~/.poirot`。先运行索引解析与查询测试，再运行受影响的 `/report`、runtime、CLI、报告与 SQLite 测试，最后执行项目要求的全量测试。记录新增失败和既有失败。

至少覆盖：

1. 一份报告的 name/description、L0、L1、多个 L2 分别能命中，返回正确报告、章节和层级；普通代码块、日志、L3、tool/system 内容不能进入首层索引。
2. 同一 thread 的两份报告分别存在；同一报告重复索引不重复；内容变化后旧块被替换。
3. 中文、英文、中英混合查询和精确标识符查询；FTS 特殊字符、空查询、无命中和排序稳定性。
4. 项目与规范化 cwd 过滤：相似前缀目录、同名目录、符号链接指向同一目录、缺失 cwd 和跨项目报告不能错误匹配。
5. 缺失字段、未知 schema、损坏 Markdown、不可读报告及报告目录外符号链接被安全跳过；一份坏报告不影响其他报告。
6. 报告保存成功而索引失败、事务中断、数据库损坏/删除、全量重建及删除报告后的陈旧条目清理。
7. 两个独立进程：进程 A 通过真实 `/report` 路径写入报告并建索引，进程 B 用同一临时 storage root 查询；删除索引库后由报告重建，结果仍正确。
8. 自动 export 报告仍只写原 run artifact，不被索引；现有 thread checkpoint 和对话副本文件没有被索引流程修改。

验收时直接检查返回的块内容、来源和过滤结果，不能只用“数据库文件存在”证明可检索。最终说明索引库路径、中文方案、增量/重建行为、测试命令与结果，以及保留给 `/search` 和 Agent 工具的接口。
