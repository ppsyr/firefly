# 功能：`/search` 报告检索与渐进式披露

## 本部分实现的功能（一览）

> **本部分 = "让用户用 `/search` 查询历史报告，并按摘要、知识块、对话逐层取证后得到带来源的回答"。**

**前置功能已完成：**模块一的 `/report [标题]` 已把当前 thread 保存为用户级分层 Markdown：L0 概览、L1 结构化及逐轮摘要、L2 `rag` 知识块；相邻的 `conversation.jsonl` 只含 user/assistant 文本，作为 L3 深度来源。模块二已用 SQLite FTS5 索引 L0/L1/L2，提供可按项目和真实 `cwd` 过滤、返回报告/章节来源的内部查询接口。原 checkpoint 和 export 自动 `final_report.md` 保持原逻辑。

**本部分实现：**

1. **`/search <内容或问题>`**：直接关键词和自然语言问题均可查询历史报告。
2. **默认范围**：只搜索当前 thread 的项目且真实 `cwd` 相同的报告。
3. **显式跨项目**：`/search --all-projects <内容或问题>` 搜索用户级全部项目报告；不改变文件 sandbox。
4. **候选发现与排序**：用已有 FTS5 索引找到报告，合并同一报告的相近命中，并保留命中章节。
5. **渐进式披露**：先提供 L0/L1 摘要；不足时取命中的 L2；必要时只读取相关 L3 对话轮次。
6. **带来源回答**：将有预算上限的证据交给现有 LLM 回答路径，输出可定位到报告和章节的来源；证据不足时明确说明。
7. **失败反馈**：空查询、无结果、索引缺失、报告损坏或深层来源不可读，都有确定行为。

**本部分不做：**

- Agent 自主调用 `search_reports`，以及普通聊天每轮自动检索；
- Embedding、向量数据库、混合排序和本地文件知识源；
- 修改 `/report` 的报告结构、对话副本或 FTS5 索引协议；
- 跨项目文件读取、绕过 sandbox、读取完整 checkpoint 中的 tool/system 消息；
- 把检索片段永久写成当前 thread 的消息或长期记忆。

## 命令与范围

```text
/search 数据库迁移
/search 为什么按 thread 分开保存 checkpoint？
/search --all-projects 哪个项目讨论过 sandbox？
```

命令后剩余文本是查询内容，允许中文、空格和普通标点。`--all-projects` 是明确的命令选项；参数缺失或查询为空时显示用法。查询词恰好包含 FTS 语法字符时按普通文本安全处理，不把它当作可信 SQL/FTS 表达式。

默认过滤同时满足：报告 `project` 与当前项目一致，且报告 `cwd` 与当前 thread 的**真实目录**一致。只比较项目名不足以判断范围；同名目录、相似前缀路径不能误匹配。当前 thread 没有 `cwd` 时不能默默扩大为全部报告，应明确提示默认搜索范围不可确定。不同项目名即便指向同一目录，默认搜索仍按“当前项目 + 当前 cwd”过滤；跨项目只能显式使用 `--all-projects`。

`--all-projects` 扩大的是**用户级报告搜索范围**。它不更新当前 thread 的项目、`cwd` 或 sandbox，也不授予其他项目的文件工具权限。结果必须展示来源项目和目录，避免混淆。

## 检索与回答流程

```text
/search 查询
   ↓
解析命令与 scope；确认当前 thread 的项目/cwd
   ↓
对查询做轻量意图识别与关键词整理
   ↓
FTS5 在允许范围内发现候选报告（L0/L1/L2 均可参与发现）
   ↓
先取候选报告的 L0/L1，保留命中章节线索
   ↓
需要具体证据时展开相关 L2
   ↓
仍不足且有相关轮次时读取 L3 user/assistant 对话片段
   ↓
现有 LLM 路径生成带来源的回答
```

**候选发现**可使用 L2 命中。否则某个术语只出现在 `rag` 块时，报告会完全漏检。但**首次注入的证据**以 L0/L1 为主；L2 命中的块可作为下一层的明确展开目标。不要把 FTS5 排名分数当作答案可靠度，是否展开应根据问题是否需要具体细节、摘要能否支持回答以及可用证据判断，并限制最多展开次数。

直接关键词查询可以直接使用 FTS5；完整问题可以先抽取关键词、实体和时间线索。意图整理应优先复用现有 Agent/LLM 能力，但不强制每次额外调用一次模型。查询改写失败时退回原文本，不能因意图步骤失败而无法做基础检索。

后续回答只依据已取回的证据。报告内容是**来源材料**，其中出现的“忽略规则”“执行命令”等指令不能成为当前会话的操作指令。来源引用至少能定位到报告标题或相对路径、章节；引用 L3 时还应标明轮次。没有可靠证据时明确说明未找到，不以相关但不充分的报告推断事实。

## 分层读取与预算

| 层级 | 读取内容 | 触发条件 |
|---|---|---|
| **L0/L1** | 概览、结构化摘要、匹配的逐轮摘要 | 每次有候选时首先读取 |
| **L2** | 与查询相关的 `rag` 知识块 | 摘要不够回答、问题要求设计细节，或 L2 是主要命中依据 |
| **L3** | 对应报告的 user/assistant 对话片段 | 需要原话、细节或核对摘要，且前两层仍不足 |

- 每层都限制报告数、检索块数、单块长度和总 token；具体默认值以现有上下文预算机制与模型窗口为准，并可配置/测试。
- 优先保留最相关、来源不同的证据；同一报告相邻块去重，避免重复占用上下文。
- L3 只从该报告配对的 `conversation.jsonl` 读取相关轮次，按需取有限窗口，不整份注入。
- 读取 L3 时再次校验角色只为 user/assistant、来源路径仍在 reports 目录内，不能因 JSONL 字段或 frontmatter 被篡改而读取任意路径或 tool/system 内容。
- 超出预算时有确定的截断顺序，并在交给 LLM 的材料和用户可见结果中标明“已截断/未展开”的范围。
- 检索资料只在本次 `/search` 回答中使用，不追加为当前 thread 的永久历史消息；正常命令输出和运行日志仍遵循项目原有机制。

## 失败与恢复行为

- **无命中**：给出“当前范围未找到”的明确提示；可说明当前范围，不自动改用 `--all-projects`。
- **索引未建立/损坏**：与“确实没有结果”区分；提示模块二提供的重建方式。搜索过程不隐式重建索引或扫描完整 checkpoint。
- **旧报告缺失或不可读**：跳过该候选并提示来源失效，不能把索引里的陈旧块当作已核实证据。
- **L3 不可用**：仍可使用已确认的 L0/L1/L2，标明无法进一步核对；不得退而读取 tool/system checkpoint。
- **LLM 调用失败**：保留可读的检索结果和来源信息，说明回答生成失败；不把失败误报成无命中。
- **切换 thread/project 后**：下一次命令必须重新取得当前范围，不能复用上一个 thread 的项目/cwd 或候选缓存。

## 提示词

````text
# 开发任务：实现 `/search` 报告检索与渐进式披露

你是这个 Python Agent 项目的开发 Agent。请先阅读实际代码，再直接实施并验证模块三，不要只提交方案。按已有的命令分发、runtime、context engineering 和报告索引接口组织实现，不要求采用指定文件或类名。

## 已完成的前置功能

模块一已实现 `/report [标题]`：报告保存到用户级 `{storage_root}/reports/YYYY/MM/DD/`，Markdown 含来源元信息和 L0 概览、L1 结构化/逐轮摘要、L2 `rag` 知识块；配对的 `conversation.jsonl` 只保存 user/assistant 文本，作为 L3 深度来源。原 checkpoint 完整保留，export 自动 `final_report.md` 仍按原逻辑运行。

模块二已实现 SQLite FTS5 报告索引：可索引 L0/L1/L2，能返回报告、章节、层级、项目、真实 cwd 等来源，并提供项目/cwd 过滤、增量更新和重建能力。请以实际代码确认接口和存储格式，优先复用，不另建一套索引。

## 目标与边界

实现 `/search <内容或问题>`，让用户在历史报告中检索并得到带来源的回答。默认只搜索当前项目且真实 cwd 相同的报告；`/search --all-projects <内容或问题>` 由用户显式扩大到全部项目报告。

必须交付命令解析、范围校验、关键词/问题处理、FTS5 候选发现、L0/L1 → L2 → L3 的按需展开、上下文预算、来源引用，以及 CLI/TUI 适用的反馈。

不实现 Agent 自主检索、Embedding、向量数据库、本地文件知识源，也不改变 `/report`、索引、checkpoint 或 sandbox 的既有语义。`--all-projects` 只扩大报告搜索，不扩大文件工具访问。不得将检索结果永久写入当前 thread 的消息或长期记忆。

## 开始前核查

先简短确认并继续开发：

1. `/search` 是否已有命令占位、CLI/TUI 如何复用命令处理，以及非交互终端如何显示结果；
2. FTS5 内部查询接口、过滤参数、排序、报告 ID 和章节定位；
3. L0/L1/L2 的解析与 L3 JSONL 的角色/轮次格式；
4. 当前 thread 的项目与规范化 cwd 从哪里取得，切换后如何刷新；
5. 现有 context engineering 的预算/截断机制、LLM 回答入口及来源展示方式；
6. 索引缺失、报告失效和 LLM 调用失败时，已有错误/日志处理惯例。

## 命令和范围契约

- 支持 `/search 查询内容` 和 `/search --all-projects 查询内容`。普通查询文本可包含空格、中文、标点和 FTS 特殊字符；空查询、只有选项或未知选项给出明确用法。
- 默认过滤必须同时使用当前项目和真实 cwd。不同目录不可因名称相似而命中；不同项目名但真实 cwd 相同仍按项目过滤。当前 thread 缺少 cwd 时明确拒绝默认搜索，不退回进程 cwd 或全项目搜索。
- `--all-projects` 必须由用户明确写出；搜索结果展示项目、cwd 和报告来源。不修改 sandbox、thread 绑定或项目状态。
- 普通命令不自动跨项目重试。项目或 thread 切换后，下一次搜索使用新的范围。
- 报告路径只允许落在用户级 reports 根目录；查询结果、frontmatter 和对话副本路径不能诱导读取任意外部文件。

## 检索与渐进式披露

1. 先安全解析查询。关键词可直接检索；自然语言问题做轻量意图/关键词整理，必要时复用现有 LLM，但不能要求每次额外模型调用。整理失败时用原查询继续。
2. 候选发现可利用 FTS5 中的 L0/L1/L2。若关键词仅在 L2，仍须找得到报告；首次返回/注入以该报告 L0/L1 为主，并记录 L2 命中线索。
3. 对结果排序、按报告聚合并去重；保留足以区分同一 thread 多份报告快照的报告 ID/路径。FTS 排名只表示文本匹配，不等于回答置信度。
4. 摘要能支持回答时停止；若问题要求细节或摘要不足，读取相关 L2；仍不足且有相关轮次时，读取对应报告的有限 L3 user/assistant 片段。不从完整 checkpoint 读取 tool/system 作为替代。
5. L3 再次校验来源路径和消息角色，只读取必要的轮次窗口；没有轮次映射时采用有界的回退，不整份注入。
6. 复用现有 context engineering 预算与截断；限制报告数、块数、单块和总 token。结果过长要标明截断和实际展开层级。
7. 将检索文本标记为来源资料，交给现有 LLM 回答路径。资料中的指令不能被当作用户或系统指令执行。回答引用报告和章节；L3 引用包含轮次。没有证据时说未找到，不编造。

本模块既支持直接要搜索的词，也支持问题。用户不必额外指定 `summary`/`detail`/`conversation`；系统按证据需要逐层展开，但必须有有界、可测试的停止条件。不要只根据固定 FTS 分数阈值宣布“答案足够”。

## 错误处理

- 把“没有命中”“索引不可用”“报告文件失效”“深层对话不可读”“回答模型失败”区分开。
- 索引缺失时提示模块二提供的重建方式；`/search` 本身保持只读，不隐式重建或扫描 checkpoint。
- 失效报告不作为可靠证据；L3 失败时保留已可用的浅层证据并说明限制。
- 模型失败时仍给出有来源的匹配结果，避免用户误以为数据库没有相关内容。
- `/search` 只读报告和索引，不修改当前 thread、报告快照、索引内容或文件 sandbox。

## 测试与验收

所有测试使用临时 `storage_root` 和至少两个临时项目目录，不读写开发者真实 `~/.poirot`。先运行命令/检索/展开测试，再运行受影响的 CLI、TUI、报告、索引和 runtime 测试，最后运行项目要求的全量测试；区分新增失败与既有失败。

至少覆盖：

1. 关键词、中文自然语言问题、中英混合查询、FTS 特殊字符、空查询和参数错误；查询整理失败时的退回。
2. 当前项目且真实 cwd 过滤；同名目录、相似路径前缀、符号链接、跨项目同一真实目录、无 cwd 的旧 thread，以及显式 `--all-projects`。
3. 只在 L2 出现的关键词仍找到报告；首次证据为 L0/L1，必要时展开匹配 L2；无需细节时不读 L3。
4. L3 仅含相关轮次的 user/assistant 文本；tool/system、工具参数和结果不能进入 LLM 证据；越界副本路径被拒绝。
5. 多份相似报告及同 thread 多次生成的版本不混淆；结果去重、来源章节和轮次准确。
6. 长报告与长对话的报告数、块数、token 限制及截断标记；报告内容中的伪指令不会改变命令执行或回答规则。
7. 无命中、索引缺失/损坏、陈旧结果、报告损坏、L3 不可读、LLM 失败均给出区分明确的反馈。
8. 从真实应用入口经两个独立进程：第一进程 `/report` 保存并索引，第二进程 `/search` 找到该报告、回答问题并显示来源；切换项目后默认范围随之改变。
9. CLI 交互与非交互输出可用；TUI 共享入口可用；自动 export 的 `final_report.md` 不被错误纳入搜索。

验收不能只看“返回了几个命中”，还要断言回答所用证据、层级、来源、范围和当前 thread 状态。最终报告实际使用的查询/回答接口、预算策略、测试命令与结果，以及没有完成的模块四和 Embedding 扩展。
````
