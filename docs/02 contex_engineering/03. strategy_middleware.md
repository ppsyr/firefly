---

name: StrategyMiddleware — 接入 adapter，把 6 个 hook 路由到 GovernanceStrategy bundle。

description:

【整体职责】
用一个 AgentMiddleware 持有一个策略 bundle 实例，把 LangChain 暴露的 6 类 hook（before_agent / after_agent / before_model / after_model / wrap_model_call / wrap_tool_call）统一路由到 bundle 上对应的方法。  

【两类 hook 的语义差异】
1) state-channel hooks（before_agent / after_agent / before_model / after_model）
- 返回 dict（state_patch），由 apply_governance_result 应用到 state。
- 可携带 metrics / jump_to 等治理结果。
- before_model / after_model 标了 @hook_config(can_jump_to=["model"])，
允许治理结果跳回 model 节点。
  
2) wrap hooks（wrap_model_call / wrap_tool_call）
- 作为 adapter 包住 handler，只消费 GovernanceResult.request_override。
- wrap hook 不适合写 state_patch / metrics：因为 wrap 必须返回
ModelCallResult / ToolMessage，没有 state 通道；状态写入交给 before/after hook 完成。
- wrap_model_call = PRE：bundle 先改 request，再交给 handler。
- wrap_tool_call = POST：先让 handler 拿到 tool result，再让 bundle 改 result。

【ctx 构造】
每次 hook 调用都会构造一个 GovernanceContext，把 state、governance、 config、token_counter、runtime、hook 名以及 hook 特定参数一并传入， bundle 侧据此做治理决策。

# StrategyMiddleware 总结（结合 DefaultStrategy 实际实现优化）

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 方法）

```
StrategyMiddleware — 接入 adapter，路由 6 hook 到 GovernanceStrategy bundle
│
└─ class StrategyMiddleware(AgentMiddleware)
    ├─ state_schema = ThreadState
    │
    ├─ __init__(bundle, config=None)              ← 持有 bundle + config
    │   └─ config 实际是 config.params（策略参数 dict），
    │      由 DefaultStrategy.__init__ 消费（thresholds / externalize_dir /
    │      preserve_recent / snapshot_dir 等）
    │
    ├─ _ctx(state, runtime, hook, **hook_specific)  ← 构造 GovernanceContext
    │   └─ 注入：state / governance / config / token_counter / runtime / hook
    │      hook-specific：messages / tools / model_request /
    │                     tool_call_request / tool_result
    │
    ├─ 【state-channel hooks：返回 dict，apply_governance_result】──────────
    │   ├─ before_agent(state, runtime)           ← DefaultStrategy.before_agent
    │   │   └─ budget.init_budget → state_patch.governance
    │   ├─ abefore_agent(state, runtime)          ← 同上（复用同步）
    │   ├─ after_agent(state, runtime)            ← DefaultStrategy.after_agent
    │   │   └─ budget.clear_run_state → state_patch.governance
    │   ├─ aafter_agent(state, runtime)           ← 同上（复用同步）
    │   ├─ before_model(state, runtime)           ← @hook_config(can_jump_to=["model"])
    │   │   └─ DefaultStrategy.before_model
    │   │       ├─ _ensure_pairing → messages_patch
    │   │       ├─ P3 分支 → state_patch.governance（p3_obs_limit）
    │   │       ├─ P4 分支 → snapshot + summarize → messages_patch + state_patch
    │   │       └─ P1 分支 → externalize_history → messages_patch + state_patch
    │   ├─ abefore_model(state, runtime)          ← 同上（复用同步）
    │   ├─ after_model(state, runtime)            ← @hook_config(can_jump_to=["model"])
    │   │   └─ DefaultStrategy.after_model
    │   │       ├─ budget.track → state_patch.governance
    │   │       ├─ _mark_thinking → messages_patch
    │   │       └─ P5 分支 → _strip_tool_calls + stop_msg +
    │   │                     jump_to="model" + state_patch.governance
    │   └─ aafter_model(state, runtime)           ← 同上（复用同步）
    │
    └─ 【wrap hooks：adapter 包 handler，仅消费 request_override】──────────
        ├─ wrap_model_call(request, handler)      ← PRE：bundle 改 request → handler
        │   └─ DefaultStrategy.wrap_model_call = no-op（返空 GovernanceResult）
        ├─ awrap_model_call(request, handler)     ← 同上（no-op）
        ├─ wrap_tool_call(request, handler)       ← POST：handler 取 result → bundle 改 result
        │   └─ DefaultStrategy.wrap_tool_call
        │       └─ externalizer.externalize_if_needed → request_override
        └─ awrap_tool_call(request, handler)      ← 同上（复用同步）
```

### 0.2. 运行时调用树（分两类 hook）

#### A. state-channel hook

**A1. before_agent / after_agent（预算初始化与清理，同步）**

```
LangGraph 进入 before_agent 阶段
│
└─ StrategyMiddleware.before_agent(state, runtime)
    ├─ _ctx(state, runtime, "before_agent", messages=state.get("messages") or [])
    │   └─ GovernanceContext(state, governance, config, token_counter,
    │                        runtime, hook="before_agent", messages=...)
    ├─ bundle.before_agent(ctx)                   ← DefaultStrategy.before_agent
    │   └─ budget.init_budget(ctx.governance)
    │       → GovernanceResult(state_patch={"governance": ...})
    └─ apply_governance_result(state, result)
        └─ return {"governance": ...}             ← 写回 state 通道(转换格式)
```

```
LangGraph 进入 after_agent 阶段
│
└─ StrategyMiddleware.after_agent(state, runtime)
    ├─ _ctx(...)                                  ← hook="after_agent"
    ├─ bundle.after_agent(ctx)                    ← DefaultStrategy.after_agent
    │   └─ budget.clear_run_state(ctx.governance)
    │       → GovernanceResult(state_patch={"governance": ...})
    └─ apply_governance_result(state, result)
        └─ return {"governance": ...}             ← 清掉 budget/pending/warned 等(转换格式)
```

**A2. before_model（压缩主入口，同步）**

```
LangGraph 进入 before_model 阶段
│
└─ StrategyMiddleware.before_model(state, runtime)     ← @hook_config(can_jump_to=["model"])
    ├─ _ctx(state, runtime, "before_model", messages=state.get("messages") or [])
    │   └─ GovernanceContext(...)
    ├─ bundle.before_model(ctx)                   ← DefaultStrategy.before_model
    │   ├─ _ensure_pairing(messages)              → pairing_patch（缺失 ToolMessage 占位）
    │   ├─ 读 governance.default.{pending, budget.fraction}
    │   ├─ "P3" in pending → 设 p3_obs_limit（当前 no-op）
    │   ├─ "P4" in pending → snapshot.snapshot_if_pending
    │   │                    → summarizer.summarize_if_pending
    │   │                    → messages_patch=[RemoveAll, summary, *preserved]
    │   ├─ "P1" in pending → externalizer.externalize_history
    │   │                    → messages_patch=[替换版 ToolMessage...]
    │   └─ 最终合并 pairing_patch
    │       → GovernanceResult(state_patch / messages_patch / jump_to)
    └─ apply_governance_result(state, result)
        └─ return {"governance": ..., "messages": [...], "jump_to": ...}   (转换格式)
```

> 注意：DefaultStrategy.before_model 实际返回的 GovernanceResult **几乎不设 jump_to**
> （P4/P1 分支都不 jump，只有 P5 在 after_model 里 jump_to="model"）。
> `@hook_config(can_jump_to=["model"])` 是给所有策略留的能力，不强制策略使用。

**A3. after_model（预算追踪 + P5 收尾，同步）**

```
LangGraph 进入 after_model 阶段
│
└─ StrategyMiddleware.after_model(state, runtime)      ← @hook_config(can_jump_to=["model"])
    ├─ _ctx(state, runtime, "after_model", messages=state.get("messages") or [])
    ├─ bundle.after_model(ctx)                    ← DefaultStrategy.after_model
    │   ├─ 解析 window（config.window 优先，否则 resolve_window_size(model)）
    │   ├─ budget.track(ctx.governance, messages, token_counter, window)
    │   │   → 更新 budget.fraction / pending / seen_msgs
    │   ├─ _mark_thinking(messages)               → thinking 标记 patch
    │   ├─ "P5" in pending and not warned：
    │   │   ├─ 找最后一条带 tool_calls 的 AIMessage
    │   │   ├─ _strip_tool_calls(last_ai, fraction) → 剥 tool_calls（同 id 替换）
    │   │   ├─ _build_stop_message(fraction)        → context_budget_stop HumanMessage
    │   │   ├─ d["warned"]=True
    │   │   └─ GovernanceResult(state_patch, messages_patch, jump_to="model")
    │   └─ 否则：GovernanceResult(state_patch, messages_patch)
    └─ apply_governance_result(state, result)
        └─ return {"governance": ..., "messages": [...], "jump_to": "model"?}   (转换格式)
```

> 异步版 `abefore_agent` / `aafter_agent` / `abefore_model` / `aafter_model`
> 在 DefaultStrategy 里都是直接 `return self.<sync>`，所以行为与同步完全一致。

#### B. wrap hook

#### B1. wrap_model_call（PRE，同步）

```
模型调用进入 wrap 阶段
│
└─ StrategyMiddleware.wrap_model_call(request, handler)
    ├─ state = request.runtime.state or {}
    ├─ _ctx(state, request.runtime, "wrap_model_call",
    │        model_request=request,
    │        messages=request.messages or [],
    │        tools=request.tools)
    │   └─ GovernanceContext(...)
    ├─ result = bundle.wrap_model_call(ctx)       ← DefaultStrategy.wrap_model_call
    │   └─ 固定返回 GovernanceResult()（no-op，不改 request）
    ├─ req = result.request_override or request    ← None → 用原 request
    └─ return handler(req)                        ← 原样交给下游
```

> **实际结论**：DefaultStrategy 下 `wrap_model_call` 是**纯 no-op**，
> adapter 的 `request_override` 分支不会被触发。
> 这个 hook 目前是为未来策略（如按模型路由、改 temperature、注入系统提示）预留的。

#### B2. wrap_tool_call（POST，同步）

```
工具调用进入 wrap 阶段
│
└─ StrategyMiddleware.wrap_tool_call(request, handler)
    ├─ tool_result = handler(request)              ← 先拿 tool 结果
    ├─ state = request.runtime.state or {}
    ├─ _ctx(state, request.runtime, "wrap_tool_call",
    │        tool_call_request=request,
    │        tool_result=tool_result)
    │   └─ GovernanceContext(...)
    ├─ result = bundle.wrap_tool_call(ctx)         ← DefaultStrategy.wrap_tool_call
    │   └─ if isinstance(tool_result, ToolMessage):
    │         rewritten = externalizer.externalize_if_needed(tool_result)
    │         if rewritten is not None:
    │             return GovernanceResult(request_override=rewritten)
    │         else:
    │             return GovernanceResult()
    └─ return result.request_override or tool_result
        └─ 超阈 → 返回替换版（preview + path）
           未超阈 / 非 ToolMessage → 返回原 tool_result
```

> **实际结论**：DefaultStrategy 下唯一真正消费 `request_override` 的 hook 是
> `wrap_tool_call`，用于「工具刚返回就判断是否超阈并外化」。
> `wrap_model_call` 虽在同一 adapter 分支，但策略侧 no-op，不触发。

## 1. 「6 个 hook」——结合 DefaultStrategy 的实际落地

| # | hook 名 | 类别 | adapter 处理 | DefaultStrategy 实际行为 | 是否用 request_override | 是否用 jump_to |
|---|---|---|---|---|---|---|
| 1 | `before_agent` | state-channel | apply_governance_result | `budget.init_budget` → state_patch.governance | 否 | 否 |
| 2 | `after_agent` | state-channel | apply_governance_result | `budget.clear_run_state` → state_patch.governance | 否 | 否 |
| 3 | `before_model` | state-channel | apply_governance_result（`can_jump_to=["model"]`） | pairing 补全 + P3/P4/P1 压缩 → messages_patch + state_patch | 否 | 否（能力预留） |
| 4 | `after_model` | state-channel | apply_governance_result（`can_jump_to=["model"]`） | `budget.track` + `_mark_thinking` + P5 剥 tool_calls → messages_patch + state_patch + **jump_to="model"** | 否 | **是（P5）** |
| 5 | `wrap_model_call` | wrap | 仅消费 request_override | **no-op**（返空 GovernanceResult） | 否 | — |
| 6 | `wrap_tool_call` | wrap | 仅消费 request_override | `externalize_if_needed` → 超阈返替换版 ToolMessage | **是** | — |

**每对都有同步和异步两版**：DefaultStrategy 的 async 版全部 `return self.<sync>`，所以同步/异步行为一致。

## 2. 「GovernanceStrategy bundle」——结合 DefaultStrategy 的实际落地

- 它是一个 **Protocol**（`@runtime_checkable class GovernanceStrategy(Protocol)`），即**接入契约**，不是具体实现。
- 它规定策略 bundle 必须实现 6 对 hook，签名统一 `(ctx: GovernanceContext) -> GovernanceResult`（异步版 `Awaitable[GovernanceResult]`）。
- **DefaultStrategy 是它的一个具体实现**，用 `@register_strategy("default")` 注册进 registry，被 builder 按 `config.strategy == "default"` 查表实例化。

### 2.1. DefaultStrategy 如何消费 GovernanceContext 的字段

| GovernanceContext 字段 | DefaultStrategy 用在哪 |
|---|---|
| `state` | `before_model` P3 分支读 `state.get("observations")` |
| `governance` | 所有 hook：读/写 `governance["default"]`（budget / pending / summary / snapshot_path / metrics） |
| `config` | `after_model` 读 `config.get("window")` 作 window 覆盖 |
| `token_counter` | `after_model` 调 `budget.track(..., ctx.token_counter, window)` |
| `runtime` | `_emit_trace` / `_get_run_dir` 取 thread_id / run_id 定位 run 目录 |
| `hook` | 策略内部未显式用（adapter 注入，便于未来按 hook 分支） |
| `messages` | before_model / after_model 的压缩与标记主输入 |
| `tools` | 未用（wrap_model_call no-op） |
| `model_request` | 未用（wrap_model_call no-op） |
| `tool_call_request` | wrap_tool_call 未显式用（只读 `tool_result`） |
| `tool_result` | `wrap_tool_call` 判断是否 ToolMessage 并外化 |

### 2.2. DefaultStrategy 如何产出 GovernanceResult 的各字段

| GovernanceResult 字段 | DefaultStrategy 在哪产出 | 说明 |
|---|---|---|
| `state_patch` | before_agent / after_agent / before_model / after_model | 几乎都是 `{"governance": ...}`，写预算/pending/summary/snapshot_path/warned |
| `messages_patch` | before_model（pairing / P4 / P1）、after_model（_mark_thinking / P5） | RemoveAll+summary+preserved、外化替换、剥 tool_calls、stop_msg |
| `request_override` | wrap_tool_call | 仅外化成功时输出替换版 ToolMessage |
| `metrics` | **未使用**（DefaultStrategy 把计数写进 `governance.default.metrics`，不走 GovernanceMetric 通道） | 注意：contract 提供 GovernanceMetric，但 DefaultStrategy 目前不用它 |
| `jump_to` | after_model（P5） | 唯一跳转点，跳回 "model" |

> **关键观察**：DefaultStrategy **没有使用 GovernanceMetric 和 merge_metrics_into_governance**。
> 它把 `snapshot_count` / `summarize_count` 直接写进 `governance["default"]["metrics"]`，
> 所以 `apply_governance_result` 里的 metrics 分支在 DefaultStrategy 下不会被触发。
> 这是契约层能力与实际实现之间的一个「未用接口」。

### 2.3. adapter 与 bundle 的职责边界（结合实现看）

| 职责 | 归谁 |
|---|---|
| 构造 GovernanceContext（注入 token_counter / runtime / hook） | adapter（StrategyMiddleware._ctx） |
| 决定调 sync 还是 async hook | adapter（LangGraph 走哪个就调哪个） |
| 把 GovernanceResult.state_patch / messages_patch / metrics / jump_to 转 dict patch | adapter（apply_governance_result） |
| 把 GovernanceResult.request_override 塞给 handler | adapter（wrap hook inline） |
| 持有 handler 并调用 | adapter |
| 决定什么时候压缩、压什么、怎么压 | bundle（DefaultStrategy） |
| 读写 governance 子结构 | bundle |
| 写盘（外化 / 快照） | bundle（委托 externalizer / snapshot） |
| 调 LLM 摘要 | bundle（委托 summarizer） |

**一句话**：adapter 只管「协议转换 + handler 包裹」，bundle 管「所有治理决策与副作用」。
