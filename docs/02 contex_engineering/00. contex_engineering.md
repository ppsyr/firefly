`build_governance_middlewares` 固定挂 3 个 middleware，顺序是：

```
TaggedContextMiddleware  →  MessageNormalizerMiddleware  →  StrategyMiddleware
   （渲染标签上下文）          （合并 SystemMessage）           （策略 6 hook）
```

三者都继承 `AgentMiddleware`、`state_schema = ThreadState`，但**介入的 hook 完全不同**：

| 中间件 | 介入 hook | 作用面 | 是否持久 |
|---|---|---|---|
| TaggedContextMiddleware | `wrap_model_call`（PRE 改 request）+ `after_model`（写 trace） | 送 LLM 的上下文**渲染** | request-scoped，state 只存 trace |
| MessageNormalizerMiddleware | `wrap_model_call`（PRE 改 request） | 合并多 SystemMessage 为单条 leading | request-scoped，不动 state |
| StrategyMiddleware | 6 hook 全量 | 策略路由（压缩/预算/外化/快照/摘要） | state_patch 持久 |

**关键点**：前两个是「公共固定」，只动 request payload，**不改 checkpoint state**；第三个才是真正做治理决策的。它们在同一条 `wrap_model_call` 链上按挂载顺序依次执行。

## 1. TaggedContextMiddleware

### 定位
「标签化上下文格式基座」。把送 LLM 的上下文从「原生 message 列表」渲染成**扁平 XML 标签序列 + `<turn>` 时序分组**。

### 核心组成
- **`ContextAssembler`**（辅助类，不继承 AgentMiddleware）：真正干渲染的。
  - `render_context_block(state, governance)`：渲染头部上下文块，从 ThreadState + governance 提取字段 → `<goal>` / `<plan>` / `<reflection>` / `<summary>` / `<date>`。
  - `render_messages(messages)`：把 message 序列渲染成 `<turn>` 分组 + `<message role="user">` / `<thinking>` / `<toolcall>` / `<answer>` / `<toolresult>` 标签。**用于 trace 审计**。
  - `render_messages_for_llm(messages)`：**方案 H**——角色保留，AIMessage 的 content 包 `<thinking><answer>` 语义标签，ToolMessage 经典不变。**用于实际送 LLM**。
  - `_escape`：XML 特殊字符转义，防标签结构破坏。
- **`TaggedContextMiddleware`**：挂 `wrap_model_call` + `after_model`。

### 做了什么
**（1）`wrap_model_call`（PRE，改 request）**
- 从 request 提取原 SystemMessage 文本。
- 调 `render_context_block` 生成上下文块（`<goal><plan><reflection><summary><date>`）。
- 若有 system 文本，前置 `<system>...</system>`。
- 调 `render_messages_for_llm` 改写对话历史（AIMessage 包语义标签）。
- 组装成 `[SystemMessage(context_block), *rewritten]`，通过 `request.override(messages=...)` 送下游。

**（2）`after_model`（写 trace，不送 LLM）**
- 从 state.messages 重组渲染一遍（用 `render_messages` 的完整标签版）。
- 写 `state["tagged_context"] = {"rendered": ..., "created_at": ...}`，供审计/调试。

### 功能
- 把「结构化 state」渲染成 LLM 可读的 XML 标签块（goal/plan/reflection/summary/date）。
- 把「对话历史」渲染成带语义标签的序列（thinking/answer/toolcall/toolresult）。
- 跳过 SystemMessage 和 `poirot.summary` HumanMessage（避免重复渲染）。
- 给压缩策略提供 `poirot.*` 命名空间标记（thinking/summary/externalized 等）。
- trace 落 state.tagged_context，供事后审计。

### 特点
- **request-scoped 不持久**：改写只发生在送 LLM 那一刻，state 里始终存原始 message content。
- 只动 `request.messages`，不写 `governance`，不参与压缩决策。

## 2. MessageNormalizerMiddleware

### 定位
「SystemMessage 合并器」。解决 **strict backend（vLLM / Qwen / Anthropic）拒绝非 leading SystemMessage** 的兼容性问题。

### 做了什么
**`wrap_model_call`（PRE，改 request）**：
- 扫 request.messages，找出所有 SystemMessage。
- 若没有 SystemMessage → 返回 None，adapter 用原 request（不动）。
- 若有：
  - 把 `request.system_message`（如果有）和 messages 里的 SystemMessage 全部收集。
  - 用 `\n\n` 拼接所有 content（`_flatten_content` 处理 str / list[dict] 混合格式）。
  - additional_kwargs 逐个 update 合并。
  - 生成**单条 leading SystemMessage**。
  - 从 messages 里剔除所有 SystemMessage，得到 non_system 列表。
  - `request.override(system_message=merged, messages=non_system)`。

### 功能
- 把「散落在 messages 中间的多条 SystemMessage」合并成「一条 leading system_message」。
- 保证 strict backend 不因非 leading SystemMessage 报错。
- `_flatten_content` 兼容 str / list（含 `{"text": ...}` 结构）。
- 幂等：没有 SystemMessage 时完全不动。

### 特点
- **只动 request payload，不动 checkpoint state**，保 history scanner 正常工作。
- noop 会导致 provider 报错（功能坏），所以是「公共固定」不经过 registry。
- 在链上排在 TaggedContext 之后：TaggedContext 先把上下文块作为 SystemMessage 前置，MessageNormalizer 再把它和原 system 合并成一条 leading。

## 3. StrategyMiddleware

### 定位
「接入 adapter」。把策略 bundle（如 DefaultStrategy）的 6 个 hook 路由进 LangChain AgentMiddleware 协议。

### 做了什么
**（A）state-channel hooks（4 对，返回 dict patch）**
- `before_agent` / `abefore_agent`
- `after_agent` / `aafter_agent`
- `before_model` / `abefore_model`（带 `@hook_config(can_jump_to=["model"])`）
- `after_model` / `aafter_model`（带 `@hook_config(can_jump_to=["model"])`）

流程：`_ctx()` 构造 GovernanceContext → 调 `bundle.<hook>(ctx)` → `apply_governance_result(state, result)` → 返回 dict patch。

**（B）wrap hooks（2 对，包 handler）**
- `wrap_model_call` / `awrap_model_call`：**PRE**，bundle 改 request → handler。DefaultStrategy 下是 no-op。
- `wrap_tool_call` / `awrap_tool_call`：**POST**，handler 先取 result → bundle 改 result。DefaultStrategy 下用于单条 tool result 外化。

### 功能
- 把 GovernanceContext / GovernanceResult 契约与 LangChain 协议对接。
- 持有 bundle + config，注入 token_counter / runtime / hook 名。
- 把 state_patch / messages_patch / metrics / jump_to 转成 state-channel hook 能消费的 dict。
- 把 request_override 塞给 handler（wrap hook 专用）。
- 策略未注册时降级（builder 层处理）。

### 特点
- **唯一持久化治理状态的中间件**（state_patch 写 ThreadState.governance）。
- 是策略与框架之间的「翻译层」，自身不含治理逻辑。
- 与 DefaultStrategy 配合时：before/after_agent 做预算初始化/清理，before_model 做压缩（P1/P3/P4），after_model 做预算追踪 + P5 收尾，wrap_tool_call 做外化。

## 三者在同一条 wrap_model_call 链上的协作

```
request（原始 messages）
    │
    ▼
TaggedContextMiddleware.wrap_model_call
    ├─ 提取原 SystemMessage 文本
    ├─ render_context_block → <goal><plan><reflection><summary><date>
    ├─ render_messages_for_llm → 改写 AIMessage content（<thinking><answer>）
    └─ request.override(messages=[SystemMessage(context_block), *rewritten])
    │
    ▼
MessageNormalizerMiddleware.wrap_model_call
    ├─ 扫所有 SystemMessage（含上一步塞的 context_block）
    ├─ 合并成单条 leading SystemMessage
    └─ request.override(system_message=merged, messages=non_system)
    │
    ▼
StrategyMiddleware.wrap_model_call
    └─ DefaultStrategy.wrap_model_call = no-op（原样放行）
    │
    ▼
handler(request)  →  真正送 LLM
```

**分工总结**：
- **TaggedContext** 负责「把 state 和 messages 渲染成 LLM 友好的 XML 标签」。
- **MessageNormalizer** 负责「把多条 SystemMessage 合并成一条 leading，兼容 strict backend」。
- **Strategy** 负责「把策略的 6 hook 接进框架，执行治理决策」。

前两个是**格式层**（只改 request 形态），第三个是**决策层**（改 state、做压缩、写 governance）。
