---

name: SandboxBackend — 沙箱运行平台契约（基础设施操作层）。

description: 

【整体职责】
定义沙箱实例在「基础设施」上的 CRUD 接口：创建 / 销毁 / 存活检查 / 跨进程发现。
不限定容器类型——Docker / K8s / Firecracker microVM / WASM 都算「沙箱运行平台」。

【内容摘要】
- SandboxBackend          : 抽象基类（ABC），定义基础设施操作契约。
- create                  : 创建沙箱实例（幂等）。
- destroy                 : 销毁沙箱实例。
- is_alive                : 查实例存活（轻量，不调 HTTP）。
- discover                : 按确定性 ID 查已有实例，跨进程恢复用。
- list_running            : 列所有运行中实例，孤儿对账用（默认空）。

【职责边界】
- 只负责：基础设施层的实例 CRUD（create / destroy / is_alive / discover）。
- 不负责：进程内对象生命周期与缓存（SandboxProvider）、命令执行（Sandbox/Runtime）、
  路径转换（Translator）、安全校验（Guard）。
- 不持有状态：本类只是契约，实例状态由具体平台子类持有。

【与 SandboxProvider 的区分】
- SandboxProvider：进程内对象生命周期（acquire / get / release / 缓存 / warm_pool）。
- SandboxBackend ：基础设施操作（create / destroy / is_alive / discover / 跨进程）。
- 一句话：Provider 管「对象」，Backend 管「实例」。

## 0. 结构树

### 0.1. 静态结构树

```
sandbox_backend.py — SandboxBackend 沙箱运行平台契约（基础设施操作层，ABC）
│
├─ SandboxBackend(ABC)                        ← 基础设施操作契约；Local / Docker / K8s 各写子类
│   │                                            作用：把「实例在基础设施上的 CRUD」抽象出来，
│   │                                            不限定容器类型（Docker/K8s/microVM/WASM 都算）
│   │
│   ├─ create(thread_id, sandbox_id,          ← [抽象] 创建沙箱实例
│   │         extra_mounts=None, *, user_id)     幂等：同 sandbox_id 返回已存在实例
│   │   -> SandboxInfo
│   │   └─ 子类实现：LocalPlatform 起本地 / DockerPlatform 起容器
│   │
│   ├─ destroy(info: SandboxInfo) -> None     ← [抽象] 销毁沙箱实例
│   │   └─ 子类实现：停进程 / 停容器 / 删资源
│   │
│   ├─ is_alive(info: SandboxInfo)            ← [抽象] 查实例存活
│   │   -> bool | None                           轻量（docker inspect），不调 HTTP
│   │   └─ True=running / False=stopped / None=未知（不误杀）
│   │
│   ├─ discover(sandbox_id)                   ← [抽象] 按确定性 ID 查已有实例
│   │   -> SandboxInfo | None                    跨进程恢复用
│   │   └─ 子类实现：查基础设施上的实例
│   │
│   └─ list_running() -> list[SandboxInfo]    ← [默认] 列所有运行中实例
│       │                                        孤儿对账用
│       └─ 默认 return []
```

### 0.2. 运行时调用树

```
① 装配期（一次性）
bootstrap_sandbox.py
    └─ 选一个 SandboxBackend 子类（LocalPlatform / DockerPlatform / K8sPlatform）
          └─ 注入到 SandboxProvider 子类（Provider 持有 Backend）
    （此时不调 create，只是持有 backend）

        ═══════════ 进入 Agent 循环 ═══════════

② acquire —— 拿沙箱（Provider 内部调 Backend）
SandboxProvider.acquire(thread_id, user_id)
    ├─ 缓存命中 → 直接返回 sandbox_id（不调 Backend）
    └─ 缓存未命中 → backend.discover(sandbox_id)    ← 跨进程恢复
          ├─ 命中且 is_alive=True → 复用，回填缓存
          └─ 未命中 → backend.create(thread_id, sandbox_id, extra_mounts, user_id)
                └─ 返回 SandboxInfo
    → 回填 Provider 缓存，返回 sandbox_id

③ 健康检查 —— 存活探测
SandboxProvider / Runtime 周期性或按需调
    └─ backend.is_alive(info)
          ├─ True  → 继续使用
          ├─ False → 触发重建（destroy + create）
          └─ None  → 保持现状（不误杀）

④ 释放 / 销毁 —— Provider 收尾
SandboxProvider.release(sandbox_id)                 ← 不一定销毁（Local no-op / Docker 移 warm_pool）
SandboxProvider.shutdown()                          ← 真正销毁时调
    └─ backend.destroy(info)
          └─ 停进程 / 停容器 / 删资源

⑤ 孤儿对账 —— 启动/巡检时
bootstrap / 巡检逻辑
    └─ backend.list_running()
          └─ 与已知 sandbox_id 集合比对 → 清理孤儿实例

（其余 hook 与本模块无关）
```

## 1. 补充

**`SandboxBackend` 是 sandbox 层的"基础设施契约"——它把「沙箱实例在基础设施上的增删查」抽象出来，与 `SandboxProvider`（进程内对象生命周期）形成明确分工。**

几点补充：

- **Provider 与 Backend 的分工是本文件最核心的点**：
  - `SandboxProvider` 管「进程内对象」：缓存、warm_pool、acquire/release/get。
  - `SandboxBackend` 管「基础设施实例」：create/destroy/is_alive/discover、跨进程。
  - 一句话：**Provider 管对象，Backend 管实例**。Provider 内部会调 Backend。

- **为什么"不限定容器类型"很重要**：注释里明确说 Docker / K8s / Firecracker microVM / WASM 都是"沙箱运行平台"。这意味着 `SandboxBackend` 的抽象层级比"容器"更高——换底层平台不用改契约。

- **`is_alive` 三态（True/False/None）是设计要点**：不是简单的 bool，而是故意留 None 表示"未知"。注释说"不因健康检查失败误杀容器"——这是生产环境的经验：健康检查本身可能失败，不能据此就销毁实例。

- **`create` 幂等 + `discover` 跨进程恢复是配套的**：幂等保证"同 sandbox_id 不重复创建"，discover 保证"跨进程能找回已有实例"。这两个配合，才能支撑"多进程 / 重启后恢复沙箱"。

- **`list_running` 是孤儿对账用的**：默认返回空列表，子类按需实现。用于启动或巡检时发现"已存在但没人认领"的实例并清理。

- **和 `types.py` 的耦合点**：`create` 返回 `SandboxInfo`，`extra_mounts` 用 `PathMapping`——这两个类型都来自 `types.py`，所以 `types.py` 是 Backend 契约的依赖基础。
