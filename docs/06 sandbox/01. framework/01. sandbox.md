---

name: Sandbox 具体类 — 编排 Runtime + Translator + Guard，对外提供统一操作接口。

description: 

【整体职责】
作为 sandbox 层的对外门面，组合 Runtime（执行）+ Translator（路径转换）+ Guard（安全校验）
三个契约，把「校验 → 路径转换 → 执行 → 结果脱敏」的编排逻辑集中在一处。
切沙箱（Local / Docker / E2B）只换组件，编排逻辑复用（方案 C 核心）。

【内容摘要】
- Sandbox              : 编排类主体，对外暴露 execute/read/write/list/glob/grep/download/update。
- __init__ / id        : 注入三个契约组件，id 构造时确定。
- get_host_path        : 虚拟路径 → 宿主物理路径（供外部复制/注册 artifact 用）。
- execute_command      : 命令执行（validate → translate → exec → mask）。
- read_file            : 读文件（validate → translate → read → mask）。
- write_file           : 写文件（validate → translate → write，不 mask）。
- list_dir             : 列目录（validate → translate → list → 逐项 mask）。
- glob                 : 按 pattern 匹配路径（validate → translate → glob → 逐项 mask）。
- grep                 : 内容检索（validate → translate → grep → 对 GrepMatch 逐字段 mask）。
- download_file        : 下载文件字节流（validate → translate → download，不 mask）。
- update_file          : 上传/覆盖文件字节流（validate → translate → update）。
- close                : 关闭 runtime。

【职责边界】
- 只负责：编排顺序（guard.validate → translator.translate → runtime.execute → translator.mask）。
- 不负责：命令/路径的具体校验规则（guard）、路径转换算法（translator）、执行落地（runtime）。
- 不持有状态：除注入的组件与不可变 id 外，无自身状态；每次调用走同一编排。

## 0. 结构树

### 0.1. 静态结构树

```
sandbox.py — Sandbox 具体类（编排 Runtime + Translator + Guard）
│
├─ Sandbox                                    ← 对外门面；组合三契约，编排固定顺序
│   │                                            作用：把「校验→转换→执行→脱敏」集中一处，
│   │                                            切沙箱只换组件，编排逻辑复用（方案 C）
│   │
│   ├─ __init__(id, runtime, translator, guard)   ← 注入三契约 + 不可变 id
│   │   ├─ self._id = id
│   │   ├─ self._runtime = runtime
│   │   ├─ self._translator = translator
│   │   └─ self._guard = guard
│   │
│   ├─ id -> str                              ← property；构造时确定，不可变
│   │
│   ├─ get_host_path(virtual_path) -> str     ← 虚拟路径 → 宿主物理路径
│   │   │                                        作用：供外部复制/注册 artifact 用；
│   │   │                                        不做 guard.validate（调用方负责路径安全）
│   │   ├─ hasattr(translator, "reverse_translate") ?
│   │   │     ├─ 有 → reverse_translate(virtual_path)   ← DockerPathTranslator
│   │   │     └─ 无 → translate_path(virtual_path)      ← Identity / LocalTranslator
│   │   └─ 返回宿主路径
│   │
│   ├─ execute_command(command) -> str         ← 命令执行（四步编排）
│   │   ├─ guard.validate_command(command)
│   │   ├─ translator.translate_command(command)
│   │   ├─ runtime.exec_command(translated)
│   │   └─ translator.mask_output(output)      ← 路径逆翻译
│   │
│   ├─ read_file(path) -> str                  ← 读文件
│   │   ├─ guard.validate_path(path, write=False)
│   │   ├─ translator.translate_path(path)
│   │   ├─ runtime.read_file(physical)
│   │   └─ translator.mask_output(content)
│   │
│   ├─ write_file(path, content, append)       ← 写文件（无 mask）
│   │   ├─ guard.validate_path(path, write=True)
│   │   ├─ translator.translate_path(path)
│   │   └─ runtime.write_file(physical, content, append=append)
│   │
│   ├─ list_dir(path, max_depth, max_entries) -> list[str]   ← 列目录
│   │   ├─ guard.validate_path(path, write=False)
│   │   ├─ translator.translate_path(path)
│   │   ├─ runtime.list_dir(physical, ...)
│   │   └─ 逐项 mask_output
│   │
│   ├─ glob(path, pattern, ...) -> (list[str], bool)         ← 按 pattern 匹配路径
│   │   ├─ guard.validate_path(path, write=False)
│   │   ├─ translator.translate_path(path)
│   │   ├─ runtime.glob(physical, pattern, ...)
│   │   └─ 逐项 mask_output，返回 (结果, truncated)
│   │
│   ├─ grep(path, pattern, ...) -> (list[GrepMatch], bool)   ← 内容检索
│   │   ├─ guard.validate_path(path, write=False)
│   │   ├─ translator.translate_path(path)
│   │   ├─ runtime.grep(physical, pattern, ...)
│   │   └─ 对每个 GrepMatch 用 replace() 逐字段 mask（path / line）
│   │
│   ├─ download_file(path) -> bytes            ← 下载字节流（无 mask）
│   │   ├─ guard.validate_path(path, write=False)
│   │   ├─ translator.translate_path(path)
│   │   └─ runtime.download_file(physical)
│   │
│   ├─ update_file(path, content) -> None      ← 上传/覆盖字节流（无 mask）
│   │   ├─ guard.validate_path(path, write=True)
│   │   ├─ translator.translate_path(path)
│   │   └─ runtime.update_file(physical, content)
│   │
│   └─ close() -> None                         ← 关闭 runtime
│       └─ runtime.close()
```

### 0.2. 运行时调用树

```
① 装配期（一次性）
Sandbox 构造（由 provider 装配）
    └─ Sandbox(id, runtime, translator, guard)
          └─ 注入三契约，id 固定
    → 注入到 sandbox 工具 / middleware

        ═══════════ 进入 Agent 循环 ═══════════

② 工具调用 —— 进入 Sandbox 操作方法
bash / read_file / write_file / list_dir / str_replace / present_files
    └─ 路由到 Sandbox 对应方法
          │
          ├─ execute_command(cmd)
          │   ├─ guard.validate_command(cmd)        ← 危险命令拦截
          │   ├─ translator.translate_command(cmd)  ← 命令内路径改写
          │   ├─ runtime.exec_command(...)          ← 本地 subprocess / docker exec
          │   └─ translator.mask_output(output)     ← 宿主路径 → 虚拟路径
          │
          ├─ read_file(path)
          │   ├─ guard.validate_path(path, write=False)
          │   ├─ translator.translate_path(path)
          │   ├─ runtime.read_file(physical)
          │   └─ translator.mask_output(content)
          │
          ├─ write_file(path, content, append)
          │   ├─ guard.validate_path(path, write=True)
          │   ├─ translator.translate_path(path)
          │   └─ runtime.write_file(physical, content, append)   ← 无 mask（写不回显）
          │
          ├─ list_dir(path, ...)
          │   └─ ... → 逐项 mask_output
          │
          ├─ glob(path, pattern, ...)
          │   └─ ... → 逐项 mask_output，返回 (结果, truncated)
          │
          ├─ grep(path, pattern, ...)
          │   └─ ... → 对每个 GrepMatch 用 replace() 逐字段 mask
          │
          ├─ download_file(path)
          │   └─ ... → runtime.download_file(physical)           ← 无 mask（字节流）
          │
          └─ update_file(path, content)
              └─ ... → runtime.update_file(physical, content)    ← 无 mask（字节流）

③ 生命周期收尾
Sandbox.close()
    └─ runtime.close()                            ← 释放容器 / 进程资源

（其余 hook 与本模块无关）
```

## 1. 补充

**`sandbox.py` 是 sandbox 层的"编排中枢"——它不实现任何校验、转换、执行的具体逻辑，只负责把 Runtime / Translator / Guard 三个契约按固定顺序串起来，对外提供统一的文件与命令操作接口。**

几点补充：

- **方案 C 的核心价值**：`Sandbox` 不是 ABC，而是具体类。切 Local / Docker / E2B 时只替换注入的三个组件，编排逻辑（validate → translate → execute → mask）完全复用。新增一种沙箱实现不需要改本文件。
- **四步编排是硬约束**：所有操作方法都遵循 `guard.validate → translator.translate → runtime.execute → translator.mask`。这是本类唯一的"业务逻辑"，也是最容易被误改的地方。
- **`mask_output` 归 translator 不归 guard**：因为脱敏本质是路径翻译的逆操作（宿主路径 → 虚拟路径），不是安全校验。这是设计上的一个明确分界（注释里标了 Grill #4）。
- **写操作不 mask**：`write_file` / `update_file` 没有 mask，因为没有回显路径的需求；`download_file` 返回字节流，同样不 mask。只有会"回显路径给 Agent 看"的方法（read/list/glob/grep/execute）才需要 mask。
- **`grep` 的 mask 最特殊**：因为 `GrepMatch` 是 dataclass，需要用 `replace()` 逐字段重建，而不是对整个对象调用一次 mask。这是本类里唯一需要逐字段处理的地方。
- **`get_host_path` 是例外**：它绕过 `guard.validate`，且 translator 方法名不同（`reverse_translate` vs `translate_path`）。因为它的用途是"供外部复制/注册 artifact"，调用方自己负责路径安全。
- **`close()` 后不可再用**：这是注释里的 INVARIANT，但代码本身不做状态检查，依赖调用方遵守。
