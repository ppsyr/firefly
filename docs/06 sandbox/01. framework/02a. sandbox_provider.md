---

name: SandboxProvider — 沙箱生命周期管理契约。

description: 

【整体职责】
定义沙箱「获取 / 查找 / 释放 / 元信息 / 重置 / 销毁」的生命周期接口。
方案 C 生命周期层：Local / Docker 各写子类，上层（工具 / middleware / bootstrap）
只依赖本契约，不关心具体是哪种沙箱。

【内容摘要】
- SandboxProvider          : 抽象基类（ABC），定义生命周期契约。
- uses_thread_data_mounts  : 类属性，标记是否使用 thread 级数据挂载。
- needs_upload_permission_adjustment : 类属性，标记是否需要调整上传权限。
- acquire / acquire_async  : 获取（或复用）沙箱，返回 sandbox_id。
- get                      : 纯内存查找，返回 Sandbox 实例或 None。
- release                  : 释放沙箱（不一定销毁）。
- get_sandbox_info         : 返回沙箱元信息（含 sandbox_url），供 specialist 透传。
- reset                    : 清缓存，不 shutdown。
- shutdown                 : 销毁所有沙箱 + 清缓存。

【职责边界】
- 只负责：定义生命周期接口与默认行为。
- 不负责：沙箱如何创建/销毁的具体实现（子类）、命令执行（Sandbox/Runtime）、
  路径转换（Translator）、安全校验（Guard）。
- 不持有状态：本类只是契约，状态由子类持有（缓存、warm_pool 等）。

## 0. 结构树

### 0.1. 静态结构树

```
sandbox_provider.py — SandboxProvider 沙箱生命周期契约（ABC）
│
├─ SandboxProvider(ABC)                       ← 生命周期契约；Local / Docker 各写子类
│   │                                            作用：上层只依赖此契约，不关心具体沙箱类型
│   │
│   ├─ uses_thread_data_mounts: bool = False           ← 类属性；标记是否用 thread 级数据挂载
│   ├─ needs_upload_permission_adjustment: bool = True ← 类属性；标记是否需调整上传权限
│   │
│   ├─ acquire(thread_id, *, user_id) -> str          ← [抽象] 获取/复用沙箱
│   │   │                                                返回 sandbox_id；可能阻塞
│   │   └─ 子类实现：Local 建本地沙箱 / Docker 启容器
│   │
│   ├─ acquire_async(thread_id, *, user_id) -> str    ← [默认] 异步版
│   │   └─ asyncio.to_thread(acquire, ...)            ← 默认把同步实现丢线程池
│   │        子类可重写（Docker 重写以避免阻塞事件循环）
│   │
│   ├─ get(sandbox_id) -> Sandbox | None              ← [抽象] 纯内存查找
│   │   │                                                返回 None 表示未找到；事件循环安全
│   │   └─ 子类实现：查自身缓存
│   │
│   ├─ release(sandbox_id) -> None                    ← [抽象] 释放沙箱（不一定销毁）
│   │   └─ 子类实现：Local no-op / Docker 移入 warm_pool
│   │
│   ├─ get_sandbox_info(sandbox_id) -> SandboxInfo | None   ← [默认] 返回元信息
│   │   │                                                含 sandbox_url，供 specialist 透传
│   │   └─ 默认 return None；Docker 子类重写
│   │
│   ├─ reset() -> None                                ← [默认] 清缓存，不 shutdown
│   │   └─ 默认 pass；子类按需重写
│   │
│   └─ shutdown() -> None                             ← [默认] 销毁所有沙箱 + 清缓存
│       └─ 默认 pass；子类按需重写
```

### 0.2. 运行时调用树

```
① 装配期（一次性）
bootstrap_sandbox.py
    └─ 选一个 SandboxProvider 子类（Local / Docker）
          └─ 注入到 make_sandbox_tools / SandboxMiddleware
    （此时不调 acquire，只是持有 provider）

        ═══════════ 进入 Agent 循环 ═══════════

② before_agent —— 获取沙箱
SandboxMiddleware.before_agent(state)
    └─ provider.acquire(thread_id, user_id=...)     ← 同步路径
          └─ 返回 sandbox_id
    → 写 state["sandbox"]["sandbox_id"]

    （或 async 路径）
    └─ await provider.acquire_async(...)            ← 默认 to_thread 包同步
          └─ Docker 子类重写避免阻塞事件循环

③ 工具调用 —— 查找沙箱
bash / read_file / write_file / ...
    └─ provider.get(sandbox_id)                     ← 纯内存查找，事件循环安全
          └─ 返回 Sandbox 实例
              └─ Sandbox.execute_command(...) / read_file(...) / ...

④ specialist 透传 —— 取元信息
specialist（跨进程/跨 Agent 连接 Docker 容器）
    └─ provider.get_sandbox_info(sandbox_id)
          ├─ Docker → SandboxInfo（含 sandbox_url）
          └─ Local  → None

⑤ 释放 / 收尾
provider.release(sandbox_id)                        ← 释放（Local no-op / Docker 移 warm_pool）
provider.reset()                                    ← 清缓存，不 shutdown
provider.shutdown()                                 ← 销毁所有沙箱（atexit 时）
```

## 1. 补充

**`SandboxProvider` 是 sandbox 层的"生命周期契约"——它只定义「怎么拿沙箱、怎么查、怎么放、怎么销毁」，把"造沙箱"和"用沙箱"彻底分开。**

几点补充：

- **抽象 vs 默认的分工**：`acquire` / `get` / `release` 是 `@abstractmethod`，子类必须实现（这是生命周期核心）；`get_sandbox_info` / `reset` / `shutdown` / `acquire_async` 有默认实现，子类按需重写。读代码时先看抽象方法，再看默认方法。

- **`release` 不销毁是本契约最反直觉的点**：`release` 的语义是"放回"，不是"杀掉"。Local 直接 no-op，Docker 移入 `warm_pool` 复用——这直接影响"多个 Agent 是否共享沙箱"的答案。

- **`reset` 和 `shutdown` 的区别**：`reset` 只清缓存，沙箱可能还活着；`shutdown` 才真正销毁所有沙箱。别把两者混为一谈。

- **`acquire_async` 是"默认 to_thread + 可重写"模式**：默认实现够用，但 Docker 会重写以避免阻塞事件循环。这是模板方法模式的典型用法。

- **两个类属性是"能力声明"**：`uses_thread_data_mounts` / `needs_upload_permission_adjustment` 不是状态，而是让上层在不 import 子类的情况下判断 provider 的能力（比如要不要调权限调整逻辑）。

- **`get_sandbox_info` 是 Local 与 Docker 的分水岭**：Local 没有 URL 概念返 None，Docker 返 `SandboxInfo`。这也是 `types.py` 里 `SandboxInfo` 字段差异（`container_name` / `container_id` 仅 Local 有）的对应点。
