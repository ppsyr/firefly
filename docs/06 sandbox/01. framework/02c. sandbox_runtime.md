---

name: SandboxRuntime — 中立沙箱运行时协议（裸执行契约）。

description: 

【整体职责】
定义沙箱「裸执行」的最小接口：命令执行与文件读写。方案 C 三组件之一，
只负责执行，不涉及路径翻译、不做安全检查，由 Sandbox 编排层负责调用前后处理。
Local / Docker / E2B 各写 adapter；异构差异（如 E2B 无 glob）封装在 adapter 内。

【内容摘要】
- SandboxRuntime          : Protocol（runtime_checkable），裸执行契约。
- exec_command            : 执行命令，返回输出。
- read_file               : 读文件。
- write_file              : 写文件（支持 append）。
- list_dir                : 列目录（带深度与条目上限）。
- glob                    : 按 pattern 匹配路径，返回 (结果, truncated)。
- grep                    : 内容检索，返回 (GrepMatch 列表, truncated)。
- download_file           : 下载文件字节流。
- update_file             : 上传/覆盖文件字节流。
- close                   : 释放运行时资源。

【职责边界】
- 只负责：裸执行（exec / read / write / list / glob / grep / download / update / close）。
- 不负责：路径翻译（Translator）、安全检查（Guard）、编排顺序（Sandbox）、
  生命周期缓存（Provider）、基础设施 CRUD（Backend）。
- 不持有状态：Protocol 只定义接口；状态由具体 adapter 持有。

## 0. 结构树

### 0.1. 静态结构树

```
sandbox_runtime.py — SandboxRuntime 中立沙箱运行时协议（裸执行契约）
│
├─ SandboxRuntime(Protocol)                   ← 裸执行契约；@runtime_checkable
│   │                                            方案 C 三组件之一：只管执行，不管翻译/安全
│   │                                            Local / Docker / E2B 各写 adapter
│   │
│   ├─ exec_command(command) -> str           ← 执行命令，返回输出
│   │
│   ├─ read_file(path) -> str                 ← 读文件
│   │
│   ├─ write_file(path, content, append=False) -> None   ← 写文件（可 append）
│   │
│   ├─ list_dir(path, max_depth=2,            ← 列目录（带深度与条目上限）
│   │           max_entries=1000) -> list[str]
│   │
│   ├─ glob(path, pattern, *,                 ← 按 pattern 匹配路径
│   │        include_dirs=False,                 返回 (结果, truncated)
│   │        max_results=200)
│   │   -> tuple[list[str], bool]
│   │
│   ├─ grep(path, pattern, *,                 ← 内容检索
│   │        glob=None,                          返回 (GrepMatch 列表, truncated)
│   │        literal=False,
│   │        case_sensitive=False,
│   │        max_results=100)
│   │   -> tuple[list[GrepMatch], bool]
│   │
│   ├─ download_file(path) -> bytes           ← 下载文件字节流
│   │
│   ├─ update_file(path, content) -> None     ← 上传/覆盖文件字节流
│   │
│   └─ close() -> None                        ← 释放运行时资源
```

### 0.2. 运行时调用树

```
① 装配期（一次性）
bootstrap_sandbox.py
    └─ 选一个 SandboxRuntime adapter（Local / Docker / E2B）
          └─ 注入到 Sandbox 构造（Sandbox(runtime, translator, guard)）
    （此时不调任何方法，只是持有 runtime）

        ═══════════ 进入 Agent 循环 ═══════════

② 工具调用 —— 经 Sandbox 编排后进入 Runtime
Sandbox.execute_command(cmd)
    ├─ guard.validate_command(cmd)              ← 前：安全校验（不在本协议内）
    ├─ translator.translate_command(cmd)        ← 前：路径/命令翻译（不在本协议内）
    ├─ runtime.exec_command(translated)         ← 本协议方法：裸执行
    └─ translator.mask_output(output)           ← 后：结果脱敏（不在本协议内）

Sandbox.read_file(path)
    ├─ guard.validate_path(path, write=False)
    ├─ translator.translate_path(path)
    ├─ runtime.read_file(physical)              ← 本协议方法：裸执行
    └─ translator.mask_output(content)

Sandbox.write_file(path, content, append)
    ├─ guard.validate_path(path, write=True)
    ├─ translator.translate_path(path)
    └─ runtime.write_file(physical, content, append)   ← 本协议方法：裸执行

Sandbox.list_dir / glob / grep
    └─ ... → runtime.list_dir / glob / grep     ← 本协议方法：裸执行

Sandbox.download_file / update_file
    └─ ... → runtime.download_file / update_file   ← 本协议方法：裸执行（字节流，不 mask）

③ 异常路径 —— 统一异常类型
runtime.exec_command(...) 抛 subprocess.CalledProcessError
    └─ adapter 包装 → SandboxCommandError       ← 本协议约定的异常体系
工具层 catch SandboxError
    └─ ToolCallMiddleware 统一转 error ToolMessage

④ 生命周期收尾
Sandbox.close()
    └─ runtime.close()                          ← 本协议方法：释放资源
```

## 1. 补充

**`SandboxRuntime` 是 sandbox 层的"裸执行契约"——它只定义"怎么执行"，不定义"执行前怎么校验、执行后怎么脱敏"。方案 C 的三组件分工在这里体现得最清楚。**

几点补充：

- **Protocol + `@runtime_checkable` 而非 ABC**：`SandboxRuntime` 用 `Protocol` 定义，意味着 adapter 不需要显式继承，只要"长得像"就满足契约。这让 Local / Docker / E2B 的 adapter 可以更自由地组织代码（比如包装第三方 SDK 的类）。

- **"裸执行"是本协议的核心语义**：注释说得很明确——"只负责裸执行（exec/read/write），不知路径翻译、不做安全检查"。所以协议里没有 `validate`、没有 `translate`、没有 `mask`。这些都在 `Sandbox` 编排层。

- **路径契约由调用方保证，而不是本协议统一**：注释说"Local 路径已翻译为物理路径；Docker/E2B 直传虚拟路径"。这是本协议里最容易被忽略的一点——**同一个方法在不同 adapter 下收到的 path 语义可能不同**，取决于调用方（`Sandbox`）怎么翻译。

- **异构差异封装在 adapter 内**：注释举了"E2B 无 glob"的例子。这意味着协议定义了 `glob`，但某个 adapter 可以用别的方式（比如降级为 `list_dir` + 过滤）实现，对外行为一致。

- **异常体系是协议的一部分**：注释明确列出五个 `SandboxError` 子类，并规定"runtime 实现负责包装内置异常"。这是本协议的硬约束——工具层只需要 `catch SandboxError`，不用关心底层是 `subprocess` 还是 `docker`。

- **协议方法与 `Sandbox` 方法几乎一一对应，但少了两个**：`Sandbox` 有 `get_host_path`，协议里没有——因为 `get_host_path` 是纯 translator 操作，不经过 runtime。这反过来印证了"runtime 只管执行"的边界。

- **和 `types.py` 的耦合点**：`grep` 返回 `list[GrepMatch]`，`GrepMatch` 来自 `types.py`。这是本协议与 `types.py` 唯一的直接依赖。
