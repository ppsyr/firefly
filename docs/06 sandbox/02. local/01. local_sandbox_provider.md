---

name: LocalSandboxProvider — 本地沙箱 provider（LRU 缓存 + 确定性 ID）。

description: 

【整体职责】
实现 SandboxProvider 契约的"本地版本"：按 thread_id 创建 / 复用本地沙箱实例，
用 LRU 缓存控制常驻数量，用确定性 ID 保证跨进程可推导。本地模式下
Sandbox 组合 LocalRuntime + LocalPathTranslator + AuditGuard(LocalSecurityGuard)。

【内容摘要】
- _DEFAULT_LRU_SIZE       : LRU 缓存默认容量（256）。
- _deterministic_sandbox_id: 由 user:thread 推导的确定性 sandbox_id（sha256[:8]）。
- LocalSandboxProvider    : 本地 provider 类。
    ├─ __init__   : 持有 path_mappings / LRU 容量 / sandbox 缓存 / 锁 / allow_host_bash。
    ├─ acquire    : 按 thread_id 取或建 sandbox；LRU 驱逐；返回 sandbox_id。
    ├─ get        : 纯内存查找，返回 Sandbox 或 None。
    ├─ release    : no-op（保留缓存，供下次复用）。
    ├─ reset      : 清空缓存（不 close）。
    └─ shutdown   : 清空缓存 + 锁外逐个 close。

【职责边界】
- 只负责：sandbox 的创建 / 缓存 / 查找 / 回收，以及本地组件组合。
- 不负责：runtime / translator / guard 的具体实现（各自独立模块）、
  sandbox 内的命令执行（Sandbox 门面）。
- 持有状态：path_mappings / LRU 容量 / OrderedDict 缓存 / 线程锁 / allow_host_bash。

## 0. 结构树

### 0.1. 静态结构树

```
local_sandbox_provider.py — LocalSandboxProvider（本地沙箱 provider：LRU 缓存 + 确定性 ID）
│
├─ _DEFAULT_LRU_SIZE = 256                     ← LRU 缓存默认容量
│
├─ _deterministic_sandbox_id(user_id, thread_id) -> str
│   ← 确定性 sandbox_id；作用：同一 (user, thread) 跨进程可推导
│   └─ sha256("{user or 'default'}:{thread or 'default'}")[:8]
│
└─ LocalSandboxProvider(SandboxProvider)
    ├─ 类属性
    │   ├─ uses_thread_data_mounts = True
    │   └─ needs_upload_permission_adjustment = False
    │
    ├─ __init__(path_mappings=None, lru_size=256, sandbox_config=None)
    │   ← 初始化；持有映射表 / LRU 容量 / 缓存 / 锁 / allow_host_bash
    │   ├─ _path_mappings: list[PathMapping]
    │   ├─ _lru_size: int
    │   ├─ _sandboxes: OrderedDict[str, Sandbox]  ← LRU 缓存
    │   ├─ _lock: threading.Lock                  ← 保护 _sandboxes 全部读写
    │   └─ _allow_host_bash: bool（从 sandbox_config 读，缺省 True）
    │
    ├─ acquire(thread_id=None, *, user_id=None) -> str
    │   ← 取或建 sandbox；作用：缓存命中则复用，未命中则构造并 LRU 驱逐
    │   ├─ thread_id is None → raise ValueError（Grill #6）
    │   ├─ sandbox_id = _deterministic_sandbox_id(user_id, thread_id)
    │   └─ with _lock:
    │         ├─ 命中 → _sandboxes.move_to_end(sandbox_id) → return
    │         ├─ 未命中 → 组合：
    │         │     ├─ runtime    = LocalRuntime(allow_host_bash=...)
    │         │     ├─ translator = LocalPathTranslator(_path_mappings)
    │         │     ├─ guard      = AuditGuard(LocalSecurityGuard(_path_mappings))
    │         │     └─ sandbox    = Sandbox(sandbox_id, runtime, translator, guard)
    │         │           └─ _sandboxes[sandbox_id] = sandbox
    │         └─ len > _lru_size → popitem(last=False) 取出 evicted（锁内）
    │       evicted 非空 → evicted.close()（锁外，避免持锁阻塞 I/O）
    │
    ├─ get(sandbox_id) -> Sandbox | None
    │   ← 纯内存查找；未命中返回 None
    │   └─ with _lock: return _sandboxes.get(sandbox_id)
    │
    ├─ release(sandbox_id) -> None
    │   ← no-op；作用：保留缓存，供下次 acquire 复用
    │
    ├─ reset() -> None
    │   ← 清空缓存（不 close）
    │   └─ with _lock: _sandboxes.clear()
    │
    └─ shutdown() -> None
        ← 清空缓存 + 锁外逐个 close
        ├─ with _lock: sandboxes = list(...); _sandboxes.clear()
        └─ 锁外 for sandbox in sandboxes: sandbox.close()
```

### 0.2. 运行时调用树

```
① 装配期
LocalSandboxProvider(path_mappings, lru_size, sandbox_config)
    └─ 初始化空 LRU 缓存 + 锁 + allow_host_bash

        ═══════════ 进入 Agent 循环 ═══════════

② 中间件获取 sandbox_id —— acquire(thread_id, user_id)
SandboxMiddleware.wrap_tool_call
    └─ provider.acquire(thread_id, user_id=...)
          ├─ thread_id is None → raise ValueError
          ├─ sandbox_id = sha256("{user}:{thread}")[:8]
          └─ with _lock:
                ├─ [命中缓存]
                │     ├─ move_to_end(sandbox_id)   ← 刷新 LRU 顺序
                │     └─ return sandbox_id
                └─ [未命中]
                      ├─ 构造 LocalRuntime + LocalPathTranslator
                      │        + AuditGuard(LocalSecurityGuard)
                      ├─ Sandbox(sandbox_id, runtime, translator, guard)
                      ├─ _sandboxes[sandbox_id] = sandbox
                      └─ 超容量 → popitem(last=False) 取出 evicted
            （锁外）evicted.close()

③ 工具层取 Sandbox —— get(sandbox_id)
tools.py / _ensure_sandbox
    └─ provider.get(sandbox_id)
          └─ with _lock: _sandboxes.get(sandbox_id)
                ├─ 命中 → return Sandbox
                └─ 未命中 → return None → 抛 SandboxNotFoundError

④ 工具调用结束 —— release(sandbox_id)
（通常由 middleware / 上层调用）
    └─ provider.release(sandbox_id)
          └─ no-op（保留缓存）

⑤ 重置 / 销毁
provider.reset()       ← 清空缓存，不 close
provider.shutdown()    ← 清空缓存 + 锁外逐个 close（进程退出时由 bootstrap 调用）
```

## 1. 补充

**`local_sandbox_provider.py` 是本地沙箱的 provider 实现——它负责"造沙箱、缓存沙箱、按 id 找沙箱"，并通过 LRU + 确定性 ID 控制常驻数量与跨进程可推导性。**

几点补充：

- **确定性 ID 是"跨进程可推导"的关键**：`sha256(user:thread)[:8]`——同一 `(user, thread)` 无论在哪个进程，算出的 `sandbox_id` 都一样。这让"沙箱跨进程恢复"成为可能（`SandboxInfo` 持久化后，别的进程能算回同一 id）。

- **LRU 是"控制常驻数量"的机制**：`OrderedDict` + `move_to_end` + `popitem(last=False)` 实现经典 LRU。命中时 `move_to_end` 刷新为"最新"，超容量时 `popitem(last=False)` 淘汰"最旧"。

- **锁的粒度是"锁内 pop、锁外 close"**：
  - `_lock` 保护 `_sandboxes` 的**全部读写**（严重1 修复）。
  - 但 `close()` 放在**锁外**——因为 `close` 可能阻塞 I/O，持锁会拖住其他线程。
  - 注释里点明："被驱逐 sandbox 可能正被别线程用，但 `LocalRuntime.close` 是 no-op，不会炸"——本地 runtime 的 close 无副作用，所以锁外关安全。

- **`release` 是 no-op，`reset` 只清不关，`shutdown` 才真关**：
  - `release` — 保留缓存，下次复用（**不是"释放"**，名字有误导性）。
  - `reset` — 清空缓存但**不 close**（测试 / 重置场景用）。
  - `shutdown` — 清空 + **逐个 close**（进程退出时由 `bootstrap_sandbox` 调）。

- **本地组合 = LocalRuntime + LocalPathTranslator + AuditGuard(LocalSecurityGuard)**：
  - `LocalRuntime` — 本地"保活"（几乎 no-op）。
  - `LocalPathTranslator` — 双向路径翻译。
  - `AuditGuard(LocalSecurityGuard)` — 审计 + 本地严格守卫组合。
  这正是你前面看的 guard / translator / runtime 三条线的**装配点**。

- **`get` 是纯内存查找**：不加额外副作用，只 `with _lock: return _sandboxes.get(...)`——事件循环安全（不会阻塞 I/O）。

- **`_lock` 是 `threading.Lock` 而非 `asyncio.Lock`**：说明 provider 设计为**多线程共享**（不同线程可能同时 `acquire` / `get`），用线程锁保证 `_sandboxes` 一致。
