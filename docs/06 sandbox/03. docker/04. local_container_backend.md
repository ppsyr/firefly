---

name: LocalContainerBackend — 本地容器基础设施 CRUD（Docker / Apple Container CLI）。

description: 

【整体职责】
实现 SandboxBackend 契约的"本地容器版本"：用 docker / Apple Container CLI 管理
沙箱容器的创建 / 发现 / 存活检查 / 批量列举 / 销毁，以及端口分配与跨进程发现。
不依赖 Docker SDK，直接用 subprocess 调 CLI，减少第三方依赖。
被 DockerSandboxProvider 用作底层基础设施层。

【内容摘要】
- 模块常量：
    _DEFAULT_IMAGE                 : 默认镜像（all-in-one-sandbox:latest）。
    _CONTAINER_PORT                : 容器内服务端口（8080）。
    _VIRTUAL_PATH_PREFIX           : 容器内虚拟路径前缀（/mnt/poirot/user-data）。
    _MAX_PORT_RETRIES              : 端口重试上限（10）。
    _DOCKER_TIMESTAMP_SENTINEL     : 时间戳解析失败时的哨兵值（0.0）。
- 模块函数：
    _parse_docker_timestamp        : 解析 Docker ISO 8601 时间戳（纳秒 + Z）。
    _extract_host_port             : 从 docker inspect 条目提 host port。
    _format_mount                  : 格式化 bind mount（Docker --mount / Apple -v）。
    _get_free_port                 : bind 探测空闲端口。
    _is_no_such_container_error    : 判定 stderr 是否明确"容器不存在"。
- LocalContainerBackend            : 本地容器后端类。
    ├─ __init__ / _detect_runtime / _container_name
    ├─ create          : 幂等创建容器（端口重试循环）。
    ├─ _start_container: 拼 docker run 命令并执行。
    ├─ discover        : 按确定性 ID 查已有容器（跨进程恢复）。
    ├─ _get_container_port: docker port 查 host port。
    ├─ destroy         : 幂等静默停止容器（--rm 自动移除）。
    ├─ is_alive        : 轻量 docker inspect，返 True / False / None。
    ├─ list_running    : batch docker inspect（2 次 subprocess，非 N+1）。
    └─ _batch_inspect  : 单次 docker inspect *names → dict。

【职责边界】
- 只负责：容器基础设施 CRUD（create / discover / destroy / is_alive / list_running）。
- 不负责：容器内命令执行（DockerRuntime）、生命周期编排 / 缓存 / idle（provider）、
  路径翻译（translator）、安全校验（guard）。
- 持有状态：镜像 / 端口 / 前缀 / sandbox_root / environment / executor / runtime 类型。

## 0. 结构树

### 0.1. 静态结构树

```
local_container_backend.py — LocalContainerBackend（Docker / Apple Container CLI 基础设施 CRUD）
│
├─ logger                                      ← 模块 logger
│
├─ 模块常量
│   ├─ _DEFAULT_IMAGE = "all-in-one-sandbox:latest"
│   ├─ _CONTAINER_PORT = 8080                  ← 容器内服务端口
│   ├─ _VIRTUAL_PATH_PREFIX = "/mnt/poirot/user-data"
│   ├─ _MAX_PORT_RETRIES = 10                  ← 端口重试上限
│   └─ _DOCKER_TIMESTAMP_SENTINEL = 0.0        ← 时间戳解析失败哨兵
│
├─ 模块函数
│   ├─ _parse_docker_timestamp(raw) -> float   ← 解析 Docker ISO 8601（纳秒 + Z）
│   ├─ _extract_host_port(entry, port) -> int | None
│   │   ← 从 docker inspect 条目提 host port
│   ├─ _format_mount(runtime, host, container, read_only) -> list[str]
│   │   ├─ docker → ["--mount", "type=bind,src=...,dst=...[,readonly]"]
│   │   └─ container → ["-v", "host:container[:ro]"]
│   ├─ _get_free_port(start_port) -> int       ← bind 探测空闲端口
│   └─ _is_no_such_container_error(stderr, name) -> bool
│       ← 区分"容器不存在"与 transient 错误
│
└─ LocalContainerBackend(SandboxBackend)
    ├─ 状态
    │   ├─ _image / _base_port / _prefix
    │   ├─ _sandbox_root: Path
    │   ├─ _environment: dict
    │   ├─ _executor: DockerExecutor
    │   └─ _runtime: str                       ← "docker" | "container"
    │
    ├─ __init__(image, base_port, container_prefix, sandbox_root,
    │           environment, executor)
    │
    ├─ _detect_runtime() -> str                ← macOS 优先 Apple Container
    ├─ _container_name(sandbox_id) -> str      ← {prefix}-{sandbox_id}
    │
    ├─ ── 创建 ──────────────────────────────────
    ├─ create(thread_id, sandbox_id, extra_mounts, *, user_id) -> SandboxInfo
    │   ├─ validate_sandbox_id
    │   ├─ discover 幂等检查（已存在 → 复用）
    │   └─ 端口 retry loop（10 次）：
    │         ├─ _get_free_port → _start_container
    │         ├─ 端口冲突 → next_start = port + 1，continue
    │         └─ 名称冲突 → discover 复用
    │
    ├─ _start_container(name, port, sandbox_id, thread_id, extra_mounts) -> str
    │   ← 拼 docker run 命令并执行
    │   ├─ docker: --security-opt seccomp=unconfined + bind_host
    │   ├─ --rm -d -p port --name
    │   ├─ -e SANDBOX_ID / THREAD_ID + 自定义 environment
    │   ├─ bind mount sandbox_root/{sandbox_id} → /mnt/poirot/user-data
    │   ├─ 追加 extra_mounts
    │   └─ executor.run → container_id
    │
    ├─ ── 发现 / 查询 ──────────────────────────
    ├─ discover(sandbox_id) -> SandboxInfo | None
    │   ← 按确定性 ID 查已有实例；不存在 / 未运行 / 无端口 → None
    │
    ├─ _get_container_port(name) -> int | None ← docker port 查 host port
    │
    ├─ is_alive(info) -> bool | None           ← 轻量 inspect
    │   ├─ returncode == 0 → 运行? True : False
    │   ├─ 容器不存在     → False
    │   └─ 其他（transient）→ None（不误杀）
    │
    ├─ list_running() -> list[SandboxInfo]      ← batch inspect（2 次 subprocess）
    │   ├─ docker ps --filter name={prefix}-
    │   └─ _batch_inspect(names)

    ├─ _batch_inspect(names) -> dict[name, (created_at, host_port)]
    │   ← 单次 docker inspect *names → JSON 解析
    │
```

### 0.3. 运行时调用树

```
① 装配期
LocalContainerBackend(image, base_port, container_prefix, sandbox_root,
                      environment, executor)
    └─ _detect_runtime()             ← macOS 试 "container --version"，失败回退 docker

        ═══════════ 进入 Agent 循环 ═══════════

② 创建容器 —— provider._create_sandbox → backend.create(...)
create(thread_id, sandbox_id, extra_mounts, user_id)
    ├─ validate_sandbox_id
    ├─ discover(sandbox_id)          ← 幂等检查
    │     └─ 已存在 → 直接返回 SandboxInfo
    └─ 端口 retry loop（最多 10 次）：
          ├─ port = _get_free_port(next_start)
          └─ _start_container(name, port, ...)
                ├─ docker run --security-opt seccomp=unconfined
                │            --rm -d -p {bind_host}:{port}:8080
                │            --name {prefix}-{sandbox_id}
                │            -e SANDBOX_ID -e THREAD_ID + environment
                │            --mount type=bind,src={host_data},dst=/mnt/poirot/user-data
                │            {image}
                ├─ 成功 → 返回 container_id
                └─ 失败 → RuntimeError：
                      ├─ 端口冲突 → 换端口 continue
                      └─ 名称冲突 → discover 复用

③ 发现已有容器 —— provider._discover_or_create → backend.discover(...)
discover(sandbox_id)
    ├─ validate_sandbox_id
    ├─ docker inspect -f {{.State.Running}} {name}
    │     ├─ returncode != 0 → None（不存在）
    │     └─ stdout != "true" → None（未运行）
    └─ _get_container_port(name)
          ├─ None → None
          └─ 有 → SandboxInfo(sandbox_id, url, name)

④ 探活 —— provider._reuse_in_process / _reclaim_warm → backend.is_alive(...)
is_alive(info)
    ├─ docker inspect -f {{.State.Running}} {name}
    ├─ returncode == 0 → True / False
    ├─ _is_no_such_container_error → False
    └─ 其他（超时 / 文件缺失）→ None（不误杀）

⑤ 孤儿对账 —— provider._reconcile_orphans → backend.list_running()
list_running()
    ├─ docker ps --filter name={prefix}- --format {{.Names}}
    ├─ names = 过滤 {prefix}- 开头
    └─ _batch_inspect(names)
          ├─ docker inspect *names（一次调用）
          ├─ JSON 解析 → 每项 (Created, host_port)
          └─ 组装 list[SandboxInfo]

⑥ 销毁 —— provider._destroy_active / _drop_unhealthy → backend.destroy(...)
destroy(info)
    ├─ target = info.container_id or info.container_name
    ├─ docker stop {target}         ← --rm 自动移除，不调 docker rm
    └─ 异常仅 warning，不抛（幂等静默）
```

## 1. 补充

**`local_container_backend.py` 是 Docker 沙箱的"容器基础设施层"——它只负责"造容器 / 找容器 / 探活 / 列举 / 停容器"这五件事，用 `docker` / `container` CLI 实现，不依赖 Docker SDK。**

几点补充：

- **它是 `SandboxBackend` 契约的"本地容器"实现**：上层 `DockerSandboxProvider` 通过它管理容器；下层 `DockerExecutor` 负责把命令落到 CLI（本机或 WSL）。

- **`create` 幂等的两层保护**：
  - 进函数先 `discover`——已存在则直接复用。
  - 端口重试循环里遇到**容器名冲突**，也 `discover` 复用。
  这样即使并发的多个进程同时创建，也不会产生重复容器。

- **端口重试是"bind→release→run 竞态"的兜底**：`_get_free_port` 先 bind 一个空闲端口，但 release 后到 `docker run` 之间可能被别人抢占；如果 `docker run` 报"端口已分配"，就换下一个端口重试，最多 10 次。

- **`--rm` 简化了销毁逻辑**：容器停止后自动移除，所以 `destroy` 只 `stop` 不 `rm`——这让 `destroy` 天然幂等（多次 `stop` 一个已停的容器不会报错）。

- **`is_alive` 的三态设计是"不误杀"的关键**：
  - `True` — 容器在运行。
  - `False` — 容器明确不存在（`_is_no_such_container_error` 判定）。
  - `None` — 未知（超时 / 文件缺失 / transient 错误）——**不判死**，避免误杀正在启动的容器。

- **`list_running` 的"batch inspect"是性能关键**：不是对每个容器单独 `inspect`（N+1），而是 `docker ps` 拿名单后**一次 `docker inspect *names`**——**2 次 subprocess**，不是 N 次。

- **`_format_mount` 区分 Docker / Apple Container**：
  - **Docker** 用 `--mount type=bind,src=...,dst=...`——避免 Windows 盘符 `C:` 和 `-v host:container` 的 `:` 歧义。
  - **Apple Container** 用 `-v host:container[:ro]`——它不支持 `--mount`。

- **`_detect_runtime` 的 mac 优先策略**：macOS 上先试 `container --version`（Apple Container），失败回退 `docker`——因为 Apple Container 在 mac 上性能更好。

- **安全相关细节**：
  - `--security-opt seccomp=unconfined`——允许容器内某些系统调用（Docker 特有）。
  - `POIROT_SANDBOX_BIND_HOST`（默认 `127.0.0.1`）——端口只绑本机，不对外暴露。

- **`_is_no_such_container_error` 的存在意义**：Docker 的错误信息多样（`no such object` / `no such container` / `not found` + 各种上下文），直接匹配 `not found` 可能误判 transient 错误；这个函数**多条件联合判定**，只在明确"容器不存在"时返回 `True`。

- **`_batch_inspect` 的容错**：`json.loads` 失败、`returncode != 0`、`subprocess` 异常——全部返回空 dict，**不抛异常**。因为它是"尽力而为"的信息收集，失败不影响主流程（孤儿对账拿不到信息就跳过）。
