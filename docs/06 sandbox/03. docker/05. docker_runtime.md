---

name: DockerRuntime — 通过 agent_sandbox SDK 调容器内 AIO runtime。

description: 

【整体职责】
实现 sandbox_runtime 契约的"Docker 版本"：用 agent_sandbox SDK（Fern 生成，sync）
通过 HTTP 调容器内 all-in-one-sandbox 镜像，完成命令执行与文件操作。
容器内 AIO runtime 接收虚拟路径（/mnt/poirot/user-data/...），本层不翻译路径
（配合 IdentityTranslator / DockerPathTranslator 的正向直传使用）。
所有异常统一包装成 SandboxError 子类（Grill #5）。

【内容摘要】
- 模块常量：
    _MAX_DOWNLOAD_SIZE            : 下载大小上限（100 MB）。
    _DEFAULT_NO_CHANGE_TIMEOUT    : SDK 无变更超时（1800 秒）。
    _ERROR_OBSERVATION_SIGNATURE  : 检测 SDK 已知 bug 的特征串。
    VIRTUAL_PATH_PREFIX           : 容器内虚拟路径前缀（/mnt/poirot/user-data）。
- DockerRuntime : 容器 runtime 类。
    ├─ __init__      : 建 AioSandboxClient + 锁 + closed 标记。
    ├─ exec_command  : 执行命令（锁内串行；ErrorObservation 自动重试）。
    ├─ read_file     : 读文本文件。
    ├─ write_file    : 写 / 追加文本文件。
    ├─ list_dir      : 列目录（走 shell find，无专用端点）。
    ├─ glob          : 按 pattern 匹配（find_files / list_path 两条路径）。
    ├─ grep          : 内容搜索（list_path + 逐文件 search_in_file 客户端编排）。
    ├─ download_file : 下载二进制（路径遍历检查 + 大小上限）。
    ├─ update_file   : 上传二进制（base64 编码）。
    └─ close         : Best-effort 关底层 httpx.Client（遍历属性链）。

【职责边界】
- 只负责：把容器能力封装成 runtime 方法 + 异常包装 + 并发保护。
- 不负责：路径翻译（translator）、安全校验（guard）、容器生命周期（provider）。
- 持有 SDK client + 线程锁 + closed 标记；client 在 close 后置 None。

## 0. 结构树

### 0.1. 静态结构树

```
docker_runtime.py — DockerRuntime（agent_sandbox SDK 调容器内 AIO runtime）
│
├─ logger                                      ← 模块 logger
│
├─ 模块常量
│   ├─ _MAX_DOWNLOAD_SIZE = 100 MB             ← 下载大小上限
│   ├─ _DEFAULT_NO_CHANGE_TIMEOUT = 1800       ← SDK 无变更超时（秒）
│   ├─ _ERROR_OBSERVATION_SIGNATURE            ← SDK 已知 bug 特征串
│   │     "'ErrorObservation' object has no attribute 'exit_code'"
│   └─ VIRTUAL_PATH_PREFIX = "/mnt/poirot/user-data"  ← 容器内虚拟路径前缀
│
└─ DockerRuntime
    ├─ _url: str                              ← sandbox_url
    ├─ _client: AioSandboxClient | None       ← SDK client（close 后置 None）
    ├─ _lock: threading.Lock                  ← 串行化容器操作
    ├─ _closed: bool                          ← 关闭标记
    │
    ├─ __init__(sandbox_url)
    │   └─ AioSandboxClient(base_url, timeout=1800) + 锁 + closed=False
    │
    ├─ exec_command(command) -> str           ← 执行命令
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   ├─ 检测 ErrorObservation 签名：
    │   │     └─ 命中 → 建 fresh session 重试一次（finally cleanup_session）
    │   ├─ 重试后仍命中 → raise SandboxCommandError
    │   ├─ 空输出 → 返回 "(no output)"
    │   └─ 其他异常 → raise SandboxCommandError(exit_code=-1)
    │
    ├─ read_file(path) -> str                 ← 读文本
    │   ├─ 错误信息含 "not found"/"no such file" → SandboxFileNotFoundError
    │   ├─ 含 "permission denied"/"403"          → SandboxPermissionError
    │   └─ 其他                                    → SandboxFileError
    │
    ├─ write_file(path, content, append=False) ← 写/追加文本
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   └─ 错误信息匹配 → SandboxPermissionError / SandboxFileError
    │
    ├─ list_dir(path, max_depth=2) -> list[str] ← 列目录（走 shell find）
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   └─ find {path} -maxdepth N -type f -o -type d | head -500
    │
    ├─ glob(path, pattern, *, include_dirs=False, max_results=200)
    │   -> (list[str], bool)                  ← 匹配，返回 (matches, truncated)
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   ├─ include_dirs=False → SDK find_files（只返文件）
    │   └─ include_dirs=True  → SDK list_path + 客户端 fnmatch 过滤
    │
    ├─ grep(path, pattern, *, glob=None, literal=False,
    │        case_sensitive=False, max_results=100)
    │   -> (list[GrepMatch], bool)             ← 内容搜索（客户端编排）
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   ├─ literal=True → re.escape；否则原 pattern
    │   ├─ 候选文件：glob 指定走 find_files；否则 list_path 过滤目录
    │   ├─ 逐文件 search_in_file → GrepMatch（truncate_line）
    │   └─ should_ignore_path 过滤
    │
    ├─ download_file(path) -> bytes            ← 下载二进制
    │   ├─ 路径遍历检查：任一段 ".." → SandboxPermissionError
    │   ├─ 前缀校验：必须落 VIRTUAL_PATH_PREFIX → 否则 SandboxPermissionError
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   └─ 流式下载，累计 > 100MB → SandboxFileError
    │
    ├─ update_file(path, content: bytes)       ← 上传二进制
    │   ├─ _closed → raise SandboxRuntimeError
    │   ├─ _lock 串行化
    │   └─ base64 编码 → write_file(encoding="base64")
    │
    └─ close() -> None                         ← Best-effort 关底层 httpx.Client
        ├─ _lock 内：_closed=True；client = _client；_client = None
        ├─ 遍历属性链找可 close 对象：
        │     client._client_wrapper.httpx_client.httpx_client
        │       └─ 依次尝试 (real_httpx, fern_http, client) 中第一个有 close 的
        ├─ 找不到 → logger.debug 返回
        └─ 关闭异常 → logger.warning（不阻断）
```

### 0.2. 与本地 runtime 的对照

```
【命令执行】
    本地 LocalRuntime  → subprocess.run(shell=True) 直接在宿主跑
    Docker DockerRuntime → SDK shell.exec_command 走 HTTP 调容器内 AIO

【文件操作】
    本地 → Path(path).read_text() / write_text() 直接操作宿主 FS
    Docker → SDK file.read_file / write_file / list_path / search_in_file

【并发保护】
    本地 → 无锁（subprocess 每次独立进程）
    Docker → _lock 串行化（防并发破坏持久 shell session）

【关闭】
    本地 close  → no-op（subprocess 无持久连接）
    Docker close → 遍历属性链找 httpx.Client.close()（SDK 不暴露）

【路径处理】
    本地 → 接收已翻译的物理路径
    Docker → 接收虚拟路径（容器内 AIO 自己认），DockerRuntime 不翻译
```

### 0.3. 运行时调用树

```
① 装配期
DockerSandboxProvider._make_sandbox(sandbox_id, info)
    └─ DockerRuntime(info.sandbox_url)
          └─ AioSandboxClient(base_url=sandbox_url, timeout=1800)

        ═══════════ 进入命令执行 ═══════════

② Sandbox.execute_command(cmd)
    └─ runtime.exec_command(cmd)
          ├─ _closed → raise SandboxRuntimeError
          ├─ with _lock:
          │     ├─ SDK shell.exec_command(command, no_change_timeout=1800)
          │     ├─ 命中 ErrorObservation 签名：
          │     │     ├─ create_session(fresh_id)
          │     │     ├─ exec_command(command, id=fresh_id) 重试
          │     │     └─ finally cleanup_session(fresh_id)
          │     ├─ 重试后仍命中 → raise SandboxCommandError
          │     ├─ 空输出 → return "(no output)"
          │     └─ 其他异常 → raise SandboxCommandError(exit_code=-1)
          └─ 返回 output 给 Sandbox 门面

③ Sandbox.read_file / write_file / list_dir / glob / grep / download / update
    └─ runtime.<method>(...)
          ├─ 均先检查 _closed
          ├─ 均 with _lock（write / list / glob / grep / download / update）
          ├─ 异常统一包装为 SandboxError 子类
          └─ download_file 额外做路径遍历 + 前缀 + 大小检查

④ Sandbox 销毁 —— provider.release() / _destroy_active()
    └─ sandbox.close()
          └─ runtime.close()
                ├─ _lock 内标记 _closed + 摘除 client 引用
                └─ 锁外遍历属性链找 httpx.Client.close()（失败不阻断）
```

## 1. 补充

**`docker_runtime.py` 是 Docker 沙箱的"远程执行引擎"——它不像 `LocalRuntime` 那样直接操作本机，而是通过 `agent_sandbox` SDK 经 HTTP 调容器内的 all-in-one-sandbox 服务。**

几点补充：

- **"SDK 调容器"是本文件的核心定位**：
  - `LocalRuntime` —— `subprocess.run` 直接在宿主执行。
  - `DockerRuntime` —— `AioSandboxClient` 经 HTTP 调容器内 AIO runtime。
  命令和文件操作**都发生在容器内**，本机只发 HTTP 请求。

- **`_lock` 串行化是 Docker 特有需求**：本地 runtime 每次 `subprocess` 是独立进程，无需锁；Docker runtime 共享**一个持久 shell session**，并发调用会破坏 session（#1433），所以除 `read_file` 外都加锁。

- **`read_file` 没加锁，其他方法都加了**：因为读文件不共享 shell session，安全；写、执行、列目录、glob、grep、下载、上传都共享 session，必须串行。

- **`exec_command` 的 ErrorObservation 重试是"SDK bug 兜底"**：SDK 偶发返回 `"'ErrorObservation' object has no attribute 'exit_code'"`（SDK 内部 bug），检测到这个签名就**建一个新 session 重试一次**；重试后仍命中才抛错。这是仿 deer-flow 的做法。

- **`close` 是"属性链挖掘"**：SDK 不暴露 `close()`，真实 socket owner 藏在 `_client._client_wrapper.httpx_client.httpx_client`。本方法**逐层 getattr** 找到第一个有 `close()` 的对象并关闭，失败只 warning 不阻断（#2872）。

- **`download_file` 有两道检查 + 一道限额**：
  - **路径遍历**：任一段为 `..` 即拒。
  - **前缀校验**：必须落 `VIRTUAL_PATH_PREFIX`（`/mnt/poirot/user-data`）。
  - **大小限额**：流式累计超 100MB 即拒。

- **`glob` / `grep` 的"客户端编排"**：
  - 容器内**没有服务端 grep**——`grep` 是"先列候选文件，再逐文件 `search_in_file`"的客户端循环。
  - `glob` 有两条路径：`include_dirs=False` 走 SDK `find_files`；`include_dirs=True` 走 `list_path` + 客户端 `fnmatch`。

- **`list_dir` 走 shell `find`**：容器内没有专用"列目录"端点，用 `find` + `head -500` 兜底。

- **路径不翻译**：容器内 AIO runtime 直接认 `/mnt/poirot/user-data/...` 虚拟路径——`DockerRuntime` 不做任何翻译，这正是 `DockerPathTranslator` 正向直传的原因。

- **`_closed` 是统一防线**：`close()` 置 `_closed=True` 后，所有需要 client 的方法都抛 `SandboxRuntimeError("runtime already closed")`——避免"关闭后误用"。

- **与本地 runtime 的复杂度对比**：

| 维度 | LocalRuntime | DockerRuntime |
|---|---|---|
| 执行方式 | `subprocess.run` 本机 | SDK HTTP 调容器 |
| 并发保护 | 无锁 | `_lock` 串行化 |
| 关闭 | no-op | 属性链挖 `httpx.Client.close()` |
| 异常来源 | 内置异常（`FileNotFoundError` 等） | SDK 异常 + 字符串匹配 |
| 路径 | 接收已翻译的物理路径 | 接收虚拟路径，不翻译 |
| 特殊兜底 | 无 | ErrorObservation 重试（#1433 / #2872） |
