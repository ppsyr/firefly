---

name: DockerSandboxProvider — Docker 容器生命周期管理 + warm_pool + idle_checker。

description: 

【整体职责】
实现 SandboxProvider 契约的"Docker 版本"：编排容器化沙箱的全生命周期——
三层缓存（in-process → warm_pool → cross-process lock + discover/create）、
容器创建/就绪/销毁、空闲回收、孤儿对账、信号清理。
组合 LocalContainerBackend（基础设施 CRUD）+ DockerRuntime（HTTP 调容器）
+ DockerPathTranslator + AuditGuard(DockerPathGuard)。

【内容摘要】
- 模块常量：
    _DEFAULT_IDLE_TIMEOUT  : 空闲超时默认值（600 秒）。
    _DEFAULT_REPLICAS      : 副本软上限默认值（3）。
    _IDLE_CHECK_INTERVAL   : idle_checker 扫描间隔（60 秒）。
- 模块函数：
    _deterministic_sandbox_id : 确定性 sandbox_id = sha256(user:thread)[:8]。
- DockerSandboxProvider       : Docker provider 类。
    ├─ __init__ / _make_executor / _make_sandbox / _register / _get_thread_lock
    ├─ acquire / acquire_async
    ├─ _acquire_internal / _acquire_internal_async
    ├─ _reuse_in_process        : Layer 1 —— in-process 缓存复用 + 健康检查。
    ├─ _reclaim_warm            : Layer 1.5 —— warm_pool 回收。
    ├─ get / get_sandbox_info   : 查询（get 会刷新 last_activity）。
    ├─ _drop_unhealthy          : 移除不健康 sandbox + 二次校验后 destroy。
    ├─ _discover_or_create(_async) : Layer 2 —— 跨进程锁 + discover/create。
    ├─ _create_sandbox(_async)  : 创建容器 + readiness 等待 + 注册。
    ├─ _enforce_replicas / _evict_oldest_warm : 副本软上限控制。
    ├─ release                  : 移入 warm_pool（不销毁）。
    ├─ shutdown / _destroy_active : 清空 active + warm。
    ├─ _start_idle_checker / _idle_checker_loop / _cleanup_idle : 空闲回收。
    ├─ _reconcile_orphans       : 启动时对账孤儿容器。
    └─ _register_signal_handlers: SIGTERM / SIGINT / SIGHUP 清理。

【职责边界】
- 只负责：容器化沙箱的创建 / 复用 / 回收 / 销毁，以及各组件组合。
- 不负责：容器基础设施 CRUD 的具体实现（LocalContainerBackend）、
  HTTP 调容器（DockerRuntime）、路径翻译（translator）、安全校验（guard）。
- 持有大量进程内状态：三层缓存 + 每线程锁 + idle_checker 线程 + 关闭标记。

├─ 模块常量

│   ├─ _DEFAULT_REPLICAS = 3                   ← 副本软上限默认值
│   └─ _IDLE_CHECK_INTERVAL = 60               ← idle_checker 扫描间隔（秒）

    │   ← 异步版
    │

    │   ← total(active + warm) >= replicas → evict_oldest_warm
    │
    ├─ _evict_oldest_warm()

    │

### 0.2. 三层缓存 + warm_pool 结构

```
【acquire 的三层查找顺序】—— _acquire_internal

    Layer 1: in-process 缓存
        _reuse_in_process(thread_id, user_id)
            ├─ _thread_sandboxes 命中 → 探活 → 返回
            └─ 未命中 → 下一层
                  │
                  ▼
    Layer 1.5: warm_pool
        _reclaim_warm(thread_id, sandbox_id, user_id)
            ├─ _warm_pool 命中 → 探活 → 转入 active
            └─ 未命中 → 下一层
                  │
                  ▼
    Layer 2: cross-process lock + discover/create
        _discover_or_create(thread_id, sandbox_id, user_id)
            ├─ validate_sandbox_id
            ├─ open_lock_file + lock_file_exclusive   ← 跨进程锁
            ├─ 再次 _reuse_in_process（锁内复查）
            ├─ discover → 命中则 _register
            └─ 未命中 → _create_sandbox

【三层缓存的数据结构】

    active（运行中、被线程绑定）：
        _sandboxes:     sandbox_id → Sandbox
        _sandbox_infos: sandbox_id → SandboxInfo
        _thread_sandboxes: (user, thread) → sandbox_id
        _last_activity: sandbox_id → 时间戳

    warm（已释放、容器仍在跑）：
        _warm_pool:     sandbox_id → (SandboxInfo, release_ts)
```

### 0.3. 运行时调用树

```
① 装配期
DockerSandboxProvider(path_mappings, sandbox_config, ...)
    ├─ 构造 LocalContainerBackend
    ├─ _reconcile_orphans()          ← 对账启动前遗留容器 → warm_pool
    ├─ _start_idle_checker()         ← 启守护线程（60s 间隔）
    └─ _register_signal_handlers()   ← SIGTERM / SIGINT / SIGHUP

        ═══════════ 进入 Agent 循环 ═══════════

② 取或建沙箱 —— acquire(thread_id, user_id)
SandboxMiddleware.wrap_tool_call
    └─ provider.acquire(thread_id, user_id)
          ├─ thread_id is None → raise ValueError
          ├─ thread_lock = _get_thread_lock(...)
          └─ with thread_lock:
                └─ _acquire_internal(thread_id, user_id)
                      ├─ Layer 1: _reuse_in_process
                      │     ├─ 命中 → 探活 → 返回
                      │     └─ 不健康 → _drop_unhealthy（S7 二次校验后 destroy）
                      ├─ Layer 1.5: _reclaim_warm
                      │     ├─ 命中 → 探活 → 转入 active
                      │     └─ 不健康 → _drop_unhealthy
                      └─ Layer 2: _discover_or_create
                            ├─ validate_sandbox_id
                            ├─ open_lock_file → lock_file_exclusive
                            ├─ _reuse_in_process（锁内复查）
                            ├─ _backend.discover → 命中 → _register
                            └─ 未命中 → _create_sandbox
                                  ├─ _enforce_replicas → 可能 _evict_oldest_warm
                                  ├─ _backend.create → SandboxInfo
                                  ├─ wait_for_sandbox_ready(60s)
                                  │     └─ 失败 → destroy + raise
                                  └─ _register → _make_sandbox + 入 active

③ 一次 bash 调用
tools.py bash_tool(cmd)
    └─ _ensure_sandbox(provider)
          ├─ get_sandbox_id()          ← ContextVar
          └─ provider.get(sandbox_id)  ← 命中刷新 last_activity
                └─ Sandbox.execute_command(cmd)
                      └─ runtime/translator/guard（均为 Docker 版）

④ 释放 —— release(sandbox_id)
    ├─ 从 active 移除（_sandboxes / _sandbox_infos / _thread_sandboxes）
    ├─ sandbox.close()
    └─ 转入 _warm_pool[sandbox_id] = (info, now)
        （容器保持运行，供下次 _reclaim_warm 复用）

⑤ idle_checker 后台 —— 每 60s
_idle_checker_loop()
    └─ _cleanup_idle()
          ├─ active 超 idle_timeout → 二次确认 → _destroy_active
          └─ warm 超 idle_timeout   → _backend.destroy

⑥ 进程退出
shutdown()
    ├─ 停 idle_checker 线程（join 5s）
    ├─ 逐个 _destroy_active（S7 二次校验）
    └─ 逐个 _backend.destroy（warm）
```

## 1. 补充

**`docker_sandbox_provider.py` 是 Docker 沙箱的 provider 实现——它比本地 provider 复杂得多，因为它要管"容器生命周期"（创建 / 就绪 / 复用 / 回收 / 销毁）+ "跨进程协调"（跨进程锁 + 孤儿对账）+ "空闲回收"（idle_checker）。**

几点补充：

- **三层缓存是本文件的核心结构**：
  - **Layer 1（in-process）**——`_reuse_in_process`：最快，命中即返回，附一次探活。
  - **Layer 1.5（warm_pool）**——`_reclaim_warm`：容器已释放但仍在跑，可快速"复活"。
  - **Layer 2（cross-process lock + discover/create）**——`_discover_or_create`：最慢，需要跨进程锁保护，先 `discover` 复用已有容器，没有才 `create`。

- **`release` 的语义和本地完全不同**：
  - **本地**：`release` 是 no-op（保留缓存）。
  - **Docker**：`release` 是**移出 active → 转入 warm_pool**（容器**继续运行**，不销毁）。
  这是为了"下次 `acquire` 能快速复用"——避免反复启停容器。

- **warm_pool 有两个入口**：
  - `release` —— 主动释放时转入。
  - `_reconcile_orphans` —— **进程启动时**把上次遗留的容器 adopt 进来（防止孤儿容器泄漏）。

- **warm_pool 有两个出口**：
  - `_reclaim_warm` —— 被 `acquire` 复用，转回 active。
  - `_evict_oldest_warm` / `_cleanup_idle` —— 被驱逐 / 超时销毁。

- **S5 修复（`acquire_async`）**：`acquire` 必须在 `try` 块内，用 `acquired` flag 判断"是否已持有锁"——因为 `cancel` 可能在等待锁期间抛出，如果无脑 `release` 会 `RuntimeError`（释放未持有的锁）。

- **S7 修复（`destroy` 前二次 discover）**：`_drop_unhealthy` / `_destroy_active` 在真正 `destroy` 前，会再 `discover` 一次比对 `info`——若容器已被别线程用同 ID 重建（`current_info != expected_info`），**跳过 destroy**，避免误杀新容器。

- **`_cleanup_idle` 的"二次确认"**：收集 active 空闲项后、销毁前，再查一次 `_last_activity`——防止"收集后、销毁前"被其他线程刷新（避免误杀刚被使用的沙箱）。

- **两处锁外操作**：
  - `_drop_unhealthy` / `_destroy_active`：锁内 pop 状态，**锁外** `close` + `destroy`——避免持锁阻塞 I/O。
  - `_evict_oldest_warm`：锁内 pop，**锁外** `destroy`。

- **Docker 组合 = DockerRuntime + DockerPathTranslator + AuditGuard(DockerPathGuard)**：
  - `DockerRuntime(info.sandbox_url)` —— 用 URL 通过 HTTP 调容器。
  - `DockerPathTranslator(self._sandbox_root, sandbox_id)` —— 正向直传 + 反向映射。
  - `AuditGuard(DockerPathGuard())` —— 审计 + Docker 路径守卫。

- **`path_mappings` 不作为 `extra_mounts`**：注释点明"父 bind mount 覆盖"——即虚拟路径的挂载已由父级 bind mount 完成，不需要再通过 `extra_mounts` 重复挂载。`extra_mounts` 只来自 `config.sandbox.mounts`（用户自定义挂载）。

- **信号处理比本地多**：Docker provider 注册 `SIGTERM` / `SIGINT` / `SIGHUP`（因为容器需要显式清理），而本地 provider 只靠 `atexit`（无容器需要清理）。
