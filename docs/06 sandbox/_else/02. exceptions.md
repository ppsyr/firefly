---

name: Sandbox 异常体系 — 统一的沙箱错误类型。

description: 

【整体职责】
定义 sandbox 层所有对外抛出的异常类型，形成一棵以 SandboxError 为根的继承树。
工具层只需 catch SandboxError 即可统一处理，由 ToolCallMiddleware 转 error ToolMessage。
runtime / guard / provider 等实现负责把底层异常（subprocess、FileNotFound 等）
包装成本体系的类型。

【内容摘要】
- SandboxError              : 错误基类，带 details dict，__str__ 自动展开。
- SandboxNotFoundError      : 沙箱找不到。
- SandboxRuntimeError       : runtime 不可用 / 配置错。
- SandboxCommandError       : 命令执行失败（command 自动截断 100 字符）。
- SandboxFileError          : 文件操作失败（path + operation）。
- SandboxPermissionError    : 权限拒绝（继承 SandboxFileError）。
- SandboxFileNotFoundError  : 文件不存在（继承 SandboxFileError）。

【职责边界】
- 只负责：定义异常类型、携带结构化 details、格式化错误信息。
- 不负责：异常抛出时机（runtime / guard / provider）、异常捕获与转换（middleware）。
- 不持有状态：异常对象只承载一次错误的信息，无生命周期。

【异常树结构】
SandboxError
├─ SandboxNotFoundError
├─ SandboxRuntimeError
├─ SandboxCommandError
└─ SandboxFileError
    ├─ SandboxPermissionError
    └─ SandboxFileNotFoundError

## 0. 结构树

### 0.1. 静态结构树

```
exceptions.py — Sandbox 异常体系（统一的沙箱错误类型）
│
├─ SandboxError(Exception)                     ← 错误基类；作用：统一沙箱层对外抛出的错误，
│   │                                            带结构化 details，工具层只需 catch 它即可兜底
│   ├─ message: str                            ← 错误信息（人类可读）
│   ├─ details: dict                           ← 结构化数据；供日志 / 上报 / 前端展示
│   │
│   ├─ __init__(message, *, details=None)      ← 初始化；details 缺省为空 dict
│   └─ __str__() -> str                        ← 格式化；无 details 时只返回 message，
│                                                 否则展开成 message (k=v, ...)
│
├─ SandboxNotFoundError(SandboxError)          ← 沙箱找不到；作用：sandbox_id 无效/已销毁时抛出
│   └─ __init__(sandbox_id)                    ← details = {sandbox_id}
│
├─ SandboxRuntimeError(SandboxError)           ← runtime 不可用 / 配置错；作用：启动/健康检查
│                                                 失败、配置非法时抛出（无额外字段）
│
├─ SandboxCommandError(SandboxError)           ← 命令执行失败；作用：backend 执行命令非预期失败
│   └─ __init__(message, *, command,           ← details = {command(截断100), exit_code}
│                exit_code=None)                   command 超长自动截断，避免撑爆日志
│
└─ SandboxFileError(SandboxError)              ← 文件操作失败；作用：读写/列目录等文件类操作失败
    │   └─ __init__(message, *, path,          ← details = {path, operation}
    │                operation)                    强制携带 path + operation
    │
    ├─ SandboxPermissionError(SandboxFileError)      ← 权限拒绝；继承文件异常（自带 path/op）
    └─ SandboxFileNotFoundError(SandboxFileError)    ← 文件不存在；继承文件异常（自带 path/op）
```

**异常树结构（继承关系一览）**

```
SandboxError
├─ SandboxNotFoundError
├─ SandboxRuntimeError
├─ SandboxCommandError
└─ SandboxFileError
    ├─ SandboxPermissionError
    └─ SandboxFileNotFoundError
```

### 0.2. 运行时调用树

```
① 装配期
（本模块不介入；只定义类型，无初始化、无副作用）

        ═══════════ 进入 Agent 循环 ═══════════

② runtime / provider 抛错 —— 抛出 SandboxRuntimeError / SandboxNotFoundError
SandboxRuntime.start() 失败
    └─ raise SandboxRuntimeError("...", details={...})
SandboxProvider 找不到沙箱
    └─ raise SandboxNotFoundError(sandbox_id)

③ backend 执行命令失败 —— 抛出 SandboxCommandError
backend.execute(...)
    └─ 非零退出 / 异常
          └─ raise SandboxCommandError(msg, command=..., exit_code=...)
                └─ command 超长 → 截断到 100 字符

④ 文件操作失败 —— 抛出 SandboxFileError 及子类
backend.read_file / write_file / list_dir
    ├─ 权限拒绝  → raise SandboxPermissionError(msg, path=..., operation=...)
    ├─ 文件不存在 → raise SandboxFileNotFoundError(msg, path=..., operation=...)
    └─ 其他失败  → raise SandboxFileError(msg, path=..., operation=...)

⑤ guard 拦截 —— 抛出本体系异常（由具体 guard 决定用哪类）
guard.check_command / check_path
    └─ raise SandboxError 子类（如权限/命令类）

⑥ 工具层统一兜底 —— catch SandboxError
ToolCallMiddleware
    └─ except SandboxError as e
          └─ 转 error ToolMessage（details 供展示）

（其余 hook 与本模块无关）
```

## 1. 补充

**`exceptions.py` 是 sandbox 层的"错误词汇表"——所有实现（Local / Docker / K8s）对外抛出的错误都收敛到这棵以 `SandboxError` 为根的继承树，工具层只需 `catch SandboxError` 即可统一处理。**

几点补充：

- **纯类型、无行为**：本文件只有异常类定义，没有任何业务逻辑或副作用。唯一的"行为"是 `SandboxError.__str__` 的格式化与 `SandboxCommandError` 的命令截断——都是为了让日志更可读。
- **`details` 是结构化契约**：不是随便塞的字符串，而是供日志 / 上报 / 前端展示的 dict。各子类通过 `__init__` 强制携带关键字段（`sandbox_id` / `command` / `path` + `operation`），保证错误信息不丢上下文。
- **截断是防爆日志的手段**：`SandboxCommandError` 把 `command` 截到 100 字符（`+ "..."`），避免超长命令撑爆日志——这是 INVARIANT，改的时候别删。
- **文件异常继承链的意义**：`SandboxPermissionError` / `SandboxFileNotFoundError` 继承 `SandboxFileError`，既能被"文件类"统一捕获，又能被"具体类型"精确捕获；同时天然继承了 `path` + `operation` 两个字段，不用重复声明。
- **捕获边界**：工具层只认 `SandboxError` 根，不关心具体子类——这就是"工具层只需 catch SandboxError 即可统一处理"的落地方式。具体子类的区分留给需要精细化处理的调用方（如 middleware 想对权限错误做特殊提示）。
- **抛出时机不在本文件**：本文件只定义"有哪些错误"，"何时抛"由 runtime / guard / provider / backend 决定，"怎么转"由 middleware 决定——职责边界清晰。
