## 1. Translators 总览

Translator 是 sandbox 层的**路径翻译抽象**——负责在「Agent 视角的虚拟路径」和「真实可执行路径」之间做双向映射，并对命令、输出做相应替换。它满足 `contracts/path_translator.py` 契约。

---

## 2. 契约方法（三个核心 + 一个扩展）

### 2.1 契约定义的三个方法

| 方法 | 方向 | 作用 |
|---|---|---|
| `translate_path(virtual_path)` | 正向 | 虚拟路径 → 真实路径 |
| `translate_command(command)` | 正向 | 把命令中的虚拟路径替换成真实路径 |
| `mask_output(output)` | 反向 | 把输出中的真实路径换回虚拟路径（脱敏） |

### 2.2 Docker 特有的扩展方法

| 方法 | 方向 | 作用 |
|---|---|---|
| `reverse_translate(virtual_path)` | 反向 | 虚拟路径 → 宿主机物理路径（artifact 提取用） |

**注意**：`reverse_translate` **不在契约里**，只有 `DockerPathTranslator` 有。它服务于 `Sandbox.get_host_path`——从宿主机拿产物时需要知道文件落在宿主机哪。

---

## 3. 三个 Translator 的定位

### 3.1 IdentityTranslator — 恒等直传

**虚拟路径 == 真实路径时使用，三个方法全部原样返回。**

- 适用：Docker（bind mount 物理对齐）/ E2B（沙箱内路径就是虚拟路径）。
- 无状态：不持有字段，构造无参。

### 3.2 LocalPathTranslator — 双向翻译（本地）

**虚拟路径 ≠ 宿主真实路径，必须靠 `PathMapping` 双向翻译。**

- **正向**：`translate_path` / `translate_command` —— 虚拟 → 物理。
- **反向**：`mask_output` —— 物理 → 虚拟（脱敏，防泄漏宿主目录结构）。
- **规则**：最长前缀优先（前向按 `container_path` 长度降序，反向按 `local_path` 长度降序）。
- **防穿越**：`resolve()` 跟随 symlink 后做越界检测，防止软链逃逸。
- **缓存**：四个 `cached_property` 缓存排序 / `resolve` / 正则编译。

### 3.3 DockerPathTranslator — 正向直传 + 反向映射

**正向三个方法全部直传（容器内路径与虚拟路径对齐），只有反向 `reverse_translate` 做映射。**

- **正向**：`translate_path` / `translate_command` / `mask_output` —— 全部原样返回。
- **反向**：`reverse_translate` —— 虚拟 → 宿主机物理路径（artifact 提取）。
- **前缀校验**：`reverse_translate` 仅接受 `/mnt/poirot/user-data`（精确匹配或带 `/`）。
- **状态**：持有 `_host_root`（由 `sandbox_root + sandbox_id` 构造时拼出，不可变）。

---

## 4. 与 Guard 的职责边界

| | Guard | Translator |
|---|---|---|
| 管什么 | **允不允许**（安全校验） | **路径怎么对应**（映射） |
| 失败 | 抛 `SandboxPermissionError` | 抛 `PermissionError` / `ValueError` |
| 是否做安全决策 | 是 | 否（翻译出越界路径时，最终仍由 guard 决定放不放） |

**两者都用 `/mnt/poirot/user-data` 这个前缀，但一个做校验、一个做翻译，互不替代。**

---

## 5. 总结

**Translator 是 sandbox 的路径翻译抽象，负责虚拟 ↔ 真实路径的双向映射；本地模式双向都复杂（靠 `PathMapping` + 防穿越 + 脱敏），Docker 模式正向直传、只剩反向 `reverse_translate` 一处映射——因为 bind mount 把"路径对齐"从软件层下沉到了挂载层。**
