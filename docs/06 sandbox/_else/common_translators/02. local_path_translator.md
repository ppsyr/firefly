---

name: LocalPathTranslator — 本地路径翻译器（PathMapping 双向翻译 + 输出脱敏）。

description: 

【整体职责】
实现 path_translator 契约的"本地版本"：基于 PathMapping 列表，
在虚拟路径 ↔ 物理路径之间做双向翻译，并对命令、输出做相应替换。
- 正向：虚拟路径 → 物理路径（translate_path / translate_command）
- 反向：物理路径 → 虚拟路径（mask_output，输出脱敏）
用于本地沙箱——虚拟路径与宿主真实路径不一致、必须显式映射的场景。
Docker / E2B 场景改用 IdentityTranslator（路径本就对齐，直传即可）。

【内容摘要】
- LocalPathTranslator                     : 本地路径翻译器类。
    ├─ __init__                              : 持有 PathMapping 列表。
    ├─ _mappings_by_container_specificity    : 按 container_path 长度降序（前向解析用）。
    ├─ _mappings_by_local_specificity        : 按 local_path 长度降序（反向解析用）。
    ├─ _resolved_local_paths                 : 每个 mapping 的 resolve() 后物理路径（缓存 syscall）。
    ├─ _command_pattern                      : 命令中容器路径的正则（shell-aware 边界）。
    ├─ _reverse_output_patterns              : 物理→虚拟的反向正则列表（输出脱敏用）。
    ├─ _resolve_path_with_mapping            : 虚拟路径 → ResolvedPath（物理路径 + 命中 mapping）。
    ├─ translate_path                        : 虚拟路径 → 物理路径。
    ├─ translate_command                     : 命令中的容器路径 → 物理路径。
    └─ mask_output                           : 物理路径 → 虚拟路径（脱敏）。

【职责边界】
- 只负责：虚拟 ↔ 物理路径的双向翻译、命令中的路径替换、输出的反向脱敏。
- 不负责：安全校验（guard）、命令执行（backend）、路径匹配规则的定义
  （由装配层注入 PathMapping）。
- 持有 PathMapping 列表：映射规则来源，构造时注入；翻译规则全由 mapping 决定。

## 0. 结构树

### 0.1. 静态结构树

```
local_path_translator.py — LocalPathTranslator（PathMapping 双向翻译 + 输出脱敏）
│
└─ LocalPathTranslator
    ├─ _mappings: list[PathMapping]            ← 映射表（构造时注入）
    │
    ├─ __init__(path_mappings)                 ← 初始化；持有 mapping 列表
    │
    ├─ @cached_property
    │  _mappings_by_container_specificity      ← 按 container_path 长度降序（前向解析用）
    │      └─ 最长前缀优先，防 /mnt/poirot/skills 误匹配 /mnt/poirot/skills-extra
    │
    ├─ @cached_property
    │  _mappings_by_local_specificity          ← 按 local_path 长度降序（反向解析用）
    │
    ├─ @cached_property
    │  _resolved_local_paths: dict             ← 每个 mapping 的 resolve() 后物理路径
    │      └─ 缓存 syscall，避免重复 resolve
    │
    ├─ @cached_property
    │  _command_pattern: Pattern | None        ← 命令中容器路径的正则（shell-aware 边界）
    │      └─ 边界字符集：/ | $ | 空白 | 引号 | ; & | < > ( )
    │
    ├─ @cached_property
    │  _reverse_output_patterns: list          ← 物理→虚拟的反向正则列表（脱敏用）
    │      └─ 每项 (pattern, mapping, local)：
    │            pattern 匹配 local + 子路径
    │
    ├─ _resolve_path_with_mapping(virtual_path) -> ResolvedPath
    │   ← 虚拟路径 → ResolvedPath（物理路径 + 命中 mapping）
    │   ├─ 按 container_path 最长前缀匹配
    │   ├─ 命中 → resolve + relative_to 越界检测
    │   │     └─ 越界 → raise PermissionError（symlink 防穿越）
    │   └─ 未命中 → ResolvedPath(virtual_path, None)
    │
    ├─ translate_path(virtual_path) -> str      ← 正向：虚拟 → 物理
    │   └─ _resolve_path_with_mapping(...).path
    │
    ├─ translate_command(command) -> str        ← 正向：命令中的容器路径 → 物理路径
    │   ├─ _command_pattern is None → 原样返回
    │   └─ pattern.sub(translate_path, command)
    │
    └─ mask_output(output) -> str               ← 反向：物理 → 虚拟（脱敏）
        └─ 遍历 _reverse_output_patterns：
              ├─ 匹配 local_root + 子路径
              └─ 替换为 container + 子路径（\\ 转 /）
```

### 0.2. 三套解析方向的对照

```
【正向：虚拟 → 物理】——translate_path / translate_command
    virtual_path
        ↓ 按 container_path 最长前缀匹配
    mapping.container_path
        ↓ 剥离前缀，取 relative
    relative
        ↓ local_root / relative → resolve()
    resolved 物理路径
        ↓ 越界检测（relative_to local_root）
    返回 / 抛 PermissionError

【反向：物理 → 虚拟】——mask_output
    output 中的物理路径
        ↓ 按 local_path 最长前缀匹配（正则）
    local_root + 子路径
        ↓ 剥离 local_root，取 relative
    relative
        ↓ container_path + relative（\\ 转 /）
    虚拟路径（脱敏后）
```

### 0.3. 运行时调用树

```
① 装配期
LocalPathTranslator(path_mappings)
    └─ 注入 PathMapping 列表
    → 产出 translator 实例
    （cached_property 在首次访问时才计算，非构造期）

        ═══════════ 进入命令执行 ═══════════

② 命令翻译（正向）—— translate_command(command)
sandbox.execute_command(cmd)
    └─ translator.translate_command(cmd)
          ├─ _command_pattern 首次访问 → 编译正则（缓存）
          ├─ _command_pattern is None → return cmd（无 mapping）
          └─ pattern.sub(translate_path, cmd)
                └─ 对每个匹配到的容器路径：
                      translate_path(path)
                          └─ _resolve_path_with_mapping(path)
                                ├─ 按 container_path 最长前缀匹配
                                ├─ 命中 → resolve + relative_to 越界检测
                                │     └─ 越界 → raise PermissionError
                                └─ 未命中 → 原样返回
          → 返回已替换物理路径的命令

③ 路径翻译（正向）—— translate_path(virtual_path)
（通常被 translate_command 内部调用，也可能被单独调用）
    └─ _resolve_path_with_mapping(virtual_path).path
          └─ 首次访问 _mappings_by_container_specificity /
             _resolved_local_paths → 排序 + resolve（缓存）

④ 输出脱敏（反向）—— mask_output(output)
sandbox.execute_command(cmd) 拿到 backend 返回后
    └─ translator.mask_output(output)
          └─ 首次访问 _reverse_output_patterns → 编译反向正则（缓存）
                └─ 遍历 [(pattern, mapping, local)]：
                      ├─ 匹配 local_root + 子路径
                      └─ replace_match：container + relative（\\ 转 /）
          → 返回脱敏后的输出（物理路径已换回虚拟路径）

（本模块不介入安全校验、命令执行）
```

## 1. 补充

**`local_path_translator.py` 是 sandbox 层的"双向路径翻译器"——它基于 `PathMapping` 列表，在虚拟路径 ↔ 物理路径之间做双向映射，并对命令、输出做相应替换。正向（`translate_path` / `translate_command`）用于"让命令能真正执行"，反向（`mask_output`）用于"不让宿主路径泄漏给 LLM"。**

几点补充：

- **三个方法是"三件不同的事"**，不是三个方向的同一件事：
  - `translate_path` — **单路径**正向翻译（虚拟 → 物理）。
  - `translate_command` — **整条命令**里的路径正向翻译（内部复用 `translate_path`）。
  - `mask_output` — **输出**反向翻译（物理 → 虚拟），是 `translate_path` 的逆操作。

- **"最长前缀优先"是贯穿全文件的核心规则**：
  - 前向：按 `container_path` 长度降序（`_mappings_by_container_specificity`）。
  - 反向：按 `local_path` 长度降序（`_mappings_by_local_specificity`）。
  - 目的：防 `/mnt/poirot/skills` 误匹配 `/mnt/poirot/skills-extra`——**必须长前缀先匹配**。

- **四个 `cached_property` 是性能关键**：排序、`resolve()`（syscall）、正则编译都只在**首次访问**时做一次，之后复用。这类"翻译器"在每次工具调用都会被用到，缓存避免了重复开销。

- **symlink 防穿越**：`_resolve_path_with_mapping` 里 `resolve()` 会**跟随 symlink**，然后用 `relative_to(local_root)` 检查是否越界——如果 symlink 指向了映射区外，`relative_to` 抛 `ValueError`，转成 `PermissionError`。**这是防"用软链逃逸白名单"的关键**。

- **`_command_pattern` 的 shell-aware 边界**：正则用 `(?=/|$|[\s"';&|<>()])` 做**前瞻断言**，确保匹配的是"完整路径 token"，不是子串。比如命令里 `/mnt/poirot/user-data/workspace/a.txt` 必须整体匹配，不能只匹配到 `/mnt/poirot/user-data` 就停。

- **`mask_output` 的 `\\` 转 `/`**：Windows 路径分隔符统一成 `/`，保证脱敏后输出跨平台一致。

- **无命中 mapping 的兜底**：`translate_path` 原样返回虚拟路径（`ResolvedPath.mapping=None`）——这是"没有映射规则时不做翻译"的合理默认。

- **一个代码层面的注意点**（不是注释问题）：`_resolve_path_with_mapping` 抛的是 Python 内置 `PermissionError`，**和 guard 抛的 `SandboxPermissionError` 不是同一个类**。如果你希望统一，那是代码改动，不在这轮注释范围内。

- **与 `IdentityTranslator` 的对照**：

| 维度 | IdentityTranslator | LocalPathTranslator |
|---|---|---|
| 适用场景 | Docker（bind mount 对齐）/ E2B | 本地（虚拟 ≠ 物理） |
| translate_path | 原样返回 | 虚拟 → 物理 |
| translate_command | 原样返回 | 命令中路径替换 |
| mask_output | 原样返回 | 物理 → 虚拟（脱敏） |
| 状态 | 无 | 持有 PathMapping + 缓存 |
| 复杂度 | 零 | 高（三套正则 + 双向匹配 + 防穿越） |

- **与 guard 的职责边界**：translator **不做安全校验**——它只管"翻译"，"允不允许"是 guard 的事。防穿越在这里是"防止翻译出映射区外的路径"，不是"安全策略"，最终是否放行仍由 guard 决定。
