---

name: Sandbox 工具工厂 — 把 Sandbox 能力包装成 Agent 可调用的 @tool 工具集。

description: 

【整体职责】
基于给定的 SandboxProvider，工厂式地构造一组 LangChain @tool（bash / read_file /
write_file / list_dir / str_replace / present_files），供 Agent 在工具调用中使用。
工具内部通过 ContextVar 取当前 sandbox_id，再经 provider.get 拿到 Sandbox 实例。

【内容摘要】
- _BASH_OUTPUT_MAX_CHARS : bash 输出截断阈值（10000 字符）。
- WRITE_FILE_MAX_BYTES   : write_file 非 append 模式下的单次写入上限（5 MiB）。
- _truncate_output       : 长输出截断，超限追加 omitted 提示。
- _ensure_sandbox        : 从 ContextVar 取 sandbox_id + provider.get 拿 Sandbox；
                           缺失时抛 SandboxRuntimeError / SandboxNotFoundError。
- _make_bash_tool        : 构造 bash 工具（受 allow_host_bash 控制是否注册）。
- _make_read_file_tool   : 构造 read_file 工具。
- _make_write_file_tool  : 构造 write_file 工具（含大小上限 + append 语义）。
- _make_list_dir_tool    : 构造 list_dir 工具（树形输出）。
- _make_str_replace_tool : 构造 str_replace 工具（按 sandbox+path 加锁串行化）。
- _make_present_files_tool: 构造 present_files 工具（声明交付物，校验路径前缀）。
- make_sandbox_tools     : 工厂入口；闭包捕获 provider，产出工具列表。

【职责边界】
- 只负责：把 Sandbox 能力包装成 @tool、参数校验、输出截断/格式化、按需加锁。
- 不负责：Sandbox 的创建与生命周期（provider）、路径转换（translator）、
  安全校验（guard）、sandbox_id 的设置（middleware）。
- 闭包持有 provider 引用：工具通过 provider 间接访问 Sandbox，本身不持有 Sandbox 实例。

## 0. 结构树

### 0.1. 静态结构树

```
tools.py — Sandbox 工具工厂（把 Sandbox 能力包装成 Agent 可调用的 @tool 工具集）
│
├─ 模块级常量
│   ├─ _BASH_OUTPUT_MAX_CHARS = 10000          ← bash 输出截断阈值（字符数）
│   └─ WRITE_FILE_MAX_BYTES = 5 * 1024 * 1024  ← write_file 非 append 单次写入上限（5 MiB）
│
├─ _truncate_output(output, max_chars=...)     ← 长输出截断；作用：防止 bash 输出撑爆上下文
│   └─ 超限 → output[:max_chars] + "... (truncated, N chars omitted)"
│
├─ _ensure_sandbox(provider) -> Sandbox        ← 统一取 Sandbox；作用：所有工具的公共入口，
│   │                                            从 ContextVar 取 sandbox_id + provider.get 拿实例
│   ├─ sandbox_id is None → raise SandboxRuntimeError（middleware 未 set）
│   └─ provider.get 返回 None → raise SandboxNotFoundError
│
├─ _make_bash_tool(provider) -> BaseTool       ← 构造 bash 工具；作用：在沙箱内执行命令
│   └─ bash_tool(command)                      ← execute_command + _truncate_output
│
├─ _make_read_file_tool(provider) -> BaseTool  ← 构造 read_file 工具；作用：读虚拟路径文件
│   └─ read_file_tool(path)                    ← _ensure_sandbox().read_file(path)
│
├─ _make_write_file_tool(provider) -> BaseTool ← 构造 write_file 工具；作用：写/追加文件
│   └─ write_file_tool(path, content, append) ← 非 append 超 WRITE_FILE_MAX_BYTES 拒绝；
│                                                否则 write_file(path, content, append)
│
├─ _make_list_dir_tool(provider) -> BaseTool   ← 构造 list_dir 工具；作用：树形列目录
│   └─ list_dir_tool(path, max_depth=2)        ← list_dir → 按层级缩进格式化输出
│
├─ _make_str_replace_tool(provider) -> BaseTool← 构造 str_replace 工具；作用：文件内文本替换
│   └─ str_replace_tool(path, old_str,        ← 按 (sandbox.id, path) 加 file_operation_lock
│                       new_str, replace_all)    读改写串行化；old_str 不存在则报错
│
├─ make_sandbox_tools(provider,                ← 工厂入口；作用：产出工具列表，闭包捕获 provider
│                     allow_host_bash=True)
│   ├─ allow_host_bash=True  → 6 个工具
│   └─ allow_host_bash=False → 5 个工具（不注册 bash，S2 安全加固）
│
└─ _make_present_files_tool(provider) -> BaseTool ← 构造 present_files 工具；作用：声明交付物
    └─ present_files_tool(paths)               ← 校验路径前缀 /mnt/poirot/user-data/，
                                                 否则报错；返回 Presented N file(s)
```

**工具产出对照（随 `allow_host_bash` 变化）**

```
make_sandbox_tools(provider, allow_host_bash=True)   → 6 个
├─ bash
├─ read_file
├─ write_file
├─ list_dir
├─ str_replace
└─ present_files

make_sandbox_tools(provider, allow_host_bash=False)  → 5 个
├─ read_file
├─ write_file
├─ list_dir
├─ str_replace
└─ present_files      （无 bash）
```

### 0.2. 运行时调用树

```
① 装配期
make_sandbox_tools(provider, allow_host_bash)
    ├─ allow_host_bash=True  → _make_bash_tool(provider)
    ├─ _make_read_file_tool(provider)
    ├─ _make_write_file_tool(provider)
    ├─ _make_list_dir_tool(provider)
    ├─ _make_str_replace_tool(provider)
    └─ _make_present_files_tool(provider)
    → 产出 list[BaseTool]（每个工具闭包捕获 provider）

        ═══════════ 进入 Agent 循环 ═══════════

② middleware 绑定 sandbox_id
SandboxMiddleware.wrap_tool_call
    └─ set_sandbox_id(sandbox_id)               ← ContextVar 写入
          │
          ▼
③ LLM 调用工具（以 bash 为例）
bash_tool(command)
    ├─ _ensure_sandbox(provider)
    │   ├─ sandbox_id = get_sandbox_id()         ← ContextVar 读取
    │   │     └─ None → raise SandboxRuntimeError
    │   ├─ sandbox = provider.get(sandbox_id)
    │   │     └─ None → raise SandboxNotFoundError
    │   └─ return sandbox
    ├─ sandbox.execute_command(command)          ← 实际执行（backend 层）
    └─ _truncate_output(output)                  ← 超 10000 字符截断
    → 返回 str 给 LLM

④ write_file 分支（含大小校验）
write_file_tool(path, content, append)
    ├─ not append and 超 WRITE_FILE_MAX_BYTES
    │     └─ raise SandboxRuntimeError（提示改用 append=True）
    ├─ _ensure_sandbox(provider).write_file(path, content, append)
    └─ return "wrote N chars to path"

⑤ str_replace 分支（含加锁）
str_replace_tool(path, old_str, new_str, replace_all)
    ├─ sandbox = _ensure_sandbox(provider)
    ├─ lock = get_file_operation_lock(sandbox.id, path)
    └─ with lock:                                ← 按 (sandbox, path) 串行化
          ├─ content = sandbox.read_file(path)
          ├─ old_str not in content → raise SandboxRuntimeError
          ├─ new_content = content.replace(...)
          └─ sandbox.write_file(path, new_content)
    → return "replaced N occurrence(s) in path"

⑥ present_files 分支（含前缀校验）
present_files_tool(paths)
    ├─ invalid = [p for p in paths
    │             if not p.startswith("/mnt/poirot/user-data/")]
    │     └─ invalid 非空 → raise SandboxRuntimeError
    └─ return "Presented N file(s): ..."

（其余工具分支结构类似，均经 _ensure_sandbox 取 Sandbox）
```

## 1. 补充

**`tools.py` 是 sandbox 层对 Agent 的"能力出口"——它把 `Sandbox` 的底层能力包装成一组 LangChain `@tool`，让 LLM 能直接调用；同时用 `ContextVar + provider.get` 把"用哪个沙箱"的决策从工具签名里剥离出去。**

几点补充：

- **闭包捕获的是 provider，不是 Sandbox**：每个 `_make_*_tool` 都返回一个闭包，闭包捕获 `provider`。工具运行时才通过 `_ensure_sandbox` 取当前 `sandbox_id` 对应的 `Sandbox` 实例。这样做的好处是——**同一组工具可以服务多个沙箱**，具体用哪个由 `ContextVar` 在运行时决定。
- **`_ensure_sandbox` 是唯一入口**：所有工具都走它拿 `Sandbox`，不直接 new、不直接持有。它把两类错误收敛成两种异常：`SandboxRuntimeError`（middleware 没 set）和 `SandboxNotFoundError`（provider 查无此 id）。工具层只需关心这两类，不用管底层。
- **三道"防爆"约束**：
  - `_BASH_OUTPUT_MAX_CHARS`——防 bash 输出撑爆上下文。
  - `WRITE_FILE_MAX_BYTES`——防单次写入过大，提示改用 `append` 分块。
  - `present_files` 的路径前缀校验——防把不可交付路径（如 `/home/...`）声明成交付物。
- **`str_replace` 是唯一显式加锁的工具**：因为它是"读—改—写"复合操作，必须按 `(sandbox.id, path)` 串行化，否则并发替换同一文件会丢更新。其他工具是单次原子操作，不需要锁。锁来自 `utils/file_operation_lock.py`。
- **工具数量是条件性的**：`allow_host_bash=False` 时不注册 `bash`，产出 5 个而非 6 个。这是 S2 安全加固——禁用宿主 bash 时不给 LLM 执行任意命令的能力。原 docstring 只说"返回 6 个"，容易让人忽略这个条件。
- **`present_files` 的 docstring 是功能契约**：它是给 LLM 看的工具说明（含路径要求、调用时机），不是给开发者看的注释，因此保持原样、不按注释格式改写。
- **本文件不负责的事**：Sandbox 的创建与生命周期（provider）、路径转换（translator）、安全校验（guard）、`sandbox_id` 的设置（middleware）——这些都在别的模块，工具层只做"包装 + 校验 + 格式化 + 按需加锁"。
