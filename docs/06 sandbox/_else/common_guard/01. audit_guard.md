---

name: AuditGuard — 命令分级 + 审计日志（S8 defense-in-depth）。

description: 

【整体职责】
组合模式守卫：包装一个底层 guard（LocalSecurityGuard 或 PermissiveGuard），
在命令校验前先做三档分级（block / warn / pass），并把每次命令分级结果写入审计日志；
路径校验直接透传底层 guard。用于在"决策型 guard"之外叠加一层"观察 + 分级"能力。

【内容摘要】
- _BLOCK_PATTERNS : block 档正则表——破坏性命令，无论 Local/Docker 都拦截。
- _WARN_PATTERNS  : warn 档正则表——危险但非破坏，记日志放行（容器隔离兜底）。
- _classify       : 命令分级函数；返回 (level, matched_desc)，level ∈ {block, warn, pass}。
- AuditGuard      : 审计守卫类；组合底层 guard + 可选 journal。
    ├─ validate_path    : 路径校验，透传底层 guard。
    ├─ validate_command : 命令分级 + 审计 + 按档处理（block 拦截 / warn+pass 透传）。
    └─ _audit           : 写审计日志（logger + 可选 journal），失败不影响主流程。

【职责边界】
- 只负责：命令分级、审计记录、按档决定拦截或透传。
- 不负责：底层命令/路径规则（由 inner guard 负责）、真正执行（backend）、
  路径转换（translator）。
- 组合持有 inner guard：自身不实现底层规则，只在其外层叠加分级与审计。

## 0. 结构树

### 0.1. 静态结构树

```
audit_guard.py — AuditGuard（命令分级 + 审计日志，S8 defense-in-depth）
│
├─ _logger                                     ← 模块 logger；作用：写分级日志
│
├─ _BLOCK_PATTERNS: list[(Pattern, str)]       ← block 档正则表；作用：破坏性命令一律拦截
│   ├─ rm -rf /            ← rm -rf /（排除 /word）
│   ├─ rm -rf ~            ← rm -rf ~
│   ├─ rm -rf $HOME        ← rm -rf $HOME
│   ├─ rm -rf /*           ← rm -rf /*
│   ├─ mkfs                ← mkfs.xxx
│   ├─ dd to device        ← dd ... of=/dev/
│   └─ fork bomb           ← :(){:|:&};: 类
│
├─ _WARN_PATTERNS: list[(Pattern, str)]        ← warn 档正则表；作用：危险但非破坏，记日志放行
│   ├─ curl pipe to shell  ← curl ... | bash/sh
│   ├─ wget pipe to shell  ← wget ... | bash/sh
│   ├─ sudo                ← sudo
│   ├─ chmod 777           ← chmod 777
│   ├─ eval                ← eval
│   └─ exec builtin        ← exec（排除 exec *.py）
│
├─ _classify(command) -> (level, desc)         ← 命令分级；作用：先扫 block，再扫 warn，
│   │                                            都不中则 pass
│   ├─ 命中 _BLOCK_PATTERNS → ("block", desc)
│   ├─ 命中 _WARN_PATTERNS  → ("warn", desc)
│   └─ 都不命中              → ("pass", None)
│
└─ AuditGuard                                  ← 审计守卫类；作用：组合底层 guard，
    │                                            在命令校验前叠加分级 + 审计
    ├─ _inner: Any                             ← 底层 guard（LocalSecurityGuard / PermissiveGuard）
    ├─ _journal: Any = None                    ← 可选 RunJournal，写 sandbox.command 审计事件
    │
    ├─ __init__(inner, journal=None)           ← 初始化；持有 inner + 可选 journal
    │
    ├─ validate_path(path, *, write=False)     ← 路径校验；作用：直接透传底层 guard，
    │   └─ self._inner.validate_path(...)         本层不做分级
    │
    ├─ validate_command(command)               ← 命令校验；作用：分级 → 审计 → 按档处理
    │   ├─ level, desc = _classify(command)
    │   ├─ self._audit(command, level, desc)   ← 无论哪档都先记审计
    │   ├─ level == "block" → raise SandboxPermissionError
    │   │                       (path=command[:100], operation="validate_command")
    │   └─ warn / pass       → self._inner.validate_command(command)  ← 透传底层
    │
    └─ _audit(command, level, desc)            ← 写审计；作用：logger 分级 + 可选 journal
        ├─ block / warn → _logger.warning(msg)
        ├─ pass         → _logger.debug(msg)
        └─ journal 非空 → journal.append("sandbox.command",
                            {level, desc, command[:200]})   ← 异常静默吞掉
```

### 0.2. 运行时调用树

```
① 装配期（组合模式）
AuditGuard(inner, journal)
    ├─ Local  模式 → AuditGuard(LocalSecurityGuard, journal)
    └─ Docker 模式 → AuditGuard(PermissiveGuard, journal)
    → 产出组合 guard，供 Sandbox 门面在 execute_command 前调用

        ═══════════ 进入命令执行 ═══════════

② 命令校验 —— validate_command(command)
sandbox.execute_command(cmd)
    └─ guard.validate_command(cmd)              ← 此处 guard 即 AuditGuard
          │
          ├─ level, desc = _classify(cmd)
          │     ├─ 扫 _BLOCK_PATTERNS → 命中即返回 ("block", desc)
          │     ├─ 扫 _WARN_PATTERNS  → 命中返回 ("warn", desc)
          │     └─ 都不中             → ("pass", None)
          │
          ├─ _audit(cmd, level, desc)
          │     ├─ logger：block/warn → warning；pass → debug
          │     └─ journal.append("sandbox.command", {...})   ← 失败静默
          │
          ├─ level == "block"
          │     └─ raise SandboxPermissionError（拦截，主流程中断）
          │
          └─ level == "warn" / "pass"
                └─ inner.validate_command(cmd)   ← 透传底层 guard 继续检查
                      ├─ Local  → LocalSecurityGuard.validate_command
                      └─ Docker → PermissiveGuard.validate_command

③ 路径校验 —— validate_path(path, write)
sandbox.execute_command(cmd) 内部对涉及的路径
    └─ guard.validate_path(path, write=...)
          └─ inner.validate_path(path, write=...)   ← 直接透传，不做分级
                ├─ Local  → LocalSecurityGuard.validate_path
                └─ Docker → PermissiveGuard.validate_path

（本模块不介入 backend 执行、路径转换、输出回写）
```

## 1. 补充

**`audit_guard.py` 是 guard 体系里的"组合层"——它不自己定义底层规则，而是包一个 inner guard（LocalSecurityGuard 或 PermissiveGuard），在其外层叠加"三档分级 + 审计日志"，形成 S8 的 defense-in-depth。**

几点补充：

- **组合模式，不是替代**：`AuditGuard` 持有 `_inner`，所有"底层规则"交给 inner；自己只负责"分级 + 审计 + 按档决定拦还是透传"。这解释了为什么 guard 目录里既有 `local_security_guard` / `permissive_guard`（被包装），又有 `audit_guard`（包装者）——它们不在同一层。
- **三档语义是核心契约**：
  - `block` — 破坏性命令，**无论 Local/Docker 都拦**（本地/容器都危险）。
  - `warn` — 危险但非破坏，**记日志放行**，靠容器隔离兜底（Docker 下更敢放）。
  - `pass` — 其余，**透传底层 guard**。
- **block 优先于 warn**：`_classify` 先扫 block，命中即返回，不再看 warn。顺序不能反，否则 `rm -rf /` 可能被误判成 warn。
- **Local 与 Docker 的差异在"inner 是谁"**，不在 AuditGuard 本身：
  - Local → `AuditGuard(LocalSecurityGuard)`：底层严格，warn/pass 还要过本地规则。
  - Docker → `AuditGuard(PermissiveGuard)`：底层宽松，warn 放行靠容器兜底。
  - **分级逻辑是共用的**，只有底层严格程度不同。
- **两处截断长度不同**（易看漏）：block 抛出时 `path=command[:100]`；审计日志 `command[:200]`。
- **路径校验不对称**：`validate_path` **不做分级**、直接透传；只有 `validate_command` 做分级。这是刻意设计（分级只针对命令）。
- **审计容错**：`journal.append` 包在 try/except 里，**审计失败不影响主流程**——审计是旁路，不能因为它挂掉就阻断命令。
- **组合方式由模式决定**（写死在装配处）：Local 用 `AuditGuard(LocalSecurityGuard)`，Docker 用 `AuditGuard(PermissiveGuard)`——这正是你之前问的"为什么有 permissive 和 audit"的答案：**permissive 是被 audit 包装的底层宽松实现，audit 是叠加在两者之上的分级+审计层**。
