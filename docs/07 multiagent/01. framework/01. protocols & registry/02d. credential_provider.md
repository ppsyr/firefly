---

name: CredentialProvider Protocol — specialist 凭证发现契约。

description: 

【整体职责】
定义"如何发现 specialist 凭证"的契约：只发现、不管理。凭证由 CLI 登录态提供，
Poirot 读取后仅传给 specialist runtime，不写入任何状态、不做刷新或存储。

【内容摘要】
- Credential(基类, frozen)         : 凭证数据结构，含 kind 标识 specialist 类型。
- CredentialProvider(Protocol)     : 凭证发现契约，仅一个 get_credential() 方法。

【职责边界】
- 只负责：发现凭证（读 CLI 登录态文件）。
- 不负责：刷新凭证、存储凭证、管理凭证生命周期、写 ThreadState。
- 不持有状态：Protocol 无实现，纯接口。

---

## 0. 结构树

### 0.1. 静态结构树

```
credential_provider.py — CredentialProvider Protocol（specialist 凭证发现契约）
│
├─ Credential(frozen)                         ← specialist 凭证基类
│   │                                            只传给 specialist runtime，不写 ThreadState
│   │                                            （避免凭证进入 LLM 上下文）
│   └─ kind: str                              ← 标识 specialist 类型（"codex" / "claude"）
│
└─ CredentialProvider(Protocol)               ← specialist 凭证发现契约
    │                                            复用 CLI 登录态，不管理凭证
    │                                            只发现，不刷新、不存储
    │
    └─ get_credential() -> Credential | None  ← 发现 specialist 凭证
        │                                        返回 None → 凭证缺失
        │                                        （调用方把 specialist 标 disabled，不注册 tool）
        └─ 返回的 Credential 只传 runtime，不写 ThreadState

   实现示例（不在本文件）：
    ├─ CodexCredentialProvider                 ← 读 ~/.codex/auth.json
    ├─ ClaudeCredentialProvider                ← 读 ~/.claude/.credentials.json
    └─ （Pi 不走本契约，走 config 的 specialists_pi_api_key env）

   子类扩展（不在本文件）：
    ├─ CodexCredential(Credential)             ← 扩展 codex 专属字段
    └─ ClaudeCredential(Credential)            ← 扩展 claude 专属字段
```

### 0.2. 运行时调用树

```

bootstrap

        ═══════════ 进入 Agent 循环 ═══════════
```

### 0.3. 补充

**`credential_provider.py` 是 multiagent 的"身份闸门"——只负责发现外部 CLI 的登录态，绝不管理、绝不外泄。**

几点补充：

- **Protocol 而非 ABC**：用 `typing.Protocol` 定义，实现方无需显式继承，duck typing 即可。`...` 是占位符。
- **`Credential` 是 frozen dataclass**：凭证对象不可变，避免被意外修改；基类只带 `kind`，具体字段由子类扩展。
- **"不进 ThreadState" 是安全边界**：这是本契约最核心的约束。凭证一旦进 state，就会进序列化、进 LLM 上下文、进日志，等于泄漏。
- **缺失返 None 而非抛异常**：凭证缺失是正常情况（用户没登录某 CLI），返 None 让上层优雅降级。
- **Pi 不走本契约**：Pi 的凭证走 `config.py` 的 `specialists_pi_api_key`（env 直读），说明不同 specialist 的凭证来源可以完全不同。
## 1. Specialist 凭证是什么

**Specialist 凭证 = 让外部 specialist（Claude Code / Codex / Pi）能以"已登录用户身份"运行的认证信息。**

因为 multiagent 派活给的不是 Poirot 自己的 LLM 调用，而是**外部进程 / 外部 CLI**（比如 Claude Code、Codex CLI）。这些外部工具需要自己的登录态才能跑，凭证就是它们的"身份证"。

---

### 1.1. 为什么需要凭证

一次派活的链路：

```
Leader 派活
  → SpecialistRuntime.execute()
      → 启动外部进程（claude / codex / pi CLI）
          → 这个 CLI 需要认证才能调 LLM
              → 认证信息从哪来？ ← 凭证
```

**Poirot 自己不持有这些凭证**，它只是"发现"宿主上已经存在的登录态，拿来喂给外部进程。

---

### 1.2. 凭证从哪来：复用 CLI 登录态

关键设计：**Poirot 不管理凭证，只发现。**

| Specialist | 凭证来源 | 说明 |
|---|---|---|
| Codex | `~/.codex/auth.json` | Codex CLI 的登录态文件 |
| Claude | `~/.claude/.credentials.json` | Claude Code CLI 的登录态文件 |
| Pi | `POIROT_MULTIAGENT_PI_API_KEY`（env） | Pi 走 env 配置，见 `config.py` |
| Subagent | 不独立 | 继承 Leader，Poirot 内部，无需外部凭证 |

**为什么复用 CLI 登录态**：用户已经用 `claude login` / `codex login` 登录过了，Poirot 直接读那份文件就行，不用再让用户配一遍。

---

### 1.3. 凭证长什么样

```python
@dataclass(frozen=True)
class Credential:
    kind: str        # "codex" / "claude"

# 子类会扩展具体字段（Batch 4 定义）
# CodexCredential  → 可能含 api_key / token / expires_at
# ClaudeCredential → 可能含 access_token / refresh_token
```

基类只带一个 `kind` 标识"这是哪种 specialist 的凭证"，子类补充实际认证字段。

---

### 1.4. 三条铁律

#### 1. 凭证不进 LLM 主态

**这是最核心的约束。**

```python
# ✅ 正确：只传给 runtime
credential = provider.get_credential()
runtime.invoke(request, credential)

# ❌ 错误：写进 ThreadState
state["credential"] = credential   # 禁止！
```

**为什么**：`ThreadState` 会被序列化、会进 LLM 上下文、会写日志。凭证一旦进去，就等于**把密钥暴露给 LLM 和所有能读 state 的地方**。

所以凭证只在"发现 → 传 runtime"这条最短路径上流动，用完即弃。

#### 2. Poirot 只发现，不管理

| 动作 | 谁负责 |
|---|---|
| 登录 | 用户（`claude login` / `codex login`） |
| 发现凭证 | **Poirot（CredentialProvider）** |
| 刷新凭证 | 外部 CLI |
| 存储凭证 | 外部 CLI |

Poirot 只做"读文件"这一件事。不做 OAuth 流程、不做 token 刷新、不落库。

#### 3. 缺失返 None，不抛异常

```python
def get_credential(self) -> Credential | None:
    # 找不到 → 返回 None
    # 调用方：把 specialist 标 disabled，不注册对应 tool
```

**为什么是 None 而不是抛异常**：凭证缺失是**正常情况**（用户没登录 Claude 但想用 Codex）。返 None 让上层可以优雅降级——跳过这个 specialist，而不是整个 multiagent 崩掉。
