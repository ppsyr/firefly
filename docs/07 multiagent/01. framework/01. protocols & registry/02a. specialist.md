---

name: SpecialistAgent Protocol — 专业 agent 高层抽象契约。

description: 

【整体职责】
定义 specialist 的高层契约：一个 specialist 必须能报名字、报能力、被调用执行。
Poirot 通过本契约把 specialist 当黑盒使用，不关心其内部 model、ReAct loop、context 管理。

【内容摘要】
- SpecialistAgent(Protocol)  : specialist 高层契约，含 name / capabilities / invoke 三成员。

【职责边界】
- 只负责：定义契约（属性 + 方法签名 + 语义）。
- 不负责：具体执行（runtime 负责）、上下文摘要（ContextSummarizer 负责）、
  结果摘要（ResultSummarizer 负责）、凭证获取（CredentialProvider 负责）。
- 不持有状态：Protocol 无实现，纯接口。

## 0. 结构树

### 0.1. 静态结构树

```
specialist.py — SpecialistAgent Protocol（专业 agent 高层抽象契约）
│
└─ SpecialistAgent(Protocol)                  ← specialist 高层契约
    │                                            黑盒：自带 model + 自管 ReAct loop + 自管 context
    │                                            Poirot 只传 goal + context_summary + sandbox_id
    │                                            不继承 SpecialistRuntime（高层 vs 低层，持有关系）
    │
    ├─ name (property) -> str                 ← specialist 唯一名
    │                                            用于生成 delegate_to_<name> 工具 + Registry 注册
    │
    ├─ capabilities (property)                ← specialist 能力声明
    │   └─ -> SpecialistCapabilities          ← list_specialists 按能力过滤时使用
    │
    └─ invoke(request) -> SpecialistRawResult ← 执行 specialist 调用
        │                                        输入：SpecialistRequest
        │                                        输出：SpecialistRawResult（raw output + artifacts
        │                                              + usage + duration + exit_code）
        └─ 失败抛 SpecialistError 子类          ← Timeout / Crash / Startup / Credential

   实现示例（不在本文件）：
   ├─ CodexSpecialist                         ← 组合 CodexRuntime + 专属 Summarizer + 凭证
   ├─ ClaudeCodeSpecialist                    ← 组合 ClaudeCodeRuntime + 专属 Summarizer + 凭证
   └─ SubagentSpecialist                      ← 组合 SubagentRuntime + SelfCopy Summarizer
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
bootstrap
    └─ 实例化各 specialist 实现 → registry.register(specialist)
        ├─ 读取 specialist.name                ← 生成 delegate_to_<name> 工具
        └─ 读取 specialist.capabilities        ← 供 list_specialists 过滤
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（每次派活）
Leader 决定派活
    ├─ registry.list_specialists(capability)   ← 按能力过滤，拿到候选名字
    ├─ registry.get(name) -> SpecialistAgent   ← 取实例（走本契约）
    │
    ▼
specialist.invoke(request: SpecialistRequest)
    ├─ 内部：ContextSummarizer 压上下文
    ├─ 内部：CredentialProvider 取凭证
    ├─ 内部：SpecialistRuntime.execute 执行
    │
    ├─ 成功 → return SpecialistRawResult
    └─ 失败 → raise SpecialistError 子类
          │
          ▼
（RawResult 交给 ResultSummarizer 压缩为 SpecialistResult，回传 Leader）
```

### 0.3. 补充

**`specialist.py` 是 multiagent 的"岗位说明书"——它规定一个 specialist 必须能报名字、报能力、被调用；Poirot 通过它把 specialist 当黑盒使用。**

几点补充：

- **Protocol 而非 ABC**：用 `typing.Protocol` 定义，实现方无需显式继承，duck typing 即可。`...` 是占位符。
- **黑盒边界是本契约的核心**：`invoke` 只接收 `SpecialistRequest`（goal + success_criteria + context_summary + sandbox_id），不暴露 specialist 内部的 model、loop、context。
- **高层 vs 低层**：`SpecialistAgent` 是"高层封装"（含语义），`SpecialistRuntime` 是"低层执行"（裸跑）。两者是**持有关系**，不是继承关系——这是理解 multiagent 分层的关键。
- **三个成员各司其职**：`name` 用于注册与工具生成，`capabilities` 用于过滤，`invoke` 用于执行。
