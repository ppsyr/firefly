---

name: SpecialistRuntime Protocol — specialist 裸执行契约（sync only）。

description: 

【整体职责】
定义 specialist 的底层执行契约：只负责把 SpecialistRequest 跑成一个
SpecialistRawResult，不掺任何上下文摘要、结果压缩、状态管理。
上层由 SpecialistAgent 持有并组合使用。

【内容摘要】
- SpecialistRuntime(Protocol) : 裸执行契约，仅一个 invoke() 方法。

【职责边界】
- 只负责：执行 specialist loop，返回 raw output。
- 不负责：上下文摘要（ContextSummarizer）、结果摘要（ResultSummarizer）、
  线程状态管理（ThreadState）、凭证获取（CredentialProvider）。
- 不持有状态：Protocol 无实现，纯接口。

## 0. 结构树

### 0.1. 静态结构树

```
specialist_runtime.py — SpecialistRuntime Protocol（裸执行契约，sync only）
│
└─ SpecialistRuntime(Protocol)                ← specialist 底层执行契约
    │                                            低层纯执行：不知 ContextSummarizer /
    │                                            ResultSummarizer / ThreadState
    │                                            被 SpecialistAgent 持有（不是继承）
    │                                            sync only：不提供 ainvoke
    │
    └─ invoke(request) -> SpecialistRawResult ← 执行 specialist loop
        │                                        输入：SpecialistRequest
        │                                        输出：SpecialistRawResult（raw output +
        │                                              artifacts + usage + duration + exit_code）
        └─ 失败抛 SpecialistError 子类          ← Timeout / Crash / Startup / Credential

   实现示例（不在本文件）：
    ├─ CodexRuntime                           ← Codex 执行器
    ├─ ClaudeCodeRuntime                      ← Claude Code 执行器
    └─ SubagentRuntime                        ← 自复制 subagent 执行器
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
bootstrap
    └─ 实例化各 runtime → 注入到对应 SpecialistAgent
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（每次派活）
Leader → registry.get(name) → specialist.invoke(request)
    │
    ▼
SpecialistAgent.invoke(request)
    │
    │  内部组合（Agent 层负责）：
    │  ├─ ContextSummarizer 压上下文 → request.context_summary
    │  ├─ CredentialProvider 取凭证
    │  └─ 调用 runtime.invoke(request)          ← 本契约
    │
    ▼
SpecialistRuntime.invoke(request)
    │  本层不感知上下文/结果摘要/线程状态，只跑 loop
    │
    ├─ 成功 → return SpecialistRawResult
    └─ 失败 → raise SpecialistError 子类
          │
          ▼
（RawResult 回到 Agent 层，再交给 ResultSummarizer 压缩）
```

### 0.3. 补充

**`specialist_runtime.py` 是 multiagent 的"发动机接口"——只规定"能把请求跑成原始输出"，不管上下文、不管结果、不管状态。**

几点补充：

- **Protocol 而非 ABC**：用 `typing.Protocol` 定义，实现方无需显式继承，duck typing 即可。`...` 是占位符。
- **与 SpecialistAgent 的分工**：Agent 是"高层封装"（管上下文、凭证、摘要），Runtime 是"低层执行"（只管跑）。**Agent 持有 Runtime**，不是继承。
- **sync only 是显式取舍**：MVP 只做同步，不提供 `ainvoke`；并发靠 `max_concurrent` + 线程池，不靠 async。
- **不感知摘要器与状态**：Runtime 不 import `ContextSummarizer` / `ResultSummarizer` / `ThreadState`，保证它是最纯粹的"执行层"。
- **异常边界**：Runtime 抛出的异常必须是 `SpecialistError` 子类，方便上层 middleware 统一收敛为 error ToolMessage。
