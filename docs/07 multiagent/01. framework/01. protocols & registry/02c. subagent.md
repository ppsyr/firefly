description: 

【整体职责】
定义"自复制 subagent"的生成契约：让 Leader 能 spawn 一个与自己同构的子 Agent 执行任务。
子 Agent 复用 lead agent factory，但以 leaf role 运行、隔离上下文、共享沙箱。

【内容摘要】
- SubagentProvider(Protocol) : 自复制 subagent 契约，仅一个 spawn() 方法。

【职责边界】
- 只负责：定义 spawn 契约（方法签名 + 语义）。
- 不负责：具体 spawn 实现（SubagentRuntime 负责）、上下文摘要、结果摘要、
  与 specialist 体系的适配（SubagentSpecialist 负责）。
- 不持有状态：Protocol 无实现，纯接口。

## 0. 结构树

### 0.1. 静态结构树

```
subagent.py — SubagentProvider Protocol（Poirot self-copy subagent 契约）
│
└─ SubagentProvider(Protocol)                 ← 自复制 subagent 契约（sync only，leaf role）
    │                                            复用 lead agent factory（create_poirot_agent）
    │                                            leaf role：不能再 spawn（防无限递归）
    │                                            isolated context：全新 ThreadState
    │                                            shared thread sandbox：复用父 sandbox_id
    │
    └─ spawn(request) -> SubagentResult       ← spawn 一个自复制 subagent 执行任务
        │                                        输入：SubagentRequest
        │                                        输出：SubagentResult
        └─ 失败抛 SubagentError 子类           ← SubagentTimeoutError / SubagentMaxStepsError

   实现示例（不在本文件）：
    └─ SubagentRuntime                        ← 内部构造 lead factory 调用

   与 SpecialistRuntime 对照：
    ├─ SubagentProvider.spawn()   → SubagentResult    （高层 API，自复制专用）
    └─ SpecialistRuntime.invoke() → SpecialistRawResult（低层 API，通用执行）

   适配关系（不在本文件）：
    └─ SubagentSpecialist 组合 SubagentRuntime，把 SubagentProvider 适配为 SpecialistRuntime
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
bootstrap
    └─ 实例化 SubagentRuntime → 注入 SubagentSpecialist
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（Leader 派活给 subagent）
Leader → registry.get("subagent") → specialist.invoke(request)
    │
    ▼
SubagentSpecialist.invoke(request)
    │
    │  内部：把 SpecialistRequest 适配为 SubagentRequest
    │
    ▼
SubagentProvider.spawn(SubagentRequest)        ← 本契约
    │
    ├─ 复用 lead agent factory 创建子 Agent
    ├─ 子 Agent 以 leaf role 运行（tool_groups 不含 multiagent）
    ├─ 全新 ThreadState（不继承父 message history）
    ├─ 复用父 sandbox_id（不另起沙箱）
    │
    ├─ 成功 → return SubagentResult
    └─ 失败 → raise SubagentError 子类
          │
          ▼
（SubagentResult 回到 SpecialistAgent 层，再适配为 SpecialistResult 回传 Leader）
```

### 0.3. 补充

**`subagent.py` 是 multiagent 的"自复制契约"——规定 Leader 怎么 spawn 一个与自己同构、但以 leaf role 运行、上下文隔离、沙箱共享的子 Agent。**

几点补充：

- **Protocol 而非 ABC**：用 `typing.Protocol` 定义，实现方无需显式继承，duck typing 即可。`...` 是占位符。
- **leaf role 是递归安全阀**：子 Agent 的 `tool_groups` 不含 multiagent，看不到 `delegate_to_*` 工具，无法再 spawn——从工具层面杜绝无限递归，而不是靠运行时检测。
- **context 隔离 vs sandbox 共享**：上下文用全新 `ThreadState`（避免父历史污染子决策），沙箱复用父 `sandbox_id`（避免重复起容器、保证文件可见）。**一个隔离一个共享，是刻意设计。**
- **高层 API vs 低层 API**：`spawn` 直接返回 `SubagentResult`（已含成功/失败语义），而 `SpecialistRuntime.invoke` 返回 `SpecialistRawResult`（还要经 `ResultSummarizer` 压缩）。所以 `SubagentSpecialist` 需要一层适配。
- **复用 lead factory 而非另写一套**：`create_poirot_agent` 同时服务 Leader 和 subagent，保证两者行为一致，减少维护面。
