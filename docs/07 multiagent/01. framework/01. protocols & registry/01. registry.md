---

name: SpecialistRegistry — specialist 注册发现（非全局单例）。

description: 

【整体职责】
维护"名字 → specialist 实例"的映射，供 Leader / bootstrap 查询与过滤 specialist。
作为 CapabilityRegistry 的一个能力注入，不做全局单例；装配期由 bootstrap 反射填充。

【内容摘要】
- SpecialistRegistry      : 注册表主类（内部可变 dict）。
- register()              : 注册 specialist，返回其名字。
- get()                   : 按名字取 specialist，缺失抛 SpecialistNotFoundError。
- list_specialists()      : 列出 specialist 名字，可按能力过滤。
- register_from_config()  : 装配期反射加载入口（当前为接口契约，未实现）。
- __len__ / __contains__  : 支持 len() 与 in 查询。

【职责边界】
- 只负责：注册、查询、按能力过滤、长度/成员判断。
- 不负责：specialist 的实例化（bootstrap 负责）、凭证检测（bootstrap 负责）、
  实际派活（Leader 负责）。
- 非全局单例：每个 CapabilityRegistry 持有自己的 registry 实例。

## 0. 结构树

### 0.1. 静态结构树

```
registry.py — SpecialistRegistry（specialist 注册发现，非全局单例）
│
└─ SpecialistRegistry                         ← 注册表主类（内部可变 dict，非 frozen）
    │                                            作为 CapabilityRegistry 的能力注入使用；
    │                                            装配期由 bootstrap 反射加载
    │
    ├─ _specialists: dict[str, SpecialistAgent] ← 内部映射：名字 → specialist 实例
    │
    ├─ __init__()                             ← 初始化空 dict
    │
    ├─ register(specialist) -> str            ← 注册 specialist，返回其 name
    │                                            同名覆盖（last-write-wins）
    │
    ├─ get(name) -> SpecialistAgent           ← 按名字取 specialist
    │                                            缺失抛 SpecialistNotFoundError（不返回 None）
    │
    ├─ list_specialists(capability=None)      ← 列出 specialist 名字
    │   │                                        capability=None → 返回全部
    │   └─ 按 capability 过滤                  ← 走 specialist.capabilities.has()
    │
    ├─ register_from_config(use_list)         ← 装配期反射加载入口（当前未实现）
    │                                            预期：反射 import + 凭证检测 + disabled 不注册
    │                                            当前：raise NotImplementedError
    │
    ├─ __len__() -> int                       ← 返回已注册数量
    │
    └─ __contains__(name) -> bool             ← 判断名字是否已注册
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
bootstrap
    └─ registry.register_from_config(use_list)
          └─ （实现层：反射 import specialist 类 → 凭证检测 → 逐个 register）

② 装配期（逐个注册）
bootstrap
    └─ registry.register(specialist)           ← 返回 name；同名覆盖

③ 运行期（Leader 派活前查询）
Leader
    ├─ registry.list_specialists()             ← 列全部
    ├─ registry.list_specialists(capability)   ← 按能力过滤
    └─ registry.get(name)                      ← 取实例
          └─ 缺失 → raise SpecialistNotFoundError

④ 运行期（其他）
len(registry) / name in registry               ← 计数 / 成员判断

（本模块不负责：specialist 实例化、凭证检测、实际派活）
```

### 0.3. 补充

**`registry.py` 是 multiagent 的"花名册"——存 specialist 实例、按名字/能力查询；它只认契约（SpecialistAgent Protocol），不认具体实现。**

几点补充：

- **非全局单例**：每个 `CapabilityRegistry` 持有自己的 registry 实例，避免跨 Agent 污染。
- **同名覆盖不报错**：`register` 采用 last-write-wins。装配期重复注册不会失败，后注册的生效。
- **get 缺失抛异常而非返回 None**：调用方必须处理 `SpecialistNotFoundError`，避免"拿到 None 后继续用"的隐性 bug。
- **duck typing**：接受任何实现 `SpecialistAgent` Protocol 的对象，不要求显式继承。
- **`register_from_config` 当前是空壳**：抛 `NotImplementedError`，真正的反射加载在 bootstrap 层实现。这是"接口契约先定，实现后补"的典型写法。



## 1. 注册表和契约的关系

**一句话：注册表存的是"契约的实现者"，并按契约规定的语义去调用它们。**

### 关系图

```
Registry（注册表）
   │
   │  存的是：
   ▼
List[Specialist]   ← 这里 Specialist 是「契约」
   │
   │  每个元素实际是：
   ▼
ClaudeCodeSpecialist / CodexSpecialist / PiSpecialist / SubagentSpecialist
                    ↑ 这些是「契约的实现者」
```

### 具体关系拆成三层

**第一层：注册表按契约类型存放**

```python
class MultiAgentRegistry:
    def register(self, specialist: Specialist):  # 参数类型 = 契约
        self._specialists[specialist.name] = specialist

    def get(self, name: str) -> Specialist:      # 返回类型 = 契约
        return self._specialists[name]
```

注册表**不关心**你注册的是 Claude 还是 Codex，只要求你**满足 Specialist 契约**。

**第二层：注册表通过契约调用，不碰具体实现**

```python
# Leader 派活时，注册表返回的是 Specialist 契约
specialist = registry.get("claude_code")

# 下面这些调用全部走「契约方法」，不依赖具体类
specialist.capabilities()              # 契约规定必须有
specialist.context_summarizer.summarize(...)
specialist.result_summarizer.summarize(...)
specialist.runtime.execute(...)         # runtime 也是契约
```

**第三层：契约保证"可替换"**

因为注册表只认契约，所以：

- 今天注册 `ClaudeCodeSpecialist`，明天换成 `CodexSpecialist`，**Leader 代码一行不改**
- 新增一个 `MyCustomSpecialist`，只要实现 Specialist 契约，**注册进去就能用**

这就是**面向接口编程**：注册表是"容器"，契约是"插槽标准"。



```
        ┌─────────────────────────────────────────┐
        │  Specialist 契约（interface）             │
        │  - name                                   │
        │  - capabilities()                         │
        │  - run()                                  │
        └─────────────────────────────────────────┘
                        ▲
                        │ 实现（implements）
        ┌───────────────┼───────────────┬──────────────┐
        │               │               │              │
 ClaudeCode      Codex           Pi          Subagent
 Specialist      Specialist      Specialist  Specialist
        │               │               │              │
        └───────────────┴───────────────┴──────────────┘
                        │
                        │ 注册（register）
                        ▼
        ┌─────────────────────────────────────────┐
        │  MultiAgentRegistry（注册表）             │
        │  _specialists: dict[name, Specialist]    │
        │  get(name) -> Specialist                 │
        └─────────────────────────────────────────┘
                        │
                        │ 查询（get）
                        ▼
                   Leader（消费者）
```

**三层职责：**

| 层 | 角色 | 职责 |
|---|---|---|
| 契约 | 标准 | 规定"必须有什么方法" |
| 实现 | 具体类 | 真正干活（Claude / Codex / Pi / Subagent） |
| 注册表 | 容器 | 存实现、按契约查、按契约调 |
