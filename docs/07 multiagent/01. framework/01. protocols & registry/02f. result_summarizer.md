---

name: ResultSummarizer Protocol — specialist 输出端转换器 + programmatic eval 契约。

description: 

【整体职责】
定义 specialist 输出端的转换契约：把 runtime 返回的原始输出压缩为 SpecialistResult，
并在此过程中完成 programmatic eval（校验 success_criteria、生成 gap_analysis）。
与 ContextSummarizer（输入端）配对，一进一出，控制 Leader 上下文膨胀。

【内容摘要】
- ResultSummarizer(Protocol) : 输出端转换器契约，仅一个 summarize() 方法。

【职责边界】
- 只负责：定义转换契约（方法签名 + 语义）。
- 不负责：具体压缩策略（各 specialist 的实现负责）、上下文输入压缩
  （ContextSummarizer 负责）、specialist 执行（runtime 负责）。
- 不持有状态：Protocol 无实现，纯接口。

## 0. 结构树

### 0.1. 静态结构树

```
result_summarizer.py — ResultSummarizer Protocol（输出端转换器 + programmatic eval 契约）
│
└─ ResultSummarizer(Protocol)                 ← 输出端转换器契约
    │                                            与 ContextSummarizer（输入端）配对
    │                                            per-specialist 实现，不共用通用逻辑
    │
    └─ summarize(raw_output, artifacts, goal, success_criteria) -> SpecialistResult
        │                                        ← 压缩原始输出 + 校验成功标准
        │
        ├─ 输入 raw_output: str               ← specialist 原始输出文本
        ├─ 输入 artifacts: list[ArtifactRef]  ← 产物引用列表
        ├─ 输入 goal: str                     ← 任务目标（用于校验）
        ├─ 输入 success_criteria: str         ← 成功标准（用于校验）
        │
        └─ 输出 SpecialistResult              ← 压缩后的结果
            ├─ success=False → gap_analysis 必填 ← programmatic eval floor
            └─ failure_category               ← L2 FailureFocuser 读取

   实现示例（不在本文件）：
   ├─ BaseResultSummarizer                    ← 通用校验基类
   ├─ CodexResultSummarizer                   ← Codex 专属
   ├─ ClaudeCodeResultSummarizer              ← Claude Code 专属
   └─ SelfCopyResultSummarizer                ← 自复制 subagent 专属
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
bootstrap
    └─ 为每个 specialist 绑定专属 ResultSummarizer 实现
        ═══════════ 进入 Agent 循环 ═══════════

② runtime 返回后（每次派活）
SpecialistRuntime.execute()
    └─ return SpecialistRawResult(raw_output, artifacts, usage, ...)
          │
          ▼
ResultSummarizer.summarize(
    raw_output       ← 来自 RawResult
    artifacts        ← 来自 RawResult
    goal             ← 来自 Request
    success_criteria ← 来自 Request
)
    ├─ 校验产物存在性
    ├─ 校验 success_criteria 回应
    ├─ 校验无敏感改动
    ├─ success=False → 填 gap_analysis
    ├─ 启发式生成 failure_category          ← L2 消费
    └─ return SpecialistResult
          │
          ▼
回传 Leader（不返回 raw_output 全量，控制上下文膨胀）
```

### 0.3. 补充

**`result_summarizer.py` 是 multiagent 的"输出闸门"——它同时承担两个职责：压缩输出 + 程序化评估（programmatic eval）。**

几点补充：

- **Protocol 而非 ABC**：用 `typing.Protocol` 定义，实现方无需显式继承，duck typing 即可。`...` 是占位符，表示"实现方负责"。
- **一个方法两个职责**：`summarize` 既压缩又评估。校验 `success_criteria` 是"程序化评估"的最低要求（floor），不依赖 LLM。
- **与 ContextSummarizer 对称**：输入端 `ContextSummarizer` 压上下文，输出端 `ResultSummarizer` 压结果，一进一出配对。
- **per-specialist 实现**：契约只有一份，但每个 specialist 有专属实现——因为不同 specialist 的输出格式、成功判定标准不同。
- **`failure_category` 是 L2 的输入**：这个字段不是给 Leader 看的，是给 L2 `FailureFocuser` 做失败归类用的。
