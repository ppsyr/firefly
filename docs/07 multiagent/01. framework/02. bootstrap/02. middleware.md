---

name: OrchestrationMiddleware — 横切打点 + 产物汇总。

description: 

【整体职责】
在工具调用层拦截 delegate_to_* 这类"委派给 specialist"的调用，做两件事：
1. 打点：在调用前后维护 multiagent 的四个计数器
   （selection / invoked / completion / fallback）。
2. 产物汇总：把 specialist 返回的 artifacts 归一化为 ArtifactRef 列表，
   写进 ThreadState.orchestration（active_specialists + specialist_artifacts）。

【内容摘要】
- _tool_text()                     : 把工具结果压平成字符串（供 success 判定 / artifacts 解析）。
- OrchestrationMiddleware          : 中间件主类，实现 wrap_tool_call / awrap_tool_call。
- _is_delegate_tool()              : 判断是否委派类工具（名字以 delegate_to_ 开头）。
- _extract_specialist_name()       : 从工具名剥出 specialist 名。
- _is_success()                    : 从结果 JSON 判定成败。
- _build_orchestration_update()    : 构造写入 ThreadState.orchestration 的更新。
- _before_handler()                : handler 前的 state 暴露 + selection/invoked 打点。
- _after_handler()                 : handler 后的 completion/fallback 打点 + orchestration 构造。
- _make_error_response()           : specialist 抛异常时合成 error ToolMessage 的 Command。
- wrap_tool_call / awrap_tool_call : 同步 / 异步拦截入口。

【职责边界】
- 只负责：横切打点、产物汇总、异常转 ToolMessage。
- 不负责：选择哪个 specialist（由 LLM 自行决定，soft routing）、
  specialist 实际执行（runtime 负责）、L2 触发与预算检查
  （l2_trigger_middleware / budget_guard 预留，本文件未使用）。
- 非委派工具直接透传，不做任何处理。

## 0. 结构树

### 0.1. 静态结构树

```
middleware.py — OrchestrationMiddleware（横切打点 + 产物汇总）
│
├─ _tool_text(result) -> str                  ← 把工具结果压平成字符串
│   ├─ ToolMessage：content 为 str → 原样
│   │                content 为 list → 逐项拼接（dict 取 "text"）
│   │                其他 → str(content)
│   ├─ Command：递归取 update.messages[0]；无 messages → str
│   └─ 其他对象：str(result)
│
└─ OrchestrationMiddleware(AgentMiddleware)   ← 中间件主类
    │                                            拦截 delegate_to_* 工具调用
    │                                            非 delegate_to_* → 直接透传
    │
    ├─ state_schema = ThreadState             ← 声明中间件处理的 state 类型
    │
    ├─ __init__(metrics_store, l2_trigger_middleware, budget_guard)
    │   ├─ _metrics: MultiAgentMetricsStore | None    ← 打点用；None 则不打点
    │   ├─ _l2_trigger_middleware: Any | None         ← 预留，本文件未使用
    │   └─ _budget_guard: Any | None                  ← 预留，本文件未使用
    │
    ├─ _is_delegate_tool(tool_name) -> bool   ← 判断名字是否以 "delegate_to_" 开头
    ├─ _extract_specialist_name(tool_name)    ← 从 "delegate_to_X" 剥出 X
    ├─ _is_success(result) -> bool            ← 压平后 json.loads 取 "success" 字段
    │
    ├─ _build_orchestration_update(name, result) -> dict
    │   └─ 从结果 JSON 的 "artifacts" 构造 ArtifactRef 列表
    │      返回 {active_specialists: [name], specialist_artifacts: [...]}
    │
    ├─ _before_handler(request, name) -> None ← handler 前：暴露 state + 打点
    │   ├─ set_current_state(request.state)
    │   ├─ record_selection(name)
    │   └─ record_invoked(name)
    │
    ├─ _after_handler(name, result) -> dict   ← handler 后：打点 + 构造 orchestration
    │   ├─ _is_success → record_completion 或 record_fallback
    │   └─ _build_orchestration_update(...)
    │
    ├─ _make_error_response(request, exc, name) -> Command
    │   └─ 合成 error ToolMessage（status="error"）+ orchestration
    │      保证 AIMessage(tool_calls) → ToolMessage 配对
    │
    ├─ wrap_tool_call(request, handler) -> Any       ← 同步入口（@override）
    │   ├─ 非 delegate_to_* → handler(request) 透传
    │   ├─ _before_handler
    │   ├─ try: result = handler(request)
    │   │   except → record_fallback + _make_error_response
    │   ├─ orch_update = _after_handler
    │   └─ result 是 Command → 合并 orchestration；否则包 Command 返回
    │
    └─ awrap_tool_call(request, handler) -> Any      ← 异步入口（@override）
        └─ 逻辑同 wrap_tool_call，仅 handler 改为 await
```

### 0.2. 运行时调用树

```
① 装配期
setup_multiagent
    └─ OrchestrationMiddleware(metrics_store, l2_trigger_mw?, budget_guard?)
        → 挂到 Leader 的中间件链（在 ToolCallMiddleware 之后）
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（LLM 发起工具调用）
Leader 执行 → ToolNode 触发 wrap_tool_call
    │
    ├─ 工具名不以 delegate_to_ 开头
    │   └─ handler(request) 直接透传（不处理）
    │
    └─ 工具名以 delegate_to_ 开头
        │
        ├─ _extract_specialist_name(tool_name)      ← 剥出 specialist 名
        ├─ _before_handler
        │   ├─ set_current_state(state)             ← 暴露 ThreadState 给 tool handler
        │   ├─ record_selection(name)               ← metrics 打点
        │   └─ record_invoked(name)                 ← metrics 打点
        │
        ├─ try: handler(request)                    ← 实际调用 specialist tool
        │   │
        │   ├─ 成功
        │   │   └─ _after_handler
        │   │       ├─ _is_success(result) → record_completion / fallback
        │   │       └─ _build_orchestration_update  ← ArtifactRef 列表
        │   │
        │   └─ 异常
        │       ├─ record_fallback(name)
        │       └─ _make_error_response → Command{error ToolMessage + orchestration}
        │
        └─ 返回 Command{update: {messages, orchestration}}
              → 写回 ThreadState.orchestration
              → active_specialists / specialist_artifacts 被更新
```

### 0.3. 补充

**`middleware.py` 是 multiagent 的"打点与汇总拦截器"——在工具调用层拦截 `delegate_to_*`，负责记账、归集产物、兜底异常，但不参与路由。**

几点补充：

- **soft routing**：选哪个 specialist 完全由 LLM 决定（通过 tool call），中间件不做任何路由判断，只认"名字是否以 `delegate_to_` 开头"。
- **pairing 完整性是硬约束**：specialist 抛异常时必须返回 error `ToolMessage`，否则 `AIMessage(tool_calls)` 后面缺 `ToolMessage`，下一轮 model 调用会被 LLM 侧拒绝（400）。这是把它放在中间件而非 try/except 里的根本原因。
- **同步 / 异步双入口逻辑必须镜像**：`wrap_tool_call` 和 `awrap_tool_call` 只有 `handler(request)` 一处不同（后者 `await`）。改其中一个必须同步改另一个。
- **`l2_trigger_middleware` / `budget_guard` 是预留位**：构造参数接收了，但本文件完全没使用。真正的预算检查和 L2 触发在别处（或后续版本接入）。
- **`set_current_state` 是"上下文桥"**：把当前 `ThreadState` 暴露给 specialist tool handler，让 handler 内部能读到 state（如 sandbox_id）。用 ContextVar 实现，见 `tools.py`。
- **产物归一化是"扁平化"**：specialist 返回的 artifacts 是 JSON dict，中间件转成 `ArtifactRef`（只留 path / type / specialist_name），避免异构 specialist 的产物结构泄漏到 `ThreadState`。
