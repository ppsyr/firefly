---

name: MultiAgentMetricsStore — multiagent 编排的 SQLite 指标存储。

description: 

【整体职责】
以 SQLite 持久化 multiagent 的运行指标与辅助数据，供健康检查、L2 进化、L3 评估读取。
存储 9 张表：specialist 计数器、judgment 明细、进化产物/实验、L2 指标、
预算用量/告警、L2 阻断模式、决策日志（主表 + 归档表）。

【内容摘要】
- _SCHEMA_VERSION / _SCHEMA_SQL  : schema 版本与建表 SQL（9 张表）。
- SpecialistMetrics              : specialist 聚合指标（从 specialist_records 派生）。
- SpecialistHealth               : specialist 健康状态（health_check 输出）。
- MultiAgentMetricsStore         : 存储主类，提供打点、查询、健康检查、决策日志、归档等方法。

【职责边界】
- 只负责：SQLite 建表、打点写入、指标查询、决策日志存取与归档。
- 不负责：指标消费决策（health_check 只判定，不触发动作）、L2/L3 业务逻辑
  （通过 MetricsView 协议暴露数据给它们）、specialist 执行。
- 不进 ThreadState：指标与线程状态分离。

---
| 层      | 名称                     | 干什么                                                 | 默认     | 触发方式          |
| ------ | ---------------------- | --------------------------------------------------- | ------ | ------------- |
| **L1** | 运行层（Runtime / Metrics） | 每次派活都记录指标（选择/调用/完成/回退）                              | 常开     | 每次调用          |
| **L2** | 进化层（Evolution）         | 读 L1 指标 → 发现退化/失败 → 变异 specialist/prompt → 产生新版本    | **关闭** | 数据驱动（周期 + 阈值） |
| **L3** | 评估层（Eval）              | 给 specialist 的产出打分（programmatic / LLM judge），产出决策日志 | **关闭** | 数据驱动          |

## 0. 结构树

### 0.1. 静态结构树

```
metrics.py — MultiAgentMetricsStore（multiagent 编排的 SQLite 指标存储）
│
├─ _SCHEMA_VERSION: int = 3                   ← schema 版本号；低于此值触发建表/升级
├─ _SCHEMA_SQL: str                           ← 建表 SQL（9 张表 + 索引，全部 IF NOT EXISTS）
│   ├─ specialist_records                     ← specialist 4 计数器主表（L1）
│   ├─ specialist_judgments                   ← 每次调用明细（L1）
│   ├─ evolution_artifacts                    ← 进化产物（L2）
│   ├─ evolution_experiments                  ← 进化实验记录（L2）
│   ├─ l2_metrics                             ← L2 指标事件（L2）
│   ├─ specialist_budget_usage                ← 每日预算用量（预算）
│   ├─ budget_warnings                        ← 预算告警（预算）
│   ├─ l2_blocked_patterns                    ← 被阻断 pattern（L2）
│   ├─ specialist_decision_log                ← 决策日志主表（L3）
│   └─ specialist_decision_log_archive        ← 决策日志归档表（L3）
│
├─ SpecialistMetrics(frozen)                  ← specialist 聚合指标（从 specialist_records 派生）
│   ├─ specialist_name: str                   ← specialist 名称
│   ├─ total_selections: int                  ← 被选中次数
│   ├─ total_invoked: int                     ← 被调用次数
│   ├─ total_completions: int                 ← 成功完成次数
│   ├─ total_fallbacks: int                   ← 回退次数
│   ├─ completion_rate (property) -> float    ← completions / invoked；invoked=0 → 0.0
│   └─ fallback_rate (property) -> float      ← fallbacks / invoked；invoked=0 → 0.0
│
├─ SpecialistHealth(frozen)                   ← specialist 健康状态（health_check 输出）
│   ├─ specialist_name: str                   ← specialist 名称
│   ├─ completion_rate: float                 ← 完成率
│   ├─ total_invoked: int                     ← 被调用次数
│   └─ degraded: bool                         ← 是否退化（rate < 阈值 且 invoked >= 下限）
│
└─ MultiAgentMetricsStore                     ← 存储主类
    ├─ __init__(db_path)                      ← 建父目录 + 初始化 schema
    │
    ├─ _connect() -> Connection               ← 建连接（WAL + busy_timeout）
    ├─ _init_schema()                         ← 按版本号建表 / 升级
    ├─ _upsert_counter(name, field)           ← 计数器 +1 的 upsert（内部）
    │
    ├─ ① L1 打点
    │   ├─ record_selection(name)             ← total_selections +1
    │   ├─ record_invoked(name)               ← total_invoked +1
    │   ├─ record_completion(name)            ← total_completions +1
    │   ├─ record_fallback(name)              ← total_fallbacks +1
    │   └─ record_judgment(...)               ← 写一条调用明细
    │
    ├─ ② L1 查询
    │   ├─ get_metrics(name) -> Metrics|None  ← 单个聚合指标
    │   ├─ get_top_specialists(limit)         ← 按 invoked 降序取前 N
    │   ├─ health_check(threshold, min)       ← 健康检查，返回全部状态
    │   ├─ list_specialists() -> list[str]    ← 列出有记录的 specialist
    │   └─ get_failure_categories() -> dict   ← 按失败分类统计（L2 消费）
    │
    ├─ ③ MetricsView 协议实现（供 L2 读 L1）
    │   ├─ get_specialist_metrics(name, since)← 单 specialist 快照（含成本/延迟）
    │   ├─ get_global_metrics(since)          ← 全局快照
    │   └─ get_recent_failures(category, limit)← 某分类最近 N 条失败
    │
    └─ ④ L3 决策日志
        ├─ save_decision_log(record)          ← 保存一条决策日志
        ├─ get_decision_logs(name, cat, limit)← 查询决策日志
        └─ archive_decision_logs(retention)   ← 归档过期日志，返回条数
```

### 0.2. 运行时调用树

```
① 装配期（启动时一次）
MultiAgentMetricsStore(db_path)
    ├─ Path(db_path).parent.mkdir(...)         ← 建父目录
    └─ _init_schema()
        ├─ PRAGMA user_version                 ← 读当前版本
        └─ version < _SCHEMA_VERSION → executescript(_SCHEMA_SQL) + 更新版本
        ═══════════ 进入 Agent 循环 ═══════════

② L1 打点（每次派活，常开）
Leader 派活
    ├─ record_selection(name)                  ← 选中时
    ├─ record_invoked(name)                    ← 实际调用时
    ├─ record_completion(name) 或 fallback     ← 结束时
    └─ record_judgment(run_id, name, success, duration, tokens, cost, fc, gap)

③ L1 查询（随时）
health_check(threshold, min_invoked)
    └─ get_top_specialists(100) → 逐个算 degraded

④ L2 读 L1（MetricsView 协议）
L2 Evolution
    ├─ get_specialist_metrics(name)            ← 单 specialist 快照
    ├─ get_global_metrics()                    ← 全局快照
    ├─ get_failure_categories()                ← 失败分类统计
    └─ get_recent_failures(category, limit)    ← 某类最近失败
        ═══════════ L3 评估 ═══════════

⑤ L3 决策日志
L3 Eval
    ├─ save_decision_log(record)               ← 存 lesson
    └─ archive_decision_logs(retention_days)   ← 周期归档
```

### 0.3. 补充

**`metrics.py` 是 multiagent 的"数据底座"——L1 打点常开，L2/L3 按需读取；所有层的数据都汇到同一个 SQLite。**

几点补充：

- **9 张表分属不同层**：`specialist_records` / `specialist_judgments` 是 L1；`evolution_artifacts` / `evolution_experiments` / `l2_metrics` / `l2_blocked_patterns` 是 L2；`specialist_decision_log(+archive)` 是 L3；`specialist_budget_usage` / `budget_warnings` 服务预算。
- **schema 版本机制**：`PRAGMA user_version` 记版本，低于 `_SCHEMA_VERSION` 才建表。当前不处理"降级"或"增量迁移"，版本升级会重跑全量建表 SQL（`IF NOT EXISTS` 保证幂等）。
- **锁策略简单粗暴**：所有读写都持 `threading.Lock`，每次操作新建连接。没有连接池、没有读写分离，以"简单正确"优先。
- **`since` 参数存在但实现不完整**：`get_specialist_metrics` / `get_global_metrics` / `get_failure_categories` 都接受 `since`，但内部忽略它（`since_str = utc_now_iso()` 写死当前时间）。**这是已知的半成品**。
- **lazy import 避免循环依赖**：`FailureCategory` / `FailureRecord` / `DecisionLogRecord` 在方法内 import，因为 `metrics.py` 被 evolution / eval 反向引用。
- **成本估算为占位**：`tokens * 0.00002` 是硬编码占位价，真实价格应从 config 取。
- **决策日志归档是"复制 + 删除"两步**：先 `INSERT INTO archive SELECT ...`，再 `DELETE`，同一事务内完成。
