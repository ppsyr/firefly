---

name: Multi-Agent bootstrap — 装配 specialist + 凭证检测 + metrics + 注入 CapabilityRegistry。

description: 

【整体职责】
multiagent 的装配入口：按 config 反射加载 specialist、检测凭证、构造 metrics /
middleware / tools，并把结果打包成 MultiAgentSetup 交给 CapabilityRegistry 注入。
enabled=false 时返回空 setup，Leader 行为不变。

【内容摘要】
- _warn_specialist_disabled() : 凭证缺失时按 specialist 类型打印启用指引（不阻塞主流程）。
- MultiAgentSetup(frozen)     : 装配结果容器（registry / subagent / metrics / middleware / tools / l2）。
- _EMPTY_SETUP                : enabled=false 时返回的空 setup。
- _load_specialist()          : 反射加载单个 specialist + 凭证检测 + 匹配 summarizer。
- setup_multiagent()          : 装配主入口。

【职责边界】
- 只负责：反射加载、凭证检测、构造 metrics/middleware/tools、打包 setup、warn 提示。
- 不负责：运行时派活（Leader / runtime 负责）、L2 内部装配（evolution.bootstrap 负责）、
  specialist 实际执行。
- 不持有状态：函数式装配，产出 setup 后即退出。

## 0. 结构树

### 0.1. 静态结构树

```
bootstrap.py — Multi-Agent bootstrap（装配 specialist + 凭证检测 + metrics + 注入）
│
├─ _warn_specialist_disabled(name, reason)   ← 凭证缺失时的分级提示（不阻塞主流程）
│   ├─ "pi"      → warning + Pi CLI 安装步骤
│   ├─ "codex"   → warning + Codex CLI 安装/登录步骤
│   ├─ "claude"  → warning + Claude Code 安装/登录步骤
│   ├─ "subagent"→ error（subagent 应零配置可用，disabled = bug）
│   └─ 其他      → warning + 简要原因
│
├─ MultiAgentSetup(frozen)                    ← 装配结果容器（供 CapabilityRegistry 注入）
│   ├─ specialist_registry: SpecialistRegistry | None
│   ├─ subagent_provider: SubagentRuntime | None
│   ├─ metrics_store: MultiAgentMetricsStore | None
│   ├─ orchestration_middleware: OrchestrationMiddleware | None
│   ├─ specialist_tools: tuple[BaseTool, ...]
│   └─ l2_setup: Any | None = None           ← L2 未启用时 None
│
├─ _EMPTY_SETUP: MultiAgentSetup              ← enabled=false 时返回的空 setup
│                                                所有字段为空，Leader 行为不变
│
├─ _load_specialist(name, config, agent_factory) -> tuple | None
│   │                                            ← 反射加载单个 specialist + 凭证检测 + 匹配 summarizer
│   │                                            返回 (specialist, ctx_summarizer, result_summarizer)
│   │                                            None = disabled（凭证缺失或未知 name）
│   │
│   ├─ "pi"        → PiInstaller.ensure_installed → PiCredentialProvider.get_credential
│   │                → PiSpecialist(PiRuntime(PiRuntimeConfig)) + Pi*Summarizer
│   │
│   ├─ "codex"     → CodexCredentialProvider.get_credential
│   │                → CodexSpecialist + Codex*Summarizer
│   │
│   ├─ "claude"    → ClaudeCredentialProvider.get_credential
│   │                → ClaudeCodeSpecialist + ClaudeCode*Summarizer
│   │
│   ├─ "subagent"  → SubagentRuntime(agent_factory) → SubagentSpecialist
│   │                + SelfCopy*Summarizer
│   │
│   └─ 其他        → None
│
└─ setup_multiagent(config, agent_factory) -> MultiAgentSetup
    │                                            ← 装配主入口
    ├─ ① enabled 检查
    │   └─ false → return _EMPTY_SETUP
    │
    ├─ ② 构造 metrics
    │   └─ MultiAgentMetricsStore(config.metrics_db_path)
    │
    ├─ ③ L2 装配
    │   └─ evolution.bootstrap.setup_l2(config, metrics) → l2_setup | None
    │
    ├─ ④ 构造 middleware
    │   └─ OrchestrationMiddleware(metrics, l2_trigger_mw?, budget_guard?)
    │
    ├─ ⑤ 遍历 specialists_use
    │   └─ _load_specialist → register + make_specialist_tool
    │
    ├─ ⑥ subagent 兜底（仅当 "subagent" 不在 specialists_use 时）
    │   ├─ SubagentRuntime(agent_factory)
    │   └─ make_subagent_tool(...)
    │
    ├─ ⑦ L2 worker 启动
    │   └─ l2_setup.worker.start()
    │
    └─ ⑧ 打包 MultiAgentSetup 返回
```

### 0.2. 运行时调用树

```
① 启动期（应用 bootstrap 调用一次）
app.bootstrap
    └─ setup_multiagent(config, agent_factory)
        │
        ├─ enabled=false → return _EMPTY_SETUP（Leader 行为不变）
        │
        ├─ metrics = MultiAgentMetricsStore(...)      ← 打开 SQLite
        ├─ l2_setup = setup_l2(config, metrics)       ← L2 未启用则 None
        ├─ orch_mw = OrchestrationMiddleware(...)
        │
        ├─ for name in config.specialists_use:
        │     ├─ _load_specialist(name, config, agent_factory)
        │     │     ├─ 反射 import specialist / runtime / summarizer / credential
        │     │     ├─ 凭证检测 → None 则返回 None
        │     │     └─ 返回 (specialist, ctx_sum, res_sum) | None
        │     │
        │     ├─ None → _warn_specialist_disabled(name, reason); continue
        │     └─ 非 None → registry.register + tools.append(make_specialist_tool)
        │
        ├─ if "subagent" not in specialists_use:
        │     └─ tools.append(make_subagent_tool(SubagentRuntime(agent_factory), ...))
        │
        ├─ if l2_setup: l2_setup.worker.start()        ← L2 daemon 线程
        │
        └─ return MultiAgentSetup(registry, subagent_provider, metrics,
                                  orch_mw, tools, l2_setup)
        ═══════════ 进入 Agent 循环 ═══════════

② 装配结果注入
CapabilityRegistry
    ├─ .specialist_registry = setup.specialist_registry
    ├─ .metrics_store = setup.metrics_store
    ├─ .orchestration_middleware = setup.orchestration_middleware
    └─ .specialist_tools = setup.specialist_tools
    → Leader 装配时读取以上组件

③ 运行期（Leader 派活）
Leader → registry.get(name) → specialist.invoke(...)   ← 走运行时链路
```

### 0.3. 补充

**`bootstrap.py` 是 multiagent 的"装配总入口"——把 config 变成一组可用组件（registry / metrics / middleware / tools / l2），打包成 `MultiAgentSetup` 交给上层注入。**

几点补充：

- **enabled=false 是短路**：直接返回 `_EMPTY_SETUP`，后续完全不执行，保证 Leader 行为零变化。这是"opt-out 安全"的写法。
- **凭证缺失是正常路径**：`_load_specialist` 返回 None 时只 warn 不抛，跳过该 specialist；系统继续装配其他 specialist。**subagent 例外**——它 disabled 被视为 bug，打 error。
- **反射加载是"分散的 if 链"**：没有用注册表 / 工厂模式，而是对每个 name 手写 import + 构造。好处是显式、易读；代价是新增 specialist 要改这里。
- **subagent 有两条进入路径**：
  - 在 `specialists_use` 里 → 走 `_load_specialist` 分支，注册为普通 specialist。
  - 不在 `specialists_use` 里 → 走 ⑥ 兜底分支，单独生成 `delegate_to_subagent` 工具。
  - **两条路径互斥**，避免重复注册。
- **L2 是可选装配**：`setup_l2` 返回 None 时，middleware / tools 都不注入 L2 相关参数，L1 行为完全不变。L2 启用时最后启动 daemon 线程。
- **【已知不一致】**：`_load_specialist` 的 subagent 分支返回的三元组中，`result_summarizer` 在调用方 `setup_multiagent` 里被使用（传给 `make_specialist_tool`），但在 ⑥ 兜底分支里是**另起一个 `SelfCopyResultSummarizer()`**，不是复用同一条路径。两处实例化逻辑重复，但对象不同——这是一个容易看漏的点。
