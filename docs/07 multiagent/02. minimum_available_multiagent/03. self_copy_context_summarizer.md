---

name: SelfCopyContextSummarizer — 自复制 subagent 的输入端转换器。

description: 

【整体职责】
为 self-copy subagent 生成 context_summary：优先用 LLM 精准提取研究上下文，
无 LLM 时退回规则提取（goal + success_criteria + user_input + 最近 observations）。
只输出精简字符串，不传全量 ThreadState。

【内容摘要】
- _MAX_OBSERVATIONS / _MAX_SUMMARY_CHARS : 规则提取的截断上限。
- _field()                               : 从 dict 或对象中统一取字段。
- SelfCopyContextSummarizer              : 输入端转换器主类。
- summarize()                            : 入口，按有无 LLM 分派。
- _rule_summarize()                      : 无 LLM 时的规则提取。
- _llm_summarize()                       : 有 LLM 时的精准提取（MVP 为占位实现）。

【职责边界】
- 只负责：从 ThreadState 提取并压缩成 context_summary 字符串。
- 不负责：结果压缩（ResultSummarizer 负责）、specialist 执行、LLM 的构造。
- 不持有运行时状态：LLM 引用由构造参数传入，可为 None。

## 0. 结构树

### 0.1. 静态结构树

```
self_copy_context_summarizer.py — SelfCopyContextSummarizer（自复制 subagent 的输入端转换器）
│
├─ _MAX_OBSERVATIONS: int = 5                 ← 规则提取时最多取最近 N 条 observation
├─ _MAX_SUMMARY_CHARS: int = 3000             ← 规则提取结果的最大字符数
│
├─ _field(item, name) -> Any                  ← 统一字段访问
│   ├─ dict   → item.get(name)
│   └─ 对象   → getattr(item, name, None)
│
└─ SelfCopyContextSummarizer                  ← 输入端转换器主类
    │                                            LLM 提取 + 规则 fallback
    │                                            输出精简 context_summary 字符串
    │
    ├─ _llm: Any | None                       ← 构造注入；None 则走规则路径
    │
    ├─ __init__(llm=None)                     ← 注入 LLM
    │
    ├─ summarize(state, goal, success_criteria, template=None) -> str
    │   │                                        ← 入口，按有无 LLM 分派
    │   ├─ llm 非 None → _llm_summarize
    │   └─ llm 为 None → _rule_summarize
    │
    ├─ _rule_summarize(state, goal, success_criteria, template=None) -> str
    │   │                                        ← 规则提取路径
    │   ├─ 拼 "Goal: ..." / "Success criteria: ..."
    │   ├─ 有 user_input → 拼 "Original request: ..."
    │   ├─ 取 observations[-5:] → 逐条拼 "Finding: ..."
    │   └─ 总长 > 3000 → 截断 + "...(truncated)"
    │
    └─ _llm_summarize(state, goal, success_criteria, template=None) -> str
        │                                        ← LLM 提取路径（MVP 占位实现）
        ├─ 构造 prompt（含 goal / criteria / user_input）
        ├─ self._llm.invoke(prompt)
        └─ 取 content 字段返回
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap._load_specialist 的 subagent 分支）
_load_specialist("subagent", config, agent_factory)
    ├─ SubagentRuntime(agent_factory=agent_factory)
    ├─ SelfCopyContextSummarizer()              ← 构造（无 LLM）
    └─ SubagentSpecialist(runtime=runtime)
        → make_specialist_tool(name, specialist, ctx_sum, res_sum, ...)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（Leader 派活给 subagent）
delegate_to_subagent tool handler
    │
    ▼
SelfCopyContextSummarizer.summarize(state, goal, success_criteria)
    │
    ├─ self._llm 非 None → _llm_summarize
    │     ├─ 拼 prompt
    │     ├─ self._llm.invoke(prompt)           ← LLM 调用
    │     └─ return content
    │
    └─ self._llm 为 None → _rule_summarize
          ├─ 拼 Goal / Success criteria
          ├─ user_input → "Original request: ..."
          ├─ observations[-5:] → "Finding: ..."
          └─ 截断到 3000 字符
    │
    ▼
返回 context_summary 字符串
    → 填入 SubagentRequest.context_summary
    → 传给 SubagentRuntime.invoke
```

### 0.3. 补充

**`self_copy_context_summarizer.py` 是 self-copy subagent 的"输入端闸门"——把父 Agent 的 ThreadState 压缩成一段精简 context_summary，只保留 goal、成功标准、原始请求和最近几条观察。**

几点补充：

- **双路径，LLM 可选**：`self._llm` 为 None 时走规则提取，保证"零 LLM 也能用"。装配时 bootstrap 传的是 `SelfCopyContextSummarizer()`（无 LLM），所以**实际运行走的是规则路径**——LLM 路径是预留。
- **LLM 路径是占位实现**：`_llm_summarize` 只是"拼 prompt → invoke → 取 content"，没有针对 subagent 场景的精细提取逻辑，属于 MVP 占位。
- **截断是硬约束**：规则路径总长超过 3000 字符直接截断，不做智能压缩。目的是**控制 token 成本**，宁可丢信息也不超预算。
- **只取最近 5 条 observation**：不是全部。原因同上——subagent 的 context 不需要父 Agent 的全部历史，只取最近的相关观察。
- **`template` 参数全程未用**：两条路径都接收 `template`，但都没使用。这是 L2 扩展的预留位（L2 启用时可能传入模板来定制提取规则）。
- **只读 ThreadState，不修改**：`state.get(...)` 只读，不写回。**输入端摘要器是纯函数式读取，不产生副作用。**
