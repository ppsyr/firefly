---

name: SubagentSpecialist — 组合 SubagentRuntime 的 self-copy specialist。

description: 

【整体职责】
把 SubagentRuntime 适配为 SpecialistAgent 契约：对外表现为一个名为 "subagent"、
能力为 RESEARCH 的 specialist，内部只做转发——invoke 直接调 runtime.invoke。

【内容摘要】
- SubagentSpecialist : specialist 实现，组合 SubagentRuntime。

【职责边界】
- 只负责：暴露 name / capabilities / invoke 三成员，invoke 转发给 runtime。
- 不负责：实际执行（SubagentRuntime 负责）、上下文摘要、结果摘要、凭证获取。
- 不持有状态：内部只持有 runtime 引用。

## 0. 结构树 — self-copy subagent 全流程

### 0.1. 静态结构树

```
self-copy subagent 体系（跨文件）
│
├─ 【装配期参与的文件】
│   ├─ bootstrap.py                    ← 装配入口：造组件、注册 specialist、生成 tool
│   ├─ subagent_specialist.py          ← specialist 实现：把 runtime 适配成 SpecialistAgent 契约
│   ├─ subagent_runtime.py             ← runtime 实现：进程内调 lead factory 跑子 Agent
│   ├─ self_copy_context_summarizer.py ← 输入端摘要器：压父上下文成 context_summary
│   ├─ self_copy_result_summarizer.py  ← 输出端摘要器：薄壳，复用基类校验
│   ├─ tools.py                        ← tool 工厂：生成 LLM 可见的 delegate_to_subagent
│   └─ registry.py                     ← 注册表：存 specialist 实例，供 Leader 查询
│
├─ 【运行时参与的文件】
│   ├─ middleware.py                   ← 拦截 delegate_to_*：打点 + 汇总产物
│   ├─ tools.py                        ← tool handler：派活编排（摘要→执行→摘要→JSON）
│   ├─ subagent_specialist.py          ← invoke 转发：specialist → runtime
│   ├─ subagent_runtime.py             ← 实际执行：建隔离 state → agent.invoke
│   ├─ self_copy_context_summarizer.py ← 压上下文
│   ├─ self_copy_result_summarizer.py  ← 压结果（走基类）
│   └─ base.py                         ← BaseResultSummarizer：真正的校验与压缩逻辑
│
└─ 【组件清单与去向】
    │
    ├─ SubagentSpecialist              ← ✅ 进 registry（name="subagent"）
    │   ├─ _runtime: SubagentRuntime   ← ❌ 不进 registry，被 Specialist 持有
    │   │                                用途：invoke 时转发执行
    │   ├─ name = "subagent"           ← 用途：决定 tool 名 / registry key
    │   └─ capabilities = (RESEARCH,)  ← 用途：list_specialists 按能力过滤
    │
    ├─ SubagentRuntime                 ← ❌ 不进 registry
    │   └─ _agent_factory: Callable    ← ❌ 不进 registry，构造注入
    │                                    用途：每次 invoke 造一个 leaf-role 子 Agent
    │
    ├─ SelfCopyContextSummarizer       ← ❌ 不进 registry
    │   └─ _llm: Any | None            ← 装配时传 None，走规则路径
    │                                    用途：把父 ThreadState 压成 context_summary
    │
    ├─ SelfCopyResultSummarizer        ← ❌ 不进 registry
    │   └─ 继承 BaseResultSummarizer   ← 真正的 summarize 逻辑在基类
    │                                    用途：校验成功标准 + 压结果成 SpecialistResult
    │
    └─ delegate_to_subagent (BaseTool) ← ❌ 不进 registry
        ├─ 闭包捕获: SubagentSpecialist          ← 用途：invoke 时调它
        ├─ 闭包捕获: SelfCopyContextSummarizer   ← 用途：invoke 前压上下文
        ├─ 闭包捕获: SelfCopyResultSummarizer    ← 用途：invoke 后压结果
        ├─ 闭包捕获: max_steps=20                ← 用途：传给 SubagentRequest
        └─ 闭包捕获: timeout_seconds=300         ← 用途：传给 SubagentRequest
```

### 0.2. 装配期调用树

```
① bootstrap.setup_multiagent(config, agent_factory)
   │  用途：multiagent 装配主入口，把 config 变成一组可用组件
   │
   ├─ metrics = MultiAgentMetricsStore(...)
   │  用途：建 SQLite 账本，供 L1 打点 / L2 读指标
   │
   ├─ l2_setup = setup_l2(config, metrics)
   │  用途：装配 L2 进化层；未启用返回 None
   │
   ├─ orch_mw = OrchestrationMiddleware(...)
   │  用途：造拦截器，运行时拦截 delegate_to_* 打点 + 汇总
   │
   ├─ specialist_registry = SpecialistRegistry()
   │  用途：建空花名册，准备注册 specialist
   │
   └─ for name in config.specialists_use:
       │  用途：按配置逐个装配 specialist
       │
       └─ name == "subagent" 时：
           │
           ▼
② bootstrap._load_specialist("subagent", config, agent_factory)
   │  用途：反射加载一个 specialist，返回 (specialist, ctx_sum, res_sum) 或 None
   │
   ├─ runtime = SubagentRuntime(agent_factory=agent_factory)
   │  用途：造 runtime，持有 agent_factory 供运行时造子 Agent
   │
   └─ return (
          SubagentSpecialist(runtime=runtime),         ← ① specialist：适配 runtime 为契约
          SelfCopyContextSummarizer(),                 ← ② ctx 摘要器：压输入
          SelfCopyResultSummarizer(),                  ← ③ result 摘要器：压输出
      )
   │
   ▼
③ bootstrap.setup_multiagent 收到三元组
   │
   ├─ specialist_registry.register(specialist)
   │  用途：✅ 唯一注册点——把 specialist 存进 registry，供 Leader 查能力/取名
   │  结果：registry._specialists["subagent"] = SubagentSpecialist
   │
   └─ tools.append(
          make_specialist_tool(
              name="subagent",
              specialist,                              ← 闭包捕获，运行时调它
              ctx_summarizer,                          ← 闭包捕获，运行时压上下文

              max_steps=config.max_steps,
              timeout_seconds=config.timeout_seconds,
          )
      )
   │  用途：为 specialist 生成一个 LLM 可见的工具
   │
   ▼
④ tools.py make_specialist_tool(...)
   │  用途：工厂函数，把 specialist + 两个 summarizer + 参数封进一个 BaseTool
   │
   └─ @tool("delegate_to_subagent")
       └─ return delegate_tool
           │  用途：产出 BaseTool，名字固定 delegate_to_subagent
           │        内层 handler 捕获闭包，运行时执行派活编排
           │
           ▼
⑤ setup_multiagent 打包
   │  用途：把所有组件装进 MultiAgentSetup，交给上层
   │
   └─ return MultiAgentSetup(
          specialist_registry=specialist_registry,     ← 含 SubagentSpecialist
          subagent_provider=subagent_provider,         ← 通常 None（已作为 specialist 注册）
          metrics_store=metrics,                       ← 账本
          orchestration_middleware=orch_mw,            ← 拦截器
          specialist_tools=(..., delegate_to_subagent, ...),  ← 工具在这里
          l2_setup=l2_setup,                           ← L2 装配结果
      )
   │
   ▼
⑥ CapabilityRegistry 注入（不在本文件）
   │  用途：把 setup 的各字段挂到中央 registry，供 Leader 取用
   │
   ├─ registry.specialist_registry = setup.specialist_registry
   │  用途：Leader 可查 specialist 能力
   ├─ registry.specialist_tools = setup.specialist_tools
   │  用途：Leader 可取工具注入
   ├─ registry.orchestration_middleware = setup.orchestration_middleware
   │  用途：Leader 可挂中间件
   └─ registry.metrics_store = setup.metrics_store
      用途：供 middleware 打点
   │
   ▼
⑦ Leader factory（不在本文件）
   │  用途：构造 Leader，注入工具与中间件
   │
   ├─ tools = builtin_tools + list(registry.specialist_tools)
   │  用途：delegate_to_subagent 进入 Leader tools
   ├─ middlewares = builtin_mw + [registry.orchestration_middleware]
   │  用途：拦截器挂到 Leader 执行链
   └─ create_poirot_agent(tools=tools, middlewares=middlewares)
      用途：把 tools 转成 schema，交给 LLM
       │
       ▼
   LLM 看到 delegate_to_subagent
```

**注册点总结：**

| 组件 | 注册到哪 | 哪一步 | 用途 |
|---|---|---|---|
| `SubagentSpecialist` | `SpecialistRegistry._specialists["subagent"]` | ③ | 供 Leader 按能力查询 / 按名字取用 |
| `SubagentRuntime` | 无 | — | 被 Specialist 持有，运行时转发执行 |
| `SelfCopyContextSummarizer` | 无（闭包捕获） | ④ | 运行时压上下文 |
| `SelfCopyResultSummarizer` | 无（闭包捕获） | ④ | 运行时压结果 |
| `delegate_to_subagent` tool | 无（进 `tools` list） | ④→⑤→⑥→⑦ | 让 LLM 能发起派活 |

### 0.3. 运行期调用树

```
① Leader LLM 决定派活
   │  用途：LLM 看到 delegate_to_subagent 的 schema，决定调用它
   │
   └─ tool_call("delegate_to_subagent", {goal, success_criteria})
       │
       ▼
② ToolNode → OrchestrationMiddleware.wrap_tool_call(request, handler)
   │  用途：拦截 tool 调用，在前后打点 + 汇总产物
   │
   ├─ _is_delegate_tool("delegate_to_subagent") → True
   │  用途：只拦 delegate_to_*，其余透传
   ├─ _extract_specialist_name → "subagent"
   │  用途：剥出 specialist 名，供打点用
   │
   ├─ _before_handler
   │   ├─ set_current_state(request.state)
   │   │  用途：把 ThreadState 写进 ContextVar，供 tool handler 读取
   │   ├─ metrics.record_selection("subagent")
   │   │  用途：L1 打点——被选中 +1
   │   └─ metrics.record_invoked("subagent")
   │      用途：L1 打点——被调用 +1
   │
   └─ try: result = handler(request)
       │  用途：放行，进入真正的 tool handler
       │
       ▼
③ delegate_to_subagent handler（tools.py 闭包）
   │  用途：派活编排——摘要 → 执行 → 摘要 → JSON
   │
   ├─ state = get_current_state()
   │  用途：从 ContextVar 读 ThreadState
   ├─ resolved_sandbox_id = _extract_sandbox_id(...)
   │  用途：解析沙箱 ID（显式参数优先，否则从 state 取）
   │
   ├─ context_summary = ctx_summarizer.summarize(state, goal, criteria)
   │   │  用途：压父上下文成一段精简字符串，控制 token
   │   │
   │   └─ SelfCopyContextSummarizer.summarize
   │       ├─ _llm 为 None → _rule_summarize
   │       │   ├─ "Goal: ..." / "Success criteria: ..."   ← 任务定义
   │       │   ├─ user_input → "Original request: ..."    ← 原始请求
   │       │   ├─ observations[-5:] → "Finding: ..."      ← 最近 5 条观察
   │       │   └─ 截断到 3000 字符                        ← 控制 token 成本
   │       └─ 返回 context_summary 字符串
   │
   ├─ request = SpecialistRequest(
   │       goal, success_criteria, context_summary,
   │       sandbox_id=resolved_sandbox_id, ...
   │   )
   │  用途：组装派活请求
   │
   ├─ raw = specialist.invoke(request)
   │   │  用途：调 specialist（走 SpecialistAgent 契约）
   │   │
   │   └─ SubagentSpecialist.invoke(request)
   │       │  用途：适配层，只做转发
   │       │
   │       └─ SubagentRuntime.invoke(request)
   │           │  用途：实际执行——进程内跑 leaf-role 子 Agent
   │           │
   │           ├─ _get_agent() → agent_factory()
   │           │  用途：造一个 leaf-role 子 Agent（不含 multiagent 工具，防递归）
   │           ├─ _create_isolated_state(request)
   │           │  用途：建全新 ThreadState，隔离父上下文
   │           │   ├─ create_initial_thread_state(goal)   ← 空 state
   │           │   ├─ state["metadata"]["context_summary"] = ...  ← 只传摘要
   │           │   └─ state["sandbox"] = {"sandbox_id": ...}      ← 复用父沙箱
   │           ├─ agent.invoke(state, recursion_limit=max_steps*2)
   │           │  用途：真正跑子 Agent
   │           │   ├─ RecursionError → SubagentMaxStepsError  ← 超步数
   │           │   └─ 其他异常 → SpecialistCrashError         ← 崩溃
   │           ├─ _extract_output(result)
   │           │  用途：抽最后一条消息的 content 作为 raw_output
   │           └─ return SpecialistRawResult(raw_output, duration)
   │
   ├─ result = result_summarizer.summarize(raw.raw_output, raw.artifacts, goal, criteria)
   │   │  用途：压结果 + 程序化评估（校验成功标准）
   │   │
   │   └─ SelfCopyResultSummarizer.summarize（继承自 BaseResultSummarizer）
   │       ├─ 校验 success_criteria    ← 判断是否达成
   │       ├─ 压缩 raw_output → summary ← 控制返回给 Leader 的 token
   │       ├─ success=False → 填 gap_analysis  ← 失败时说明差距
   │       └─ return SpecialistResult(specialist_name="subagent")
   │
   └─ return json.dumps({success, summary, specialist, gap_analysis, artifacts})
       │  用途：转成 JSON 字符串，作为 ToolMessage 内容
       │
       ▼
④ 回到 OrchestrationMiddleware.wrap_tool_call
   │  用途：tool 执行完，做后置处理
   │
   ├─ _after_handler("subagent", result)
   │   ├─ _is_success(result) → record_completion 或 record_fallback
   │   │  用途：L1 打点——成功 +1 / 回退 +1
   │   └─ _build_orchestration_update → ArtifactRef 列表
   │      用途：把 specialist 产物归一化为 ArtifactRef
   │
   └─ return Command(update={
          "messages": [result],
          "orchestration": {
              "active_specialists": ["subagent"],
              "specialist_artifacts": [...],
          },
      })
      用途：把 ToolMessage + orchestration 写回 ThreadState
       │
       ▼
⑤ ThreadState 更新
   ├─ messages 追加 ToolMessage          ← LLM 下一轮能看到
   └─ orchestration 更新                 ← 记录本次派活的 specialist + 产物
       │
       ▼
⑥ Leader LLM 看到 ToolMessage → 继续推理
   用途：LLM 根据 specialist 返回的 JSON 决定下一步（继续派活 / 自己干 / 收尾）
```

### 0.4. 补充

**self-copy subagent 是 multiagent 里"最简一条路径"——零外部依赖（无凭证、无外部进程），但组件分层与其他 specialist 完全一致。**

几点补充：

- **注册点只有一个**：`setup_multiagent` 里的 `specialist_registry.register(specialist)`。**其他所有组件都不进 registry**，各自被持有或闭包捕获。
- **三种"持有"方式并存**：
  - `SubagentRuntime` 被 `SubagentSpecialist._runtime` **持有**（对象属性）
  - 两个 Summarizer 被 `make_specialist_tool` **闭包捕获**（函数闭包）
  - `agent_factory` 被 `SubagentRuntime._agent_factory` **持有**（对象属性）
- **两条进入路径互斥**：若 `"subagent"` 在 `specialists_use` 里，走 `_load_specialist` 分支；若不在，走 `setup_multiagent` 兜底分支。**不会同时生效。**
- **`agent_factory` 是全链路唯一外部依赖**：`SubagentRuntime` 靠它造 leaf-role agent。它是 self-copy 复用 Leader 代码的关键接口。
- **异常层次在 runtime 处交叉**：`SubagentRuntime.invoke` 抛 `SpecialistCrashError` / `SpecialistStartupError`（SpecialistError 层次），只有 `SubagentMaxStepsError` 走 `SubagentError`。**这是两套异常层次唯一交汇的地方。**
