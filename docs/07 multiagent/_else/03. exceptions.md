---

name: Multi-Agent 异常层次 — SpecialistError + SubagentError 两条独立层次。

description: 

【整体职责】
定义 multiagent 层可能抛出的全部异常，按两条独立层次组织：
- SpecialistError 层次：外部异构 specialist（claude / codex / pi）失败时抛。
- SubagentError 层次：Poirot 内部自复制 subagent 失败时抛。
供 runtime / registry / middleware / summarizer 抛出与捕获，保证失败语义统一。

【内容摘要】
- SpecialistError            : specialist 异常基类，带 details dict，__str__ 自动展开。
- SpecialistTimeoutError     : specialist 超时。
- SpecialistCrashError       : specialist 子进程异常退出（含 exit_code）。
- SpecialistStartupError     : specialist 启动失败（握手 / spawn 失败）。
- SpecialistCredentialError  : specialist 凭证缺失或失效。
- SpecialistNotFoundError    : specialist 未注册（Registry 查不到）。
- SubagentError              : subagent 异常基类（独立层次）。
- SubagentTimeoutError       : subagent 超时。
- SubagentMaxStepsError      : subagent 超过 max_steps 限制（含 max_steps）。

【职责边界】
- 只负责：定义异常类型、details 语义、__str__ 展开格式。
- 不负责：异常的抛出时机（runtime / registry 负责）、异常到 ToolMessage 的转换
  （OrchestrationMiddleware 负责）、异常重试策略。
- 不持有状态：异常对象只在抛出瞬间携带 details。

## 0. 结构树

### 0.1. 静态结构树

```
exceptions.py — Multi-Agent 异常层次（两条独立层次）
│
├─ SpecialistError(Exception)                 ← specialist 异常基类
│   │                                            带 details dict，__str__ 自动展开
│   │                                            展开格式：message (k='v', k2='v2')
│   ├─ message: str                           ← 错误消息
│   ├─ details: dict                          ← 附加详情（默认空 dict）
│   └─ __str__() -> str                       ← 有 details 时展开，否则只返回 message
│   │
│   ├─ SpecialistTimeoutError                 ← specialist 超时（timeout_seconds 触发 kill）
│   │   └─ details: {timeout_seconds}         ← 仅传入时写入
│   │
│   ├─ SpecialistCrashError                   ← specialist 子进程异常退出
│   │   └─ details: {exit_code}               ← 仅传入时写入
│   │
│   ├─ SpecialistStartupError                 ← specialist 启动失败（握手 / spawn 失败）
│   │
│   ├─ SpecialistCredentialError              ← specialist 凭证缺失或失效
│   │                                            （该 specialist 标 disabled，不进 LLM 主态）
│   │
│   └─ SpecialistNotFoundError                ← specialist 未注册（Registry.get 缺失抛此）
│       └─ details: {name}                    ← 固定携带未注册的 name
│
└─ SubagentError(Exception)                   ← subagent 异常基类（独立层次，不继承 SpecialistError）
    │                                            subagent 是 Poirot 内部 self-copy，非黑盒 specialist
    ├─ message: str                           ← 错误消息
    ├─ details: dict                          ← 附加详情（默认空 dict）
    ├─ __str__() -> str                       ← 同 SpecialistError 展开格式
    │
    ├─ SubagentTimeoutError                   ← subagent 超时（timeout_seconds 触发中断）
    │
    └─ SubagentMaxStepsError                  ← subagent 超过 max_steps 限制
        └─ details: {max_steps}               ← 仅传入时写入（leaf role 递归控制）
```

### 0.2. 运行时调用树

```
① specialist 执行期 —— 抛 SpecialistError 子类
SpecialistRuntime.execute()
    ├─ 超时           → raise SpecialistTimeoutError(timeout_seconds=...)
    ├─ 子进程崩溃      → raise SpecialistCrashError(exit_code=...)
    ├─ 启动/握手失败   → raise SpecialistStartupError(...)
    └─ 凭证缺失/失效   → raise SpecialistCredentialError(...)

② registry 查询期 —— 抛 SpecialistNotFoundError
SpecialistRegistry.get(name)
    └─ 未注册         → raise SpecialistNotFoundError(name)

③ subagent 执行期 —— 抛 SubagentError 子类
SubagentRuntime.execute()
    ├─ 超时           → raise SubagentTimeoutError(...)
    └─ 超过步数上限    → raise SubagentMaxStepsError(max_steps=...)

④ 异常收敛 —— middleware 转 ToolMessage
OrchestrationMiddleware
    ├─ catch SpecialistError    ← 转 error ToolMessage 回 Leader
    └─ catch SubagentError      ← 转 error ToolMessage 回 Leader
```

### 0.3. 补充

**`exceptions.py` 是 multiagent 层的"失败语义总表"——两条独立层次（SpecialistError / SubagentError）把所有失败情形收拢，供 middleware 统一转 ToolMessage。**

几点补充：

- **两条层次必须独立**：`SubagentError` 不继承 `SpecialistError`。因为 subagent 是 Poirot 内部 self-copy，不是黑盒 specialist；如果共用基类，middleware 就无法区分"外部 specialist 失败"和"内部 subagent 失败"。
- **details 用"有则记"模式**：`timeout_seconds` / `exit_code` / `max_steps` 仅在显式传入时才写入 details，避免 `None` 值污染输出。
- **`__str__` 展开格式全层统一**：`message (k='v', k2='v2')`，无 details 时只返回 message；两条层次的展开逻辑是重复代码，但保持对称。
