---

name: Multi-Agent 核心数据结构 — frozen dataclass。

description: 

【整体职责】
定义 multiagent 层在 Leader 与 specialist / subagent 之间传递的全部数据结构：
请求（Request）、原始结果（RawResult）、最终结果（Result）、能力声明、产物引用、token 用量。
供 registry / specialist / runtime / summarizer / middleware 共同引用，保证跨 specialist 语义一致。

【内容摘要】
- SpecialistCapability    : 能力枚举（coding / research / review / planning）。
- SpecialistCapabilities  : specialist 的能力声明，支持 has() 查询。
- TokenUsage              : token 用量（specialist 自报，可选）。
- ArtifactRef             : specialist 产物的轻量引用（不含全局 artifact_id）。
- SpecialistRequest       : 派活给 specialist 的请求结构。
- SpecialistRawResult     : specialist runtime 返回的原始输出，交给 ResultSummarizer 消费。
- SpecialistResult        : ResultSummarizer 压缩后回传 Leader 的结果结构。
- SubagentRequest         : 派活给自复制 subagent 的请求结构（与 SpecialistRequest 同构）。
- SubagentResult          : 自复制 subagent 返回的结果结构（与 SpecialistResult 同构）。

【职责边界】
- 只负责：定义数据结构、字段语义、枚举。
- 不负责：上下文摘要逻辑（ContextSummarizer）、结果摘要逻辑（ResultSummarizer）、
  specialist 执行（runtime）、能力注册与过滤（registry）。
- 不持有状态：全部为 frozen dataclass，构造后不可变。

## 0. 结构树

### 0.1. 静态结构树

```
types.py — Multi-Agent 核心数据契约（frozen dataclass）
│
├─ SpecialistCapability(str, Enum)            ← Specialist 能力枚举；作用：list_specialists 按能力过滤
│   ├─ CODING = "coding"                      ← 编码能力
│   ├─ RESEARCH = "research"                  ← 研究能力
│   ├─ REVIEW = "review"                      ← 评审能力
│   └─ PLANNING = "planning"                  ← 规划能力
│
├─ SpecialistCapabilities(frozen)             ← Specialist 能力声明；register 时填，list 时过滤
│   ├─ capabilities: tuple[SpecialistCapability, ...] = () ← 能力集合
│   └─ has(capability) -> bool                ← 判断是否具备某能力
│
├─ TokenUsage(frozen)                         ← specialist 调用 token 用量；specialist 自报，可选
│   ├─ prompt_tokens: int = 0                 ← 输入 token
│   ├─ completion_tokens: int = 0             ← 输出 token
│   └─ total_tokens: int = 0                  ← 总 token
│
├─ ArtifactRef(frozen)                        ← specialist 产物轻量引用
│   │                                            写入 orchestration.specialist_artifacts；
│   │                                            不带全局 artifact_id（specialist 黑盒）
│   ├─ path: str                              ← 产物路径
│   ├─ artifact_type: str                     ← 产物类型
│   ├─ specialist_name: str                   ← 产出该产物的 specialist
│   ├─ description: str = ""                  ← 描述
│   └─ created_at: str | None = None          ← 创建时间
│
├─ SpecialistRequest(frozen)                  ← 派活给 specialist 的请求
│   │                                            tool handler 内部构造；LLM 只填 goal +
│   │                                            success_criteria（+ 可选 sandbox_id）
│   ├─ goal: str                              ← 任务目标
│   ├─ success_criteria: str                  ← 成功标准（必填）
│   ├─ context_summary: str                   ← 上下文摘要（ContextSummarizer 生成）
│   ├─ sandbox_id: str | None                 ← 沙箱 ID（可选）
│   ├─ artifacts_path: str | None             ← 产物路径
│   ├─ max_steps: int = 50                    ← 最大步数
│   ├─ timeout_seconds: int = 600             ← 超时（秒）
│   ├─ allowed_tools: tuple[str, ...] = ()    ← 允许使用的工具
│   └─ skill_injection: str | None = None     ← 技能注入内容
│
├─ SpecialistRawResult(frozen)                ← specialist runtime 返回的原始输出
│   │                                            由 ResultSummarizer 消费
│   ├─ raw_output: str                        ← 原始输出文本
│   ├─ artifacts: tuple[ArtifactRef, ...] = () ← 产物引用
│   ├─ usage: TokenUsage | None = None        ← token 用量（可选）
│   ├─ duration_seconds: float = 0.0          ← 执行耗时
│   └─ exit_code: int = 0                     ← 退出码
│
├─ SpecialistResult(frozen)                   ← specialist 调用结果；ResultSummarizer 生成，回传 Leader
│   ├─ specialist_name: str                   ← specialist 名称
│   ├─ summary: str                           ← 结果摘要
│   ├─ artifacts: tuple[ArtifactRef, ...] = () ← 产物引用
│   ├─ success: bool = False                  ← 是否成功
│   ├─ gap_analysis: str = ""                 ← 差距分析（success=False 时必填）
│   ├─ usage: TokenUsage | None = None        ← token 用量
│   ├─ duration_seconds: float = 0.0          ← 执行耗时
│   ├─ error: str | None = None               ← 错误信息（仅失败时填）
│   └─ failure_category: str | None = None    ← 失败分类（L2 FailureFocuser 读取）
│
├─ SubagentRequest(frozen)                    ← 派活给自复制 subagent 的请求
│   │                                            与 SpecialistRequest 同构，复用 lead factory
│   ├─ goal: str                              ← 任务目标
│   ├─ success_criteria: str                  ← 成功标准
│   ├─ context_summary: str                   ← 上下文摘要
│   ├─ sandbox_id: str | None                 ← 沙箱 ID
│   ├─ artifacts_path: str | None             ← 产物路径
│   ├─ max_steps: int = 20                    ← 最大步数（比 specialist 小）
│   ├─ timeout_seconds: int = 300             ← 超时（比 specialist 短）
│   ├─ allowed_tools: tuple[str, ...] = ()    ← 允许使用的工具
│   └─ skill_injection: str | None = None     ← 技能注入内容
│
└─ SubagentResult(frozen)                     ← 自复制 subagent 返回结果；与 SpecialistResult 同构
    ├─ summary: str                           ← 结果摘要
    ├─ artifacts: tuple[ArtifactRef, ...] = () ← 产物引用
    ├─ success: bool = False                  ← 是否成功
    ├─ gap_analysis: str = ""                 ← 差距分析
    ├─ usage: TokenUsage | None = None        ← token 用量
    ├─ duration_seconds: float = 0.0          ← 执行耗时
    └─ error: str | None = None               ← 错误信息
```

### 0.2. 运行时调用树

```
① 派活（Leader → specialist）
Leader 决策派活
    └─ tool handler 构造 SpecialistRequest
          ├─ goal / success_criteria      ← LLM 填
          ├─ sandbox_id                   ← 可选，从 state 取
          ├─ context_summary              ← ContextSummarizer 生成
          └─ max_steps / timeout / ...    ← 从 config 取
        ═══════════ runtime 执行 ═══════════

② runtime 返回原始输出
SpecialistRuntime.execute(request)
    └─ return SpecialistRawResult(raw_output, artifacts, usage, ...)

③ 结果压缩（RawResult → Result）
ResultSummarizer.summarize(raw_result)
    ├─ 校验 success_criteria              ← 未达成则 success=False
    ├─ success=False → 必填 gap_analysis
    └─ return SpecialistResult(...)
    → 回传 Leader，写入 orchestration.specialist_artifacts

④ 自复制路径（结构与上面同构）
SubagentRequest → SubagentRuntime → SubagentResult → 回传 Leader

⑤ L2 消费
FailureFocuser 读取 SpecialistResult.failure_category   ← 失败归类，驱动进化
```

### 0.3. 补充

**`types.py` 是 multiagent 层的"数据契约总表"——所有跨组件的请求/结果/能力/产物/token 结构都在这里定义，全部 frozen，保证跨线程安全。**

几点补充：

- **纯数据、无行为**：本文件只有 enum + frozen dataclass + 一个 `has()` 查询，无业务逻辑。
- **`frozen=True` 是并发前提**：这些结构在 Leader、runtime、summarizer、middleware 之间传递，不可变才能安全共享。
- **黑盒边界**：`SpecialistRequest` 只带 goal / success_criteria / context_summary，不带 specialist 内部细节；`ArtifactRef` 不带全局 artifact_id，都是"黑盒"约束在类型上的体现。
- **两对同构结构**：`SpecialistRequest` / `SubagentRequest`、`SpecialistResult` / `SubagentResult` 同构，便于 middleware 统一处理两条路径。
- **可选字段用 None 表达**：`TokenUsage` 可能不上报、`sandbox_id` 可能不绑、`error` 仅失败时填，统一用 `None` 表示"无"，不做哨兵值。
