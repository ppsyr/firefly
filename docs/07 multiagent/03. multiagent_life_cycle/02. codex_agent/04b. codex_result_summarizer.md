---

name: CodexResultSummarizer — Codex 输出端转换器（测试通过率 + diff 合法性）。

description: 

【整体职责】
在 BaseResultSummarizer 通用校验之上，为 Codex specialist 追加两项编码场景
专属校验：若输出报告了测试结果，"0 passed" 视为失败；并在 gap_analysis 中
补充测试失败数或 diff 标记缺失说明。

【内容摘要】
- _TEST_RESULT_RE / _TEST_FAIL_RE / _DIFF_MARKER_RE : 测试通过 / 失败 / diff 标记正则。
- CodexResultSummarizer      : 输出端转换器主类。
- _evaluate_success()        : 覆写基类成功判定，追加"0 passed → 失败"规则。
- _parse_test_pass_rate()    : 从输出解析通过测试数（无则 None）。
- _extract_gap()             : 覆写基类 gap 提取，追加测试失败 / diff 缺失说明。

【职责边界】
- 只负责：在基类校验之上追加 Codex 专属的成功判定与 gap 补充。
- 不负责：通用校验逻辑（基类负责）、结果压缩（基类负责）、specialist 执行。
- 不持有运行时状态：纯函数式判定。

## 0. 结构树 — CodexResultSummarizer（含 Base 视角）

### 0.1. 静态结构树

```
base.py — BaseResultSummarizer（通用 programmatic eval floor）
│
├─ 常量
│   ├─ _MAX_SUMMARY_CHARS: int = 2000         ← 压缩上限，超出截断
│   └─ _SENSITIVE_PATTERNS: list[str]         ← 敏感改动正则（5 条）
│       ├─ rm -rf /
│       ├─ mkfs.
│       ├─ dd of=/dev/
│       ├─ > /etc/passwd
│       └─ chmod 777 /
│
└─ BaseResultSummarizer                      ← 通用骨架主类
    │                                           对外唯一入口 summarize()
    │                                           其余 _ 开头方法为钩子，子类可覆写
    │
    ├─ _specialist_name: str = "base"        ← 写进产出的 SpecialistResult
    │
    ├─ __init__(specialist_name="base")      ← 子类传入自己的名字
    │
    ├─ summarize(raw_output, artifacts, goal, success_criteria) -> SpecialistResult
    │   │                                        ← ★ 对外唯一入口（模板方法）
    │   ├─ ① success = self._evaluate_success(...)
    │   │     └─ 钩子：子类可覆写（ClaudeCode 覆写了它）
    │   ├─ ② gap_analysis = "" if success else self._extract_gap(...)
    │   │     └─ 钩子：子类可覆写（ClaudeCode 覆写了它）
    │   ├─ ③ summary = self._compress(raw_output)
    │   │     └─ 钩子：子类可覆写
    │   ├─ ④ failure_category = self._classify_failure(success, raw_output)
    │   │     └─ 钩子：子类可覆写
    │   └─ ⑤ return SpecialistResult(...)
    │
    ├─ _classify_failure(success, raw_output) -> str | None
    │   │                                        ← 钩子：启发式失败分类
    │   ├─ success=True → None
    │   ├─ "context"          → "context_insufficient"
    │   ├─ "skill" / "ability"→ "ability_insufficient"
    │   ├─ "goal" / "unclear" → "goal_unclear"
    │   ├─ "sandbox" / "timeout" → "sandbox_issue"
    │   └─ 默认               → "ability_insufficient"
    │
    ├─ _evaluate_success(raw_output, artifacts, success_criteria) -> bool
    │   │                                        ← 钩子：通用成功判定
    │   ├─ raw_output 空白 → False
    │   ├─ 有敏感改动 → False
    │   ├─ artifacts 为空（非 None） → False
    │   └─ 否则 → True
    │
    ├─ _has_sensitive_changes(raw_output) -> bool
    │   │                                        ← 钩子：检测敏感改动
    │   └─ 遍历 _SENSITIVE_PATTERNS 正则匹配
    │
    ├─ _compress(raw_output) -> str           ← 钩子：压缩 raw_output
    │   ├─ len <= 2000 → 原样
    │   └─ len > 2000 → 截断 + "...(truncated)"
    │
    └─ _extract_gap(raw_output, success_criteria) -> str
        │                                        ← 钩子：提取失败原因
        └─ "Criteria not met: <criteria>. Output tail: <最后 5 行，最多 200 字符>"

   继承链：
    BaseResultSummarizer（通用校验 + 压缩 + gap + 分类）
        └─ CodexResultSummarizer（本文件，覆写 2 个方法）
            ├─ _evaluate_success（覆写）
            └─ _extract_gap（覆写）
            
	   子类扩展点（本文件外）：
	    ├─ SelfCopyResultSummarizer               ← 纯继承，零覆写
	    └─ ClaudeCodeResultSummarizer             ← 覆写 2 个钩子
	        ├─ _evaluate_success（覆写）
	        │   ├─ 先 super() 通用校验
	        │   └─ 再 _has_suggestions 追加 review 专属判定
	        └─ _extract_gap（覆写）
	            ├─ 先 super() 拿 base_gap
	            └─ 再按 suggestion / issue 缺失情况追加说明```

### 0.2. 模板方法调用链（codex 视角）

```
外部调用（delegate_to_codex tool handler）
    │
    ▼
summarizer.summarize(raw_output, artifacts, goal, success_criteria)
    │
    │  ← summarizer 是 CodexResultSummarizer
    │    它没覆写 summarize，调的是「继承来的」基类版本
    │
    ▼
BaseResultSummarizer.summarize（模板方法，流程固定）
    │
    ├─ ① self._evaluate_success(raw_output, artifacts, success_criteria)
    │   │
    │   │  ┌── Codex 覆写版 ──┐
    │   │  │ ① super()._evaluate_success(...)     ← 通用校验（空白/敏感/artifacts）
    │   │  │ ② _parse_test_pass_rate(raw_output)  ← 解析测试通过数
    │   │  │ ③ passed is not None 且 passed == 0 → False
    │   │  │ ④ 其余 → True
    │   │  └───────────────────┘
    │   │
    │   └─ success = 上述结果
    │
    ├─ ② success=False → self._extract_gap(raw_output, success_criteria)
    │   │
    │   │  ┌── Codex 覆写版 ──┐
    │   │  │ base_gap = super()._extract_gap(...)   ← 基类格式
    │   │  │ + 有 "N failed" → 附 "Tests failed: N"
    │   │  │ + 无 diff 标记 → 附 "No diff markers found in output."
    │   │  └───────────────────┘
    │   │
    │   └─ success=True → gap_analysis = ""
    │
    ├─ ③ self._compress(raw_output)
    │   └─ 基类版：超 2000 字符截断（Codex 未覆写）
    │
    ├─ ④ self._classify_failure(success, raw_output)
    │   └─ 基类版：启发式分类（Codex 未覆写）
    │
    └─ ⑤ return SpecialistResult(
           specialist_name="codex",
           summary, artifacts, success, gap_analysis, failure_category
       )
```

| `_extract_gap` | 基类版 | 继承 | **覆写**（+ 缺失说明） | **覆写**（+ 测试/diff 说明） |
| `_compress` | 基类版 | 继承 | 继承 | 继承 |

| `_has_sensitive_changes` | 基类版 | 继承 | 继承 | 继承 |

### 0.3. 补充

**`codex_result_summarizer.py` 是 Codex specialist 的"输出端闸门"——在基类通用校验之上，追加"编码场景专属"的测试通过率判定与 gap 说明。**

几点补充：

- **只覆写两个方法**：`_evaluate_success` 和 `_extract_gap`。其余全部继承自 `BaseResultSummarizer`。**这是"扩展"而非"重写"。**
- **成功判定是"条件性叠加"**：`if passed is not None and passed == 0: return False`——**只有在输出里确实解析出了测试结果时才触发**。如果解析不出（比如任务不是跑测试），就跳过这条规则，只依赖基类通用校验。
  - **对比 ClaudeCode**：Claude 是"无条件追加 suggestion 检查"——不管什么输出都要求有 suggestion。
  - **Codex 更保守**：不把"没提到测试"当成失败，避免误判非测试类任务。
- **两个正则用途不同，这是关键**：
  - `_TEST_RESULT_RE`（`<n> passed`）→ **参与成功判定**。0 passed 视为失败。
  - `_TEST_FAIL_RE`（`<n> failed`）→ **不参与成功判定**，只在 gap 里报告失败数。
  - `_DIFF_MARKER_RE`（`@@` / `---` / `+++`）→ **不参与成功判定**，只在 gap 里说明"没有 diff"。
- **为什么"0 passed"算失败，但"N failed"不算**：因为 `passed=0` 是"测试完全没通过"的强信号；而"N failed"的信息（N 是多少、总共有多少测试）不足以单独判定成败——**它只作为 gap 说明，让 Leader 知道失败规模**。
- **gap 是"追加"而非"替换"**：`base_gap = super()._extract_gap(...)`——基类的 gap 保留，只在后面拼上测试/diff 说明。**信息不丢。**
- **依赖基类 `BaseResultSummarizer`**：本文件是"薄扩展"，真正要理解输出端行为，得看 `summarizers/result/base.py`。
- **三个 summarizer 的定位对照**：

| Summarizer | 成功判定叠加 | 场景定位 |
|---|---|---|
| `SelfCopyResultSummarizer` | 无（纯基类） | 自复制——按 Leader 自己的标准衡量 |
| `ClaudeCodeResultSummarizer` | 必须有 suggestion | 代码审查——关注"问题/建议" |
| `CodexResultSummarizer` | 不能 0 passed | 编码实现——关注"测试通过 + diff 存在" |

**这就是 per-specialist result summarizer 的核心价值**：同一套骨架，不同 specialist 按自己的场景定制"什么叫成功"。
