---

name: CodexContextSummarizer — 规则提取（代码片段 + 文件路径，零 LLM）。

description: 

【整体职责】
为 Codex specialist 生成 context_summary：从父 ThreadState 中提取代码块和文件路径，
拼成一段精简上下文。零 LLM，纯规则提取，控制 token 成本。

【内容摘要】
- _CODE_BLOCK_RE / _MAX_CODE_BLOCKS / _MAX_PATHS / _MAX_SUMMARY_CHARS : 规则常量。
- _field()                      : 从 dict 或对象中统一取字段。
- CodexContextSummarizer        : 输入端转换器主类。
- summarize()                   : 入口，拼装 goal + 代码块 + 文件路径。
- _extract_code_blocks()        : 从 messages 中提取代码块（最多 3 个）。
- _extract_file_paths()         : 从 artifacts 中提取文件路径（最多 10 个）。

【职责边界】
- 只负责：从 ThreadState 规则提取代码块与文件路径，拼成 context_summary 字符串。
- 不负责：结果压缩（ResultSummarizer 负责）、specialist 执行、LLM 调用。
- 不持有运行时状态：纯函数式读取，不写回 state。

## 0. 结构树

### 0.1. 静态结构树

```
codex_context_summarizer.py — CodexContextSummarizer（规则提取：代码 + 文件路径）
│
├─ 常量
│   ├─ _CODE_BLOCK_RE                         ← 代码块正则：``` ... ```（含跨行）
│   ├─ _MAX_CODE_BLOCKS: int = 3              ← 最多提取的代码块数量
│   ├─ _MAX_PATHS: int = 10                   ← 最多提取的文件路径数量
│   └─ _MAX_SUMMARY_CHARS: int = 3000         ← 总摘要最大字符数，超出截断
│
├─ _field(item, name) -> Any                  ← 统一字段访问
│   ├─ dict → item.get(name)
│   └─ 对象 → getattr(item, name, None)
│
└─ CodexContextSummarizer                    ← 输入端转换器主类（零 LLM，纯规则）
    │
    ├─ summarize(state, goal, success_criteria, template=None) -> str
    │   │                                        ← 入口：拼装 context_summary
    │   ├─ ① 拼 "Goal: ..." / "Success criteria: ..."
    │   ├─ ② _extract_code_blocks(state)
    │   │     └─ 非空 → 拼 "Relevant code:" + 各代码块
    │   ├─ ③ _extract_file_paths(state)
    │   │     └─ 非空 → 拼 "Files: path1, path2, ..."
    │   ├─ ④ 总长 > 3000 → 截断 + "...(truncated)"
    │   └─ ⑤ 返回 summary
    │
    ├─ _extract_code_blocks(state) -> list[str] ← 从 messages 提取代码块
    │   ├─ 遍历 messages → _field(msg, "content")
    │   ├─ 非 str → 跳过
    │   ├─ _CODE_BLOCK_RE.findall(content)
    │   ├─ 找够 _MAX_CODE_BLOCKS=3 → break
    │   └─ 返回 blocks[:3]
    │
    └─ _extract_file_paths(state) -> list[str]  ← 从 artifacts 提取文件路径
        ├─ 遍历 state["artifacts"] → _field(artifact, "path")
        ├─ 空值 → 跳过
        ├─ 重复 → 跳过
        ├─ 找够 _MAX_PATHS=10 → break
        └─ 返回 paths[:10]
```

### 0.3. 补充

**`codex_context_summarizer.py` 是 Codex specialist 的"输入端闸门"——从父 ThreadState 里挑出"代码块 + 涉及的文件路径"，压成一段精准上下文，零 LLM。**

几点补充：

- **零 LLM，纯规则**：与 `ClaudeCodeContextSummarizer` 一样，没有任何 LLM 路径。**完全靠正则和列表遍历**，速度快、成本零、行为确定。
- **提取两个维度**：代码块（从 messages）+ 文件路径（从 artifacts）。**这正是 Codex"编码实现"场景最需要的信息**——看代码、知道涉及哪些文件。
- **两个提取源不同**：
  - `_extract_code_blocks` 扫 `state["messages"]`（对话历史里的代码）
  - `_extract_file_paths` 扫 `state["artifacts"]`（已产出的文件清单）
- **上限数量不同**：代码块 3 个、路径 10 个。路径上限更宽松——因为**路径短、信息密度低**，多给几条对 token 压力小；代码块长，给多了会撑爆上下文。
- **`template` 参数全程未用**：与所有其他 context summarizer 一样，是 L2 扩展预留位。
- **和 ClaudeCodeContextSummarizer 对比**：
  - 两者都提代码块（Claude 上限 2、Codex 上限 3）
  - 第二个维度不同：Claude 提 **review 关键词**（从 messages 扫），Codex 提 **文件路径**（从 artifacts 扫）
  - **同一份 ThreadState，不同 specialist 提取不同视角**——这就是 per-specialist summarizer 的核心价值。
