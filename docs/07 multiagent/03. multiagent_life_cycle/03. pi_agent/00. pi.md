# 1. Pi 专家系统流程

## 1.1. 5 个核心组件的角色

| 文件 | 角色 | 一句话职责 |
|---|---|---|
| `installer/pi_installer.py` | 安装器 | 检测 Pi CLI 是否已装；未装时后台 npm install（daemon 线程，不阻塞主流程） |
| `credentials/pi_credential.py` | 凭证提供者 | 双轨解析凭证（config 优先 + env 兜底 + auth.json 文件），前置条件是 pi CLI 在 PATH |
| `runtimes/pi_runtime.py` | 执行器 | 启动 `pi --mode rpc` 子进程，stdio JSON-RPC 收发；强制走 Poirot MCP |
| `specialists/pi_specialist.py` | 适配器 | 把 runtime 包装成 `SpecialistAgent` 契约（name="pi" / capability=CODING / invoke） |
| `summarizers/context/pi_context_summarizer.py` | 输入端闸门 | 从父 ThreadState 规则提取"代码块 + 文件路径"，零 LLM |
| `summarizers/result/pi_result_summarizer.py` | 输出端闸门 | 解析 pi 输出的三段格式（What You Did / Success / Gaps），覆写 `summarize` |

**额外组件（跨语言桥）**：

| 文件 | 角色 | 一句话职责 |
|---|---|---|
| `extensions/pi-sandbox-bridge/index.ts` | Pi extension（TS） | 注册 8 个 `poirot_*` 工具到 pi，通过 stdio MCP 转发到 Poirot SpecialistMcpServer |

**与 subagent 的对照**：

| | subagent | pi |
|---|---|---|
| 执行器 | `SubagentRuntime`（进程内调 lead factory） | `PiRuntime`（外部 CLI + RPC 协议） |
| 输入端摘要 | `SelfCopyContextSummarizer`（LLM + 规则） | `PiContextSummarizer`（纯规则） |
| 输出端摘要 | `SelfCopyResultSummarizer`（纯继承） | `PiResultSummarizer`（**覆写 summarize，三段解析**） |
| capability | RESEARCH | CODING |
| 凭证 | 无（继承 Leader） | **`PiCredentialProvider`（双轨）** |
| 安装器 | 无 | **`PiInstaller`（后台 npm install）** |
| 跨语言桥 | 无 | **`pi-sandbox-bridge`（TS extension）** |
| 强制 MCP | 无 | **`--no-builtin-tools` + extension** |
| token 用量 | ❌ 无 | ✅ **从 agent_end 提取** |
| 沙箱隔离 | 无（Poirot 内部） | **逻辑约束（走 MCP，非物理隔离）** |

## 1.3. 完整流程（装配 → 运行）

### 装配期结构树

```
bootstrap.setup_multiagent(config, agent_factory)
│
└─ for name in config.specialists_use:
    │
    └─ name == "pi" 时：
        │
        ▼
    bootstrap._load_specialist("pi", config)
        │
        ├─ ① PiInstaller(auto_install=config.specialists_pi_auto_install)
        │   └─ installer.ensure_installed()
        │       │  用途：检测 pi CLI 是否可用
        │       ├─ _is_installed() → True → 继续
        │       ├─ auto_install=false → warning → return None
        │       ├─ npm 不可用 → warning → return None
        │       └─ 启动 daemon 线程后台 npm install → return False
        │           └─ bootstrap 收到 False → return None（本次不可用）
        │
        ├─ ② PiCredentialProvider(
        │       config_provider=config.specialists_pi_provider or None,
        │       config_api_key=config.specialists_pi_api_key or None,
        │   ).get_credential()
        │   │  用途：四级优先级解析凭证
        │   ├─ ⓪ pi CLI 不在 PATH → None
        │   ├─ ① config 显式 api_key → 返回
        │   ├─ ② config 显式 provider → 查 env → 命中返回
        │   ├─ ③ 遍历 provider env（国内优先）→ 命中返回
        │   ├─ ④ auth.json 文件存在 → 返回
        │   └─ ⑤ 都未命中 → None
        │       └─ cred is None → return None（specialist disabled）
        │           └─ bootstrap 打印 warning：安装 + 设 API key
        │
        └─ ③ 构造三元组：
            ├─ PiSpecialist(
            │       runtime=PiRuntime(PiRuntimeConfig(provider, model, thinking_level)),
            │       credential=cred,
            │   )                                   ← specialist
            ├─ PiContextSummarizer()                ← 输入端摘要器
            └─ PiResultSummarizer()                 ← 输出端摘要器
        │
        ▼
    registry.register(specialist)
        └─ ✅ 唯一注册点：
           registry._specialists["pi"] = PiSpecialist
        │
        ▼
    make_specialist_tool(
        "pi", specialist,
        ctx_summarizer,        ← 闭包捕获
        result_summarizer,     ← 闭包捕获
        max_steps, timeout_seconds
    )
        └─ 产出：delegate_to_pi (BaseTool)
        │
        ▼
    工具进 MultiAgentSetup.specialist_tools
        │
        ▼
    CapabilityRegistry.specialist_tools = setup.specialist_tools
        │
        ▼
    Leader factory: tools = builtin + registry.specialist_tools
        │
        ▼
    LLM 看到 delegate_to_pi
```

**装配后状态**：
- registry 里：`{"pi": PiSpecialist}`
- tool 闭包里：`PiSpecialist` + `PiContextSummarizer` + `PiResultSummarizer`
- `PiRuntime` 藏在 Specialist 里，`PiRuntimeConfig` / `credential` 藏在 Runtime / Specialist 里

### 运行期结构树

```
① LLM 决定派活
   └─ tool_call("delegate_to_pi", {goal, success_criteria})
       │
       ▼
② OrchestrationMiddleware.wrap_tool_call
   ├─ _is_delegate_tool("delegate_to_pi") → True
   ├─ _extract_specialist_name → "pi"
   ├─ set_current_state(state)              ← 写 ContextVar
   ├─ metrics.record_selection("pi")
   └─ metrics.record_invoked("pi")
       │
       ▼
③ delegate_to_pi handler（tools.py 闭包）
   │
   ├─ state = get_current_state()
   │
   ├─ context_summary = ctx_summarizer.summarize(state, goal, criteria)
   │   │  用途：输入端闸门
   │   │
   │   └─ PiContextSummarizer.summarize
   │       ├─ ① 拼 "Goal: ..." / "Success criteria: ..."
   │       ├─ ② _extract_code_blocks(state)
   │       │     ├─ 遍历 messages → finditer 匹配 ``` ... ```
   │       │     └─ 最多 3 个
   │       ├─ ③ _extract_file_paths(state)
   │       │     ├─ 先扫 observations → 正则匹配路径
   │       │     ├─ 再扫 messages → 正则匹配路径
   │       │     └─ 去重，最多 10 条
   │       ├─ ④ 超过 3000 字符 → 截断
   │       └─ 返回 context_summary 字符串
   │
   ├─ request = SpecialistRequest(goal, criteria, context_summary, sandbox_id, ...)
   │
   ├─ raw = specialist.invoke(request)
   │   │
   │   └─ PiSpecialist.invoke(request)
   │       │
   │       └─ PiRuntime.invoke(request)
   │           │  用途：执行器——启动 pi 子进程
   │           │
   │           ├─ ① _build_command(request)
   │           │     └─ [pi, --mode, rpc, --no-session, --provider, ...,
   │           │         --model, ..., --thinking, medium,
   │           │         --no-builtin-tools, -e <index.ts>]
   │           │
   │           ├─ ② _build_env(request)
   │           │     ├─ 读 13 个 provider env（国内优先）
   │           │     ├─ PI_CODING_AGENT_DIR
   │           │     ├─ POIROT_SANDBOX_MCP_ENDPOINT（sandbox_id 非 None）
   │           │     └─ {**os.environ, **auth_env}
   │           │
   │           ├─ ③ subprocess.Popen(cmd, stdin/stdout/stderr=PIPE, text=True, env=env)
   │           │     │
   │           │     │  ┌── 操作系统级：启动 pi 子进程 ──┐
   │           │     │  │ fork/exec → stdio 管道          │
   │           │     │  │ pi 内部：                      │
   │           │     │  │   ├─ 读 -e → jiti 加载 TS      │
   │           │     │  │   ├─ 调 default(pi)            │
   │           │     │  │   ├─ registerTool × 8          │
   │           │     │  │   └─ agent 运行                │
   │           │     │  └───────────────────────────────┘
   │           │     │
   │           │     ├─ ④ 写一行 JSON prompt 到 stdin：
   │           │     │     {"type": "prompt", "message": prompt, "id": "req-1"}
   │           │     │
   │           │     └─ ⑤ 逐行读 stdout：
   │           │         ├─ message_update(text_delta) → chunks
   │           │         ├─ agent_end → usage + break
   │           │         └─ extension_error → SpecialistCrashError
   │           │
   │           ├─ ⑥ finally：关闭子进程（stdin.close → terminate → wait(5s) → kill）
   │           │
   │           └─ ⑦ return SpecialistRawResult(raw_output, usage, duration)
   │
   │           ┌── pi agent 内部调用 poirot_* 工具时 ──┐
   │           │  pi agent → poirot_bash               │
   │           │    → extension.execute                 │
   │           │      → callPoirotMcp("bash", args)     │
   │           │        → spawn SpecialistMcpServer      │
   │           │          （Python 子进程）              │
   │           │            → PathTranslator + Guard     │
   │           │            → sandbox 执行               │
   │           │        → 返回文本                        │
   │           └────────────────────────────────────────┘
   │
   ├─ result = result_summarizer.summarize(raw.raw_output, raw.artifacts, goal, criteria)
   │   │  用途：输出端闸门
   │   │
   │   └─ PiResultSummarizer.summarize（覆写版）
   │       ├─ ① base_success = self._evaluate_success(...)   ← 基类通用校验
   │       ├─ ② sections = self._parse_pi_sections(raw_output)
   │       │     ├─ did     ← "## What You Did" 段
   │       │     ├─ success ← "## Success" 段
   │       │     └─ gaps    ← "## Gaps" 段
   │       ├─ ③ pi_success = self._evaluate_pi_success(sections, base_success)
   │       │     ├─ base_success 为 False → False
   │       │     ├─ 无 Success 段 → 退化为 base_success
   │       │     └─ Success 段含负面词 → False；否则 True
   │       ├─ ④ gap = sections["gaps"] or ("" if pi_success else _extract_gap(...))
   │       ├─ ⑤ summary = sections["did"] or _compress(raw_output)
   │       └─ return SpecialistResult(..., success=pi_success, gap_analysis=gap)
   │           └─ ⚠️ 未填 failure_category（覆写 summarize 时漏调）
   │
   └─ return json.dumps({success, summary, specialist, gap_analysis, artifacts})
       │
       ▼
④ OrchestrationMiddleware.wrap_tool_call（返回后）
   ├─ metrics.record_completion / record_fallback
   ├─ _build_orchestration_update → ArtifactRef 列表
   └─ return Command{update: {messages, orchestration}}
       │
       ▼
⑤ ThreadState 更新 → LLM 看到 ToolMessage → 继续推理
```

## 1.4. 每个文件在流程里的"出场点"

| 文件 | 装配期出场 | 运行期出场 | 具体动作 |
|---|---|---|---|
| `installer/pi_installer.py` | **① 被调** | ❌ 不再出场 | 检测 pi CLI；未装则后台 npm install |
| `credentials/pi_credential.py` | **② 被调** | ❌ 不再出场 | 双轨解析凭证，返回 PiCredential 或 None |
| `runtimes/pi_runtime.py` | ③ 被构造 | **运行期被 invoke** | 启动 pi 子进程，RPC 收发 |
| `specialists/pi_specialist.py` | ③ 被构造 + 进 registry | **运行期被 invoke** | 转发给 runtime |
| `summarizers/context/pi_context_summarizer.py` | ③ 被构造 + 闭包捕获 | 运行期被 summarize | 提取代码块 + 文件路径 |
| `summarizers/result/pi_result_summarizer.py` | ③ 被构造 + 闭包捕获 | 运行期被 summarize | 三段解析 + 成功判定 |
| `extensions/pi-sandbox-bridge/index.ts` | ❌ 不出场 | **pi 子进程启动时被 jiti 加载** | 注册 8 个 poirot_* 工具 |
| `mcp/specialist_mcp_server.py` | ❌ 不出场 | **pi agent 调工具时被 spawn** | 路径翻译 + 安全校验 + 沙箱执行 |

**与 subagent 的差异**：Pi 多了**安装器**（装配期）、**凭证提供者**（装配期）、**跨语言 extension**（运行期）、**MCP server**（运行期）——**四个环节都是外部异构 specialist 多出的复杂度。**

## 1.5. 最小可用的"数据流"

```
父 ThreadState
    │
    │ ① PiContextSummarizer 压（正则提取代码 + 文件路径）
    ▼
context_summary: str
    │
    │ ② 装进 SpecialistRequest
    ▼
SpecialistRequest
    │
    │ ③ PiRuntime._build_command + _build_env
    ▼
["pi", "--mode", "rpc", ..., "--no-builtin-tools", "-e", "<index.ts>"]
    + env（13 个凭证 + MCP endpoint）
    │
    │ ④ subprocess.Popen 启动 pi 子进程
    │    └─ pi 内部：jiti 加载 extension → registerTool × 8 → agent 运行
    ▼
pi 子进程
    │  ⑤ 写 prompt JSON 到 stdin
    │  ⑥ 逐行读 stdout（JSON 事件）
    ▼
message_update(text_delta) → chunks
agent_end → usage + break
    │
    │ ⑦ raw_output = "".join(chunks)
    │    usage = _extract_usage(...)
    ▼
SpecialistRawResult(raw_output, usage, duration)
    │
    │ ⑧ PiResultSummarizer.summarize
    │    ├─ 解析三段：did / success / gaps
    │    ├─ 成功判定：base + Success 段无负面词
    │    └─ 组装 SpecialistResult
    ▼
SpecialistResult(specialist_name="pi", success, summary, gap_analysis)
    │
    │ ⑨ json.dumps 转 ToolMessage
    ▼
回 Leader
```

**侧链路（pi agent 调工具时）**：

```
pi agent → poirot_bash
    → extension.execute
        → callPoirotMcp("bash", args)
            → spawn SpecialistMcpServer（Python 子进程）
                → PathTranslator + SecurityGuard
                → sandbox 执行
            → 返回文本
    → pi agent 继续推理
```

**与 subagent 数据流的关键差异**：

| 步骤 | subagent | pi |
|---|---|---|
| 执行方式 | **进程内调 agent.invoke** | **`subprocess.Popen(["pi", ...])`** |
| 执行载体 | 当前 Python 进程 | **Node.js 子进程** |
| 输出收集 | agent result 最后一条消息 | **逐行读 stdout 的 text_delta** |
| token 用量 | ❌ 无 | **✅ 从 agent_end 提取** |
| 工具调用 | 直接用 Poirot 内置工具 | **经 extension + MCP 桥接** |
| 成功判定 | 基类通用校验 | **基类 + 三段 Success 段判定** |

## 1.6. 总结

> **Pi 专家系统是 multiagent 的"外部异构接入路径"，且是三条外部路径里最复杂的一条——它涉及三层跨语言桥接：Python（PiRuntime）启动 Node.js（pi CLI）→ pi 加载 TS（extension）→ extension spawn Python（SpecialistMcpServer）。装配期有两道闸门（安装器 + 凭证提供者），运行期有强制 MCP 约束（`--no-builtin-tools` + `-e extension`）。输出端是唯一覆写 `summarize` 的 summarizer——因为 pi 按约定输出三段格式，摘要器要解析这三段。**

**与 subagent / ClaudeCode / Codex 的四方对比**：

| 维度 | subagent | ClaudeCode | Codex | Pi |
|---|---|---|---|---|
| 本质 | 进程内自复制 | 外部 CLI | 外部 ACP | **外部 CLI + RPC + TS extension** |
| 装配闸门 | 无 | 凭证探测 | 凭证探测 | **安装器 + 凭证提供者** |
| 输入摘要 | LLM + 规则 | 纯规则 | 纯规则 | 纯规则 |
| 输出摘要 | 纯继承 | 继承 + 2 覆写 | 继承 + 2 覆写 | **覆写 summarize（三段解析）** |
| 执行方式 | `agent.invoke` | `subprocess.run` | ACP 异步 | **`subprocess.Popen` + RPC** |
| token 用量 | ❌ | ❌ | ❌ | **✅** |
| 强制 MCP | ❌ | ❌ | ❌ | **✅** |
| 跨语言桥 | ❌ | ❌ | ❌ | **✅ TS extension** |
| 物理隔离 | 无 | 无 | 无 | **无（逻辑约束）** |

**核心**：Pi 的复杂度来源是"**三层跨语言桥接 + 两道装配闸门 + 强制 MCP 约束**"——这是外部异构 specialist 里最复杂的接入方式，但换来了"**token 用量上报 + 统一沙箱访问 + 多 provider 自动发现**"的能力。
