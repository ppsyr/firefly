---

name: PiCredentialProvider — 双轨凭证解析（config 优先 + env 兜底）。

description: 

【整体职责】
发现 Pi specialist 的凭证：先确认 pi CLI 可执行，再按四级优先级解析凭证
（config 显式 api_key > config 显式 provider 对应的 env > 遍历所有 provider env >
auth.json 文件），返回 PiCredential。凭证缺失时返回 None（不抛异常）。

【内容摘要】
- PiCredential               : 凭证数据类，含 provider / api_key / auth_file。
- PiCredentialProvider       : 凭证发现主类，实现 get_credential()。
- get_credential()           : 四级优先级解析凭证，返 PiCredential | None。
- _is_pi_installed()         : 检测 pi CLI 是否在 PATH。
- _resolve_auth_path()       : 解析 auth.json 路径（支持 PI_CODING_AGENT_DIR 覆盖）。
- _provider_env_map()        : provider → env var 映射（国内 provider 靠前）。

【职责边界】
- 只负责：检测 pi CLI、按优先级解析凭证、读取文件路径。
- 不负责：刷新凭证、存储凭证、管理凭证生命周期、写 ThreadState。
- 不持有运行时状态：每次 get_credential 重新解析。

## 0. 结构树

### 0.1. 静态结构树

```
pi_credential.py — PiCredentialProvider（双轨凭证解析：config 优先 + env 兜底）
│
├─ PiCredential(Credential, frozen)           ← Pi agent 凭证
│   │                                            只传给 specialist runtime，不写 ThreadState
│   │                                            kind 固定 "pi"
│   ├─ kind: str = "pi"                       ← 固定标识
│   ├─ provider: str | None = None            ← 用户偏好的 provider
│   ├─ api_key: str | None = None             ← 直接 API key（config/env 命中时填）
│   └─ auth_file: str | None = None           ← auth.json 路径（文件兜底时填）
│
└─ PiCredentialProvider                      ← 凭证发现主类
    │                                            双轨：config 优先 + env 兜底
    │                                            文件仅最后兜底
    │
    ├─ _config_provider: str | None          ← config 显式 provider
    ├─ _config_api_key: str | None           ← config 显式 api_key
    │
    ├─ __init__(config_provider, config_api_key)
    │
    ├─ get_credential() -> PiCredential | None
    │   │                                        ← 四级优先级解析
    │   ├─ ⓪ _is_pi_installed()?
    │   │     └─ pi 不在 PATH → return None（即使有 key）
    │   ├─ ① config 显式 api_key → 返回（provider 缺省 "anthropic"）
    │   ├─ ② config 显式 provider → 查 env var，命中则返回
    │   ├─ ③ 遍历 _provider_env_map（国内优先）→ 命中则返回
    │   ├─ ④ auth.json 存在 → 返回（仅带 auth_file）
    │   └─ ⑤ 都未命中 → None
    │
    ├─ _is_pi_installed() -> bool             ← pi CLI 是否在 PATH
    │   └─ shutil.which("pi") is not None
    │
    ├─ _resolve_auth_path() -> Path | None    ← 解析 auth.json 路径
    │   ├─ PI_CODING_AGENT_DIR 存在 → Path(env) / "auth.json"
    │   └─ 否则 → ~/.pi/agent/auth.json
    │
    └─ _provider_env_map() -> dict[str, str]  ← provider → env var 映射（13 个）
        ├─ 国内（便宜优先）：
        │   deepseek → DEEPSEEK_API_KEY
        │   kimi-coding → KIMI_API_KEY
        │   minimax → MINIMAX_API_KEY
        │   xiaomi → XIAOMI_API_KEY
        │   zai → ZAI_API_KEY
        ├─ 国外大厂：
        │   anthropic → ANTHROPIC_API_KEY
        │   openai → OPENAI_API_KEY
        │   google → GEMINI_API_KEY
        └─ 聚合/其他：
            openrouter / groq / xai / mistral / together
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap._load_specialist 的 pi 分支）
_load_specialist("pi", config)
    │
    ├─ PiInstaller(auto_install=...).ensure_installed()
    │   └─ False → return None（pi 本次不可用）
    │
    ├─ PiCredentialProvider(
    │       config_provider=config.specialists_pi_provider or None,
    │       config_api_key=config.specialists_pi_api_key or None,
    │   ).get_credential()                      ← 本文件
    │   │
    │   ├─ ⓪ _is_pi_installed()?
    │   │     └─ shutil.which("pi") 为 None → return None
    │   │
    │   ├─ ① config_api_key 非空？
    │   │     └─ return PiCredential(provider=config_provider or "anthropic",
    │   │                              api_key=config_api_key)
    │   │
    │   ├─ ② config_provider 非空？
    │   │     └─ 查 env var → 命中 → return PiCredential(provider, api_key)
    │   │
    │   ├─ ③ 遍历 _provider_env_map（国内优先）
    │   │     └─ 命中 → return PiCredential(provider, api_key)
    │   │
    │   ├─ ④ _resolve_auth_path() → 文件存在？
    │   │     └─ return PiCredential(auth_file=str(path))
    │   │
    │   └─ ⑤ 都未命中 → None
    │
    ├─ cred is None → return None（specialist disabled）
    │   └─ bootstrap 打印 warning：安装 + 设 API key
    │
    └─ cred 非 None → 构造 PiSpecialist(runtime, credential=cred) + Summarizers
        → registry.register(specialist)
        → make_specialist_tool(...)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（派活给 pi 时）
PiRuntime.invoke(request)
    │
    ├─ _build_env(request)
    │   ├─ 再次遍历 13 个 provider env（同一个列表）
    │   ├─ PI_CODING_AGENT_DIR
    │   ├─ POIROT_SANDBOX_MCP_ENDPOINT（sandbox_id 非 None）
    │   └─ {**os.environ, **auth_env}
    │
    └─ subprocess.Popen(["pi", "--mode", "rpc", ...], env=env)
        └─ pi 子进程内部读 env / auth.json
```

**注意**：`get_credential` 只用于**装配期判断 specialist 是否可用**；运行期不再调它——`PiRuntime._build_env` **独立重新遍历同一批 env 变量**，透传给子进程。**Provider 和 Runtime 各自维护一份 provider 列表**（内容一致，但代码重复）。

### 0.3. 补充

**`pi_credential.py` 是 Pi specialist 的"身份探测闸门"——装配期判断"pi CLI 是否可执行 + 有没有任何可用凭证"，决定 specialist 是否注册。**

几点补充：

- **唯一有"前置条件"的凭证 Provider**：`_is_pi_installed()` 必须为 True——**没装 CLI，有 API key 也跑不起来**。Claude / Codex 的 Provider 没有这个前置检查（它们直接读文件，文件不存在就返 None）。
- **唯一"文件是最后兜底"的 Provider**：Claude / Codex 主要靠读文件；Pi 主要靠 **config 显式传 + env 变量**，auth.json 只是第四级兜底。
- **四级优先级体现"config 优先"**：
  1. config 显式 api_key（用户在 config.yaml 里写死）
  2. config 显式 provider（用户在 config.yaml 里指定 provider，值从 env 取）
  3. 遍历所有 provider env（自动发现）
  4. auth.json 文件（最后的兼容兜底）
- **"国内 provider 优先"是显式设计**：`_provider_env_map` 的字典顺序就是优先级——DeepSeek / Kimi / MiniMax / Xiaomi / ZAI 靠前。**理由：便宜优先。**
- **同一个 provider 列表在 runtime 里重复了一遍**：`PiCredentialProvider._provider_env_map` 和 `PiRuntime._build_env` 的 `pi_env_vars` 内容几乎一致。**这是代码重复点**——如果新增 provider，需要改两处。
- **返回的三种形态**：
  - 只带 `api_key`（config 或 env 命中）
  - 只带 `auth_file`（文件兜底）
  - **不会同时带 api_key 和 auth_file**（因为一旦命中 api_key 就 return 了）
- **与 CodexCredentialProvider 的核心差异**：

| 维度 | Codex | Pi |
|---|---|---|
| 前置条件 | 无 | **pi CLI 必须在 PATH** |
| 主要凭证来源 | 文件 | **config + env** |
| 文件角色 | 主要 | **兜底** |
| 支持 config 显式传 | ❌ | ✅ |
| provider 数量 | 1（Codex 自己） | **13 个** |
| 是否强制读文件 | ✅ | ❌ |
