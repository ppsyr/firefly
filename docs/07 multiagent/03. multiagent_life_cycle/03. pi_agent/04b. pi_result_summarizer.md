---

name: PiResultSummarizer — Pi 输出端转换器（三段解析 + programmatic eval floor）。

description: 

【整体职责】
在 BaseResultSummarizer 通用校验之上，为 Pi specialist 追加"三段输出格式"解析：
从输出中提取 What You Did / Success / Gaps 三段，用 Success 段的内容参与成功判定，
用 Gaps 段作为 gap_analysis，用 What You Did 段作为 summary。

【内容摘要】
- _WHAT_YOU_DID_RE / _SUCCESS_SECTION_RE / _GAPS_SECTION_RE : 三段标题正则。
- _SUCCESS_POSITIVE_RE / _SUCCESS_NEGATIVE_RE              : Success 段正/负面关键词。
- PiResultSummarizer          : 输出端转换器主类。
- summarize()                 : 覆写基类入口，编排三段解析 + 成功判定 + 结果组装。
- _parse_pi_sections()        : 从输出解析三段（缺失段返空串）。
- _evaluate_pi_success()      : pi-specific 成功判定（base 通过 + Success 段无负面）。

【职责边界】
- 只负责：解析三段格式、在基类校验之上追加 pi 专属成功判定、优先用三段内容组装结果。
- 不负责：通用校验逻辑（基类负责）、结果压缩（基类提供兜底）、specialist 执行。
- 不持有运行时状态：纯函数式判定。

## 0. 结构树 — PiResultSummarizer（含 Base 视角）

### 0.1. 静态结构树

```
pi_result_summarizer.py — PiResultSummarizer（三段解析 + programmatic eval floor）
│
├─ 常量
│   ├─ _WHAT_YOU_DID_RE                       ← What You Did 段正则
│   │   └─ ## What You Did ... (?=## Success|## Gaps|$)，DOTALL + IGNORECASE
│   ├─ _SUCCESS_SECTION_RE                    ← Success 段正则
│   │   └─ ## Success ... (?=## Gaps|$)，DOTALL + IGNORECASE
│   ├─ _GAPS_SECTION_RE                       ← Gaps 段正则
│   │   └─ ## Gaps ... $，DOTALL + IGNORECASE
│   ├─ _SUCCESS_POSITIVE_RE                   ← 正面关键词：yes / pass / met / complete
│   └─ _SUCCESS_NEGATIVE_RE                   ← 负面关键词：no / fail / not met / partial / incomplete
│
└─ PiResultSummarizer(BaseResultSummarizer)
    │                                            ← 继承基类，specialist_name 固定 "pi"
    │                                            ★ 覆写 summarize（而非只覆写钩子）
    │
    ├─ __init__()                             ← 调 super().__init__(specialist_name="pi")
    │
    ├─ summarize(raw_output, artifacts, goal, success_criteria) -> SpecialistResult
    │   │                                        ← ★ 覆写基类入口（整体替换）
    │   ├─ ① base_success = self._evaluate_success(...)
    │   │     └─ 基类通用校验（空白 / 敏感改动 / artifacts）
    │   ├─ ② sections = self._parse_pi_sections(raw_output)
    │   │     └─ 解析三段：did / success / gaps
    │   ├─ ③ pi_success = self._evaluate_pi_success(sections, base_success)
    │   │     ├─ base_success 为 False → False
    │   │     ├─ 无 Success 段 → 退化为 base_success
    │   │     └─ Success 段含负面关键词 → False；否则 True
    │   ├─ ④ gap = sections["gaps"] or ("" if pi_success else self._extract_gap(...))
    │   │     └─ 优先 Gaps 段；缺失且失败 → 基类兜底
    │   ├─ ⑤ summary = sections["did"] or self._compress(raw_output)
    │   │     └─ 优先 What You Did 段；缺失 → 基类兜底
    │   └─ ⑥ return SpecialistResult(
    │          specialist_name="pi",
    │          summary, artifacts, success=pi_success, gap_analysis=gap
    │       )
    │       └─ ⚠️ 未填 failure_category（覆写 summarize 时漏调 _classify_failure）
    │
    ├─ _parse_pi_sections(output) -> dict[str, str]
    │   │                                        ← 解析 pi 输出三段
    │   ├─ _WHAT_YOU_DID_RE.search → sections["did"]
    │   ├─ _SUCCESS_SECTION_RE.search → sections["success"]
    │   ├─ _GAPS_SECTION_RE.search → sections["gaps"]
    │   └─ 返回 sections（缺失段不出现在 dict 中）
    │
    └─ _evaluate_pi_success(sections, base_success) -> bool
        │                                        ← pi-specific 成功判定
        ├─ ① base_success 为 False → False
        ├─ ② 无 Success 段 → return base_success（退化）
        ├─ ③ Success 段含负面关键词 → False
        └─ ④ 无负面关键词 → True

   继承链：
    BaseResultSummarizer（通用校验 + 压缩 + gap + 分类）
        └─ PiResultSummarizer（本文件，覆写 summarize 整体替换）

   同基类的其他子类：
    BaseResultSummarizer
        ├─ SelfCopyResultSummarizer（纯继承，零覆写）
        ├─ ClaudeCodeResultSummarizer（覆写 2 个钩子）
        ├─ CodexResultSummarizer（覆写 2 个钩子）
        └─ PiResultSummarizer（本文件，覆写 summarize）
```

### 0.3. 补充

**`pi_result_summarizer.py` 是 Pi specialist 的"输出端闸门"——它覆写了整个 `summarize` 入口，利用 pi 约定的三段输出格式，从结构化内容里提取 summary 和 gap_analysis。**

几点补充：

- **唯一覆写 `summarize` 的 summarizer**：其他三个都只覆写钩子（或完全不覆写），Pi 覆写了入口——因为**要插入"三段解析"这一额外步骤**，而基类的模板方法没预留这个钩子。
- **依赖 pi 的输出格式约定**：三段正则与 `PiRuntime._build_prompt` 的 `## Output Format` 严格对齐。**这是"运行时要求格式、摘要器解析格式"的契约配对。**
- **summary 和 gap 来源都变了**：
  - `summary` ← `What You Did` 段（而非基类压缩的全文）
  - `gap_analysis` ← `Gaps` 段（而非基类格式化的 "Criteria not met..."）
- **成功判定是"叠加 + 退化"**：
  - 基类通用校验是必要条件；
  - Success 段有负面词 → 失败；
  - **无 Success 段 → 退化为基类判定**（不做额外否定）。
- **⚠️ 未填 `failure_category`**：由于覆写了 `summarize` 且没有调用 `_classify_failure`，**返回的 `SpecialistResult.failure_category` 恒为 None**。这是与 Claude / Codex 的行为差异——**L2 FailureFocuser 读 Pi 的结果时拿不到失败分类**。
- **`_SUCCESS_POSITIVE_RE` 定义了但未使用**：正面关键词（yes/pass/met/complete）当前只在注释里"加强信心"，代码里没用。**这是预留或未完成的设计点。**
- **兜底策略清晰**：三段缺失时都退化为基类行为——`summary` 用 `_compress`，`gap` 用 `_extract_gap`。**保证 pi 不按格式输出时也能返回合理结果。**

## 1.  Pi 的 `summarize` 被重写了

**因为 Pi 要在"校验 → 压缩 → 提 gap"的固定流程里插入一个基类没预留的步骤：解析三段结构化输出。**

---

## 1.1. 基类的模板方法长什么样

`BaseResultSummarizer.summarize` 固定了流程：

```python
def summarize(self, raw_output, artifacts, goal, success_criteria):
    success = self._evaluate_success(...)           # ① 校验
    gap_analysis = "" if success else self._extract_gap(...)  # ② 提 gap
    summary = self._compress(raw_output)            # ③ 压缩
    failure_category = self._classify_failure(...)  # ④ 分类
    return SpecialistResult(...)
```

**它暴露了三个钩子**给子类覆写：`_evaluate_success` / `_extract_gap` / `_compress`。

**但没暴露"解析结构化输出"这一步。**

---

## 1.2. Pi 需要什么基类没给的

Pi 的 runtime 在 `_build_prompt` 里**强制要求 pi 按三段格式输出**：

```
## What You Did
- Files changed
- Commands run

## Success
- Whether success criteria are met (yes/no/partial)
- Evidence

## Gaps
- Any incomplete parts
```

**所以 Pi 的 summarize 需要先做一件事：把这三段解析出来。**

- `summary` ← `What You Did` 段
- `success` 判定 ← `Success` 段
- `gap_analysis` ← `Gaps` 段

**这三段是"数据源"，不是"输出字段"。** 基类的 `summarize` 没有"先解析再组装"这个环节。

---

## 1.3. 如果只用钩子会怎样

假设 Pi 不覆写 `summarize`，只覆写钩子：

```python
# 假想的"只用钩子"版本
class PiResultSummarizer(BaseResultSummarizer):
    def _evaluate_success(self, raw_output, artifacts, success_criteria):
        sections = self._parse_pi_sections(raw_output)   # ← 解析一次
        ...
        return pi_success

    def _extract_gap(self, raw_output, success_criteria):
        sections = self._parse_pi_sections(raw_output)   # ← 又解析一次
        return sections["gaps"] or super()._extract_gap(...)

    def _compress(self, raw_output):
        sections = self._parse_pi_sections(raw_output)   # ← 再解析一次
        return sections["did"] or super()._compress(...)
```

**问题**：

1. **解析三次**：`_parse_pi_sections` 在三个钩子里各调一次，浪费。
2. **`summary` 拿不到 Did 段**：`_compress` 的签名只接收 `raw_output`，它内部能解析出 Did 段——但如果基类的 `summarize` 调 `_compress` 时**已经决定"summary 就是压缩后的全文"**，那钩子里换内容只是"换了压缩算法"，语义上别扭。
3. **`failure_category` 会被强制填**：基类的 `summarize` 一定会调 `_classify_failure`——**如果 Pi 想让 `failure_category` 保持 None，只覆写钩子做不到。**

**所以覆写 `summarize` 是最干净的方式**：一次解析、统一组装、完全控制返回字段。

---

## 1.4. Pi 的覆写版做了什么

```python
def summarize(self, raw_output, artifacts, goal, success_criteria):
    # ① 基类通用校验
    base_success = self._evaluate_success(...)

    # ② 解析三段（只解析一次）
    sections = self._parse_pi_sections(raw_output)

    # ③ pi-specific 成功判定
    pi_success = self._evaluate_pi_success(sections, base_success)

    # ④ gap：优先 Gaps 段
    gap = sections.get("gaps", "") or ("" if pi_success else self._extract_gap(...))

    # ⑤ summary：优先 What You Did 段
    summary = sections.get("did", "") or self._compress(raw_output)

    # ⑥ 组装（不填 failure_category）
    return SpecialistResult(..., success=pi_success, gap_analysis=gap)
```

**对比基类版**：

| 步骤 | 基类版 | Pi 版 |
|---|---|---|
| 校验 | `_evaluate_success` | `_evaluate_success`（复用） |
| 解析三段 | ❌ 无 | ✅ **新增** |
| 成功判定 | 直接用 `_evaluate_success` 结果 | **叠加 Success 段判定** |
| gap | `_extract_gap` | **优先 Gaps 段**，兜底才用 `_extract_gap` |
| summary | `_compress` | **优先 What You Did 段**，兜底才用 `_compress` |
| failure_category | `_classify_failure` | ❌ **不填** |

**覆写后，Pi 完全掌控了返回值的每个字段。**

---

## 1.5. 代价：漏填 `failure_category`

覆写 `summarize` 后，Pi **完全接管了返回值的构造**——基类的 `_classify_failure` 不再被调用：

```python
# 基类版会调
failure_category = self._classify_failure(success, raw_output)

# Pi 版没调 → failure_category 走 SpecialistResult 的默认值（None）
```

**结果**：Pi 的 `SpecialistResult.failure_category` 恒为 `None`。

**影响**：L2 `FailureFocuser` 从 metrics 里读 Pi 的失败分类时，拿不到值——**Pi 的失败无法被 L2 归类。**

**这是覆写的副作用**：获得了完全控制权，也要负责把该填的字段填上。**Pi 版漏了 `failure_category`，是一个可修的点**（要么补上 `_classify_failure`，要么在 `SpecialistResult` 里显式传）。

---

## 1.6. 总结

> **Pi 覆写 `summarize`，是因为它的输出是"三段结构化格式"，需要先解析再组装——而基类的模板方法只预留了"校验/提 gap/压缩"三个钩子，没有"解析结构化输出"这一步。只覆写钩子会导致解析三次、summary 语义别扭、failure_category 被强制填。覆写整个 `summarize` 一次解析、统一组装、完全控制。代价是接管了所有字段的构造——Pi 版漏填了 `failure_category`，这是与 Claude / Codex 的一个行为差异。**
