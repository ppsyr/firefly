---

name: PiInstaller — 后台安装 Pi coding agent（不阻塞主流程）。

description: 

【整体职责】
检测 Pi CLI 是否已安装；未装时在 daemon 线程里后台执行 npm install，
不阻塞主流程。装完写 flag 文件，下次启动时 Pi specialist 自动可用。
安装状态通过 status 属性暴露给 TUI 展示。

【内容摘要】
- PiInstaller              : 安装器主类。
- ensure_installed()       : 检测 + 触发后台安装，返回"当前是否可用"。
- status (property)        : 暴露安装状态给 TUI（not_started / installing / done / failed）。
- _is_installed()          : 检测 Pi 是否已装（PATH 查找 或 flag 文件存在）。
- _is_npm_available()      : 检测 npm 是否可用。
- _install_in_background() : daemon 线程里的 npm install 实现。

【职责边界】
- 只负责：检测是否已装、触发后台安装、维护安装状态、写 flag 文件。
- 不负责：Pi 凭证（PiCredentialProvider 负责）、Pi 运行时（PiRuntime 负责）、
  Pi specialist 注册（bootstrap 负责）。
- 不持有运行时状态：状态在内存里，跨进程靠 flag 文件。

## 0. 结构树

### 0.1. 静态结构树

```
pi_installer.py — PiInstaller（后台安装 Pi coding agent）
│
└─ PiInstaller                               ← 安装器主类
    │                                            不阻塞主流程；daemon 线程后台装
    │                                            装完写 flag，下次启动自动可用
    │
    ├─ PACKAGE_NAME = "@earendil-works/pi-coding-agent"  ← npm 包名
    ├─ FLAG_FILE = ~/.poirot/pi-installed.flag            ← 安装完成标记文件
    │
    ├─ _auto_install: bool = True            ← 是否允许自动后台安装
    ├─ _install_status: str                  ← 状态机：not_started / installing / done / failed
    ├─ _install_thread: threading.Thread | None ← 后台安装线程
    │
    ├─ __init__(auto_install=True)
    │
    ├─ ensure_installed() -> bool             ← 主入口：检测 + 触发后台安装
    │   ├─ ① _is_installed() → True  → 直接返回 True
    │   ├─ ② not auto_install → warning → 返回 False
    │   ├─ ③ not _is_npm_available() → warning → 返回 False
    │   ├─ ④ 启动 daemon 线程（_install_in_background）
    │   │     ├─ _install_status = "installing"
    │   │     └─ thread.start()
    │   └─ ⑤ 返回 False（本次不可用，后台装）
    │
    ├─ status (property) -> str              ← 供 TUI 查询
    │   └─ not_started / installing / done / failed
    │
    ├─ _is_installed() -> bool               ← PATH 查找 pi 或 flag 文件存在
    │   └─ shutil.which("pi") or FLAG_FILE.exists()
    │
    ├─ _is_npm_available() -> bool           ← npm 是否在 PATH
    │   └─ shutil.which("npm") is not None
    │
    └─ _install_in_background() -> None      ← 后台安装实现（daemon 线程）
        ├─ ① shutil.which("npm") 拿全路径
        │     └─ 拿不到 → status = "failed"
        ├─ ② subprocess.run([
        │       npm_path, "install", "-g", "--ignore-scripts", PACKAGE_NAME
        │     ], capture_output=True, timeout=300)
        ├─ ③ returncode == 0 → 写 FLAG_FILE + status = "done"
        ├─ ④ returncode != 0 → status = "failed" + log stderr
        ├─ ⑤ TimeoutExpired → status = "failed"
        └─ ⑥ 其他异常 → status = "failed"
```

## 0.2. 运行时调用树

```
① 装配期（bootstrap._load_specialist 的 pi 分支）
_load_specialist("pi", config)
    │
    ├─ PiInstaller(auto_install=config.specialists_pi_auto_install)
    │
    └─ installer.ensure_installed()             ← 本文件
        │
        ├─ _is_installed()?
        │   ├─ 是（PATH 有 pi 或 flag 存在）→ return True
        │   └─ 否 → 继续
        │
        ├─ auto_install?
        │   └─ 否 → warning → return False
        │
        ├─ _is_npm_available()?
        │   └─ 否 → warning（提示装 Node.js）→ return False
        │
        ├─ 启动 daemon 线程 _install_in_background
        │   │
        │   └─ （后台执行，不阻塞）
        │       ├─ subprocess.run(["npm", "install", "-g",
        │       │                   "--ignore-scripts", PACKAGE_NAME],
        │       │                  timeout=300)
        │       ├─ 成功 → 写 FLAG_FILE + status = "done"
        │       └─ 失败 → status = "failed"
        │
        └─ return False（本次不可用）
        │
        ▼
    bootstrap 收到 False → return None（specialist 本次不注册）
        └─ _warn_specialist_disabled("pi", "credential missing or load failed")
            → 打印 warning：如何手动安装 + 设 API key
        ═══════════ 下次启动 Poirot ═══════════
        
② 下次启动（flag 文件已存在）
_load_specialist("pi", config)
    └─ PiInstaller().ensure_installed()
        └─ _is_installed() → FLAG_FILE.exists() → True
            └─ return True（Pi 可用，继续注册）
```

## 1. 为什么 Pi 需要 installer，Claude / Codex 不需要

### 1.1. 一句话

**因为 Poirot 对 Pi 做了"自动安装"的承诺，而对 Claude / Codex 只做"探测"。**

看 `config.py` 的字段就能看出这个差异：

```python
specialists_pi_auto_install: bool = True    # ← 只有 Pi 有这个开关
```

**只有 Pi 有 `auto_install` 开关**——这说明"自动安装"是 Pi 专属能力。

### 1.2. 两者的流程差异

**Claude / Codex：只探测，不安装**

```
_load_specialist("claude")
    └─ ClaudeCredentialProvider().get_credential()
        ├─ 找到凭证 → 注册 specialist
        └─ 没找到   → return None（disabled）
                       + warning："请自己安装并登录：
                         npm install -g @anthropic/claude-code
                         claude /login"
```

**关键**：Claude / Codex 的 Provider **只读文件，不做安装**。

**Pi：探测 + 自动安装**

```
_load_specialist("pi")
    └─ PiInstaller.ensure_installed()
        ├─ 已装      → True（继续）
        └─ 没装      → 启动后台 npm install（daemon 线程）
                        + 立即返回 False（本次不可用）
                        + 装完写 flag，下次启动可用
```

**关键**：Pi 的 Installer **不仅探测，还主动装**。

### 1.3. 四个原因

**原因 ①：Claude / Codex 有"登录态"问题，Pi 没有**

Claude 和 Codex 是**需要登录**的工具：

- Claude 要 `claude /login`，凭证在 `~/.claude/.credentials.json`
- Codex 要 `codex login`，凭证在 `~/.codex/auth.json`

**光装 CLI 不够，还得登录。** 登录涉及 OAuth 流程、账号密码——**Poirot 不可能替用户做**。所以只能"探测凭证是否存在"。

**Pi 则不同**：`PiInstaller` 没有凭证探测步骤，Pi 的凭证来自 **env 变量**（`ANTHROPIC_API_KEY` 之类）或 config。**"装"这个动作就能解决大部分问题。**

**原因 ②：Pi 的安装足够简单、无副作用**

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

**纯 npm 包安装**：不需要 OAuth、不需要交互、不需要用户输入、`--ignore-scripts` 保证不跑任意脚本。

**Claude / Codex 的安装则没这么简单**：

```bash
npm install -g @anthropic/claude-code
claude /login          # ← 需要交互登录
```

**`claude /login` 是交互式的**——需要浏览器 OAuth 或粘贴 token。Poirot 不能代替用户做。

**原因 ③：Pi 是"零配置可用"的定位**

从 warning 文案能看出：

```
"[PiSpecialist] disabled: %s\n"
"To enable, install Pi CLI and set any API key:\n"
"  npm install -g @earendil-works/pi-coding-agent\n"
"  Set any of: ANTHROPIC_API_KEY, OPENAI_API_KEY, ..."
```

**Pi 只要"装 + 任意一个 API key"就能用。** 不需要登录、不需要 OAuth、不需要账号。

**这让"自动安装"变得合理**——装完就能用，Poirot 可以直接替用户装。

**原因 ④：Pi 的依赖链更短**

| 工具 | 依赖 | 安装后还要做什么 |
|---|---|---|
| Claude Code | Node.js + npm | 登录（OAuth） |
| Codex | Node.js + npm | 登录（OAuth 或 API key） |
| Pi | Node.js + npm + **任意 API key** | 无（key 走 env） |

**Pi 的"安装后状态"就是"可用状态"**——只要 env 里有 key。这让自动安装真正有意义。

### 1.4. 设计上的取舍

| 维度 | Claude / Codex | Pi |
|---|---|---|
| **Poirot 的角色** | 探测者（发现凭证） | 安装者 + 探测者 |
| **用户要做的事** | 装 + 登录 | 装（Poirot 代劳）+ 设 API key |
| **是否自动安装** | ❌ 不 | ✅ 是（后台 daemon） |
| **安装是否需要交互** | ✅ 需要（登录） | ❌ 不需要 |
| **不可用时的提示** | "请自己装 + 登录" | "Poirot 正在后台装" |
| **跨启动状态** | 靠凭证文件 | 靠 flag 文件 |

**核心逻辑**：

```
能做自动化的前提 = 安装过程无交互 + 装完即可用
    ├─ Claude：装后要登录 → 有交互 → 不自动化
    ├─ Codex ：装后要登录 → 有交互 → 不自动化
    └─ Pi    ：装完即用（key 走 env） → 无交互 → 自动化 ✅
```

### 1.5. 为什么"不阻塞"很重要

`PiInstaller` 的核心设计是 **daemon 线程 + 后台安装**：

```python
self._install_thread = threading.Thread(
    target=self._install_in_background,
    daemon=True,
    name="pi-installer",
)
self._install_thread.start()
return False   # ← 立即返回
```

**为什么要这样**：`npm install` 可能要跑几分钟。如果同步等待，整个 Poirot 启动就会卡住。

**策略**：

- 本次启动：Pi 不可用（返回 False，跳过注册）
- 后台装完：写 flag 文件
- 下次启动：`_is_installed` 命中 flag → Pi 可用

**这是"下次启动生效"的策略**——用简单换可靠。

### 1.6. 总结

> **Pi 需要 installer，因为它的可用性只取决于"CLI 装没装"——不需要登录、不需要 OAuth、装完设个 API key 就能用。这让"自动安装"成为可能且合理。Claude / Codex 需要登录（OAuth 或交互式），"装"只是第一步，Poirot 无法代替用户完成登录，所以只做"凭证探测"，让用户自己搞定安装与登录。**

### 1.7. 补充

**`pi_installer.py` 是 Pi specialist 的"自动安装器"——在后台 daemon 线程里跑 npm install，不阻塞主流程，装完写 flag 供下次启动识别。**

几点补充：

- **它和其他 specialist 的 Provider 不是一类东西**：Claude / Codex 的 `CredentialProvider` 是"探测者"，Pi 的 `PiInstaller` 是"安装者 + 探测者"。**这是 Pi 的特殊性。**
- **"下次启动生效"是刻意的简单策略**：本次启动后台装完也不会"当场可用"——因为 `ensure_installed` 已返回 False，bootstrap 不会回头再注册。**用"一次启动延迟"换取实现简单。**
- **flag 文件是唯一跨进程状态**：`_install_status` 只在内存里，进程重启就丢；flag 文件是唯一持久化的"已装"信号。**所以两个判断条件是 `or` 关系**：PATH 里有 pi（别人装的）或 flag 存在（自己装的）。
- **`--ignore-scripts` 是安全考量**：npm 的 lifecycle scripts 可以执行任意命令，Pi 官方推荐跳过。**Poirot 遵循这个建议，避免自动安装引入安全风险。**
- **状态机单向流转**：`not_started → installing → done / failed`。TUI 可轮询 `status` 展示安装进度。
- **Windows 兼容处理**：npm 在 Windows 上是 `.cmd` 文件，用 `shutil.which` 拿全路径后 `subprocess.run` 直接调，不依赖 `shell=True`。
