---

name: ClaudeCodeResultSummarizer — Claude Code 输出端转换器（review 完整性 + 修改建议）。

description: 

【整体职责】
在 BaseResultSummarizer 通用校验之上，为 Claude Code specialist 追加两项
review 专属校验：输出必须包含修改建议（suggestion）才算成功；若无 issue 或
无 suggestion，在 gap_analysis 中说明缺失项。

【内容摘要】
- _SUGGESTION_RE / _ISSUE_RE      : 修改建议 / 问题描述的正则。
- ClaudeCodeResultSummarizer      : 输出端转换器主类。
- _evaluate_success()             : 覆写基类成功判定，追加 suggestion 检查。
- _has_suggestions()              : 判断输出是否含修改建议。
- _has_issues()                   : 判断输出是否含问题描述。
- _extract_gap()                  : 覆写基类 gap 提取，追加缺失说明。

【职责边界】
- 只负责：在基类校验之上追加 Claude Code 专属的成功判定与 gap 补充。
- 不负责：通用校验逻辑（基类负责）、结果压缩（基类负责）、specialist 执行。
- 不持有运行时状态：纯函数式判定。

## 0. 结构树 — BaseResultSummarizer（ClaudeCode 扩展视角）

### 0.1. 静态结构树

```
base.py — BaseResultSummarizer（通用 programmatic eval floor）
│
├─ 常量
│   ├─ _MAX_SUMMARY_CHARS: int = 2000         ← 压缩上限，超出截断
│   └─ _SENSITIVE_PATTERNS: list[str]         ← 敏感改动正则（5 条）
│       ├─ rm -rf /
│       ├─ mkfs.
│       ├─ dd of=/dev/
│       ├─ > /etc/passwd
│       └─ chmod 777 /
│
└─ BaseResultSummarizer                      ← 通用骨架主类
    │                                           对外唯一入口 summarize()
    │                                           其余 _ 开头方法为钩子，子类可覆写
    │
    ├─ _specialist_name: str = "base"        ← 写进产出的 SpecialistResult
    │
    ├─ __init__(specialist_name="base")      ← 子类传入自己的名字
    │
    ├─ summarize(raw_output, artifacts, goal, success_criteria) -> SpecialistResult
    │   │                                        ← ★ 对外唯一入口（模板方法）
    │   ├─ ① success = self._evaluate_success(...)
    │   │     └─ 钩子：子类可覆写（ClaudeCode 覆写了它）
    │   ├─ ② gap_analysis = "" if success else self._extract_gap(...)
    │   │     └─ 钩子：子类可覆写（ClaudeCode 覆写了它）
    │   ├─ ③ summary = self._compress(raw_output)
    │   │     └─ 钩子：子类可覆写
    │   ├─ ④ failure_category = self._classify_failure(success, raw_output)
    │   │     └─ 钩子：子类可覆写
    │   └─ ⑤ return SpecialistResult(...)
    │
    ├─ _classify_failure(success, raw_output) -> str | None
    │   │                                        ← 钩子：启发式失败分类
    │   ├─ success=True → None
    │   ├─ "context"          → "context_insufficient"
    │   ├─ "skill" / "ability"→ "ability_insufficient"
    │   ├─ "goal" / "unclear" → "goal_unclear"
    │   ├─ "sandbox" / "timeout" → "sandbox_issue"
    │   └─ 默认               → "ability_insufficient"
    │
    ├─ _evaluate_success(raw_output, artifacts, success_criteria) -> bool
    │   │                                        ← 钩子：通用成功判定
    │   ├─ raw_output 空白 → False
    │   ├─ 有敏感改动 → False
    │   ├─ artifacts 为空（非 None） → False
    │   └─ 否则 → True
    │
    ├─ _has_sensitive_changes(raw_output) -> bool
    │   │                                        ← 钩子：检测敏感改动
    │   └─ 遍历 _SENSITIVE_PATTERNS 正则匹配
    │
    ├─ _compress(raw_output) -> str           ← 钩子：压缩 raw_output
    │   ├─ len <= 2000 → 原样
    │   └─ len > 2000 → 截断 + "...(truncated)"
    │
    └─ _extract_gap(raw_output, success_criteria) -> str
        │                                        ← 钩子：提取失败原因
        └─ "Criteria not met: <criteria>. Output tail: <最后 5 行，最多 200 字符>"

   子类扩展点（本文件外）：
    ├─ SelfCopyResultSummarizer               ← 纯继承，零覆写
    └─ ClaudeCodeResultSummarizer             ← 覆写 2 个钩子
        ├─ _evaluate_success（覆写）
        │   ├─ 先 super() 通用校验
        │   └─ 再 _has_suggestions 追加 review 专属判定
        └─ _extract_gap（覆写）
            ├─ 先 super() 拿 base_gap
            └─ 再按 suggestion / issue 缺失情况追加说明
```

### 0.2. 模板方法调用链（含子类覆写视角）

```
外部调用（tool handler）
    │
    ▼
summarizer.summarize(raw_output, artifacts, goal, success_criteria)
    │
    │  ← 若 summarizer 是 ClaudeCodeResultSummarizer，
    │    这里调的是「继承来的」BaseResultSummarizer.summarize
    │    （ClaudeCode 没覆写 summarize，只覆写了钩子）
    │
    ▼
BaseResultSummarizer.summarize（模板方法，流程固定）
    │
    ├─ ① self._evaluate_success(raw_output, artifacts, success_criteria)
    │   │
    │   │  ┌── 若 self 是 BaseResultSummarizer ──┐
    │   │  │ 走基类版：空白/敏感改动/artifacts 检查 │
    │   │  └────────────────────────────────────┘
    │   │
    │   │  ┌── 若 self 是 ClaudeCodeResultSummarizer ──┐
    │   │  │ 走子类版：                                  │
    │   │  │   ├─ super()._evaluate_success(...)  ← 先通用校验
    │   │  │   │   （空白 / 敏感改动 / artifacts）        │
    │   │  │   └─ self._has_suggestions(raw_output)      │
    │   │  │       （追加：无 suggestion → False）        │
    │   │  └────────────────────────────────────────────┘
    │   │
    │   ├─ 通过 → success = True
    │   └─ 不通过 → success = False
    │
    ├─ ② success=False → self._extract_gap(raw_output, success_criteria)
    │   │
    │   │  ┌── 基类版 ──┐
    │   │  │ "Criteria not met: ... Output tail: ..." │
    │   │  └───────────┘
    │   │
    │   │  ┌── ClaudeCode 覆写版 ──┐
    │   │  │ base_gap = super()._extract_gap(...)       │
    │   │  │ + 无 suggestion → 附 "No modification suggestions found." │
    │   │  │ + 有 suggestion 无 issue → 附 "No review issues identified." │
    │   │  └───────────────────────┘
    │   │
    │   └─ success=True → gap_analysis = ""
    │
    ├─ ③ self._compress(raw_output)
    │   └─ 基类版：超 2000 字符截断（子类未覆写）
    │
    ├─ ④ self._classify_failure(success, raw_output)
    │   └─ 基类版：启发式分类（子类未覆写）
    │
    └─ ⑤ return SpecialistResult(
           specialist_name=self._specialist_name,
           summary, artifacts, success, gap_analysis, failure_category
       )
```

**三个 specialist 走同一条 summarize 骨架，差异只在钩子：**

| 钩子 | BaseResultSummarizer | SelfCopyResultSummarizer | ClaudeCodeResultSummarizer |
|---|---|---|---|
| `_evaluate_success` | 基类版 | **继承** | **覆写**（+ suggestion 检查） |
| `_extract_gap` | 基类版 | **继承** | **覆写**（+ 缺失说明） |
| `_compress` | 基类版 | 继承 | 继承 |
| `_classify_failure` | 基类版 | 继承 | 继承 |
| `_has_sensitive_changes` | 基类版 | 继承 | 继承 |

### 0.3. 补充

**`base.py` 是输出端转换的"通用骨架"——`summarize` 固定流程，`_evaluate_success` / `_extract_gap` 等留成钩子，子类按 specialist 定制。**

几点补充：

- **模板方法模式**：`summarize` 是对外唯一入口（无下划线），其余 `_` 方法都是"基类与子类之间的内部协议"。**子类没有新对外功能，只改写骨架内的钩子。**
- **成功判定是"叠加"结构**：`ClaudeCodeResultSummarizer._evaluate_success` 先调 `super()` 拿通用结论，再追加自己的检查。**子类不能绕过基类的通用校验**——这是"通用底线 + 专属增强"的设计。
- **gap 提取同样是"叠加"**：`ClaudeCodeResultSummarizer._extract_gap` 保留 `base_gap` 再追加说明，**信息不丢**。
- **`_classify_failure` 的输出直接喂给 L2**：返回的字符串是 `failure_category` 的原始值，`metrics.py` 里再转成 `FailureCategory` 枚举。**这是 L1 与 L2 的数据接口之一。**
- **敏感改动是"硬红线"**：`_SENSITIVE_PATTERNS` 匹配到 `rm -rf /` 等就直接判失败，**不是建议、不是警告，是一票否决**。这是 programmatic eval floor 的核心语义。
- **`_compress` 只管长度，不管语义**：超 2000 字符直接截断，不做智能摘要。**保持"零 LLM"的实现。**
- **子类覆写钩子必须先调 super()**：这是不成文的约定——**基类保证通用底线，子类只做增强**。`ClaudeCodeResultSummarizer` 严格遵守了这个约定。
