---

name: ClaudeCredentialProvider — 读 ~/.claude/.credentials.json 复用 Claude Code CLI 登录态。

description: 

【整体职责】
发现 Claude Code CLI 的 OAuth 凭证：优先读环境变量直接提供的 token，
否则读 credentials 文件（路径可被 env 覆盖，默认 ~/.claude/.credentials.json），
解析出 accessToken / refreshToken / expiresAt，返回 ClaudeCredential。
凭证缺失或过期时返回 None（不抛异常）。

【内容摘要】
- ClaudeCredential              : 凭证数据类，含 access_token / refresh_token / expires_at。
- ClaudeCredentialProvider      : 凭证发现主类，实现 get_credential()。
- get_credential()              : 按三级查找顺序发现凭证，返 ClaudeCredential | None。
- _resolve_path()               : 解析 credentials 文件路径（env 覆盖 + 默认路径）。
- _load_json()                  : 读取并解析 JSON 文件，失败返回 None。

【职责边界】
- 只负责：发现凭证、读取文件、解析字段、过期检测。
- 不负责：刷新凭证、存储凭证、管理凭证生命周期、写 ThreadState。
- 不持有运行时状态：每次 get_credential 重新读取。

## 0. 结构树

### 0.1. 静态结构树

```
claude_credential.py — ClaudeCredentialProvider（读 ~/.claude/.credentials.json）
│
├─ ClaudeCredential(Credential, frozen)       ← Claude Code CLI OAuth 凭证
│   │                                            只传给 specialist runtime，不写 ThreadState
│   │                                            kind 固定 "claude"
│   ├─ access_token: str                      ← OAuth 访问令牌
│   ├─ refresh_token: str = ""                ← OAuth 刷新令牌（可选，读但不用）
│   ├─ expires_at: int = 0                    ← 毫秒时间戳；0 表示无过期信息
│   └─ is_expired (property) -> bool          ← 过期检测（留 1 分钟 buffer）
│       └─ expires_at <= 0 → False（不检测）
│
└─ ClaudeCredentialProvider                   ← 凭证发现主类
    │                                            复用 CLI 登录态，不管理凭证
    │                                            凭证缺失/过期返 None，不抛异常
    │
    ├─ get_credential() -> ClaudeCredential | None
    │   │                                        ← 三级查找顺序
    │   ├─ ① $CLAUDE_CODE_OAUTH_TOKEN / $ANTHROPIC_AUTH_TOKEN
    │   │     └─ 非空 → 直接返回 ClaudeCredential(access_token=token)
    │   ├─ ② _resolve_path() 解析路径
    │   ├─ ③ _load_json(path) 读文件
    │   │     └─ None → 返回 None
    │   ├─ ④ 取 data["claudeAiOauth"]
    │   │     ├─ 非 dict → 视为 {}
    │   │     └─ accessToken 缺失 → 返回 None
    │   ├─ ⑤ 构造 ClaudeCredential(access_token, refresh_token, expires_at)
    │   ├─ ⑥ is_expired → 返回 None
    │   └─ ⑦ 返回 ClaudeCredential
    │
    ├─ _resolve_path() -> Path                ← 解析 credentials 文件路径
    │   ├─ $CLAUDE_CODE_CREDENTIALS_PATH 存在 → Path(env).expanduser()
    │   └─ 否则 → ~/.claude/.credentials.json
    │
    └─ _load_json(path) -> dict | None        ← 读取并解析 JSON
        ├─ 文件不存在 / 是目录 → None
        ├─ JSONDecodeError / OSError → None
        └─ 成功 → dict
```

### 0.2. 为什么需要它（设计动机）

```
没有它的情况：
    bootstrap 无脑注册 claude specialist
        → 生成 delegate_to_claude 工具
        → LLM 看到工具，以为可以派活
        → 用户其实没登录 claude
        → 派活时 subprocess.run(["claude", ...]) 失败
        → SpecialistCrashError
        → LLM 白跑一轮，还要重新规划

问题：
    ① LLM 被"骗"——看到不可用的工具
    ② 错误在运行时才暴露，不是启动时
    ③ 浪费一轮推理
    ④ 可能反复失败，陷入循环

有了它之后：
    bootstrap 先探测凭证
        ├─ 有 → 注册 specialist，生成工具
        └─ 无 → 跳过注册，不生成工具
                + warning 提示如何启用

好处：
    ① LLM 不被骗——不可用的工具根本不出现
    ② 启动时就告知用户如何启用
    ③ 优雅降级——没 claude 就用其他 specialist
    ④ 不阻塞——探测失败只 warn，不抛异常
```

**它解决的三个具体问题：**

| 问题 | 解法 |
|---|---|
| **可用性判断** | 启动时知道哪些 specialist 能用；返回非 None = 能用 |
| **凭证来源适配** | 把"从哪找凭证"（env / 文件 / 默认路径）封装起来 |
| **过期检测** | 凭证过期时当"不可用"，避免注册"看起来能用但会失败"的 specialist |

**Provider 与 Runtime 的分工：**

```
装配期（早）                              运行期（晚）
ClaudeCredentialProvider                 ClaudeCodeRuntime
  ├─ 读 env / 文件                         ├─ _build_env 透传 env
  ├─ 解析 token / expires                  ├─ subprocess.run(["claude", ...])
  ├─ 判断是否可用                           └─ claude 子进程自己读登录态
  └─ 返 Credential | None
  │
  ▼
bootstrap 据此决定：
  ├─ 注册 specialist + 生成工具
  └─ 或 跳过 + warning
```

**关键点**：Provider 返回的 `ClaudeCredential` **不直接传给 runtime**——它只用于"判断可用性"。运行时 `ClaudeCodeRuntime._build_env` **重新读一遍 env**，透传给子进程。**Provider 是"启动时的探测员"，不是"运行时的凭证搬运工"。**

### 0.3. 运行时调用树

```
① 装配期（bootstrap._load_specialist 的 claude 分支）
_load_specialist("claude", config)
    │
    ├─ ClaudeCredentialProvider().get_credential()      ← 本文件
    │   │
    │   ├─ ① 读 $CLAUDE_CODE_OAUTH_TOKEN / $ANTHROPIC_AUTH_TOKEN
    │   │     └─ 有 → 直接返回 token 凭证（跳过文件读取）
    │   │
    │   ├─ ② _resolve_path()
    │   │     ├─ $CLAUDE_CODE_CREDENTIALS_PATH → 指定路径
    │   │     └─ 默认 ~/.claude/.credentials.json
    │   │
    │   ├─ ③ _load_json(path)
    │   │     ├─ 不存在 / 目录 / 解析失败 → None
    │   │     └─ 成功 → dict
    │   │
    │   ├─ ④ 解析 data["claudeAiOauth"]
    │   │     ├─ accessToken 缺失 → None
    │   │     └─ 构造 ClaudeCredential
    │   │
    │   ├─ ⑤ is_expired 检测
    │   │     ├─ 过期 → None
    │   │     └─ 未过期 → 返回
    │   │
    │   └─ 返回 ClaudeCredential | None
    │
    ├─ cred is None → return None（specialist disabled）
    │   └─ bootstrap 打印 warning：如何登录 Claude Code
    │
    └─ cred 非 None → 构造 ClaudeCodeSpecialist + Summarizers
        → registry.register(specialist)
        → make_specialist_tool(...)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期（派活给 claude 时）
ClaudeCodeRuntime.invoke(request)
    │
    ├─ _build_env()
    │   ├─ 再次读 auth 相关 env 变量
    │   │   （CLAUDE_CODE_OAUTH_TOKEN / ANTHROPIC_AUTH_TOKEN /
    │   │    ANTHROPIC_API_KEY / CLAUDE_CODE_CREDENTIALS_PATH）
    │   └─ 透传给 claude 子进程
    │
    └─ subprocess.run(["claude", "--print", goal], env=env)
        │
        └─ claude 子进程内部读自己的登录态（文件 / env）
```

### 0.4. 补充

**`claude_credential.py` 是 Claude specialist 的"身份探测闸门"——装配期判断"用户是否登录过 Claude Code"，决定 specialist 是否注册。**

几点补充：

- **装配期发现，运行期透传**：`get_credential()` 只在 bootstrap 时调一次，判断 specialist 是否可用；运行时 `ClaudeCodeRuntime._build_env` 把 env 变量透传给 `claude` 子进程，由子进程自己读登录态。**Provider 不直接传 token 给 runtime，只负责"探明是否存在"。**
- **三级查找顺序**：env 直传 token > env 指定文件路径 > 默认文件路径。**env 直传优先于文件**——用户可以用 env 覆盖 CLI 登录态。
- **`expires_at <= 0` 视为"不检测"**：不是"已过期"。兼容某些凭证文件不带 `expiresAt` 字段的情况——没有过期信息就不猜。
- **过期检测留 1 分钟 buffer**：提前 1 分钟判定过期，避免"刚好卡在过期边界"的竞态。
- **IO 失败统一返 None**：文件不存在、是目录、JSON 解析失败、读取异常——四种情况都不抛异常，统一返 None。**保证"凭证探测"永不阻塞启动流程。**
- **`refresh_token` 被读取但不被使用**：Poirot 不刷新凭证——刷新是 Claude CLI 的事。这个字段只是"顺带带出来"，供未来扩展。
