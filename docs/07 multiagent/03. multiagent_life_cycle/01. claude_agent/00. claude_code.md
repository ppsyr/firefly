# 1. ClaudeCode 专家系统流程

## 1.1. 4 个核心组件的角色

| 文件 | 角色 | 一句话职责 |
|---|---|---|
| `runtimes/claude_code_runtime.py` | 执行器 | 启动 `claude --print` 子进程，用 stdout 作为原始输出；异常统一为 SpecialistError |
| `specialists/claude_code_specialist.py` | 适配器 | 把 runtime 包装成 `SpecialistAgent` 契约（name="claude" / capability=REVIEW / invoke） |
| `summarizers/context/claude_code_context_summarizer.py` | 输入端闸门 | 从父 ThreadState 规则提取"代码块 + review 关键词"，零 LLM |
| `summarizers/result/claude_code_result_summarizer.py` | 输出端闸门 | 继承 BaseResultSummarizer，追加 review 完整性校验（必须有修改建议） |

**与 subagent 的对照**：

| | subagent | claude_code |
|---|---|---|
| 执行器 | `SubagentRuntime`（进程内调 lead factory） | `ClaudeCodeRuntime`（外部 CLI 子进程） |
| 输入端摘要 | `SelfCopyContextSummarizer`（LLM + 规则 fallback） | `ClaudeCodeContextSummarizer`（纯规则） |
| 输出端摘要 | `SelfCopyResultSummarizer`（纯继承，零覆写） | `ClaudeCodeResultSummarizer`（继承 + 2 覆写） |
| capability | RESEARCH | REVIEW |
| 凭证 | 继承 Leader，无需外部凭证 | 需要 `ClaudeCredentialProvider` 检测登录态 |
| 额外依赖 | 无 | `configure_mcp`（注册 SpecialistMcpServer） |

**关键差异**：claude_code 多了"**凭证探测**"和"**MCP 配置**"两个环节——这是外部异构 specialist 相比自复制 subagent 多出的复杂度。

## 1.2. 组件装配关系图

```
                    ClaudeCodeSpecialist
                    ├─ name = "claude"
                    ├─ capabilities = (REVIEW,)
                    ├─ invoke() → 转发
                    └─ _runtime: ClaudeCodeRuntime
                            ├─ _command = "claude"
                            └─ _sandbox_provider

                    ClaudeCodeContextSummarizer    ClaudeCodeResultSummarizer
                    （零 LLM，正则提取）              （继承 BaseResultSummarizer，
                                                       覆写 _evaluate_success + _extract_gap）

                    ┌──────────────────────────────────────┐
                    │  三者被 make_specialist_tool 闭包捕获  │
                    │  → 绑定到 delegate_to_claude tool      │
                    └──────────────────────────────────────┘

                    ┌──────────────────────────────────────┐
                    │  ClaudeCredentialProvider              │
                    │  （装配期单独调，决定 specialist 是否可用）│
                    │  返回 ClaudeCredential | None          │
                    └──────────────────────────────────────┘
```

**与 subagent 的关键差异**：claude_code 的装配路径上多了一个"**凭证闸门**"——`ClaudeCredentialProvider` 在 specialist 被构造前先探测，探测失败则整个分支跳过。

## 1.3. 完整流程（装配 → 运行）

### 阶段 A：装配（启动时一次）

```
① bootstrap._load_specialist("claude", config)
   │
   ├─ ①-1 ClaudeCredentialProvider().get_credential()
   │   │  用途：探测用户是否登录过 Claude Code
   │   │  三级查找：env token > env 文件路径 > ~/.claude/.credentials.json
   │   │
   │   └─ 返回 None → return None（specialist disabled，跳过注册）
   │       └─ bootstrap._warn_specialist_disabled("claude", ...)
   │           → 打印 warning：如何安装 + 登录 Claude Code
   │
   └─ ①-2 cred 非 None → 继续构造
       │
       └─ return (
              ClaudeCodeSpecialist(),                # ② specialist
              ClaudeCodeContextSummarizer(),         # ③ 输入端摘要器
              ClaudeCodeResultSummarizer(),          # ④ 输出端摘要器
          )
   │
   ▼
② registry.register(specialist)
   └─ 用途：✅ 唯一注册点——ClaudeCodeSpecialist 进 SpecialistRegistry
   │
   ▼
③ make_specialist_tool(
       "claude", specialist,
       ctx_summarizer,        ← ClaudeCodeContextSummarizer 闭包捕获
       result_summarizer,     ← ClaudeCodeResultSummarizer 闭包捕获
       max_steps=..., timeout_seconds=...
   )
   └─ 产出：delegate_to_claude (BaseTool)
   │
   ▼
④ 工具进 Leader 的 tools 列表 → LLM 可见
```

**可选路径（MCP 配置）**：

```
⑤ configure_mcp(sandbox_id)                    ← 由 specialist / bootstrap 在 invoke 前调
   ├─ _build_mcp_add_command(sandbox_id)
   │   └─ claude mcp add poirot_sandbox -- python -m ...specialist_mcp_server
   │       [+ sandbox URL 参数]
   └─ subprocess.run(cmd, timeout=30)           ← 把 Poirot MCP server 注册给 claude CLI
```

**装配后状态**：
- registry 里：`{"claude": ClaudeCodeSpecialist}`
- tool 闭包里：`ClaudeCodeSpecialist` + `ClaudeCodeContextSummarizer` + `ClaudeCodeResultSummarizer`
- `ClaudeCodeRuntime` 藏在 Specialist 里，`command` / `sandbox_provider` 藏在 Runtime 里
- 凭证探测的结论：要么注册，要么跳过 + warning

### 阶段 B：运行（每次派活）

```
① LLM 决定派活
   └─ tool_call("delegate_to_claude", {goal, success_criteria})
   │
   ▼
② OrchestrationMiddleware.wrap_tool_call
   ├─ set_current_state(state)                  ← 把 ThreadState 写进 ContextVar
   └─ metrics 打点（selection / invoked）
   │
   ▼
③ delegate_to_claude handler（闭包）
   │
   ├─ state = get_current_state()               ← 读 ContextVar
   │
   ├─ context_summary = ctx_summarizer.summarize(state, goal, criteria)
   │   │  用途：输入端闸门——从父上下文提取代码 + review 重点
   │   │
   │   └─ ClaudeCodeContextSummarizer.summarize
   │       ├─ ① 拼 "Goal: ..." / "Success criteria: ..."
   │       ├─ ② _extract_code_blocks(state)
   │       │     ├─ 遍历 messages → 正则 ``` ... ```
   │       │     └─ 最多 2 个代码块
   │       ├─ ③ _extract_review_hints(state)
   │       │     ├─ 匹配 review / check / verify / test / lint /
   │       │     │   security / performance
   │       │     └─ 去重取前 5
   │       ├─ ④ 超过 3000 字符 → 截断
   │       └─ 返回 context_summary 字符串
   │
   ├─ request = SpecialistRequest(
   │       goal, success_criteria, context_summary, sandbox_id, ...
   │   )
   │
   ├─ raw = specialist.invoke(request)
   │   │  用途：适配层转发
   │   │
   │   └─ ClaudeCodeSpecialist.invoke(request)
   │       └─ self._runtime.invoke(request)
   │           │  用途：执行器——启动外部 claude 子进程
   │           │
   │           ├─ ① _build_command(request)
   │           │     └─ ["claude", "--print", goal]
   │           ├─ ② _build_env()
   │           │     ├─ 读 4 个 auth env 变量
   │           │     ├─ 无 auth → None
   │           │     └─ 有 auth → {**os.environ, **auth_env}
   │           ├─ ③ subprocess.run(cmd, capture_output=True, text=True,
   │           │                   timeout=request.timeout_seconds, env=env)
   │           │     │
   │           │     │  ┌── 操作系统级：启动 claude 子进程 ──┐
   │           │     │  │ PATH 查找 → fork/exec             │
   │           │     │  │ claude 内部：读 auth → 调 API      │
   │           │     │  │              → ReAct loop        │
   │           │     │  │              → stdout → exit     │
   │           │     │  └──────────────────────────────────┘
   │           │     │
   │           │     ├─ TimeoutExpired   → SpecialistTimeoutError
   │           │     ├─ FileNotFoundError→ SpecialistStartupError
   │           │     └─ returncode != 0  → SpecialistCrashError(exit_code)
   │           │
   │           └─ ④ return SpecialistRawResult(raw_output=stdout, duration)
   │
   ├─ result = result_summarizer.summarize(raw.raw_output, raw.artifacts, goal, criteria)
   │   │  用途：输出端闸门——压结果 + 程序化评估（review 完整性）
   │   │
   │   └─ ClaudeCodeResultSummarizer.summarize（继承自 BaseResultSummarizer）
   │       ├─ _evaluate_success（覆写）
   │       │   ├─ super()._evaluate_success(...)   ← 通用校验（空白/敏感/artifacts）
   │       │   └─ _has_suggestions(raw_output)    ← 追加：必须有修改建议
   │       ├─ _compress(raw_output)               ← 超 2000 字符截断
   │       ├─ _extract_gap（覆写，仅 success=False）
   │       │   ├─ base_gap = super()._extract_gap(...)
   │       │   ├─ 无 suggestion → 附 "No modification suggestions found."
   │       │   └─ 有 suggestion 无 issue → 附 "No review issues identified."
   │       ├─ _classify_failure(success, raw_output)  ← 启发式分类
   │       └─ return SpecialistResult(specialist_name="claude", ...)
   │
   └─ return json.dumps({success, summary, specialist, gap_analysis, artifacts})
   │
   ▼
④ OrchestrationMiddleware.wrap_tool_call（返回后）
   ├─ metrics 打点（completion / fallback）
   ├─ _build_orchestration_update → ArtifactRef 列表
   └─ return Command{update: {messages, orchestration}}
   │
   ▼
⑤ ThreadState 更新 → LLM 看到 ToolMessage → 继续推理
```

## 1.4. 每个文件在流程里的"出场点"

| 文件 | 装配期出场 | 运行期出场 | 具体动作 |
|---|---|---|---|
| `credentials/claude_credential.py` | **①-1 被调** | ❌ 不再出场 | 探测登录态，返回 Credential 或 None |
| `runtimes/claude_code_runtime.py` | ①-2 被构造 | ③ 被 invoke | 启动 claude 子进程，收 stdout |
| `specialists/claude_code_specialist.py` | ①-2 被构造 + ② 进 registry | ③ 被 invoke | 转发给 runtime |
| `summarizers/context/claude_code_context_summarizer.py` | ①-2 被构造 + ③ 闭包捕获 | ③ 被 summarize | 提取代码 + review 关键词 |
| `summarizers/result/claude_code_result_summarizer.py` | ①-2 被构造 + ③ 闭包捕获 | ③ 被 summarize | review 完整性校验 + gap 补充 |
| `runtimes/__init__.py`（`append_sandbox_url_args`） | — | ⑤ configure_mcp 时 | 构造 mcp add 的沙箱 URL 参数 |

**与 subagent 的差异**：claude_code 多了一个 `claude_credential.py` **只在装配期出场**——运行期不再调它，auth 通过 env 透传给子进程。

## 1.5. 最小可用的"数据流"

```
父 ThreadState
    │
    │ ① ClaudeCodeContextSummarizer 压（正则提取代码 + review 关键词）
    ▼
context_summary: str
    │
    │ ② 装进 SpecialistRequest
    ▼
SpecialistRequest
    │
    │ ③ ClaudeCodeRuntime._build_command + _build_env
    ▼
["claude", "--print", goal] + env
    │
    │ ④ subprocess.run 启动 claude 子进程
    ▼
claude 进程（内部：读 auth → 调 API → ReAct → stdout）
    │
    │ ⑤ _extract_output：取 result.stdout
    ▼
raw_output: str
    │
    │ ⑥ ClaudeCodeResultSummarizer 压 + 校验（必须含 suggestion）
    ▼
SpecialistResult(specialist_name="claude", success, summary, gap_analysis)
    │
    │ ⑦ json.dumps 转 ToolMessage
    ▼
回 Leader
```

**与 subagent 数据流的关键差异**：

| 步骤 | subagent | claude_code |
|---|---|---|
| ② 输入构造 | goal + context_summary | goal + context_summary（同样的） |
| ③ 执行方式 | **进程内调 agent.invoke** | **`subprocess.run(["claude", ...])`** |
| ④ 执行载体 | 当前 Python 进程 | **操作系统子进程** |
| ⑤ 结果来源 | agent result 的最后一条消息 | **claude 子进程的 stdout** |
| ⑥ 成功判定 | 基类通用校验 | **基类 + review 完整性（必须有 suggestion）** |

---

## 1.6. 总结

> **claude_code 专家系统是 multiagent 的"外部异构接入路径"——通过 `subprocess.run` 启动 `claude` CLI 子进程，用它的 stdout 作为结果；输入端用纯规则提取代码与 review 重点，输出端在通用校验之上追加"必须有修改建议"的 review 专属判定。装配期多一道"凭证探测"闸门：没登录就不注册，避免 LLM 被不可用的工具误导。**

**一句话对比 subagent**：

| 维度 | subagent | claude_code |
|---|---|---|
| 本质 | 进程内自复制 | 外部 CLI 调用 |
| 依赖 | 无外部依赖 | 依赖 claude CLI + 登录态 |
| 装配闸门 | 无 | **凭证探测** |
| 输入摘要 | LLM + 规则 fallback | **纯规则** |
| 输出摘要 | 纯继承 | **继承 + 2 覆写** |
| 执行方式 | `agent.invoke` | **`subprocess.run`** |
| 额外环节 | 无 | **`configure_mcp`** |

**核心**：claude_code 比 subagent 多的三个环节——**凭证探测（装配期）、MCP 配置（可选）、外部进程执行（运行期）**——正是"外部异构 specialist"相比"内部自复制"多出的复杂度来源。
