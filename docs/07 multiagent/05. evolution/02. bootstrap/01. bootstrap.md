---

name: L2 evolution bootstrap — 装配 L2 组件 + 启动 daemon 线程。

description: 

【整体职责】
L2 进化层的装配入口：当 config.l2.enabled=true 时，构造 L2 的全部组件
（VersionDAG / PromotionGate / EvolutionMutator / TriggerManager /
L2TriggerMiddleware / BudgetGuard / OrchestrationMetricsL2 / L2EvolutionWorker），
并在 L3 启用时嵌套调用 setup_l3；enabled=false 时返回 None，L1 行为不变。

【内容摘要】
- L2Setup(dataclass)                 : L2 装配结果容器（注入 L1 MultiAgentSetup）。
- setup_l2(config, metrics_store)    : 装配主入口。
- _build_budget_limits(budget_config): 从 BudgetConfig 构造 per-specialist BudgetLimit。

【职责边界】
- 只负责：构造 L2 组件、注入 L3（可选）、打包 L2Setup。
- 不负责：L2 演化逻辑（各组件负责）、L3 内部装配（setup_l3 负责）。
- 不持有状态：装配产出 L2Setup 后返回。

```

│   ├─ version_dag: VersionDAG            ← 版本 DAG（版本谱系）

│   ├─ budget_guard: BudgetGuard          ← 预算守卫

│   │   └─ 共享 cron 队列

│   │
│   ├─ ⑩ trigger_manager = TriggerManager(task_queue, cooldown, cron, thresholds)
│   │
│   ├─ ⑪ l2_trigger_mw = L2TriggerMiddleware(trigger_manager, metrics_view)
│   │   └─ L1 graph after_model 钩子

        ├─ ③ metrics_view = metrics_store
        ├─ ④ focuser = FailureFocuser(...)
        ├─ ⑤ mutator = EvolutionMutator(llm_caller=None, ...)
        ├─ ⑥ bridge = None 或 OrchestrationBridge
        ├─ ⑦ gate = PromotionGate(evaluator=None, bridge=bridge, ...)
        ├─ ⑧ task_queue = queue.Queue()
        ├─ ⑨ thresholds = TriggerThresholds(...)
        ├─ ⑩ trigger_manager = TriggerManager(...)
        ├─ ⑪ l2_trigger_mw = L2TriggerMiddleware(...)
        ├─ ⑫ budget_limits = _build_budget_limits(config.budget)
        ├─ ⑬ budget_guard = BudgetGuard(...)
        ├─ ⑭ metrics_l2 = OrchestrationMetricsL2(...)

        │

        │   └─ l3_setup = setup_l3(config, metrics_store, task_queue)
        │       ├─ SpecialistEvalRegistry + 3 adapter
        │       ├─ OrchestrationBridge
        │       ├─ SpecialistRuntimeTracker
        │       ├─ DecisionLogWriter / Reader
        │       ├─ MultiagentProgrammaticFacade
        │       └─ 启动 6h 健康检查 daemon 线程
        │
        └─ ⑰ return L2Setup(version_dag, gate, mutator, trigger_manager,
        │                    l2_trigger_mw, budget_guard, metrics_l2,
        │                    worker, task_queue, l3_setup)
        │
        ▼
    L2Setup 注入 L1 MultiAgentSetup
    （specialist_tools 加 budget_guard / version_dag / bridge 参数）
    （orchestration_middleware 加 l2_trigger_middleware / budget_guard 参数）
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2TriggerMiddleware 拦截（L1 graph after_model）
L1 graph 执行到 after_model
    │
    └─ L2TriggerMiddleware（本文件装配，定义在 trigger_middleware.py）
        │
        ├─ 读 metrics_view 的指标
        ├─ 判断是否满足触发条件（4 源）
        └─ 满足 → trigger_manager.enqueue(...) → task_queue.put(EvolutionTask)

③ 运行期：L2EvolutionWorker 消费
L2EvolutionWorker（daemon 线程）
    │
    ├─ 从 task_queue 取 EvolutionTask
    │
    ├─ ① failure_focuser.analyze(...)           ← 聚类失败
    ├─ ② evolution_mutator.mutate(...)           ← 变异出 candidate
    ├─ ③ promotion_gate.decide(...)              ← 评估 + 晋升决策
    │   └─ 调 bridge.evaluate(ctx)              ← 如果 L3 启用
    │       └─ OrchestrationBridge → adapter → EvalResult
    ├─ ④ version_dag.commit(...)                 ← 记录版本
    └─ ⑤ metrics_l2.record_*(...)               ← 打点 11 种事件

④ 运行期：派活前预算检查
delegate_to_* tool handler
    └─ budget_guard.check_and_record(name, cost)
        ├─ allowed=True → 继续派活
        └─ allowed=False → 返回 BudgetExceeded JSON
```

### 0.3. 补充

**`bootstrap.py`（L2）是 L2 进化层的"装配总入口"——把 DAG / Gate / Mutator / Trigger / Budget / Metrics / Worker 组装成 `L2Setup`，并在 L3 启用时嵌套调用 `setup_l3`。**

几点补充：

- **`enabled=false` 是短路**：直接 `return None`——**L1 行为完全不变**。与 `setup_multiagent` 的 `_EMPTY_SETUP`、`setup_l3` 的 `None` 是同一模式。
- **`metrics_view = metrics_store`**：**直接复用 L1 的 `MultiAgentMetricsStore` 实例**——它同时实现 `MetricsView` Protocol。
- **MVP 阶段全 None**：`EvolutionMutator.llm_caller=None` + `PromotionGate.evaluator=None`——**真正的 LLM / evaluator 要等数据驱动触发后才注入**。
- **`bridge` 是 L2→L3 的连接点**：L3 启用时，`setup_l2` 里**手动构造 `OrchestrationBridge`** 并注入 `PromotionGate`——**这是 L2 与 L3 的唯一连接**。
- **`task_queue` 是 L2 与 L3 共享的**：L2 的 `TriggerManager` 往里写，L3 的 `trigger_l2_evolution_if_degraded` 也往里写——**两个触发源汇到同一个队列**。
- **L3 是 L2 的"嵌套子层"**：`setup_l3` 在 `setup_l2` 内部被调用——**不是平级，是嵌套**。
- **`worker` 是"构造但不启动"**：代码里只 `L2EvolutionWorker(...)` 构造——**启动可能在 `bootstrap_runtime` 或 `AppRuntime` 里**。
- **`_build_budget_limits` 是配置转换**：从 `BudgetConfig`（配置层）转成 `BudgetLimit` dict（运行时用）——**两个不同的类，字段相似**。
- **三层 setup 的嵌套关系**：

```
setup_multiagent（最顶层）
    └─ setup_l2（嵌套在 multiagent 后）
        └─ setup_l3（嵌套在 L2 里）
```

| 维度 | `setup_multiagent` | `setup_l2` | `setup_l3` |
|---|---|---|---|
| 开关 | `config.enabled` | `config.l2.enabled` | `config.l3.enabled` |
| 关闭时 | `_EMPTY_SETUP` | `None` | `None` |
| 产出 | `MultiAgentSetup` | `L2Setup` | `L3Setup` |
| 核心组件 | specialist + metrics + tools | DAG + Gate + Mutator + Worker | Bridge + 3 adapter + Tracker |
