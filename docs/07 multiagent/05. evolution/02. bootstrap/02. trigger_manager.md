---

name: TriggerManager — 四源触发 + 1h 冷却 + per-profile 串行。

description: 

【整体职责】
决定 L2 进化"什么时候触发"：用纯数值判断检查四类触发源（失败聚焦 / specialist 降级 /
metric 阈值 / 周期兜底），命中且不在冷却窗口内时记录触发信息并允许 enqueue
EvolutionTask 到共享队列。

【内容摘要】
- TriggerThresholds(dataclass) : 触发阈值配置（可覆盖默认值）。
- TriggerState(dataclass)      : per-profile 触发状态（冷却 + last_trigger 记录）。
- TriggerManager               : 触发管理主类（should_trigger / _check_sources / enqueue）。

【职责边界】
- 只负责：纯数值判断是否触发、记录触发状态、enqueue 任务。
- 不负责：任务执行（worker 负责）、具体演化逻辑（mutator 负责）、
  周期兜底判定（worker loop 负责）。
- 不持有重状态：只持有 queue / thresholds / states dict + 锁。

## 0. 结构树

### 0.1. 静态结构树

```
trigger_manager.py — TriggerManager（四源触发 + 1h 冷却 + per-profile 串行）
│
├─ 外部 import
│   ├─ MetricsView              ← from evolution/metrics_view.py（读 L1 指标）
│   ├─ EvolutionTask            ← from evolution/types.py
│   ├─ FailureCategory          ← from evolution/types.py
│   └─ TriggerSource            ← from evolution/types.py
│
├─ TriggerThresholds(dataclass)              ← 触发阈值配置
│   ├─ failure_window_seconds: float = 86400.0   ← 失败聚焦统计窗口（24h）
│   ├─ failure_threshold: int = 5                ← 失败聚焦阈值（≥5）
│   ├─ degradation_min_invoked: int = 5          ← 降级最小调用次数
│   ├─ degradation_threshold: float = 0.4        ← 降级 completion_rate 阈值
│   ├─ cost_alert_usd: float = 1.0               ← cost 告警阈值
│   └─ latency_alert_seconds: float = 300.0      ← latency 告警阈值
│
├─ TriggerState(dataclass)                   ← per-profile 触发状态
│   ├─ last_trigger_ts: float = 0.0          ← 上次触发时间戳（冷却用）
│   ├─ last_trigger_source: TriggerSource | None ← 上次触发的 source
│   └─ last_trigger_detail: str = ""          ← 上次触发详情
│
└─ TriggerManager                            ← ★ 触发管理主类
    │   用途：四源检查 + 冷却 + enqueue
    │   should_trigger 纯数值判断（不调 LLM）
    │   per-profile 串行由 daemon 单线程消费保证
    │
    ├─ _queue: queue.Queue[EvolutionTask]     ← 共享任务队列
    ├─ _cooldown_seconds: float = 3600.0      ← 冷却窗口（1h）
    ├─ _cron_interval_seconds: float = 21600.0← 周期兜底间隔（6h）
    ├─ _thresholds: TriggerThresholds        ← 触发阈值
    ├─ _lock: threading.Lock                 ← 保护 states
    ├─ _states: dict[str, TriggerState]      ← per-profile 状态
    ├─ last_trigger_source: TriggerSource | None ← 供 Middleware 读取
    ├─ last_trigger_detail: str              ← 供 Middleware 读取
    │
    ├─ __init__(task_queue, cooldown_seconds, cron_interval_seconds, thresholds)
    │
    ├─ should_trigger(metrics_view, profile="default") -> bool
    │   │   ★ 主入口：纯数值检查
    │   │
    │   ├─ ① 取 state（per-profile）
    │   ├─ ② 冷却检查：now - last_trigger_ts < cooldown_seconds?
    │   │     └─ 是 → return False
    │   ├─ ③ source, detail = _check_sources(metrics_view, now)
    │   ├─ ④ source is None?
    │   │     └─ 是 → return False
    │   ├─ ⑤ 更新 state + self.last_trigger_*
    │   └─ ⑥ return True
    │
    ├─ _check_sources(metrics_view, now) -> tuple[TriggerSource | None, str]
    │   │   ★ 四源检查（顺序固定）
    │   │
    │   ├─ ① 失败聚焦（24h 窗口）
    │   │     └─ get_failure_categories(since)
    │   │         ├─ 跳过 GOAL_UNCLEAR / SANDBOX_ISSUE（不可演化）
    │   │         └─ count >= failure_threshold → FAILURE_FOCUSED
    │   │
    │   ├─ ② specialist 降级
    │   │     └─ 遍历 list_specialists()
    │   │         ├─ get_specialist_metrics(name, since)
    │   │         └─ invoked >= 5 且 rate < 0.4 → SPECIALIST_DEGRADED
    │   │
    │   ├─ ③ metric 阈值
    │   │     └─ get_global_metrics(since)
    │   │         ├─ total_cost_usd > $1 → COST_ALERT
    │   │         └─ avg_latency > 5min → LATENCY_ALERT
    │   │
    │   └─ ④ 周期兜底（不由本方法判定）
    │         └─ 由 worker loop time.sleep 兜底
    │
    └─ enqueue(task) -> None
        │   用途：把 EvolutionTask 放入共享队列
        └─ self._queue.put(task)
```

### 0.2. 运行时调用树

```
① 装配期（L2 启用时）
setup_l2（evolution/bootstrap.py）
    │
    ├─ task_queue = queue.Queue()
    ├─ thresholds = TriggerThresholds(
    │     failure_window_seconds=config.l2.failure_window_hours * 3600,
    │     failure_threshold=config.l2.failure_threshold,
    │     degradation_min_invoked=config.l2.degradation_min_invoked,
    │     degradation_threshold=config.l2.degradation_threshold,
    │     cost_alert_usd=config.l2.cost_alert_usd,
    │     latency_alert_seconds=config.l2.latency_alert_seconds,
    │   )
    │
    └─ trigger_manager = TriggerManager(
           task_queue=task_queue,
           cooldown_seconds=config.l2.cooldown_seconds,
           cron_interval_seconds=config.l2.cron_interval_hours * 3600,
           thresholds=thresholds,
       )
       │
       └─ 注入 L2TriggerMiddleware + L2EvolutionWorker
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2TriggerMiddleware 拦截（L1 graph after_model）
L1 graph 执行到 after_model
    │
    └─ L2TriggerMiddleware
        │
        ├─ ① trigger_manager.should_trigger(metrics_view, profile)   ← 本文件
        │   │
        │   ├─ ① 取 state（per-profile）
        │   ├─ ② 冷却检查
        │   │     ├─ 未过期 → False（跳过）
        │   │     └─ 过期 → 继续
        │   ├─ ③ _check_sources（四源顺序）
        │   │     ├─ ① 失败聚焦
        │   │     │   └─ get_failure_categories(since=24h_ago)
        │   │     │       └─ 命中 → ("failure_focused", detail)
        │   │     ├─ ② specialist 降级
        │   │     │   └─ list_specialists() + get_specialist_metrics
        │   │     │       └─ 命中 → ("specialist_degraded", detail)
        │   │     ├─ ③ metric 阈值
        │   │     │   └─ get_global_metrics(since)
        │   │     │       ├─ cost > $1 → ("cost_alert", detail)
        │   │     │       └─ latency > 5min → ("latency_alert", detail)
        │   │     └─ ④ 周期兜底不在本方法（worker loop 兜底）
        │   ├─ ④ 更新 state + last_trigger_*
        │   └─ ⑤ return True
        │
        ├─ ② 若 should_trigger 返回 True：
        │     ├─ 读 trigger_manager.last_trigger_source / detail
        │     ├─ 构造 EvolutionTask
        │     └─ trigger_manager.enqueue(task)                     ← 本文件
        │         └─ task_queue.put(task)
        │
        └─ ③ 否则跳过

③ 运行期：L2EvolutionWorker 消费
L2EvolutionWorker（daemon 线程）
    │
    ├─ 从 task_queue 取 EvolutionTask
    │   ├─ 事件驱动：由 L2TriggerMiddleware enqueue 的任务
    │   └─ 周期兜底：worker loop 每 6h 主动 enqueue
    │
    └─ 执行演化（focuser → mutator → gate → version_dag）
```

### 0.3. 补充

**`trigger_manager.py` 是 L2 的"触发决策者"——用纯数值判断检查四类触发源，命中且不在冷却窗口内时记录触发信息，供 Middleware 构造 EvolutionTask。**

几点补充：

- **`should_trigger` 是纯数值判断**：**不调 LLM**——这是"便宜的事常做"原则的体现。**触发判定很轻**。
- **四源检查有固定顺序**：失败聚焦 → specialist 降级 → metric 告警 → 周期兜底。**按优先级短路返回**。
- **1h 冷却防抖**：每个 profile 独立冷却——**避免同一问题反复触发**。
- **不可演化类被排除**：`GOAL_UNCLEAR` / `SANDBOX_ISSUE` **不触发失败聚焦**——因为这两类不是模板能解决的（与 `FailureCategory` 的"可演化/不可演化"区分一致）。
- **周期兜底不在本类**：注释明确说"由 `L2EvolutionWorker` worker loop 兜底"——**TriggerManager 只管事件驱动，周期兜底归 worker**。
- **`last_trigger_source` / `last_trigger_detail` 是"跨对象传递"**：注释说"供 `L2TriggerMiddleware._enqueue_evolution_task` 读取"——**Middleware 调 `should_trigger` 后，从这两个属性拿触发信息来构造 `EvolutionTask`**。
- **per-profile 串行由"单线程消费"保证**：注释说"daemon thread 单线程消费 queue，不加额外锁"——**不用锁，靠"只有一个人消费"来串行**。
- **`_check_sources` 返回 tuple**：`(source, detail)`——**source=None 表示无触发**，detail 是给人看的描述（写进 `EvolutionTask.trigger_detail`）。
- **阈值可配置**：`TriggerThresholds` 的默认值可被 `L2Config` 覆盖——**配置层与运行时分离**。
- **和 `setup_l2` 的字段对应**：

| TriggerThresholds 字段 | L2Config 字段 | 默认值 |
|---|---|---|
| `failure_window_seconds` | `failure_window_hours * 3600` | 24h |
| `failure_threshold` | `failure_threshold` | 5 |
| `degradation_min_invoked` | `degradation_min_invoked` | 5 |
| `degradation_threshold` | `degradation_threshold` | 0.4 |
| `cost_alert_usd` | `cost_alert_usd` | 1.0 |
| `latency_alert_seconds` | `latency_alert_seconds` | 300.0 |

**装配时从 `L2Config` 构造 `TriggerThresholds`**——两个结构相似但不同类（配置层 vs 运行时层）。

- **`TriggerState` 是 per-profile 的**：`_states: dict[str, TriggerState]`——**每个 profile 有自己的冷却计时**。不同 profile 互不干扰。
- **`should_trigger` 有副作用**：命中后会更新 `state.last_trigger_ts`——**这实现了"冷却窗口"**。连续调用时，第一次命中后 1h 内不会再次命中。
