---

name: L2 db schema management — 6 张表 + PRAGMA user_version v1→v2。

description: 

【整体职责】
管理 L2 进化层所需的 SQLite schema：创建 6 张表（evolution_artifacts /
evolution_experiments / l2_metrics / specialist_budget_usage / budget_warnings /
l2_blocked_patterns），并把 PRAGMA user_version 从 v1（L1）升级到 v2（L2）。
与 L1 共用同一个 metrics 数据库（不同表），不破坏已有表。

【内容摘要】
- _L2_SCHEMA_SQL / _L2_SCHEMA_VERSION : 建表 SQL（6 表 + 索引）+ schema 版本号。
- L2SchemaManager                     : schema 管理主类（__init__ 幂等建表）。
- schema_version (property)           : 暴露当前 schema 版本号。

【职责边界】
- 只负责：L2 六张表的建表、版本号升级、幂等性保证。
- 不负责：表的读写（各业务模块负责）、L1/L3 表的建表（各自负责）。
- 不持有运行时状态：只持有 db_path + 锁。

    │   └─ ④ commit
    │
    └─ schema_version (property) -> int
        └─ 固定返回 _L2_SCHEMA_VERSION = 2

### 0.2. 运行时调用树

```
① 装配期（L2 启用时）
bootstrap_runtime / setup_l2
    │
    └─ L2SchemaManager(db_path=".poirot/multiagent.db")
        │
        ├─ ① Path(db_path).parent.mkdir(parents=True, exist_ok=True)
        │     └─ 建 .poirot/ 目录（若不存在）
        │
        └─ ② _init_schema()
            ├─ 加锁
            ├─ conn = _connect()（WAL + busy_timeout）
            ├─ version = PRAGMA user_version
            │   ├─ 新库 → 0
            │   ├─ L1 已用 → 1
            │   ├─ L2 已升过 → 2
            │   └─ L3 已升过 → 3
            ├─ executescript(_L2_SCHEMA_SQL)
            │   └─ CREATE TABLE IF NOT EXISTS ...（幂等）
            ├─ version < 2 → PRAGMA user_version = 2
            ├─ conn.commit()
            └─ conn.close()
        ═══════════ L2 装配完成 ═══════════

② 运行期（L2 各组件读写）
L2 的读写不经过本类——由各业务模块负责：
    ├─ evolution_mutator  → 写 evolution_artifacts（新 candidate）
    ├─ promotion_gate     → 读/写 evolution_artifacts + evolution_experiments
    ├─ budget_guard       → 读/写 specialist_budget_usage + budget_warnings
    ├─ trigger_manager    → 写 l2_metrics（事件）
    └─ version_dag        → 读 evolution_artifacts（版本谱系）

③ 重复装配（幂等）
下次启动再次 L2SchemaManager(...)
    └─ _init_schema()
        ├─ version = 2
        ├─ executescript（CREATE IF NOT EXISTS → 什么都不做）
        └─ version < 2 为 False → 不更新 user_version
```

### 0.3. 补充

**`db.py`（L2）是 L2 的"建表员"——只负责创建 6 张 L2 表 + 升级 schema 版本号；读写由各业务模块负责。**

几点补充：

- **6 张表分四类**：
  - **演化产物**：`evolution_artifacts`（版本化产物主表）
  - **实验与指标**：`evolution_experiments`（每次演化记录）+ `l2_metrics`（事件）
  - **预算**：`specialist_budget_usage`（用量）+ `budget_warnings`（告警）
  - **防环**：`l2_blocked_patterns`（被阻断的 pattern）
- **`evolution_artifacts` 是核心表**：它记录每次演化的"版本"——`artifact_type`（类别）+ `template_id`（模板）+ `version`（版本号）三字段唯一。**`is_active=1` 表示当前活跃版本**（晋升后切换）。
- **`evolution_experiments` 记录"演化实验"**：每次演化都写一条——`from_artifact_id`（父版本）+ `trigger_source`（触发原因）+ `eval_result_json`（评估结果）+ `decision`（决策）。**这是版本 DAG 的数据来源。**
- **`l2_metrics` 复用给 L3**：注释说 "event_type 加 l3_ 前缀" —— **L3 的事件也写这张表**，不新建。
- **`specialist_budget_usage` 按天记账**：`PRIMARY KEY (specialist_name, date)` —— 每个 specialist 每天一行。**per-day UTC 0 点重置**。
- **`l2_blocked_patterns` 是防环机制**：记录"被阻断的变异 pattern"——如果某个 pattern 反复导致失败，就 block 它，`auto_release_at` 到期后自动释放。
- **版本号是"阶梯"**：L1 = 1，L2 = 2，L3 = 3。**每个 SchemaManager 只推一档**，不越级、不降级。
- **和 L1 / L3 SchemaManager 的对照**：

| 维度 | L1（metrics.py） | L2SchemaManager | L3SchemaManager |
|---|---|---|---|
| 表数 | 多张 | 6 张 | 2 张 |
| 版本号 | 初始 1 | v1 → v2 | v2 → v3 |
| DB 文件 | `.poirot/multiagent.db` | 同一个 | 同一个 |
| 职责 | 打点 / 查询 / 建表 | 只建 L2 表 + 升版本 | 只建 L3 表 + 升版本 |
