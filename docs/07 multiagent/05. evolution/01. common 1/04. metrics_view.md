---

name: MetricsView Protocol — L2 读 L1 metrics 接口。

description: 

【整体职责】
定义 L2（以及 L3）读取 L1 指标的统一契约：5 个方法覆盖 specialist 聚合指标、
全局聚合指标、失败分类统计、最近失败记录、specialist 列表。
L2/L3 只依赖此 Protocol，不直接耦合 L1 的 MultiAgentMetricsStore 实现类。

【内容摘要】
- SpecialistMetricsSnapshot(TypedDict) : 单 specialist 聚合快照。
- GlobalMetricsSnapshot(TypedDict)     : 全局聚合快照。
- MetricsView(Protocol, runtime_checkable) : 读 L1 指标契约（5 方法）。

【职责边界】
- 只负责：定义读取契约（方法签名 + 语义）。
- 不负责：指标的实际读写（L1 MultiAgentMetricsStore 负责）、
  指标的消费决策（L2 FailureFocuser / L3 RuntimeTracker 负责）。
- 不持有状态：Protocol 无实现，纯接口。

## 0. 结构树

### 0.1. 静态结构树

```
metrics_view.py — MetricsView Protocol（L2 读 L1 metrics 接口）
│
├─ 外部 import
│   ├─ FailureCategory        ← from evolution/types.py（本包内）
│   └─ FailureRecord          ← from evolution/types.py（本包内）
│
├─ SpecialistMetricsSnapshot(TypedDict)      ← 单 specialist 聚合快照
│   │   用途：get_specialist_metrics 的返回类型
│   ├─ specialist_name: str
│   ├─ total_selections: int                 ← 4 计数器之一
│   ├─ total_invoked: int
│   ├─ total_completions: int
│   ├─ total_fallbacks: int
│   ├─ completion_rate: float                ← completions / invoked（0 除保护）
│   ├─ avg_cost_usd: float                   ← JOIN specialist_judgments
│   ├─ avg_latency_seconds: float            ← JOIN specialist_judgments
│   └─ sample_size: int                      ← 样本数（< 20 可信度低）
│
├─ GlobalMetricsSnapshot(TypedDict)          ← 全局聚合快照
│   │   用途：get_global_metrics 的返回类型
│   ├─ total_calls: int
│   ├─ total_cost_usd: float
│   ├─ avg_latency_seconds: float
│   ├─ total_selections: int
│   ├─ total_completions: int
│   └─ total_fallbacks: int
│
└─ MetricsView(Protocol, runtime_checkable)  ← ★ L2 读 L1 指标的统一契约
    │   用途：L2/L3 只依赖此 Protocol，不 import MultiAgentMetricsStore
    │   实现方：L1 MultiAgentMetricsStore（5 个方法）
    │
    ├─ get_specialist_metrics(name, *, since=None) -> SpecialistMetricsSnapshot | None
    │   │   用途：单 specialist 聚合快照
    │   └─ None 表示 specialist 不存在 / 无记录
    │
    ├─ get_global_metrics(*, since=None) -> GlobalMetricsSnapshot
    │   │   用途：全局聚合快照（跨所有 specialist）
    │   └─ 消费方：报表 / 全局健康判断
    │
    ├─ get_failure_categories(*, since=None) -> dict[FailureCategory, int]
    │   │   用途：失败分类统计
    │   └─ 消费方：FailureFocuser（判定 dominant_category）
    │
    ├─ get_recent_failures(*, category, limit=10) -> list[FailureRecord]
    │   │   用途：最近 N 条某类失败记录
    │   └─ 消费方：FailureFocuser（取 top 样本）
    │
    └─ list_specialists() -> list[str]
        │   用途：所有有记录的 specialist 名列表
        └─ 消费方：candidate metadata 生成 / RuntimeTracker
```

### 0.2. 运行时调用树

```
① 装配期
setup_l2 / setup_l3
    │
    ├─ metrics_store = MultiAgentMetricsStore(...)   ← L1 实现，满足 MetricsView
    │
    ├─ L2 组件注入 metrics_store：
    │   ├─ FailureFocuser(metrics_view=metrics_store)
    │   ├─ TriggerManager(metrics_view=metrics_store)
    │   └─ IntentEngineStrengthened(metrics_view=metrics_store)
    │
    └─ L3 组件注入 metrics_store：
        └─ SpecialistRuntimeTracker(metrics_view=metrics_store)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2 消费（FailureFocuser 举例）
FailureFocuser.analyze(...)
    │
    ├─ ① metrics_view.get_failure_categories(since=...)
    │   │   用途：拿到各失败分类的计数
    │   └─ 实现：SELECT failure_category, COUNT(*) FROM specialist_judgments
    │            GROUP BY failure_category
    │
    ├─ ② 判定 dominant_category（占比最高且可演化的）
    │
    ├─ ③ metrics_view.get_recent_failures(category=..., limit=...)
    │   │   用途：拿该类最近的失败记录
    │   └─ 实现：SELECT ... FROM specialist_judgments
    │            WHERE failure_category=? ORDER BY ts DESC LIMIT ?
    │
    └─ ④ 构造 FailureStats（by_category / dominant_category / sample_failures）

③ 运行期：L2 消费（TriggerManager 举例）
TriggerManager
    └─ metrics_view.get_specialist_metrics(name)
        │   用途：看 specialist 的 completion_rate / invoked
        └─ 判定：invoked >= 5 且 completion_rate < 0.4 → SPECIALIST_DEGRADED 触发

④ 运行期：L3 消费（RuntimeTracker 举例）
SpecialistRuntimeTracker.degraded_specialists(threshold)
    │
    ├─ ① metrics_view.list_specialists()
    │   │   用途：拿到所有 specialist 名
    │   └─ 实现：SELECT specialist_name FROM specialist_records
    │
    └─ ② 对每个 name：metrics_view.get_specialist_metrics(name)
        └─ 判定：total_invoked >= 5 且 completion_rate < threshold
```

### 0.3. 补充

**`metrics_view.py` 是 L2/L3 读 L1 指标的"统一读契约"——5 个方法覆盖 specialist 聚合、全局聚合、失败分类、最近失败、specialist 列表。**

几点补充：

- **它是"读接口"，不是"写接口"**：5 个方法全是 `get_*` / `list_*`——**写入由 L1 的 `record_*` 方法负责**（不在本 Protocol 里）。
- **L2 和 L3 都依赖它**：不只是 L2——`runtime_tracker.py`（L3）也用 `get_specialist_metrics` / `list_specialists`。**这是跨层共享的读契约。**
- **实现方是 L1 `MultiAgentMetricsStore`**：它已经在 `metrics.py` 里实现了这 5 个方法——**Protocol 和实现分离**。
- **`since` 参数语义统一**：None = 全量，非 None = 时间窗口起点。**除了 `list_specialists`，其余 4 个都支持**。
- **`avg_cost_usd` / `avg_latency_seconds` 来自 JOIN**：注释说"JOIN specialist_judgments 表算 avg"——**这两个指标不是 4 计数器能算出来的**，需要查明细表。
- **`sample_size` 是"可信度"指标**：< 20 时 LLM 可判断"数据不足"——**这是给 L2 IntentEngine 或 L3 LLM judge 用的**。
- **两个 TypedDict 而非 dataclass**：`SpecialistMetricsSnapshot` / `GlobalMetricsSnapshot` 用 TypedDict——**因为它们只是"字典的形状"，不需要方法**。
- **容易混淆的点**：

| 名字 | 位置 | 类型 | 用途 |
|---|---|---|---|
| `SpecialistMetricsSnapshot` | `evolution/metrics_view.py` | TypedDict | 读接口返回的字典 |
| `SpecialistMetrics` | `multiagent/metrics.py` | frozen dataclass | L1 内部聚合对象 |
| `GlobalMetricsSnapshot` | `evolution/metrics_view.py` | TypedDict | 读接口返回的字典 |
| `SpecialistHealthReport` | `eval/types.py` | frozen dataclass | L3 健康报告（多了 trend / advice） |

**`get_specialist_metrics` 返回的是 TypedDict（字典），不是 dataclass**——`RuntimeTracker.health_report` 再把字典转成 `SpecialistHealthReport` dataclass。
- **5 个方法的消费方**：

| 方法 | 消费方 |
|---|---|
| `get_specialist_metrics` | TriggerManager / RuntimeTracker / IntentEngine |
| `get_global_metrics` | 报表 / 全局健康判断 |
| `get_failure_categories` | FailureFocuser |
| `get_recent_failures` | FailureFocuser |
| `list_specialists` | RuntimeTracker / IntentEngine |
