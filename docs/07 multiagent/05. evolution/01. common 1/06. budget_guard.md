---

name: BudgetGuard — per-specialist budget 三维度记账 + per-day UTC 0 重置 + 超限 fallback lead。

description: 

【整体职责】
为每个 specialist 做每日预算的记账与超限检查：三维度（tokens / cost_usd / calls）
累加当日用量，超限时返回 allowed=False 并指定 fallback 目标为 lead；
80% 用量时写预警记录。全部持久化到 multiagent.db。

【内容摘要】
- _BUDGET_SCHEMA_SQL           : 两张表建表 SQL（specialist_budget_usage / budget_warnings）。
- BudgetLimit(frozen)          : per-specialist 单日预算上限。
- _utc_date_str()              : UTC 日期字符串（per-day 重置 key）。
- BudgetGuard                  : 记账主类（check_and_record / get_today_usage / fallback_target / get_warnings）。

【职责边界】
- 只负责：三维度记账、超限检查、80% 预警写库、按天查询。
- 不负责：成本计算（CostRecord 由调用方构造）、主动通知 LLM（不推送，只写库）、
  在 system prompt 中注入（通过 tool 返 JSON 通知）。
- 不持有运行时状态：只持有 db_path / limits / warning_threshold + 锁。

## 0. 结构树

### 0.1. 静态结构树

```
budget_guard.py — BudgetGuard（per-specialist budget 三维度记账 + per-day 重置 + 超限 fallback lead）
│
├─ 外部 import
│   ├─ utc_now_iso            ← from journal/events.py
│   └─ BudgetCheckResult / BudgetRemaining / CostRecord
│                              ← from evolution/types.py
│
├─ 常量
│   └─ _BUDGET_SCHEMA_SQL                     ← budget 两张表建表 SQL（幂等）
│       ├─ specialist_budget_usage            ← 每日用量表
│       │   ├─ specialist_name TEXT NOT NULL
│       │   ├─ date TEXT NOT NULL
│       │   ├─ tokens_used INTEGER DEFAULT 0
│       │   ├─ cost_usd_used REAL DEFAULT 0.0
│       │   ├─ calls_used INTEGER DEFAULT 0
│       │   ├─ last_updated TEXT NOT NULL
│       │   └─ PRIMARY KEY (specialist_name, date)
│       └─ budget_warnings                    ← 预警记录表
│           ├─ warning_id TEXT PRIMARY KEY
│           ├─ specialist_name TEXT NOT NULL
│           ├─ date TEXT NOT NULL
│           ├─ warning_type TEXT NOT NULL
│           ├─ detail TEXT
│           ├─ timestamp TEXT NOT NULL
│           └─ idx_budget_warnings_name_date
│
├─ BudgetLimit(frozen)                        ← per-specialist 单日预算上限
│   ├─ per_day_tokens: int = 200000           ← 每日 token 上限
│   ├─ per_day_cost_usd: float = 20.0         ← 每日成本上限（美元）
│   └─ per_day_calls: int = 50                ← 每日调用次数上限
│
├─ _utc_date_str() -> str                     ← UTC 日期字符串（per-day 重置 key）
│   └─ datetime.now(timezone.utc).strftime("%Y-%m-%d")
│
└─ BudgetGuard                               ← ★ 记账主类
    │   用途：三维度记账 + 超限检查 + 80% 预警
    │   三维度：tokens / cost_usd / calls；cost_usd 为主触发
    │   per-day UTC 0 点重置；超限 fallback 到 lead
    │
    ├─ _db_path: str = ".poirot/multiagent.db"
    ├─ _limits: dict[str, BudgetLimit]       ← per-specialist 上限
    ├─ _warning_threshold: float = 0.8        ← 预警阈值
    ├─ _lock: threading.Lock
    │
    ├─ __init__(db_path, limits, warning_threshold)
    │   ├─ 建父目录
    │   └─ _init_schema()
    │
    ├─ _connect() -> sqlite3.Connection
    │   ├─ PRAGMA journal_mode=WAL
    │   └─ PRAGMA busy_timeout=30000
    │
    ├─ _init_schema() -> None
    │   └─ executescript(_BUDGET_SCHEMA_SQL)（幂等）
    │
    ├─ _get_limit(specialist_name) -> BudgetLimit
    │   └─ _limits.get(name, BudgetLimit())  ← 无配置用默认
    │
    ├─ check_and_record(specialist_name, cost) -> BudgetCheckResult
    │   │   ★ 核心方法：检查 + 记录合一
    │   │
    │   ├─ ① 读当日已用量（无记录 → 0）
    │   ├─ ② 累加本次用量（new_*）
    │   ├─ ③ UPSERT 写回 specialist_budget_usage
    │   ├─ ④ 检查超限（优先级 cost_usd > tokens > calls）
    │   │     ├─ new_cost > limit  → "daily_cost_exceeded"
    │   │     ├─ new_tokens > limit → "daily_tokens_exceeded"
    │   │     └─ new_calls > limit  → "daily_calls_exceeded"
    │   ├─ ⑤ 80% 预警判断（old_pct < 0.8 <= new_pct 且未超限）
    │   │     └─ INSERT INTO budget_warnings（只写库，不推送）
    │   └─ ⑥ 返回 BudgetCheckResult
    │         ├─ allowed=False → reason + remaining + fallback_target="lead"
    │         └─ allowed=True  → reason=None + remaining + fallback_target="lead"
    │
    ├─ get_today_usage(specialist_name) -> dict
    │   │   用途：查当日用量（per-day UTC 0 点重置）
    │   └─ 无记录 → {"tokens_used": 0, "cost_usd_used": 0.0, "calls_used": 0}
    │
    ├─ fallback_target(specialist_name) -> str
    │   └─ 固定返回 "lead"（不 fallback 另一 specialist）
    │
    └─ get_warnings(specialist_name, date_str=None) -> list[dict]
        │   用途：查 80% 预警记录（CLI inspect，无推送）
        └─ date_str=None → 当天
```

### 0.2. 运行时调用树

```
① 装配期（L2 启用时）
setup_l2（evolution/bootstrap.py）
    │
    ├─ limits = {
    │     "codex": BudgetLimit(...),
    │     "claude": BudgetLimit(...),
    │     "subagent": BudgetLimit(...),
    │     "pi": BudgetLimit(...),
    │   }
    │
    └─ budget_guard = BudgetGuard(
           db_path=".poirot/multiagent.db",
           limits=limits,
           warning_threshold=0.8,
       )
       │
       ├─ 建父目录
       └─ _init_schema()（幂等建两张表）
       │
       └─ 注入 L2Setup + tools.py 的 delegate_tool 闭包
       ═══════════ 进入 Agent 循环 ═══════════

② 运行期：派活前预算检查
delegate_to_codex tool handler
    │
    ├─ cost = SimpleNamespace(tokens=0, cost_usd=0.0, calls=1)
    │
    └─ budget_guard.check_and_record("codex", cost)   ← 本文件
        │
        ├─ ① _get_limit("codex") → BudgetLimit
        │
        ├─ ② 读当日用量
        │     SELECT tokens_used, cost_usd_used, calls_used
        │     FROM specialist_budget_usage
        │     WHERE specialist_name='codex' AND date='2026-09-23'
        │
        ├─ ③ 累加：new_tokens / new_cost / new_calls
        │
        ├─ ④ UPSERT 写回 specialist_budget_usage
        │
        ├─ ⑤ 检查超限（cost_usd > tokens > calls）
        │     ├─ 未超限 → reason=None
        │     └─ 超限 → reason="daily_cost_exceeded" 等
        │
        ├─ ⑥ 80% 预警判断
        │     ├─ old_pct < 0.8 <= new_pct 且未超限 → INSERT budget_warnings
        │     └─ 否则跳过
        │
        └─ ⑦ return BudgetCheckResult
            │
            ├─ allowed=False → tool handler 返回 BudgetExceeded JSON
            │   └─ LLM 看到后 fallback 到 lead
            │
            └─ allowed=True → tool handler 继续派活
                ├─ ContextSummarizer → specialist.invoke → ResultSummarizer
                └─ ...

③ 运行期：按需查用量 / 预警
CLI / 运维
    ├─ budget_guard.get_today_usage("codex")
    │   └─ SELECT ... WHERE date=当天
    │
    └─ budget_guard.get_warnings("codex")
        └─ SELECT ... FROM budget_warnings WHERE date=当天

④ 运行期：fallback 目标
tool handler 或外部
    └─ budget_guard.fallback_target("codex") → "lead"（固定）
```

### 0.3. 补充

**`budget_guard.py` 是 L2 的"预算管家"——为每个 specialist 做每日预算的三维度记账、超限检查、80% 预警。**

几点补充：

- **三维度记账**：tokens / cost_usd / calls——**三个维度独立累加、独立检查**。
- **cost_usd 是"主触发"**：超限检查优先级 `cost_usd > tokens > calls`——**成本是最重要的维度**。
- **per-day UTC 0 点重置**：日期 key 用 UTC 日期——**不需要定时任务重置**，只要查当天的 key 就是"今日用量"。
- **超限 fallback 固定 "lead"**：注释说"不 fallback 另一 specialist"——**避免 specialist 之间互相推诿**。
- **通知方式是"tool 返 JSON"**：不污染 system prompt——**LLM 在 ToolMessage 里看到 BudgetExceeded，自己决定下一步**。
- **80% 预警"只写库不推送"**：注释说"不主动通知 LLM"——**预警是给运维看的，不是给 LLM 看的**。
- **预警只在"跨过阈值"时写一次**：`old_pct < 0.8 <= new_pct`——**不会重复写**。
- **`check_and_record` 是"检查 + 记录"合一**：**先记账，再判断**——保证即使超限，用量也被记录。
- **两个表分工**：
  - `specialist_budget_usage`：**用量**（每天每 specialist 一行）
  - `budget_warnings`：**预警**（跨 80% 时写一条）
- **和 `L3Config` / `BudgetConfig` 的关系**：

| 概念 | 位置 | 角色 |
|---|---|---|
| `BudgetConfig` | `multiagent/config.py` | **配置**（codex/claude/subagent/pi 的预算上限） |
| `SpecialistBudgetLimit` | `multiagent/config.py` | **配置字段结构** |
| `BudgetLimit` | 本文件 | **运行时用的数据结构** |
| `BudgetGuard` | 本文件 | **记账 + 检查** |

**装配时从 `BudgetConfig` 的 `SpecialistBudgetLimit` 转到 `BudgetLimit`**——两者字段相似但不同类。

- **`CostRecord` 的 `calls=1` 是默认值**：每次派活算 1 次调用——**所以 `per_day_calls=50` 意味着每天最多派 50 次活**。
- **`warning_id` 带百分比**：`warn_<name>_<date>_<pct>`——**同一阈值只写一次**（如果跨了 80% 和 90% 会写两条）。
