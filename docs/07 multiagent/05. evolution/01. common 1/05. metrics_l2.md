---

name: OrchestrationMetricsL2 — L2 演化过程指标（11 种事件类型）。

description: 

【整体职责】
记录 L2 进化过程的 11 类事件（trigger / evolution_start / mutator_call /
evolution_failed / promotion_decision / eval_executed / eval_failed /
version_rollback / blocked_marked / budget_warning / budget_exceeded），
写入 multiagent.db 的 l2_metrics 表，供 CLI inspect（无主动推送）。

【内容摘要】
- 11 个 EVENT_* 常量 + _ALL_EVENT_TYPES : 事件类型定义。
- _SCHEMA_SQL                           : l2_metrics 表建表 SQL（幂等）。
- OrchestrationMetricsL2                : 指标写入主类（11 个 record_* 方法 + query）。
- query_by_event_type()                 : 按事件类型查询（CLI inspect 用）。
- event_types (property)                : 暴露 11 种事件类型 tuple。

【职责边界】
- 只负责：事件写入 l2_metrics 表、按类型查询。
- 不负责：指标消费决策（L2 各组件负责）、主动推送（无，用户主动 inspect）、
  与 L1 的 specialist call 指标混合（两者独立）。
- 不持有运行时状态：只持有 db_path + 锁。

### 0.2. 运行时调用树

```
① 装配期（L2 启用时）
setup_l2（evolution/bootstrap.py）
    │
    └─ l2_metrics = OrchestrationMetricsL2(db_path=".poirot/multiagent.db")
        │
        ├─ 建父目录
        └─ _init_schema()（幂等建 l2_metrics 表）
        │
        └─ 注入 L2Setup
            ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2 演化流程打点
L2 演化各阶段
    │
    ├─ ① 触发阶段
    │   └─ TriggerManager
    │       └─ l2_metrics.record_trigger(trigger_source, detail, profile)
    │
    ├─ ② 演化开始
    │   └─ Worker / Mutator
    │       └─ l2_metrics.record_evolution_start(experiment_id, type, from_version)
    │
    ├─ ③ 变异 LLM 调用
    │   └─ EvolutionMutator
    │       └─ l2_metrics.record_mutator_call(model, in_tokens, out_tokens, latency, retries)
    │       └─ 失败时：record_evolution_failed(failure_type, ...)
    │
    ├─ ④ 评估执行
    │   └─ Bridge / Adapter
    │       ├─ l2_metrics.record_eval_executed(eval_method, sample_count, ...)
    │       └─ 失败时：record_eval_failed(eval_failure_type, ...)
    │
    ├─ ⑤ 晋升决策
    │   └─ PromotionGate
    │       └─ l2_metrics.record_promotion_decision(decision, c_score, b_score, ci_low, ci_high)
    │
    ├─ ⑥ 回滚 / 阻断
    │   ├─ VersionDAG
    │   │   └─ record_version_rollback(from, to, reason)
    │   └─ BlockedPatternManager
    │       └─ record_blocked_marked(pattern, type, auto_release_at)
    │
    └─ ⑦ 预算
        └─ BudgetGuard
            ├─ record_budget_warning(name, usage_percent, remaining_cost)
            └─ record_budget_exceeded(name, dimension, fallback_target)
    │
    ▼
每次 record_* 都调 _record(event_type, payload)
    ├─ 生成 metric_id
    ├─ 序列化 payload
    ├─ INSERT INTO l2_metrics
    └─ 提交

③ 运行期：CLI inspect（用户主动查）
CLI / 运维
    └─ l2_metrics.query_by_event_type("trigger", limit=50)
        └─ SELECT ... FROM l2_metrics WHERE event_type="trigger"
            ORDER BY timestamp DESC LIMIT 50
        └─ 返回 dict 列表

④ 自描述查询
外部 / CLI
    └─ l2_metrics.event_types
        └─ 返回 11 种事件类型 tuple
```

### 0.3. 补充

**`metrics_l2.py` 是 L2 的"演化过程账本"——记录 11 类事件，写 `l2_metrics` 表，供 CLI inspect。**

几点补充：

- **11 种事件覆盖演化全流程**：
  - 触发阶段：`trigger`
  - 演化阶段：`evolution_start` / `mutator_call` / `evolution_failed`
  - 评估阶段：`eval_executed` / `eval_failed`
  - 决策阶段：`promotion_decision`
  - 回滚 / 阻断：`version_rollback` / `blocked_marked`
  - 预算：`budget_warning` / `budget_exceeded`
- **每种事件有专属 `record_*` 方法**：**封装 payload 结构**——调用方不需要知道 payload 里有哪些字段，只调 `record_trigger(...)` 就行。
- **`_record` 是唯一写入口**：所有 `record_*` 最终调它——**统一 metric_id 生成 + payload 序列化 + 时间戳**。
- **`query_by_event_type` 是唯一查询入口**：CLI inspect 用它——**没有"查全部"的方法**，必须指定 event_type。
- **无主动推送**：注释说 "No active push, user inspects via CLI"——**这是被动的 metrics**，不像日志那样实时打。
- **与 L1 metrics 独立**：L1 记 specialist call，L2 记演化过程——**两张表、两个类、两类事件**。
- **`event_types` 属性暴露全部 11 种**：供 CLI 或外部枚举——**这是"自描述"的接口**。
- **与 `L2SchemaManager` 的分工**：

| 维度 | L2SchemaManager | OrchestrationMetricsL2 |
|---|---|---|
| 职责 | **只建表 + 升版本号** | **打点 + 查询** |
| 表 | 6 张（含 `l2_metrics`） | `l2_metrics`（同一张） |
| 时机 | L2 装配时调一次 | 每次演化事件时写 |
| 幂等 | ✅ | 依赖表已存在 |

**`L2SchemaManager` 建 `l2_metrics` 表；`OrchestrationMetricsL2` 往里写/读。** 两者共用同一张表。

- **`l2_metrics` 表也被 L3 复用**：注释说 "event_type 加 l3_ 前缀可复用给 L3"——**L3 的评估事件也写这张表**，不新建。
