---

name: IntentEngineStrengthened — ContextSummarizer 的输入源（非 middleware）。

description: 

【整体职责】
分层意图识别：用 IntentTreeStrategy（规则匹配，零 LLM）优先，命中则直接返回；
未命中且 LLM 兜底启用时，调 LLMIntentStrategy（MVP 未实现）。
同时提供 get_candidate_metadata 生成 SpecialistCandidate 列表，供 ContextSummarizer
渲染进 context_summary（per-call 产物，不注入 system prompt）。

【内容摘要】
- IntentAnalysis(frozen)       : 意图识别结果（confidence / candidates / intent_type）。
- IntentStrategy(Protocol)     : 意图识别策略契约。
- IntentTreeStrategy           : 薄包装既有 ReportIntentStrategy.match。
- LLMIntentStrategy            : LLM 兜底（MVP 仅接口，未实现）。
- IntentEngineStrengthened     : 分层意图识别主类（analyze + get_candidate_metadata）。

【职责边界】
- 只负责：意图识别、候选 metadata 生成。
- 不负责：上下文渲染（ContextSummarizer 负责）、specialist 执行、
  specialist 选择（LLM 自决）。
- 不持有运行时状态：tree / llm / metrics_view 由构造或方法参数注入。

## 0. 结构树

### 0.1. 静态结构树

```
intent_strengthened.py — IntentEngineStrengthened（ContextSummarizer 的输入源）
│
├─ 外部 import
│   ├─ ReportIntentStrategy       ← from intent/engine.py（既有意图引擎）
│   ├─ MetricsView                ← from evolution/metrics_view.py（读 L1 指标）
│   └─ SpecialistCandidate        ← from evolution/types.py（候选 metadata）
│
├─ IntentAnalysis(frozen)                    ← 意图识别结果
│   ├─ confidence: float                     ← 置信度（>= 0.7 命中）
│   ├─ candidates: list[str]                 ← 候选列表（MVP 恒空）
│   └─ intent_type: str = "unknown"          ← 意图类型
│
├─ IntentStrategy(Protocol)                  ← 意图识别策略契约
│   └─ analyze(user_message, available_specialists) -> IntentAnalysis
│
├─ IntentTreeStrategy                        ← ★ 规则策略（薄包装）
│   │   用途：包装既有 ReportIntentStrategy.match，零 LLM 成本
│   │   不调 detect_and_dispatch（避免 CLI 路由副作用）
│   │
│   ├─ _strategy: ReportIntentStrategy      ← 既有意图引擎
│   ├─ _threshold: float = 0.7              ← 命中阈值
│   │
│   ├─ __init__(confidence_threshold=0.7)
│   │
│   └─ analyze(user_message, available_specialists) -> IntentAnalysis
│       ├─ ① result = self._strategy.match(user_message)
│       ├─ ② result.matched 且 confidence >= threshold?
│       │     ├─ 是 → 返回 IntentAnalysis(confidence, [], intent_type)
│       │     │      （intent_type 从 payload["type"] 取 .value）
│       │     └─ 否 → 返回 IntentAnalysis(0.0, [], "unknown")
│       └─ candidates 始终空（IntentTree 无 specialist 分类能力）
│
├─ LLMIntentStrategy                         ← ★ LLM 兜底（MVP 未实现）
│   │   用途：数据触发后实现（委派率 < 20% 或 ABILITY_INSUFFICIENT > 50%）
│   │
│   └─ analyze(user_message, available_specialists) -> IntentAnalysis
│       └─ raise NotImplementedError（MVP 不实现）
│
└─ IntentEngineStrengthened                  ← ★ 分层意图识别主类
    │   用途：IntentTree 优先 + LLM 兜底 + candidate metadata 生成
    │   作为 ContextSummarizer 输入源，不作为 middleware
    │
    ├─ _tree: IntentTreeStrategy            ← 规则策略（必传）
    ├─ _llm: LLMIntentStrategy | None        ← LLM 兜底（None = 未启用）
    │
    ├─ __init__(tree, llm=None)
    │
    ├─ analyze(user_message, available_specialists) -> IntentAnalysis
    │   │   用途：分层识别（tree 优先 + LLM 兜底 + 失败 fallback）
    │   │
    │   ├─ ① result = self._tree.analyze(...)
    │   ├─ ② result.confidence >= 0.7 或 llm=None?
    │   │     └─ 是 → 直接返回 result
    │   ├─ ③ try: return self._llm.analyze(...)
    │   ├─ ④ except NotImplementedError → fallback result
    │   └─ ⑤ except Exception → fallback result
    │
    └─ get_candidate_metadata(goal, available_specialists, metrics_view) -> list[SpecialistCandidate]
        │   用途：生成候选 metadata（供 ContextSummarizer 渲染）
        │
        ├─ 遍历 available_specialists
        ├─ snap = metrics_view.get_specialist_metrics(name)
        ├─ snap is None → 用默认值（sample_size=0）
        └─ snap 非 None → 用 completion_rate / avg_cost_usd / avg_latency_seconds
```

### 0.2. 运行时调用树

```
① 装配期
setup_l2 或 bootstrap（不在 setup_l2 的 L2Setup 字段里）
    │
    └─ IntentEngineStrengthened(
           tree=IntentTreeStrategy(confidence_threshold=config.l2.intent_confidence_threshold),
           llm=LLMIntentStrategy() if config.l2.intent_llm_enabled else None,
       )
       │
       └─ 注入 ContextSummarizer（per-specialist summarizer）
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：派活前构造 context_summary
delegate_to_codex tool handler
    │
    └─ context_summarizer.summarize(state, goal, success_criteria)
        │
        ├─ ① intent_engine.analyze(user_message, available_specialists)
        │   │
        │   ├─ 先调 tree.analyze（规则匹配，零 LLM）
        │   │   ├─ 命中 → 返回（confidence >= 0.7）
        │   │   └─ 未命中 → 继续
        │   │
        │   ├─ llm=None（MVP）→ 直接返回 tree 结果
        │   │
        │   └─ llm 非 None → 调 llm.analyze
        │       ├─ NotImplementedError → fallback tree
        │       └─ 其他异常 → fallback tree
        │
        ├─ ② intent_engine.get_candidate_metadata(
        │          goal, available_specialists, metrics_view)
        │   │
        │   ├─ 遍历 available_specialists
        │   ├─ metrics_view.get_specialist_metrics(name)
        │   │   ├─ None → SpecialistCandidate(name, 0.0, 0.0, 0.0, 0)
        │   │   └─ 非 None → SpecialistCandidate(name, rate, cost, latency, size)
        │   └─ 返回 candidate 列表
        │
        └─ ③ 把 intent + candidates 渲染进 context_summary
            │   → context_summary 字符串
            │   → 作为 SpecialistRequest.context_summary 传给 specialist
            │
            └─ 注意：不注入 system prompt（per-call 产物）

③ 运行期：LLM 决策（Leader）
Leader LLM
    │
    └─ 看到 context_summary 里的 candidate metadata
        ├─ 每个 specialist 的历史成功率 / 成本 / 延迟
        └─ 据此选择派给谁（soft routing，LLM 自决）
```

### 0.3. 补充

**`intent_strengthened.py` 是 ContextSummarizer 的"意图与候选输入源"——它给 Summarizer 提供意图识别结果与 specialist 候选 metadata，供渲染进 context_summary。**

几点补充：

- **它不是 `EvolutionMutator` 的辅助**：上一轮我从"不在 `setup_l2` 里"推测它可能被 Mutator 用。**实际代码显示它是 `ContextSummarizer` 的输入源**——服务于"派活时的上下文构造"，不是"进化时的变异"。
- **它不注入 system prompt**：注释明确说"作为 ContextSummarizer 输入源，不作为 before_model middleware，不注入 system prompt"——**通过 per-call 的 context_summary 传递**。
- **两个方法各司其职**：
  - `analyze` → **意图识别**（分层：规则 + LLM 兜底）
  - `get_candidate_metadata` → **生成 specialist 候选 metadata**（供 LLM 选择派给谁）
- **分层意图识别**：
  - **第一层 `IntentTreeStrategy`**：包装既有 `ReportIntentStrategy.match`，零 LLM 成本
  - **第二层 `LLMIntentStrategy`**：MVP 未实现，数据触发后才启用
  - **兜底逻辑**：LLM 未实现 / 调用异常 → fallback 到 tree 结果（**不阻塞 turn**）
- **`IntentTreeStrategy` 不调 `detect_and_dispatch`**：注释说"CLI 路由入口返 bool 会触发 report action 副作用"——**只调纯匹配的 `match`**。
- **`get_candidate_metadata` 是"给 LLM 的决策依据"**：它把每个 specialist 的历史成功率 / 成本 / 延迟渲染进 context——**LLM 据此选择派给谁**。这印证了 **soft routing（LLM 自决）**。
- **无记录的 specialist 用默认值**：`sample_size=0`——**LLM 可据此判断"这个 specialist 没历史数据，可信度低"**。
- **MVP 阶段 LLM 兜底未启用**：`intent_llm_enabled=false` → `llm=None` → `analyze` 永远只走 tree 规则。
- **启用 LLM 兜底的数据触发条件**：注释说"委派率 < 20% 或 ABILITY_INSUFFICIENT > 50%"——**这是"规则不够用"的信号**。
- **它在 L2 里的位置**（修正版）：

```
L2 演化层
├── 演化流程（触发 → 聚焦 → 变异 → 评估 → 晋升）
│   ├── trigger_manager / trigger_middleware
│   ├── failure_focuser
│   ├── evolution_mutator
│   ├── promotion_gate
│   └── version_dag
│
├── 上下文增强（服务于派活）
│   └── intent_strengthened.py        ← ★ 这里！不是演化流程的一部分
│       └─ 被 ContextSummarizer 调用
│
└── 周边（budget / metrics / worker / cli）
```

**它不在"演化流程"里，而在"上下文增强"里**——**服务于 Leader 派活时的上下文构造，不是 L2 的进化逻辑**。

**但它是 L2 的组件**——因为它服务的是"specialist 派活"，而 specialist 派活是 multiagent 的核心。**它和 L2 的关系是"配置同源"（`L2Config.intent_*` 字段），不是"流程串联"。**
