---

name: L2TriggerMiddleware — L1 graph after_model 末尾轻量检查。

description: 

【整体职责】
作为 L1 graph 的 after_model 钩子：每次模型调用后，用纯数值判断检查是否
满足 L2 演化触发条件；命中则 enqueue EvolutionTask 到共享队列，由 daemon
线程消费。不修改 ThreadState，延迟 < 1ms。

【内容摘要】
- L2TriggerMiddleware : middleware 主类（after_model / aafter_model）。

【职责边界】
- 只负责：after_model 时委托 TriggerManager 判定、命中则 enqueue。
- 不负责：触发判定逻辑（TriggerManager 负责）、任务执行（worker 负责）、
  ThreadState 修改（返 None，不改）。
- 不持有重状态：只持有 trigger_manager / metrics_view / profile 引用。

## 0. 结构树

### 0.1. 静态结构树

```
trigger_middleware.py — L2TriggerMiddleware（L1 graph after_model 末尾轻量检查）
│
├─ 外部 import
│   ├─ AgentMiddleware        ← from langchain.agents.middleware.types
│   ├─ MetricsView            ← from evolution/metrics_view.py
│   ├─ TriggerManager         ← from evolution/trigger_manager.py
│   ├─ EvolutionTask / TriggerSource ← from evolution/types.py
│   └─ ThreadState            ← from state/types.py
│
└─ L2TriggerMiddleware(AgentMiddleware)      ← ★ middleware 主类
    │   用途：L1 graph after_model 时判定是否触发 L2 演化
    │   委托 TriggerManager，命中则 enqueue EvolutionTask
    │   不改 ThreadState，延迟 < 1ms
    │
    ├─ state_schema = ThreadState            ← 声明 middleware 处理的 state 类型
    │
    ├─ _trigger_manager: TriggerManager      ← 触发管理器（委托判定）
    ├─ _metrics_view: MetricsView            ← 读 L1 指标
    ├─ _profile: str = "default"             ← 演化 profile（per-profile 冷却 key）
    │
    ├─ __init__(trigger_manager, metrics_view, profile="default")
    │
    ├─ after_model(state, runtime) -> dict | None    ← @override 同步入口
    │   │   用途：L1 graph after_model 时轻量检查
    │   │
    │   ├─ ① _should_trigger(state)?
    │   │     └─ 否 → return None（不改 state）
    │   ├─ ② _enqueue_evolution_task(_extract_snapshot_id(state))
    │   └─ ③ return None（始终不改 state）
    │
    ├─ aafter_model(state, runtime) -> dict | None   ← @override 异步入口
    │   └─ 委托 self.after_model（纯数值无阻塞 IO）
    │
    ├─ _should_trigger(state) -> bool
    │   │   用途：委托 TriggerManager.should_trigger
    │   │   （命中时 TriggerManager 会更新 last_trigger_source/detail）
    │   └─ trigger_manager.should_trigger(metrics_view, profile)
    │
    ├─ _extract_snapshot_id(state) -> str
    │   │   用途：从 state 提取快照 ID（用作 task_id）
    │   ├─ state.metadata.snapshot_id
    │   ├─ state.metadata.thread_id
    │   └─ 都无 → ""
    │
    └─ _enqueue_evolution_task(snapshot_id) -> None
        │   用途：构造 EvolutionTask 并 enqueue
        │
        ├─ ① trigger_source = trigger_manager.last_trigger_source
        │     └─ None → TriggerSource.PERIODIC（兜底）
        ├─ ② task_id = snapshot_id or f"l2_{int(time.time())}"
        ├─ ③ 构造 EvolutionTask(
        │       task_id, profile,
        │       trigger_source,
        │       trigger_detail=trigger_manager.last_trigger_detail,
        │       timestamp=str(int(time.time())),
        │   )
        └─ ④ trigger_manager.enqueue(task) → task_queue.put(...)
```

### 0.3. 补充

**`trigger_middleware.py` 是 L1 与 L2 的"触发桥"——在 L1 graph 的 after_model 钩子里判断是否触发 L2 演化，命中则 enqueue 任务。**

几点补充：

- **`after_model` 不改 state**：始终返回 `None`——**这是 middleware 的"只读观察者"定位**。L2 触发不影响 L1 的执行流。
- **延迟 < 1ms**：`should_trigger` 是纯数值判断（读几个指标 + 比较）——**很快**，不阻塞 L1 turn。
- **`aafter_model` 委托同步**：注释说"L2 触发是纯数值，无阻塞 IO"——**不需要真正的异步实现**。
- **`_should_trigger` 有副作用**：它调 `trigger_manager.should_trigger`——**后者命中时会更新 `last_trigger_source` / `last_trigger_detail`**。所以 `_enqueue_evolution_task` 能从这两个属性读到触发信息。
- **`task_id` 是"快照 ID"**：从 `state.metadata.snapshot_id` 或 `thread_id` 提取——**用于追踪"哪个 thread / 快照触发了演化"**。空则用时间戳兜底。
- **`trigger_source` 兜底为 PERIODIC**：如果 `last_trigger_source` 是 `None`（理论上不应该，因为 `should_trigger` 返回 True 时必然设了），用 `PERIODIC` 兜底——**防御式编程**。
- **`timestamp` 用字符串**：`str(int(time.time()))`——**Unix 时间戳的字符串形式**，而不是 `utc_now_iso()`。**这是一个小的不一致点**（其他组件用 ISO 格式）。
- **`profile` 默认 "default"**：构造时注入——**不同 profile 有独立的冷却窗口**。
- **它在 L1/L2 交界处的位置**：

```
L1 graph 执行
    │
    ├─ model 节点（LLM 调用）
    │
    └─ after_model 钩子链
        ├─ ...
        ├─ L2TriggerMiddleware.after_model    ← ★ 本文件
        │   │   用途：判断是否触发 L2 演化
        │   │
        │   ├─ ① TriggerManager.should_trigger（纯数值）
        │   │     ├─ 冷却检查（1h）
        │   │     └─ 四源检查（失败聚焦 / 降级 / metric / 周期）
        │   │
        │   ├─ ② 命中 → _extract_snapshot_id(state)
        │   ├─ ③ 构造 EvolutionTask
        │   └─ ④ trigger_manager.enqueue(task) → task_queue
        │
        └─ ...
    │
    ▼
L1 graph 继续（tools 节点 / 下一轮 model）
```

**L2 的 daemon 线程（L2EvolutionWorker）从 `task_queue` 消费——`after_model` 只负责"塞任务"，不负责"跑任务"。**

- **和 `TriggerManager` / `Worker` 的关系**：

| 组件 | 角色 | 交互 |
|---|---|---|
| **L2TriggerMiddleware** | **L1 graph 钩子** | **调 `should_trigger` + `enqueue`** |
| TriggerManager | 触发判定 + 队列 | 被 Middleware 调 |
| L2EvolutionWorker | daemon 消费 | 从 queue 取任务 |

**Middleware 是"触发端"，Worker 是"消费端"**——两者通过 `task_queue` 连接。
