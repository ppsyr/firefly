---

name: L3 SpecialistRuntimeTracker — specialist 健康监控 + 趋势判定 + degraded 检测。

description: 

【整体职责】
读 L1 的指标聚合（通过 L2 MetricsView Protocol），算出 specialist 的健康报告
（completion_rate / cost / latency / fallback / trend），并检测哪些 specialist
已 degraded；degraded 命中时把消息 enqueue 到 L2 cron queue，由 L2 消费触发进化。

【内容摘要】
- _MIN_JUDGMENTS_FOR_TREND / _DEGRADATION_DELTA : 趋势判定最小样本量 + 退化阈值常量。
- SpecialistRuntimeTracker                      : 健康监控主类。
- health_report()                               : 生成单个 specialist 的健康报告。
- degraded_specialists()                        : 列出已 degraded 的 specialist。
- trigger_l2_evolution_if_degraded()            : degraded 命中 → enqueue L2 cron queue。

【职责边界】
- 只负责：读指标、算健康报告、判定 degraded、enqueue 触发消息。
- 不负责：指标存储（L1 metrics 负责）、进化执行（L2 负责）、
  lesson 读写（decision_log 负责）。
- 不持有运行时状态：metrics_view 由构造注入。

## 0. 结构树

### 0.1. 静态结构树

```
runtime_tracker.py — L3 SpecialistRuntimeTracker（specialist 健康监控 + 趋势判定 + degraded 检测）
│
├─ 外部 import
│   ├─ SpecialistHealthReport   ← from eval/types.py（L3 自建类型）
│   └─ MetricsView              ← from evolution/metrics_view.py（L2 Protocol，复用）
│
├─ 常量
│   ├─ _MIN_JUDGMENTS_FOR_TREND = 4   ← 趋势判定所需最小样本量
│   └─ _DEGRADATION_DELTA = 0.15      ← 退化判定默认阈值（与 skill 同构）
│
├─ SpecialistRuntimeTracker                  ← ★ 健康监控主类
│   │   用途：读 L1 指标 → 算健康报告 → 检测 degraded
│   │   自建（不复用 skill RuntimeTracker——字段不兼容）
│   │   复用 L2 MetricsView Protocol 读指标
│   │
│   ├─ _metrics: MetricsView              ← L2 MetricsView Protocol 实现
│   ├─ _degradation_delta: float           ← 退化阈值（构造注入，默认 0.15）
│   │
│   ├─ __init__(metrics_view, degradation_delta)
│   │
│   ├─ health_report(specialist_name, window=20) -> SpecialistHealthReport | None
│   │   │   用途：生成单个 specialist 的健康报告
│   │   ├─ ① snapshot = metrics.get_specialist_metrics(name)
│   │   │     └─ None → return None（specialist 不存在 / 无记录）
│   │   ├─ ② trend 判定（MVP）：
│   │   │     ├─ sample_size < 4 → "insufficient_data"
│   │   │     └─ 否则 → "stable"
│   │   ├─ ③ fallback_rate = total_fallbacks / total_invoked（invoked=0 → 0.0）
│   │   └─ ④ 构造 SpecialistHealthReport
│   │
│   └─ degraded_specialists(threshold=0.4) -> list[str]
│       │   用途：列出已 degraded 的 specialist
│       ├─ 遍历 metrics.list_specialists()
│       ├─ 判定：total_invoked >= 5 且 completion_rate < threshold
│       └─ 累积 degraded 名列表
│
└─ trigger_l2_evolution_if_degraded(tracker, cron_queue, threshold=0.4) -> list[str]
    │   用途：degraded 命中 → enqueue L2 cron queue（解耦，不直接调 L2 TriggerManager）
    │
    ├─ ① degraded = tracker.degraded_specialists(threshold)
    ├─ ② for name in degraded: cron_queue.put(("specialist_degraded", name))
    └─ ③ return degraded
```

### 0.3. 补充

**`runtime_tracker.py` 是 L3 的"健康监控器"——读 L1 指标算出 specialist 的健康报告与 degraded 状态，并把 degraded 消息 enqueue 给 L2 触发进化。**

几点补充：

- **自建，不复用 skill**：注释说"不实现 skill Protocol——返回类型 SkillHealthReport 字段不兼容"。**L3 的 `SpecialistHealthReport` 多了 `avg_cost_usd` / `avg_latency_seconds`**，与 skill 的字段不同。
- **依赖 L2 的 `MetricsView` Protocol**：本类通过 **`MetricsView` Protocol** 读 L1 指标——**这是 L3 读 L1 的标准接口**（`get_specialist_metrics` / `list_specialists`）。
- **trend 判定是 MVP**：注释说"MVP trend 基于 sample_size 判定"。**真正的"前后两半比较 completion_rate delta"需要 MetricsView 支持读历史序列**——这是"数据驱动触发后补"的待办。
- **degraded 判定有双重条件**：`total_invoked >= 5` **且** `completion_rate < threshold`。**样本不足时不判 degraded**——避免"调用 1 次失败就算退化"的误判。
- **`trigger_l2_evolution_if_degraded` 只 enqueue**：不直接调 L2 的 TriggerManager——**解耦 L3 和 L2**。消息 `("specialist_degraded", name)` 由 L2 cron 消费。
- **`window` 参数是预留**：`health_report(name, window=20)` 里的 `window` 当前未使用——**MVP 阶段不按窗口切分，直接用聚合快照**。
- **`degradation_delta` 未被使用**：构造参数接收了 `degradation_delta`，但 `health_report` / `degraded_specialists` 里都没用它——**这是"预留字段"，真正用它需要"前后两半比较"的逻辑**。
- **`# type: ignore[arg-type]` 的注释**：`trend` 字段在 `SpecialistHealthReport` 里是 `Trend` 字面量类型，而本类赋的是普通字符串——**类型检查器会警告，所以加 ignore**。这是 MVP 的临时处理。
- **数据流位置**：

```
L1 metrics（specialist_records 表）
    │
    │ MetricsView Protocol（L2 定义，L3 用）
    ▼
SpecialistRuntimeTracker（本文件）
    ├─ health_report() → SpecialistHealthReport（给 L2 看）
    └─ degraded_specialists() → list[str]
        │
        │ trigger_l2_evolution_if_degraded
        ▼
    L2 cron queue（消息）
        └─ L2 消费 → 触发进化
```
