---

name: L3 EvalBridge Protocol — L2 调 L3 的唯一入口契约。

description: 

【整体职责】
定义 L2 调用 L3 的统一契约（EvalBridge Protocol），并提供一个实现
（OrchestrationBridge）：根据 EvalContext 自动选 adapter、调它、fail-closed 返回
EvalResult。L2 的 PromotionGate 只依赖此契约，不关心 L3 是否启用。

【内容摘要】
- EvalBridge(Protocol, runtime_checkable) : L2 调 L3 的契约（evaluate / list_available_methods / health_check）。
- OrchestrationBridge                     : EvalBridge 的实现（选 adapter + 调用 + fail-closed）。

【职责边界】
- 只负责：定义契约、按 ctx 特征选 adapter、调用 adapter、异常兜底。
- 不负责：具体评估逻辑（adapter 负责）、评估器注册（registry 负责）、
  晋升决策（L2 PromotionGate 负责）。
- 不持有状态：OrchestrationBridge 只持有 registry 引用。

## 0. 结构树

### 0.1. 静态结构树

```
bridge.py — L3 EvalBridge Protocol（L2 调 L3 的唯一入口契约）
│
├─ 外部 import
│   ├─ SpecialistEvalRegistry   ← from eval/registry.py
│   ├─ EvalContext              ← from eval/types.py
│   └─ EvalResult               ← from evolution/promotion_gate.py（复用 L2）
│
├─ EvalBridge(Protocol, runtime_checkable)   ← ★ L2 调 L3 的契约
│   │   用途：定义 L2 依赖的唯一接口，L2 不关心 L3 是否启用
│   │   runtime_checkable：支持 isinstance 检查
│   │
│   ├─ evaluate(ctx) -> EvalResult           ← 同步阻塞评估
│   │   │   用途：评估 candidate vs baseline，返回 EvalResult
│   │   └─ fail-closed：异常时返回 success=False，不抛异常
│   │
│   ├─ list_available_methods() -> tuple[str, ...]
│   │   │   用途：返回已注册的评估方法名
│   │   └─ 示例：("programmatic", "llm_judge", "longitudinal_pairs")
│   │
│   └─ health_check() -> bool                ← registry 非空时 True
│       └─ 至少 1 个 adapter 注册
│
└─ OrchestrationBridge                       ← ★ EvalBridge 的实现（L3 启用时）
    │   用途：L2 调 L3 的唯一入口（注入 PromotionGate.bridge）
    │   流程：evaluate → _select_method → registry.get → adapter.evaluate
    │
    ├─ _adapters: SpecialistEvalRegistry    ← 评估器注册表
    │
    ├─ __init__(adapter_registry)
    │
    ├─ evaluate(ctx) -> EvalResult          ← ★ 核心方法
    │   │   用途：选 adapter → 调用 → fail-closed 兜底
    │   │
    │   ├─ ① method = self._select_method(ctx)
    │   ├─ ② adapter = registry.get(method)
    │   │     └─ None → 返回失败（adapter '<method>' not registered）
    │   ├─ ③ try: return adapter.evaluate(ctx)
    │   └─ ④ except Exception as exc:
    │         └─ 返回失败（failure_reason=str(exc)）
    │
    ├─ _select_method(ctx) -> str           ← ★ 自动选 adapter
    │   │   用途：根据 ctx 特征决定用哪个 method
    │   │   优先级（从高到低）：
    │   ├─ ① ctx.eval_method_hint（显式指定）
    │   ├─ ② 全部 task 有 expected_outcome → "longitudinal_pairs"
    │   ├─ ③ ctx.metadata["task_type"] == "open_ended" → "llm_judge"
    │   └─ ④ 默认 → "programmatic"
    │
    ├─ list_available_methods() -> tuple    ← 转发给 registry.list_methods()
    │
    └─ health_check() -> bool               ← registry 至少有 1 个 adapter
```

### 0.2. 运行时调用树

```
① 装配期（L3 启用时）
setup_l3（eval/bootstrap.py）
    │
    ├─ registry = SpecialistEvalRegistry()
    │   ├─ register("programmatic", ProgrammaticAdapter(None))
    │   ├─ register("llm_judge", LLMJudgeAdapter(None))
    │   └─ register("longitudinal_pairs", LongitudinalPairsAdapter(None))
    │
    └─ bridge = OrchestrationBridge(adapter_registry=registry)
        │
        └─ 注入 L2 PromotionGate.bridge
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2 触发评估（cron 周期）
L2 Evolution
    │
    ├─ 检测退化 / 触发进化
    ├─ 变异出 candidate
    ├─ 抽样 task_sample
    │
    └─ PromotionGate.decide(...)
        │
        └─ bridge.evaluate(ctx)                ← 本文件
            │
            ├─ ① _select_method(ctx)
            │   ├─ eval_method_hint 非空 → 用它
            │   ├─ 全 task 有 expected_outcome → "longitudinal_pairs"
            │   ├─ task_type == "open_ended" → "llm_judge"
            │   └─ 默认 → "programmatic"
            │
            ├─ ② registry.get(method)
            │   ├─ 命中 → 拿到 EvalAdapter
            │   └─ None → 返回失败（adapter '<method>' not registered）
            │
            ├─ ③ adapter.evaluate(ctx)
            │   ├─ 成功 → 返回 EvalResult
            │   └─ 抛异常 → 返回失败（failure_reason=str(exc)）
            │
            └─ ④ 返回 EvalResult（无论成功失败都不抛异常）
                │
                ▼
            PromotionGate 消费 EvalResult
                ├─ success=True 且 candidate 更好 → 晋升
                └─ success=False / 没更好 → 丢弃

③ 运行期：健康检查
L2 或外部调用
    └─ bridge.health_check()
        └─ len(registry.list_methods()) > 0
```

### 0.3. 补充

**`bridge.py` 是 L2 与 L3 之间的"唯一接口"——定义 `EvalBridge` 契约 + 提供 `OrchestrationBridge` 实现（自动选 adapter + fail-closed 兜底）。**

几点补充：

- **`EvalBridge` 是 L2 依赖的唯一契约**：`PromotionGate.bridge` 参数类型就是它。**L2 不知道 L3 是否启用**——L3 启用时给 `OrchestrationBridge`，未启用时给 `MultiagentProgrammaticFacade`。
- **`OrchestrationBridge` 是"策略选择器 + 转接层"**：它不自己评估，而是**根据 ctx 特征选一个 adapter**，交给它评。**这是策略模式的应用**。
- **四级选法优先级**：
  1. `ctx.eval_method_hint`（显式指定——最优先）
  2. 全 task 有 `expected_outcome` → `longitudinal_pairs`（适合版本对比）
  3. `task_type == "open_ended"` → `llm_judge`（适合开放式任务）
  4. 默认 → `programmatic`（通用兜底）
  - **这是"配置默认 + Bridge 自动覆盖"的设计**。
- **fail-closed 两层兜底**：
  - adapter 未注册 → 返回失败（`adapter '<method>' not registered`）
  - adapter 抛异常 → 返回失败（`failure_reason=str(exc)`）
  - **都不向上抛异常**——L2 拿到的是"失败的 EvalResult"，不是异常。
- **`EvalBridge` 是 `runtime_checkable` Protocol**：支持 `isinstance` 运行时检查。
- **不共享 skill 的 EvalBridge**：skill 用 `SkillRecord` 专属类型，不能跨模块共享——**L3 自建 EvalBridge**。
- **两个实现的最终对照**：

| 维度 | OrchestrationBridge | MultiagentProgrammaticFacade |
|---|---|---|
| 接口 | `EvalBridge` | `EvalBridge`（同一个） |
| 启用条件 | L3 启用 | L3 未启用 |
| 评估方法 | 通过 registry 选（3 种） | 直接调 evaluator（1 种） |
| `list_available_methods` | registry 里有啥返回啥 | 固定 `("programmatic",)` |
| 选法逻辑 | `_select_method` 四级优先级 | 无（只有一种） |
| 依赖 | `SpecialistEvalRegistry` | `Evaluator` callable |
