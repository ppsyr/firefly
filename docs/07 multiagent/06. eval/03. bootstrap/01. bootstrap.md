---

name: L3 eval bootstrap — 装配 L3 组件 + 启动健康检查 daemon 线程。

description: 

【整体职责】
L3 评估层的装配入口：当 config.l3.enabled=true 时，构造 L3 的全部组件
（registry + 3 adapter + bridge + runtime_tracker + decision_log writer/reader + facade），
并启动一个 6 小时周期的健康检查 daemon 线程；enabled=false 时返回 None，L2 行为不变。

【内容摘要】
- L3Setup(dataclass)             : L3 装配结果容器（注入 L2Setup 供 L1 bootstrap 使用）。
- setup_l3(config, metrics_store, task_queue) : 装配主入口。
- _start_health_check_thread()   : 启动 6h 周期的健康检查 daemon 线程。

【职责边界】
- 只负责：构造 L3 组件、启动健康检查线程、打包 L3Setup。
- 不负责：L3 评估逻辑（adapter 负责）、健康检查逻辑（runtime_tracker 负责）、
  L2 进化触发（只 enqueue，由 L2 消费）。
- 不持有状态：装配产出 L3Setup 后返回。

## 0. 结构树

### 0.1. 静态结构树

```
bootstrap.py — L3 eval bootstrap（装配 L3 组件 + 启动健康检查 daemon 线程）
│
├─ 外部 import
│   ├─ MultiAgentConfig              ← from multiagent/config.py
│   ├─ LLMJudgeAdapter               ← from eval/adapters/llm_judge.py
│   ├─ LongitudinalPairsAdapter      ← from eval/adapters/longitudinal_pairs.py
│   ├─ ProgrammaticAdapter           ← from eval/adapters/programmatic.py
│   ├─ OrchestrationBridge           ← from eval/bridge.py
│   ├─ DecisionLogWriter / Reader    ← from eval/decision_log.py
│   ├─ MultiagentProgrammaticFacade  ← from eval/facade.py
│   ├─ SpecialistEvalRegistry        ← from eval/registry.py
│   └─ SpecialistRuntimeTracker / trigger_l2_evolution_if_degraded
│                                     ← from eval/runtime_tracker.py
│
├─ L3Setup(dataclass)                       ← ★ 装配结果容器
│   │   用途：持有 L3 全部运行时组件，注入 L2Setup 供 L1 bootstrap 使用
│   ├─ bridge: OrchestrationBridge           ← L2 PromotionGate 的 bridge
│   ├─ registry: SpecialistEvalRegistry      ← 评估器注册表
│   ├─ runtime_tracker: SpecialistRuntimeTracker  ← 健康监控 + degraded 检测
│   ├─ decision_log_writer: DecisionLogWriter     ← 异步写决策日志
│   ├─ decision_log_reader: DecisionLogReader     ← 读 lesson + 归档
│   ├─ facade: MultiagentProgrammaticFacade       ← L3 未启用时备用
│   └─ health_thread: threading.Thread            ← 后台健康检查线程
│
├─ setup_l3(config, metrics_store, task_queue) -> L3Setup | None
│   │   ★ 装配主入口
│   │
│   ├─ ① enabled 检查
│   │   └─ False → return None（L2 行为不变）
│   │
│   ├─ ② 构造 SpecialistEvalRegistry + 注册 3 adapter
│   │   ├─ registry.register("programmatic", ProgrammaticAdapter(evaluator=None))
│   │   ├─ registry.register("llm_judge", LLMJudgeAdapter(judge_fn=None))
│   │   └─ registry.register("longitudinal_pairs", LongitudinalPairsAdapter(evaluator=None))
│   │   （MVP：evaluator / judge_fn 全为 None，数据驱动触发后才装配）
│   │
│   ├─ ③ 构造 OrchestrationBridge(adapter_registry=registry)
│   │   └─ 用途：作为 L2 PromotionGate 的 bridge
│   │
│   ├─ ④ 构造 SpecialistRuntimeTracker(metrics_view=metrics_store,
│   │                                   degradation_delta=config.l3.degradation_delta)
│   │   └─ 用途：健康监控 + degraded 检测
│   │
│   ├─ ⑤ 构造 DecisionLogWriter / DecisionLogReader
│   │   └─ 共用 metrics_store（L1 MultiAgentMetricsStore）
│   │
│   ├─ ⑥ 构造 MultiagentProgrammaticFacade(evaluator=None)
│   │   └─ 用途：L3 未启用时备用，向后兼容
│   │
│   ├─ ⑦ 启动健康检查 daemon 线程
│   │   └─ _start_health_check_thread(...)
│   │
│   └─ ⑧ 打包 L3Setup 返回
│
└─ _start_health_check_thread(runtime_tracker, task_queue, threshold, interval_seconds)
    │   用途：启动 6h 周期的健康检查 daemon 线程
    │
    ├─ stop_event = threading.Event()
    │
    ├─ _health_loop()（内层函数）
    │   └─ while not stop_event.is_set():
    │       ├─ trigger_l2_evolution_if_degraded(tracker, cron_queue, threshold)
    │       │   └─ 只 enqueue，不直接调 L2 TriggerManager
    │       ├─ except Exception → pass（daemon 不崩溃）
    │       └─ stop_event.wait(timeout=interval_seconds)
    │
    ├─ thread = threading.Thread(target=_health_loop, daemon=True, name="l3-health-check")
    ├─ thread.start()
    └─ return thread
```

### 0.2. 运行时调用树

```
① 装配期（L3 启用时）
bootstrap_runtime（app/bootstrap.py）
    │
    └─ setup_l2（evolution/bootstrap.py）
        │
        └─ setup_l3(config, metrics_store, task_queue)   ← 本文件
            │
            ├─ config.l3.enabled == False?
            │     └─ 是 → return None（L2 行为不变）
            │
            ├─ ② registry = SpecialistEvalRegistry()
            │     ├─ register("programmatic", ProgrammaticAdapter(None))
            │     ├─ register("llm_judge", LLMJudgeAdapter(None))
            │     └─ register("longitudinal_pairs", LongitudinalPairsAdapter(None))
            │
            ├─ ③ bridge = OrchestrationBridge(adapter_registry=registry)
            │
            ├─ ④ runtime_tracker = SpecialistRuntimeTracker(metrics_store, delta)
            │
            ├─ ⑤ decision_log_writer = DecisionLogWriter(metrics_store)
            │     decision_log_reader = DecisionLogReader(metrics_store)
            │
            ├─ ⑥ facade = MultiagentProgrammaticFacade(None)
            │
            ├─ ⑦ health_thread = _start_health_check_thread(...)
            │     │
            │     ├─ 创建 stop_event
            │     ├─ 创建 _health_loop 闭包
            │     ├─ 启动 daemon thread
            │     └─ return thread
            │
            └─ ⑧ return L3Setup(bridge, registry, runtime_tracker,
            │                    writer, reader, facade, health_thread)
            │
            ▼
        L3Setup 注入 L2Setup（供 L1 bootstrap 使用）
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：健康检查 daemon 线程（每 6 小时）
_health_loop（后台线程）
    │
    └─ while not stop_event.is_set():
        │
        ├─ trigger_l2_evolution_if_degraded(
        │       tracker=runtime_tracker,
        │       cron_queue=task_queue,
        │       threshold=threshold,
        │   )
        │   │   用途：检测 specialist 健康，degraded 则 enqueue L2 进化任务
        │   ├─ 读 runtime_tracker 的健康报告
        │   ├─ 判断是否 degraded
        │   └─ degraded → task_queue.put(...)
        │
        ├─ except Exception → pass（daemon 不崩溃）
        │
        └─ stop_event.wait(timeout=6*3600)
            └─ 等 6 小时（或 stop_event 被 set）

③ 运行期：主进程退出
atexit / 关闭流程
    └─ daemon 线程随主进程结束（daemon=True，不阻塞退出）
```

### 0.3. 补充

**`bootstrap.py`（L3）是 L3 评估层的"装配总入口"——把 registry / 3 adapter / bridge / tracker / decision log / facade 组装成 `L3Setup`，并启动 6h 健康检查 daemon 线程。**

几点补充：

- **`enabled=false` 是短路**：直接 `return None`——**L2 行为完全不变**，与 `setup_multiagent` 的 `_EMPTY_SETUP` 是同一模式（opt-out 安全）。
- **MVP 阶段 adapter 全为 None**：3 个 adapter 都传 `evaluator=None` / `judge_fn=None`——**真正打分函数要等数据驱动触发后才注入**。此时 `evaluate` 会返回 `success=False`，但不会崩。
- **`facade` 即使 L3 启用也构造**：注释说"向后兼容备用"——**虽然 L3 启用后用 `bridge`，但 facade 仍存在**。
- **健康检查是"enqueue 不是直调"**：`trigger_l2_evolution_if_degraded` 只往 `task_queue` 里塞消息，**由 L2 cron 消费**——**解耦 L3 和 L2**，避免 L3 直接调 L2 的 TriggerManager。
- **daemon 线程异常吞掉**：`except Exception: pass`——**daemon 线程不能崩**，否则健康监控就断了。
- **6 小时周期是硬编码**：`interval_seconds=6 * 3600.0`——**默认每 6 小时检查一次 specialist 健康**。和 `L2Config.cron_interval_hours` 默认 6.0 一致。
- **`L3Setup` 是 dataclass 而非 frozen**：与 `MultiAgentSetup` 同款——**装配结果容器，不需不可变**。
- **装配链位置**：

```
bootstrap_runtime
    ├─ setup_multiagent          ← multiagent 装配
    └─ setup_l2
        └─ setup_l3              ← L3 装配（本文件）
            └─ L3Setup
```

**关键**：`setup_l3` **不是**被 `bootstrap_runtime` 直接调，而是**嵌套在 `setup_l2` 里**——**L3 是 L2 的子层**。这印证了 L2/L3 的关系：**L2 是进化层（owner），L3 是评估层（被 L2 调用）**。
