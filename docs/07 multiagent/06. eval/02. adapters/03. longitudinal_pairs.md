---

name: L3 LongitudinalPairsAdapter — candidate vs baseline 同批 task 对比 + Wilson CI。

description: 

【整体职责】
实现 EvalAdapter 契约：让 candidate 与 baseline 在同一批 task_sample 上各跑一遍，
用 evaluator 判定每个 task 的 success_criteria_met（bool），再算 Wilson 95% 置信区间，
返回 EvalResult。候选是否优于基线由 L2 PromotionGate 决定。

【内容摘要】
- LongitudinalPairsAdapter : 评估器主类，实现 evaluate + health_check。

【职责边界】
- 只负责：遍历 task_sample 调 evaluator、聚合分数、算 Wilson CI、返回 EvalResult。
- 不负责：task_sample 抽样（L2 负责）、晋升决策（L2 PromotionGate 负责）、
  pool 淘汰（L2 负责）、evaluator 实现（bootstrap 注入）。
- 不持有运行时状态：evaluator / z 由构造注入。

## 0. 结构树

### 0.1. 静态结构树

```
longitudinal_pairs.py — L3 LongitudinalPairsAdapter（candidate vs baseline 同批对比 + Wilson CI）
│
├─ 外部 import
│   ├─ EvalContext            ← from eval/types.py
│   └─ EvalResult / Evaluator / _wilson_ci
│                              ← from evolution/promotion_gate.py（复用 L2）
│
└─ LongitudinalPairsAdapter                  ← ★ 评估器主类
    │                                            实现 EvalAdapter Protocol
    │                                            （无需显式继承）
    │                                            与 ProgrammaticAdapter 独立实现
    │
    ├─ _evaluator: Evaluator | None          ← 单任务评估器（bootstrap 注入）
    ├─ _z: float = 1.96                       ← Wilson CI 的 z 值
    │
    ├─ __init__(evaluator=None, z_score=1.96)
    │   └─ evaluator 为 None 时 evaluate 直接返回失败
    │
    ├─ evaluate(ctx: EvalContext) -> EvalResult   ← ★ 核心方法
    │   │   用途：对 task_sample 逐个评估 candidate / baseline，聚合返回
    │   │
    │   ├─ ① evaluator is None?
    │   │     └─ 是 → 返回 success=False, failure_reason="no evaluator configured"
    │   │
    │   ├─ ② 遍历 ctx.task_sample
    │   │     ├─ c_met = evaluator.evaluate(ctx.candidate, task)
    │   │     ├─ b_met = evaluator.evaluate(ctx.baseline, task)
    │   │     ├─ 异常 → continue（跳过）
    │   │     └─ 累积 candidate_scores / baseline_scores（1.0 / 0.0）
    │   │
    │   ├─ ③ candidate_scores 为空?
    │   │     └─ 是 → 返回 success=False, failure_reason="all_tasks_failed"
    │   │
    │   ├─ ④ c_score = 平均分；b_score = 平均分
    │   ├─ ⑤ c_low, c_high = _wilson_ci(c_score, n, z)
    │   │
    │   └─ ⑥ 返回 EvalResult(
    │          candidate_score, baseline_score,
    │          ci_low, ci_high, sample_size,
    │          method_used="longitudinal_pairs", success=True
    │       )
    │
    └─ health_check() -> bool                 ← 健康检查
        └─ evaluator is not None（已配置即可用）
```

### 0.2. 运行时调用树

```
① 装配期（L3 启用时）
bootstrap / setup_l3
    │
    ├─ 构造 LongitudinalPairsAdapter(evaluator=..., z_score=1.96)
    │
    └─ 注册进 SpecialistEvalRegistry
        └─ registry.register("longitudinal_pairs", adapter)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2 触发评估
L2 Evolution（cron 周期触发）
    │
    ├─ ① L2 抽样 task_sample（80% 失败 + 20% 成功）
    ├─ ② 变异出 candidate
    │
    └─ ③ OrchestrationBridge.evaluate(ctx)
        │
        ├─ ① 决定 method（ctx.eval_method_hint 或默认）
        ├─ ② registry.get("longitudinal_pairs") → LongitudinalPairsAdapter
        ├─ ③ adapter.health_check()
        │     └─ True → 继续
        │
        └─ ④ adapter.evaluate(ctx)              ← 本文件
            │
            ├─ ① evaluator is None?
            │     └─ 是 → 返回失败（no evaluator configured）
            │
            ├─ ② 遍历 task_sample：
            │     ├─ candidate 评估 → c_met → 1.0 / 0.0
            │     ├─ baseline 评估 → b_met → 1.0 / 0.0
            │     └─ 累积分数
            │
            ├─ ③ 全部失败 → 返回失败（all_tasks_failed）
            │
            ├─ ④ 算平均分
            ├─ ⑤ _wilson_ci(c_score, n, 1.96) → (c_low, c_high)
            │
            └─ ⑥ 返回 EvalResult(method_used="longitudinal_pairs", ...)
                │
                ▼
            L2 PromotionGate.decide(EvalResult)
                ├─ candidate CI 下界 > baseline CI 上界 → accept 倾向
                └─ 否则 → reject
```

### 0.3. 补充

**`longitudinal_pairs.py` 是 L3 的"纵向配对评估器"——让 candidate 与 baseline 在同批 task 上各跑一遍，用 evaluator 判定成败，返回带 Wilson CI 的 EvalResult。**

几点补充：

- **实现 EvalAdapter Protocol**：**无需显式继承**——只要实现 `evaluate` + `health_check` 就满足契约。
- **与 `ProgrammaticAdapter` 逻辑几乎一样**：都用 `Evaluator`（bool → 1.0/0.0），都算 Wilson CI。**唯一区别是 `method_used` 字符串不同**（`"longitudinal_pairs"` vs `"programmatic"`）。
- **为什么独立实现两份**：注释明确说 "3 adapter 各自实现（L3-3.1 决策 b）"——**刻意不共享基类**。好处是每个 adapter 独立演进；代价是少量代码重复。
- **task_sample 抽样是 L2 的事**：注释说 "80% 失败 + 20% 成功"——**这是 L2 的抽样策略**，adapter 只消费 `ctx.task_sample`。
- **L3 不做池淘汰**：注释说 "单 task 累计 eval ≤ 3 次（pool 淘汰逻辑在 L2）"——**L3 只管评估，不管理"评过几次了"**。
- **accept 决策在 L2**：注释说 "candidate CI 下界 > baseline CI 上界 → accept 倾向，由 L2 PromotionGate.decide 判定"——**adapter 只返回 EvalResult，不做 accept/reject**。
- **两种失败返回**：
  - `evaluator=None` → `failure_reason="no evaluator configured"`（配置问题）
  - 任务全失败 → `failure_reason="all_tasks_failed"`（数据问题）
- **单任务异常跳过**：`try / except: continue`——**不因单个任务失败中断整体评估**。
- **四个评估实现的最终对照**：

| 维度 | MultiagentProgrammaticFacade | ProgrammaticAdapter | LLMJudgeAdapter | LongitudinalPairsAdapter |
|---|---|---|---|---|
| 层次 | L2 用的 facade | L3 adapter | L3 adapter | L3 adapter |
| 接口 | EvalBridge | EvalAdapter | EvalAdapter | EvalAdapter |
| method_used | `programmatic` | `programmatic` | `llm_judge` | `longitudinal_pairs` |
| 分数来源 | evaluator → bool → 0/1 | evaluator → bool → 0/1 | judge_fn → [0,1] | evaluator → bool → 0/1 |
| 依赖 | L1 ResultSummarizer | L1 ResultSummarizer | LLM | L2 Evaluator |
| 成本 | 极低 | 极低 | 高 | 低 |
| 是否 L3 启用后注册 | ❌ | ✅ | ✅ | ✅ |

**关键**：`ProgrammaticAdapter` 和 `LongitudinalPairsAdapter` 的**逻辑几乎完全一样**——两者的差异主要在"语义定位"（programmatic = 通用程序化评估；longitudinal_pairs = 纵向配对对比），而非实现细节。**这是"语义分层"而非"实现分层"。**
