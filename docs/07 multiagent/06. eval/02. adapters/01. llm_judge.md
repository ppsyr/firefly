---

name: L3 LLMJudgeAdapter — LLM 四维加权评分评估器。

description: 

【整体职责】
实现 EvalAdapter 契约：用 LLM 对 candidate / baseline 在任务样本上打分，
四维加权汇总为 [0,1] 分数，再算 Wilson 95% 置信区间，返回 EvalResult。
评分函数 judge_fn 由 bootstrap 注入。

【内容摘要】
- JudgeFn                     : 评分函数类型别名（artifact + task → float [0,1]）。
- LLMJudgeAdapter             : 评估器主类，实现 evaluate + health_check。
- WEIGHTS                     : 四维权重常量（task_completion / response_quality /
                                efficiency / tool_usage）。

【职责边界】
- 只负责：遍历 task_sample 调 judge_fn、聚合分数、算 Wilson CI、返回 EvalResult。
- 不负责：judge_fn 的实现（bootstrap 注入）、评估方法选择（Bridge 负责）、
  结果持久化（db 负责）。
- 不持有运行时状态：judge_fn / model / z 由构造注入。

## 0. 结构树

### 0.1. 静态结构树

```
llm_judge.py — L3 LLMJudgeAdapter（LLM 四维加权评分评估器）
│
├─ 外部 import
│   ├─ EvalContext            ← from eval/types.py
│   ├─ EvalResult / EvalTask / EvolutionArtifact / _wilson_ci
│   │                          ← from evolution/promotion_gate.py（复用 L2）
│   │
│   └─ JudgeFn = Callable[[EvolutionArtifact, EvalTask], float]  ← 评分函数类型
│
└─ LLMJudgeAdapter                           ← ★ 评估器主类
    │                                            实现 EvalAdapter Protocol
    │                                            （无需显式继承，靠方法签名匹配）
    │
    ├─ WEIGHTS: dict = {                     ← 四维权重常量
    │     "task_completion": 0.50,           ← 任务完成
    │     "response_quality": 0.35,          ← 响应质量
    │     "efficiency": 0.05,                ← 效率
    │     "tool_usage": 0.10,                ← 工具使用
    │   }
    │   （与 skill TaskQualityJudge 一致，但不实现 skill Protocol）
    │
    ├─ _judge_fn: JudgeFn | None             ← 评分函数（bootstrap 注入）
    ├─ _llm_judge_model: str | None           ← LLM 模型名（None 继承 lead）
    ├─ _z: float = 1.96                       ← Wilson CI 的 z 值
    │
    ├─ __init__(judge_fn, llm_judge_model, z_score)
    │
    ├─ evaluate(ctx: EvalContext) -> EvalResult   ← ★ 核心方法
    │   │   用途：对 task_sample 逐个评分，聚合返回
    │   │
    │   ├─ ① judge_fn is None?
    │   │     └─ 是 → 返回 success=False, failure_reason="no judge_fn configured"
    │   │
    │   ├─ ② 遍历 ctx.task_sample
    │   │     ├─ c_score = judge_fn(ctx.candidate, task)
    │   │     ├─ b_score = judge_fn(ctx.baseline, task)
    │   │     ├─ 异常 → continue（跳过）
    │   │     ├─ clamp 到 [0,1]（max/min 双向）
    │   │     └─ 累积 candidate_scores / baseline_scores
    │   │
    │   ├─ ③ candidate_scores 为空?
    │   │     └─ 是 → 返回 success=False, failure_reason="all_tasks_failed"
    │   │
    │   ├─ ④ c_score = 平均分；b_score = 平均分
    │   ├─ ⑤ c_low, c_high = _wilson_ci(c_score, n, z)
    │   │
    │   └─ ⑥ 返回 EvalResult(
    │          candidate_score, baseline_score,
    │          ci_low, ci_high, sample_size,
    │          method_used="llm_judge", success=True
    │       )
    │
    └─ health_check() -> bool                 ← 健康检查
        └─ judge_fn is not None（已配置即可用）
```

### 0.2. 运行时调用树

```
① 装配期（L3 启用时）
bootstrap / setup_l3
    │
    ├─ 构造 LLMJudgeAdapter(judge_fn=..., llm_judge_model=..., z_score=1.96)
    │
    └─ 注册进 SpecialistEvalRegistry
        └─ registry.register("llm_judge", adapter)
        ═══════════ 进入 Agent 循环 ═══════════

② 运行期：L2 触发评估
L2 Evolution（cron 周期触发）
    │
    └─ OrchestrationBridge.evaluate(ctx)
        │
        ├─ ① 决定 method（ctx.eval_method_hint 或默认）
        ├─ ② registry.get("llm_judge") → LLMJudgeAdapter
        ├─ ③ adapter.health_check()
        │     └─ True → 继续
        │
        └─ ④ adapter.evaluate(ctx)              ← 本文件
            │
            ├─ ① judge_fn is None?
            │     └─ 是 → 返回失败（no judge_fn configured）
            │
            ├─ ② 遍历 task_sample：
            │     ├─ candidate 评分 → clamp [0,1]
            │     ├─ baseline 评分 → clamp [0,1]
            │     └─ 累积分数
            │
            ├─ ③ 全部失败 → 返回失败（all_tasks_failed）
            │
            ├─ ④ 算平均分
            ├─ ⑤ _wilson_ci(c_score, n, 1.96) → (c_low, c_high)
            │
            └─ ⑥ 返回 EvalResult(method_used="llm_judge", ...)
                │
                ▼
            L2 消费 EvalResult（决定是否晋升新版本）

③ judge_fn 内部（bootstrap 注入，不在本文件）
judge_fn(artifact, task)
    ├─ 跑 specialist（用 artifact 的 prompt 或配置）
    ├─ LLM 四维评分：
    │   ├─ task_completion
    │   ├─ response_quality
    │   ├─ efficiency
    │   └─ tool_usage
    └─ 加权汇总：0.50 * completion
                + 0.35 * quality
                + 0.05 * efficiency
                + 0.10 * tool
        → 返回 [0,1] 分数
```

### 0.3. 补充

**`llm_judge.py` 是 L3 的"LLM 评分评估器"——用 LLM 四维加权对 candidate / baseline 打分，返回带 Wilson CI 的 EvalResult。**

几点补充：

- **实现 EvalAdapter Protocol**：**无需显式继承**——只要实现 `evaluate` + `health_check` 两个方法就满足契约。这是 Poirot 用 Protocol 表达契约的统一方式。
- **WEIGHTS 与 skill 一致但不复用实现**：四维权重 `0.50 / 0.35 / 0.05 / 0.10` 与 skill 的 `TaskQualityJudge` 完全一样——**但代码不 import skill 的类**。原因：skill 是 async，L3 是 sync。**这是"值对齐、实现独立"的刻意选择。**
- **judge_fn 是注入点**：`LLMJudgeAdapter` 自己不实现"怎么调 LLM 打分"——它把这件事交给 `judge_fn`（一个 `Callable`）。**bootstrap 负责构造 judge_fn**，adapter 只负责遍历任务、聚合分数。**这是依赖注入的典型用法。**
- **分数双向 clamp**：`max(0.0, min(1.0, c_score))`——**既防负数又防超过 1**。`judge_fn` 返回越界值时会被裁剪。
- **两种失败返回**：
  - `judge_fn=None` → `failure_reason="no judge_fn configured"`（配置问题）
  - 任务全失败 → `failure_reason="all_tasks_failed"`（数据问题）
- **单任务异常跳过**：`try / except: continue`——**不因单个任务失败中断整体评估**。注释说这是 "fail-closed，不降级"——**降级由 Bridge 层负责选 programmatic adapter**。
- **llm_judge_model 默认 None**：继承 lead 的模型——**与 L2 EvolutionMutator 同款**。
- **与 programmatic facade / programmatic adapter 的三角关系**：

| 维度 | MultiagentProgrammaticFacade | ProgrammaticAdapter（未贴） | LLMJudgeAdapter |
|---|---|---|---|
| 层次 | L2 用的 facade | L3 adapter | L3 adapter |
| 评估方法 | programmatic | programmatic | llm_judge |
| 分数 | 二值 0/1 | 二值 0/1 | 连续 [0,1] |
| 接口 | EvalBridge | EvalAdapter | EvalAdapter |
| 依赖 | L1 ResultSummarizer | L1 ResultSummarizer | LLM（通过 judge_fn） |
| 成本 | 极低 | 极低 | 高 |

**关键**：**两个 `programmatic` 实现分属不同层次**——facade 是"L3 未启用时 L2 直接调的降级门面"，adapter 是"L3 启用后注册进 registry 的评估器"。**它们的评估逻辑相似（都调 L1 的 success_criteria_met），但接口不同、位置不同。**
