---

name: L3 db schema management — 2 张表 + PRAGMA user_version v2→v3。

description: 

【整体职责】
管理 L3 评估层所需的 SQLite schema：创建 specialist_decision_log 与
specialist_decision_log_archive 两张表，并把 PRAGMA user_version 从 v2（L2）
升级到 v3（L3）。与 L1/L2 共用同一个 metrics 数据库（不同表），不破坏已有表。

【内容摘要】
- _L3_SCHEMA_SQL / _L3_SCHEMA_VERSION : 建表 SQL（2 表 + 索引）+ schema 版本号。
- L3SchemaManager                     : schema 管理主类（__init__ 幂等建表）。
- schema_version (property)           : 暴露当前 schema 版本号。

【职责边界】
- 只负责：L3 两张表的建表、版本号升级、幂等性保证。
- 不负责：表的读写（metrics.py 负责）、L1/L2 表的建表（各自负责）、
  归档逻辑（archive_decision_logs 在 metrics.py 里）。
- 不持有运行时状态：只持有 db_path + 锁。

## 0. 结构树

### 0.1. 静态结构树

```
db.py — L3 db schema management（2 张表 + PRAGMA user_version v2→v3）
│
├─ 常量
│   ├─ _L3_SCHEMA_SQL                        ← 建表 SQL（2 表 + 索引，IF NOT EXISTS）
│   │   ├─ specialist_decision_log           ← 决策日志主表
│   │   │   ├─ log_id TEXT PRIMARY KEY
│   │   │   ├─ specialist_name TEXT NOT NULL
│   │   │   ├─ task_id TEXT NOT NULL
│   │   │   ├─ goal TEXT NOT NULL
│   │   │   ├─ success_criteria TEXT NOT NULL
│   │   │   ├─ failure_category TEXT
│   │   │   ├─ success_criteria_met INTEGER
│   │   │   ├─ lesson_text TEXT
│   │   │   └─ timestamp TEXT NOT NULL
│   │   │   + idx_decision_log_specialist (specialist_name, timestamp)
│   │   │   + idx_decision_log_category (failure_category, timestamp)
│   │   │
│   │   └─ specialist_decision_log_archive   ← 决策日志归档表
│   │       └─ 与主表同字段 + archived_at TEXT NOT NULL
│   │
│   └─ _L3_SCHEMA_VERSION: int = 3           ← 当前 schema 版本号（L2=2 → L3=3）
│
└─ L3SchemaManager                           ← ★ schema 管理主类
    │                                            只负责"建表 + 升版本号"
    │                                            读写由 metrics.py 负责
    │
    ├─ _db_path: str = ".poirot/multiagent.db"  ← DB 路径（与 L1/L2 共用）
    ├─ _lock: threading.Lock                    ← 保护初始化
    │
    ├─ __init__(db_path)
    │   │   用途：建父目录 + 幂等建表 / 升级版本号
    │   ├─ Path(db_path).parent.mkdir(parents=True, exist_ok=True)
    │   └─ _init_schema()
    │
    ├─ _connect() -> sqlite3.Connection
    │   │   用途：建连接并设置 PRAGMA
    │   ├─ PRAGMA journal_mode=WAL
    │   └─ PRAGMA busy_timeout=30000
    │
    ├─ _init_schema() -> None
    │   │   用途：幂等建表 + 版本号升级
    │   ├─ ① 读 PRAGMA user_version
    │   ├─ ② executescript(_L3_SCHEMA_SQL)      ← IF NOT EXISTS 保证幂等
    │   ├─ ③ version < 3 → 更新 user_version = 3
    │   └─ ④ commit
    │
    └─ schema_version (property) -> int
        └─ 固定返回 _L3_SCHEMA_VERSION = 3
```

### 0.2. 运行时调用树

```
① 装配期（L3 启用时）
bootstrap / setup_l3
    │
    └─ L3SchemaManager(db_path=".poirot/multiagent.db")
        │
        ├─ ① Path(db_path).parent.mkdir(parents=True, exist_ok=True)
        │     └─ 建 .poirot/ 目录（若不存在）
        │
        └─ ② _init_schema()
            ├─ 加锁
            ├─ conn = _connect()（WAL + busy_timeout）
            ├─ version = PRAGMA user_version
            │   ├─ 新库 → 0
            │   ├─ L1/L2 已用 → 2
            │   └─ L3 已升过 → 3
            ├─ executescript(_L3_SCHEMA_SQL)
            │   └─ CREATE TABLE IF NOT EXISTS ...（幂等）
            ├─ version < 3 → PRAGMA user_version = 3
            ├─ conn.commit()
            └─ conn.close()
        ═══════════ L3 装配完成 ═══════════

② 运行期（L3 被调用时）
L3 的读写不经过本类——由 metrics.py 负责：
    ├─ metrics.save_decision_log(record)       ← 写 specialist_decision_log
    ├─ metrics.get_decision_logs(...)          ← 读 specialist_decision_log
    └─ metrics.archive_decision_logs(days)     ← 主表 → archive 表
        └─ 归档时要求两表已存在（本类保证）

③ 重复装配（幂等）
下次启动再次 L3SchemaManager(...)
    └─ _init_schema()
        ├─ version = 3
        ├─ executescript（CREATE IF NOT EXISTS → 什么都不做）
        └─ version < 3 为 False → 不更新 user_version
```

### 0.3. 补充

**`db.py` 是 L3 的"建表员"——只负责创建 `specialist_decision_log` / `_archive` 两张表 + 升级 schema 版本号；读写由 `metrics.py` 负责。**

几点补充：

- **和 `metrics.py` 分工**：本类**只建表**，`metrics.py` 负责**打点 / 查询 / 归档**。两者操作**同一 DB、同一批表**——**"建"与"用"分离**。
- **共用 DB 不同表（Z3 模式）**：`specialist_decision_log` 和 `specialist_records` / `evolution_artifacts` / `l2_metrics` **在同一个 `.poirot/multiagent.db` 里**。L1/L2/L3 共用文件、各占各的表。
- **幂等性靠两层保证**：
  1. `CREATE TABLE IF NOT EXISTS` —— 表已存在则跳过
  2. `if version < 3` —— 版本号已是最新则不更新
  - **重复运行是 no-op**——不会报错、不会破坏数据。
- **版本号只升不降**：`if version < _L3_SCHEMA_VERSION` 才更新。**如果数据库是 v3，不会降回 v2。**
- **不破坏 L1/L2 表**：只对 L3 两张表 `CREATE IF NOT EXISTS`，**没有任何 DROP / ALTER / DELETE**——L1/L2 的数据安全。
- **归档表多一个 `archived_at`**：主表 9 个字段，归档表 10 个（多 `archived_at`）。**归档时记录归档时间。**
- **归档语义是"移"不是"删"**：90 天后主表记录 `INSERT INTO archive SELECT ...` + `DELETE FROM 主表`——**数据不丢，只是搬到 archive 表。**
- **和 `L3Config` 的字段对应**：
  - `decision_log_retention_days: int = 90` —— 归档天数（`archive_decision_logs` 用它）
  - `decision_log_archive_enabled: bool = True` —— 是否启用归档
- **`schema_version` 属性是"固定值"**：它返回的是**代码里的常量**，不是从 DB 读的实际版本。**所以即使 DB 是 v2，属性也返回 3**——这里指的是"本类期望的版本"。
