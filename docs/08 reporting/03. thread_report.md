---

name: 渠道无关的报告生成服务 — 从 thread 累积 state 合成报告 + 保存 artifact。

description: 

【整体职责】
为 CLI / API / IM 等所有交互渠道提供统一的报告生成入口：
从 checkpointer 取 thread 累积 state，调用 reporter 合成报告，按配置保存 artifact。
各渠道自行负责 presentation（console / HTTP / IM），本模块只产结果、不碰呈现。

【内容摘要】
- ReportArtifact        : 报告生成结果（渠道无关），含报告文本与 artifact 路径。
- _ReportRuntime        : Protocol，描述本模块所需 runtime 的形状（AppRuntime 结构性满足）。
- generate_report_from_thread : 主入口，取 state → 合成 → 可选保存 artifact。

【职责边界】
- 只负责：取 thread state、合成报告、按配置保存 artifact，返回渠道无关的 ReportArtifact。
- 不负责：交互呈现（console / HTTP / IM）、报告文本渲染逻辑（reporter）、
  artifact 存储实现（artifact_store）、runtime 的构造与生命周期。

【依赖方向】
agents 层不 import app 层，故用 Protocol（_ReportRuntime）描述 runtime 形状，
AppRuntime 结构性满足，避免反向依赖。

## 0. 结构树

### 0.1. 静态结构树

```
（报告生成服务文件）— 渠道无关的报告生成服务
│
├─ ReportArtifact(dataclass)                  ← 报告生成结果；渠道无关
│   ├─ final_report: str                      ← 合成的最终报告文本
│   └─ artifact_path: str | None              ← 保存的 artifact 路径；未保存为 None
│
├─ _ReportRuntime(Protocol)                   ← generate_report_from_thread 所需 runtime 形状
│   │                                            AppRuntime 结构性满足；避免 agents→app 反向依赖
│   ├─ leader_agent: Any                      ← Leader Agent（含 .graph）
│   ├─ thread_id: str                         ← 线程 ID，用于取 checkpointer 累积 state
│   ├─ capability_registry: Any               ← 能力注册表（含 get_reporter / get_artifact_store）
│   ├─ thread_dir: Path                       ← 线程产物目录，作为 artifact 输出目录
│   └─ config: Any                            ← 运行配置（含 .reporting.save_artifact）
│
└─ generate_report_from_thread(runtime, topic) ← 主入口；取 state → 合成 → 可选保存
    ├─ ① graph.get_state(config)               ← 取 checkpointer 累积 state
    │       config = {"configurable": {"thread_id": runtime.thread_id}}
    ├─ ② topic 非空 → 覆盖 research_question    ← 可选主题注入
    ├─ ③ reporter.generate_report(state)       ← 合成报告
    │       三级 fallback：final_report → observations/sources → last AIMessage
    ├─ ④ config.reporting.save_artifact 为真    ← 条件保存
    │       └─ artifact_store.save_artifact(content, output_dir, title, filename, metadata)
    └─ return ReportArtifact(final_report, artifact_path)
```

---

### 0.2. 运行时调用树

```
① 渠道调用（CLI / API / IM 任一）
渠道入口
    └─ generate_report_from_thread(runtime, topic)
        ═══════════ 取 state ═══════════
        ├─ runtime.leader_agent.graph.get_state({"configurable": {"thread_id": ...}})
        │       └─ 取 checkpointer 累积 state（snapshot.values）
        ├─ topic 非空 → state["research_question"] = topic
        ═══════════ 合成报告 ═══════════
        ├─ runtime.capability_registry.get_reporter()
        └─ reporter.generate_report(state, run_context=None)
                └─ 三级 fallback → result.final_report
        ═══════════ 保存 artifact ═══════════
        ├─ runtime.config.reporting.save_artifact 为真
        │       └─ capability_registry.get_artifact_store()
        │             └─ save_artifact(content, output_dir=thread_dir,
        │                               title, filename="report.md", metadata)
        │                   └─ artifact.path → artifact_path
        └─ return ReportArtifact(final_report, artifact_path)

② 渠道自行呈现（不在本文件）
渠道侧将 ReportArtifact 渲染为 console / HTTP / IM 输出
```

### 0.3. 补充

**本文件是报告生成的"渠道无关服务层"——把取 state、合成、保存三步收敛为一个入口，让 CLI/API/IM 复用同一逻辑，各自只负责呈现。**

几点补充：

- **职责单一、边界清晰**：只做取 state → 合成 → 可选保存，presentation 完全外置给调用渠道。
- **Protocol 解耦依赖方向**：agents 层不 import app 层，用 `_ReportRuntime` 描述 runtime 形状，`AppRuntime` 结构性满足，避免反向依赖（Duck Typing + 结构化子类型）。
- **`ReportArtifact` 是渠道无关的产出契约**：只带报告文本与可选路径，不携带任何渠道相关信息。
- **保存是条件行为**：由 `config.reporting.save_artifact` 开关控制，未开启时 `artifact_path` 为 None。
- **三级 fallback 复用 reporter 能力**：本文件不关心 fallback 细节，完全委托 `MarkdownReporter.generate_report`（final_report → observations/sources → last AIMessage）。
- **`topic` 双重作用**：既覆盖 state 的 `research_question`，又作为 artifact 的 title 与 metadata。
