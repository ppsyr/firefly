---

name: Markdown 报告生成器 — 将 thread_state 渲染为最终 Markdown 报告。

description: 

【整体职责】
从 thread_state 中提取研究问题与证据，按优先级产出一份 Markdown 文本，
封装为 ReportResult 返回。供 LeaderAgent 在收尾阶段调用。

【内容摘要】
- MarkdownReporter.generate_report : 主入口，三级 fallback 产出报告文本。
- _render_structured              : Tier 2 兜底，把 observations + sources 渲染为结构化 Markdown。
- _last_ai_message                : Tier 3 兜底，从 messages 中倒序取最后一条 AI 消息文本。
- _summary                        : 生成 Summary 段落（observations 优先，其次 AI 回答）。
- _field                          : 通用字段读取，兼容 dict 与对象属性两种访问方式。

【职责边界】
- 只负责：把已有证据渲染成 Markdown 文本，产出 ReportResult。
- 不负责：证据收集（middleware / tool）、报告事件的发送（由 LeaderAgent.run 发）、
  证据充分性判断（reflection / evidence middleware）。

## 0. 结构树

### 0.1. 静态结构树

```
markdown_reporter.py — Markdown 报告生成器
│
├─ MarkdownReporter                                  ← 报告生成器类
│   └─ generate_report(thread_state, run_context)    ← 主入口；三级 fallback 产出报告文本
│       ├─ ① final_report 字段                        ← ReportMiddleware 已合成完整报告（最优）
│       ├─ ② _render_structured(observations/sources) ← 结构化兜底（有证据但未合成）
│       └─ ③ _last_ai_message                         ← 无证据兜底（fast 模式 / 单轮对话）
│       → return ReportResult(final_report=...)       ← 仅封装报告文本
│
├─ _render_structured(question, observations, sources) ← Tier 2 兜底；渲染结构化 Markdown
│   ├─ 一级标题                                        ← # {question}
│   ├─ ## Summary                                     ← _summary(observations, "")
│   ├─ ## Findings                                    ← observations 逐条渲染为列表项
│   │                                                   无则 "No observations collected."
│   └─ ## Sources                                     ← sources 渲染为链接列表
│                                                       无则 "No sources."
│
├─ _last_ai_message(thread_state)                     ← Tier 3 兜底；倒序取最后一条 AI 消息文本
│   ├─ 遍历 messages（reversed）                       ← 匹配 "AI" 类型名且 content 非空
│   ├─ content 为 str                                  ← 直接返回
│   ├─ content 为 list                                 ← 多模态分段，拼接 text 后返回
│   └─ 无匹配                                          ← 返回空串
│
├─ _summary(observations, ai_answer)                  ← 生成 Summary 段落
│   ├─ observations 非空                               ← 取 observations[0].content（最高优先）
│   ├─ ai_answer 非空                                  ← 返回 AI 回答
│   └─ 均空                                            ← "No evidence collected yet."
│
└─ _field(item, name)                                 ← 通用字段读取，兼容 dict 与对象属性
    ├─ item 为 dict                                    ← item.get(name)
    └─ item 为对象                                     ← getattr(item, name, None)
```

### 0.2. 运行时调用树

```
① Leader 收尾阶段
LeaderAgent.run
    └─ MarkdownReporter.generate_report(thread_state, run_context)
          ├─ 读取 question ← research_question | user_input | "Research report"
          └─ 三级 fallback 判定
                ├─ final_report 非空 → 直接采用
                ├─ observations 非空 → _render_structured
                │                        ├─ _summary(observations, "")
                │                        └─ _field(obs/src, name) × N
                └─ 否则              → _last_ai_message
                                          └─ 倒序遍历 messages，取最后一条 AI 文本
        ═══════════ 返回 ═══════════
    └─ return ReportResult(final_report)

② 事件发送（不在本文件）
LeaderAgent.run 发 report.generated 事件   ← F1：reporter 只产文本，不发事件
```

### 0.3. 补充

**`markdown_reporter.py` 是报告收尾的"文本渲染器"——把 thread_state 里已有的证据按优先级渲染成一份 Markdown，不参与证据收集与事件发送。**

几点补充：

- **纯渲染、无副作用**：本文件只读取 thread_state、产出文本，不写状态、不发事件。
- **三级 fallback 是核心设计**：保证任意 thread_state 形态下都能返回可用 Markdown——已合成直接用、有证据就结构化渲染、无证据退回旧行为（最后一条 AI 消息）。
- **`_field` 是容错边界**：observations / sources 可能是 dict 也可能是对象，统一用 `_field` 读取，避免调用方感知数据形态差异。
- **`run_context` 保留未用**：接口签名保留 `run_context` 以兼容调用方，当前实现不消费。
- **职责外置**：`report.generated` 事件由 `agent.py`（LeaderAgent.run）发出，本文件只产文本（F1 注释标注）。
