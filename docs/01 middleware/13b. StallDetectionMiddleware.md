---

name: StallDetectionMiddleware — 检测 agent 卡死并暂停求助。

description:

【整体职责】
在 agent 反复失败、陷入死胡同时检测到「卡死（stall）」，并暂停 graph
向用户求助；如果求助次数用尽，则强制收尾。

【两个 hook 的分工】
- wrap_tool_call：记录工具失败（含异常路径），必要时置 pending_stuck 标记。
  **不在这里暂停**——因为并行 tool_calls 时暂停会打断 ToolMessage 配对，
  要等所有 ToolMessage 都就位后再暂停。
- after_model：记录 todo 状态；若 pending_stuck 为真，则在此执行暂停
  （返回 Command(goto=END)）。此时 ToolMessage 已全部就位，配对完整。

【暂停的实现】
after_model 返回 Command(goto=END)，把 graph 跳到终点，交回用户。
为了在 resume 时消息历史合法，暂停前会把所有悬空 tool_call 补上占位
ToolMessage。DanglingToolCallMiddleware 会在 resume 时兜底修补剩余缺口。

【求助次数上限】
max_help_requests 用尽后，不再暂停求助，而是走 _force_finalize 强制收尾。

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 方法）

```
StallDetectionMiddleware — detect agent dead-ends and pause for help
│
└─ class StallDetectionMiddleware(AgentMiddleware)
    ├─ state_schema = ThreadState
    │
    ├─ __init__(max_help_requests=3)
    │   ← 三张按 run_id 索引的表：
    │      _trackers / _help_counts / _pending_stuck
    │
    ├─ 【按 run_id 存取 tracker / 计数】
    │   ├─ _get_tracker(runtime)              ← run_id → StallTracker（懒创建）
    │   ├─ _help_count(runtime)               ← run_id → 已求助次数
    │   └─ _increment_help(runtime)           ← 求助次数 +1
    │
    ├─ 【检测与判定】
    │   ├─ _check_and_flag_stuck(runtime, tool_name, tool_input, error)
    │   │   ← 记失败 + 若 stuck 置 _pending_stuck[run_id] = True
    │   ├─ _check_stuck_and_pause(state, runtime)
    │   │   ← 判定是否暂停 / 强制收尾，补齐悬空 ToolMessage，返回 Command
    │   └─ _force_finalize(state, runtime, tracker)
    │       ← 求助用尽后的强制收尾 Command
    │
    ├─ 【hook】
    │   ├─ after_model(state, runtime)        ← 记 todos；pending_stuck → 暂停
    │   ├─ aafter_model(state, runtime)       ← 转调同步版
    │   ├─ wrap_tool_call(request, handler)   ← 记失败 / 成功衰减；不暂停
    │   └─ awrap_tool_call(request, handler)  ← 同同步版，await handler
```

### 0.2. 运行时调用树（记录失败 → 标记 → 暂停）

```
【阶段 A：工具调用 — wrap_tool_call / awrap_tool_call】

wrap_tool_call / awrap_tool_call
│
├─ tool_name / tool_input
├─ try: result = handler(request) / await handler(request)
│
├─ except Exception as exc:
│   ├─ _check_and_flag_stuck(runtime, tool_name, tool_input, str(exc))
│   │   ├─ tracker.record_tool_failure(...)
│   │   └─ if tracker.stuck: _pending_stuck[run_id] = True
│   └─ raise                                  ← 不在此暂停
│
├─ if result 是 ToolMessage(status="error"):
│   └─ _check_and_flag_stuck(runtime, tool_name, tool_input, str(result.content))
│
├─ elif result 是 ToolMessage:
│   └─ tracker.record_tool_success()          ← 衰减陈旧失败信号
│
└─ return result

【阶段 B：模型调用后 — after_model / aafter_model】

after_model / aafter_model
│
├─ tracker.record_todo_state(todos)            ← 记录 todo 状态
├─ run_id = runtime.run_id or "default"
│
└─ if _pending_stuck[run_id]:
    ├─ _pending_stuck[run_id] = False
    ├─ result = _check_stuck_and_pause(state, runtime)
    │   ├─ if not tracker.stuck:            return None
    │   ├─ if is_interrupt_protected():     return None
    │   ├─ if help_count >= max_help:       return _force_finalize(...)
    │   │
    │   └─ 正常求助路径：
    │       ├─ _increment_help(runtime)
    │       ├─ journal.append("help.requested", {run_id, reason, failures})
    │       ├─ tracker.reset()
    │       ├─ 补齐悬空 tool_call → extra_patches（ToolMessage）
    │       └─ return Command(goto=END, update={
    │            messages: extra_patches + [HumanMessage(...)]})
    │
    └─ if result:
        update = dict(result.update)
        update["jump_to"] = "end"
        return update
```

## 1. 检测 agent 卡死并暂停求助每一步怎么实现

### 步骤 1：工具失败时记录（`wrap_tool_call`）

```python
try:
    result = handler(request)
except Exception as exc:
    runtime = getattr(request, "runtime", None)
    if runtime is not None:
        self._check_and_flag_stuck(runtime, tool_name, tool_input, str(exc))
    raise
```

- 工具抛异常：先记失败，再把异常向上抛（不吞异常，不打乱上层逻辑）。
- 注意这里 **不暂停**，只记录 + 可能置 `_pending_stuck`。

```python
if isinstance(result, ToolMessage) and getattr(result, "status", None) == "error":
    ... _check_and_flag_stuck(runtime, tool_name, tool_input, str(result.content))
elif isinstance(result, ToolMessage):
    ... self._get_tracker(runtime).record_tool_success()
```

- 工具返回 `status="error"` 的 ToolMessage → 也算失败，记录。
- 工具返回正常 ToolMessage → `record_tool_success()`，
  用成功信号**衰减**陈旧的失败信号（避免「很久前失败过就一直判卡死」）。

### 步骤 2：记失败 + 标记待暂停（`_check_and_flag_stuck`）

```python
tracker = self._get_tracker(runtime)          # 取当前 run 的 tracker
tracker.record_tool_failure(tool_name, tool_input, error)
if tracker.stuck:
    run_id = _get_runtime_value(runtime, "run_id", None) or "default"
    self._pending_stuck[run_id] = True
```

- 把这次失败交给 tracker 累计判定。
- 若 tracker 判定为 `stuck`，就在 `_pending_stuck[run_id]` 打一个「待暂停」标记。
- **标记 ≠ 暂停**：这里只标记，真正暂停留给 `after_model`。

**为什么不在 `wrap_tool_call` 暂停？** 模块 docstring 里写明：

> Does NOT pause from wrap_tool_call to avoid breaking parallel tool_calls pairing — pause happens in after_model after all ToolMessages are in place.

并行 tool_calls 时如果在这里 `goto=END`，会打断 ToolMessage 配对；
等 after_model（所有 ToolMessage 已就位）再暂停才安全。

### 步骤 3：after_model 记录 todo 状态

```python
tracker = self._get_tracker(runtime)
todos = state.get("todos") or []
if todos:
    tracker.record_todo_state(todos)
```

- 每次模型调用后，把当前 todos 喂给 tracker。
- todo 状态是 tracker 判定「卡死」的重要信号之一（比如长时间没有 todo 进展）。

### 步骤 4：检查待暂停标记，触发暂停判定

```python
run_id = _get_runtime_value(runtime, "run_id", None) or "default"
if self._pending_stuck.get(run_id):
    self._pending_stuck[run_id] = False
    result = self._check_stuck_and_pause(state, runtime)
    if result is not None:
        update = dict(result.update)
        update["jump_to"] = "end"
        return update
return None
```

- 只有 `_pending_stuck[run_id]` 为真才进入暂停判定。
- 进入时先清标记（一次性消费）。
- 调 `_check_stuck_and_pause` 拿结果；有结果就把 `jump_to="end"` 加进 update 返回。
- `jump_to="end"` 配合 `@hook_config(can_jump_to=["end"])`，
  让这个 hook 能跳到 end 节点（LangGraph 的 hook 跳转机制）。

### 步骤 5：暂停判定（`_check_stuck_and_pause`）

```python
tracker = self._get_tracker(runtime)
if not tracker.stuck:
    return None                                    # 没卡死，什么都不做

if is_interrupt_protected():
    return None                                    # 中断保护中，不打扰

if self._help_count(runtime) >= self._max_help:
    return self._force_finalize(state, runtime, tracker)   # 求助用尽 → 强制收尾
```

三道闸门：

1. **tracker 判定卡死**才继续；否则直接退出。
2. **中断保护中**不打扰（保护正在进行的关键中断流程）。
3. **求助次数用尽** → 走 `_force_finalize` 强制收尾，不再求助。

### 步骤 6：正常求助路径

```python
self._increment_help(runtime)
journal = _get_runtime_value(runtime, "journal", None)
run_id = _get_runtime_value(runtime, "run_id", None)
reason = tracker.get_stuck_reason() or "unknown"
if journal is not None:
    journal.append("help.requested", {
        "run_id": run_id, "reason": reason,
        "failures": len(tracker.get_failures()),
    })

from langchain_core.messages import AIMessage
tracker.reset()
```

- 求助次数 +1（用于后续上限判断）。
- 写 journal 事件 `help.requested`，含 run_id、卡死原因、失败次数。
- `tracker.reset()`：重置卡死状态，让 resume 后重新开始判定，
  避免一恢复就又被判卡死。

### 步骤 7：补齐悬空 tool_call

```python
extra_patches: list = []
messages = state.get("messages") or []
answered_ids: set = set()
for msg in messages:
    if isinstance(msg, ToolMessage):
        answered_ids.add(msg.tool_call_id)

for msg in messages:
    if not isinstance(msg, AIMessage):
        continue
    for tc in (getattr(msg, "tool_calls", None) or []):
        tc_id = tc.get("id", "") if isinstance(tc, dict) else getattr(tc, "id", "")
        if tc_id and tc_id not in answered_ids:
            extra_patches.append(ToolMessage(
                content=f"[Skipped — stall detected ({reason})]",
                tool_call_id=tc_id,
                name=tc.get("name", "unknown") if isinstance(tc, dict) else getattr(tc, "name", "unknown"),
            ))
            answered_ids.add(tc_id)
```

- 第一遍：收集所有已应答的 `tool_call_id`。
- 第二遍：对每条 AIMessage 的每个 tool_call，
  若 id 非空且未应答 → 补一条占位 ToolMessage，并加入 answered_ids。
- 代码注释解释了原因：

> If we skip ToolNode while AIMessage(tool_calls=[...]) is in state, the next run restores the checkpoint and immediately gets a 400 from LLM.

也就是：跳 END 会绕过 ToolNode，若不补齐配对，
checkpoint 里就留下「有 call 没 result」的不完整历史，
下次 resume 时 LLM 直接 400。

### 步骤 8：构造 Command 暂停 graph

```python
messages_update = extra_patches + [HumanMessage(
    content=f"[STALL DETECTED] {reason}. Pausing for user help.",
    name="stall_detection",
    additional_kwargs={"hide_from_ui": True},
)]
return Command(goto=END, update={"messages": messages_update})
```

- `messages_update` 由两部分组成：
  1. 补齐的占位 ToolMessage（保配对）；
  2. 一条隐藏的 HumanMessage（`hide_from_ui=True`），
     content 标明 "[STALL DETECTED] ... Pausing for user help."。
- 这条 HumanMessage 是给用户/下游看的提示，UI 不展示。
- `goto=END`：跳终点，暂停本次 run，把控制权交回用户。

### 步骤 9：求助用尽 → 强制收尾（`_force_finalize`）

```python
if journal is not None:
    journal.append("help.exhausted", {"run_id": run_id})
```

- 写 `help.exhausted` 事件。

```python
extra_patches: list = []
... # 同样逻辑补齐悬空 tool_call，content 标 "[Skipped — help exhausted]"
```

```python
return Command(goto=END, update={"messages": extra_patches + [HumanMessage(
    content="[HELP EXHAUSTED] Maximum help requests reached. Forcing finalization.",
    name="stall_detection", additional_kwargs={"hide_from_ui": True},
)]})
```

- 与正常求助路径结构相同：补配对 + 隐藏提示 + `goto=END`。
- 区别：占位文案与最终提示不同，且不再增加求助次数。

### 步骤 10：异步路径

`aafter_model`、`awrap_tool_call` 逻辑与同步版一致：

```python
async def aafter_model(self, state, runtime):
    return self.after_model(state, runtime)      # 直接转调

async def awrap_tool_call(self, request, handler):
    result = await handler(request)              # 仅此处 await
    ...
```

## 2. 整体流程一图

```
【循环里】
工具调用
  │
  ├─ 抛异常 ──────────────┐
  ├─ ToolMessage(error) ──┤→ _check_and_flag_stuck
  └─ ToolMessage(ok) ─────┘   ├─ tracker.record_tool_failure / success
                              └─ if tracker.stuck:
                                    _pending_stuck[run_id] = True
  │
  ▼
after_model
  │
  ├─ tracker.record_todo_state(todos)
  │
  └─ if _pending_stuck[run_id]:
      ├─ 清标记
      └─ _check_stuck_and_pause(state, runtime)
          │
          ├─ not tracker.stuck → None
          ├─ is_interrupt_protected() → None
          ├─ help_count >= max_help → _force_finalize → Command(goto=END)
          │
          └─ 正常求助：
              ├─ _increment_help
              ├─ journal "help.requested"
              ├─ tracker.reset()
              ├─ 补齐悬空 tool_call → extra_patches
              └─ Command(goto=END,
                         update={messages: extra_patches + [HumanMessage(...)]})
      │
      ▼
    return update + jump_to="end"        ← hook 跳到 end 节点
      │
      ▼
    本次 run 暂停，控制权交回用户
      │
      ▼
    用户回复 → 新一轮 run
    （resume 时 DanglingToolCallMiddleware 兜底修补任何残留缺口）
```

## 3. 关键设计取舍

| 决策 | 原因 |
|---|---|
| 失败记录在 `wrap_tool_call`，暂停在 `after_model` | 并行 tool_calls 时在 wrap 暂停会打断配对；等 ToolMessage 全部就位再暂停才安全 |
| 用 `_pending_stuck` 标记而非立即暂停 | 把「检测」和「暂停」解耦，检测点可以在 wrap，暂停点必须在 after_model |
| 暂停前补齐悬空 tool_call | 跳 END 绕过 ToolNode，不补齐会在 checkpoint 留下不完整历史，resume 时 LLM 400 |
| 成功时 `record_tool_success()` | 衰减陈旧失败信号，避免「很久前失败过就一直判卡死」 |
| 求助次数上限 + `_force_finalize` | 防止无限求助；用尽后强制收尾，保证 run 能结束 |
| `tracker.reset()` 在求助时调用 | resume 后重新判定，避免一恢复就又被判卡死 |
| `is_interrupt_protected()` 检查 | 保护正在进行的中断保护流程，不在其中插入求助 |
| 全部状态按 `run_id` 索引 | 多 run 并存时不互相污染 |
