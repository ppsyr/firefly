---

name: ReflectionMiddleware — ReAct 退出闸门，简单反思（L1 充分性）。

description:

【整体职责】
当模型想退出（给最终答案、无工具调用意图）时，用 observations 对 todos
的 step 覆盖度做一次「实质充分性」判断。若判定不充分，就：
- 写 reflection_items（记录缺口）；
- 把 guidance 作为隐藏 HumanMessage 注入；
- 返回 jump_to="model"，让模型回去补研究。

【架构：外壳 + 可替换 Strategy】
- ReflectionMiddleware 是外壳：管触发时机、jump 预算、事件打点；
- 判断逻辑委托给 ReflectionStrategy（默认 SufficiencyStrategy）。
- ReflectionAction 契约预留 revise_plan / backtrack / rollback_to
  供未来 L2 / L3 扩展；L1 只用 pass / continue。

【启用范围】
仅 general / expert 模式启用。

【与 TodoMiddleware 共享 jump 预算】
两个中间件的 jump 合计 ≤ 3（_jump_budget），防止无限跳转。

## 1. 反思什么

**一句话：反思「模型给出的最终答案，有没有足够的证据支撑」。**

具体来说，反思的是 **todos 的每个步骤有没有被 observations 覆盖**，也就是
「你说你把每步都做完了，但每步真的都有证据吗？」

反思的判定对象（按优先级）：

| 检查项 | 结论 | 说明 |
|---|---|---|
| 问题类型是 personal | 不反思 | 非研究类问题，直接答即可 |
| todos 未全部 completed | 不反思 | 未完成部分归 Todo Layer 2 管 |
| 有工具持续失败（attempt≥3） | 不反思 | 放宽，避免卡死 |
| observations 为空 | 不反思 | 无证据可判 |
| 以上都不是 | **反思** | 检查每步覆盖度 |

反思的两种方式（二选一）：

**方式 A：规则判断（无 LLM 时）**

```python
covered = {_step_id(o) for o in observations if _step_id(o)}
missing = [f"todo-{i}" for i, _ in enumerate(todos)
           if f"todo-{i}" not in covered]
```

- 收集所有 observation 的 `step_id`；
- 对每个 `todo-{i}`，看是否在 covered 里；
- 有缺失 → 不充分；
- 无缺失 → 充分。

**方式 B：LLM 评估（有 LLM 时）**

把 question / todos_desc / obs_desc 交给 LLM，让它判断
「这些证据是否足以支撑研究结论」。LLM 返回 JSON，含 `sufficient` 字段。

所以反思的本质是：**「完成度」和「证据覆盖度」的交叉检查**——
todos 说做完了，但 observations 里有没有对应的证据支撑。

## 2. 反思的结果是什么

反思的结果是一个 **`ReflectionAction`**：

```python
class ReflectionAction(TypedDict):
    verdict: str                    # "pass" | "continue" | ...
    reflection_items: list[Any]     # ReflectionItem 列表
    plan: Any                       # revise_plan/backtrack 时的 plan，否则 None
    guidance: str                   # 注回模型的提示
    rollback_to: str                # backtrack 回退点（L3 预留）
```

L1 只用两种 verdict：

### 结果 A：`pass`（充分）

```python
ReflectionAction(verdict="pass", reflection_items=[],
                 plan=None, guidance="", rollback_to="")
```

- 含义：证据足够，模型可以退出。
- Middleware 收到 pass → `return None`，不拦，让 graph 正常结束。

### 结果 B：`continue`（不充分）

规则判断的 continue：

```python
ReflectionItem(
    item_id=_make_reflection_id(),
    scope="run",
    kind="gap",
    question=f"以下步骤标记完成但缺少证据覆盖：{', '.join(missing)}",
    related_refs=tuple(missing),      # 缺失的 step_id
)

guidance = (
    "<system_reminder>\n"
    f"以下研究步骤已标记完成但缺少证据支撑：{', '.join(missing)}。\n"
    "请针对这些步骤补充搜索/调研，确保每步都有 observations 证据后再给出最终答案。\n"
    "</system_reminder>"
)
```

LLM 评估的 continue：

```python
ReflectionItem(
    item_id=_make_reflection_id(),
    scope="run",
    kind="gap",
    question="LLM 评估证据不足以支撑研究结论",
    related_refs=(),
)

guidance = (
    "<system_reminder>\n"
    "LLM 评估认为当前证据不足以充分支撑研究结论，请补充搜索/调研后再给出最终答案。\n"
    "</system_reminder>"
)
```

### 特殊结果：`pass` + guidance（personal 问题）

```python
ReflectionAction(
    verdict="pass", reflection_items=[], plan=None,
    guidance=(
        "<system_reminder>\n"
        "该问题似乎不需要深度研究。建议 /default 模式对话，"
        "或提供更具体的研究方向。当前将直接回答。\n"
        "</system_reminder>"
    ),
    rollback_to="",
)
```

这是「pass 但带提示」——不拦，但告诉模型「这题不太像研究题」。

### continue 之后 middleware 做什么

```python
# 消费 jump 预算
if not _jump_budget.try_consume(runtime):
    self._emit(runtime, "reflection.budget_exhausted", {...})
    return None

# 发事件
self._emit(runtime, "reflection.fired", {
    "verdict": action["verdict"],
    "gap_steps": gap_steps,
    "remaining_budget": _jump_budget.remaining(runtime),
})

# 组装 update
update = {"reflection_items": action["reflection_items"]}
if action["guidance"]:
    update["messages"] = [HumanMessage(
        name="reflection",
        additional_kwargs={"hide_from_ui": True},
        content=action["guidance"],
    )]
if action["plan"]:
    update["plan"] = action["plan"]

return {"jump_to": "model", **update}
```

三件事：

1. **写 `reflection_items`**：把缺口记进 state，供后续审计 / 展示；
2. **注入 guidance**：作为隐藏 HumanMessage，模型能看到「你缺哪些证据」；
3. **`jump_to="model"`**：跳回 model 节点，让模型回去补研究。

## 3. 结果汇总表

| verdict          | reflection_items          | guidance | 动作                     |
| ---------------- | ------------------------- | -------- | ---------------------- |
| `pass`           | `[]`                      | `""`     | 不拦，graph 正常结束          |
| `pass`（personal） | `[]`                      | 提示文本     | 不拦，但注入「建议用 default 模式」 |
| `continue`（规则）   | 1 个 gap item（含缺失 step 列表） | 提示补研究    | jump_to="model"，回去补    |
| `continue`（LLM）  | 1 个 gap item（无 step 列表）   | 提示补研究    | jump_to="model"，回去补    |

---

## 4. 与相邻中间件的关系

- **TodoMiddleware**：管「完成度」（todos 有没有全 completed）；
  **ReflectionMiddleware**：管「充分性」（completed 的步骤有没有证据）。
  两者互补：Todo 管「做没做完」，Reflection 管「做完的部分有没有证据」。
- **共享 jump 预算**：`_jump_budget` 让 Todo 和 Reflection 的 jump 合计 ≤ 3，
  防止两个中间件互相触发导致无限跳转。
- **持续失败放行**：两者都检查 `_has_persistent_failures`，
  工具反复失败时不强制补研究，让任务能收尾。

一句话：**反思的是「证据够不够」，结果是「够就放行（pass）、不够就跳回去补（continue + jump_to=model）」。**
