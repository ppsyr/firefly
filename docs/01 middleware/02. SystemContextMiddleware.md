---

name:SystemContextMiddleware — before_model 注入 system_context 元数据。

description:

【整体职责】
在每次进入 model 之前，往 state 的 metadata 里写入一份 system_context，内容是当前 agent 的身份标识与运行时区。下游（如 prompt 渲染、trace 审计、系统提示拼装）可以据此拿到「我是谁、现在是什么时区」这类元信息。
  
【时区来源】
时区不是写死的，而是通过 _get_runtime_value 从 runtime 上读取：
- 取到则用 runtime 上的 "timezone"；
- 取不到则回退默认值 "Asia/Shanghai"。
  
【只写 metadata】
本中间件只往 metadata 里塞 system_context，不改 messages、不改其他 state 字段，属于轻量、幂等的元数据注入。

### 0.1. 静态结构树（模块 → 类 → 方法）


## 1. state、message、metadate

| 概念           | 层级    | 本质                                                | 谁持有                     |
| ------------ | ----- | ------------------------------------------------- | ----------------------- |
| **message**  | 对话内容层 | 一次具体的对话消息（Human / AI / Tool / System）             | `state["messages"]` 列表里 |
| **state**    | 图状态层  | 整个 agent 运行期的共享状态容器（含 messages、governance、todos…） | LangGraph 的 ThreadState |
| **metadata** | 附属信息层 | 挂在 state 上的**附属说明字段**，不是对话内容，也不参与对话               | `state["metadata"]` 里   |

一句话：**state 是总容器，message 是容器里"对话"那一格，metadata 是容器里"说明/注解"那一格。**

---


### 1.1. message（对话消息）

装的是**真正参与对话的内容**：

```python
HumanMessage(content="帮我查一下...")          # 用户说的
AIMessage(content="好的", tool_calls=[...])    # 模型说的 / 要调工具
ToolMessage(content="查询结果...", name="search")  # 工具返回的
SystemMessage(content="你是一个...")            # 系统提示
```

特点：
- 有**角色**（user / assistant / tool / system）。
- 有**顺序**（时间线），LLM 靠它理解上下文。
- 送 LLM 时会被渲染成 prompt（本仓库就是渲染成 XML 标签序列）。

### 1.2. state（图状态）

装的是**整个 agent 运行期的所有共享数据**，messages 只是其中一格：

```python
ThreadState = {
    "messages":     [...],        # ← message 列表在这里
    "metadata":     {...},        # ← metadata 在这里
    "governance":   {...},        # 治理配置
    "todos":        [...],        # 计划
    "reflection_items": [...],    # 反思
    "research_question": "...",   # 目标
    "tagged_context": {...},      # trace 快照
    ...
}
```

特点：
- 是 LangGraph 节点间**传递的共享内存**。
- 每个节点/hook 读它、返回 patch 改它。
- 是 checkpoint 持久化的对象（落盘的是 state）。

### 1.3. metadata（元数据）

装的是**关于这次运行的说明性信息**，不是对话内容：

```python
state["metadata"] = {
    "system_context": {
        "agent": "Poirot deep research agent",
        "timezone": "Asia/Shanghai",
    },
    ...
}
```

特点：
- 不参与对话，不进 prompt（除非有人显式去读它）。
- 给下游代码（prompt 拼装、trace、审计、UI）读的**注解**。
- 通常轻量、幂等。

## 2. 三者的联系

```
ThreadState（总容器，LangGraph 持有，可持久化）
│
├─ "messages": [ HumanMessage, AIMessage, ToolMessage, ... ]   ← 对话层
│      · 有时间顺序
│      · 送 LLM 时渲染成 prompt
│      · 每个元素可带 additional_kwargs（层 2 标记）
│
├─ "metadata": { system_context: {...}, ... }                   ← 注解层
│      · 无顺序、不参与对话
│      · 给下游代码读
│
└─ 其他字段：governance / todos / reflection_items / ...
```

关系要点：

1. **state 包含 message 和 metadata**：后两者都是 state 的字段，不是并列的同级概念。
2. **message 是内容，metadata 是注解**：一个进 prompt，一个不进（除非显式读）。
3. **additional_kwargs 是 message 的"私有 metadata"**：本仓库的 `poirot.*` 标记就挂在 `message.additional_kwargs` 上，属于「单条消息自己的注解」；而 `state["metadata"]` 是「整个运行的注解」。两者层级不同：
   - `message.additional_kwargs["poirot.thinking"]` → 这条 AI 消息带思维链
   - `state["metadata"]["system_context"]` → 这次运行的 agent 身份/时区
4. **中间件读写路径不同**：
   - `SystemContextMiddleware` 写 `state["metadata"]`；
   - `TaggedContextMiddleware` 读 `state["messages"]` 渲染 prompt，并读 `message.additional_kwargs` 判断怎么渲染；
   - `StrategyMiddleware` 读整个 state 做治理决策，返回 state patch。

---

### 2.1. 用一份代码对照（本仓库实际）

```python
# message 层：单条消息 + 它自己的 additional_kwargs
AIMessage(
    content="...",
    additional_kwargs={"poirot.thinking": True, "reasoning_content": "..."}
)

# metadata 层：整个运行的注解
{"metadata": {"system_context": {"agent": "...", "timezone": "Asia/Shanghai"}}}

# state 层：总容器，把上面都装进去
{
    "messages": [AIMessage(...), HumanMessage(...)],   # message 列表
    "metadata": {...},                                  # metadata
    "governance": {...},
    "todos": [...],
    ...
}
```

---

- **message**：说了什么（内容，有顺序，进 prompt）。
- **state**：现在整个运行是什么样（总容器，可持久化）。
- **metadata**：关于这次运行的说明（注解，不进对话）。
- **additional_kwargs**：单条 message 自己的注解（介于 message 和 metadata 之间，但归属 message）。
