# `_build_middlewares` 中间件注册与调用链路

本文按 `_build_middlewares` 的创建顺序逐段整理，覆盖 22 个中间件。每段包含：创建代码 → 中间件详情（模块位置、钩子作用、触发条件、定位）。

---

## 0. 结构树

### 0.1. 静态结构树（创建顺序 → 中间件 → 钩子）

```
_build_middlewares(expert_mode, model, ...)
│
├─ 第 1 段：治理层（context_governance is not None）
│   ├─ 1a. TaggedContextMiddleware
│   │   ├─ wrap_model_call / awrap_model_call   ← XML 标签序列渲染
│   │   └─ after_model                          ← trace 审计
│   ├─ 1b. MessageNormalizerMiddleware
│   │   └─ wrap_model_call / awrap_model_call   ← 合并 SystemMessage 为单条 leading
│   └─ 1c. StrategyMiddleware
│       ├─ before_agent / abefore_agent
│       ├─ after_agent / aafter_agent
│       ├─ before_model / abefore_model         ← can_jump_to=["model"]
│       ├─ after_model / aafter_model           ← can_jump_to=["model"]
│       ├─ wrap_model_call / awrap_model_call   ← PRE
│       └─ wrap_tool_call / awrap_tool_call     ← POST
│
├─ 第 2 段：SystemContext
│   └─ 2. SystemContextMiddleware
│       └─ before_model / abefore_model         ← 注入 system_context
│
├─ 第 3 段：SkillInjection（条件挂）
│   └─ 3. SkillInjectionMiddleware
│       └─ before_model / abefore_model         ← 注入 active skills
│
├─ 第 4 段：SkillMetrics（条件挂）
│   └─ 4. SkillMetricsMiddleware
│       ├─ awrap_tool_call                       ← applied 打点（仅 async）
│       └─ after_agent / aafter_agent           ← completions/fallbacks 归因
│
├─ 第 5 段：SkillActivation（条件挂）
│   └─ 5. SkillActivationMiddleware
│       └─ before_model                          ← 关键词建议（仅 sync，无 async）
│
├─ 第 6 段：Title + RunJournal
│   ├─ 6a. TitleMiddleware
│   │   └─ after_agent / aafter_agent           ← metadata.title
│   └─ 6b. RunJournalMiddleware
│       ├─ before_agent / after_agent           ← agent.started / finished
│       ├─ before_model / after_model           ← llm.request / response
│       └─ wrap_tool_call / awrap_tool_call     ← tool.called / finished
│
├─ 第 7 段：MCP Audit（条件挂）
│   └─ 7. McpAuditMiddleware
│       └─ awrap_tool_call                       ← 熔断器 + 审计（仅 async）
│
├─ 第 8 段：Sandbox（条件挂）
│   └─ 8. SandboxMiddleware
│       ├─ abefore_model                         ← 恢复 ContextVar
│       ├─ awrap_tool_call                       ← acquire + present_files
│       └─ aafter_agent                          ← release（仅 async）
│
├─ 第 9 段：Memory（条件挂）
│   └─ 9. MemoryMiddleware
│       ├─ abefore_model                         ← 召回注入
│       └─ aafter_model                          ← 清除 turn_id（仅 async）
│
├─ 第 10 段：MemoryConsolidation（条件挂）
│   └─ 10. MemoryConsolidationMiddleware
│       ├─ abefore_model                         ← no-op
│       └─ aafter_model                          ← 每 N 轮 submit 任务（仅 async）
│
├─ 第 11 段：HelpRequest + DanglingToolCall + ToolCall
│   ├─ 11a. HelpRequestMiddleware
│   │   └─ wrap_tool_call / awrap_tool_call     ← 拦截 ask_help 暂停
│   ├─ 11b. DanglingToolCallMiddleware
│   │   └─ before_model / abefore_model         ← 修补悬空 tool_call
│   └─ 11c. ToolCallMiddleware
│       ├─ before_agent                         ← 记录 baseline
│       ├─ before_model / abefore_model         ← drain 摘要
│       └─ wrap_tool_call / awrap_tool_call     ← 账本 + 预算 + 重试
│
├─ 第 12 段：Orchestration（条件挂）
│   └─ 12. OrchestrationMiddleware
│       └─ wrap_tool_call / awrap_tool_call     ← 横切打点 + 产物汇总
│
├─ 第 13 段：Evidence + StallDetection + Todo + Reflection
│   ├─ 13a. EvidenceMiddleware
│   │   └─ wrap_tool_call / awrap_tool_call     ← 证据抽取
│   ├─ 13b. StallDetectionMiddleware
│   │   ├─ wrap_tool_call / awrap_tool_call     ← 记录失败
│   │   └─ after_model / aafter_model           ← 暂停求助
│   ├─ 13c. TodoMiddleware
│   │   ├─ before_agent / abefore_agent         ← 清理 + 重置
│   │   ├─ before_model / abefore_model         ← Layer 1 + Layer 3
│   │   ├─ after_model / aafter_model           ← Layer 2 完成度强制
│   │   ├─ wrap_model_call / awrap_model_call   ← 注入完成度提醒
│   │   └─ after_agent / aafter_agent           ← 清理
│   └─ 13d. ReflectionMiddleware
│       └─ after_model / aafter_model           ← L1 充分性反思
│
└─ 第 14 段：Report（model is not None）
    └─ 14. ReportMiddleware
        └─ after_agent / aafter_agent           ← 独立合成 final_report
```

### 0.2. 运行时调用树

```
用户发起会话
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【before_agent】进入 agent 前（每轮 1 次｜执行方向：正序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │  注册顺序：
│   │    1c. Strategy → 6b. RunJournal → 11c. ToolCall → 13c. Todo
│   │  执行顺序：正序（与注册一致）
│   │
│   ├─ ① 1c. StrategyMiddleware.before_agent
│   │   ├─ 路由到治理 bundle.before_agent(ctx)
│   │   ├─ 应用 state_patch / metrics / jump_to
│   │   └─ 作用：让治理策略在 run 正式开始前完成"出厂设置"——写 governance 状态、
│   │             启动统计、预算计数器归零。后面所有治理决策都基于这里建立的状态。
│   │             缺了它，治理策略会读到上一轮的脏状态。
│   │
│   ├─ ② 6b. RunJournalMiddleware.before_agent
│   │   ├─ 写 journal 事件 "agent.started"（含 run_id）
│   │   └─ 作用：在磁盘事件流（events.jsonl）里打上"本次 run 开始"的锚点，
│   │             与末尾 "agent.finished" 配对，构成完整 run 时间区间。
│   │             用途：① UI 计时；② 回放/审计；③ 排查"run 没结束"。
│   │
│   ├─ ③ 11c. ToolCallMiddleware.before_agent
│   │   ├─ 记录 state.errors 长度作为 baseline
│   │   ├─ 清理其他 run 的陈旧队列 + 基线
│   │   └─ 作用：建立 per-run 计数基准（本轮工具调用数 = len(errors) - baseline），
│   │             避免跨 run 累积；防止旧 run 残留污染新 run——跨 run 隔离关键。
│   │
│   └─ ④ 13c. TodoMiddleware.before_agent
│       ├─ _clear_other_runs（清同 thread 下其他 run 的完成度状态）
│       ├─ _reset_nag_counters（重置 steps_since_write / steps_since_reminder /
│       │                       last_write_count）
│       └─ 作用：让 Nag 提醒节奏从零开始，避免上一轮步数影响本轮——
│                 Nag 是累积计数，不清零会继承残留值；同时清旧 run 的提醒队列。
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【before_model】每次模型调用前（每轮多次｜执行方向：正序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │  注册顺序：
│   │    1c. Strategy → 2. SystemContext → 3. SkillInjection →
│   │    5. SkillActivation → 6b. RunJournal → 11b. DanglingToolCall →
│   │    9. Memory → 10. MemoryConsolidation → 11c. ToolCall → 13c. Todo
│   │  执行顺序：正序（与注册一致）
│   │
│   ├─ ① 1c. StrategyMiddleware.before_model
│   │   ├─ 路由到 bundle.before_model(ctx)
│   │   ├─ 应用治理结果（can_jump_to=["model"]）
│   │   └─ 作用：模型调用前最后一道治理决策点，可跳回 model 或改写 state。
│   │             上下文预算/压缩策略的接入点（超预算时触发压缩）。
│   │
│   ├─ ② 2.  SystemContextMiddleware.before_model
│   │   ├─ 从 runtime 取 timezone
│   │   ├─ 写 metadata.system_context（agent 身份 + 时区）
│   │   └─ 作用：给下游提供「我是谁、现在几点」元信息（供 prompt 拼装 / trace / UI）。
│   │             让"时间"这类全局信息只算一次、多处复用。
│   │
│   ├─ ③ 3.  SkillInjectionMiddleware.before_model
│   │   ├─ 混合来源选 skill（runtime.skill_override / metadata.skill_override
│   │   │                      + selector 自动选）
│   │   ├─ 命中则：record_selection + journal "skill.select" + build_injection_text
│   │   │          + 发 skill_active 事件 + 写 ContextVar _active_skills_ctx /
│   │   │            _applied_ctx + 返回 SystemMessage(injection) + metadata.active_skills
│   │   └─ 作用：把本轮该用的 skill 内容真正送进模型上下文 + 留 provenance 锚点，
│   │             供 SkillMetrics 在工具调用后判定「是否真的用上了」。没有它，
│   │             skill 就只是磁盘上的文件，模型永远看不到。
│   │
│   ├─ ④ 5.  SkillActivationMiddleware.before_model
│   │   ├─ 取最后一条 message 的 content
│   │   ├─ 用 _KEYWORD_MAP 关键词匹配
│   │   ├─ 返回 {"skill_suggestion": [{"keyword", "skill"}, ...]}
│   │   └─ 作用：零 LLM 成本地主动建议相关 skill（写旁路字段，不改 system prompt，
│   │             保护 prompt caching），让 lead agent 自己决定是否进一步 skill_search。
│   │             与 SkillInjection 的区别：Injection 是"强注入"（模型必然看到），
│   │             Activation 是"软建议"（模型可选读）——提示而非命令。
│   │
│   ├─ ⑤ 6b. RunJournalMiddleware.before_model
│   │   ├─ 写 journal "llm.request"（含 run_id / model）
│   │   └─ 作用：标记本轮 LLM 调用开始，与 "llm.response" 配对成完整计时。
│   │             用途：算单次调用延迟 / 审计调用次数 / 排查"调用卡住"。
│   │
│   ├─ ⑥ 9.  MemoryMiddleware.abefore_model
│   │   ├─ 从最后一条 HumanMessage 提 query
│   │   ├─ retrieve 召回 → 格式化 + token 裁剪
│   │   ├─ 注入 HumanMessage(name="memory_recall", hide_from_ui=True)
│   │   ├─ 写 recalled_memories（只存 id + score + strength）
│   │   └─ 作用：把长期记忆里相关片段召回进本轮上下文，解决 LLM 无状态问题。
│   │             关键设计：per-call HumanMessage（保护 caching）+ hide_from_ui
│   │             （UI 不显示）+ 只存索引（避免 state 膨胀）。
│   │
│   ├─ ⑦ 10.  MemoryConsolidationMiddleware.abefore_model
│   │   └─ no-op（沉淀只在 after_model；占位保证 hook 链完整）
│   │
│   ├─ ⑧ 11b. DanglingToolCallMiddleware.before_model
│   │   ├─ 扫描 messages：收集已应答的 tool_call_id
│   │   ├─ 对 AIMessage 里未应答的 tool_call 补占位 ToolMessage
│   │   └─ 作用：修复"有 tool_call 没 tool_result"的不完整历史，防止下一轮
│   │             模型调用直接 400——场景：graph 因 help/interrupt 暂停后
│   │             resume，历史缺 ToolMessage。严格后端要求 tool_calls 后必须
│   │             紧跟 ToolMessage。它是 resume 场景的"历史修复器"。
│   │
│   ├─ ⑨ 11c. ToolCallMiddleware.before_model
│   │   ├─ drain 队列里的 failure_summary / budget_exhausted 提示
│   │   ├─ 拼成隐藏 HumanMessage(name="tool_failure_summary")
│   │   └─ 作用：把「连续失败摘要」「预算耗尽」延迟到此时注入
│   │             （before_model 在 ToolNode 之后，ToolMessage 已就位，不破坏配对）。
│   │             wrap_tool_call 里只"入队"，此处才"出队注入"——延迟注入解法。
│   │
│   └─ ⑩ 13c. TodoMiddleware.before_model
│       ├─ Layer 1：todos 存在但 messages 里看不到 write_todos → 注入 todo_reminder
│       ├─ Layer 3：双阈值 Nag（steps_since_write ≥ 5 AND steps_since_reminder ≥ 5
│       │                AND len(todos) ≥ 3 AND 有未完成）→ 注入 todo_nag
│       └─ 作用：Layer 1 防 write_todos 被截断后「忘了有计划」（防失忆）；
│                 Layer 3 双阈值（AND）既防忘记（很久没更新）又防打扰（每步提醒）。
│                 触发后只重置 reminder 计数（不重置 write 计数）。
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【wrap_model_call】包住模型调用（每轮多次｜PRE 正序 / POST 反序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │  注册顺序：
│   │    1a. TaggedContext → 1b. MessageNormalizer → 1c. Strategy → 13c. Todo
│   │  PRE 执行（正序，外→内）：1a → 1b → 1c → 13c
│   │  POST 执行（反序，内→外）：13c → 1c → 1b → 1a
│   │
│   ├─ ① 1a. TaggedContextMiddleware.wrap_model_call（最外层）
│   │   ├─ PRE：调 ContextAssembler 渲染扁平 XML 标签序列
│   │   │     （<goal><plan><reflection><summary><date><turn>
│   │   │       <thinking><answer><toolresult> 等）
│   │   ├─ request.override(messages=...) 送 LLM
│   │   └─ 作用：把 state 各字段渲染成结构化 XML 上下文送给 LLM——
│   │             state → messages 的核心转换器。research_question→<goal>、
│   │             todos→<plan>、reflection_items→<reflection>、
│   │             governance.summary→<summary>、日期→<date>，对话历史改写成
│   │             <thinking><answer><toolresult> 序列。request-scoped 不持久。
│   │
│   ├─ ② 1b. MessageNormalizerMiddleware.wrap_model_call
│   │   ├─ PRE：合并 request.system_message 与 messages 里所有 SystemMessage
│   │   │       为单条 leading SystemMessage
│   │   ├─ 从 messages 里移除所有 SystemMessage
│   │   └─ 作用：把多个 SystemMessage 合并成一条"开头的" SystemMessage，
│   │             满足 vLLM / Qwen / Anthropic 等严格后端「只允许一条 leading
│   │             SystemMessage」的要求。散落多处会直接 400——消息格式规范化器。
│   │
│   ├─ ③ 1c. StrategyMiddleware.wrap_model_call
│   │   ├─ PRE：bundle.wrap_model_call(ctx)
│   │   ├─ 若 request_override 非空则替换 request
│   │   └─ 作用：治理策略在模型调用前"最后改写 request"的机会——
│   │             裁剪 messages（超预算时）、换 model（路由调整）、改 system prompt。
│   │             与 before_model 区别：before_model 改 state，wrap_model_call
│   │             直接改"送 LLM 的 request"。
│   │
│   ├─ ④ 13c. TodoMiddleware.wrap_model_call（最内层）
│   │   ├─ PRE：drain 队列里的完成度提醒
│   │   ├─ 追加 HumanMessage(name="todo_completion_reminder", hide_from_ui=True)
│   │   ├─ 再交给 super().wrap_model_call
│   │   └─ 作用：把 after_model 里排队的「todos 未完成」提醒在送 LLM 前注入——
│   │             after_model 判定"模型想给答案但 todos 没做完"→ jump 回 model
│   │             + 入队提醒；此处才真正把提醒注入 messages，逼模型继续处理。
│   │             它是"完成度强制"的最后一环。
│   │
│   └─ ⑤ handler → LLM（最内层）
│       └─ 真正发起模型调用
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【LLM 调用 → 模型返回】
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   └─ FallbackChatModel.invoke/ainvoke
│       ├─ 从 _active 轮转链内 provider
│       ├─ ChatDeepSeek / ChatOpenAI / ... 发请求、流式收 token
│       ├─ 成功 → 更新 _active，返回
│       └─ 失败 → _should_fallback → 降级下一个
│       └─ 作用：在"模型调用"这一层提供运行时容错——维护一条 provider 降级链
│                 （如 deepseek → openai → qwen）。每次从上次成功的 provider
│                 开始试，遇瞬时错误自动降级，成功则记住位置。只降级瞬时错误
│                 （客户端错误如 400 直接抛）。是模型层的高可用网关。
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【after_model】每次模型调用后（每轮多次｜执行方向：反序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │  注册顺序：
│   │    1a. TaggedContext → 1c. Strategy → 6b. RunJournal →
│   │    9. Memory → 10. MemoryConsolidation → 13b. StallDetection →
│   │    13c. Todo → 13d. Reflection
│   │  执行顺序：反序（注册逆序）——
│   │    13d. Reflection → 13c. Todo → 13b. StallDetection →
│   │    10. MemoryConsolidation → 9. Memory → 6b. RunJournal →
│   │    1a. TaggedContext → 1c. Strategy
│   │
│   ├─ ① 13d. ReflectionMiddleware.after_model（最先执行）
│   │   ├─ 取最后一条 AIMessage；有工具调用意图 → 不拦
│   │   ├─ strategy.reflect(state) → verdict=="pass" → 不拦
│   │   ├─ jump 预算耗尽 → 发 reflection.budget_exhausted + 不拦
│   │   ├─ 否则：发 reflection.fired + 写 reflection_items + 注入 guidance
│   │   │        + jump_to="model"
│   │   └─ 作用：ReAct 循环的"退出闸门"——模型想给最终答案时检查"证据是否充分"，
│   │             不充分就跳回去补研究，防止"急着交卷"。与 Todo 共享 jump
│   │             预算（合计 ≤3），防止无限跳转——质量守门人。
│   │
│   ├─ ② 13c. TodoMiddleware.after_model
│   │   ├─ super().after_model（基类 parallel write_todos 检测）
│   │   ├─ _infer_current_step_id 更新 current_step_id
│   │   ├─ 仅拦截「干净的最终答案」（无工具调用意图）
│   │   ├─ 放行条件：enforce_completion=False / todos 全完成 / 持续失败 /
│   │   │            强制次数超限 / jump 预算耗尽
│   │   └─ 否则 → 入队完成度提醒 + jump_to="model"
│   │   └─ 作用："完成度强制"——todos 没做完但模型想交卷时把它拽回来继续做。
│   │             与 Reflection 分工：Reflection 管"证据充分性"，Todo 管
│   │             "任务完成度"。防止模型"跳步"——任务守门人。
│   │
│   ├─ ③ 13b. StallDetectionMiddleware.after_model
│   │   ├─ record_todo_state(todos)
│   │   ├─ 若 _pending_stuck[run_id] 为真 → 清标记 + _check_stuck_and_pause：
│   │   │     ├─ 未中断保护 + 未达 help 上限
│   │   │     │     → 递增 help_count + journal "help.requested"
│   │   │     │     → tracker.reset() + 补悬空 ToolMessage + Command(goto=END)
│   │   │     └─ 已达上限 → _force_finalize（Command(goto=END)）
│   │   └─ 作用：检测到 agent "卡死"时暂停 graph 向用户求助。为什么暂停放
│   │             after_model 而非 wrap_tool_call？因为并行 tool_calls 时暂停
│   │             会打断 ToolMessage 配对——必须等所有 ToolMessage 就位。
│   │             价值：卡死时把控制权交回用户（不无限空转烧 token）；
```

### 1a. `TaggedContextMiddleware`

**模块**：`middlewares/tagged_context_middleware.py`

| 钩子 | 作用 |
|---|---|
| `wrap_model_call` / `awrap_model_call` | 调 `ContextAssembler` 渲染扁平 XML 标签序列（`<goal>` / `<plan>` / `<reflection>` / `<summary>` / `<date>` / `<turn>` / `<thinking>` / `<answer>` / `<toolresult>`），`request.override(messages=...)` 送 LLM。request-scoped 不持久。 |
| `after_model` | trace 审计：从 `state.messages` 重组渲染写 `state.tagged_context`（`{rendered, created_at}`），供审计/持久快照。 |

**触发条件**：`context_governance is not None`（几乎总是存在）。

**定位**：把送 LLM 的上下文渲染成结构化 XML 标签，并留下 trace 快照。是所有上下文的「渲染层」。

---

### 1b. `MessageNormalizerMiddleware`

**模块**：`middlewares/message_normalizer_middleware.py`

| 钩子 | 作用 |
|---|---|
| `wrap_model_call` / `awrap_model_call` | 合并多条 `SystemMessage` + `request.system_message` 为**单条 leading SystemMessage**，从 `request.messages` 里移除所有 SystemMessage。仅动 request payload，不动 checkpoint state。 |

**触发条件**：`context_governance is not None`。

**定位**：strict backend（vLLM/Qwen/Anthropic）拒绝非 leading SystemMessage，本中间件保证请求合法。

---

### 1c. `StrategyMiddleware`

**模块**：`context_engineering/strategy_middleware.py`

| 钩子 | 作用 |
|---|---|
| `before_agent` / `abefore_agent` | 路由到 `bundle.before_agent(ctx)`，`apply_governance_result` 应用 state_patch/metrics/jump_to。 |
| `after_agent` / `aafter_agent` | 路由到 `bundle.after_agent(ctx)`，应用结果。 |
| `before_model` / `abefore_model` | 路由到 `bundle.before_model(ctx)`，应用结果（`can_jump_to=["model"]`）。 |
| `after_model` / `aafter_model` | 路由到 `bundle.after_model(ctx)`，应用结果（`can_jump_to=["model"]`）。 |
| `wrap_model_call` / `awrap_model_call` | **PRE**：`bundle.wrap_model_call(ctx)` → 若 `request_override` 非空则替换 request → `handler(req)`。state_patch/metrics 不适用（wrap 返 `ModelCallResult`）。 |
| `wrap_tool_call` / `awrap_tool_call` | **POST**：先 `handler(request)` 取 result → `bundle.wrap_tool_call(ctx)` → 若 `request_override` 非空则返回它，否则返回原 result。 |

**触发条件**：`context_governance is not None` + `config.strategy` 已注册。

**定位**：**6 hook adapter**，把 6 个钩子路由到策略 bundle。是治理策略的统一入口。

```python
def make_lead_agent(
    expert_mode: bool = False,
    capability_registry: CapabilityRegistry | None = None,
    middleware_manager: Any = None,
    runnable_config: RunnableConfig | None = None,
    context_governance: Any = None,
    sandbox_provider: Any = None,
    artifact_server: Any = None,
    mcp_audit_middleware: Any = None,
    skill_injection_middleware: Any = None,
    skill_metrics_middleware: Any = None,
    specialist_tools: list[BaseTool] | None = None,
    orchestration_middleware: Any = None,
    memory_provider: Any = None,
    memory_config: Any = None,
    memory_worker: Any = None,
) -> Any:
    """App-layer factory: expert_flag 参数化装配 graph。

    - middleware: _build_middlewares(expert_mode) 全挂参数化
    - tools: get_available_tools(groups=...) 按 expert 选 core / core+deferred
    - system_prompt: apply_prompt_template(expert_mode, specialist_registry=...)
      — specialist_registry 非空时条件注入 <specialist_routing> 段（Bug B 修复）
    - checkpointer: get_checkpointer() 单例，thread_id 跨轮 + 跨模式保留 state

    Registry MUST store BaseChatModel / BaseTool instances directly.
    """
    from poirot.backend.agents.leader.agent import LeaderAgent

    if runnable_config is not None and "configurable" in runnable_config:
        registry = runnable_config["configurable"].get("capability_registry")
    else:
        registry = capability_registry
        runnable_config = {"configurable": {"expert_mode": expert_mode, "capability_registry": registry}}

    if registry is None:
        raise ValueError("capability_registry is required (in configurable or as param)")

    configurable = runnable_config.get("configurable", {})
    # runnable_config 透传的 expert_mode 优先，否则用参数
    resolved_expert = bool(configurable.get("expert_mode", expert_mode))

    model = registry.get_model("researcher")

    # summarize_model 独立取：config.params.summarize_model 配名 → registry 取独立 model；否则 None（fallback research model）
    summarize_model = None
    if context_governance is not None:
        sm_name = (getattr(context_governance, "params", None) or {}).get("summarize_model")
        if sm_name:
            try:
                summarize_model = registry.get_model(sm_name)
            except Exception:
                summarize_model = None

    # tool groups: default=core, expert=core+deferred
    groups = ["core", "deferred"] if resolved_expert else ["core"]
    tools: list[BaseTool] = []
    for tool in get_available_tools(groups=groups):
        if isinstance(tool, BaseTool) and tool not in tools:
            tools.append(tool)
    # registry 额外注册的工具（如 web_search_mcp 别名）保留
    for tool in registry.tools.values():
        if isinstance(tool, BaseTool) and tool not in tools:
            tools.append(tool)
    # multiagent specialist tools（delegate_to_*）
    if specialist_tools:
        for tool in specialist_tools:
            if isinstance(tool, BaseTool) and tool not in tools:
                tools.append(tool)

    return LeaderAgent(
        graph=create_agent(
            model=model,
            tools=tools or None,
            middleware=_build_middlewares(resolved_expert, model, context_governance, summarize_model, sandbox_provider, artifact_server, mcp_audit_middleware, skill_injection_middleware, skill_metrics_middleware, orchestration_middleware, memory_provider, memory_config, memory_worker),
            system_prompt=apply_prompt_template(
                expert_mode=resolved_expert,
                specialist_registry=_safe_get_specialist_registry(registry),
                skills_enabled=skill_injection_middleware is not None,
            ),
            state_schema=ThreadState,
            checkpointer=get_checkpointer(),
        ),
        capability_registry=registry,
    )
```
