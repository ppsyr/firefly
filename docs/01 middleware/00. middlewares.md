# `_build_middlewares` 中间件注册与调用链路

本文按 `_build_middlewares` 的创建顺序逐段整理，覆盖 22 个中间件。每段包含：创建代码 → 中间件详情（模块位置、钩子作用、触发条件、定位）。

同步与异步版本同时存在时，合并在表格同一行；仅单版本时单独标注。

---

## 0. 结构树

### 0.1. 静态结构树（创建顺序 → 中间件 → 钩子）

```
_build_middlewares(expert_mode, model, ...)
│
├─ 第 1 段：治理层（context_governance is not None）
│   ├─ 1a. TaggedContextMiddleware
│   │   ├─ wrap_model_call / awrap_model_call   ← XML 标签序列渲染
│   │   └─ after_model                          ← trace 审计
│   ├─ 1b. MessageNormalizerMiddleware
│   │   └─ wrap_model_call / awrap_model_call   ← 合并 SystemMessage 为单条 leading
│   └─ 1c. StrategyMiddleware
│       ├─ before_agent / abefore_agent
│       ├─ after_agent / aafter_agent
│       ├─ before_model / abefore_model         ← can_jump_to=["model"]
│       ├─ after_model / aafter_model           ← can_jump_to=["model"]
│       ├─ wrap_model_call / awrap_model_call   ← PRE
│       └─ wrap_tool_call / awrap_tool_call     ← POST
│
├─ 第 2 段：SystemContext
│   └─ 2. SystemContextMiddleware
│       └─ before_model / abefore_model         ← 注入 system_context
│
├─ 第 3 段：SkillInjection（条件挂）
│   └─ 3. SkillInjectionMiddleware
│       └─ before_model / abefore_model         ← 注入 active skills
│
├─ 第 4 段：SkillMetrics（条件挂）
│   └─ 4. SkillMetricsMiddleware
│       ├─ awrap_tool_call                       ← applied 打点（仅 async）
│       └─ after_agent / aafter_agent           ← completions/fallbacks 归因
│
├─ 第 5 段：SkillActivation（条件挂）
│   └─ 5. SkillActivationMiddleware
│       └─ before_model                          ← 关键词建议（仅 sync，无 async）
│
├─ 第 6 段：Title + RunJournal
│   ├─ 6a. TitleMiddleware
│   │   └─ after_agent / aafter_agent           ← metadata.title
│   └─ 6b. RunJournalMiddleware
│       ├─ before_agent / after_agent           ← agent.started / finished
│       ├─ before_model / after_model           ← llm.request / response
│       └─ wrap_tool_call / awrap_tool_call     ← tool.called / finished
│
├─ 第 7 段：MCP Audit（条件挂）
│   └─ 7. McpAuditMiddleware
│       └─ awrap_tool_call                       ← 熔断器 + 审计（仅 async）
│
├─ 第 8 段：Sandbox（条件挂）
│   └─ 8. SandboxMiddleware
│       ├─ abefore_model                         ← 恢复 ContextVar
│       ├─ awrap_tool_call                       ← acquire + present_files
│       └─ aafter_agent                          ← release（仅 async）
│
├─ 第 9 段：Memory（条件挂）
│   └─ 9. MemoryMiddleware
│       ├─ abefore_model                         ← 召回注入
│       └─ aafter_model                          ← 清除 turn_id（仅 async）
│
├─ 第 10 段：MemoryConsolidation（条件挂）
│   └─ 10. MemoryConsolidationMiddleware
│       ├─ abefore_model                         ← no-op
│       └─ aafter_model                          ← 每 N 轮 submit 任务（仅 async）
│
├─ 第 11 段：HelpRequest + DanglingToolCall + ToolCall
│   ├─ 11a. HelpRequestMiddleware
│   │   └─ wrap_tool_call / awrap_tool_call     ← 拦截 ask_help 暂停
│   ├─ 11b. DanglingToolCallMiddleware
│   │   └─ before_model / abefore_model         ← 修补悬空 tool_call
│   └─ 11c. ToolCallMiddleware
│       ├─ before_agent                         ← 记录 baseline
│       ├─ before_model / abefore_model         ← drain 摘要
│       └─ wrap_tool_call / awrap_tool_call     ← 账本 + 预算 + 重试
│
├─ 第 12 段：Orchestration（条件挂）
│   └─ 12. OrchestrationMiddleware
│       └─ wrap_tool_call / awrap_tool_call     ← 横切打点 + 产物汇总
│
├─ 第 13 段：Evidence + StallDetection + Todo + Reflection
│   ├─ 13a. EvidenceMiddleware
│   │   └─ wrap_tool_call / awrap_tool_call     ← 证据抽取
│   ├─ 13b. StallDetectionMiddleware
│   │   ├─ wrap_tool_call / awrap_tool_call     ← 记录失败
│   │   └─ after_model / aafter_model           ← 暂停求助
│   ├─ 13c. TodoMiddleware
│   │   ├─ before_agent / abefore_agent         ← 清理 + 重置
│   │   ├─ before_model / abefore_model         ← Layer 1 + Layer 3
│   │   ├─ after_model / aafter_model           ← Layer 2 完成度强制
│   │   ├─ wrap_model_call / awrap_model_call   ← 注入完成度提醒
│   │   └─ after_agent / aafter_agent           ← 清理
│   └─ 13d. ReflectionMiddleware
│       └─ after_model / aafter_model           ← L1 充分性反思
│
└─ 第 14 段：Report（model is not None）
    └─ 14. ReportMiddleware
        └─ after_agent / aafter_agent           ← 独立合成 final_report
```

### 0.2. 运行时调用树（一次会话从发起到得到回答）

```
用户发起会话
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【before_agent】进入 agent 前（每轮 1 次，注册顺序正序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ StrategyMiddleware.before_agent
│   │   ├─ 路由到治理 bundle.before_agent(ctx)
│   │   ├─ 应用 state_patch / metrics / jump_to
│   │   └─ 作用：治理策略在 run 开始前初始化（写 governance 状态、启动统计）
│   │
│   ├─ RunJournalMiddleware.before_agent
│   │   ├─ 写 journal 事件 "agent.started"（含 run_id）
│   │   └─ 作用：标记本次 run 正式开始，供审计 / 回放 / UI 计时
│   │
│   ├─ ToolCallMiddleware.before_agent
│   │   ├─ 记录 state.errors 长度作为 baseline
│   │   ├─ 清理其他 run 的陈旧队列 + 基线
│   │   └─ 作用：建立 per-run 计数基准（本轮工具调用数 = len(errors) - baseline），
│   │           避免跨 run 累积；防止旧 run 残留污染新 run
│   │
│   └─ TodoMiddleware.before_agent
│       ├─ _clear_other_runs（清同 thread 下其他 run 的完成度状态）
│       ├─ _reset_nag_counters（重置 steps_since_write / steps_since_reminder /
│       │                       last_write_count）
│       └─ 作用：让 Nag 计数从零开始，避免上个 run 的步数影响本轮提醒节奏
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【before_model】每次模型调用前（每轮多次，注册顺序正序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ StrategyMiddleware.before_model
│   │   ├─ 路由到 bundle.before_model(ctx)
│   │   ├─ 应用治理结果（can_jump_to=["model"]）
│   │   └─ 作用：模型调用前最后一道治理决策点，可跳回 model 或改写 state
│   │
│   ├─ SystemContextMiddleware.before_model
│   │   ├─ 从 runtime 取 timezone
│   │   ├─ 写 metadata.system_context（agent 身份 + 时区）
│   │   └─ 作用：给下游（prompt 拼装 / trace / UI）提供「我是谁、现在几点」元信息
│   │
│   ├─ SkillInjectionMiddleware.before_model
│   │   ├─ 混合来源选 skill（runtime.skill_override / metadata.skill_override
│   │   │                      + selector 自动选）
│   │   ├─ 命中则：
│   │   │     ├─ record_selection
│   │   │     ├─ journal "skill.select"
│   │   │     ├─ build_injection_text
│   │   │     ├─ 发 skill_active 事件
│   │   │     ├─ 写 ContextVar _active_skills_ctx / _applied_ctx
│   │   │     └─ 返回 SystemMessage(injection) + metadata.active_skills
│   │   └─ 作用：把本轮该用的 skill 注入上下文 + 留 provenance 锚点，
│   │             供 SkillMetrics 在工具调用后判定「是否真的用上了」
│   │
│   ├─ SkillActivationMiddleware.before_model
│   │   ├─ 取最后一条 message 的 content
│   │   ├─ 用 _KEYWORD_MAP 关键词匹配
│   │   ├─ 返回 {"skill_suggestion": [{"keyword", "skill"}, ...]}
│   │   └─ 作用：零 LLM 成本地主动建议相关 skill，写旁路字段，
│   │             让 lead agent 自己决定是否进一步 skill_search；
│   │             不改 system prompt，保护 prompt caching
│   │
│   ├─ RunJournalMiddleware.before_model
│   │   ├─ 写 journal "llm.request"（含 run_id / model）
│   │   └─ 作用：标记本轮 LLM 调用开始，供审计 / 计时 / 回放
│   │
│   ├─ DanglingToolCallMiddleware.before_model
│   │   ├─ 扫描 messages：收集已应答的 tool_call_id
│   │   ├─ 对 AIMessage 里未应答的 tool_call 补占位 ToolMessage
│   │   └─ 作用：修复 resume 后「有 call 没 result」的不完整历史，
│   │             否则严格后端会直接 400
│   │
│   ├─ MemoryMiddleware.abefore_model
│   │   ├─ 从最后一条 HumanMessage 提 query
│   │   ├─ retrieve 召回
│   │   ├─ 格式化 + token 裁剪
│   │   ├─ 注入 HumanMessage(name="memory_recall", hide_from_ui=True)
│   │   ├─ 写 recalled_memories（只存 id + score + strength）
│   │   └─ 作用：把长期记忆里相关片段召回进本轮上下文，辅助模型决策
│   │
│   ├─ MemoryConsolidationMiddleware.abefore_model
│   │   └─ no-op（沉淀只在 after_model；占位保证 hook 链完整）
│   │
│   ├─ ToolCallMiddleware.before_model
│   │   ├─ drain 队列里的 failure_summary / budget_exhausted 提示
│   │   ├─ 拼成隐藏 HumanMessage(name="tool_failure_summary")
│   │   └─ 作用：把「连续失败摘要」「预算耗尽」延迟到此时注入
│   │             （before_model 在 ToolNode 之后，ToolMessage 已就位，
│   │              不会破坏 tool_call 配对）
│   │
│   └─ TodoMiddleware.before_model
│       ├─ Layer 1：todos 存在但 messages 里看不到 write_todos → 注入 todo_reminder
│       ├─ Layer 3：双阈值 Nag（steps_since_write ≥ 5
│       │                AND steps_since_reminder ≥ 5
│       │                AND len(todos) ≥ 3
│       │                AND 有未完成）→ 注入 todo_nag
│       └─ 作用：Layer 1 防 write_todos 被截断后「忘了有计划」；
│                  Layer 3 在「真的很久没更新」且「距上次提醒也够久」时提醒，
│                  既防忘记又防打扰
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【wrap_model_call】包住模型调用（洋葱结构，注册顺序由外到内）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ StrategyMiddleware.wrap_model_call（最外层）
│   │   ├─ PRE：bundle.wrap_model_call(ctx)
│   │   ├─ 若 request_override 非空则替换 request
│   │   └─ 作用：治理策略在模型调用前改写 request（裁剪 messages / 换 model）
│   │
│   ├─ TaggedContextMiddleware.wrap_model_call
│   │   ├─ 调 ContextAssembler 渲染扁平 XML 标签序列
│   │   │     （<goal><plan><reflection><summary><date><turn>
│   │   │       <thinking><answer><toolresult> 等）
│   │   ├─ request.override(messages=...) 送 LLM
│   │   └─ 作用：把 state + messages 渲染成结构化 XML 上下文；
│   │             request-scoped 不持久，只影响本次模型调用
│   │
│   ├─ MessageNormalizerMiddleware.wrap_model_call
│   │   ├─ 合并 request.system_message 与 messages 里所有 SystemMessage
│   │   │   为单条 leading SystemMessage
│   │   ├─ 从 messages 里移除所有 SystemMessage
│   │   └─ 作用：满足 strict backend（vLLM / Qwen / Anthropic）
│   │             「只允许一条 leading SystemMessage」的要求
│   │
│   ├─ TodoMiddleware.wrap_model_call（较内层）
│   │   ├─ drain 队列里的完成度提醒
│   │   ├─ 追加 HumanMessage(name="todo_completion_reminder", hide_from_ui=True)
│   │   ├─ 再交给 super().wrap_model_call
│   │   └─ 作用：把 after_model 里排队的「todos 未完成」提醒在送 LLM 前注入，
│   │             逼模型看到提醒后继续处理
│   │
│   └─ handler → LLM（最内层）
│       └─ 真正发起模型调用
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【LLM 调用 → 模型返回】
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   └─ FallbackChatModel.invoke/ainvoke
│       ├─ 从 _active 轮转链内 provider
│       ├─ ChatDeepSeek / ChatOpenAI / ... 发请求、流式收 token
│       ├─ 成功 → 更新 _active，返回
│       └─ 失败 → _should_fallback → 降级下一个
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【after_model】每次模型调用后（每轮多次，注册顺序正序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ StrategyMiddleware.after_model
│   │   ├─ 路由到 bundle.after_model(ctx)
│   │   ├─ 应用结果（can_jump_to=["model"]）
│   │   └─ 作用：模型返回后的治理决策点，可跳回 model 再跑一轮
│   │
│   ├─ TaggedContextMiddleware.after_model
│   │   ├─ 从 state.messages 重组渲染
│   │   ├─ 写 state.tagged_context（{rendered, created_at}）
│   │   └─ 作用：留一份 trace 快照，供审计 / 持久化 / 回放；
│   │             只写旁路字段，不影响送 LLM 的内容
│   │
│   ├─ RunJournalMiddleware.after_model
│   │   ├─ 写 journal "llm.response"（含 run_id / model）
│   │   └─ 作用：标记本轮 LLM 调用结束，与 "llm.request" 配对成完整计时
│   │
│   ├─ MemoryMiddleware.aafter_model
│   │   ├─ set_turn_id(None) 清除 turn_id
│   │   ├─ enable_extract=False 时直接返回
│   │   └─ 作用：无论 before_model 是否注入过 turn_id，这里都清掉，
│   │             保证 traceability 生命周期干净
│   │
│   ├─ MemoryConsolidationMiddleware.aafter_model
│   │   ├─ 统计 HumanMessage 数
│   │   ├─ 每 N 轮取最近 N*2 条 messages
│   │   ├─ 构造 MemoryTask 交给 worker.submit（非阻塞）
│   │   └─ 作用：周期性把对话切片交给后台 worker 异步沉淀，不阻塞主流程
│   │
│   ├─ StallDetectionMiddleware.after_model
│   │   ├─ record_todo_state(todos)
│   │   ├─ 若 _pending_stuck[run_id] 为真 → 清标记 + _check_stuck_and_pause：
│   │   │     ├─ 未中断保护 + 未达 help 上限
│   │   │     │     → 递增 help_count
│   │   │     │     → journal "help.requested"
│   │   │     │     → tracker.reset()
│   │   │     │     → 补悬空 ToolMessage
│   │   │     │     → Command(goto=END)
│   │   │     └─ 已达上限 → _force_finalize（Command(goto=END)）
│   │   └─ 作用：检测到 agent 卡死时暂停 graph 向用户求助；
│   │             求助次数用尽后强制收尾，保证 run 能结束；
│   │             不在 wrap_tool_call 暂停，避免打断并行 tool_calls 配对
│   │
│   ├─ TodoMiddleware.after_model
│   │   ├─ super().after_model（基类 parallel write_todos 检测）
│   │   ├─ _infer_current_step_id 更新 current_step_id
│   │   ├─ 仅拦截「干净的最终答案」（无工具调用意图）
│   │   ├─ 放行条件：
│   │   │     ├─ enforce_completion=False
│   │   │     ├─ todos 全完成
│   │   │     ├─ 持续失败
│   │   │     ├─ 强制次数超限
│   │   │     └─ jump 预算耗尽
│   │   └─ 否则 → 入队完成度提醒 + jump_to="model"
│   │   └─ 作用：Layer 2 完成度强制——todos 没做完但模型想给最终答案时，
│   │             把它拽回来继续做；用多重闸门防止无限跳转
│   │
│   └─ ReflectionMiddleware.after_model
│       ├─ 取最后一条 AIMessage
│       ├─ 有工具调用意图 → 不拦
│       ├─ strategy.reflect(state) → verdict=="pass" → 不拦
│       ├─ jump 预算耗尽 → 发 reflection.budget_exhausted + 不拦
│       ├─ 否则：
│       │     ├─ 发 reflection.fired
│       │     ├─ 写 reflection_items
│       │     ├─ 注入 guidance HumanMessage
│       │     └─ jump_to="model"
│       └─ 作用：ReAct 退出闸门——模型想给答案时检查「证据是否充分」，
│                 不充分就跳回去补研究；与 Todo 共享 jump 预算（合计 ≤3）
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【wrap_tool_call】包住工具调用（若有 tool_calls，洋葱由外到内）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ StrategyMiddleware.wrap_tool_call（最外层）
│   │   ├─ POST：先 handler(request) 取 result
│   │   ├─ 再 bundle.wrap_tool_call(ctx)
│   │   ├─ 若 request_override 非空则返回它，否则返回原 result
│   │   └─ 作用：治理策略在工具返回后改写结果
│   │
│   ├─ RunJournalMiddleware.wrap_tool_call
│   │   ├─ 写 journal "tool.called"（含 tool_name / tool_input）
│   │   ├─ handler(request) 后根据 status 写 "tool.finished"
│   │   ├─ activity_tracker start / finish
│   │   ├─ 异常时记 error 并 re-raise
│   │   └─ 作用：把工具调用生命周期完整记入 journal；
│   │             作为 wrap 外层，它能看到所有内层中间件处理后的最终结果
│   │
│   ├─ HelpRequestMiddleware.wrap_tool_call
│   │   ├─ tool_name != "ask_help" → handler(request)
│   │   ├─ 否则：
│   │   │     ├─ 格式化求助消息
│   │   │     ├─ journal "help.requested"
│   │   │     └─ 返回 Command(update={messages: [ToolMessage]}, goto=END)
│   │   └─ 作用：拦截 ask_help，暂停 graph 向用户求助；
│   │             不执行 ask_help 的实际工具实现
│   │
│   ├─ McpAuditMiddleware.awrap_tool_call
│   │   ├─ registry 取 entry（含 breaker）
│   │   ├─ 熔断器 open → 记 circuit_open + 返回 error ToolMessage
│   │   ├─ 否则 await handler(request)
│   │   ├─ 成功 → record_success + 记 ok
│   │   ├─ 异常 → record_failure + sanitize_error + 记 error + re-raise
│   │   └─ 作用：MCP 工具的熔断器 + 审计 + 凭证脱敏 + 外化联动标记；
│   │             异常向上抛，交给 ToolCallMiddleware 转 ToolMessage
│   │
│   ├─ SandboxMiddleware.awrap_tool_call
│   │   ├─ 非 sandbox 工具 → await handler(request)
│   │   ├─ sandbox 工具首次调用：
│   │   │     ├─ provider.acquire
│   │   │     ├─ set_sandbox_id
│   │   │     └─ 发 sandbox_update
│   │   ├─ await handler(request)
│   │   ├─ present_files → _register_artifacts
│   │   │     （复制到 .poirot/outputs/ + 注册 + 追加 Download URL）
│   │   ├─ 首次 acquire → Command(update={"sandbox", "messages"})
│   │   └─ 作用：sandbox 按需获取 + 跨轮复用 + 产出物落盘
│   │
│   ├─ SkillMetricsMiddleware.awrap_tool_call
│   │   ├─ 读 ContextVar _active_skills_ctx / _applied_ctx
│   │   ├─ 若 tool_name ∈ allowed_tools：
│   │   │     ├─ applied_map[sid] = True
│   │   │     └─ journal "skill.apply"
│   │   └─ 作用：承接 SkillInjection 的 provenance，
│   │             把「工具真的被调用了」标记到对应 skill 上，供 after_agent 归因
│   │
│   ├─ OrchestrationMiddleware.wrap_tool_call
│   │   ├─ tool_name 不以 delegate_to_ 开头 → handler(request)
│   │   ├─ 否则：
│   │   │     ├─ _before_handler（set_current_state + record_selection + record_invoked）
│   │   │     ├─ handler(request)
│   │   │     ├─ 异常 → record_fallback + _make_error_response
│   │   │     └─ _after_handler（record_completion / record_fallback
│   │   │                        + _build_orchestration_update）
│   │   └─ 作用：多 agent 委派的横切打点 + 产物汇总；
│   │             不做编排决策（调谁由 LLM 决定）
│   │
│   ├─ EvidenceMiddleware.wrap_tool_call
│   │   ├─ tool_name not in _EVIDENCE_TOOLS → handler(request)
│   │   ├─ 否则：
│   │   │     ├─ handler(request)
│   │   │     ├─ interrupt_protection 内：
│   │   │     │     ├─ _extract_sources
│   │   │     │     ├─ _resolve_step_id
│   │   │     │     └─ _make_observation
│   │   │     └─ 返回 Command(update={observations, sources, messages})
│   │   └─ 作用：拦截证据类工具，把结果结构化沉淀进 observations / sources；
│   │             双写 messages（模型可见）+ 旁路存档
│   │
│   ├─ StallDetectionMiddleware.wrap_tool_call
│   │   ├─ handler(request)
│   │   ├─ 异常 → _check_and_flag_stuck + re-raise
│   │   ├─ ToolMessage(status="error") → _check_and_flag_stuck
│   │   ├─ 成功 → tracker.record_tool_success()（衰减失败信号）
│   │   └─ 作用：记录工具失败，必要时置 pending_stuck；
│   │             不在此处暂停（暂停留给 after_model，避免破坏并行 pairing）
│   │
│   ├─ ToolCallMiddleware.wrap_tool_call（较内层）
│   │   ├─ 检查 per-tool retry budget → 超限 → tool.blocked + error ToolMessage
│   │   ├─ 检查 per-run hard budget → 超限 → tool.budget_exhausted + error ToolMessage
│   │   ├─ 否则 handler(request)
│   │   ├─ _process_result：
│   │   │     ├─ 判定成败
│   │   │     ├─ 记 AgentError
│   │   │     ├─ 合成 error ToolMessage
│   │   │     ├─ 失败摘要入队
│   │   │     ├─ 硬预算检查
│   │   │     └─ 合并 Command
│   │   └─ 作用：工具调用的统一治理点——账本 + 失败分类 + 重试预算 +
│   │             超限禁工具 + 硬预算
│   │
│   └─ handler → 工具执行（最内层）
│       └─ 真正执行工具
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【循环判定】
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ 若模型不再发 tool_calls（或触发 jump_to / goto=END）→ 退出循环
│   └─ 否则回到【before_model】继续下一轮
│
│
├─ ═══════════════════════════════════════════════════════════════════════
├─ 【after_agent】循环结束（每轮 1 次，注册顺序反序）
├─ ═══════════════════════════════════════════════════════════════════════
│   │
│   ├─ ReportMiddleware.after_agent
│   │   ├─ auto_synthesize=False → None
│   │   ├─ observations 空 → None
│   │   ├─ 否则 _synthesize：
│   │   │     ├─ 构造 reporter messages
│   │   │     ├─ model.invoke
│   │   │     └─ 返回 {"final_report": report}
│   │   └─ 作用：ReAct 循环结束后独立合成 final_report，
│   │             不赌最后一条 AIMessage（deer-flow 模式）
│   │
│   ├─ TodoMiddleware.after_agent
│   │   ├─ _clear_run_state（清当前 run 的完成度提醒与计数）
│   │   ├─ _jump_budget.clear(runtime)（清 jump 预算）
│   │   └─ 作用：run 结束时清理 per-run 状态，避免污染下一 run
│   │
│   ├─ SandboxMiddleware.aafter_agent
│   │   ├─ state["sandbox"]["sandbox_id"] 存在 → provider.release(sandbox_id)
│   │   └─ 作用：释放 sandbox（LocalSandboxProvider 为 no-op，
│   │             远端 provider 真正回收）
│   │
│   ├─ SkillMetricsMiddleware.after_agent
│   │   ├─ 读 metadata.active_skills

│   │             支撑「选中→应用→完成/回退」的漏斗统计
│   │
│   ├─ RunJournalMiddleware.after_agent
│   │   ├─ 写 journal "agent.finished"（含 run_id）
│   │   └─ 作用：标记本次 run 结束，与 "agent.started" 配对

│       └─ 作用：治理策略在 run 结束后的收口点
│
│
└─ 得到回答（final_report / 最后一条 AIMessage）
```

```python
    # L5 Memory Consolidation: MemoryMiddleware 后(HelpRequest 前)
    if memory_worker is not None:
        from poirot.backend.agents.middlewares.memory_consolidation_middleware import (
            MemoryConsolidationMiddleware,
        )
        trigger_n = (
            memory_config.phase2.get("trigger_every_n_turns", 10)
            if memory_config else 10
        )
        middlewares.append(MemoryConsolidationMiddleware(
            worker=memory_worker,
            trigger_every_n_turns=trigger_n,
        ))
    middlewares.extend([
        HelpRequestMiddleware(),
        DanglingToolCallMiddleware(),
        # LoopDetectionMiddleware 已移除——用户要求取消循环上限约束。
        # 原配置：after_model 检测近 10 条消息同 (tool, args_hash) ≥3 → 清 tool_calls + jump model。
        # 如需恢复，取消下行注释 + 确保 import 存在。
        # LoopDetectionMiddleware(),
        ToolCallMiddleware(),
    ])
    if orchestration_middleware is not None:
        middlewares.append(orchestration_middleware)
    middlewares.extend([
        EvidenceMiddleware(),
        StallDetectionMiddleware(),
        TodoMiddleware(enforce_completion=expert_mode),
        ReflectionMiddleware(
            strategy=SufficiencyStrategy(llm=model) if expert_mode else LightReflectionStrategy(),
            llm=model,
        ),
    ])
    if model is not None:
        middlewares.append(ReportMiddleware(model, auto_synthesize=expert_mode))
    return middlewares


def make_lead_agent(
    expert_mode: bool = False,
    capability_registry: CapabilityRegistry | None = None,
    middleware_manager: Any = None,
    runnable_config: RunnableConfig | None = None,
    context_governance: Any = None,
    sandbox_provider: Any = None,
    artifact_server: Any = None,
    mcp_audit_middleware: Any = None,
    skill_injection_middleware: Any = None,
    skill_metrics_middleware: Any = None,
    specialist_tools: list[BaseTool] | None = None,
    orchestration_middleware: Any = None,
    memory_provider: Any = None,
    memory_config: Any = None,
    memory_worker: Any = None,
) -> Any:
    """App-layer factory: expert_flag 参数化装配 graph。

    - middleware: _build_middlewares(expert_mode) 全挂参数化
    - tools: get_available_tools(groups=...) 按 expert 选 core / core+deferred
    - system_prompt: apply_prompt_template(expert_mode, specialist_registry=...)
      — specialist_registry 非空时条件注入 <specialist_routing> 段（Bug B 修复）
    - checkpointer: get_checkpointer() 单例，thread_id 跨轮 + 跨模式保留 state

    Registry MUST store BaseChatModel / BaseTool instances directly.
    """
    from poirot.backend.agents.leader.agent import LeaderAgent

    if runnable_config is not None and "configurable" in runnable_config:
        registry = runnable_config["configurable"].get("capability_registry")
    else:
        registry = capability_registry
        runnable_config = {"configurable": {"expert_mode": expert_mode, "capability_registry": registry}}

    if registry is None:
        raise ValueError("capability_registry is required (in configurable or as param)")

    configurable = runnable_config.get("configurable", {})
    # runnable_config 透传的 expert_mode 优先，否则用参数
    resolved_expert = bool(configurable.get("expert_mode", expert_mode))

    model = registry.get_model("researcher")

    # summarize_model 独立取：config.params.summarize_model 配名 → registry 取独立 model；否则 None（fallback research model）
    summarize_model = None
    if context_governance is not None:
        sm_name = (getattr(context_governance, "params", None) or {}).get("summarize_model")
        if sm_name:
            try:
                summarize_model = registry.get_model(sm_name)
            except Exception:
                summarize_model = None

    # tool groups: default=core, expert=core+deferred
    groups = ["core", "deferred"] if resolved_expert else ["core"]
    tools: list[BaseTool] = []
    for tool in get_available_tools(groups=groups):
        if isinstance(tool, BaseTool) and tool not in tools:
            tools.append(tool)
    # registry 额外注册的工具（如 web_search_mcp 别名）保留
    for tool in registry.tools.values():
        if isinstance(tool, BaseTool) and tool not in tools:
            tools.append(tool)
    # multiagent specialist tools（delegate_to_*）
    if specialist_tools:
        for tool in specialist_tools:
            if isinstance(tool, BaseTool) and tool not in tools:
                tools.append(tool)

    return LeaderAgent(
        graph=create_agent(
            model=model,
            tools=tools or None,
            middleware=_build_middlewares(resolved_expert, model, context_governance, summarize_model, sandbox_provider, artifact_server, mcp_audit_middleware, skill_injection_middleware, skill_metrics_middleware, orchestration_middleware, memory_provider, memory_config, memory_worker),
            system_prompt=apply_prompt_template(
                expert_mode=resolved_expert,
                specialist_registry=_safe_get_specialist_registry(registry),
                skills_enabled=skill_injection_middleware is not None,
            ),
            state_schema=ThreadState,
            checkpointer=get_checkpointer(),
        ),
        capability_registry=registry,
    )
```
