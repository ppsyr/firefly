---

name:StrategyMiddleware — 接入 adapter，把 6 个 hook 路由到 GovernanceStrategy bundle。

description:

【整体职责】
用一个 AgentMiddleware 持有一个策略 bundle 实例，把 LangChain 暴露的 6 类 hook（before_agent / after_agent / before_model / after_model / wrap_model_call / wrap_tool_call）统一路由到 bundle 上对应的方法。  

【两类 hook 的语义差异】
1) state-channel hooks（before_agent / after_agent / before_model / after_model）
- 返回 dict（state_patch），由 apply_governance_result 应用到 state。
- 可携带 metrics / jump_to 等治理结果。
- before_model / after_model 标了 @hook_config(can_jump_to=["model"])，
允许治理结果跳回 model 节点。
  
2) wrap hooks（wrap_model_call / wrap_tool_call）
- 作为 adapter 包住 handler，只消费 GovernanceResult.request_override。
- wrap hook 不适合写 state_patch / metrics：因为 wrap 必须返回
ModelCallResult / ToolMessage，没有 state 通道；状态写入交给 before/after hook 完成。
- wrap_model_call = PRE：bundle 先改 request，再交给 handler。
- wrap_tool_call = POST：先让 handler 拿到 tool result，再让 bundle 改 result。

【ctx 构造】
每次 hook 调用都会构造一个 GovernanceContext，把 state、governance、 config、token_counter、runtime、hook 名以及 hook 特定参数一并传入， bundle 侧据此做治理决策。

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 方法）

```
StrategyMiddleware — 接入 adapter，路由 6 hook 到 GovernanceStrategy bundle
│
└─ class StrategyMiddleware(AgentMiddleware)
    ├─ state_schema = ThreadState
    │
    ├─ __init__(bundle, config=None)              ← 持有 bundle + config
    │
    ├─ _ctx(state, runtime, hook, **hook_specific)  ← 构造 GovernanceContext
    │   └─ 注入：state / governance / config / token_counter / runtime / hook
    │
    ├─ 【state-channel hooks：返回 dict，apply_governance_result】──────────
    │   ├─ before_agent(state, runtime)           ← bundle.before_agent
    │   ├─ abefore_agent(state, runtime)          ← bundle.abefore_agent
    │   ├─ after_agent(state, runtime)            ← bundle.after_agent
    │   ├─ aafter_agent(state, runtime)           ← bundle.aafter_agent
    │   ├─ before_model(state, runtime)           ← @hook_config(can_jump_to=["model"])
    │   ├─ abefore_model(state, runtime)          ← @hook_config(can_jump_to=["model"])
    │   ├─ after_model(state, runtime)            ← @hook_config(can_jump_to=["model"])
    │   └─ aafter_model(state, runtime)           ← @hook_config(can_jump_to=["model"])
    │
    └─ 【wrap hooks：adapter 包 handler，仅消费 request_override】──────────
        ├─ wrap_model_call(request, handler)      ← PRE：bundle 改 request → handler
        ├─ awrap_model_call(request, handler)     ← PRE async
        ├─ wrap_tool_call(request, handler)       ← POST：handler 取 result → bundle 改 result
        └─ awrap_tool_call(request, handler)      ← POST async
```

### 0.2. 运行时调用树（分两类 hook）

#### A. state-channel hook（以 before_model 为例，同步）

```
LangGraph 进入 before_model 阶段
│
└─ StrategyMiddleware.before_model(state, runtime)
    ├─ _ctx(state, runtime, "before_model", messages=state.get("messages") or [])
    │   └─ GovernanceContext(state, governance, config, token_counter,
    │                        runtime, hook="before_model", messages=...)
    ├─ bundle.before_model(ctx)                   ← 返回 GovernanceResult
    └─ apply_governance_result(state, result)     ← 应用 state_patch / metrics / jump_to
        └─ return dict | None                     ← 写回 state 通道
```

异步版 `abefore_model` 同样流程，`bundle` 调用改为 `await bundle.abefore_model(...)`。

> after_agent / before_agent 同构，仅 bundle 方法名与 hook 名不同；
> before_model / after_model 额外带 `@hook_config(can_jump_to=["model"])`，
> 允许治理结果跳回 model 节点。

---

#### B. wrap hook

#### B1. wrap_model_call（PRE，同步）

```
模型调用进入 wrap 阶段
│
└─ StrategyMiddleware.wrap_model_call(request, handler)
    ├─ state = request.runtime.state or {}
    ├─ _ctx(state, request.runtime, "wrap_model_call",
    │        model_request=request,
    │        messages=request.messages or [],
    │        tools=request.tools)
    │   └─ GovernanceContext(...)
    ├─ result = bundle.wrap_model_call(ctx)       ← GovernanceResult
    ├─ req = result.request_override or request    ← 仅消费 request_override
    └─ return handler(req)                        ← 交给下游
```

异步版 `awrap_model_call`：`await bundle.awrap_model_call(ctx)`，再 `await handler(req)`。

#### B2. wrap_tool_call（POST，同步）

```
工具调用进入 wrap 阶段
│
└─ StrategyMiddleware.wrap_tool_call(request, handler)
    ├─ tool_result = handler(request)              ← 先拿 tool 结果
    ├─ state = request.runtime.state or {}
    ├─ _ctx(state, request.runtime, "wrap_tool_call",
    │        tool_call_request=request,
    │        tool_result=tool_result)
    │   └─ GovernanceContext(...)
    ├─ result = bundle.wrap_tool_call(ctx)         ← GovernanceResult
    └─ return result.request_override or tool_result
```

异步版 `awrap_tool_call`：`await handler(request)`，再 `await bundle.awrap_tool_call(ctx)`。

## 1. 「6 个 hook 」

| # | hook 名 | 类别 | 方向/语义（据本文件注释） |
|---|---|---|---|
| 1 | `before_agent` | state-channel | agent 开始前，返回 state patch |
| 2 | `after_agent` | state-channel | agent 结束后，返回 state patch |
| 3 | `before_model` | state-channel | model 调用前，返回 state patch；可 `can_jump_to=["model"]` |
| 4 | `after_model` | state-channel | model 调用后，返回 state patch；可 `can_jump_to=["model"]` |
| 5 | `wrap_model_call` | wrap | PRE：bundle 先改 request，再交给 handler |
| 6 | `wrap_tool_call` | wrap | POST：先取 handler 的 tool result，再让 bundle 改 result |

**每对都有同步和异步两版**：`before_agent` / `abefore_agent`、`after_agent` / `aafter_agent`、`before_model` / `abefore_model`、`after_model` / `aafter_model`、`wrap_model_call` / `awrap_model_call`、`wrap_tool_call` / `awrap_tool_call`。

关键区别：
- **前 4 个（before/after_agent、before/after_model）是 state-channel hook**，返回 `GovernanceResult`，经 `apply_governance_result` 转成 dict patch 写 state。
- **后 2 个（wrap_model_call / wrap_tool_call）是 wrap hook**，由 `StrategyMiddleware` adapter 包住 handler；bundle 通过 `GovernanceContext` 收 request/result，**不直接持 handler**。

**方法名就是 hook 名，不预设能力语义**。也就是说，契约层只规定"有这 6 个入口"，具体每个 hook 里做什么（压缩、记忆、审计、路由……）完全由策略 bundle 自己决定。

---

## 2. 「GovernanceStrategy bundle」

- 它是一个 **Protocol**（`@runtime_checkable class GovernanceStrategy(Protocol)`），即**接入契约**，不是具体实现。
- 它规定了策略 bundle 必须实现上述 6 对 hook，且每个方法签名统一为 `(ctx: GovernanceContext) -> GovernanceResult`（异步版返回 `Awaitable[GovernanceResult]`）。
- 它是**骨架族无关**的接入契约：策略 bundle 实现 GovernanceStrategy 6 hook，内部完全自由。
- 它的调用方是 `StrategyMiddleware` adapter：adapter 构造 `GovernanceContext` 调 bundle，再用 `apply_governance_result` 应用 `GovernanceResult`。
- 文件还给了配套的数据契约：`GovernanceContext`（hook 级统一入参）、`GovernanceResult`（hook 级统出参）、`GovernanceMetric`（策略级 metric），以及 `MemorySink`（短期治理层与长期记忆层的边界接口）。
