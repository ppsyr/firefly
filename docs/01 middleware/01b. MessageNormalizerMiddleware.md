MessageNormalizerMiddleware — wrap_model_call 合并多 SystemMessage 为单条 leading。

【为什么需要这个中间件】
严格后端（vLLM / Qwen / Anthropic 等）会拒绝「非 leading 位置的 SystemMessage」，即要求整条请求里只能有一条 SystemMessage，且必须排在最前面。这个中间件在 wrap_model_call 里把请求 payload 中出现的多条 SystemMessage（含 request.system_message 与 messages 里的 SystemMessage）合并成一条，放到 leading 位置，从而满足严格后端的要求。
  
【定位：公共固定件】
这是所有 agent 都需要的公共需求，因此作为固定件直接存在，不经过 registry注册流程。如果把它的行为改成 noop（什么都不做），在严格后端上会直接因为provider 报错而导致功能坏掉——所以它不是可选优化，而是必需件。

【作用范围】
只动 request payload（本次模型调用请求），不动 checkpoint state。这样可以保证 history scanner 仍然能按原始消息结构正常工作。

【与 TaggedContextMiddleware 的关系】
TaggedContextMiddleware 会把上下文块包成一条 SystemMessage 放在最前；本中间件则负责把「已经存在的多条 SystemMessage」归拢成一条 leading，两者都只作用于 request payload，不改 state。

## 0. 结构树

下面按你之前那种「调用树」风格，给这份文件梳理出**静态结构树**和**运行时调用树**两棵。

---

### 0.1. 静态结构树（模块 → 函数/类 → 方法）

```
MessageNormalizerMiddleware — wrap_model_call 合并多 SystemMessage 为单条 leading
│
├─ _flatten_content(content)                     ← 把 SystemMessage.content 压平成字符串
│   ├─ str          → 原样返回
│   ├─ list         → 逐项处理：str 直取 / dict 取 "text" / 其他 str() 兜底，"\n" 连接
│   └─ 其他类型     → str(content) 兜底
│
└─ class MessageNormalizerMiddleware(AgentMiddleware)   ← 合并 SystemMessage 为单条 leading
    ├─ state_schema = ThreadState
    │
    ├─ _coalesce(request)            [static]    ← 核心：多 SystemMessage → 单条 leading
    │   ├─ 收集 messages 中的 SystemMessage
    │   │   └─ 一条都没有 → 返回 None（无需改动）
    │   ├─ parts = [request.system_message] + messages 里的 SystemMessage
    │   ├─ merged_kwargs = 各 part.additional_kwargs 依次 update
    │   ├─ merged = SystemMessage(
    │   │       content = "\n\n".join(_flatten_content(p.content) ...),
    │   │       id      = parts[0].id,
    │   │       additional_kwargs = merged_kwargs)
    │   ├─ non_system = messages 中剔除所有 SystemMessage
    │   └─ request.override(system_message=merged, messages=non_system)
    │
    ├─ wrap_model_call(request, handler)          ← 同步：_coalesce → handler
    └─ awrap_model_call(request, handler)         ← 异步：_coalesce → await handler
```

---

### 0.2. 运行时调用树（真正跑一次模型调用）

```
LLM 调用触发
│
├─ MessageNormalizerMiddleware.wrap_model_call(request, handler)   ← 同步路径
│   │   （或 awrap_model_call → await handler）
│   │
│   ├─ coalesced = _coalesce(request)
│   │   ├─ in_msg_systems = [m for m in request.messages
│   │   │                    if isinstance(m, SystemMessage)]
│   │   │
│   │   ├─ if not in_msg_systems:  return None          ← 短路：无需改动
│   │   │
│   │   ├─ parts = []
│   │   ├─ if request.system_message is not None:
│   │   │     parts.append(request.system_message)      ← leading 优先
│   │   ├─ parts.extend(in_msg_systems)                 ← 保持原有相对顺序
│   │   │
│   │   ├─ merged_kwargs = {}
│   │   ├─ for p in parts: merged_kwargs.update(p.additional_kwargs or {})
│   │   │
│   │   ├─ merged = SystemMessage(
│   │   │       content = "\n\n".join(_flatten_content(p.content) for p in parts),
│   │   │       id      = parts[0].id,
│   │   │       additional_kwargs = merged_kwargs)
│   │   │   └─ _flatten_content(...)  × len(parts)
│   │   │
│   │   ├─ non_system = [m for m in request.messages
│   │   │                if not isinstance(m, SystemMessage)]
│   │   └─ return request.override(system_message=merged, messages=non_system)
│   │
│   └─ handler(coalesced if coalesced is not None else request)
│
└─ handler 真正发 LLM
```

---


| 环节                  | 行为                                        | 备注                                    |
| ------------------- | ----------------------------------------- | ------------------------------------- |
| `_coalesce` 短路      | messages 中无 SystemMessage → 返回 `None`     | 调用方直接透传原 request                      |
| 合并顺序                | `request.system_message` 在前，messages 里的在后 | 保证 leading 语义                         |
| content 合并          | 先 `_flatten_content` 压平，再 `"\n\n"` 拼接     | 兼容 str / list / dict                  |
| `additional_kwargs` | 依次 `update`，后者覆盖前者                        | 最终聚合为 `merged_kwargs`                 |
| `id`                | 沿用 `parts[0].id`                          | 保持稳定标识                                |
| `messages`          | 剔除全部 SystemMessage，其余保序                   | 保证无「非 leading SystemMessage」          |
| 作用范围                | 只动 request payload                        | 不动 checkpoint state，保 history scanner |
