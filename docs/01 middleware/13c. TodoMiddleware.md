---

name: TodoMiddleware — 扩展 TodoListMiddleware，增加上下文丢失检测与 Nag 提醒。

description:

【三层保护】
1. before_model：上下文丢失检测
   —— write_todos 的调用被上下文截断后，历史里看不到 todo，
      此时注入一条提醒，让模型知道「你有未完成的 todos」。
2. after_model：完成度强制
   —— todos 未完成但 LLM 想直接给最终答案时，跳回 model 节点，
      最多强制 2 次（防止无限循环）。
3. before_model：Nag（双阈值提醒）
   —— steps_since_write >= 5 防「忘记」：
        模型埋头干活，很久没碰 todos。
      steps_since_reminder >= 5 防「打扰」：
        模型正在做子任务时，不要每一步都提醒。
   两个条件必须同时满足（AND）才触发；触发后只重置 steps_since_reminder。-->注入一条 todo_nag 提醒消息。

【继承关系】
继承 TodoListMiddleware，复用基类的 write_todos 工具注册与 system prompt 注入。

## 0. 结构树

### 0.1. 静态结构树（模块 → 函数/类 → 方法）

### 0.2. 运行时调用树（三层保护各自触发点）

```

│
├─ todos / messages
│
├─ 【Layer 1：上下文丢失检测】
│   └─ if todos and not _todos_in_messages(messages)
│          and not _reminder_in_messages(messages):
│       └─ return {messages: [HumanMessage(name="todo_reminder",
│                                          hide_from_ui=True,
│                                          content=渲染 context_loss_reminder)]}
│
├─ 【Layer 3：Nag 双阈值】

│   │   ├─ write_count > last_write_count → steps_since_write = 0
│   │   │                                   last_write_count = write_count
│   │   ├─ 否则 steps_since_write += 1
│   │   ├─ steps_since_reminder += 1
│   │   └─ should_nag = incomplete 且 len(todos)>=3
│   │                  且 steps_since_write >= 5
│   │                  且 steps_since_reminder >= 5
│   │       └─ 命中：steps_since_reminder = 0；记下 steps
│   └─ if should_nag:

└─ return None

│
├─ base_result = super().after_model(...)     ← 基类并行 write_todos 检测
│   └─ 有结果 → 直接返回
│

│
├─ if not last_ai or _has_tool_call_intent(last_ai): return step_update or None
├─ if not enforce_completion: return step_update or None
├─ if todos 空 或 全 completed: return step_update or None
├─ if _has_persistent_failures(state): return step_update or None
├─ if _completion_reminder_count(runtime) >= 2: return step_update or None
├─ if not _jump_budget.try_consume(runtime): return step_update or None
│
├─ _queue_completion_reminder(runtime, _format_completion_reminder(todos))
└─ return {"jump_to": "model", **step_update}
```

## 1. 三层保护每一步具体怎么实现

### Layer 1：上下文丢失检测（`before_model` 前半段）

**要解决的问题**：write_todos 的调用被上下文截断后，历史里看不到 todo，模型会「忘了自己还有计划」。

**实现**：

```python
todos: list[Todo] = state.get("todos") or []
messages = state.get("messages") or []

if todos and not _todos_in_messages(messages) and not _reminder_in_messages(messages):
    return {"messages": [HumanMessage(
        name="todo_reminder",
        additional_kwargs={"hide_from_ui": True},
        content=get_prompt_manager().load("todo", "context_loss_reminder", todos=_format_todos(todos)),
    )]}
```

**三个条件同时成立才触发**：
1. `todos` 非空——确实有计划；
2. `not _todos_in_messages(messages)`——历史里没有 write_todos 调用（被截断）；
3. `not _reminder_in_messages(messages)`——还没注入过 todo_reminder（防重复）。

**判定辅助函数**：
- `_todos_in_messages`：遍历 AIMessage.tool_calls，看有没有 `name == "write_todos"`。
- `_reminder_in_messages`：遍历 HumanMessage，看有没有 `name == "todo_reminder"`。

**注入内容**：用 prompt manager 渲染 `todo/context_loss_reminder` 模板，把 todos 格式化成多行文本传进去。`hide_from_ui=True` 表示不在 UI 展示。

---

### Layer 2：完成度强制（`after_model` + `wrap_model_call`）

**要解决的问题**：todos 还没做完，模型就想直接给最终答案「跑路」。

**分两段实现：after_model 决定要不要强制，wrap_model_call 把提醒注入。**

#### 2.1. after_model 的判定顺序

```python
# 1. 先继承基类逻辑
base_result = super().after_model(state, runtime)
if base_result is not None:
    return base_result
```

基类会处理并行 write_todos 的检测；有结果就优先返回，不抢。

```python
# 2. 取最后一条 AIMessage，推断 step_id
messages = state.get("messages") or []
last_ai = next((m for m in reversed(messages) if isinstance(m, AIMessage)), None)
step_id = _infer_current_step_id(last_ai)
step_update = {"current_step_id": step_id} if step_id is not None else {}
```

`_infer_current_step_id` 从 AIMessage 的 write_todos 调用里找第一个 `in_progress` 项，返回 `f"todo-{index}"`。这样每轮结束都能把 `current_step_id` 更新到最新状态。

```python
# 3. 只拦截「干净的最终答案」
if not last_ai or _has_tool_call_intent(last_ai):
    return step_update or None
```

`_has_tool_call_intent` 检查多处：
- `tool_calls` 非空；
- `invalid_tool_calls` 非空；
- `additional_kwargs.tool_calls` / `function_call`；
- `response_metadata.finish_reason` 是 `tool_calls` / `function_call`。

**只要有工具调用意图，就不算「想跑路」，放行。**

```python
# 4. default 模式：不强制完成度
if not self._enforce_completion:
    return step_update or None
```

`enforce_completion=False` 时，模型想退就退，只保留软引导。

```python
# 5. todos 为空或全完成 → 允许退出
todos: list[Todo] = state.get("todos") or []
if not todos or all(t.get("status") == "completed" for t in todos):
    return step_update or None
```

**没有未完成的 todo，就不拦。**

```python
# 6. 工具持续失败时放行
if _has_persistent_failures(state):
    return step_update or None
```

`_has_persistent_failures` 从 `state.errors` 派生：对每个 tool 取最新条目的 attempt，任一 `>= 3` 就算持续失败。

**为什么放行**：工具已经反复失败，强行要求 all-completed 只会卡死；让任务跑到结尾产一份带缺口的报告更合理。

```python
# 7. 强制次数上限
if self._completion_reminder_count(runtime) >= _MAX_COMPLETION_REMINDERS:
    return step_update or None
```

最多强制 2 次，防死循环。

```python
# 8. 共享 jump 预算
if not _jump_budget.try_consume(runtime):
    return step_update or None
```

`_jump_budget` 是与 Reflection 共享的跳转预算（合计 ≤3）。
`try_consume` 失败（预算用尽）就放行退出。

```python
# 9. 入队 + 跳回 model
self._queue_completion_reminder(runtime, _format_completion_reminder(todos))
return {"jump_to": "model", **step_update}
```

- `_queue_completion_reminder`：把提醒入队，并给 `_completion_reminder_counts[key]` +1。
- `return {"jump_to": "model", ...}` 配合 `@hook_config(can_jump_to=["model"])`，
  让 graph 跳回 model 节点，逼模型继续处理未完成 todo。

`_format_completion_reminder` 只列未完成的 todo，交给 prompt manager 渲染 `todo/completion_reminder` 模板。

#### 2.2. wrap_model_call 注入提醒

```python
reminders = self._drain_completion_reminders(request.runtime)
if not reminders:
    return super().wrap_model_call(request, handler)
new_messages = [
    *request.messages,
    HumanMessage(
        content="\n\n".join(dict.fromkeys(reminders)),
        name="todo_completion_reminder",
        additional_kwargs={"hide_from_ui": True},
    ),
]
return super().wrap_model_call(request.override(messages=new_messages), handler)
```

- `_drain_completion_reminders` 把队列取空。
- 去重（`dict.fromkeys`）后拼成一条 HumanMessage 追加到 messages 末尾。
- `request.override(messages=new_messages)` 改写请求，再交给父类。

**为什么不在 after_model 直接注入？** 因为 after_model 只返回 state patch / jump 指令，注入消息要在送 LLM 时做——wrap_model_call 正好是送 LLM 前的最后一站。

---

### Layer 3：Nag 双阈值提醒（`before_model` 后半段）

**要解决的问题**：
- 「忘记」：模型埋头干活，很久没更新 todos；
- 「打扰」：如果每步都提醒，会打断模型正在做的子任务。

**用双阈值 AND 解决**：

```python
thread_id = self._get_thread_id(runtime)
incomplete = [t for t in todos if t.get("status") != "completed"]
write_count = _count_write_todos(messages)

with self._lock:
    if write_count > self._last_write_count.get(thread_id, 0):
        self._last_write_count[thread_id] = write_count
        self._steps_since_write[thread_id] = 0
    else:
        self._steps_since_write[thread_id] = self._steps_since_write.get(thread_id, 0) + 1
    self._steps_since_reminder[thread_id] = self._steps_since_reminder.get(thread_id, 0) + 1

    should_nag = (
        bool(incomplete)
        and len(todos) >= _NAG_MIN_TODOS
        and self._steps_since_write[thread_id] >= _STEPS_SINCE_WRITE_THRESHOLD
        and self._steps_since_reminder[thread_id] >= _STEPS_SINCE_REMINDER_THRESHOLD
    )
    if should_nag:
        self._steps_since_reminder[thread_id] = 0
        steps = self._steps_since_write[thread_id]

if should_nag:
    return {"messages": [HumanMessage(
        name="todo_nag",
        additional_kwargs={"hide_from_ui": True},
        content=get_prompt_manager().load("todo", "nag_reminder", steps=steps, lines=_format_todos(incomplete)),
    )]}
```

**逐步拆解**：

1. **取 incomplete**：只关心未完成的 todos。
2. **算 write_count**：`_count_write_todos(messages)` 统计历史里 write_todos 的总次数。
3. **更新 steps_since_write**：
   - 若 write_count 比上次记录大 → 刚写过 → 重置为 0，同时更新 last_write_count；
   - 否则 → +1。
4. **更新 steps_since_reminder**：无条件 +1（每进一次 before_model 就算一步）。
5. **判定 should_nag**（四个条件 AND）：
   - 有未完成 todo；
   - `len(todos) >= _NAG_MIN_TODOS`（3）—— todo 太少不值得 nag；
   - `steps_since_write >= 5`——真的很久没写 todos；
   - `steps_since_reminder >= 5`——距上次 nag 也够久了。
6. **命中时**：只重置 `steps_since_reminder = 0`（`steps_since_write` 保留，因为「没写 todos」这个事实没变），记下 steps 值。
7. **注入**：渲染 `todo/nag_reminder` 模板，传入 steps 和未完成列表。

**为什么只重置 steps_since_reminder**：设计注释写明「firing resets only steps_since_reminder」。`steps_since_write` 保留原值，才能保证「模型一直没写」这一事实在下次判定时仍成立。

**为什么用 AND 而不是 OR**：
- 只用 `steps_since_write`：模型在忙子任务时也会被反复提醒（spam）。
- 只用 `steps_since_reminder`：即使模型刚写过 todos 也会被提醒。
- AND 两者：既确保模型真的忘了，又确保上次提醒已过足够久。

## 2. 生命周期与状态隔离

**before_agent**：
```python
self._clear_other_runs(runtime)      # 清同一 thread 下其他 run 的陈旧状态
self._reset_nag_counters(runtime)    # 重置 Nag 计数（新 run 重新计步）
```

**after_agent**：
```python
self._clear_run_state(runtime)       # 清当前 run 的完成度提醒与计数
_jump_budget.clear(runtime)          # 清 jump 预算（下一 run 重新算）
```

**状态隔离的两个维度**：
- 完成度提醒 / 计数用 `(thread_id, run_id)` 作 key——不同 run 互不干扰。
- Nag 计数只用 `thread_id` 作 key——同一 thread 内跨 run 累积步数（因为 todos 是 thread 级状态）。

## 3. 一句话总结

三层保护各司其职：

| 层       | Hook                          | 触发条件                              | 动作                      |
| ------- | ----------------------------- | --------------------------------- | ----------------------- |
| Layer 1 | before_model                  | todos 存在但历史里看不到 write_todos       | 注入 `todo_reminder`      |
| Layer 2 | after_model + wrap_model_call | todos 未完成 + 模型想给最终答案 + 未超上限 + 预算够 | 入队提醒，jump_to="model" 跳回 |
| Layer 3 | before_model                  | 未完成 todos ≥3 + 距上次写≥5 + 距上次提醒≥5   | 注入 `todo_nag`           |

关键设计：
- **Layer 2 的提醒延迟到 wrap_model_call 注入**，保证在送 LLM 前才加消息；
- **Layer 3 双阈值 AND** 既防忘记又防打扰；
- **共享 jump 预算** 与 Reflection 合计 ≤3，防止无限跳转；
- **持续失败放行** 避免工具反复失败时任务卡死。
