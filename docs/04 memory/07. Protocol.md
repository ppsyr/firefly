|类别|文件|作用|
|---|---|---|
|**Protocol 契约（7 个）**|`decay_policy.py` / `forget_policy.py` / `memory_manager.py` / `memory_provider.py` / `memory_store.py` / `retriever.py` / `persona_policy.py`|定义接口签名，供实现层"实现"，供装配层"依赖"|
|**异常（1 个）**|`exceptions.py`|定义错误层次，供实现层"抛"，供上层"捕获"|

它们**都不在主链的调用栈里**，但主链的每个实现都通过它们被约束。

# 0.契约层结构树

文件分两类：**7 个 Protocol**（接口契约）+ **1 个异常层次**。

---

```
契约层（poirot/backend/agents/memory/）
│
├── memory_store.py —— MemoryStore Protocol
│   │   约束：持久化后端必须提供 8 个方法
│   │
│   ├── 定义的方法（被 MarkdownFileStore 实现）
│   │   ├── add(trace)
│   │   │     新增一条记忆。
│   │   │     用途：encode / consolidate 落库的唯一入口。
│   │   │     id 冲突抛 MemoryConflictError（防重复写）。
│   │   │     被 manager.encode / manager.consolidate 调用。
│   │   ├── get(trace_id)
│   │   │     按 id 取一条记忆。
│   │   │     用途：写操作的前置检查（update / associate / reconsolidate 都要先取）。
│   │   │     不存在返 None（不抛错，让调用方自行判空）。
│   │   │     被 manager 四操作、worker 幂等检查调用。
│   │   ├── update(trace)
│   │   │     替换一条已有记忆（frozen 语义：整条替换，非原地改）。
│   │   │     用途：associate（改 associations）、reconsolidate（改 content）、
│   │   │          retriever 强化写回（改 strength / access_count）。
│   │   │     id 不存在抛 MemoryNotFoundError（防误写）。
│   │   ├── batch_update(traces)
│   │   │     批量替换（一次提交，非 N 次 update）。
│   │   │     用途：consolidate 标记 N 条旧 trace forgotten 时用。
│   │   │     设计原因：避免 N 次 update 的 O(N²)（MarkdownFileStore 一次全量重写）。
│   │   │     原子性：任一 id 不存在抛 MemoryNotFoundError（全成功或全失败）。
│   │   ├── remove(trace_id)
│   │   │     删除一条记忆。
│   │   │     用途：显式删除（如用户要求忘记）。
│   │   │     幂等：不存在静默返回，不抛错。
│   │   ├── list_by_type(type)
│   │   │     按记忆类型列出。
│   │   │     用途：worker._maybe_consolidate 查 episodic 总量。
│   │   ├── list_by_filter(filter)
│   │   │     按过滤器列出（粗筛）。
│   │   │     用途：遗忘策略扫描候选（type / max_age_hours / metadata 粗筛）。
│   │   │     职责边界：store 只粗筛，strength 精算由调用方逐条 compute_strength。
│   │   └── list_all()
│   │         列出全部。
│   │         用途：retriever 冷启动建索引、retrieve 取候选集。
│   │
│   ├── 引用的类型
│   │   ├── schema.py · MemoryTrace / MemoryType
│   │   └── types.py · MemoryFilter
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/store.py · MarkdownFileStore（实现）
│       ├── strategies/default/manager.py · DefaultMemoryManager（构造参数类型）
│       ├── strategies/default/retriever.py · HybridRetriever（构造参数类型）
│       └── strategies/default/strategy.py · build_default_provider（装配时注入）
│
├── retriever.py —— Retriever Protocol
│   │   约束：检索后端必须提供 retrieve 方法
│   │
│   ├── 定义的方法（被 HybridRetriever 实现）
│   │   └── retrieve(query) → list[RetrievalResult]
│   │         从记忆库召回与 query 相关的记忆。
│   │         用途：MemoryMiddleware.abefore_model 每轮对话调用，把结果注入 prompt。
│   │         复合分数：score = similarity × 0.7 + strength × 0.3。
│   │         副作用：命中 trace 自动强化（lazy decay + access_count+1 + 写回 store）。
│   │                  这是「检索即强化」的核心——不用跑后台衰减任务。
│   │         过滤：forgotten trace 不召回（metadata.forgotten=True 剔除）。
│   │
│   ├── 引用的类型
│   │   └── types.py · MemoryQuery / RetrievalResult
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/retriever.py · HybridRetriever（实现）
│       ├── strategies/default/strategy.py · build_default_provider（注入 provider）
│       └── memory_recall_middleware.py · abefore_model（provider.retriever().retrieve()）
│
├── memory_manager.py —— MemoryManager Protocol
│   │   约束：四操作编排必须提供 4 个方法，且不含 LLM
│   │
│   ├── 定义的方法（被 DefaultMemoryManager 实现）
│   │   ├── encode(content, type, *, importance, source, metadata) → MemoryTrace
│   │   │     编码一条新记忆。
│   │   │     用途：worker 抽取 episodic 后落库；工具调用创建记忆。
│   │   │     幂等：id = SHA256(content+type)[:16]，同内容同 type 自动去重（返旧 trace）。
│   │   │     初始强度：strength = base_strength（由 type 决定）。
│   │   │     无 LLM：content 由外部传入（worker 从 LLM 抽取后传）。
│   │   ├── associate(trace_id_a, trace_id_b, *, strength, type) → None
│   │   │     建立两条记忆的双向关联。
│   │   │     用途：把相关记忆连起来，供扩散激活（下次检索到一条时激活另一条）。
│   │   │     副作用：超 max_associations_per_trace 时 LRU 淘汰 strength 最低的关联。
│   │   ├── consolidate(trace_ids, merged_content) → MemoryTrace
│   │   │     多条零散记忆合并为一条稳定知识（通常 episodic → semantic）。
│   │   │     用途：worker._maybe_consolidate 在 episodic 积累到阈值时调用。
│   │   │     副作用：旧 trace 标记 forgotten（不删除，保留回滚）。
│   │   │     数量校验：trace_ids 在 [2, 10] 范围，超范围抛 ValueError。
│   │   │     无 LLM：merged_content 由外部传入（worker 从 LLM 生成后传）。
│   │   ├── reconsolidate(trace_id, new_content) → MemoryTrace
│   │   │     更新一条已有记忆的内容。
│   │   │     用途：用户修正事实（如「改去大阪了」）时更新旧记忆。
│   │   │     设计：保留原 strength（视为一次访问，不重置）；记 content diff 到日志。
│   │   │     无 LLM：new_content 由外部传入。
│   │   └── 注意：没有 retrieve —— 检索统一走 Retriever
│   │         原因：检索有副作用（强化写回），单独隔离在 Retriever 更清晰。
│   │
│   ├── 引用的类型
│   │   └── schema.py · MemoryTrace / MemoryType
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/manager.py · DefaultMemoryManager（实现）
│       ├── strategies/default/strategy.py · build_default_provider（注入 provider）
│       └── worker.py · _process（self._manager.encode / consolidate）
│
├── memory_provider.py —— MemoryProvider Protocol
│   │   约束：组合门面必须提供 3 个取子组件方法
│   │
│   ├── 定义的方法（被 DefaultMemoryProvider 实现）
│   │   ├── store() → MemoryStore
│   │   │     取持久化后端。
│   │   │     用途：manager / retriever 构造时注入；bootstrap._wrap_store 包装。
│   │   ├── retriever() → Retriever
│   │   │     取检索后端。
│   │   │     用途：MemoryMiddleware.abefore_model 调 retrieve。
│   │   ├── manager() → MemoryManager
│   │   │     取四操作编排。
│   │   │     用途：worker / 工具调用调 encode / consolidate 等。
│   │   └── 注意：Protocol 不定义 shutdown —— 走 hasattr duck-type
│   │         原因：不同实现关闭需求不同（MarkdownFileStore 无资源可关；
│   │               SQLiteShadowStore / VectorStore 需关连接 / unload model）。
│   │
│   ├── 引用的类型
│   │   ├── memory_store.py · MemoryStore
│   │   ├── retriever.py · Retriever
│   │   └── memory_manager.py · MemoryManager
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/strategy.py · DefaultMemoryProvider（实现）
│       ├── bootstrap.py · get_memory_provider（返回类型）
│       └── 两个中间件（构造时接收）
│
├── decay_policy.py —— DecayPolicy Protocol
│   │   约束：衰减策略必须提供 compute_strength 方法
│   │
│   ├── 定义的方法（被 EbbinghausDecayPolicy 实现）
│   │   └── compute_strength(trace, now) → float（0.0~1.0）
│   │         算一条记忆的当前强度。
│   │         用途：retriever.retrieve 时算 strength（用于复合分数）；
│   │               forget_policy.should_forget 规则 2 判是否低于阈值。
│   │         lazy decay：不修改 trace，只返回 float。
│   │         retrieve 命中后由 Retriever 用 with_strength 更新并写回。
│   │
│   ├── 引用的类型
│   │   └── schema.py · MemoryTrace
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/decay.py · EbbinghausDecayPolicy（实现）
│       ├── strategies/default/forget.py · CompositeForgetPolicy（构造接收）
│       ├── strategies/default/manager.py · DefaultMemoryManager（构造接收）
│       └── strategies/default/retriever.py · HybridRetriever（构造接收）
│
├── forget_policy.py —— ForgetPolicy Protocol
│   │   约束：遗忘策略必须提供 should_forget 方法，且不含矛盾解决
│   │
│   ├── 定义的方法（被 CompositeForgetPolicy 实现）
│   │   └── should_forget(trace, now) → bool
│   │         判一条记忆是否应被遗忘。
│   │         用途：Phase 2 / 遗忘触发时，manager 决定是否标记 forgotten。
│   │         两规则：TTL 过期（长期未访问）或 strength 低于阈值 → True。
│   │         职责边界：只判「是否该忘」，不做实际删除；不含矛盾解决
│   │                   （矛盾解决走 reconsolidate / consolidate）。
│   │
│   ├── 引用的类型
│   │   └── schema.py · MemoryTrace
│   │
│   └── 被谁实现 / 引用
│       ├── strategies/default/forget.py · CompositeForgetPolicy（实现）
│       └── strategies/default/manager.py · DefaultMemoryManager（构造接收）
│
├── persona_policy.py —— PersonaPolicy Protocol
│   │   约束：用户画像策略必须提供 3 个方法（当前无实现，L6 预留）
│   │
│   ├── 定义的方法
│   │   ├── get_static_profile(user_id) → dict
│   │   │     取稳定事实（偏好 / 长期目标）。
│   │   │     用途：把用户长期特征注入 prompt。
│   │   ├── get_dynamic_profile(user_id) → dict
│   │   │     取近期活动（当前任务 / 最近对话）。
│   │   │     用途：把用户短期状态注入 prompt。
│   │   └── update_profile(user_id, facts) → None
│   │         更新画像。
│   │         用途：从 semantic 记忆归纳出用户特征后写回画像。
│   │         设计：借鉴 supermemory profile.static + dynamic 二分。
│   │
│   ├── 引用的类型
│   │   └── （无项目内引用）
│   │
│   └── 被谁实现 / 引用
│       └── 当前无实现、无引用（Layer 6 预留 StaticDynamicPersona）
│
└── exceptions.py —— 异常层次
    │   约束：错误信号必须带 details，fail-closed
    │
    ├── 定义的类
    │   ├── MemoryError（基类，带 details: dict + __str__ 自动展开）
    │   │     用途：所有 memory 错误的基类；details 携带上下文便于 debug；
    │   │           __str__ 自动展开成 "message (k1=v1, k2=v2)"。
    │   │   ├── MemoryNotFoundError(trace_id)
    │   │   │     找不到 trace 时抛。
    │   │   │     被 store.update / manager.associate / manager.reconsolidate 抛。
    │   │   ├── MemoryStoreError(message, *, operation, path)
    │   │   │     存储失败时抛（文件读写失败等）。
    │   │   │     带 operation + path 便于定位。
    │   │   ├── MemoryRetrieveError(message, *, query)
    │   │   │     检索失败时抛。
    │   │   │     query 超 100 字符自动截断（防日志爆炸）。
    │   │   ├── MemoryConsolidateError(message, *, trace_ids)
    │   │   │     巩固失败时抛。
    │   │   │     带 trace_ids 便于定位哪些记忆合并失败。
    │   │   └── MemoryConflictError(message, *, old_id, new_id)
    │   │         矛盾冲突时抛（如 add 时 id 已存在）。
    │   │         带 old_id + new_id 便于回溯。
    │   │
    │   └── 每个子类带上下文 details，便于 debug 回溯
    │
    └── 被谁引用 / 抛出
        ├── strategies/default/store.py
        │     ├── add 冲突 → MemoryConflictError
        │     └── update 找不到 → MemoryNotFoundError
        ├── strategies/default/manager.py
        │     └── associate / reconsolidate 找不到 → MemoryNotFoundError
        └── 上层（中间件）可捕获做优雅降级
```

---

```
契约层 = 8 个文件
├── 7 个 Protocol：定义「接口长什么样」
│   ├── 6 个有实现（被 strategies/default/* 实现）
│   └── 1 个无实现（persona_policy.py，L6 预留）
└── 1 个异常层次：定义「错误长什么样」
    └── 被 store / manager 抛出，被上层捕获

它们不直接进主链调用栈，
但主链上每个实现类都在「满足某个 Protocol」，
每个错误路径都在「抛某个 MemoryError 子类」。
```

**约束的核心意义**：让实现可换、可 mock、可独立测试。换 store 只要满足 `MemoryStore`，manager 不用改；换 retriever 只要满足 `Retriever`，中间件不用改。
