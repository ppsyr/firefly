description:

【挂载位置】
Sandbox 之后，HelpRequest / ToolCall 之前。
放在这个位置的原因：记忆可以引用 sandbox 结果；注入形态是 user message，
不进入 tool pairing 结构。

用 per-call HumanMessage 注入（保护 prompt caching，不进 system_prompt

【set_turn_id 生命周期】
before_model 注入，after_model 清除（traceability C），
用于把记忆操作关联到具体对话轮次。

从 agents/memory/middleware.py 迁到
agents/middlewares/memory_recall_middleware.py，与既有 18 个 middleware
同层治理。内容 1:1 搬迁，类名 MemoryMiddleware 保留。

【INVARIANT（必须保持的不变量）】
- 记忆是 middleware，不进 leader agent 主体（00 D9）。
- 不进 system prompt cache：用 per-call HumanMessage(hide_from_ui=True)（00 D10）。
- set_turn_id 注入 / 清除：before_model 注入，after_model 清除。
- recalled_memories 只存索引（id + score + strength），不存全量内容。

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 方法）

```

│
├─ 模块级常量
│   ├─ _CHARS_PER_TOKEN = 4                 ← 1 token ≈ 4 字符（简化估算）
│   └─ logger
│
└─ class MemoryMiddleware(AgentMiddleware)
```

## 1. 召回（abefore_model）

召回发生在**每次进 model 之前**，分 6 步。

### 1.1. 开关与 query 提取

```python
if not self._enable_recall:
    return None
query = self._extract_query(state)
if not query:
    return None
```

- `enable_recall` 默认 True，default 模式下可关。
- `_extract_query` 从 messages **从后往前**找最后一条 `HumanMessage`：
  - content 是 str → 直接用；
  - content 是 list（multimodal）→ 取第一段 `text`；
  - 其他 → `str(content)` 兜底。
- 拿不到 query 就不召回，直接返回。

### 1.2. 注入 turn_id（traceability C）

```python
turn_id = self._build_turn_id(state, runtime)
set_turn_id(turn_id)
```

- `_build_turn_id` 拼出 `"{thread_id}:turn:{len(messages)}"`：
  - thread_id 优先 `runtime.config["configurable"]["thread_id"]`；
  - 其次 `state["thread_id"]`；
  - 再退 `"unknown"`。
- `set_turn_id` 是往 Layer 2 manager 的 ContextVar 写，供 `operation_log.actor` 取用，把这次记忆操作关联到具体对话轮次。
- **注意：注入发生在 retrieve 之前**，所以后续 retriever 内部的强化写回（1A）也能带上 turn_id。

### 1.3. 召回（retrieve）

```python
results = self._provider.retriever().retrieve(MemoryQuery(text=query))
if not results:
    set_turn_id(None)
    return None
```

- 调的是 `provider.retriever()`，即 L3 的 `HybridRetriever`。
- **retriever 内部**会做两件本文件不负责的事：
  - 强化写回 1A（召回命中的记忆会被"强化"）；
  - forgotten 过滤 3B（被标记遗忘的不返回）。
- 无结果 → **清掉刚注入的 turn_id**，返回 None（不留脏状态）。

### 1.4. 格式化 + token 预算裁剪

```python
memories_text = self._format_recall(results, self._token_budget)
```

`_format_recall` 做的事：

```python
max_chars = token_budget * _CHARS_PER_TOKEN      # 2000 * 4 = 8000 字符
lines = ["[Recalled Memories]"]
current_len = len(lines[0])
for r in results:
    line = f"[score={r.score:.2f} strength={r.strength:.2f}] {r.trace.content}"
    if current_len + len(line) + 1 > max_chars:
        break                                     # 超预算直接截断
    lines.append(line)
    current_len += len(line) + 1
return "\n".join(lines)
```

- token → 字符是简化估算：1 token ≈ 4 字符。
- 逐条追加，**一旦下一行会超预算就 break**（不是截断单行，是整条丢弃）。
- 结果形如：

```
[Recalled Memories]
[score=0.87 strength=0.62] 用户偏好用 Python 做数据处理...
[score=0.75 strength=0.40] 上次讨论过 ... 的方案
```

### 1.5. 注入形态（关键设计）

```python
return {
    "messages": [
        HumanMessage(
            content=memories_text,
            name="memory_recall",
            additional_kwargs={"hide_from_ui": True},
        )
    ],
    "recalled_memories": [
        {"id": r.trace.id, "score": r.score, "strength": r.strength}
        for r in results
    ],
}
```

两个关键点：

1. **注入的是 per-call HumanMessage，不是 SystemMessage**。
   - 原因：保护 prompt caching。SystemMessage 会进 system prompt 的 cache prefix，一变就整段 cache 失效；per-call HumanMessage 每次都新加，不动 cache prefix。
   - `name="memory_recall"` 便于识别；`hide_from_ui=True` 让 UI 不展示这条内部消息。
2. **`recalled_memories` 只存索引**（id + score + strength），不存全量内容。
   - 全量内容已经在那条 HumanMessage 里了，state 里只留轻量索引供审计/trace。
   - 这样 state 不会因为记忆内容膨胀。

### 1.6. 召回链小结

```
最后一条 HumanMessage
   → _extract_query → query
   → _build_turn_id → set_turn_id(turn_id)
   → HybridRetriever.retrieve（内部强化写回 + forgotten 过滤）
   → _format_recall（token 预算裁剪）
   → HumanMessage(hide_from_ui=True) 注入 messages
   → recalled_memories 索引写 state
```

## 2. 清理（aafter_model）

清理发生在**每次 model 调用之后**，逻辑很短。

### 2.1. 清 turn_id（无条件）

```python
set_turn_id(None)
```

- **无论 before_model 有没有成功注入**，after_model 都清。
- 原因：turn_id 是 request-scoped 的，一次 model 调用结束就该归还，不能带到下一轮。
- 这跟召回链里的"无结果时 `set_turn_id(None)`"是同一套语义：**turn_id 的生命周期 = 一次模型调用**。

### 2.2. 可选抽取（默认关）

```python
if not self._enable_extract:
    return None
return None
```

- `enable_extract` 默认 False。
- 即便打开，Layer 4 也**只保留 hook 不实现抽取逻辑**——真正抽取走 Phase 2 cron L5。
- 所以这里无论如何都返回 None，不写 state。

### 2.3. 清理链小结

```
model 调用结束
   → set_turn_id(None)            ← 无条件清 turn_id
   → [enable_extract=False] → None
   → 不留任何 state 变更
```

## 3. 两条链的关系

```
┌─────────────────────────────────────────────────────┐
│ abefore_model（召回链）                              │
│   set_turn_id(turn_id)  ──┐                          │
│   retrieve                │  turn_id 生命周期        │
│   _format_recall          │  = 一次 model 调用       │
│   注入 HumanMessage       │                          │
│   写 recalled_memories    │                          │
└───────────────────────────┼─────────────────────────┘
                            │
                      （model 调用）
                            │
┌───────────────────────────┼─────────────────────────┐
│ aafter_model（清理链）     ▼                          │
│   set_turn_id(None)       ← 归还 turn_id             │
│   [extract 默认关] → None                            │
└─────────────────────────────────────────────────────┘
```

三个要点：

1. **召回是"注入"，不是"改写"**：记忆作为一条新的 HumanMessage 加进 messages，不动原消息、不进 system prompt。
2. **清理只清 turn_id**：注入的 HumanMessage 和 `recalled_memories` 不在这里清——它们随对话历史自然保留（HumanMessage 是普通消息），turn_id 才是 request-scoped 需要归还的那个。
3. **写回不在本文件**：召回命中后的"强化写回 1A"在 `HybridRetriever.retrieve` 内部完成，本中间件只负责 query 提取、注入、裁剪、turn_id 管理。

## 4. 总结

- **召回**：`abefore_model` 取最后一条 user 消息 → 注入 turn_id → 调 L3 retriever（内部强化写回 + 遗忘过滤）→ 按 token 预算裁剪 → 以 `HumanMessage(hide_from_ui=True)` 注入 messages，state 里只留轻量索引。
- **清理**：`aafter_model` 无条件 `set_turn_id(None)`，把 request-scoped 的 turn_id 归还；抽取默认关，Layer 4 只留 hook。

**召回的是什么：**

召回的是**记忆内容**（来自 L3 HybridRetriever 的历史记忆条目）。

- 取最后一条 user 消息作为 query；
- 去记忆库检索相关条目；
- 命中的记忆按 token 预算裁剪后，以一条 `HumanMessage(name="memory_recall", hide_from_ui=True)` 注入到 messages 里；
- state 里只留索引 `recalled_memories = [{id, score, strength}, ...]`，不存全量内容。

**清理的是什么：**

清理的是 **turn_id**（不是记忆本身）。

- `set_turn_id(None)` 把 request-scoped 的 turn_id 归还；
- turn_id 的生命周期 = 一次 model 调用：`abefore_model` 注入，`aafter_model` 清除；
- 注入的那条 HumanMessage 和 `recalled_memories` 不清，随对话历史自然保留。

**召回的是记忆内容，清理的是本轮 turn_id。**
