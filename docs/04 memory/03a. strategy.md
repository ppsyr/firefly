---

name: 默认 MemoryProvider 主入口（组合 store + retriever + manager）。

description:

【整体职责】
把 memory 的各个组件（store / retriever / manager / decay / forget）组装成一个
可直接使用的 DefaultMemoryProvider，是主链装配动作的落地实现。

bootstrap._load_memory_provider 调用本模块的 build_default_provider()，
本模块内部从 config 实例化 store / retriever（未注入时），组装 manager。

【组成】
1. DefaultMemoryProvider（frozen dataclass）：
   provider 的默认实现，组合 store + retriever + manager 三组件。
   构造即就绪；shutdown 走 hasattr duck-type 委托 store/retriever。

2. build_default_provider(...)：
   装配函数。支持部分注入（Layer 2 测试 mock）和完整实例化（Layer 3 从 config 建）。

【职责边界】
- 本模块只负责「组装」，不负责装配的触发时机（由 bootstrap 决定何时调用）。
- store / retriever / decay / forget 支持由调用方注入（测试用），
  未注入时从 config 实例化真实实现。
- journal 由调用方注入（bootstrap 通过 _make_journal_callback 传入），
  本模块只透传给 manager，不做事件定义。

【INVARIANT】
- DefaultMemoryProvider frozen dataclass，三组件构造时注入，运行时不可变。
- shutdown duck-type：委托 store/retriever（hasattr 检查）。
- store / retriever / journal 由调用方注入（Layer 2 测试 mock，Layer 3 后真实实例）。
- 组装顺序：先 decay / forget，再 store，再 retriever，最后 manager（后者依赖前者）。

## 0. 结构树

```
strategy.py —— 默认 MemoryProvider 主入口（组合 store + retriever + manager）
│
│   整体职责：把 memory 的各个组件（store / retriever / manager / decay / forget）
│             组装成一个可直接使用的 DefaultMemoryProvider。
│             是主链装配动作的落地实现。
│
│   主链位置：bootstrap._load_memory_provider → build_default_provider()（本模块）
│
│   装配顺序：decay → forget → store → retriever → manager（后者依赖前者）
│
│
├── 导入的模块（装配所需）
│   │
│   ├── config.py · get_memory_config()
│   │     读 storage_path 等装配参数。
│   │
│   ├── memory_manager.py · MemoryManager（Protocol）
│   │     约束 manager 的类型。
│   │
│   ├── memory_provider.py · MemoryProvider（Protocol）
│   │     约束返回值类型。
│   │
│   ├── memory_store.py · MemoryStore（Protocol）
│   │     约束 store 的类型。
│   │
│   ├── retriever.py · Retriever（Protocol）
│   │     约束 retriever 的类型。
│   │
│   └── strategies/default/ 下的实现
│       ├── decay.py · EbbinghausDecayPolicy
│       ├── forget.py · CompositeForgetPolicy
│       ├── manager.py · DefaultMemoryManager
│       ├── retriever.py · HybridRetriever
│       └── store.py · MarkdownFileStore
│
│
├── DefaultMemoryProvider（frozen dataclass）
│   │   默认 provider 实现，组合 store + retriever + manager 三组件。
│   │   构造即就绪；shutdown 走 hasattr duck-type 委托 store/retriever。
│   │
│   ├── 字段（构造时注入，运行时不可变）
│   │   ├── _store : MemoryStore
│   │   ├── _retriever : Retriever
│   │   └── _manager : MemoryManager
│   │
│   ├── store() → MemoryStore
│   │     返回持久化后端。
│   │
│   ├── retriever() → Retriever
│   │     返回检索后端。
│   │
│   ├── manager() → MemoryManager
│   │     返回四操作编排。
│   │
│   └── shutdown() → None
│       │   可选 shutdown，委托给 store / retriever（若有）。
│       │   hasattr duck-type：
│       │   - MarkdownFileStore 无 shutdown（纯文件 IO）→ 跳过。
│       │   - SQLiteShadowStore / VectorStore 有 shutdown → 调用。
│       │
│       └── 引用的模块
│           ├── store.py · shutdown()（若存在）
│           └── retriever.py · shutdown()（若存在）
│
│
└── build_default_provider(...) → MemoryProvider
    │   装配函数，支持部分注入（测试 mock）和完整实例化（从 config 建）。
    │
    ├── 参数
    │   ├── store : MemoryStore | None          ← None 时从 config 建 MarkdownFileStore
    │   ├── retriever : Retriever | None        ← None 时用 store + decay 建 HybridRetriever
    │   ├── decay_policy : EbbinghausDecayPolicy | None   ← None 时默认
    │   ├── forget_policy : CompositeForgetPolicy | None  ← None 时默认（内部用 decay）
    │   └── journal : Callable | None           ← 事件回调，透传给 manager
    │
    ├── 做什么
    │   ├── config = get_memory_config()
    │   ├── decay = decay_policy 或 EbbinghausDecayPolicy()
    │   ├── forget = forget_policy 或 CompositeForgetPolicy(decay)
    │   ├── store 未注入 → MarkdownFileStore(config.storage_path)
    │   ├── retriever 未注入 → HybridRetriever(store, decay)
    │   ├── manager = DefaultMemoryManager(store, decay, forget, journal)
    │   └── 返回 DefaultMemoryProvider(_store, _retriever, _manager)
    │
    └── 引用的模块
        ├── config.py · get_memory_config()
        ├── decay.py · EbbinghausDecayPolicy()
        ├── forget.py · CompositeForgetPolicy(decay)
        ├── store.py · MarkdownFileStore(config.storage_path)
        ├── retriever.py · HybridRetriever(store, decay)
        └── manager.py · DefaultMemoryManager(store, decay, forget, journal)
```

## 1. 装配链

```
build_default_provider(...)
    │
    ├── 1. 读 config ────────────────── config.py · get_memory_config()
    │
    ├── 2. 建策略 ──────────────────── decay.py · EbbinghausDecayPolicy()
    │                                 forget.py · CompositeForgetPolicy(decay)
    │
    ├── 3. 建 store（未注入时）──────── store.py · MarkdownFileStore(config.storage_path)
    │
    ├── 4. 建 retriever（未注入时）──── retriever.py · HybridRetriever(store, decay)
    │
    ├── 5. 建 manager ──────────────── manager.py · DefaultMemoryManager(
    │                                       store, decay, forget, journal)
    │
    └── 6. 组合 provider ───────────── DefaultMemoryProvider(
                                            _store, _retriever, _manager)
```

---

## 2. 分层差异

```
Layer 2（测试）
    └── store / retriever 由调用方注入（mock 对象）
    └── 本模块不实例化任何真实组件

Layer 3（本实现）
    └── store / retriever 未注入时从 config 实例化真实实现
    └── decay / forget / manager 总是本模块实例化

Layer 4（装配）
    └── bootstrap 调用本函数
    └── 额外注入 journal（RunJournal callback）
```

---

## 3. 总览

```
DefaultMemoryProvider  = frozen dataclass，组合 store + retriever + manager
                          store() / retriever() / manager() / shutdown()
build_default_provider = 装配函数
                          decay → forget → store → retriever → manager → provider
```
