---

name: Run journal package — 运行日志模块。

description: 

【整体职责】
记录一次运行过程中的事件流：定义运行事件的数据契约与时间工具，并把事件以追加方式
写入 events.jsonl。与 RunRecord（状态快照）互补——一个记"经历过什么"，一个记"现在是什么"。

【内容摘要】
- events      : 事件契约与时间工具（RunEvent / utc_now_iso）。
- run_journal : 事件写入器（RunJournal / _make_event_id）。

【职责边界】
- 只负责：运行事件的数据结构、时间戳工具、事件追加写入。
- 不负责：事件的产生（run_manager / activity_tracker）、事件的读取与消费
  （TUI / CLI / 审计）、运行状态的推进（run_manager）。

【两层结构】
- 事件定义：events（RunEvent + utc_now_iso）。
- 事件写入：run_journal（RunJournal.append → events.jsonl）。

【事件族】
- run.*      ：run.started / run.finished / run.failed（由 RunManager 发出）。
- activity.* ：activity.started / activity.finished / activity.heartbeat（由 ActivityTracker 发出）。

## 0. 结构树

### 0.1. 静态结构树

```
journal/ — 日志模块（运行事件流）
│
├─ __init__.py                              ← 日志包初始化（对外导出面）
│
├─ events.py                                ← 【第一层】事件定义：事件长什么样
│   ├─ _CST: timezone(+8h)                   ← 东八区时区常量
│   ├─ RunEvent(frozen)                      ← 运行事件
│   │   ├─ event_id: str                      ← 事件唯一标识
│   │   ├─ run_id: str                        ← 所属运行 ID
│   │   ├─ event_type: str                    ← 事件类型（run.* / activity.*）
│   │   ├─ payload: dict[str, Any]            ← 事件内容（形态由 event_type 约定）
│   │   ├─ created_at: str                    ← 创建时间（ISO 字符串）
│   │   └─ to_dict() -> dict                  ← 序列化（asdict）
│   └─ utc_now_iso() -> str                   ← 时间戳工具（东八区 ISO）
│
└─ run_journal.py                           ← 【第二层】事件写入：怎么落盘
    ├─ _make_event_id() -> str                ← event_id（UTC 毫秒 + 4 位随机后缀）
    └─ RunJournal                             ← 运行日志写入器
        ├─ __init__(run_id, events_path)      ← 绑定 run_id 与事件文件路径
        │   ├─ run_id: str
        │   └─ events_path: Path
        └─ append(event_type, payload) -> RunEvent ← 追加一条事件
            ├─ mkdir(parents=True, exist_ok=True)
            ├─ RunEvent(event_id, run_id, event_type, payload or {}, created_at)
            └─ events.jsonl 追加写入（JSON, indent=2 + "\n\n"）
```

---

### 0.2. 事件类型视图（已知事件族）

```
event_type 命名空间（开放）
│
├─ run.*                         ← 由 RunManager 发出
│   ├─ run.started                ← mark_running，payload: {expert_mode}
│   ├─ run.finished               ← mark_success，payload: usage（可含 total_tokens）
│   └─ run.failed                 ← mark_failed，payload: {error}
│
└─ activity.*                    ← 由 RunActivityTracker._emit 发出
    ├─ activity.started           ← start，payload: {activity_id, kind, summary, elapsed, ...}
    ├─ activity.finished          ← finish
    └─ activity.heartbeat         ← heartbeat（节流）
```

### 0.3. 运行时调用树

```
① 构造写入器（run 创建时）
RunManager.create_run(...)
    └─ RunJournal(run_id=created_run_id,
                  events_path=output_dir / "events.jsonl")
          └─ 挂到 RunContext.journal

② 追加事件（run 生命周期 / 活动）
调用方（RunManager / ActivityTracker）
    └─ journal.append(event_type, payload)
          ├─ events_path.parent.mkdir(parents=True, exist_ok=True)
          ├─ _make_event_id()                    ← UTC 毫秒 + 随机后缀
          │     └─ "evt-{UTC 时间戳}-{4 位后缀}"
          ├─ RunEvent(event_id, run_id, event_type,
          │           payload or {}, created_at=utc_now_iso())
          │     └─ utc_now_iso()                 ← 东八区 ISO（注意与 event_id 时区不同）
          └─ events.jsonl 追加写入
                └─ json.dumps(to_dict(), ensure_ascii=False, indent=2) + "\n\n"
        ═══════════ 返回 ═══════════
    └─ return RunEvent

③ 消费（读取 / 展示）
调用方（TUI / CLI / 审计）
    └─ 读取 events.jsonl（按 "\n\n" 分隔解析 JSON 块）
          └─ 按 created_at / 顺序回溯运行轨迹

═══════════ 与 RunRecord 的分工 ═══════════
RunRecord（record.json）  ← 状态快照，被覆盖更新，"现在是什么"
RunEvent（events.jsonl）  ← 事件流，只增不改，"经历过什么"
    └─ 两者均以 run_id 关联，落在同一 output_dir
```

### 0.4. 补充

**`journal/` 是运行事件流的定义与写入层——`events.py` 定义事件契约（`RunEvent`）与时间工具，`run_journal.py` 负责把事件追加写入 `events.jsonl`。**

按两层展开：

- **第一层 · 事件定义（`events.py`）**：`RunEvent` 是 frozen dataclass（event_id + run_id + event_type + payload + created_at），`to_dict` 直通序列化；`utc_now_iso()` 提供统一时间戳（实现为东八区）。
- **第二层 · 事件写入（`run_journal.py`）**：`RunJournal` 绑定 `run_id` 与 `events_path`，`append` 生成 `event_id`、构造事件、追加写入；`_make_event_id` 用 UTC 毫秒精度 + 随机后缀保证唯一。

几条主线：

- **事件即流水**：只增不改、追加写入，与 `RunRecord`（状态快照、覆盖更新）互补——一个记"经历过什么"，一个记"现在是什么"。
- **两条事件族**：`run.*`（RunManager 发的生命周期事件）与 `activity.*`（ActivityTracker 发的活动事件），`event_type` 是开放命名空间，payload 形态由其约定。
- **写入格式非严格 JSONL**：用 `indent=2 + "\n\n"` 美化，靠双换行分隔，仍可流式解析。
- **两处时区不一致**：`event_id` 内嵌 UTC 时间戳，`created_at` 用东八区（`utc_now_iso` 命名与实现偏差）；同一事件两个时间戳基准不同。
- **run_id 构造时绑定**：`append` 不接受 run_id，统一用实例的，保证事件归属明确。
- **物理落点**：`RunManager.create_run` 里指定为 `output_dir / "events.jsonl"`，与 `record.json` 同目录，均在 `RunContext.output_dir` 下。
