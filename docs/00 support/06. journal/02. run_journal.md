## 1. 运行期事件

"运行期事件"（runtime event）是 Poirot 在**一次运行（run）过程中发生的、值得记录下来的事情**——它是一条条带时间戳的"发生了什么"的记录，而不是运行结束时的"最终状态"。

### 1. 它和 `RunRecord` 的区别

这是理解它的关键。同一个 run 有两种被记录的方式：

| | `RunRecord`（record.json） | `RunEvent`（events.jsonl） |
|---|---|---|
| 性质 | **状态快照**（当前长什么样） | **事件流**（发生过什么） |
| 数量 | 一个 run 一份（被覆盖更新） | 一个 run 多条（不断追加） |
| 变化 | 每次 `mark_*` 用新记录替换旧的 | 每次 `append` 追加一条，只增不改 |
| 用途 | 查询"这个 run 现在什么状态" | 回溯"这个 run 经历了哪些事" |

一句话：**`RunRecord` 是"体检报告"，`RunEvent` 是"病历流水"。**

### 2. 从代码看你已经见过哪些事件

`RunManager` 里已经在写这些事件：

- `run.started` —— 运行开始（`mark_running`）
- `run.finished` —— 运行成功结束（`mark_success`，payload 带 usage）
- `run.failed` —— 运行失败（`mark_failed`，payload 带 error）

`RunActivityTracker._emit` 里还定义了活动类事件：

- `activity.started` / `activity.finished` / `activity.heartbeat`

也就是说，**事件类型（`event_type`）是一个开放命名空间**，目前已知的有 `run.*` 和 `activity.*` 两族。payload 的内容由具体 event_type 决定：

```python
# mark_running
journal.append("run.started", {"expert_mode": ...})

# mark_success
journal.append("run.finished", usage)      # usage 里可能含 total_tokens

# mark_failed
journal.append("run.failed", {"error": error})
```

### 3. 它的物理形态

每条事件写进 `events.jsonl`，格式是**每条事件一段 JSON（indent=2）+ 两个换行**：

```json
{
  "event_id": "evt-20240101T120000123-ab3d",
  "run_id": "run-20240101T200000-xyz9",
  "event_type": "run.started",
  "payload": {"expert_mode": false},
  "created_at": "2024-01-01T20:00:00+08:00"
}

```

注意两个细节：

- **物理文件名是 `events.jsonl`，但不是严格的一行一条**——代码里用了 `indent=2 + "\n\n"`，实际是"多行 JSON + 空行分隔"的变体。严格 JSONL 是"一行一条"，这里为了可读性做了美化，但**仍保持追加、可流式解析**的特性（靠 `\n\n` 分隔）。
- **`created_at` 用的是东八区**（`utc_now_iso()` 内部是 `_CST`），而 `event_id` 里的时间戳用的是 **UTC**（`datetime.now(timezone.utc)`）——同一条事件里两个时间戳的时区基准不同。

### 4. 它服务于什么

从消费方看，事件流的用途大致是：

- **回溯与审计**：一个 run 从 pending 到 running 到 success/failed，中间发生了什么，按时间顺序可查。
- **可观测性**：`RunActivityTracker` 的 `on_event` 回调可以把活动事件也写进来，与 `run.*` 事件汇成一条时间线。
- **调试与展示**：TUI/CLI 可以读事件流展示"运行轨迹"（对比 `RunRecord` 只给当前状态）。

### 5. 总结

> **运行期事件（`RunEvent`）是"一次运行过程中发生的事"的流水记录——每条含唯一 event_id、所属 run_id、事件类型（`run.started` / `activity.finished` 等）、payload 与时间戳，以追加方式写入 `events.jsonl`，只增不改。它与 `RunRecord`（状态快照，被覆盖更新）互补：一个记录"经历过什么"，一个记录"现在是什么"。**
