---

name: 日志事件定义 — 运行事件的数据契约与时间工具。

description: 

【整体职责】
定义运行事件（RunEvent）的数据结构：事件标识、所属 run、事件类型、payload 与
创建时间，并提供统一的时间戳工具 utc_now_iso()。供 RunJournal 写入事件流、
RunManager 记录时间戳。

【内容摘要】
- _CST           : 东八区时区常量。
- RunEvent       : 运行事件，frozen dataclass，含 to_dict 序列化。
- utc_now_iso    : 生成当前时间的 ISO 字符串。

【职责边界】
- 只负责：定义运行事件的数据结构、字段语义、序列化与时间戳工具。
- 不负责：事件的写入与持久化（run_journal）、事件的产生与消费
  （run_manager / activity_tracker / middleware）。

---

## 0. 结构树

### 0.1. 静态结构树

```
events.py — 日志事件定义（运行事件数据契约 + 时间工具）
│
├─ _CST: timezone(+8h)                        ← 东八区时区常量
│
├─ RunEvent(frozen dataclass)                 ← 运行事件
│   ├─ event_id: str                           ← 事件唯一标识
│   ├─ run_id: str                             ← 所属运行 ID
│   ├─ event_type: str                         ← 事件类型（如 run.started / activity.finished）
│   ├─ payload: dict[str, Any]                 ← 事件内容（形态由 event_type 约定）
│   ├─ created_at: str                         ← 创建时间（ISO 字符串）
│   └─ to_dict() -> dict[str, Any]             ← 序列化（asdict）
│
└─ utc_now_iso() -> str                       ← 生成当前时间 ISO 字符串
    └─ datetime.now(_CST).isoformat()          ← 使用东八区（命名与实现有偏差）
```

---

### 0.2. 运行时调用树

```
① 生成时间戳
调用方（RunManager / RunJournal）
    └─ utc_now_iso()
          └─ datetime.now(_CST).isoformat()     ← 东八区 ISO 字符串

② 构造事件
调用方（RunJournal.append）
    └─ RunEvent(event_id, run_id, event_type, payload, created_at=utc_now_iso())
          └─ 序列化
                └─ to_dict() → asdict(self)      ← 写入 events.jsonl
```

---

### 0.3. 补充

**`events.py` 是事件流的契约层——定义运行事件 `RunEvent` 的数据结构与统一时间工具 `utc_now_iso()`，供 `run_journal` 写入、`run_manager` 记时间戳。**

几条主线：

- **纯数据 + 一个工具**：`RunEvent` 是 frozen dataclass（事件标识 + 类型 + payload + 时间），`utc_now_iso()` 是唯一函数，无业务逻辑。
- **payload 由 event_type 约定**：结构本身不限制 payload 形态，事件语义靠 `event_type` 区分（如 `run.started` / `run.finished` / `run.failed` / `activity.*`）。
- **序列化直通**：`to_dict` 直接 `asdict`，无枚举转换（对比 `RunRecord.to_dict` 需要把 `status` 转 value）。
- **时间工具的偏差**：函数名为 `utc_now_iso`，实现却用东八区 `_CST`——命名与行为不一致（这解释了之前 `RunManager` 里"record 时间戳"的实际时区）。此处仅标注，不改代码。
- **与 `RunRecord` 的分工**：`RunRecord` 是"状态快照"（`record.json`），`RunEvent` 是"事件流"（`events.jsonl`），一静一动，均以 `run_id` 关联。
