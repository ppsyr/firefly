---

name: 意图识别引擎 — agent 核心能力（理解用户需求）。

description: 

【整体职责】
把用户输入识别为结构化意图，并决定是否"提前处理"（不进 graph）还是放行进 graph。
采用三分离架构：IntentNode（节点）+ IntentStrategy（匹配策略）+ IntentAction（动作），
MVP 为单层树（root → ReportIntent leaf）。与 CLI 解耦，CLI / API / IM 均可作为消费者
调用 IntentTree.detect_and_dispatch；路由决策返回 bool，由调用方决定是否进 graph。

【内容摘要】
- IntentType        : 意图类型枚举（MVP 仅 REPORT）。
- Intent            : 匹配成功的意图（type / confidence / payload）。
- MatchResult       : 策略匹配结果（matched / confidence / payload / children）。
- IntentStrategy    : 匹配策略协议（MVP 正则，未来可换 LLM）。
- IntentAction      : 匹配后动作协议（返回 bool 决定是否进 graph）。
- IntentNode        : 意图树节点（叶子有 action，中间节点有 children）。
- IntentTree        : 意图树遍历器（detect_and_dispatch）。
- AnyMatchStrategy  : root 策略，匹配任意输入进入 children。
- ReportIntentStrategy : 报告意图策略，保守关键词整句匹配（^ 锚定）。
- ReportAction      : 报告动作，调注入的 handler 触发报告合成。
- _extract_topic    : 从输入中提取 topic。
- default_intent_tree : 构造 MVP 单层树。

【职责边界】
- 只负责：意图匹配、树遍历、动作分发，返回"是否已处理"的布尔决策。
- 不负责：报告合成的实际执行（handler 由调用方注入）、图的执行（调用方决定）、
  交互呈现（CLI / API / IM）、多意图类型的完整覆盖（MVP 仅 REPORT）。

## 0. 结构树

### 0.1. 静态结构树

```
engine.py — 意图识别引擎（理解用户需求，三分离架构）
│
├─ IntentType(Enum)                          ← 意图类型枚举
│   └─ REPORT = "report"                      ← MVP 仅此一种（未来 DEEP_RESEARCH / CLARIFY_*）
│
├─ Intent(dataclass)                         ← 匹配成功的意图
│   ├─ type: IntentType                       ← 意图类型
│   ├─ confidence: float                      ← 置信度
│   └─ payload: dict                          ← 负载（如 topic）
│
├─ MatchResult(dataclass)                    ← 策略匹配结果
│   ├─ matched: bool                          ← 是否匹配
│   ├─ confidence: float                      ← 置信度
│   ├─ payload: dict                          ← 匹配负载
│   └─ children: list[IntentNode] | None      ← 子节点（非空表示进子节点）
│
├─ IntentStrategy(Protocol)                  ← 匹配策略协议
│   └─ match(text) -> MatchResult             ← MVP 正则，未来可换 LLM
│
├─ IntentAction(Protocol)                    ← 匹配后动作协议
│   └─ execute(intent, runtime) -> bool       ← True=已处理 / False=进 graph
│
├─ IntentNode(dataclass)                     ← 意图树节点
│   ├─ strategy: IntentStrategy               ← 匹配策略
│   ├─ action: IntentAction | None            ← 叶子动作
│   └─ children: list[IntentNode] | None      ← 子节点（中间节点）
│
├─ IntentTree                                ← 意图树遍历器
│   ├─ __init__(root)                         ← 绑定根节点
│   ├─ detect_and_dispatch(text, runtime) -> bool ← 对外入口
│   └─ _traverse(node, text, runtime) -> bool ← 递归遍历（匹配 → 动作/子节点）
│
├─ 【MVP 策略】
│   ├─ AnyMatchStrategy                       ← root 策略：匹配任意输入进 children
│   │   └─ match → MatchResult(matched=True, confidence=1.0)
│   └─ ReportIntentStrategy                   ← 报告意图策略（^锚定，防误触发）
│       ├─ PATTERNS: list[str]                ← 生成报告 / 出报告 / 整理成报告 / ...
│       └─ match → 命中则 payload={type, topic}
│
├─ 【MVP 动作】
│   └─ ReportAction                           ← 报告动作（调注入的 handler）
│       ├─ __init__(handler)                  ← handler 可选注入
│       └─ execute(intent, runtime) -> bool   ← handler 为 None → False
│
├─ _extract_topic(text) -> str | None        ← 从 "/report X" 或 "生成报告 X" 提取 topic
│
└─ default_intent_tree(report_handler) -> IntentTree ← 构造 MVP 单层树
    └─ root(AnyMatch) → children=[ReportIntent leaf(action=ReportAction)]
```

### 0.3. 运行时调用树

```
① 构造意图树（调用方，CLI/API/IM）
调用方
    └─ default_intent_tree(report_handler)
          ├─ root = IntentNode(AnyMatchStrategy, children=[...])
          └─ leaf = IntentNode(ReportIntentStrategy, action=ReportAction(handler))
                └─ return IntentTree(root)

② 识别与分发（每次用户输入）
调用方
    └─ tree.detect_and_dispatch(text, runtime)
          └─ _traverse(root, text, runtime)
                ├─ root.strategy.match(text)          ← AnyMatchStrategy
                │     └─ matched=True → 无 action → 进 children
                │
                └─ 遍历 children
                      └─ _traverse(leaf, text, runtime)
                            ├─ leaf.strategy.match(text) ← ReportIntentStrategy
                            │     ├─ 命中 → payload={type: REPORT, topic}
                            │     └─ 未命中 → 返回 False
                            ├─ leaf.action 非空
                            │     └─ Intent(type, confidence, payload)
                            └─ leaf.action.execute(intent, runtime)
                                  └─ ReportAction._handler(intent, runtime)
                                        ├─ True  → 已处理（不进 graph）
                                        └─ False → 进 graph

③ topic 提取（匹配命中时）
ReportIntentStrategy.match
    └─ _extract_topic(text)
          ├─ "/report X"        → X
          ├─ "生成报告 X"        → X
          └─ 无 topic            → None

④ 决策返回
detect_and_dispatch → bool
    ├─ True  → 调用方不进 graph（已提前处理）
    └─ False → 调用方进 graph（常规研究流程）
```

### 0.4. 补充

**`engine.py` 是意图识别层——用"节点 + 策略 + 动作"三分离架构把用户输入识别为意图，并返回"是否已处理"的布尔决策，由调用方决定是否进 graph。**

几条主线：

- **三分离是核心设计**：`IntentNode`（结构）、`IntentStrategy`（匹配）、`IntentAction`（执行）各司其职——策略不管动作，动作不管匹配，节点只做组合。扩展只需加 Node + Strategy + Action。
- **返回值即路由决策**：`detect_and_dispatch` / `execute` 返回 `bool`——`True` = 已处理（不进 graph），`False` = 进 graph。这是 intent 与 graph 的解耦点。
- **策略可替换**：`IntentStrategy` 是 Protocol，MVP 用正则（`ReportIntentStrategy`），未来实现 `LLMIntentStrategy` 即可替换，接口不变。
- **动作可注入**：`ReportAction` 的 handler 由调用方（CLI/API/IM）注入，**intent 模块不依赖报告合成流程**——这是与具体渠道解耦的关键。
- **保守匹配防误触发**：`ReportIntentStrategy` 的模式全部 `^` 锚定整句，所以"如何写报告"不会被误判为报告意图。
- **MVP 单层树**：root（AnyMatch）→ leaf（ReportIntent + ReportAction）；未来可扩展多层（`MatchResult.children` 已预留树扩展能力）。
- **运行时透传**：`runtime` 作为不透明对象在 `detect_and_dispatch` → `_traverse` → `execute` 间透传，模块本身不感知其结构。
- **与 `IntentState` 的关系**：本文件的 `Intent`（type/confidence/payload）是**匹配结果**；`state/types.py` 的 `IntentState`（task_type/depth/objective/...）是**状态中的意图表示**——两者名字相近但用途不同，可能存在转换关系（需看调用方）。
- **与 `ThreadState.intent` 的关系**：`ThreadState.intent: NotRequired[Any]` 是状态字段，本引擎的产出**是否写入该字段由调用方决定**——engine 本身不碰 state。
