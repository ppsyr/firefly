---

name: Runtime lifecycle package — 运行时生命周期模块。

description: 

【整体职责】
围绕"一次运行（run）"提供全生命周期支持：运行记录的数据契约、运行创建与状态推进的
调度中心、LangGraph state 持久化、以及运行期共享的上下文容器。是上层（app / AppRuntime）
与下层（graph / journal）之间的运行时枢纽。

【内容摘要】
- run_record     : 运行记录数据契约（RunRecord / RunStatus），定义一次运行的数据形态。
- run_manager    : 运行管理器（RunManager），创建 run、推进状态、持久化记录的核心调度中心。
- checkpointer   : LangGraph state 持久化单例（InMemorySaver），作为 create_agent 编译参数。
- run_context    : 运行上下文（RunContext），运行期跨组件共享的容器与路径派生。

【职责边界】
- 只负责：运行的数据形态、创建与状态推进、state 持久化、运行期上下文承载。
- 不负责：执行依赖的装配（leader_agent / capability_registry 由上层 AppRuntime 持有）、
  日志写入实现（journal 模块）、配置结构定义（config 模块）、graph 编译（create_agent）。

【四层结构】
- 数据结构：run_record（一次运行长什么样）。
- 核心管理：run_manager（怎么管理运行，装配 RunContext / RunRecord / RunJournal）。
- 持久化  ：checkpointer（LangGraph state 存/取）。
- 上下文  ：run_context（运行期在各组件间传递的上下文）。
---

## 0. 结构树

### 0.1. 静态结构树

```
runtime/ — 运行时模块（一次运行的数据、管理、持久化、上下文）
│
├─ __init__.py                              ← 运行时包初始化（对外导出面）
│
├─ run_record.py                            ← 【第一层】数据结构：一次运行长什么样
│   ├─ RunStatus(Enum)                      ← 运行状态枚举
│   │   ├─ PENDING / RUNNING / SUCCESS      ← 正常路径
│   │   └─ ERROR / TIMEOUT / CANCELLED / INTERRUPTED ← 异常路径
│   └─ RunRecord(frozen)                    ← 单次运行记录
│       ├─ run_id / thread_id / user_id     ← 标识
│       ├─ status                           ← 状态
│       ├─ created_at / updated_at          ← 时间戳（必填）
│       ├─ started_at / finished_at         ← 时间戳（可选）
│       ├─ model_name / error / total_tokens ← 执行信息（可选）
│       ├─ metadata: dict = {}              ← 扩展元数据
│       └─ to_dict()                        ← 序列化（status → value）
│
├─ run_manager.py                           ← 【第二层】核心管理：怎么管理运行
│   ├─ _CST: timezone(+8h)                  ← 东八区时区常量
│   ├─ _make_run_id() -> str                ← 生成 run_id（时间戳 + 随机后缀）
│   └─ RunManager
│       ├─ __init__(config)                  ← 初始化
│       │   ├─ _records: dict[run_id, RunRecord]   ← 内存记录映射
│       │   └─ _contexts: dict[run_id, RunContext] ← 内存上下文映射
│       │
│       ├─ create_run(...) -> RunContext     ← 创建 run（装配三件套）
│       │   ├─ _make_run_id()                ← 缺省生成 run_id
│       │   ├─ output_dir                    ← {thread_dir}/runs/{id} | {logs_root}/{id}
│       │   ├─ RunJournal(run_id, events_path)     ← 装配 journal（journal 模块）
│       │   ├─ RunContext(...)               ← 装配上下文（run_context 模块）
│       │   ├─ RunRecord(status=PENDING)     ← 装配记录（run_record 模块）
│       │   └─ _write_record → record.json   ← 首次落盘
│       │
│       ├─ mark_running(run_id) -> RunRecord ← PENDING → RUNNING
│       │   ├─ replace(..., status=RUNNING, started_at, updated_at)
│       │   └─ journal.append("run.started", ...)
│       │
│       ├─ mark_success(run_id, usage) -> RunRecord ← RUNNING → SUCCESS
│       │   ├─ replace(..., status=SUCCESS, finished_at, total_tokens)
│       │   └─ journal.append("run.finished", usage)
│       │
│       ├─ mark_failed(run_id, error) -> RunRecord ← RUNNING → ERROR
│       │   ├─ replace(..., status=ERROR, finished_at, error)
│       │   └─ journal.append("run.failed", {error})
│       │
│       ├─ get_run(run_id) -> RunRecord | None
│       ├─ _store_record(record)             ← 内存 + 写盘
│       ├─ _write_record(record)             ← 写 record.json
│       ├─ _require_record(run_id)           ← 取记录；缺失抛 KeyError
│       └─ _require_context(run_id)          ← 取上下文；缺失抛 KeyError
│
├─ checkpointer.py                          ← 【第三层】持久化：LangGraph state 存/取
│   ├─ _cp: Checkpointer | None             ← 全局单例
│   ├─ get_checkpointer() -> Checkpointer   ← 返回单例（MVP: InMemorySaver）
│   └─ reset_checkpointer()                 ← 重置单例（测试用）
│
└─ run_context.py                           ← 【第四层】上下文传递：运行期共享容器
    └─ RunContext(frozen)
        ├─ run_id / thread_id                 ← 标识
        ├─ user_id / session_id / trace_id    ← 溯源标识（可选）
        ├─ config: AppConfig                  ← 应用配置
        ├─ budget: dict = {}                  ← 运行期预算（可变）
        ├─ output_dir: Path                   ← 输出目录
        ├─ enabled_middlewares: tuple         ← 启用的中间件
        ├─ journal: RunJournal                ← 运行日志
        ├─ record_path -> Path                ← output_dir / "record.json"
        ├─ events_path -> Path                ← output_dir / "events.jsonl"
        └─ artifacts_dir -> Path              ← output_dir / "artifacts"
```

### 0.2. 运行时调用树（从 run_manager 开始，展开装配过程）

```
RunManager.create_run(thread_id, user_id, run_id, session_id, trace_id,
                      model_name, thread_dir)          ← 装配中心
│
├─ ① 生成标识
│   └─ created_run_id ← run_id | _make_run_id()         ← _CST + 随机后缀
│
├─ ② 决定输出目录
│   └─ output_dir ← {thread_dir}/runs/{run_id}
│                  | {config.runtime.logs_root}/{run_id}
│
├─ ③ 装配 RunJournal                                    ← journal 模块
│   └─ RunJournal(run_id=created_run_id,
│                 events_path=output_dir / "events.jsonl")
│
├─ ④ 装配 RunContext                                    ← run_context 模块
│   └─ RunContext(
│         run_id=created_run_id,
│         thread_id / user_id / session_id / trace_id,  ← 透传
│         config=self.config,                           ← AppConfig
│         budget={},                                    ← 空预算，运行期填充
│         output_dir=output_dir,                        ← 同 journal 目录
│         enabled_middlewares=self.config.middleware.enabled, ← 来自 config
│         journal=journal)                              ← 步骤 ③ 产物
│
├─ ⑤ 装配 RunRecord                                     ← run_record 模块
│   └─ RunRecord(
│         run_id=created_run_id,
│         thread_id / user_id,                          ← 透传
│         status=RunStatus.PENDING,                     ← 初始状态
│         created_at=updated_at=now,                    ← utc_now_iso()
│         model_name=model_name | config.models.researcher_model,
│         metadata={"expert_mode": config.runtime.expert_mode})
│
├─ ⑥ 写入内存映射
│   ├─ _contexts[created_run_id] = context
│   └─ _records[created_run_id] = record
│
├─ ⑦ 首次落盘
│   └─ _write_record(record)
│         ├─ _require_context(run_id)                   ← 取 output_dir
│         ├─ output_dir.mkdir(parents=True, exist_ok=True)
│         └─ record_path.write_text(json(record.to_dict()))
│
└─ return RunContext                                    ← 交给调用方（AppRuntime / app 层）

═══════════ 状态推进（后续调用） ═══════════

mark_running(run_id)
├─ _require_record(run_id)
├─ replace(record, status=RUNNING, started_at, updated_at)
├─ _store_record → _write_record                        ← 内存 + record.json
└─ journal.append("run.started", {expert_mode})         ← events.jsonl

mark_success(run_id, usage_summary)
├─ replace(record, status=SUCCESS, finished_at, total_tokens)
├─ _store_record → _write_record
└─ journal.append("run.finished", usage)

mark_failed(run_id, error)
├─ replace(record, status=ERROR, finished_at, error)
├─ _store_record → _write_record
└─ journal.append("run.failed", {"error": error})

═══════════ 持久化（LangGraph 侧，独立单例） ═══════════

get_checkpointer()                                       ← checkpointer 模块
└─ _cp 为 None → InMemorySaver()
      └─ 作为 create_agent(checkpointer=...) 编译参数交给 LangGraph
            └─ thread_id 经 config.configurable 透传，按 thread 存取 state
```

### 0.3. 补充

**`runtime/` 围绕"一次运行"组织：`run_record` 定义运行的数据形态，`run_manager` 是创建与状态推进的调度中心（装配 RunContext / RunRecord / RunJournal），`checkpointer` 负责 LangGraph state 持久化，`run_context` 是运行期共享的上下文容器。**

按四层展开：

- **第一层 · 数据结构（`run_record.py`）**：`RunRecord` 定义一次运行的"名词"——标识、状态、时间戳、模型/token/错误、元数据；`RunStatus` 定义状态枚举。frozen、可序列化。
- **第二层 · 核心管理（`run_manager.py`）**：`create_run` 是装配中心，一次性组装 `RunJournal` + `RunContext` + `RunRecord`，并落盘 `record.json`；`mark_running / mark_success / mark_failed` 推进状态，每次变更写盘 + 记事件；内存双映射（`_records` / `_contexts`）。
- **第三层 · 持久化（`checkpointer.py`）**：LangGraph state 存取的全局单例，MVP 用 `InMemorySaver`（进程内），经 `create_agent(checkpointer=...)` 交给 LangGraph 内部处理，`thread_id` 经 config 透传。
- **第四层 · 上下文传递（`run_context.py`）**：运行期跨组件共享的容器（标识 + config + budget + output_dir + journal），派生出 `record_path` / `events_path` / `artifacts_dir` 三类路径。

两条主线的关系：

- **记录线（RunManager）**：`RunRecord`（状态快照，record.json）+ `RunJournal`（事件流，events.jsonl），由 RunManager 持久化到 `output_dir`。
- **state 线（Checkpointer）**：LangGraph graph 的 state（对话/执行状态），由 LangGraph 经 checkpointer 按 `thread_id` 持久化。
- 两者互补：前者是"运行元信息"，后者是"执行状态"，均以 `run_id` / `thread_id` 关联。

一个值得注意的边界：

- **`RunContext` 不含执行依赖**：不含 `leader_agent` / `capability_registry` 等执行对象，说明 runtime 层只承载"运行元信息 + 配置 + 日志 + 路径"，执行对象由上层（AppRuntime）持有——这与之前 `_ReportRuntime` Protocol 的形状相呼应。
- **装配集中在 create_run**：RunContext / RunRecord / RunJournal 三件套在 `create_run` 一次性装配，是 runtime 层"承上启下"的关键入口。
