---

name: 能力注册表 — 运行期能力的统一容器与访问入口。

description: 

【整体职责】
集中承载一次运行所需的各类能力对象（模型、工具、reporter、artifact_store、
sandbox_provider、skill_store、specialist_registry、subagent_provider、
memory_provider），并提供按名/按类的 getter。缺失能力时抛 CapabilityMissingError。

【内容摘要】
- CapabilityMissingError  : 所需运行期能力缺失时抛出（继承 KeyError）。
- CapabilityRegistry      : 能力注册表，frozen dataclass，含能力字段与 getter。

【职责边界】
- 只负责：承载能力对象、提供 getter、缺失时抛错。
- 不负责：能力对象的构造与注册（由上层 bootstrap / AppRuntime 装配）、
  能力的实现（reporter / artifact_store / provider 等各自模块）。

## 0. 结构树

### 0.1. 静态结构树

```
registry.py — 能力注册表（运行期能力的统一容器与访问入口）
│
├─ CapabilityMissingError(KeyError)          ← 所需运行期能力缺失时抛出
│
└─ CapabilityRegistry(frozen)                ← 能力注册表
    ├─ 【按名索引容器】
    │   ├─ models: dict[str, Any] = {}          ← 模型集合
    │   └─ tools: dict[str, Any] = {}           ← 工具集合
    │
    ├─ 【单例能力字段】（Any | None）
    │   ├─ reporter: Any | None = None          ← 报告器
    │   ├─ artifact_store: Any | None = None    ← 产物存储
    │   ├─ sandbox_provider: Any | None = None  ← 沙箱提供者
    │   ├─ skill_store: Any | None = None       ← 技能存储
    │   ├─ specialist_registry: Any | None = None ← specialist 注册表
    │   ├─ subagent_provider: Any | None = None ← 子 Agent 提供者
    │   └─ memory_provider: Any | None = None   ← 记忆提供者
    │
    └─ 【getter】（缺失即抛 CapabilityMissingError）
        ├─ 按名类
        │   ├─ get_model(name) -> Any            ← models[name]，缺则 "model not registered: {name}"
        │   └─ get_tool(name) -> Any             ← tools[name]，缺则 "tool not registered: {name}"
        └─ 单例类
            ├─ get_reporter() -> Any              ← reporter
            ├─ get_artifact_store() -> Any        ← artifact_store
            ├─ get_sandbox_provider() -> Any      ← sandbox_provider
            ├─ get_skill_store() -> Any           ← skill_store
            ├─ get_specialist_registry() -> Any   ← specialist_registry
            ├─ get_subagent_provider() -> Any     ← subagent_provider
            └─ get_memory_provider() -> Any       ← memory_provider
```

### 0.3. 运行时调用树

```
① 构造（上层装配，一次性注入）
bootstrap / AppRuntime
    └─ CapabilityRegistry(
          models={...}, tools={...},
          reporter=..., artifact_store=..., sandbox_provider=...,
          skill_store=..., specialist_registry=..., subagent_provider=...,
          memory_provider=...)
          └─ frozen，构造后不可变

② 挂载（随运行上下文传递）
    └─ 挂到 RunContext / AppRuntime（供各中间件与组件访问）
          └─ 如 _ReportRuntime.capability_registry

③ 消费（getter，缺失即抛错）
调用方（middleware / thread_report / multiagent / memory / skill）
    ├─ registry.get_reporter()          ← 缺则 CapabilityMissingError
    ├─ registry.get_artifact_store()    ← 缺则 CapabilityMissingError
    ├─ registry.get_model(name)          ← 缺则 CapabilityMissingError("model not registered: {name}")
    └─ ...（其余 getter 同理）

④ 异常传播
CapabilityMissingError(KeyError)
    └─ 由调用方 / graph 外层捕获，转为明确提示（fail-closed，不静默返回 None）
```

### 0.4. 补充

**`registry.py` 是运行期能力的"容器 + 访问入口"——把模型、工具与七类单例能力集中承载，用 getter 统一访问，缺失即 fail-closed 抛错。**

几条主线：

- **两类承载方式**：`models` / `tools` 为**按名索引的 dict**（一个能力多个实例）；其余七个（reporter / artifact_store / sandbox_provider / skill_store / specialist_registry / subagent_provider / memory_provider）为**单例字段**（一个能力一个实例）。
- **fail-closed**：getter 在缺失时抛 `CapabilityMissingError`（继承 `KeyError`），**不返回 None**——避免调用方静默拿到空值导致后续隐晦错误。
- **frozen 但字段是引用**：注册表本身不可变，但 `models` / `tools` 是可变 dict、单例字段是对象引用——"不可变"指字段不能重新赋值，不代表容器内容不可变。
- **装配在上层**：本模块**只承载、不构造**——谁把 reporter / artifact_store 等注册进去，答案在上层（`bootstrap` / AppRuntime），这也是你之前问"Lead Agent 挂哪"的同一条线索。
- **能力覆盖面广**：从模型/工具，到报告/产物、沙箱、技能、多 Agent（specialist / subagent）、记忆——它其实是**一次运行所需依赖的总装配点**。
- **错误消息可区分**：按名 getter 带 `{name}`，单例 getter 只报能力名，便于定位是"哪个名字没注册"还是"这类能力整体缺失"。
- **与 `_ReportRuntime` 呼应**：`thread_report` 里的 `capability_registry.get_reporter()` / `get_artifact_store()` 正是本类 getter 的调用点。
