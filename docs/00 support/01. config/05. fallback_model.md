---

name: FallbackChatModel — 角色路由链 + 运行时故障降级。

description: 

【整体职责】
包装一组 BaseChatModel（按角色优先级链），对上层表现为单个 BaseChatModel。
调用时从当前活跃 provider 试起，遇瞬时 API 错误（限流 / 超时 / 连接 / 5xx）
自动降级到下一个；成功后记忆活跃 provider，避免每轮都从链首重试主力。
deepseek 作为链尾兜底。

【内容摘要】
- _should_fallback : 判断异常是否应触发降级（瞬时错误降级，客户端错误抛出）。
- FallbackChatModel: 降级链模型，实现 _generate / _agenerate / bind_tools。

【职责边界】
- 只负责：按链顺序调用、瞬时失败降级、记忆活跃 provider、对链内模型绑定 tools。
- 不负责：链的构造与选择（provider_config.route_chain_for / model_router）、
  模型实例化（build_chat_model）、角色路由表定义（MODEL_ROUTES）。

## 0. 结构树

### 0.1. 静态结构树

```
fallback_model.py — 角色路由链 + 运行时故障降级
│
├─ _should_fallback(exc) -> bool                 ← 判断异常是否应触发降级
│   ├─ TimeoutError / ConnectionError → True      ← 网络/超时类，降级
│   ├─ openai.APITimeoutError / APIConnectionError → True
│   ├─ openai.RateLimitError → True               ← 限流，降级
│   ├─ openai.APIStatusError 且 status >= 500 → True ← 5xx 服务端错误，降级
│   ├─ ImportError → 忽略（openai 未装时跳过）
│   └─ 其余（400/401/404 等客户端错误）→ False      ← 不降级，抛出
│
└─ FallbackChatModel(BaseChatModel)              ← 降级链模型，对上层表现为单个 ChatModel
    ├─ models: list[Any]                          ← 链，元素为 BaseChatModel 或其 bind_tools 后 RunnableBinding
    ├─ provider_names: list[str] = []             ← 链内 provider 名，用于标识
    ├─ _active: int = PrivateAttr(0)              ← 活跃 provider 索引（记忆上次成功）
    │
    ├─ _generate(messages, stop, run_manager, **kwargs) -> ChatResult
    │   ├─ 从 (self._active + offset) % n 轮转      ← 避免每轮从链首重试主力
    │   ├─ models[idx].invoke(...)                 ← 统一用 invoke 兼容两种形态
    │   ├─ 成功 → self._active = idx，返回 ChatResult
    │   ├─ 失败且 _should_fallback → 记 last_exc，continue
    │   ├─ 失败且不可降级 → 立即 raise
    │   └─ 链耗尽 → raise last_exc
    │
    ├─ _agenerate(messages, stop, run_manager, **kwargs) -> ChatResult
    │   └─ 逻辑同 _generate，使用 ainvoke（异步）
    │
    ├─ bind_tools(tools, **kwargs) -> FallbackChatModel
    │   ├─ 对链内每个 model 绑定 tools              ← [m.bind_tools(tools) for m in models]
    │   └─ 返回新实例（_active 重置为默认 0）
    │
    ├─ _llm_type -> str                           ← "fallback-chat-model"
    │
    └─ _identifying_params -> dict[str, Any]      ← {providers, active}
```

### 0.2. 运行时调用树

```
① 构造（由 model_router / provider_config 提供链）
model_router
    ├─ discover_available_providers()              ← 过滤 enabled + key 非空
    ├─ route_chain_for(role, providers)            ← 按 MODEL_ROUTES 筛链，保证 deepseek 在链尾
    ├─ build_chat_model(config) × N                ← 逐 provider 实例化 BaseChatModel
    └─ FallbackChatModel(models=[...], provider_names=[...])

② 调用（同步 / 异步）
上层（Leader / 中间件）
    └─ FallbackChatModel.invoke / ainvoke
          └─ _generate / _agenerate
                ├─ 从 _active 起轮转链内模型
                │     └─ models[idx].invoke / ainvoke(messages, stop, **kwargs)
                ├─ 成功 → 更新 _active，return ChatResult(generations=[ChatGeneration(ai)])
                └─ 异常 → _should_fallback 判定
                      ├─ True  → 记 last_exc，continue（降级下一个）
                      └─ False → raise（立即暴露）
                └─ 链耗尽 → raise last_exc

③ 工具绑定
上层（需要 tools 时）
    └─ FallbackChatModel.bind_tools(tools)
          └─ [m.bind_tools(tools) for m in models]  ← 逐 model 绑定
                └─ return FallbackChatModel(models=bound, ...)  ← 新实例，_active 重置

④ 标识
_identifying_params / _llm_type
    └─ 供 LangChain 追踪 / 日志使用
```

### 0.3. 补充

**`fallback_model.py` 是运行时降级层——把"角色优先级链"包装成一个 `BaseChatModel`，对上层透明地在瞬时故障时切换到下一个 provider，并记忆活跃 provider 避免反复重试主力。**

几点补充：

- **只降级瞬时错误**：`_should_fallback` 明确区分"换 provider 可能恢复"（超时/限流/连接/5xx）与"换也会失败"（400/401/404），后者直接抛出，避免无谓降级掩盖真实问题。
- **轮转起点记忆**：从 `_active` 而非 0 起试，成功后更新 `_active`，使得主力 provider 恢复后不必每轮都从链首重试。
- **统一用 invoke 而非 _generate**：因为链内元素可能是 `bind_tools` 后的 `RunnableBinding`，只有 `invoke` / `ainvoke` 对两种形态都可用。
- **deepseek 兜底是路由层保证**：本文件不感知 deepseek，链尾兜底由 `route_chain_for` 保证；本文件只负责"按链顺序降级"。
- **bind_tools 返回新实例**：不可变式设计，避免污染原对象；新实例 `_active` 重置为 0。
- **frozen 的对比**：本类继承 `BaseChatModel`（Pydantic 模型），用 `PrivateAttr` 存可变状态 `_active`，与项目其他 frozen dataclass 的"完全不可变"取向不同——因为降级需要运行时记忆。
