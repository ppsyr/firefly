---

name: ModelRouter — 角色化智能路由，按 MODEL_ROUTES 链构造 FallbackChatModel，deepseek 兜底。

description: 

【【整体职责】
模型构造的对外入口：按角色（researcher / reporter / reflection）从可用 provider 中
选出路由链，构造带降级能力的 FallbackChatModel；也支持强制单 provider（测试 / 调试）。

【内容摘要】
- ModelRouter.__init__    : 初始化，接受可选 providers 或自动发现可用 provider。
- ModelRouter.build_model : 按角色路由链构造 FallbackChatModel（多 provider 降级）。
- ModelRouter.build_from: 从指定 provider 开始构造角色降级链。
- ModelRouter.chain_names : 返回某角色的 provider 链名列表。

【职责边界】
- 只负责：角色 → 链的编排，把 chain 中的 provider 逐个实例化并组装为 FallbackChatModel。
- 不负责：provider 配置解析（provider_config）、模型实例化细节（build_chat_model）、
  降级逻辑（FallbackChatModel）、路由表定义（MODEL_ROUTES）。
---

```
MODEL_ROUTES = {
    "researcher": ["openai", "qwen", "anthropic", "gemini", "deepseek"],
    "reporter":   ["qwen", "deepseek"],
    "reflection": ["deepseek"],
}
```

## 0. 结构树

### 0.1. 静态结构树

```
model_router.py — 角色化智能路由
│
└─ ModelRouter                                 ← 模型构造的对外入口
    ├─ __init__(providers=None)                 ← 初始化；未注入则自动 discover_available_providers()
    │   └─ _providers: list[ProviderConfig]     ← 可用 provider 列表（可注入，便于测试）
    │
    ├─ build_model(role) -> BaseChatModel       ← 按角色路由链构造 FallbackChatModel
    │   ├─ route_chain_for(role, _providers)    ← 取链（deepseek 兜尾由路由层保证）
    │   ├─ [build_chat_model(p) for p in chain] ← 逐 provider 实例化
    │   └─ return FallbackChatModel(models, provider_names)
    │
    ├─ build_from(provider, model=None, role="researcher") ← CLI --provider 从指定 provider 开始
    │   ├─ MODEL_ROUTES[role] 中定位 provider，跳过之前的节点
    │   ├─ 覆盖起始 provider 的 model（可选）
    │   └─ 后续 provider 组装为 FallbackChatModel
    │
    └─ chain_names(role) -> list[str]           ← 返回角色的 provider 链名列表
        └─ route_chain_for(role, _providers) → [p.provider for p in chain]
```

---

### 0.2. 运行时调用树

```
① 构造路由器
调用方（CLI / bootstrap / 上层）
    └─ ModelRouter(providers=None | [...])
          └─ providers 为 None → discover_available_providers()
                ├─ _all_configs()               ← provider_config
                └─ 过滤 enabled 且 key 非空（或免 key），按 priority 升序

② 按角色构造降级模型（主路径）
调用方
    └─ router.build_model(role)
          ├─ route_chain_for(role, _providers)
          │     ├─ MODEL_ROUTES[role] 筛 by_name
          │     └─ 保证 deepseek 在链尾（若可用）
          ├─ build_chat_model(p) × N            ← 逐 provider 按 kind 实例化
          └─ FallbackChatModel(models=[...], provider_names=[...])
                └─ 后续 invoke / ainvoke 时按链降级（见 fallback_model）

③ 从指定 provider 开始构造降级模型（CLI / 运行时切换）
调用方（CLI --provider）
    └─ router.build_from(provider, model, role="researcher")
          ├─ MODEL_ROUTES[role] 中定位 provider
          ├─ provider 的 model 可由参数覆盖
          └─ 后续 provider → FallbackChatModel 降级链

④ 查询链名
调用方
    └─ router.chain_names(role)
          └─ route_chain_for(role, _providers) → [provider names]
```

### 0.3. 补充

**`model_router.py` 是模型构造的对外门面——把"角色 → 路由链 → 实例化 → 组装降级模型"这条链路收敛为几个方法，供上层按角色取模型。**

几点补充：

- **纯编排、无策略**：本类不实现路由规则与降级逻辑，全部委托 `route_chain_for`（路由）与 `FallbackChatModel`（降级），自身只负责串起来。
- **providers 可注入**：构造时传入 `providers` 则复用，否则自动 `discover_available_providers()`，便于测试与复用（避免每次重新发现）。
- **两种构造路径**：`build_model`（按角色、完整 provider 链）为默认路径；`build_from`（从指定 provider 开始、保留后续 provider 作为降级）服务于 CLI `--provider` 与运行时切换。
- **deepseek 兜底不在本层**：链尾兜底由 `route_chain_for` 保证，本类不重复处理，保持职责单一。
- **`chain_names` 是轻量查询**：只返回链名列表，不实例化模型，便于展示或调试路由结果。
