---

name: RunActivityTracker — 追踪运行期活动，用于可观测性。(还未实现)

description: 

【整体职责】
把每次模型调用、工具调用、沙箱命令、specialist 调用追踪为一条"活动"，
记录其生命周期（started / finished）与心跳（last_progress_at）。消费者（TUI / CLI）
轮询 get_active() 展示当前活动，并据此检测无进展停滞。

【内容摘要】
- Activity            : 单条活动记录，含生命周期、心跳、状态、输出量与错误。
- RunActivityTracker  : 活动追踪器，管理活动集合与生命周期事件。
- RunActivityTracker.start / finish / heartbeat : 活动生命周期入口。
- RunActivityTracker.get_active / get_recent_completed / get_stale_activities
- RunActivityTracker.total_elapsed / reset
- _emit               : 向回调发送活动事件。

【职责边界】
- 只负责：追踪活动生命周期与心跳、检测停滞、汇总耗时、对外发事件。
- 不负责：活动的业务语义（模型/工具/沙箱调用本身）、事件消费与展示（TUI / CLI）、
  停滞的处置（interrupt_protection）、态势汇总（situation_report）。

## 0. 结构树

### 0.1. 静态结构树

```
activity_tracker.py — RunActivityTracker（追踪运行期活动）
│
├─ Activity(dataclass)                       ← 单条活动记录
│   ├─ activity_id: str                      ← 活动唯一标识
│   ├─ kind: str                             ← "model" | "tool" | "sandbox" | "specialist"
│   ├─ summary: str                          ← 活动摘要
│   ├─ started_at: float                     ← 开始时间戳
│   ├─ last_progress_at: float               ← 最近进展时间戳（心跳）
│   ├─ status: str = "running"               ← "running" | "ok" | "error" | "cancelled"
│   ├─ output_size: int = 0                  ← 输出大小
│   ├─ finished_at: float | None = None      ← 结束时间戳
│   ├─ error: str | None = None              ← 错误信息（仅失败时填）
│   ├─ elapsed (property) -> float           ← 已耗时（到结束或当前）
│   └─ no_progress_duration (property) -> float ← 距最近进展的时长
│
└─ RunActivityTracker                        ← 活动追踪器
    ├─ __init__(heartbeat_interval=10.0,      ← 初始化
    │           no_progress_threshold=180.0,
    │           on_event=None)
    │   ├─ _heartbeat_interval: float         ← 心跳事件节流间隔
    │   ├─ _no_progress_threshold: float      ← 无进展停滞阈值
    │   ├─ _on_event: Callable | None         ← 事件回调
    │   ├─ _activities: dict[id, Activity]    ← 进行中的活动
    │   ├─ _completed: list[Activity]         ← 已完成活动归档
    │   └─ _last_heartbeat_emit: dict[id, float] ← 各活动上次发心跳时间
    │
    ├─ start(activity_id, kind, summary) -> Activity ← 开始活动
    │   ├─ 新建 Activity（status=running）
    │   ├─ 登记 _activities
    │   └─ _emit("activity.started", activity)
    │
    ├─ finish(activity_id, status, error, output_size) -> Activity | None ← 结束活动
    │   ├─ 从 _activities 弹出（不存在 → None）
    │   ├─ 更新 status / error / output_size / finished_at
    │   ├─ 归档 _completed
    │   ├─ 清理 _last_heartbeat_emit
    │   └─ _emit("activity.finished", activity)
    │
    ├─ heartbeat(activity_id, output_size) -> None ← 刷新进展
    │   ├─ 更新 last_progress_at / output_size
    │   └─ 距上次 emit >= heartbeat_interval → _emit("activity.heartbeat")
    │
    ├─ get_active() -> list[Activity]          ← 进行中的活动
    ├─ get_recent_completed(limit=8) -> list   ← 最近完成的活动
    ├─ get_stale_activities() -> list          ← 无进展超阈值的活动
    │   └─ no_progress_duration >= _no_progress_threshold
    ├─ total_elapsed() -> float                ← 全部活动覆盖的总耗时
    │   └─ max(ends) - min(starts)
    ├─ reset() -> None                          ← 清空全部活动与心跳状态
    │
    └─ _emit(event_type, activity) -> None     ← 向回调发事件（None 时跳过）
        └─ 事件 dict：{type, activity_id, kind, summary, elapsed, status, output_size}
```

### 0.2. 运行时调用树

```
① 开始活动（模型 / 工具 / 沙箱 / specialist 调用前）
调用方（middleware / runtime）
    └─ tracker.start(activity_id, kind, summary)
          ├─ 新建 Activity（started_at = last_progress_at = now）
          ├─ _activities[activity_id] = activity
          └─ _emit("activity.started", activity)   ← on_event 回调

② 进展心跳（调用过程中）
调用方
    └─ tracker.heartbeat(activity_id, output_size)
          ├─ activity.last_progress_at = now
          ├─ activity.output_size = output_size
          └─ 距上次 emit >= heartbeat_interval
                └─ _emit("activity.heartbeat", activity) ← 节流

③ 结束活动（调用完成 / 失败）
调用方
    └─ tracker.finish(activity_id, status, error, output_size)
          ├─ _activities.pop(activity_id)        ← 不存在 → 返回 None
          ├─ 更新 status / error / output_size / finished_at
          ├─ _completed.append(activity)         ← 归档
          ├─ _last_heartbeat_emit.pop(activity_id)
          └─ _emit("activity.finished", activity)

④ 消费（TUI / CLI 轮询）
    ├─ tracker.get_active()                      ← 展示当前活动
    ├─ tracker.get_recent_completed(limit)       ← 展示最近完成
    ├─ tracker.get_stale_activities()            ← 检测停滞
    └─ tracker.total_elapsed()                   ← 展示总耗时

⑤ 重置（新 run / 测试）
    └─ tracker.reset()
```

### 0.3. 补充

**`activity_tracker.py` 是可观测性的基础信号源——把每次模型/工具/沙箱/specialist 调用登记为一条带生命周期与心跳的"活动"，供消费者展示当前活动并检测无进展停滞。**

几条主线：

- **活动即一等公民**：`Activity` 记录 kind、lifecycle（started/finished）、heartbeat（last_progress_at），两个属性 `elapsed` / `no_progress_duration` 直接服务展示与停滞判定。
- **三类事件**：`activity.started` / `activity.finished` / `activity.heartbeat`，经 `_emit` 发回调，消费者据此实时更新。
- **心跳节流**：`heartbeat` 按 `heartbeat_interval` 节流发事件，避免高频输出；但 `last_progress_at` 每次都更新，保证停滞判定准确。
- **停滞检测**：`get_stale_activities` 用 `no_progress_duration >= no_progress_threshold` 筛出疑似卡住的活动，对应 `HitlConfig.no_progress_timeout`。
- **完成即归档**：`finish` 把活动从进行中移入 `_completed`，保持 `_activities` 只含活跃项，`get_recent_completed` 提供有限历史的回看。
- **线程安全依赖 GIL**：图执行单线程，故不加锁——这是显式假设，若未来并行执行需补锁。
- **回调可选**：`_on_event` 为 None 时全部 `_emit` 空操作，使 tracker 在无消费者时零开销。
