name: ClaudeMarketplaceSource — 拉 Claude Marketplace registry 安装 skill。

description: 

【整体职责】
hub 的远程技能源之一：从 Claude Marketplace registry（Anthropic 官方技能生态）
发现技能，转成 SkillMeta。
- 拉取 registry（HTTP GET + JSON 解析）。
- 按关键词匹配 name / description，转 SkillMeta。
- registry 不可达时降级返空（不抛异常）。

设计（design_docs/46 §2.4）：
- 拉 Claude Marketplace registry（Anthropic 官方 skill 生态）。
- 转 SkillMeta。
- identifier 格式：claude-marketplace:<skill-name>。

【内容摘要】
模块常量：
- _MARKETPLACE_REGISTRY_URL : Claude Marketplace registry URL（MVP 用 placeholder）。

类方法：
- __init__(registry_url)                : 保存 registry URL。
- search(query, limit) -> list[SkillMeta] : 搜 registry，转 SkillMeta。
- fetch(identifier, dest_dir) -> Path   : 下载 skill（MVP 占位）。
- preview(identifier) -> str | None     : 预览 SKILL.md（MVP 返 None）。
- _fetch_registry() -> list[dict] | None: HTTP GET registry，解析 JSON。

【职责边界】
- 只负责：拉 registry + 关键词匹配 + 转 SkillMeta。
- 不负责：搜索编排（search.py）、安装流程（installer.py）、中心存储（hub_store.py）、
  技能解析（parser）、持久化（store）。
- MVP 未实现 fetch / preview 的完整逻辑：fetch 只占位返 dest_dir，preview 恒返 None。
- 不做认证：MVP 无凭证处理（官方 registry 如公开则可直接 GET）。

## 0. 结构树

### 0.1. 静态结构树

```
skill/hub/sources/claude_marketplace_source.py — ClaudeMarketplaceSource（拉 Claude Marketplace registry）
│
├─ 模块常量
│   └─ _MARKETPLACE_REGISTRY_URL = "https://registry.claude.com/skills/index.json"  ← registry URL（placeholder）
│
└─ class ClaudeMarketplaceSource
    ├─ name = "claude-marketplace"                       ← 源标识（类属性）
    │
    ├─ __init__(registry_url=None)                       ← 保存 registry URL
    │   └─ self._registry_url = registry_url or _MARKETPLACE_REGISTRY_URL
    │
    ├─ search(query, limit=10) -> list[SkillMeta]        ← 【对外主入口】搜 registry
    │   ├─ _fetch_registry()（失败 / 空 → []）
    │   ├─ 大小写不敏感匹配 name / description
    │   ├─ 命中 → SkillMeta(source="claude-marketplace",
    │   │                 identifier=f"claude-marketplace:{name}",
    │   │                 is_installed=False)
    │   └─ 达 limit → 提前返回
    │
    ├─ fetch(identifier, dest_dir) -> Path               ← 【占位】MVP：返 dest_dir
    │   └─ 完整 HTTP 下载留后续实现
    │
    ├─ preview(identifier) -> str | None                 ← 【占位】MVP：恒返 None
    │
    └─ _fetch_registry() -> list[dict] | None            ← 【内部】HTTP GET + JSON 解析
        ├─ httpx.get(url, timeout=10, follow_redirects=True)
        ├─ status != 200 → None
        ├─ JSON list → 直接返回
        ├─ JSON dict 含 "skills" → 返回 data["skills"]
        └─ 其他 / 异常 → None
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap）
    ClaudeMarketplaceSource(registry_url)（缺省用模块常量）
        └─ 注册到 hub 的 sources 列表

② 搜索（search.py 编排）

    installer.install(meta)
        ├─ ClaudeMarketplaceSource.fetch(identifier, dest_dir)  ← 占位，返 dest_dir
        ├─ parser.parse_skill_file(SKILL.md)
        └─ store.register(SkillRecord)                          → skills.db

④ 预览（CLI / TUI 按需）
    ClaudeMarketplaceSource.preview(identifier)                 ← 占位，恒返 None
```

## 1. 补充

- **本文件是 MVP 占位**：`fetch` / `preview` 都没实现真正逻辑——`fetch` 直接返 `dest_dir`，`preview` 恒返 `None`。完整 HTTP 下载 / 预览留后续。
- **搜索是真的能用**：`_fetch_registry` 已实现 HTTP GET + JSON 解析，支持两种响应结构（`list` 或 `{"skills": [...]}`）。
- **降级彻底**：registry 不可达 / HTTP 非 200 / JSON 解析失败 / 结构不符 → 全部 silent 返空（`search` 返 `[]`，`_fetch_registry` 返 `None`），不抛异常。
- **`identifier` 前缀固定**：`claude-marketplace:<name>`——installer 靠这个前缀分发到本 source 的 `fetch`。
- **谁触发下载不在本文件**：本文件只定义 `fetch` 接口；实际调用方是 `installer`，而 installer 又由 CLI（`/skill install`）或 Agent 工具触发——见上一轮的讨论。
- **`is_installed` 恒 False**：远程源本地无记录；只有 install 后写进 store 才可能为 True（由上层填）。
- **与 `BuiltinSource` 的对比**：
  - Builtin：零网络，`fetch` 返本地路径（路径已在 `search` 时返回）。
  - ClaudeMarketplace：需网络，`search` 拉 registry；`fetch` 应下载但 MVP 未实现。
