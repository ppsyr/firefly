
## 0. 结构树

### 0.1. 数据流（按 Agent 循环阶段划分）

```
┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 0：装配期（不在 Agent 循环内，进程启动 / 会话建立时一次性发生）          │
│ 涉及：bootstrap / config / init / types / parser / store / hub           │
└────────────────────────────────────────────────────────────────────────┘
  ⓪ hub 装配（输入侧，独立于 Agent 循环）
     bootstrap
        ├─ BuiltinSource / GitHubSource / ClaudeMarketplaceSource / WellKnownSource
        ├─ HubLockFile / SkillsGuard / AuditLog
        └─ Installer(sources, lock_file, guard, audit_log, dest_root)
              └─ 挂到 CLI / Agent 工具（/skill search / install / list）

  ① 配置读取（构造期）
     build_skill_manager()
        └─ load_skill_config() ──→ SkillConfig                    = _config
              （enabled / db_path / skill_dirs / max_inject /
                quality_threshold / min_selections / evolve_* / eval_config / hub_*）

  ② 技能发现 + 解析（启动期，一次性）
     SkillManager.load_startup(llm)
        ├─ store.discover(user_dirs, IMPORTED)
        │       └─ parser.parse_skill_file(SKILL.md, origin)      ← parser 穿插在此
        │              ├─ SkillRecord   (types)                   ← types 穿插在此
        │              └─ SkillLineage  (types)
        ├─ store.discover(core_dir, BUILTIN)                      ← 仅 core/ 自动加载
        ├─ store.register / _upsert_record → 写入 SQLite          = _store
        ├─ 建 _selector  : SkillSelector(store, llm, max_skills,  = _selector
        │                                 quality_threshold, min_selections)
        └─ 建 _injection / _metrics 中间件                        = _injection / _metrics
              （lazy import，避免 skill → middlewares → skill 循环）

  ③ 回注（bootstrap 在 L2 / L3 装配后回注）
     ├─ SkillManager.set_eval_layer(EvalLayer(...))               = _eval_layer
     │     └─ EvalLayer(bridge, judgment_analyzer, task_judge, runtime_tracker)
     └─ SkillManager.set_evolution_manager(EvolutionManager(...)) = _evolution
           （回注而非内建，避免与 store / eval 类型循环依赖）

                    ═══════════ 进入 Agent 循环 ═══════════

┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 1：before_model —— 读路径（召回 + 注入）                              │
│   执行者：_injection（SkillInjectionMiddleware.before_model）            │
└────────────────────────────────────────────────────────────────────────┘
  SkillInjectionMiddleware.before_model(state, runtime)
        ├─ _selector.select_for_task(task, overrides)             = _selector
        │     ├─ 1. override 强制包含（get_active + enabled）
        │     ├─ 2. active enabled + quality filter               = _store
        │     │       （淘汰 effective_rate < threshold 且 selections >= min）
        │     ├─ 3. dedup combine（override 优先）
        │     ├─ 4. 候选 <= max → 全返（跳过 LLM）
        │     ├─ 5. 候选 > max 且有 llm → LLM select
        │     └─ 6. fallback → effective_rate 降序 top max
        ├─ build_injection_text(selected)                         = injector
        │     └─ 从 SKILL.md 现读 body（去 frontmatter）→ markdown 块
        ├─ 注入选中技能到上下文
        └─ 写 _active_skills_ctx.set([(skill_id, allowed_tools)])  （_ctx.py 桥接）
                    │
                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 2：model —— 模型推理                                                │
│   （skill 模块不介入；skill 已注入上下文中，模型据此生成 tool call）        │
└────────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 3：awrap_tool_call —— 工具调用（标记 applied）                        │
│   执行者：_metrics（SkillMetricsMiddleware.awrap_tool_call）              │
│   ⚠ 此 hook 无 state 参数，只能靠 _ctx.py 的 ContextVar 旁路               │
└────────────────────────────────────────────────────────────────────────┘
  SkillMetricsMiddleware.awrap_tool_call(call, next_handler)
        ├─ _active_skills_ctx.get()                                （_ctx.py 读）
        ├─ 若 call.tool_name ∈ allowed_tools：
        │     _applied_ctx.set({skill_id: True})                   （_ctx.py 写）
        └─ await next_handler(call)
                    │
                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 4：after_model —— （skill 模块不介入，主流程照常）                      │
└────────────────────────────────────────────────────────────────────────┘
                    │
                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 5：after_agent —— 写路径（归因打点）+ 执行层/任务层评估（异步）          │
│   执行者：_metrics（打点）/ _eval_layer（评估）                            │
└────────────────────────────────────────────────────────────────────────┘
  A. 打点（同步）
     SkillMetricsMiddleware.after_agent(state, runtime)
        ├─ _applied_ctx.get()                                      （_ctx.py 读）
        └─ store.record_outcome(skill_id, run_id, applied, ...)    = _store
              ├─ 4 计数器累加（applied / completions / fallbacks）
              └─ INSERT skill_judgments

  B. 评估（异步 fire-and-forget，caller 负责 asyncio.create_task）
     SkillJudgmentAnalyzer.analyze_execution(...)                  = _eval_layer
        ├─ 一次 LLM 调用产 SkillJudgment + EvolutionSuggestion
        ├─ store.save_judgment                                     = _store
        ├─ store.record_outcome（反向修 L1 4 计数器）               = _store
        └─ suggestions → L2 trigger（供下一轮进化）
     TaskQualityJudge.judge_task(...)                              = _eval_layer
        └─ LLM 4 维加权 → store.save_task_score                    = _store
                    │
                    ▼
        ┌───────────────────────────────────────────────┐
        │ 闭环 A：计数器 → rate 变化 → 下一轮 before_model │
        │        selector 据此重新选择（写路径 → 读路径）  │
        └───────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 6：评估（Layer 3）—— 循环结束 / 异步窗口 / 晋升前，非每轮必跑            │
│   执行者：_eval_layer（bootstrap 回注，不属 SkillManager.__init__ 构造）    │
└────────────────────────────────────────────────────────────────────────┘
  A. 响应层（candidate 晋升前，同步，L2 调）
     L2 ScoreDeltaGate
        └─ RegistryEvalBridge.evaluate(ctx)                        = _eval_layer
              ├─ registry.get_contract_checker()
              ├─ checks.read_content(candidate / baseline)
              └─ ResponseContractChecker.check
                    ├─ ContractCompiler.compile（硬 / contract / soft 规则）
                    ├─ _run_rule → checks.*（确定性检查）
                    └─ EvalResult（score / hard_failures / recommendation）
              （异常 → fail-closed 返 reject）

  B. 趋势层（按需）
     RuntimeTracker.health_report / degraded_skills                = _eval_layer
        └─ 读 _store 的 judgments + 计数器

  C. 落库
     store.save_judgment / save_task_score / save_eval_run         = _store

┌────────────────────────────────────────────────────────────────────────┐
│ 阶段 7：自进化（Layer 2）—— 阈值 / 触发器 / 冷却驱动，非每轮必跑             │
│   执行者：_evolution（bootstrap 回注，不属 SkillManager.__init__ 构造）    │
└────────────────────────────────────────────────────────────────────────┘
  EvolutionManager.run_cycle / evolve_skill / capture_skill
        └─ _run_evolution(ctx)（闭环七步）
              1. focus    ：IVEFocuser.focus（IVE 5 问诊断）
              2. mutate   ：LLMMutator.mutate（FIX 编辑 / CAPTURED 生成）
              3. eval     ：eval_bridge.evaluate → EvalResult
              4. gate     ：ScoreDeltaGate.decide → GateDecision
              5. promote  ：accept → store.create_version(...)     = _store
              6. record   ：store.record_evolution（EvolutionRecord）= _store
              7. journal  ：skill.evolve / captured / evolve_rejected
        └─ 上线后监控：GitRatchet.check_and_rollback → store.rollback
                    │
                    ▼
        ┌───────────────────────────────────────────────┐
        │ 闭环 B：eval 产出 → L2 决策                    │
        │ 闭环 C：evolution.create_version → eval 再评   │
        └───────────────────────────────────────────────┘
```

### 0.2. 三条闭环（跨阶段）

```
闭环 A（每轮）  ：写路径打点 → 4 计数器 → rate 变化 → 下一轮读路径选择
闭环 B（跨层）  ：eval 产 EvalResult / SkillJudgment / EvolutionSuggestion
                  → gate / focuser / trigger 消费
闭环 C（跨轮）  ：evolution.create_version → 新版本 → eval 下一轮评估
```

### 0.3. 各阶段与组件对应

| 阶段 | 触发时机 | 执行者 | 是否每轮 |
|------|---------|--------|:---:|
| 0 装配 | 进程 / 会话启动 | bootstrap + `build_skill_manager` + `load_startup` + setter 回注 | 一次性 |
| 1 注入 | `before_model` | `_injection`（selector + injector） | ✅ |
| 2 推理 | `model` | — | ✅ |
| 3 标记 | `awrap_tool_call` | `_metrics` | ✅ |
| 4 模型后 | `after_model` | — | ✅ |
| 5 打点 + 执行/任务评估 | `after_agent` | `_metrics` + `_eval_layer`（异步） | ✅ |
| 6 评估（响应 / 趋势） | 晋升前 / 按需 | `_eval_layer` | ❌ |
| 7 进化 | 阈值 / 触发器 / 冷却 | `_evolution` | ❌ |
| hub（输入侧） | 用户 / LLM 触发 | `Installer` + 4 源 + 三件套 | ❌ |

### 0.5. 异常与降级（按阶段）

| 阶段 | 原则 | 典型行为 |
|------|------|---------|
| 0 装配 | opt-in | `enabled=false` → `build_skill_manager` 返 None |
| 1 注入 | 降级 | LLM 失败 → rate 排序；store None → 返空 |
| 3 标记 | silent | `_ctx` 为 None → 不标记 |
| 5 打点 | silent | 写库异常不阻断 |
| 5 评估 | fail-silent | 无 llm / 异常 → 返空 / None |
| 6 响应层 | fail-closed | 异常 → reject |
| 7 进化 | silent（自动）/ 抛错（手动） | 无记录 → RuntimeError |
| 7 门控 | fail-closed | 宁可错拒 |
| hub 搜索 | silent | 单源失败跳过，降级 builtin |
| hub 安装 | 抛错 | 安全拒绝 → ValueError |

### 0.6. 总览

```
hub（进来）→ L1（用：选择 / 注入 / 打点）→ L3（评）→ L2（改）→ 回到 L1
   ①            ②③④⑤              ⑥         ⑦
```

**skill 的本质**：一个自我改进的技能系统——hub 把外部技能装进来，L1 在每轮对话中选择并注入、同时打点，L3 事后评估质量，L2 据此触发进化、产生新版本，新版本再回到 L1 被使用与评估。四层通过 `SkillManager` 门面 + setter 回注 + 共享数据契约咬合成闭环。



## 1. skill 全链路总览

```
外部来源（builtin / github / well-known / claude-marketplace）
        │
        ▼
   hub（发现 / 安装 / 安全 / provenance）        ← 输入侧
        │  install → parser → store
        ▼
   L1 基础层：store / parser / types / selector / injector / _ctx / 中间件
        │  打点（4 计数器） + 注入（读路径）
        ▼
   L3 评估层：eval（执行 / 任务 / 响应 / 趋势）
        │  评分 + 建议
        ▼
   L2 进化层：evolution（触发 / 聚焦 / 变异 / 门控 / 晋升 / 回滚）
        │  create_version
        ▼
   回到 L1（新版本 → 下一轮选择 → 再评估）        ← 闭环
```

一句话：**hub 负责"进来"，L1 负责"用"，L3 负责"评"，L2 负责"改"，四层咬合成闭环。**

## 3. 组件是怎么工作的

### 3.1 hub：从外部到本地

```
unified_search：聚合 4 源 → 去重 → 排序（已安装优先）→ 截断
Installer.install：fetch → scan → install → hash → lock.add → audit.append
SkillsGuard：正则匹配三类风险 + TRUSTED_REPOS 白名单 → 命中进 quarantine
```

### 3.2 L1：读路径 + 写路径

```
读路径（before_model）
    SkillInjectionMiddleware
        └─ SkillSelector.select_for_task
              ├─ override 强制包含
              ├─ quality filter（anti-loop）
              ├─ 候选 ≤ max → 全返
              ├─ 候选 > max + llm → LLM 选
              └─ fallback → effective_rate 排序
        └─ build_injection_text → 注入
        └─ 写 _active_skills_ctx

写路径（awrap_tool_call → after_agent）
    SkillMetricsMiddleware
        ├─ 读 _active_skills_ctx
        ├─ 判断 tool ∈ allowed_tools → 写 _applied_ctx
        └─ after_agent：读 _applied_ctx → store.record_outcome
              └─ 累加 4 计数器 → rate 变化 → 下一轮 selector 读到
```

### 3.3 L3：四层评估

```
执行层（after_agent，async）
    SkillJudgmentAnalyzer.analyze_execution
        ├─ 一次 LLM 调用产 SkillJudgment + EvolutionSuggestion
        ├─ store.save_judgment
        └─ store.record_outcome（反向修 L1 计数器）

任务层（任务结束后，async）
    TaskQualityJudge.judge_task
        └─ LLM 4 维加权 → store.save_task_score

响应层（candidate 晋升前，同步）
    RegistryEvalBridge.evaluate → ResponseContractChecker.check
        └─ ContractCompiler.compile → checks.* → EvalResult

趋势层（按需）
    RuntimeTracker.health_report / degraded_skills
```

### 3.4 L2：闭环七步

```
EvolutionManager._run_evolution(ctx)
    1. focus    ：IVEFocuser.focus（IVE 5 问）
    2. mutate   ：LLMMutator.mutate（FIX 编辑 / CAPTURED 生成）
    3. eval     ：eval_bridge.evaluate → EvalResult
    4. gate     ：gate.decide → GateDecision
    5. promote  ：accept → store.create_version
    6. record   ：store.record_evolution
    7. journal  ：skill.evolve / captured / evolve_rejected
```

## 4. 在哪里装配

### 4.1 bootstrap 装配总图

```
bootstrap
    ├─ hub
    │     BuiltinSource / GitHubSource / ClaudeMarketplaceSource / WellKnownSource
    │     HubLockFile / SkillsGuard / AuditLog
    │     Installer(sources, lock_file, guard, audit_log, dest_root)
    │
    ├─ L1
    │     build_skill_manager()
    │         ├─ load_skill_config() → SkillConfig
    │         ├─ SkillManager(config)
    │         │     ├─ SQLiteSkillStore(config.db_path)
    │         │     ├─ load_startup(llm)
    │         │     │     ├─ store.discover（parser 解析）
    │         │     │     ├─ SkillSelector(store, llm, ...)
    │         │     │     ├─ SkillInjectionMiddleware
    │         │     │     └─ SkillMetricsMiddleware
    │         │     └─ 中间件注入链
    │
    ├─ L3
    │     build_default_registry() → RegistryEvalBridge → 注入 L2
    │     SkillJudgmentAnalyzer(llm, store)
    │     TaskQualityJudge(llm, store)
    │     RuntimeTracker(...)
    │     EvalLayer(bridge, analyzer, judge, tracker)
    │         └─ SkillManager.set_eval_layer(...)
    │
    └─ L2
          MetricMonitorTrigger / CaptureTrigger
          IVEFocuser / LLMMutator
          ProgrammaticEvalBridge 或 RegistryEvalBridge
          ScoreDeltaGate / GitRatchet
          EvolutionManager(...)
              └─ SkillManager.set_evolution_manager(...)
```

### 4.2 装配来源分层

| 组件 | 构造者 | 注入方式 |
|------|--------|---------|
| L1 config / store | `build_skill_manager` / `SkillManager.__init__` | 直接 new |
| L1 selector / middleware | `load_startup` | 内部构造 |
| L2 evolution | bootstrap | `set_evolution_manager` 回注 |
| L3 eval_layer | bootstrap | `set_eval_layer` 回注 |
| hub installer | bootstrap | 挂到 CLI / Agent 工具 |

**为什么回注**：L2 / L3 反向依赖 L1（store）与彼此类型，直接在建会成环。

## 6. 调用的内部流程

### 6.1 一次完整的 skill 生命周期

```
① 发现（hub）
    unified_search → SkillMeta

② 安装（hub）
    Installer.install → fetch → scan → parser.install → lock.add → audit.append
        └─ store.discover / register（写 DB）

③ 选择（L1，读路径）
    before_model → SkillSelector.select_for_task
        └─ override + quality filter + 裁剪

④ 注入（L1，读路径）
    build_injection_text → 写上下文 + _active_skills_ctx

⑤ 打点（L1，写路径）
    awrap_tool_call → _applied_ctx
    after_agent → store.record_outcome（4 计数器）

⑥ 评估（L3）
    执行层：SkillJudgmentAnalyzer → save_judgment + record_outcome
    任务层：TaskQualityJudge → save_task_score
    响应层：RegistryEvalBridge → ResponseContractChecker → EvalResult
    趋势层：RuntimeTracker.health_report

⑦ 进化（L2）
    trigger → focus → mutate → eval → gate → promote → record → journal
        └─ accept → store.create_version（新版本）

⑧ 闭环
    新版本 → 下一轮 ③ 选择 → ④ 注入 → ⑤ 打点 → ⑥ 评估 → ⑦ 进化
```

### 6.2 三条关键闭环

**闭环 A：打点 → 选择**

```
record_outcome（写）→ 4 计数器 → rate 变化 → selector 读（下一轮）
```

**闭环 B：评估 → 进化**

```
eval 产 EvalResult / SkillJudgment / EvolutionSuggestion
    → gate 用 EvalResult 决策
    → focuser 用 SkillJudgment 补充证据
    → trigger 用 EvolutionSuggestion
```

**闭环 C：进化 → 评估**

```
evolution.create_version → 新版本 → eval 下一轮评估新版本
```

## 9. 总结

| 层面 | 内容 |
|------|------|
| **初始化** | bootstrap 构造 hub（4 源 + 三件套 + Installer）→ L1（`build_skill_manager` + `load_startup`）→ L3（`EvalLayer` 回注）→ L2（`EvolutionManager` 回注）。 |
| **组件** | hub（输入）、L1（用）、L3（评）、L2（改），四层 + 门面 `SkillManager`。 |
| **工作方式** | hub 装进来；L1 读路径选择 + 注入、写路径打点；L3 四层评估；L2 闭环七步。 |
| **装配点** | `SkillManager` 持有全部；L2 / L3 走 setter 回注（避免循环依赖）。 |
| **调用点** | Agent 循环：`before_model` / `awrap_tool_call` / `after_agent`；周期 / 手动：CLI。 |
| **内部流程** | 生命周期八步：发现 → 安装 → 选择 → 注入 → 打点 → 评估 → 进化 → 闭环。 |
| **三条闭环** | 打点→选择、评估→进化、进化→评估。 |

**skill 的本质**：一个"自我改进的技能系统"——hub 把外部技能装进来，L1 在每轮对话中选择并注入、同时打点，L3 事后评估质量，L2 据此触发进化、产生新版本，新版本再回到 L1 被使用与评估。四层通过 `SkillManager` 门面 + setter 回注 + 共享数据契约咬合成闭环。
