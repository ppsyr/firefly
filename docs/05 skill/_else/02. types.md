name: Skill 数据模型 — frozen dataclass + 4 rate property。

description: 

【整体职责】
定义 skill 子系统的核心数据结构（全部为不可变值对象）。
作为 parser / store / selector / middleware 之间的数据契约：
- parser 产出 SkillRecord；
- store 持久化并回读 SkillRecord / 计算 SkillMetrics / SkillHealth；
- selector / middleware 消费 SkillRecord 与其 rate。

【内容摘要】
- SkillLineage ：版本血缘（父节点 / 代数 / 来源 / 版本哈希 / 创建者）。
- SkillRecord  ：技能注册条目（元数据 + 4 计数器 + 4 rate property）。
- SkillMetrics ：质量指标快照（4 计数器 + 4 rate，由 store.get_metrics 返回）。
- SkillHealth  ：健康状态（由 store.health_check 返回，带 degraded 标记）。

【职责边界】
- 只负责：数据结构定义与纯计算 property（rate）。
- 不负责：持久化（store）、解析（parser）、选择（selector）、打点触发（middleware）。
- 不存全文：SKILL.md 内容留在文件（path），此处只存引用 + metrics。

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 字段/property）

```
types.py — Skill 数据模型（frozen dataclass + 4 rate property）
│
├─ class SkillLineage(frozen)
│   ├─ parent_skill_ids: tuple[str, ...] = ()
│   ├─ generation: int = 0
│   ├─ origin: str = "IMPORTED"
│   ├─ version_hash: str = ""
│   └─ created_by: str | None = None
│
├─ class SkillRecord(frozen)
│   ├─ 身份 / 文件引用
│   │   ├─ skill_id: str
│   │   ├─ name: str
│   │   ├─ path: str
│   │   ├─ content_hash: str
│   │   └─ is_active: bool = True
│   ├─ 血缘 / 元数据
│   │   ├─ lineage: SkillLineage = field(default_factory=SkillLineage)
│   │   ├─ description: str = ""
│   │   ├─ allowed_tools: tuple[str, ...] = ()
│   │   └─ enabled: bool = True
│   ├─ 4 计数器
│   │   ├─ total_selections: int = 0
│   │   ├─ total_applied: int = 0
│   │   ├─ total_completions: int = 0
│   │   └─ total_fallbacks: int = 0
│   ├─ 时间戳
│   │   ├─ created_at: str = ""
│   │   └─ last_updated: str = ""
│   └─ 4 rate property（只读，零除保护）
│       ├─ applied_rate    = applied / selections
│       ├─ completion_rate = completions / applied
│       ├─ effective_rate  = completions / selections   ← selector 主指标
│       └─ fallback_rate   = fallbacks / selections
│
├─ class SkillMetrics(frozen)
│   ├─ skill_id: str
│   ├─ selections / applied / completions / fallbacks: int
│   └─ applied_rate / completion_rate / effective_rate / fallback_rate: float
│
└─ class SkillHealth(frozen)
    ├─ skill_id: str
    ├─ name: str
    ├─ effective_rate: float
    ├─ fallback_rate: float
    ├─ total_selections: int
    └─ degraded: bool
```

### 0.2. 运行时调用树（数据如何流经 types）

```
① parser.py 产出
parse_skill_file(skill_file, origin)
    ├─ SkillLineage(origin=origin)              ← 血缘只填 origin，其余默认
    └─ return SkillRecord(
           skill_id, name, path, content_hash,
           description, allowed_tools, enabled,
           lineage=...,
       )                                        ← 计数器 / 时间戳 / is_active 用默认

② store.py 持久化 + 回读
register / _upsert_record(record)
    └─ 写入 skill_records（含 4 计数器 DEFAULT 0）
_row_to_record(row)
    ├─ SkillLineage(parent_skill_ids, generation, origin, version_hash, created_by)
    └─ return SkillRecord(..., 4 计数器从 row 读回, ...)

③ 打点累加后计算 rate
record_selection / record_outcome
    └─ UPDATE skill_records 的 4 计数器
get_metrics(skill_id)
    ├─ 读 4 计数器
    └─ return SkillMetrics(..., 4 个 rate 现算)

④ 选择 / 健康判定
get_top_skills(n, metric="effective_rate", ...)
    └─ records.sort(key=lambda r: getattr(r, metric))   ← 直接用 SkillRecord 的 property
health_check(threshold, min_selections)
    ├─ rec.total_selections >= min_selections
    ├─ rec.effective_rate < threshold
    └─ return SkillHealth(..., degraded=...)

⑤ 注入 / 打点链路消费
SkillInjectionMiddleware.before_model
    └─ 读 rec.allowed_tools（经 _ctx 传给 awrap_tool_call）
SkillMetricsMiddleware.after_agent
    └─ store.record_outcome(...) → 回到 ③ 累加计数器
```

## 1. 这个模块在 skill 中起什么作用

一句话：**`types.py` 是 skill 子系统的"数据契约层"——定义全链路流通的四个值对象，parser 产出它、store 存取它、selector 与 middleware 消费它。**

### 1.1. 四个类各自的角色

| 类 | 角色 | 由谁产出 | 由谁消费 |
|----|------|---------|---------|
| `SkillLineage` | 版本血缘 | parser（只填 origin）/ store（回读全字段） | create_version / rollback / 进化模块 |
| `SkillRecord` | 技能主记录（身份 + 元数据 + 计数器 + rate） | parser 产出初版；store 回读带计数器版 | selector / middleware / TUI / CLI |
| `SkillMetrics` | 质量指标快照 | `store.get_metrics` | 上层展示 / 进化判定 |
| `SkillHealth` | 健康状态 | `store.health_check` | 巡检 / 淘汰逻辑 |

### 1.2. 三个关键设计点

1. **全部 frozen（不可变值对象）**
   - 构造后字段不可改，想"改"就新建一个。
   - 好处：跨线程/跨 hook 传递安全，不会被意外篡改；也符合"数据契约"的定位。

2. **计数器与 rate 分离**
   - **4 计数器**是可变的"事实"（由 store 的 `record_*` 累加）。
   - **4 rate** 是**派生量**，用 `@property` 现算，不落库。
   - 好处：DB 只存计数器（不存 rate），避免数据冗余与不一致；rate 永远和计数器同步。

3. **内容与记录分离**
   - `SkillRecord` 只存 `path` + `content_hash`，**不存 SKILL.md 全文**。
   - 全文是 source of truth，留在文件系统；DB 只是索引。

### 1.3. 和 parser 结合起来理解

两者是**"产出方 ↔ 契约"**的关系：

```
parser.py                          types.py
─────────                          ────────
读 SKILL.md
解析 frontmatter
    │
    ├─ 构造 SkillLineage(origin=...) ──→ class SkillLineage
    │
    └─ 构造 SkillRecord(...)         ──→ class SkillRecord
         （计数器/时间戳用默认值）           （定义字段与 rate）
```

具体对应关系：

| parser 里的动作 | types 里对应的定义 |
|----------------|-------------------|
| `read_or_create_skill_id(...)` → `skill_id` | `SkillRecord.skill_id` |
| `name` / `description` 校验 | `SkillRecord.name` / `.description` |
| `allowed-tools` → tuple | `SkillRecord.allowed_tools` |
| `enabled` 缺省 True | `SkillRecord.enabled` |
| `sha256(content)[:16]` | `SkillRecord.content_hash` |
| `SkillLineage(origin=origin)` | `class SkillLineage`（parser 只填 origin） |
| **不填**计数器 / 时间戳 | 由 store 写入 / 回读时填充 |

**关键点**：parser **只负责"静态元数据"**（身份、描述、工具、哈希、origin），而 `SkillRecord` 里的 **4 计数器、时间戳、is_active** 是 **store 层**填充的。所以：

- parser 产出的 `SkillRecord` 是**"初版"**（计数器全 0）。
- store `register` / `_upsert_record` 写入 DB 后，回读时 `_row_to_record` 才把计数器填回。
- 之后 `record_selection` / `record_outcome` 累加计数器 → rate 随之变化 → selector 依据 rate 决策。

### 1.4. 总结

- **parser.py**：把文件变成 `SkillRecord`（静态元数据）。
- **types.py**：定义 `SkillRecord` 长什么样，以及 rate 怎么算。
- 两者合起来 = **"技能从文件到结构化记录的完整入口"**；再往下的 store 负责让这个记录"活起来"（计数、版本、持久化）。
