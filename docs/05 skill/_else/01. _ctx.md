---

name:Skill provenance ContextVar — 跨 hook 桥接 active_skills + applied 标记。

description:

【整体职责】
定义两个模块级 ContextVar，作为 skill 打点链路的「跨 hook 旁路通道」。
用于把「本轮注入了哪些 skill」与「哪些 skill 被实际应用」，
在缺少 state 参数的 hook 之间传递。

为什么需要：
- awrap_tool_call 没有 state 参数，无法读 state.metadata。
- 因此由 SkillInjectionMiddleware.before_model 写入 ContextVar，
  SkillMetricsMiddleware.awrap_tool_call 读 / 改，
  SkillMetricsMiddleware.after_agent 读回，完成归因打点。

【内容摘要】
- _active_skills_ctx ：本轮注入的 active skill 及其 allowed_tools。
- _applied_ctx       ：awrap_tool_call 标记的被实际应用的 tool-skill。

两个变量均为模块级 ContextVar，默认值 None；本模块只定义，不含读写逻辑。
读写分别发生在：
- skill_injection_middleware.py（写 _active_skills_ctx）
- skill_metrics_middleware.py（读 _active_skills_ctx、写/读 _applied_ctx）

【职责边界】
- 只负责：定义跨 hook 传递用的 ContextVar 容器。
- 不负责：写入、读取、判断逻辑（均在两个 middleware 内）。
- 不对外暴露：命名带下划线前缀，不进入 skill 包的 __all__。
- 独立成文件的原因：injection 与 metrics 两个 middleware 都要用这两个变量，
  若定义在其中一方会形成循环依赖，故抽到独立模块供双方安全 import。

## 1. 它是什么

```python
_active_skills_ctx: ContextVar[list[tuple[str, tuple[str, ...]]] | None] = ContextVar(
    "poirot_skill_active", default=None,
)
```

- 左边 `_active_skills_ctx`：**变量名**（不是 `def`，所以不是方法/函数）。
- 右边 `ContextVar(...)`：**构造一个 ContextVar 实例**并赋给它。
- 冒号 `ContextVar[...]`：类型标注（给人和类型检查器看的，运行时不影响）。
- `default=None`：没 `set()` 过时 `.get()` 返回 `None`。

所以它是"一个全局定义的、按上下文隔离的容器对象"。

## 2. 为什么在本文件里看不到引用

`_ctx.py` 的定位是**纯定义模块**——只声明两个 `ContextVar`，不含任何逻辑。真正的引用分布在两个 middleware 里：

| 变量 | 谁写（set） | 谁读（get） |
|------|------------|------------|
| `_active_skills_ctx` | `SkillInjectionMiddleware.before_model` | `SkillMetricsMiddleware.awrap_tool_call` |
| `_applied_ctx` | `SkillMetricsMiddleware.awrap_tool_call` | `SkillMetricsMiddleware.after_agent` |

也就是说，你在 `_ctx.py` 里看不到 `.set()` / `.get()`，是因为它们被写在了：

- `poirot/backend/agents/middlewares/skill_injection_middleware.py`
- `poirot/backend/agents/middlewares/skill_metrics_middleware.py`

别的模块用它的方式很标准：**`from ..._ctx import _active_skills_ctx, _applied_ctx`，然后调 `.set()` / `.get()`**。因为它是模块级 `ContextVar`，只要 import 到就是同一个对象（Python 模块单例），跨 hook 共享。

## 3. 怎么使用

### 3.1 两个使用方

| 模块 | 用哪个变量 | 动作 |
|------|-----------|------|
| `skill_injection_middleware.py` | `_active_skills_ctx` | `.set(...)` 写 |
| `skill_metrics_middleware.py` | `_active_skills_ctx` | `.get()` 读 |
| `skill_metrics_middleware.py` | `_applied_ctx` | `.set(...)` + `.get()` |

### 3.2. 典型用法

#### 1. Injection middleware：写入 `_active_skills_ctx`

```python
from poirot.backend.agents.skill._ctx import _active_skills_ctx

class SkillInjectionMiddleware(AgentMiddleware):
    def before_model(self, state, runtime):
        selected = self._selector.select(state)      # 选中本轮要注入的 skill
        # ... 把 skill 内容注入上下文 ...

        # 关键：把 (skill_id, allowed_tools) 清单写进 ContextVar
        _active_skills_ctx.set([
            (rec.skill_id, tuple(rec.allowed_tools))
            for rec in selected
        ])
        return {...}
```

要点：**写完不需要手动清理**——`ContextVar` 随本次执行上下文结束而失效（下一轮 before_model 会重新 `set` 覆盖）。

#### 2. Metrics middleware：读 `_active_skills_ctx`、写/读 `_applied_ctx`

```python
from poirot.backend.agents.skill._ctx import _active_skills_ctx, _applied_ctx

class SkillMetricsMiddleware(AgentMiddleware):
    async def awrap_tool_call(self, call, next_handler):
        active = _active_skills_ctx.get()            # 读注入清单（可能 None）
        if active:
            for skill_id, allowed in active:
                if call.tool_name in allowed:        # tool 命中某 skill 的 allowed_tools
                    applied = _applied_ctx.get() or {}
                    applied[skill_id] = True
                    _applied_ctx.set(applied)        # 标记为已应用
        return await next_handler(call)

    def after_agent(self, state, runtime):
        applied = _applied_ctx.get() or {}           # 回读应用标记
        run_id = state.metadata.get("run_id")
        for skill_id, is_applied in applied.items():
            self._store.record_outcome(
                skill_id=skill_id,
                run_id=run_id,
                applied=is_applied,                  # True / None(guidance)
                task_completed=...,
            )
```

要点：
- `awrap_tool_call` **没有 state**，所以只能从 `_active_skills_ctx` 拿清单。
- 判断依据是 `tool_name in allowed_tools`（这也解释了为什么清单里要带 `allowed_tools`）。
- 标记通过 `_applied_ctx` 传到 `after_agent`，那里有 `state` 和 `store`，能做 `record_outcome`。

```
skill_injection_middleware.py
    from ..._ctx import _active_skills_ctx
    before_model: _active_skills_ctx.set([(skill_id, allowed_tools), ...])
                              │
                              ▼  （跨 hook 旁路，绕过无 state 的 awrap_tool_call）
skill_metrics_middleware.py
    from ..._ctx import _active_skills_ctx, _applied_ctx
    awrap_tool_call: active = _active_skills_ctx.get()
                     if tool_name in allowed:
                         applied = _applied_ctx.get() or {}
                         applied[skill_id] = True
                         _applied_ctx.set(applied)
                              │
                              ▼
    after_agent:     applied = _applied_ctx.get() or {}
                     store.record_outcome(skill_id, run_id, applied=...)
```

### 3.3. 小结

- 别的模块用它 = **import 模块级 `ContextVar` → `.set()` / `.get()`**。
- 写：injection middleware 写 `_active_skills_ctx`。
- 读：metrics middleware 读 `_active_skills_ctx`，并写/读 `_applied_ctx`。
- 关键约定：`.get()` 一律当 `None` 容错（未装配时降级），且各模块共享**同一个变量对象**。
