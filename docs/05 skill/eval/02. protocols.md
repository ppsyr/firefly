---

name: Skill eval 评估层 Protocol 抽象 — 三层 eval + 趋势层 + 持久化契约。

description: 

【整体职责】
定义 L3 评估层的 5 个 Protocol（接口契约），规定评估层各组件的职责边界：
- 执行层：SkillJudgmentAnalyzer
- 任务层：TaskQualityJudge
- 响应层：ResponseContractChecker
- 趋势层：RuntimeTracker
- 持久化：EvalRunStore

L3 实现 = 实现这些 Protocol + 由 bootstrap 注入，不改动 L2 核心（零侵入）。

【内容摘要】
- SkillJudgmentAnalyzer  : 执行层 eval（LLM 判断 per-skill 是否被应用，
                           同时产出 SkillJudgment + EvolutionSuggestion）。
- TaskQualityJudge       : 任务层 eval（LLM 4 维加权评分 → TaskQualityScore）。
- ResponseContractChecker: 响应层 eval（编译规则检查 candidate → EvalResult）。
- RuntimeTracker         : 趋势层 eval（历史数据 → SkillHealthReport + 退化检测）。
- EvalRunStore           : eval 结果持久化契约（judgment / task_score / eval_run）。

【职责边界】
- 只定义接口（Protocol），不含任何实现。
- 不负责：评估逻辑（在 analyzers / tracker 实现里）、持久化实现（在 store 里）。
- 不 runtime import 实现类：实现由 bootstrap 注入，本模块只声明契约。
- 全部 runtime_checkable：支持 isinstance 检查（便于 bootstrap 装配时校验）。

## 0. 结构树

### 0.1. 静态结构树（模块 → Protocol → 方法，含用途标注）

```
eval/protocols.py — Skill eval 评估层 Protocol 抽象（5 个接口契约）
│
├─ class SkillJudgmentAnalyzer(Protocol, runtime_checkable)   ← 【执行层】LLM 判断 skill 是否被应用
│   └─ async analyze_execution(                                ← 每次任务后调，异步 fire-and-forget
│         task_id: str,                                        ← 任务 id
│         journal_events: list[dict],                          ← 运行日志事件（执行轨迹）
│         messages_summary: str,                               ← 消息摘要
│         injected_skills: list[dict],                         ← 本轮注入的 skill 清单
│       ) -> tuple[list[SkillJudgment], list[EvolutionSuggestion]]
│                                                              ← 一次调用产两类：
│                                                                SkillJudgment（是否被应用）
│                                                                EvolutionSuggestion（进化建议）
│
├─ class TaskQualityJudge(Protocol, runtime_checkable)        ← 【任务层】LLM 4 维加权评分
│   └─ async judge_task(                                       ← 任务结束后调
│         task_id: str,                                        ← 任务 id
│         execution_trace: str,                                ← 执行轨迹文本
│         final_output: str,                                   ← 最终输出
│       ) -> TaskQualityScore                                  ← 4 维加权评分 + rationale
│
├─ class ResponseContractChecker(Protocol, runtime_checkable) ← 【响应层】编译规则检查 candidate
│   └─ check(                                                  ← 同步（candidate 晋升前调）
│         candidate_content: str,                              ← 候选 SKILL.md 文本
│         baseline_content: str,                               ← 基线 SKILL.md 文本
│       ) -> EvalResult                                        ← 走 EvalBridge 交给 L2 ScoreDeltaGate
│
├─ class RuntimeTracker(Protocol, runtime_checkable)          ← 【趋势层】历史数据 → 健康报告
│   ├─ health_report(                                          ← 产健康报告（供 TUI / evolution）
│   │     skill_id: str,                                       ← 目标 skill
│   │     window: int = 20,                                    ← 窗口大小
│   │   ) -> SkillHealthReport                                 ← 含 trend / 4 rate / advice
│   └─ degraded_skills(                                        ← 退化检测（供 GitRatchet 按需调）
│         threshold: float = 0.15,                             ← 退化阈值
│       ) -> list[str]                                         ← 退化的 skill_id 列表
│
└─ class EvalRunStore(Protocol, runtime_checkable)            ← 【持久化】eval 结果读写契约
    ├─ save_judgment(judgment: SkillJudgment) -> str          ← 写执行层判断
    ├─ save_task_score(score: TaskQualityScore) -> str        ← 写任务层评分
    ├─ save_eval_run(run: Any) -> str                         ← 写审计记录
    ├─ get_judgments(skill_id, limit=20) -> list[SkillJudgment] ← 读执行层判断
    └─ get_task_scores(task_id) -> TaskQualityScore | None    ← 读任务层评分
```

### 0.2. 运行时调用树（谁在哪个阶段调哪个 Protocol）

```
① 装配期（bootstrap，一次性）
    ├─ 构造各实现类（analyzer / judge / checker / tracker）
    │     └─ 实现类均满足对应 Protocol（bootstrap 可用 isinstance 校验）
    ├─ EvalLayer(bridge, judgment_analyzer, task_judge, runtime_tracker)
    └─ SkillManager.set_eval_layer(...)

        ═══════════ 进入 Agent 循环 ═══════════

② after_agent —— 执行层（SkillJudgmentAnalyzer）
    触发：每次任务后（异步 fire-and-forget，不阻塞用户）
    └─ async analyze_execution(task_id, journal_events, messages_summary, injected_skills)
          ├─ 产出 list[SkillJudgment]        → EvalRunStore.save_judgment
          ├─ 产出 list[EvolutionSuggestion]  → L2 trigger（供进化）
          └─ 内部调 store.record_outcome     → 更新 L1 4 计数器

③ 任务结束后 —— 任务层（TaskQualityJudge）
    └─ async judge_task(task_id, execution_trace, final_output)
          └─ TaskQualityScore → EvalRunStore.save_task_score

④ candidate 晋升前 —— 响应层（ResponseContractChecker）
    └─ check(candidate_content, baseline_content)     ← 同步
          ├─ ContractCompiler 从 skill 文本编译规则（外部 skill 零改造）
          └─ EvalResult → EvalBridge → L2 ScoreDeltaGate

⑤ 趋势层（RuntimeTracker）
    触发：after_agent 写数据；命令触发时算趋势；GitRatchet 按需调
    ├─ health_report(skill_id, window) → SkillHealthReport（供 TUI / evolution）
    └─ degraded_skills(threshold) → list[str]（供 GitRatchet 决定是否回滚）

⑥ 持久化（EvalRunStore）
    被 ②③④ 调用来写；被 ④⑤ 调用来读
```

### 0.3. 5 个 Protocol 的角色与实现方对照

| Protocol | 层级 | 方法 | 同步/异步 | 实现方（预期） | 调用时机 |
|----------|------|------|:---:|---------------|---------|
| `SkillJudgmentAnalyzer` | 执行层 | `analyze_execution` | async | `analyzers/skill_judgment_analyzer.py` | after_agent（fire-and-forget） |
| `TaskQualityJudge` | 任务层 | `judge_task` | async | `analyzers/task_quality_judge.py` | 任务结束后 |
| `ResponseContractChecker` | 响应层 | `check` | 同步 | `analyzers/response_contract_checker.py` | candidate 晋升前 |
| `RuntimeTracker` | 趋势层 | `health_report` / `degraded_skills` | 同步 | `runtime_tracker.py` | after_agent 写；命令/GitRatchet 读 |
| `EvalRunStore` | 持久化 | 5 个 save/get | 同步 | `SQLiteSkillStore`（已实现同名方法） | 各层写/读 |

### 0.4. 与 eval/types.py 的对应关系

```
eval/protocols.py（接口）              eval/types.py（数据）
──────────────────────                ──────────────────
SkillJudgmentAnalyzer     ──产──►      SkillJudgment
                          ──产──►      EvolutionSuggestion
TaskQualityJudge          ──产──►      TaskQualityScore
ResponseContractChecker   ──产──►      EvalResult（evolution/types）
RuntimeTracker            ──产──►      SkillHealthReport
EvalRunStore              ──存──►      SkillJudgment / TaskQualityScore / EvalRun
```

**要点：**

- `protocols.py` 定义**"谁做什么"**；`types.py` 定义**"产出长什么样"**。
- 两者是"接口 ↔ 数据"配对：Protocol 方法的返回类型正是 types.py 的值对象。
- 唯一例外：`ResponseContractChecker.check` 返回 `EvalResult`（来自 `evolution/types.py`），因为响应层结果要走 L2 的 ScoreDeltaGate。

### 0.6. 总结

```
eval/protocols.py
   ├─ 执行层：SkillJudgmentAnalyzer   → SkillJudgment + EvolutionSuggestion
   ├─ 任务层：TaskQualityJudge        → TaskQualityScore
   ├─ 响应层：ResponseContractChecker → EvalResult
   ├─ 趋势层：RuntimeTracker          → SkillHealthReport + degraded_skills
   └─ 持久化：EvalRunStore            → 读写三种 eval 记录
```

**本模块 = L3 评估层的"接口契约中心"**：5 个 `@runtime_checkable` Protocol 规定各组件的职责与方法签名；实现由 bootstrap 注入（零侵入 L2），数据契约在 `eval/types.py`。
