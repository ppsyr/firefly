Skill Eval 评估层（L3）总结文档

【整体职责】

Eval 层是 skill 子系统的质量评估中枢，位于"写路径（打点）"与"进化层（L2）"之间，承担"质检站"的角色。

它要回答四个问题：
1. 执行层：agent 是否真的应用了注入的 skill？（LLM 判断，比 middleware 打点更精确）
2. 任务层：整个任务执行质量如何？（LLM 4 维加权评分）
3. 响应层：候选版本是否满足 skill 自身声明的契约？（确定性规则检查）
4. 趋势层：skill 在时间窗口内是改善、稳定还是退化？（健康报告 + 退化检测）

它的产出有三个去向：
- 写回 L1：执行层判断修正 skill_records 的 4 计数器（这是 eval 唯一反向写 L1 的地方）。
- 存档审计：judgment / task_score / eval_run 落库，供回溯与展示。
- 喂给 L2：EvolutionSuggestion 与 EvalResult 交给进化层，驱动 FIX / DERIVED / CAPTURED 与晋升决策。

一句话：Eval 层消费打点数据，产出更细的评分与建议，既回流修正 L1 计数器，又为 evolution 提供决策依据。

【内容摘要】

一、四层组件
- 执行层：SkillJudgmentAnalyzer。LLM 判断 per-skill 是否被应用 + 产进化建议。after_agent 触发，async。
- 任务层：TaskQualityJudge。LLM 4 维加权评分（0.50 / 0.35 / 0.05 / 0.10）。任务结束后触发，async。
- 响应层：ResponseContractChecker。编译规则 + 检查 candidate，产 EvalResult。candidate 晋升前触发，同步。
- 趋势层：RuntimeTracker。窗口健康报告 + 退化检测。after_agent 写；命令 / GitRatchet 读，同步。

二、支撑模块
- contract_compiler.py：从 skill 文本编译规则清单（决定"跑哪些"）。
- checks.py：确定性检查函数库（决定"怎么检查"，单一真相源）。
- registry.py：EvalRegistry + RegistryEvalBridge（L2 唯一可见的 L3 实现）。

三、数据契约（eval/types.py）
- SkillJudgment：执行层产出，落 skill_eval_judgments。
- EvolutionSuggestion：执行层产出，不落库，交 L2。
- TaskQualityScore：任务层产出，落 task_quality_scores。
- ContractRule：响应层产出，随 EvalRun.result_json 存档。
- SkillHealthReport：趋势层产出，不落库。
- EvalRun：审计记录，落 skill_eval_runs。

四、接口契约（eval/protocols.py）
5 个 @runtime_checkable Protocol：SkillJudgmentAnalyzer / TaskQualityJudge / ResponseContractChecker / RuntimeTracker / EvalRunStore。实现由 bootstrap 注入，零侵入 L2。

五、初始化（装配）
bootstrap：
- 响应层：build_default_registry() → ContractCompiler → ResponseContractChecker → EvalRegistry → RegistryEvalBridge → 注入 L2（替换 ProgrammaticEvalBridge）。
- 执行层 / 任务层 / 趋势层：直接构造（llm / store 可 None）。
- EvalLayer(...) → SkillManager.set_eval_layer（回注，避免循环依赖）。

六、调用点（Agent 循环）
- 装配：启动时，全部构造，一次性。
- 执行后：after_agent，SkillJudgmentAnalyzer，每轮 async。
- 任务后：任务结束，TaskQualityJudge，每轮 async。
- 晋升前：L2 触发，RegistryEvalBridge → ResponseContractChecker，非每轮同步。
- 趋势：按需，RuntimeTracker，非每轮。

七、数据回流
- SkillJudgmentAnalyzer.save_judgment → skill_eval_judgments。
- SkillJudgmentAnalyzer.record_outcome → skill_records（L1 4 计数器）。
- TaskQualityJudge.save_task_score → task_quality_scores。
- 响应层（经 bridge）save_eval_run → skill_eval_runs。
- RuntimeTracker 不落库。

闭环：执行层修正 L1 计数器 → 下一轮 selector 依据新 effective_rate 重新选择。

八、异常与降级
- RegistryEvalBridge：registry 空 / 异常 → fail-closed 返 reject。
- SkillJudgmentAnalyzer：无 skill / 无 llm / 异常 → 返 ([], [])。
- TaskQualityJudge：无 llm / 异常 → 返 None。
- checks.read_content：文件读失败 → 返 ""。
- ResponseContractChecker._run_rule：未知 rule_id → 默认 pass。
原则：响应层 fail-closed（安全优先）；执行 / 任务层 fail-silent（不阻断主流程）。

九、关键设计编号（D-L3-x 速查）
- D-L3-2：EvalBridge Protocol 保持 L2 已有约定。
- D-L3-3：analyzer 内调 store.record_outcome 更新 L1 计数器。
- D-L3-4：ContractCompiler 从 skill 文本自动编译规则，外部 skill 零改造。
- D-L3-5 / D-L3-13：任务层 4 维权重 0.50 / 0.35 / 0.05 / 0.10。
- D-L3-8：fail-closed。
- D-L3-10：复用 skills.db v2→v3（eval 三表）。
- D-L3-14：无 skill 注入时返空。
- D-L3-16：after_agent 写数据 + 命令算趋势 + GitRatchet 调 degraded_skills。
- D-L3-19：异步 fire-and-forget。
- D-L3-21：一次 LLM 调用同时产 SkillJudgment + EvolutionSuggestion。

【职责边界】

一、Eval 层做什么
- 评估：执行层（skill 是否被用）、任务层（任务质量）、响应层（契约检查）、趋势层（健康报告）。
- 评分：产 SkillJudgment / TaskQualityScore / EvalResult / SkillHealthReport。
- 回流：执行层修正 L1 4 计数器（唯一反向写 L1 的 eval 组件）。
- 供给：EvolutionSuggestion / EvalResult 交给 L2 做进化决策。
- 暴露：通过 EvalBridge Protocol 向 L2 提供唯一入口。

二、Eval 层不做什么
- 技能解析：归 parser.py。
- 技能选择：归 selector.py。
- 注入渲染：归 injector.py。
- 打点触发时机：归 middlewares/。
- 持久化实现：归 store.py。
- 进化决策（变异 / 门控 / 晋升）：归 evolution/（L2）。
- 晋升与否的最终判断：归 L2 ScoreDeltaGate。

三、与相邻层的边界
L1（基础层）：store / parser。
L3（eval 层）：执行 / 任务 / 响应 / 趋势。
L2（evolution）：变异 / 门控 / 晋升。
- eval 读 L1 打点数据。
- eval 修 L1 的 4 计数器。
- eval 产 EvolutionSuggestion / EvalResult 给 L2。
- L2 决策后 create_version 写回 L1。

边界要点：
- eval 只读 store 的历史数据，只写 judgment / task_score / eval_run 三表 + L1 计数器。
- eval 不碰 selector / injector / middleware。
- eval 不决定晋升——只产 EvalResult，决策在 L2。
- eval 不执行进化——只产 EvolutionSuggestion，执行在 L2。

四、三条边界原则
1. 零侵入 L2：L2 只认 EvalBridge Protocol；替换 L3 实现时 L2 零改动（D-L3-2）。
2. 回注而非内建：EvalLayer 由 bootstrap 构造后 set_eval_layer 回注，避免与 L1 / L2 循环依赖。
3. 降级分级：响应层 fail-closed（关系晋升，必须保守）；执行 / 任务层 fail-silent（事后评估，失败可忽略）。

一句话总结：
Eval 层（L3）= skill 子系统的质量评估中枢。
- 整体职责：评估四层（执行 / 任务 / 响应 / 趋势），回流修正 L1 计数器，供 L2 进化决策。
- 内容摘要：四层组件 + 三支撑模块 + 六值对象 + 五 Protocol；bootstrap 装配、set_eval_layer 回注。
- 职责边界：只评估、只供给、不决策、不执行；零侵入 L2；响应层 fail-closed，执行 / 任务层 fail-silent。

### 0.2. 运行时调用树

```
① 装配期（bootstrap，一次性）
    ├─ build_default_registry()
    │     ├─ ContractCompiler()
    │     ├─ ResponseContractChecker(compiler)
    │     └─ EvalRegistry(checker)
    │           └─ RegistryEvalBridge(registry)          ← 注入 L2
    ├─ SkillJudgmentAnalyzer(llm, store)
    ├─ TaskQualityJudge(llm, store)
    ├─ RuntimeTracker(...)
    └─ EvalLayer(bridge, analyzer, judge, tracker)
          └─ SkillManager.set_eval_layer(...)

        ═══════════ 进入 Agent 循环 ═══════════

② after_agent —— 执行层（异步 fire-and-forget）
    caller
        └─ asyncio.create_task(analyzer.analyze_execution(...))
              ├─ 前置检查（无 skill / 无 llm）→ ([], [])
              ├─ _llm_analyze → judgments + suggestions
              ├─ _persist
              │     ├─ store.save_judgment(j)            → skill_eval_judgments
              │     └─ store.record_outcome(...)         → L1 4 计数器
              └─ suggestions → L2 trigger

③ 任务结束后 —— 任务层（异步）
    caller
        └─ asyncio.create_task(judge.judge_task(...))
              ├─ _llm_judge → TaskQualityScore
              └─ store.save_task_score(score)            → task_quality_scores

④ candidate 晋升前 —— 响应层（同步，L2 触发）
    L2 → RegistryEvalBridge.evaluate(ctx)
            ├─ registry.get_contract_checker()
            ├─ checks.read_content(candidate / baseline)
            └─ ResponseContractChecker.check(...)
                  ├─ ContractCompiler.compile(candidate) → rules
                  ├─ for rule: _run_rule → checks.*
                  └─ EvalResult → L2 ScoreDeltaGate
            （异常 → fail-closed 返 reject）

⑤ 趋势层（按需）
    RuntimeTracker.health_report(...) / degraded_skills(...)
        └─ 读 store 的 judgments + 计数器
```

## 1. eval 的四层与组件全景

```
eval 四层
├─ 执行层  SkillJudgmentAnalyzer   （LLM 判断 per-skill 是否被应用 + 进化建议）
├─ 任务层  TaskQualityJudge        （LLM 4 维加权评分）
├─ 响应层  ResponseContractChecker （规则编译 + 检查 candidate，产 EvalResult）
│            ├─ ContractCompiler   （决定跑哪些规则）
│            └─ checks.py          （纯函数：怎么检查）
└─ 趋势层  RuntimeTracker          （窗口健康报告 + 退化检测）

入口
├─ EvalLayer（容器）                ← bootstrap 装配
├─ EvalRegistry + RegistryEvalBridge ← L2 唯一可见的 L3 实现（响应层入口）
└─ SkillManager.set_eval_layer / get_eval_layer ← 注入 / 取用
```

**关键**：响应层走 `RegistryEvalBridge`（L2 通过 `EvalBridge` Protocol 调用）；执行层 / 任务层 / 趋势层由 bootstrap 直接构造并放入 `EvalLayer`，不经 registry。

## 2. 初始化（装配期，一次性）

### 2.1. 装配调用链

```
bootstrap
    │
    ├─ ① 响应层装配（走 registry）
    │     build_default_registry()
    │         ├─ ContractCompiler()
    │         ├─ ResponseContractChecker(compiler)
    │         └─ EvalRegistry(checker)
    │               │
    │               ▼
    │         RegistryEvalBridge(registry)      ← 实现 EvalBridge Protocol
    │               └─ 注入 L2（ScoreDeltaGate），替换 ProgrammaticEvalBridge
    │
    ├─ ② 执行层 / 任务层 / 趋势层装配（直接构造）
    │     SkillJudgmentAnalyzer(llm, store)
    │     TaskQualityJudge(llm, store)
    │     RuntimeTracker(...)
    │
    └─ ③ 打包注入 SkillManager
          EvalLayer(
              bridge            = registry_bridge,
              judgment_analyzer = judgment_analyzer,
              task_judge        = task_judge,
              runtime_tracker   = runtime_tracker,
          )
              └─ SkillManager.set_eval_layer(eval_layer)
                    └─ self._eval_layer = eval_layer
```

### 2.2. 装配来源分层

| 组件 | 构造者 | 注入方式 | 依赖 |
|------|--------|---------|------|
| `ContractCompiler` | `build_default_registry` | 直接 new | 无 |
| `ResponseContractChecker` | `build_default_registry` | 构造参数 | compiler |
| `EvalRegistry` | `build_default_registry` | 构造参数 | checker |
| `RegistryEvalBridge` | bootstrap | 构造参数 | registry |
| `SkillJudgmentAnalyzer` | bootstrap | 构造参数 | llm / store（可 None） |
| `TaskQualityJudge` | bootstrap | 构造参数 | llm / store（可 None） |
| `RuntimeTracker` | bootstrap | 构造参数 | store / 窗口参数 |
| `EvalLayer` | bootstrap | 打包 | 上述四个组件 |

### 2.3. 为什么回注而不是在 `SkillManager.__init__` 里建

- eval 组件反向依赖 skill 基础层（store）与 evolution 类型，直接在建会成环。
- 所以走 `set_eval_layer` 回注（与 `set_evolution_manager` 同理）。

## 3. 在哪里被调用（Agent 循环各阶段）

| 阶段 | Hook / 时机 | 触发哪个 eval 组件 | 同步/异步 | 是否每轮 |
|------|------------|-------------------|:---:|:---:|
| 装配 | 进程/会话启动 | 全部（构造） | — | 一次性 |
| 执行后 | `after_agent` | `SkillJudgmentAnalyzer.analyze_execution` | async | ✅ |
| 任务后 | 任务结束 | `TaskQualityJudge.judge_task` | async | ✅ |
| 晋升前 | candidate 晋升前 | `RegistryEvalBridge.evaluate` → `ResponseContractChecker.check` | 同步 | ❌（仅进化时） |
| 趋势 | after_agent 写数据；命令/GitRatchet 读 | `RuntimeTracker` | 同步 | ❌ |

**要点**：

- **执行层 / 任务层**是"事后评估"，每轮任务后异步跑，**不阻塞用户**（caller 负责 `asyncio.create_task`）。
- **响应层**只在"候选版本要晋升"时触发（L2 调 `evaluate`），是**同步且 fail-closed**。
- **趋势层**既写（after_agent）又读（命令/GitRatchet 按需）。

## 4. 内部流程（逐组件）

### 4.1. 执行层 `SkillJudgmentAnalyzer.analyze_execution`

```
1. 前置检查：injected_skills 空 或 llm None → 返 ([], [])
2. _llm_analyze：
     ├─ 构造 prompt（skill 清单 + 摘要 + journal 事件）
     ├─ llm.invoke([HumanMessage])
     ├─ _extract_json → data（失败 → ([], [])）
     ├─ 解析 judgments（过滤 skill_id 不在 injected_skills 的项，防幻觉）
     └─ 解析 suggestions（evolution_type 非法 → "FIX"）
3. _persist：
     └─ for j in judgments:
           ├─ store.save_judgment(j)              → skill_eval_judgments 表
           └─ store.record_outcome(...)           → 更新 L1 4 计数器
4. 返回 (judgments, suggestions)
     └─ suggestions → L2 trigger（供进化）
```

**特点**：一次 LLM 调用产两类；**唯一反向写 L1 计数器**的 eval 组件。

### 4.2. 任务层 `TaskQualityJudge.judge_task`

```
1. llm None → None
2. _llm_judge：
     ├─ trace / output 截断（80000 / 20000）
     ├─ 构造 prompt（trace + output + 4 维说明）
     ├─ llm.invoke([HumanMessage])
     ├─ _extract_json（失败 → None）
     ├─ 4 维 clamp 到 [0,1]（缺省 0.5）
     └─ overall = Σ(dim × weight)，round 3 位
3. store.save_task_score(score)                 → task_quality_scores 表
4. 返回 TaskQualityScore
```

**特点**：只写 `task_quality_scores`，不碰 L1 计数器。

### 4.3. 响应层 `RegistryEvalBridge.evaluate` → `ResponseContractChecker.check`

```
1. RegistryEvalBridge.evaluate(ctx)：
     ├─ registry.get_contract_checker()
     ├─ checks.read_content(ctx.candidate)
     ├─ checks.read_content(ctx.baseline)（无 → ""）
     └─ checker.check(candidate, baseline)
   任何异常 → fail-closed 返 reject

2. ResponseContractChecker.check：
     ├─ rules = compiler.compile(candidate_content)
     │     ├─ 硬规则：nonempty / json_parseable
     │     ├─ contract 规则（文本命中才编译）：
     │     │     must_cite / lead_with_conclusion / paragraph_limit
     │     └─ soft 规则：no_unfounded_claims / semantic_density
     ├─ for rule:
     │     ├─ cand_pass = _run_rule(rule_id, candidate, params)
     │     ├─ base_pass = _run_rule(rule_id, baseline, params)（无 baseline → True）
     │     ├─ cand_pass → passed += 1
     │     ├─ rule.hard 且 not cand_pass → hard_failures.append(rule_id)
     │     └─ evidence.append(EvalEvidence(...))
     ├─ score = passed / total（total=0 → 0.0）
     ├─ recommendation = "reject" if hard_failures else "accept"
     └─ EvalResult(score, metric="hard", hard_failures, evidence,
                   confidence=0.7, recommendation)
3. EvalResult → L2 ScoreDeltaGate → 决定晋升与否
```

**特点**：同步、fail-closed、逐条跑完不 short-circuit。

### 4.4. 趋势层 `RuntimeTracker`

```
health_report(skill_id, window=20)
    └─ 读 store 的历史 judgments + 计数器
        → SkillHealthReport（window 内 4 rate + trend + recent_judgments + advice）

degraded_skills(threshold=0.15)
    └─ 扫 active skills，找退化者
        → list[str]（供 GitRatchet 决定是否回滚）
```

## 5. 数据回流（写哪些表、给谁用）

### 5.1. 落库对应

| 组件 | 写入方法 | 目标表 |
|------|---------|--------|
| `SkillJudgmentAnalyzer` | `save_judgment` | `skill_eval_judgments` |
| `SkillJudgmentAnalyzer` | `record_outcome` | **`skill_records`（L1 4 计数器）** |
| `TaskQualityJudge` | `save_task_score` | `task_quality_scores` |
| `ResponseContractChecker`（经 bridge） | `save_eval_run`（由上层调） | `skill_eval_runs` |
| `RuntimeTracker` | 不落库（运行时产出） | — |

### 5.2. 回流闭环

```
执行层 judgment ──┬─► store.save_judgment（审计）
                  ├─► store.record_outcome（修正 L1 4 计数器）
                  └─► suggestions → L2 trigger（进化信号）

任务层 score ───────► store.save_task_score（评分存档）

响应层 EvalResult ──► L2 ScoreDeltaGate（决定晋升）

趋势层 report ──────► TUI 展示 / evolution 参考 / GitRatchet 回滚
```

**闭环**：执行层修正 L1 计数器 → 下一轮 selector 依据新的 `effective_rate` 重新选择。

## 6. 异常与降级总表

| 组件 | 触发条件 | 行为 |
|------|---------|------|
| `RegistryEvalBridge.evaluate` | registry 空 / 文件读失败 / checker 抛错 | **fail-closed** 返 reject |
| `SkillJudgmentAnalyzer` | 无 skill / 无 llm / 异常 / 解析失败 | 返 `([], [])` |
| `SkillJudgmentAnalyzer._persist` | 写库异常 | silent pass |
| `TaskQualityJudge` | 无 llm / 异常 / 解析失败 | 返 `None` |
| `TaskQualityJudge` | 写库异常 | silent pass |
| `ResponseContractChecker._run_rule` | 未知 rule_id | 默认 pass |
| `checks.read_content` | 文件读失败 | 返 `""` |

**原则**：

- 响应层 **fail-closed**（安全优先，宁可错拒）。
- 执行层 / 任务层 **fail-silent**（不阻断主流程）。

## 7. 完整链路（一张图）

```
装配期（bootstrap）
    ├─ build_default_registry()
    │     ├─ ContractCompiler
    │     ├─ ResponseContractChecker
    │     └─ EvalRegistry
    │           └─ RegistryEvalBridge → 注入 L2
    ├─ SkillJudgmentAnalyzer(llm, store)
    ├─ TaskQualityJudge(llm, store)
    ├─ RuntimeTracker(...)
    └─ EvalLayer(...) → SkillManager.set_eval_layer

        ═══════════ 运行期 ═══════════

after_agent
    ├─ asyncio.create_task(SkillJudgmentAnalyzer.analyze_execution(...))
    │     └─ judgments → save_judgment + record_outcome（L1 计数器）
    │        suggestions → L2 trigger
    └─ asyncio.create_task(TaskQualityJudge.judge_task(...))
          └─ score → save_task_score

candidate 晋升前（L2 触发）
    RegistryEvalBridge.evaluate(ctx)
        └─ ResponseContractChecker.check
              ├─ ContractCompiler.compile
              ├─ _run_rule → checks.*
              └─ EvalResult → L2 ScoreDeltaGate

趋势（按需）
    RuntimeTracker.health_report / degraded_skills
```

## 8. 总结

| 层面 | 内容 |
|------|------|
| **初始化** | bootstrap：响应层走 `build_default_registry` → `RegistryEvalBridge` → 注入 L2；执行/任务/趋势层直接构造 → 打包 `EvalLayer` → `set_eval_layer` 回注 SkillManager。 |
| **调用点** | 执行/任务层在 `after_agent`（异步，每轮）；响应层在 candidate 晋升前（同步，L2 触发）；趋势层按需。 |
| **内部流程** | 执行层：LLM 判断 + 进化建议 + 修 L1 计数器；任务层：LLM 4 维加权；响应层：编译规则 + 执行 + 汇总 EvalResult；趋势层：窗口健康报告。 |
| **数据回流** | 执行层 → `skill_eval_judgments` + **L1 计数器**；任务层 → `task_quality_scores`；响应层 → `EvalResult` 给 L2；趋势层 → 运行时供 TUI/evolution。 |
| **降级原则** | 响应层 fail-closed；执行/任务层 fail-silent。 |

**eval 的本质**：它是"写路径（打点）"与"进化层"之间的质检站——消费打点数据，产出更细的评分与建议，既回流修正 L1 计数器，又为 evolution 提供决策依据。
