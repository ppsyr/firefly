---

name: Skill 注入文本构建 — markdown block，从 SKILL.md 文件读 body（去 frontmatter）。

description: 

【整体职责】
把选中的 active skills 拼成一段 markdown 注入块，供 SkillInjectionMiddleware
写入上下文。正文（body）从 SKILL.md 文件现读，不依赖 DB 里存的内容。

【内容摘要】
- build_injection_text(skills) : 构建注入用的 markdown 块（模块主函数）。
- _read_body(path)             : 读 SKILL.md 并剥离 frontmatter，返回正文。

【职责边界】
- 只负责：把 SkillRecord 列表渲染成 markdown、从文件读取并剥离 frontmatter。
- 不负责：技能选择（selector）、注入时机（middleware）、打点（metrics）、持久化（store）。
- 不持有状态：纯函数，每次调用现读文件。

## 0. 结构树

### 0.1. 静态结构树

```
injector.py — Skill 注入文本构建（markdown block）
│
├─ build_injection_text(skills) -> str        ← 模块主函数
│   ├─ skills 为空 → return ""
│   ├─ lines = ["# Active Skills", ""]
│   └─ for rec in skills:
│         ├─ body = _read_body(rec.path)
│         ├─ lines.append(f"### Skill: {rec.name}")
│         ├─ lines.append(f"**Path**: {rec.path}")
│         ├─ lines.append("")
│         ├─ lines.append(body.strip())
│         ├─ lines.append("")
│         ├─ lines.append("---")
│         └─ lines.append("")
│   └─ return "\n".join(lines)
│
└─ _read_body(path) -> str
    ├─ Path(path).read_text(encoding="utf-8")   ← 异常 → return ""
    ├─ content.startswith("---") ?
    │     ├─ parts = content.split("---", 2)
    │     ├─ len(parts) >= 3 → return parts[2].lstrip("\r\n")
    │     └─ 否则 → return content
    └─ 否则 → return content
```

## 1. 补充

**`injector.py` 是 skill 注入环节的"渲染器"——把选中的 `SkillRecord` 列表渲染成一段可直接写进上下文的 markdown 文本，正文从 SKILL.md 文件现读。**

### 1.1. 在数据流中的位置

```
store ── selector ── 选中 skills ── injector ── markdown ── 注入上下文
                                        ▲
                                    你在这里
```

- **上游**：`SkillSelector` 选出本轮要用的技能（`list[SkillRecord]`）。
- **本模块**：渲染 markdown，正文从 `rec.path` 现读。
- **下游**：`SkillInjectionMiddleware` 把这段文本写进模型上下文。

它是"读路径"的**最后一步**：selector 选完 → injector 渲染 → middleware 注入。

### 1.2. 具体承担两件事

| 职责 | 说明 |
|------|------|
| **渲染** | 把 skills 列表拼成 markdown（header + 每个 skill 的 name / path / body / 分隔线）。 |
| **读取正文** | 从 `rec.path` 读 SKILL.md 并剥离 frontmatter，只取 body。 |

### 1.3. 两个关键设计点

1. **内容/索引分离的落点**
   - `SkillRecord` 只存 `path`，正文不存 DB。
   - 注入时现读文件 → 保证注入的是**最新正文**；与 parser 的 `content_hash` 变更检测形成呼应（parser 检测变更，injector 现读最新内容）。

2. **失败降级**
   - 读文件失败 → 返空 body，**只注入 header**（name + path），不抛异常。
   - 效果：某个技能文件丢失，不会导致整轮注入失败。

### 1.4. 和其他模块的关系

| 模块 | 与 injector 的关系 |
|------|-------------------|
| `types.py` | **依赖**：入参是 `SkillRecord`。 |
| `selector.py` | **上游**：产出 `list[SkillRecord]`。 |
| `middlewares/skill_injection_middleware.py` | **调用方**：在 `before_model` 里调 `build_injection_text`。 |
| `parser.py` | **互补**：parser 解析 frontmatter 入库；injector 读 body 注入。二者基于同一套 SKILL.md 格式约定。 |
| `store.py` | 无直接关系：injector 不读 DB，只读文件（`path` 来自 selector 返回的 record）。 |

### 1.5. 总结

**`injector.py` = 把 `SkillRecord` 渲染成注入用 markdown，正文从文件现读。**
它是读路径的最后一环，把"选中的技能"变成"模型真正看到的文本"。
