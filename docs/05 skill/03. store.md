---

name:SkillStore — SQLite + WAL + version DAG + 4 计数器打点。

description:

【整体职责】
skill 基础层的持久化实现。
用 SQLite（WAL 模式）存储技能记录、版本血缘（version DAG）、
质量打点（4 计数器 + judgment）、进化记录、L3 eval 记录，
并提供注册 / 发现 / 版本管理 / 打点 / 查询接口。

它是全链路的数据落点：
- 上游：parser 产出 SkillRecord → 本模块 discover/register 写入。
- 下游：selector 读 active skills；middleware 写打点；evolution/eval 读写记录。

【内容摘要】
模块常量 / 函数：
- _SCHEMA_VERSION            ：当前 schema 版本号（=3）。
- _SCHEMA_SQL                ：建表 SQL（幂等，含 8 张表 + 索引）。
- _migrate_v1_v2(conn)       ：v1→v2 增量迁移（加 skill_evolutions）。
- _migrate_v2_v3(conn)       ：v2→v3 增量迁移（加 L3 eval 三表）。
类：
- SkillStore(Protocol)       ：存储接口抽象，声明基础层契约。
- SQLiteSkillStore           ：SQLite 实现（本模块主体）。

SQLiteSkillStore 方法分组：
- 构造 / schema ：__init__ / _init_schema / _migrate
- 注册 / 发现   ：register / get / get_active / list_active / set_enabled /
                  discover / _upsert_record
- version DAG   ：create_version / get_versions / rollback
- 打点 / 查询   ：record_selection / record_outcome / get_metrics /
                  get_top_skills / health_check
- evolution     ：record_evolution / get_evolution_history
- eval 持久化   ：save_judgment / get_judgments / save_task_score /
                  get_task_scores / save_eval_run
- 辅助          ：_row_to_record / close

【职责边界】
- 只负责：持久化、schema 迁移、版本指针切换、计数器累加、查询与排序。
- 不负责：技能解析（parser）、选择（selector）、注入（injector）、
  打点触发时机（middleware）、进化决策（evolution）、评估逻辑（eval）。
- 不生成 skill_id：注册与建版本时由调用方传入 record.skill_id。
- 不 runtime import L2/L3 类型：EvolutionRecord / EvalSkillJudgment /
  TaskQualityScore / EvalRun 走 duck-type（TYPE_CHECKING + 方法内延迟 import），
  避免 L1 ↔ L2 ↔ L3 循环依赖。

### 0.2. 运行时调用树

```
① 装配期（进程 / 会话启动，一次性）
SQLiteSkillStore(db_path)                        ← SkillManager.__init__ 构造
    ├─ mkdir -p 父目录
    ├─ sqlite3.connect(check_same_thread=False) + Row factory
    └─ _init_schema()
          ├─ PRAGMA journal_mode=WAL / busy_timeout=30000
          ├─ executescript(_SCHEMA_SQL)
          └─ if user_version < 3: _migrate(v, 3) → PRAGMA user_version = 3

SkillManager.load_startup(llm)
    ├─ store.discover(user_dirs, IMPORTED)        ← parser 解析 + _upsert_record
    ├─ store.discover(core_dir, BUILTIN)
    └─ store.register(...)（幂等兜底）

        ═══════════ 进入 Agent 循环 ═══════════

② before_model —— 读路径
SkillInjectionMiddleware.before_model
    └─ SkillSelector.select(state)
          └─ store.list_active() / get_top_skills(...)     ← 读 active skills + rate
                └─ _row_to_record(row)                     ← Row → SkillRecord

③ awrap_tool_call —— 本模块不介入
（只走 _ctx.py 的 ContextVar，不碰 store）

④ after_agent —— 写路径（打点）
SkillMetricsMiddleware.after_agent
    └─ store.record_outcome(skill_id, run_id, applied, task_completed)
          ├─ 4 计数器累加（applied / completions / fallbacks）
          └─ INSERT skill_judgments

⑤ 闭环（跨轮）
store.record_selection / record_outcome
    └─ 计数器变化 → rate 变化 → 下一轮 ② 的 selector 读到新 effective_rate

⑥ 评估（Layer 3，非每轮）
EvalLayer
    ├─ store.get_judgments / get_task_scores           ← 读
    └─ store.save_judgment / save_task_score / save_eval_run   ← 写

⑦ 自进化（Layer 2，非每轮）
EvolutionManager
    ├─ store.get_metrics / get_evolution_history        ← 读
    ├─ store.record_evolution                            ← 写实验记录
    └─ store.create_version(...)                         ← 写新版本（version DAG）
```

## 1. 补充

**`store.py` 是 skill 子系统的"数据中枢"——唯一持久化层，所有组件都通过它读写技能记录、版本血缘和质量计数器。**

### 1.1. 在架构中的位置

```
             parser.py
                 │ 产出 SkillRecord
                 ▼
   ┌─────────── store.py ───────────┐        ← 你在这里
   │  持久化 / 版本 / 计数器 / 查询  │
   └────────────────────────────────┘
      ▲        ▲          ▲        ▲
      │        │          │        │
  selector  injection  metrics  evolution/eval
   （读）    （读）      （写）     （读写）
```

- **上游**：parser 产出 `SkillRecord`，store 负责落库。
- **下游**：selector 读 active skills；middleware 写打点；evolution/eval 读写记录。
- **它不在 Agent 循环内做逻辑**，只在各 hook 触发时被读写。

### 1.2. 具体承担六件事

| 职责 | 说明 |
|------|------|
| **注册 / 发现** | `discover` 扫目录调 parser，`register`/`_upsert_record` 幂等写入；`get`/`list_active` 读回。 |
| **持久化** | SQLite + WAL，内容/索引分离（只存 path + content_hash）。 |
| **version DAG** | `create_version` 建新 node + 旧 node deactive + 写血缘；`rollback` 切指针不删行。 |
| **打点** | `record_selection`（读路径命中）+ `record_outcome`（写路径归因）累加 4 计数器。 |
| **查询 / 排序** | `get_metrics` / `get_top_skills` / `health_check`，供 selector 决策。 |
| **跨层持久化** | 代 evolution（`record_evolution`）与 eval（`save_judgment` 等）写记录。 |

### 1.3. 三个关键设计点（无文档时最该记住）

1. **内容/索引分离**
   - DB 只存 `path + content_hash`，SKILL.md 全文留在文件系统（source of truth）。
   - 好处：DB 轻量，避免冗余；文件变更通过 content_hash 检测。

2. **is_active 单指针 + version DAG**
   - 每个 `name` 只有一行 `is_active=1`。
   - 版本切换只改指针（`create_version` / `rollback`），**从不删行**——保证可回溯。
   - 血缘存在 `skill_lineage_parents`，构成 DAG。

3. **4 计数器零 LLM 打点**
   - `record_selection` / `record_outcome` 纯 SQL 累加，不依赖 LLM。
   - 计数器 → rate（property 现算）→ selector 决策，形成**写路径 → 读路径闭环**。

### 1.4. 和其他 skill 模块的关系

| 模块 | 与 store 的关系 |
|------|----------------|
| `parser.py` | **被调用**：`store.discover` 里 lazy import `parse_skill_file`。 |
| `types.py` | **数据契约**：store 读写 `SkillRecord` / `SkillLineage` / `SkillMetrics` / `SkillHealth`。 |
| `selector.py` | **消费者**：`list_active` / `get_top_skills` / `health_check`。 |
| `middlewares/skill_injection_middleware.py` | 读 active skills；可能调 `record_selection`。 |
| `middlewares/skill_metrics_middleware.py` | 调 `record_outcome` 写打点。 |
| `skill/evolution/` | 读 metrics/history，写 `record_evolution` + `create_version`。 |
| `skill/eval/` | 写 `save_judgment` / `save_task_score` / `save_eval_run`，读 `get_judgments` / `get_task_scores`。 |
| `__init__.py` | `SkillManager._store` 持有它；`build_skill_manager` 用 `config.db_path` 构造。 |

### 1.5. 总结

**`store.py` = skill 子系统的唯一持久化层与数据中枢。**
它把 parser 的产出落库、维护版本 DAG、累加质量计数器、并提供查询与排序；上接 parser/types，下供 selector 与 middleware 读写，是 skill 闭环里"数据"这条线的核心。
