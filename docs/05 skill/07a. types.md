---

name: Skill eval 评估层值对象 — frozen dataclass + Literal 枚举。

description: 

【整体职责】
定义 L3 评估层的数据契约（全部为不可变值对象 + Literal 枚举）。
覆盖三层评估 + 两个跨层对象：
- 执行层：SkillJudgment / EvolutionSuggestion
- 任务层：TaskQualityScore
- 响应层：ContractRule
- 趋势层：SkillHealthReport
- 统一审计：EvalRun

这些类型是 eval 层内部产出、store 持久化、evolution 消费的共同语言。
承接 38-skill-eval-layer-design.md §4.1 接口签名。

【内容摘要】
Literal 枚举：
- EvalLayer        : "execution" / "task" / "response"（三层评估标识）。
- Trend            : "improving" / "stable" / "degrading" / "insufficient_data"。
- ContractRuleKind : "programmatic"（确定性检查）/ "llm_binary"（LLM 判断）。

值对象：
- SkillJudgment        : 执行层 per-skill per-task 有效性判断。
- EvolutionSuggestion  : 执行层 LLM 产出的进化建议（喂给 L2 trigger）。
- TaskQualityScore     : 任务层 4 维加权评分。
- ContractRule         : 响应层从 skill 文本编译的契约规则。
- SkillHealthReport    : 趋势层健康报告（RuntimeTracker 产出）。
- EvalRun              : 三层 eval 统一审计记录。

【职责边界】
- 只负责：定义数据契约（字段 + 枚举）。
- 不负责：评估逻辑（analyzers / tracker / bridge）、持久化（store）、决策（evolution）。
- 不持有可变状态：全部 frozen，构造后字段不可改。

## 0. 结构树

### 0.1. 静态结构树

```
eval/types.py — Skill eval 评估层值对象（数据契约：定义评估产出的全部类型）
│
├─ Literal 枚举
│   ├─ EvalLayer        ← 标识三层评估：execution（技能是否被用）/ task（任务质量）/ response（契约）
│   ├─ Trend            ← 趋势判定结果：improving（改善）/ stable（稳定）/ degrading（退化）/ insufficient_data（数据不足）
│   └─ ContractRuleKind ← 契约规则类型：programmatic（程序化确定性检查）/ llm_binary（LLM 二值判断）
│
├─ class SkillJudgment(frozen)                    ← 【执行层】判断"skill 是否真被应用"（比 middleware 打点更精确）
│   ├─ judgment_id: str                           ← 判断记录唯一 id
│   ├─ skill_id: str                              ← 被判断的 skill
│   ├─ skill_name: str                            ← 技能名（冗余，便于查询/展示）
│   ├─ task_id: str                               ← 所属任务
│   ├─ skill_applied: bool                        ← LLM 判断：agent 是否实际应用了 skill 指导
│   ├─ deviation_note: str = ""                   ← 偏差记录（如"跳过了 validate 步骤"）
│   └─ timestamp: str = ""                        ← ISO 时间戳
│
├─ class EvolutionSuggestion(frozen)              ← 【执行层→L2 桥】eval 产出的进化建议，喂给 evolution trigger
│   ├─ evolution_type: EvolutionType              ← FIX（修）/ DERIVED（派生）/ CAPTURED（捕获新技能）
│   ├─ target_skill_ids: tuple[str, ...] = ()     ← FIX/DERIVED 的目标；CAPTURED 无（新技能）
│   └─ direction: str = ""                        ← 自由文本：该修什么 / 该捕获什么
│
├─ class TaskQualityScore(frozen)                 ← 【任务层】任务质量 4 维加权评分
│   ├─ score_id: str                              ← 评分记录 id
│   ├─ task_id: str                               ← 所属任务
│   ├─ task_completion: float   [0,1]             ← 任务完成度（权重 0.50）
│   ├─ response_quality: float  [0,1]             ← 响应质量（权重 0.35）
│   ├─ efficiency: float        [0,1]             ← 效率（权重 0.05）
│   ├─ tool_usage: float        [0,1]             ← 工具使用（权重 0.10）
│   ├─ overall_score: float                       ← 加权总分
│   ├─ rationale: str = ""                        ← 评分理由（LLM 产出）
│   └─ timestamp: str = ""                        ← ISO 时间戳
│
├─ class ContractRule(frozen)                     ← 【响应层】从 skill 文本编译的契约规则
│   ├─ rule_id: str                               ← 规则标识（"nonempty" / "must_cite" / "json_parseable"）
│   ├─ kind: ContractRuleKind                     ← programmatic（确定性）/ llm_binary（LLM 判断）
│   ├─ hard: bool                                 ← True → 失败触发 hard_failure（reject 倾向）
│   ├─ description: str = ""                      ← 规则说明
│   └─ params: dict = {}                          ← 规则参数（按 kind 不同）
│
├─ class SkillHealthReport(frozen)                ← 【趋势层】窗口内健康报告（RuntimeTracker 产出）
│   ├─ skill_id: str                              ← 目标 skill
│   ├─ skill_name: str                            ← 技能名
│   ├─ window_selections: int                     ← 窗口内 selections 数
│   ├─ applied_rate: float                        ← 窗口内应用率
│   ├─ completion_rate: float                     ← 窗口内完成率
│   ├─ effective_rate: float                      ← 窗口内有效率
│   ├─ fallback_rate: float                       ← 窗口内回退率
│   ├─ trend: Trend                               ← improving / stable / degrading / insufficient_data
│   ├─ recent_judgments: tuple[SkillJudgment,...] ← 近 N 条偏差记录
│   └─ advice: str = ""                           ← 文字建议
│
└─ class EvalRun(frozen)                          ← 【审计】三层 eval 统一运行记录
    ├─ eval_run_id: str                           ← 运行 id
    ├─ eval_layer: EvalLayer                      ← "execution" / "task" / "response"
    ├─ skill_ids: tuple[str, ...]                 ← 本次评估涉及的 skill
    ├─ candidate_id: str | None = None            ← response 层：候选版本
    ├─ baseline_id: str | None = None             ← response 层：基线版本
    ├─ result_json: str = ""                      ← 评估结果 JSON
    └─ timestamp: str = ""                        ← ISO 时间戳
```

### 0.2. 运行时调用树（每个类型的产出方 / 消费方）

```
① 执行层（SkillJudgmentAnalyzer）
    ├─ 输入：messages / skill 上下文 / task
    ├─ 一次 LLM 调用同时产出：
    │     ├─ SkillJudgment          ← 判断"技能是否真被应用 + 偏差"
    │     │     └─ store.save_judgment(...)     → skill_eval_judgments 表
    │     └─ EvolutionSuggestion    ← 进化建议（喂 L2）
    │           └─ evolution.trigger            → 决定是否 FIX/DERIVED/CAPTURED
    └─ 产出 EvalRun（eval_layer="execution"）

② 任务层（TaskQualityJudge）
    ├─ 输入：任务消息（截断至 max_messages_chars）
    ├─ 产出：TaskQualityScore       ← 4 维加权评分 + rationale
    │     └─ store.save_task_score(...)         → task_quality_scores 表
    └─ 产出 EvalRun（eval_layer="task"）

③ 响应层（ContractCompiler → ResponseContractChecker）
    ├─ 输入：skill 文本
    ├─ 产出：ContractRule           ← 从 skill 编译出的契约规则
    │     └─ ResponseContractChecker 执行检查
    │           ├─ 通过
    │           └─ hard 规则失败 → hard_failure（reject 倾向）
    └─ 产出 EvalRun（eval_layer="response"，candidate_id / baseline_id 有值）
          └─ store.save_eval_run(...)           → skill_eval_runs 表
                （ContractRule 通过 result_json 间接存档）

④ 趋势层（RuntimeTracker）
    ├─ 输入：store 的 SkillJudgment 历史 + 计数器
    ├─ 产出：SkillHealthReport      ← 窗口内 4 rate + trend + advice
    └─ 消费方：TUI（展示）/ evolution（判断是否该进化）

⑤ 审计汇总（EvalRun）
    ├─ 三层各自产出一条 EvalRun
    └─ store.save_eval_run(...)                 → skill_eval_runs 表
```

### 0.3. 类型依赖与流转图

```
                        ┌──────────────────────────────────────┐
                        │         eval/types.py（本模块）        │
                        └──────────────────────────────────────┘
                                        │
        ┌───────────────┬───────────────┼───────────────┬───────────────┐
        ▼               ▼               ▼               ▼               ▼
  SkillJudgment  EvolutionSuggestion  TaskQualityScore  ContractRule  SkillHealthReport
        │               │               │               │               │
        │               │               │               │               │
        │ 引用自身      │ 引用 EvolutionType（外部）      │               │ 引用 SkillJudgment
        │（recent_judgments）             │               │               │
        ▼               ▼               ▼               ▼               ▼
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  store：save_judgment / save_task_score / save_eval_run                  │
  │  evolution：消费 EvolutionSuggestion                                     │
  │  RuntimeTracker：消费 SkillJudgment，产 SkillHealthReport                │
  │  ResponseContractChecker：消费 ContractRule                              │
  └─────────────────────────────────────────────────────────────────────────┘
                                        ▲
                                        │
                                  EvalRun（三层审计汇总）
```

**依赖要点：**

| 类型 | 依赖 | 说明 |
|------|------|------|
| `EvolutionSuggestion` | `EvolutionType`（外部） | 本模块唯一外部依赖 |
| `SkillHealthReport` | `SkillJudgment`（模块内） | `recent_judgments` 字段 |
| 其余类型 | 仅标准库 | 独立值对象 |

### 0.4. 与 store 表 / 方法的对应关系

| 类型 | store 写入方法 | 对应表 | 是否落库 |
|------|---------------|--------|:---:|
| `SkillJudgment` | `save_judgment` / `get_judgments` | `skill_eval_judgments` | ✅ |
| `TaskQualityScore` | `save_task_score` / `get_task_scores` | `task_quality_scores` | ✅ |
| `EvalRun` | `save_eval_run` | `skill_eval_runs` | ✅ |
| `ContractRule` | — | 随 `EvalRun.result_json` 存档 | 间接 |
| `SkillHealthReport` | — | 运行时产出（供 TUI/evolution） | ❌ |
| `EvolutionSuggestion` | — | 直接交 L2 trigger | ❌ |

### 0.5. 总结

```
eval/types.py
   ├─ 三层评估产出：SkillJudgment（执行）/ TaskQualityScore（任务）/ ContractRule（响应）
   ├─ 趋势产出：SkillHealthReport
   ├─ 跨层桥：EvolutionSuggestion（→ L2）
   └─ 审计汇总：EvalRun
```

**本模块 = L3 评估层的"数据契约中心"**：六类值对象 + 三个枚举，上游由 analyzer / judge / tracker 产出，下游由 store 落库、由 evolution 消费 `EvolutionSuggestion`。
