---

name: SkillJudgmentAnalyzer — 执行层 eval（OpenSpace ExecutionAnalyzer 模型）。

description: 

【整体职责】
执行层评估器：任务结束后，用一次 LLM 调用分析执行过程，
对每个被注入的 skill 判断"agent 是否实际应用了它"，并顺带产出进化建议。
- 产出：list[SkillJudgment] + list[EvolutionSuggestion]。
- 持久化：写 judgment、更新 L1 4 计数器（analyzer 内调 store.record_outcome）。
- 触发：异步 fire-and-forget（caller 负责 asyncio.create_task）。

【内容摘要】
模块常量：
- _MAX_MESSAGES_CHARS : 送入 LLM 的消息摘要字符上限（80000）。
- _MAX_JOURNAL_EVENTS : 送入 LLM 的 journal 事件条数上限（50）。

类方法：
- __init__(llm, store)                : 保存依赖（均可为 None）。
- analyze_execution(...)              : 对外主入口（async）。
- _llm_analyze(...)                   : 调 LLM + 解析 JSON → judgments + suggestions。
- _persist(task_id, judgments, ...)   : 写 judgment + 更新 L1 计数器。
- _format_events(events)              : journal 事件格式化为文本。
- _extract_json(content)              : 从文本提取首个 JSON 对象。

【职责边界】
- 只负责：执行层 LLM 判断 + 进化建议产出 + 持久化 judgment + 更新计数器。
- 不负责：任务层评分（TaskQualityJudge）、响应层检查（ResponseContractChecker）、
  趋势追踪（RuntimeTracker）、选择/注入（selector / injector）。
- 不负责调度：异步由 caller 创建 task（fire-and-forget），本类不自行起协程。
- 不决定是否进化：只产 EvolutionSuggestion，由 L2 trigger 决定。

## 0. 结构树

### 0.1. 静态结构树

```
eval/analyzers/skill_judgment_analyzer.py — 执行层 eval
│
├─ 模块常量
│   ├─ _MAX_MESSAGES_CHARS = 80000   ← 消息摘要截断上限
│   └─ _MAX_JOURNAL_EVENTS = 50      ← journal 事件条数上限
│
└─ class SkillJudgmentAnalyzer
    ├─ __init__(llm, store)                          ← 保存依赖（均可 None）
    │
    ├─ async analyze_execution(                      ← 【对外主入口】
    │     task_id, journal_events,
    │     messages_summary, injected_skills,
    │     task_completed=True,
    │   ) -> tuple[list[SkillJudgment], list[EvolutionSuggestion]]
    │   ├─ injected_skills 空 或 llm None → ([], [])
    │   ├─ _llm_analyze(...)
    │   ├─ _persist(...)
    │   └─ return (judgments, suggestions)
    │
    ├─ _llm_analyze(task_id, journal_events,         ← 【LLM 调用 + 解析】
    │     messages_summary, injected_skills)
    │   ├─ 构造 prompt（skill 清单 + 摘要 + journal）
    │   ├─ llm.invoke([HumanMessage])
    │   ├─ _extract_json（失败 → ([], [])）
    │   ├─ 过滤 skill_id 不在 injected_skills 的 judgment
    │   └─ 解析 suggestions（非法 type → "FIX"）
    │
    ├─ _persist(task_id, judgments, task_completed)  ← 【持久化 + 更新 L1 计数器】
    │   ├─ store None → return
    │   └─ store.save_judgment + store.record_outcome
    │
    ├─ _format_events(events) -> str                 ← 【格式化】journal 事件 → 文本
    │
    └─ _extract_json(content) -> dict | None         ← 【解析】提取首个 JSON 对象
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap）
    SkillJudgmentAnalyzer(llm, store)
        └─ EvalLayer.judgment_analyzer → SkillManager.set_eval_layer(...)

② after_agent —— 执行层 eval（异步 fire-and-forget）
    caller
        └─ asyncio.create_task(analyzer.analyze_execution(...))
              ├─ 前置检查（空/无 llm）→ ([], [])
              ├─ _llm_analyze
              │     ├─ llm.invoke
              │     └─ 产 judgments + suggestions
              ├─ _persist
              │     ├─ store.save_judgment(j)            → skill_eval_judgments 表
              │     └─ store.record_outcome(j.skill_id, ...) → L1 4 计数器
              └─ return (judgments, suggestions)
                    └─ suggestions → L2 trigger
```

## 1. 补充

- **唯一反向写 L1 计数器**的 eval 组件：`_persist` 调 `store.record_outcome`，用 LLM 判断修正 4 计数器。
- **一次 LLM 调用产两类**：`judgments`（审计）+ `suggestions`（进化信号）。
- **全 silent 降级**：无 llm / 无 skill / 异常 / 解析失败 → 返 `([], [])`，不抛。
