---

name: SKILL.md YAML frontmatter 解析 + .skill_id sidecar + install。

description: 

【整体职责】
把技能目录里的 SKILL.md 解析为 SkillRecord。
负责：
- 解析 SKILL.md 的 YAML frontmatter（name / description / allowed-tools / enabled 等）。
- 通过 .skill_id sidecar 维护持久 skill_id（目录改名 id 不变）。
- 计算内容哈希（sha256 前 16 位）。
- install：把外部技能目录拷贝进目标根目录并解析注册。

上游调用者：SQLiteSkillStore.discover（扫描目录时逐个解析）。
本模块是 store 的输入源，产出 SkillRecord 供 register / _upsert_record 写入。

【内容摘要】
- 模块常量
    - _SKILL_ID_FILE  : ".skill_id" sidecar 文件名。
    - _FRONTMATTER_RE : frontmatter 正则（匹配 `---\\n{yaml}\\n---\\n{body}`）。
- _generate_skill_id(name, origin, generation) : 按 origin 生成 skill_id。
- read_or_create_skill_id(skill_dir, name, origin, generation) : 读/写 sidecar。
- parse_skill_file(skill_file, origin) : SKILL.md → SkillRecord（模块主函数）。
- install(source_dir, name, dest_root) : 拷贝技能目录并解析，返回 skill_id。

【职责边界】
- 只负责：文件读取、frontmatter 解析、字段校验、id 生成/持久化、内容哈希、目录拷贝。
- 不负责：持久化入库（store）、选择（selector）、注入（injector）、打点（middleware）。
- 不写 DB：parse_skill_file 只返回 SkillRecord，落库由 store.register/_upsert_record 完成。
- 不做版本演进：create_version / rollback 属 store；本模块只产出初始记录。

## 0. 结构树

### 0.1. 静态结构树（模块 → 常量/函数）

```
parser.py — SKILL.md YAML frontmatter 解析 + .skill_id sidecar + install
│
├─ 模块常量
│   ├─ _SKILL_ID_FILE = ".skill_id"          ← sidecar 文件名
│   └─ _FRONTMATTER_RE                       ← frontmatter 正则（---\n{yaml}\n---\n{body}）
│
├─ _generate_skill_id(name, origin, generation) -> str
│   └─ 纯计算，按 origin 生成 id（BUILTIN 确定性 / IMPORTED / EVOLVED 带 uuid）
│
├─ read_or_create_skill_id(skill_dir, name, origin, generation) -> str
│   ├─ BUILTIN  → 直接返回 {name}__builtin（不读写 sidecar）
│   └─ IMPORTED/EVOLVED → 读 .skill_id；不存在则生成并写入（持久 id）
│
├─ parse_skill_file(skill_file, origin) -> SkillRecord      ← 模块主函数
│   ├─ 读文件 → 正则切 frontmatter / body
│   ├─ yaml.safe_load → dict 校验
│   ├─ 校验必需字段 name / description
│   ├─ 解析可选字段 allowed-tools / enabled
│   ├─ read_or_create_skill_id → skill_id
│   ├─ sha256(content)[:16] → content_hash
│   └─ return SkillRecord(...)
│
└─ install(source_dir, name, dest_root) -> str
    ├─ 校验 name（[a-z0-9-]+）
    ├─ dest_dir 存在 → shutil.rmtree
    ├─ shutil.copytree(source_dir, dest_dir)
    ├─ 校验 SKILL.md 存在
    └─ parse_skill_file → 返回 skill_id
```

### 0.2. 运行时调用树

```
① 正常解析（discover 扫描时）
SQLiteSkillStore.discover(dirs, origin)
    └─ for skill_md in dir.rglob("SKILL.md"):
          parse_skill_file(skill_md, origin)
              ├─ read_text(SKILL.md)
              ├─ _FRONTMATTER_RE.match
              │     └─ 不匹配 → raise ValueError（缺 frontmatter）
              ├─ yaml.safe_load(fm_raw)
              │     ├─ YAMLError        → raise ValueError
              │     └─ 非 dict          → raise ValueError
              ├─ name / description 缺失 → raise ValueError
              ├─ allowed-tools → tuple（缺省 ()）
              ├─ enabled = fm.get("enabled", True)
              ├─ read_or_create_skill_id(skill_dir, name, origin)
              │     ├─ BUILTIN → _generate_skill_id（确定性，不落盘）
              │     └─ 否则     → sidecar 命中读 / 未命中生成 + 写
              ├─ content_hash = sha256(content)[:16]
              └─ return SkillRecord

② sidecar 持久（目录改名）
read_or_create_skill_id(skill_dir, name, origin)
    ├─ sidecar 存在 → 直接读回 skill_id（与目录名无关）
    └─ 否则 → 生成 + 写 sidecar（此后改名 id 不变）

③ 安装（install）
install(source_dir, name, dest_root)
    ├─ re.fullmatch("[a-z0-9-]+", name) 失败 → raise ValueError
    ├─ dest_dir 存在 → rmtree
    ├─ copytree(source_dir, dest_dir)
    ├─ SKILL.md 不存在 → raise FileNotFoundError
    └─ parse_skill_file(skill_file) → 返回 skill_id（不写 DB）
```

## 1. 这个模块在 skill 中起什么作用

一句话：**它是 skill 子系统的"入口解析器"——把磁盘上的 SKILL.md 变成内存里的 `SkillRecord`，是所有后续环节（入库、选择、注入、打点）的数据源头。**

### 1.1. 在数据流中的位置

```
文件系统 (SKILL.md)
        │
        ▼
   parser.py          ← 你在这里
        │  产出 SkillRecord
        ▼
   store.py           ← 持久化（register / _upsert_record）
        │
        ▼
   selector.py        ← 决策（从 store 里挑）
        │
        ▼
   injector.py + 中间件 ← 注入 / 打点
```

没有 parser，store 就没有输入；没有 store，selector 就没有候选。**parser 是整个 skill 链路的起点。**

### 1.2. 具体承担四件事

| 职责 | 说明 |
|------|------|
| **解析** | 读 SKILL.md，正则切 frontmatter，YAML 解析成 dict，产出 `SkillRecord`。 |
| **校验** | 强制 `name` + `description` 必填；frontmatter 必须是 mapping；YAML 错误直接抛。 |
| **身份（id）** | 通过 `.skill_id` sidecar 给 IMPORTED/EVOLVED 技能一个**持久 id**（目录改名不变）；BUILTIN 用确定性 id。 |
| **变更检测** | 算 `content_hash = sha256(全文)[:16]`，供 store 判断文件是否变更。 |

外加一个工具函数 `install`：拷贝外部技能目录 → 解析 → 返回 id（供 skill hub 安装用）。

### 1.3. 三个关键设计点（无文档时最该记住）

1. **sidecar 解耦"身份"与"路径"**
   - `skill_id` 存在 `.skill_id` 文件里，而不是由目录名推导。
   - 效果：技能目录改名/移动后，`skill_id` 不变，DB 里的记录、打点、血缘都不失效。
   - BUILTIN 例外：随包提交，用确定性 id `{name}__builtin`，不需要 sidecar。

2. **origin 决定 id 与 lineage**
   - `IMPORTED` → `{name}__imp_{uuid8}` + sidecar。
   - `BUILTIN` → `{name}__builtin`（无 sidecar）。
   - `EVOLVED` → `{name}__v{generation}_{uuid8}`（供进化版本用，但版本创建走 `store.create_version`，不在此模块）。

3. **只解析、不落库**
   - `parse_skill_file` 纯函数式：读文件 → 返回 `SkillRecord`，不碰 DB。
   - 落库由 `store.discover` → `_upsert_record` 完成。
   - 这条边界让 parser 可独立测试，也避免 parser ↔ store 循环依赖。

### 1.4. 和其他 skill 模块的关系

| 模块 | 与 parser 的关系 |
|------|-----------------|
| `store.py` | **调用方**：`discover` 里 lazy import `parse_skill_file`。 |
| `types.py` | **依赖**：产出 `SkillRecord` / `SkillLineage`。 |
| `selector.py` | 间接消费者：读 store 里的 `SkillRecord`（由 parser 产出）。 |
| `skill/hub/installer.py` | 可能复用 `install` / `parse_skill_file`。 |
| `__init__.py` | `search_builtin_skills` 里 lazy import `parse_skill_file`。 |

### 1.5. 总结

**parser.py = SKILL.md → SkillRecord 的翻译层 + 技能身份（id）的持久化层。**
它是 skill 链路的**输入端点**：没有它，store 没数据、selector 没候选、注入与打点无从谈起。
