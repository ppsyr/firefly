---

name: ScoreDeltaGate — 基础门（零 LLM，用 EvalResult）。

description: 

【整体职责】
evolution 闭环的门控环节：用 EvalResult 决定 candidate 能否晋升。
规则：candidate.score > baseline.score 且无 hard_failure → accept；否则 reject。
- 零 LLM：只看 EvalResult 的分数与 hard_failures。
- CAPTURED 特例：无 baseline，score > 0 即 accept。

设计约束（D7）：门用 EvalResult，不用 LLM 自评
（SkillLens 实测 LLM 自评 46.4% 不可靠）。

【内容摘要】
- __init__(min_delta)                            : 保存最小 score 增量。
- decide(candidate, baseline, eval_result)       : 对外主入口，产 GateDecision。
- _baseline_score(eval_result) -> float          : 从 evidence 的 baseline_pass 比例推断 baseline 分。

【职责边界】
- 只负责：用 EvalResult 做门控决策，产 GateDecision。
- 不负责：评估（eval_bridge）、变异（mutator）、聚焦（focuser）、触发（trigger）、
  持久化（store）、编排（EvolutionManager）。
- 不做 LLM 自评：所有决策基于 EvalResult（D7）。
- 不写 version DAG：create_version 由 EvolutionManager 在 accept 后调。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/gates/score_delta_gate.py — ScoreDeltaGate（基础门，零 LLM）
│
└─ class ScoreDeltaGate
    ├─ __init__(min_delta=0.0)                          ← 保存最小 score 增量
    │
    ├─ decide(candidate, baseline, eval_result)         ← 【对外主入口】
    │   -> GateDecision
    │   ├─ hard_failures 非空 → reject
    │   ├─ baseline is None（CAPTURED）：
    │   │     ├─ score > 0 → accept（new_version_id=candidate.skill_id）
    │   │     └─ score = 0 → reject
    │   ├─ baseline_score = _baseline_score(eval_result)  ← 从 evidence 推断
    │   └─ FIX / DERIVED：
    │         ├─ score > baseline_score + min_delta → accept
    │         └─ 否则 → reject
    │
    └─ _baseline_score(eval_result) -> float            ← 【推断】baseline 分
        ├─ 无 evidence → 0.0
        └─ baseline_pass 比例 = passed / len(evidence)
```

---

### 0.2. 运行时调用树

```
① 装配期（bootstrap）
    ScoreDeltaGate(min_delta=0.0)
        └─ 注入 EvolutionManager(gate=...)

② 进化闭环第五步 —— 门控
    EvolutionManager._run_evolution(ctx)
        ├─ …（focus → mutate → eval）
        └─ gate.decide(candidate, baseline, eval_result)   ← 本模块主入口
              ├─ hard_failures → reject
              ├─ baseline None（CAPTURED）→ score>0 ? accept : reject
              └─ FIX/DERIVED → score > baseline_score + min_delta ? accept : reject
        └─ EvolutionManager 据 recommendation 决定是否 create_version
```

## 1. 补充

- **零 LLM**：所有决策基于 `EvalResult`（score / hard_failures / evidence），不做 LLM 自评（D7：SkillLens 实测 LLM 自评 46.4% 不可靠）。
- **三条分支**：
  - `hard_failures` 非空 → 直接 reject（candidate 改坏了）。
  - `baseline is None`（CAPTURED 新技能）→ score > 0 即 accept（无 delta 对比）。
  - FIX / DERIVED → 要求 `candidate.score > baseline_score + min_delta`。
- **baseline_score 的推断方式**：不直接存 baseline 分，而是从 `EvalResult.evidence` 里 `baseline_pass` 的通过比例反推；无 evidence 时视为 0。
- **它是 2a 的默认门**：与 `GitRatchet` 一起构成 2a 门控；2b / L3 的门（ChampionGate / HITLGate / CompositeGate / ValidationGate / MultiJudgeGate）在 `gates/protocols.py` 预留。
