---

name: ProgrammaticEvalBridge — 兼容 facade（D1 方案 A + facade 保留）。

description: 

【整体职责】
L2 的"程序化评估桥"实现，作为兼容 facade 保留：
- L3 关闭时：EvolutionManager 用此 facade（L2 自带 floor）。
- L3 启用时：bootstrap 注入 RegistryEvalBridge 替换此 facade。
内部委托 ResponseContractChecker（contract-aware 升级版）。

保留原因（D1 方案 A + facade）：
- L2a 测试直接调 ProgrammaticEvalBridge._check_* 静态方法；
- 这些静态方法在此作为 checks 模块的委托（单一真相源仍在 checks）。

【内容摘要】
模块级常量（向后兼容，L2a 测试引用）：
- _HARD_MODES / _DIRECTIVE_WORDS / _UNFOUNDED_WORDS / _CONCLUSION_WORDS /
  _CITE_PATTERN / _YAML_FRONTMATTER / _PARAGRAPH_LIMIT /
  _SEMANTIC_DENSITY_MIN / _SEMANTIC_DENSITY_MAX
  均为 checks 模块同名常量的转发。

类方法：
- __init__()                              : 构造 ResponseContractChecker。
- evaluate(ctx) -> EvalResult             : 委托 checker.check（对外主入口）。
- _read_content(record) -> str            : 委托 checks.read_content。
- _split_body(content) -> str             : 委托 checks.split_body。
- _check_nonempty / _check_json_parseable / _check_must_cite /
  _check_paragraph_limit / _check_lead_with_conclusion /
  _check_no_unfounded_claims / _check_markdown_table
                                          : 委托 checks 的检查函数。
- _semantic_density(content) -> float     : 委托 checks.semantic_density。

【职责边界】
- 只负责：兼容 facade（委托 checker + 委托 checks 的静态方法）。
- 不负责：规则编译（ContractCompiler）、检查实现（checks）、门控（gate）、
  变异（mutator）、聚焦（focuser）、持久化（store）。
- 不重复实现 check 逻辑：所有 _check_* 都委托 checks，保持单一真相源。
- 不参与 L3 启用时的流程：L3 启用后被 RegistryEvalBridge 替换。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/eval/programmatic_bridge.py — ProgrammaticEvalBridge（兼容 facade）
│
├─ 模块级常量（向后兼容，转发 checks 同名常量）
│   ├─ _HARD_MODES            = checks.HARD_MODES
│   ├─ _DIRECTIVE_WORDS       = checks.DIRECTIVE_WORDS
│   ├─ _UNFOUNDED_WORDS       = checks.UNFOUNDED_WORDS
│   ├─ _CONCLUSION_WORDS      = checks.CONCLUSION_WORDS
│   ├─ _CITE_PATTERN          = checks.CITE_PATTERN
│   ├─ _YAML_FRONTMATTER      = checks.YAML_FRONTMATTER
│   ├─ _PARAGRAPH_LIMIT       = checks.PARAGRAPH_LIMIT
│   ├─ _SEMANTIC_DENSITY_MIN  = checks.SEMANTIC_DENSITY_MIN
│   └─ _SEMANTIC_DENSITY_MAX  = checks.SEMANTIC_DENSITY_MAX
│
└─ class ProgrammaticEvalBridge
    ├─ __init__()                                ← 构造 checker（Compiler + Checker）
    │
    ├─ evaluate(ctx) -> EvalResult               ← 【对外主入口】委托 checker.check
    │   ├─ candidate_content = _read_content(ctx.candidate)
    │   ├─ baseline_content  = _read_content(ctx.baseline) or ""
    │   └─ return self._checker.check(candidate, baseline)
    │
    └─ 静态方法（全部委托 checks，向后兼容 L2a 测试）
        ├─ _read_content(record) -> str           → checks.read_content
        ├─ _split_body(content) -> str            → checks.split_body
        ├─ _check_nonempty(content) -> bool       → checks.check_nonempty
        ├─ _check_json_parseable(content) -> bool → checks.check_json_parseable
        ├─ _check_must_cite(content) -> bool      → checks.check_must_cite
        ├─ _check_paragraph_limit(content) -> bool→ checks.check_paragraph_limit
        ├─ _check_lead_with_conclusion(content)   → checks.check_lead_with_conclusion
        ├─ _check_markdown_table(content) -> bool → 恒 True（L2a 兼容）
        ├─ _check_no_unfounded_claims(content)    → checks.check_no_unfounded_claims
        └─ _semantic_density(content) -> float    → checks.semantic_density
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap，二选一）
    L3 关闭 → EvolutionManager(eval_bridge=ProgrammaticEvalBridge())   ← 本模块
    L3 启用 → EvolutionManager(eval_bridge=RegistryEvalBridge(...))    ← 替换

② 进化闭环第三步 —— 评估
    EvolutionManager._run_evolution(ctx)
        ├─ …（focus → mutate）
        └─ eval_bridge.evaluate(EvalContext(baseline, candidate, ...))
              └─ ProgrammaticEvalBridge.evaluate(ctx)      ← 本模块主入口
                    ├─ _read_content(ctx.candidate)
                    ├─ _read_content(ctx.baseline)（无则 ""）
                    └─ self._checker.check(candidate, baseline)
                          └─ ResponseContractChecker
                                ├─ ContractCompiler.compile
                                └─ _run_rule → checks.check_*
              → 返回 EvalResult

③ 测试路径（L2a 兼容）
    test → ProgrammaticEvalBridge._check_nonempty(...) / _semantic_density(...)
        └─ 转发到 checks 模块同名函数
```

## 1. 补充

- **它的定位是"兼容 facade"**：不是 L3 的一部分，而是 L2 自带的评估 floor；L3 启用时被 `RegistryEvalBridge` 替换，但保留本类以兼容 L2a 测试。
- **单一真相源**：所有 `_check_*` 与 `_read_content` / `_split_body` / `_semantic_density` 都委托 `checks` 模块，本类不含检查逻辑。
- **`evaluate` 委托链**：`evaluate` → `ResponseContractChecker.check` → `ContractCompiler.compile` + `checks.*`；即本类只是入口包装。
- **`_check_markdown_table` 是唯一的例外**：它不委托 checks，恒返 True——因为并非所有 skill 需要表格（L2a 兼容）。
- **两桥替换关系**：
  - `ProgrammaticEvalBridge`（本模块）：L2 默认，L3 关闭时用。
  - `RegistryEvalBridge`（`eval/registry.py`）：L3 启用时注入替换。
  - 二者都实现 `EvalBridge` Protocol，`EvolutionManager` 不感知差异（D-L3-2）。
