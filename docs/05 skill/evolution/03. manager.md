---

name: EvolutionManager — 自进化闭环编排。

description: 

【整体职责】
evolution（L2 进化层）的编排门面。
把 trigger → focus → mutate → eval → gate → create_version/record 串成闭环，
并对外暴露三个入口：
- run_cycle   : 扫所有 trigger，跑一轮自进化（自动）。
- evolve_skill: 手动 FIX（/skill evolve）。
- capture_skill: 手动 CAPTURED（/skill capture）。

2a 为同步触发；asyncio 后台留到 2b（todo_docs/03 §3.8）。

【内容摘要】
- __init__(store, triggers, focuser, mutator, eval_bridge, gate, llm, journal)
      注入闭环各环节组件。
- run_cycle() -> list[EvolutionRecord]
      遍历 triggers，对每个 EvolutionContext 跑 _run_evolution；
      anti-loop：若有 mark_evolved 则调用。
- evolve_skill(skill_name) -> EvolutionRecord
      手动 FIX：取 active skill → 构造 EvolutionContext(METRIC/FIX) → 跑闭环。
- capture_skill(pattern, suggested_name) -> EvolutionRecord
      手动 CAPTURED：优先用 CaptureTrigger.manual_capture，否则自造上下文。
- _run_evolution(ctx) -> EvolutionRecord | None
      单次进化闭环：focus → mutate → eval → gate → create_version → record → journal。
- _emit_journal(ctx, decision, rec)
      发 journal 事件：skill.evolve / skill.captured / skill.evolve_rejected。

【职责边界】
- 只负责：编排闭环、调各 Protocol 实现、落库记录、发 journal。
- 不负责：触发逻辑（trigger）、聚焦逻辑（focuser）、变异逻辑（mutator）、
  评估逻辑（eval_bridge）、门控逻辑（gate）——它只调它们。
- 不做决策：accept / reject 由 gate 决定；本类只根据 decision 执行后续动作。
- 2a 只支持 FIX + CAPTURED（DERIVED 留 2b）。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/manager.py — EvolutionManager（自进化闭环编排）
│
└─ class EvolutionManager
    ├─ __init__(store, triggers, focuser, mutator,          ← 注入闭环各环节组件
    │           eval_bridge, gate, llm=None, journal=None)
    │
    ├─ run_cycle() -> list[EvolutionRecord]                 ← 【自动】扫所有 trigger 跑一轮
    │   ├─ for trigger in triggers:
    │   │     ├─ contexts = trigger.should_trigger(store)
    │   │     └─ for ctx in contexts:
    │   │           ├─ _run_evolution(ctx) → rec
    │   │           └─ anti-loop：trigger.mark_evolved(name, selections)
    │   └─ return records
    │
    ├─ evolve_skill(skill_name) -> EvolutionRecord          ← 【手动】FIX（/skill evolve）
    │   ├─ store.get_active(skill_name)（None → ValueError）
    │   ├─ 构造 EvolutionContext(METRIC, FIX, target_skill=rec)
    │   └─ _run_evolution(ctx)（None → RuntimeError）
    │
    ├─ capture_skill(pattern, suggested_name)               ← 【手动】CAPTURED（/skill capture）
    │   -> EvolutionRecord
    │   ├─ 找已注册的 CaptureTrigger → manual_capture(pattern, name)
    │   ├─ 未找到 → 自造 EvolutionContext(CAPTURE, CAPTURED)
    │   └─ _run_evolution(ctx)（None → RuntimeError）
    │
    ├─ _run_evolution(ctx) -> EvolutionRecord | None        ← 【核心】单次进化闭环
    │   ├─ 1. focus   ：ctx = focuser.focus(ctx, store)
    │   ├─ 2. mutate  ：candidate, diff = mutator.mutate(ctx, llm)
    │   ├─ 3. eval    ：构造 EvalContext → eval_bridge.evaluate(...) → EvalResult
    │   ├─ 4. gate    ：gate.decide(candidate, baseline, eval_result) → GateDecision
    │   ├─ 5. promote ：若 accept / accept_new_best → store.create_version(...)
    │   ├─ 6. record  ：构造 EvolutionRecord → store.record_evolution(rec)
    │   └─ 7. journal ：若 journal 非 None → _emit_journal(...)
    │
    └─ _emit_journal(ctx, decision, rec)                    ← 【事件】发 journal
        ├─ CAPTURED                → "skill.captured"
        ├─ accept / accept_new_best → "skill.evolve"
        └─ 其他                    → "skill.evolve_rejected"
```

### 0.2. 运行时调用树

```
① 装配期（bootstrap）
    EvolutionManager(store, triggers, focuser, mutator,
                     eval_bridge, gate, llm, journal)
        └─ SkillManager.set_evolution_manager(...)   ← 回注

② 自动触发（每轮或按周期）
    run_cycle()
        └─ for trigger in triggers:
              ├─ trigger.should_trigger(store) → contexts
              └─ for ctx in contexts:
                    _run_evolution(ctx)                       ← 单次闭环
                        ├─ focuser.focus(ctx, store)
                        ├─ mutator.mutate(ctx, llm)           → (candidate, diff)
                        ├─ store.get_metrics(baseline_id)     → metrics_baseline
                        ├─ eval_bridge.evaluate(EvalContext)  → EvalResult
                        ├─ gate.decide(candidate, baseline, eval_result) → GateDecision
                        ├─ store.create_version(...)          （若 accept）
                        ├─ store.record_evolution(EvolutionRecord) → skill_evolutions 表
                        └─ _emit_journal(...)                 → journal
                    trigger.mark_evolved(name, selections)    ← anti-loop

③ 手动 FIX（/skill evolve）
    evolve_skill(skill_name)
        ├─ store.get_active(skill_name)
        └─ _run_evolution(EvolutionContext(METRIC, FIX, target_skill=rec))

④ 手动 CAPTURED（/skill capture）
    capture_skill(pattern, suggested_name)
        ├─ CaptureTrigger.manual_capture(...) 或 自造 ctx
        └─ _run_evolution(ctx)
```

## 1. 补充

- **它是编排器，不是决策者**：`_run_evolution` 只按顺序调 focus / mutate / eval / gate；accept / reject 由 `gate` 决定。
- **两条落库路径**：
  - `store.create_version(...)` —— accept 时把新版本写进 version DAG。
  - `store.record_evolution(...)` —— 无论 accept / reject 都记实验（可审计）。
- **anti-loop 机制**：`run_cycle` 里对每个 trigger 调 `mark_evolved(name, selections)`，避免同一状态反复触发进化。
- **异常静默**：`get_metrics` / `create_version` / `record_evolution` / `_emit_journal` 的异常都 silent，不阻断闭环；手动入口（`evolve_skill` / `capture_skill`）在无记录时抛 `RuntimeError`。
- **2a 只支持 FIX + CAPTURED**：DERIVED 留 2b；asyncio 后台也留 2b。
