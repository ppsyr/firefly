name: Skill 自进化层 Protocol 抽象 — 2b/L3 零侵入预留。

description: 

【整体职责】
定义 evolution（L2 进化层）的 5 个 Protocol（接口契约），规定进化闭环各环节的职责：
- Trigger         : 何时触发进化（产 EvolutionContext 列表）。
- FailureFocuser  : 失败聚焦（增强 EvolutionContext）。
- Mutator         : 变异（产 candidate + diff）。
- EvalBridge      : eval 转接（产 EvalResult；L2 自带 ProgrammaticEvalBridge，L3 替换）。
- PromotionGate   : 门控（产 GateDecision）。

L2/L3 实现 = 实现这些 Protocol + 注入 EvolutionManager，不改动 2a 核心（零侵入）。

【内容摘要】
- Trigger(Protocol)        : should_trigger(store) -> list[EvolutionContext]。
- FailureFocuser(Protocol) : focus(ctx, store) -> EvolutionContext。
- Mutator(Protocol)        : mutate(ctx, llm) -> (SkillRecord, str)。
- EvalBridge(Protocol)     : evaluate(ctx) -> EvalResult。
- PromotionGate(Protocol)  : decide(candidate, baseline, eval_result) -> GateDecision。

【职责边界】
- 只定义接口（Protocol），不含实现。
- 不负责：触发 / 聚焦 / 变异 / 评估 / 门控的具体逻辑（在 triggers / focus /
  mutators / registry / gates 的实现里）。
- 不 runtime import 实现类：实现由 bootstrap 注入。
- 全部 runtime_checkable：支持 isinstance 检查（便于 bootstrap 装配校验）。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/protocols.py — Skill 自进化层 Protocol 抽象（5 个接口契约）
│
├─ class Trigger(Protocol, runtime_checkable)          ← 【触发】何时触发进化
│   └─ should_trigger(store) -> list[EvolutionContext] ← 读 metrics/状态，产上下文列表
│
├─ class FailureFocuser(Protocol, runtime_checkable)   ← 【聚焦】失败聚焦 + 修复方向
│   └─ focus(ctx, store) -> EvolutionContext           ← 输入 raw，输出增强后
│
├─ class Mutator(Protocol, runtime_checkable)          ← 【变异】产 candidate + diff
│   └─ mutate(ctx, llm) -> tuple[SkillRecord, str]     ← candidate is_active=False
│
├─ class EvalBridge(Protocol, runtime_checkable)       ← 【评估转接】L2 ↔ L3
│   └─ evaluate(ctx: EvalContext) -> EvalResult        ← L2 floor / L3 替换
│
└─ class PromotionGate(Protocol, runtime_checkable)    ← 【门控】晋升决策
    └─ decide(candidate, baseline, eval_result) -> GateDecision
                                                        ← accept / reject / pending_human
```

---

### 0.2. 运行时调用树（Protocol 在进化闭环中的位置）

```
① 触发（Trigger）
    EvolutionManager
        └─ trigger.should_trigger(store)
              └─ 返回 list[EvolutionContext]（一次可多个）

② 聚焦（FailureFocuser）
    EvolutionManager
        └─ focuser.focus(ctx, store)
              └─ 返回增强后的 EvolutionContext
                    （补 failure_evidence / fix_direction）

③ 变异（Mutator）
    EvolutionManager
        └─ mutator.mutate(ctx, llm)
              └─ 返回 (candidate: SkillRecord, mutation_diff: str)

④ 评估（EvalBridge）
    EvolutionManager
        └─ bridge.evaluate(EvalContext(baseline, candidate, ...))
              ├─ L2 默认：ProgrammaticEvalBridge（floor）
              └─ L3 替换：RegistryEvalBridge
              → 返回 EvalResult

⑤ 门控（PromotionGate）
    EvolutionManager
        └─ gate.decide(candidate, baseline, eval_result)
              └─ 返回 GateDecision（accept_new_best / accept / reject / pending_human）

⑥ 落库（EvolutionManager 调 store）
    ├─ store.record_evolution(EvolutionRecord)   → skill_evolutions 表
    └─ store.create_version(...)                 → 新版本进 version DAG（accept 时）
```

## 1. 补充

- **5 个 Protocol 就是进化闭环的 5 个环节**：触发 → 聚焦 → 变异 → 评估 → 门控；`EvolutionManager` 按顺序编排它们。
- **EvalBridge 是唯一的跨层接口**：L2 自带 `ProgrammaticEvalBridge` 作 floor，L3 可替换为 `RegistryEvalBridge`，L2 核心零改动。
- **零侵入预留**：Protocol 先行定义，实现可后续替换（2b/L3 加 impl 时不动 2a 核心）。
- **Trigger 返回列表**：一次可触发多个 skill 的进化；`EvolutionManager` 对每个 context 独立走后续流程。
