---

name: GitRatchet — 上线后兜底回滚（借鉴 darwin git ratchet）。

description: 

【整体职责】
evolution 的"上线后监控"机制（非决策门）。
candidate 已 accept 上线后，若 metric 退化（新版 effective_rate 跌破阈值），
调 store.rollback() 切 is_active 指针回旧版。

类比 git revert（禁 reset --hard，保留历史）；
version DAG 天然支持：旧 node 仍在，只切指针。

【内容摘要】
- __init__(degradation_threshold, min_selections, runtime_tracker)
      保存退化阈值、最少 selections、可选的 RuntimeTracker 信号。
- check_and_rollback(store, current) -> str | None
      检查当前 active 是否退化，是则回滚；返回滚到的旧 skill_id 或 None。

【职责边界】
- 只负责：上线后监控 + 退化判定 + 触发 rollback。
- 不负责：晋升决策（ScoreDeltaGate 等门）、评估（eval_bridge）、变异（mutator）、
  聚焦（focuser）、触发（trigger）、编排（EvolutionManager）。
- 不删除历史：rollback 只切 is_active 指针，旧 node 保留（version DAG 可回溯）。
- 不由门控调用：由 EvolutionManager 周期调（与 PromotionGate 解耦）。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/gates/git_ratchet.py — GitRatchet（上线后兜底回滚）
│
└─ class GitRatchet
    ├─ __init__(degradation_threshold=0.3, min_selections=5, runtime_tracker=None)
    │   ├─ self._threshold          ← effective_rate 退化阈值
    │   ├─ self._min_selections     ← 评判前需积累的 selections（anti-loop）
    │   └─ self._runtime_tracker    ← 可选 RuntimeTracker（D-L3-16 退化信号）
    │
    └─ check_and_rollback(store, current) -> str | None      ← 【对外主入口】
        ├─ 1. D-L3-16：runtime_tracker 非 None → degraded_skills()（软信号）
        │        └─ 异常 silent
        ├─ 2. anti-loop：total_selections < min_selections → 返 None
        ├─ 3. 健康：effective_rate >= threshold → 返 None
        ├─ 4. 退化 → 找回滚目标：
        │        ├─ a. versions 中 skill_id ∈ parent_skill_ids 的版本
        │        └─ b. 无 parent → generation 最低的非当前版
        ├─ 5. 未找到 → 返 None
        └─ 6. store.rollback(target.skill_id)；返 target.skill_id
```

---

### 0.2. 运行时调用树

```
① 装配期（bootstrap）
    GitRatchet(degradation_threshold, min_selections, runtime_tracker)
        └─ 注入 EvolutionManager（或独立的周期任务）

② 上线后周期检查（由 EvolutionManager 或独立调度触发）
    GitRatchet.check_and_rollback(store, current)     ← 本模块主入口
        ├─ runtime_tracker.degraded_skills()          ← D-L3-16 软信号（可选）
        ├─ anti-loop：selections < min → None
        ├─ effective_rate >= threshold → None（健康）
        ├─ store.get_versions(current.name)
        │     ├─ 优先 parent_skill_ids
        │     └─ 兜底 generation 最低
        └─ store.rollback(target.skill_id)            ← 切 is_active 指针
              └─ version DAG 保留旧 node，仅切换 active

③ 与门控的区别
    ScoreDeltaGate       ：晋升前决策（accept / reject）
    GitRatchet           ：上线后退化兜底（rollback）
    两者解耦，不在同一环节
```

## 1. 补充

- **非决策门**：它不参与 accept / reject，而是在 candidate 已上线后做"事后监控"。与 `PromotionGate`（`ScoreDeltaGate`）是两回事。
- **anti-loop**：`total_selections < min_selections` 时不评判——新版本需要积累数据才能公平判断是否退化。
- **回滚目标选择策略**（两级兜底）：
  1. 优先找 `lineage.parent_skill_ids` 里的版本（血缘上的直接父节点）。
  2. 无 parent 时取 `generation` 最低的非当前版（回到最早版本）。
  3. 都无 → 不 rollback。
- **只切指针不删行**：`store.rollback` 只把 `is_active` 从当前版本切到旧版本；旧 node 仍在 version DAG 里，可随时再切回（类比 git revert，禁 reset --hard）。
- **D-L3-16 软信号**：`runtime_tracker.degraded_skills()` 提供额外退化信号，但当前逻辑是"软"的——即使它没标退化，仍会用 `effective_rate` 兜底检查；异常则静默跳过。
- **调用方**：`EvolutionManager` 周期调（`check_and_rollback`），不由 `_run_evolution` 调用——它是独立的上线后监控，不是闭环的一环。
