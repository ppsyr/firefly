---

name: MetricMonitorTrigger — 周期 metric 扫描触发（借鉴 OpenSpace Trigger 3）。

description: 

【整体职责】
METRIC 类进化的触发器：周期扫描 active skills 的 metrics，
诊断出"需要 FIX 的 skill"，产出 EvolutionContext 列表。

两阶段筛选：
- Phase 1 规则（_diagnose_skill_health，阈值宽松）：
    fallback_rate > 0.4                          → FIX（常选不用，指令不清）
    applied_rate > 0.4 且 completion_rate < 0.35 → FIX（用了没完成，指令错）
    effective_rate < 0.55 且 applied_rate > 0.25 → DERIVED（中等效果，2b）
- Phase 2 LLM 确认（llm 非 None 时调，过滤误报；None 跳过）

anti-loop：
- min_selections：total_selections < min 不触发（新进化 skill selections=0）。
- cooldown：自上次进化后需 cooldown_turns 次新 selections 才重评
  （数据驱动，无时间计数）。

【内容摘要】
模块常量（阈值，借鉴 OpenSpace，宽松——LLM 确认过滤误报）：
- _FALLBACK_THRESHOLD          = 0.4
- _LOW_COMPLETION_THRESHOLD    = 0.35
- _HIGH_APPLIED_FOR_FIX        = 0.4
- _MODERATE_EFFECTIVE_THRESHOLD = 0.55
- _MIN_APPLIED_FOR_DERIVED     = 0.25

类方法：
- __init__(threshold, min_selections, cooldown_turns, llm)
- should_trigger(store) -> list[EvolutionContext]         : 扫 active skills，产 FIX 上下文。
- mark_evolved(skill_name, total_selections)              : 记 anti-loop 锚点。
- _diagnose_skill_health(record) -> (type | None, direction) : 规则诊断（Phase 1）。
- _llm_confirm_evolution(record, direction) -> bool       : LLM 确认（Phase 2）。

【职责边界】
- 只负责：扫 metrics + 规则诊断 + LLM 确认 + 产 EvolutionContext。
- 不负责：聚焦（focuser）、变异（mutator）、评估（eval_bridge）、门控（gate）、
  持久化（store）、编排（EvolutionManager）。
- 2a 只产 FIX；DERIVED 留 2b。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/triggers/metric_monitor.py — MetricMonitorTrigger（周期 metric 扫描）
│
├─ 模块常量（阈值，宽松——LLM 确认过滤误报）
│   ├─ _FALLBACK_THRESHOLD           = 0.4    ← 高 fallback 触发 FIX
│   ├─ _LOW_COMPLETION_THRESHOLD     = 0.35   ← 低 completion 判定
│   ├─ _HIGH_APPLIED_FOR_FIX         = 0.4    ← 高 applied 判定（配合低 completion）
│   ├─ _MODERATE_EFFECTIVE_THRESHOLD = 0.55   ← 中等 effective（DERIVED）
│   └─ _MIN_APPLIED_FOR_DERIVED      = 0.25   ← DERIVED 最低 applied
│
└─ class MetricMonitorTrigger
    ├─ __init__(threshold=0.3, min_selections=5,      ← 保存阈值 + llm + anti-loop 锚点表
    │           cooldown_turns=10, llm=None)
    │   └─ self._last_evolve_selections: dict[str, int]  ← skill_name → 上次进化的 selections
    │
    ├─ should_trigger(store) -> list[EvolutionContext]   ← 【对外主入口】
    │   ├─ for rec in store.list_active():
    │   │     ├─ 跳过 not rec.enabled
    │   │     ├─ anti-loop：selections < min → 跳过
    │   │     ├─ anti-loop：selections - last < cooldown → 跳过
    │   │     ├─ Phase 1：_diagnose_skill_health(rec) → (evo_type, direction)
    │   │     │     ├─ None → 跳过
    │   │     │     └─ 非 "FIX" → 跳过（DERIVED 留 2b）
    │   │     ├─ Phase 2：llm 非 None → _llm_confirm_evolution(rec, direction)
    │   │     │     └─ False → 跳过
    │   │     └─ 收集 EvolutionContext(METRIC, FIX, target_skill, fix_direction)
    │   └─ return results
    │
    ├─ mark_evolved(skill_name, total_selections)        ← 【anti-loop 锚点】进化完成时调
    │   └─ self._last_evolve_selections[skill_name] = total_selections
    │
    ├─ _diagnose_skill_health(record) -> (type | None, direction)  ← 【Phase 1】规则诊断
    │   ├─ fallback_rate > 0.4                              → ("FIX", …)
    │   ├─ applied_rate > 0.4 且 completion_rate < 0.35     → ("FIX", …)
    │   ├─ effective_rate < 0.55 且 applied_rate > 0.25     → ("DERIVED", …)
    │   └─ 否则                                             → (None, "")
    │
    └─ _llm_confirm_evolution(record, direction) -> bool  ← 【Phase 2】LLM 确认
        ├─ 构造 prompt（name / description / direction / metrics）
        ├─ llm.invoke([HumanMessage])
        ├─ "yes" in content.lower() → True
        └─ 异常 → False（保守不触发）
```

### 0.2. 运行时调用树

```
① 周期触发（EvolutionManager.run_cycle）
    for trigger in triggers:
        └─ trigger.should_trigger(store)             ← 本模块主入口
              ├─ for rec in store.list_active():
              │     ├─ enabled 检查
              │     ├─ anti-loop：min_selections
              │     ├─ anti-loop：cooldown（_last_evolve_selections）
              │     ├─ _diagnose_skill_health（Phase 1）
              │     ├─ _llm_confirm_evolution（Phase 2，llm 非 None）
              │     └─ EvolutionContext(METRIC, FIX, ...)
              └─ return contexts
        └─ for ctx in contexts:
              EvolutionManager._run_evolution(ctx)
                    └─ …（focus → mutate → eval → gate → record）
        └─ trigger.mark_evolved(name, selections)    ← anti-loop 锚点更新

② 手动 FIX（/skill evolve）
    EvolutionManager.evolve_skill(skill_name)
        └─ 绕过 should_trigger，直接构造 EvolutionContext(METRIC, FIX)
              （不经本模块的规则诊断 / LLM 确认）
```

## 1. 补充

- **两阶段设计**：Phase 1 规则宽松（避免漏报），Phase 2 LLM 确认（过滤误报）；`llm=None` 时退化为纯规则。
- **anti-loop 双保险**：
  - `min_selections`：新进化 skill（selections=0）不会被立刻再触发。
  - `cooldown_turns`：数据驱动（按新增 selections 数），不是时间驱动。
- **2a 只产 FIX**：`DERIVED` 在 Phase 1 会被诊断出来，但被显式过滤掉（`evo_type != "FIX"` → continue）；DERIVED 留 2b。
- **`mark_evolved` 由 manager 调用**：本模块不自己更新锚点，`run_cycle` 在每轮进化后调它。
- **LLM 失败保守**：`_llm_confirm_evolution` 异常返 False → 不触发进化（宁可漏，不可误）。
