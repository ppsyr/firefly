---

name: SkillSelector — quality filter + LLM select。混合注入的 agent 自动选半。

description: 

【整体职责】
skill 读路径的决策核心。
从 store 的 active skills 里，选出本轮最多 max_skills 个技能，
供 SkillInjectionMiddleware 注入。选择策略：
    override 强制包含 → quality filter 淘汰 → 候选裁剪（全返 / LLM / 排序 fallback）。

【内容摘要】
- SkillSelector               : 选择器主类。
    - __init__(store, llm, max_skills, quality_threshold, min_selections)
    - select_for_task(task, overrides) : 对外主入口，返回选中 list[SkillRecord]。
    - _quality_filter(skills)          : 淘汰低质技能（新技能豁免）。
    - _llm_select(candidates, task, max): 让 LLM 从候选中挑 ≤ max。
    - _build_catalog(candidates)       : 构造喂给 LLM 的候选目录文本。
    - _extract_json(text)              : 从可能带 markdown fence 的文本里提取 JSON。

【职责边界】
- 只负责：候选收集、quality 过滤、候选裁剪（全返 / LLM / 排序 fallback）、去重。
- 不负责：持久化（store）、注入渲染（injector）、打点（metrics）、解析（parser）。
- 不写 store：只读（get_active / list_active）；选择结果的打点由 middleware 完成。
- LLM 只用于"从候选中挑 ≤ max"；候选数 ≤ max 时跳过 LLM。

## 0. 结构树

### 0.1. 静态结构树（模块 → 类 → 方法）

```
selector.py — SkillSelector（quality filter + LLM select）
│
└─ class SkillSelector
    ├─ __init__(store, llm, max_skills, quality_threshold, min_selections)
    │   ├─ self._store              ← 技能存储（get_active / list_active）
    │   ├─ self._llm                ← LLM（None 时跳过 LLM 选择）
    │   ├─ self._max_skills         ← 单轮最多选中数
    │   ├─ self._quality_threshold  ← 淘汰阈值
    │   └─ self._min_selections     ← 淘汰判定最少 selections（anti-loop）
    │
    ├─ select_for_task(task_description, overrides) -> list[SkillRecord]   ← 对外主入口
    │   ├─ store is None → return []
    │   ├─ 1. override 强制包含
    │   │     └─ for name in overrides: store.get_active(name) → enabled → forced
    │   ├─ 2. active enabled + quality filter
    │   │     ├─ active = [r for r in store.list_active() if r.enabled]
    │   │     └─ filtered = _quality_filter(active)
    │   ├─ 3. dedup combine（override 优先）
    │   ├─ 4. len(candidates) <= max → 全返（跳过 LLM）
    │   ├─ 5. len > max 且 llm → _llm_select；成功则 return
    │   └─ 6. fallback → sorted by effective_rate desc → top max
    │
    ├─ _quality_filter(skills) -> list[SkillRecord]
    │   └─ 保留条件：NOT (selections >= min AND effective_rate < threshold)
    │
    ├─ _llm_select(candidates, task, max_skills) -> list[SkillRecord]
    │   ├─ catalog = _build_catalog(candidates)
    │   ├─ prompt = 任务 + catalog + "选 ≤ max，只返 JSON"
    │   ├─ resp = llm.invoke([HumanMessage], config={"tags": ["internal_llm"]})
    │   ├─ content → _extract_json → json.loads
    │   ├─ ids → id_to_rec 映射 → selected[:max]
    │   └─ 异常 → logger.warning + return []
    │
    ├─ _build_catalog(candidates) -> str
    │   └─ 每行： "- {skill_id}: {description} (成功率 {rate})"
    │         rate = f"{effective_rate:.0%}" 或 "n/a"（无 selections 时）
    │
    └─ _extract_json(text) -> str   （@staticmethod）
        └─ 取首个 '{' 到末个 '}' 之间的子串；找不到则原样返回
```

（其余 hook 与本模块无关）

## 1. 这个模块在 skill 中起什么作用

一句话：**`selector.py` 是 skill 读路径的决策核心——决定本轮到底把哪些技能注入上下文。**

### 1.1. 在数据流中的位置

```
store ── selector ── 选中 skills ── injector ── markdown ── 注入上下文
            ▲
        你在这里
```

- **上游**：`store`（`get_active` / `list_active`）。
- **本模块**：筛选 + 裁剪，产出 `list[SkillRecord]`。
- **下游**：`injector` 渲染 → `SkillInjectionMiddleware` 注入。

它是 store 与 injector 之间的"过滤器 + 调度器"。

### 1.2. 具体承担四件事

| 职责 | 说明 |
|------|------|
| **override 强制包含** | 用户 `/skill` 显式指定的技能无条件进入候选（不受 quality filter 影响）。 |
| **quality filter** | 淘汰"数据足够且有效率低"的技能；新技能豁免（anti-loop）。 |
| **候选裁剪** | 三条路径：≤ max 全返 / > max 走 LLM / 无 LLM 走 rate 排序 fallback。 |
| **去重合并** | 同一 `skill_id` 只出现一次，override 优先。 |

### 1.3. 三个关键设计点

1. **LLM 只在"候选超限"时启用**
   - 候选 ≤ `max_skills` → 直接全返，**不调 LLM**（省成本、省延迟）。
   - 候选 > max 时才让 LLM 做相关性裁剪；LLM 失败还有 rate 排序兜底。
   - 这正是"混合注入"里"agent 自动选半"的含义。

2. **quality filter 的 anti-loop**
   - 淘汰条件：`total_selections >= min_selections AND effective_rate < quality_threshold`。
   - `selections < min` 的新技能**不淘汰**——给它积累数据的机会，避免"无数据 → 淘汰 → 永远无数据"的死循环。

3. **多级降级不空转**
   - LLM 失败 → rate 排序 fallback。
   - 无 LLM → 直接 rate 排序。
   - store 为 None → 返空。
   - 任何一层失败都有下一层兜底。

### 1.4. 和其他模块的关系

| 模块 | 与 selector 的关系 |
|------|-------------------|
| `store.py` | **上游**：`get_active` / `list_active`。 |
| `types.py` | **依赖**：`SkillRecord`（用 `effective_rate` / `total_selections` / `enabled` / `skill_id`）。 |
| `injector.py` | **下游**：接收 selector 的 `list[SkillRecord]`。 |
| `middlewares/skill_injection_middleware.py` | **调用方**：在 `before_model` 调 `select_for_task`。 |
| `config.py` | **参数来源**：`max_inject` / `quality_threshold` / `min_selections`。 |
| `__init__.py` | **装配**：`load_startup` 用 config 参数构造 selector。 |
| `store.get_metrics` / `get_top_skills` / `health_check` | 同源数据：selector 用 record 的 rate；这些方法也用同一批计数器。 |

### 1.5. 总结

**`selector.py` = skill 读路径的决策核心。**
它从 store 取候选 → override 强制 + quality filter + 去重 → 按"全返 / LLM / rate 排序"三级裁剪 → 输出本轮要注入的技能列表，交给 injector 渲染。
