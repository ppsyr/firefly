---

name: IVEFocuser — IVE 5 问失败聚焦（借鉴 EvoSkills IVE）。

description: 

【整体职责】
evolution 闭环的第二环：聚焦失败证据，诊断出失败性质（fundamental / implementation）
与修复方向，增强 EvolutionContext 供 Mutator 消费。

IVE 5 问诊断区分 fundamental（skill 方向错）vs implementation（执行偏差）：
1. 失败发生在 skill 哪一步？
2. 是 skill 指令本身错（fundamental）还是执行偏差（implementation）？
3. 若 implementation，是工具调用失败 / 上下文不足 / 模型理解偏差？
4. 失败是否可经微调 skill 文本修复？
5. 修复方向是什么（不直接改，给 Mutator 输入）？

升级规则：implementation 累计 impl_fail_threshold 次（默认 3）升级 fundamental
（防保守分类导致无限重试，借鉴 EvoSkills）。

降级：LLM=None 时退化为全量摘要（不崩，弱但可用）。

【内容摘要】
- __init__(llm, impl_fail_threshold)                    : 保存依赖 + implementation 计数表。
- focus(ctx, store) -> EvolutionContext                 : 对外主入口。
- _degrade_focus(ctx, judgment_notes) -> EvolutionContext : LLM=None 降级路径。
- _read_judgment_notes(ctx, store) -> list[str]         : 读 SkillJudgment 历史补充证据。
- _llm_diagnose(ctx, skill_name, judgment_notes)       : LLM 5 问诊断。
    -> tuple[FailureClass, str]

【职责边界】
- 只负责：诊断失败性质 + 产 fix_direction + 增强 ctx.failure_evidence。
- 不负责：触发（triggers）、变异（mutator）、评估（eval_bridge）、门控（gate）、
  持久化（store 只读）、编排（EvolutionManager）。
- 不直接改 skill：只给 Mutator 输入（fix_direction）。

## 0. 结构树

### 0.1. 静态结构树

```
skill/evolution/focus/ive_focuser.py — IVEFocuser（IVE 5 问失败聚焦）
│
└─ class IVEFocuser
    ├─ __init__(llm=None, impl_fail_threshold=3)         ← 保存依赖 + 计数表
    │   └─ self._impl_fail_counts: dict[str, int]        ← skill_name → implementation 累计
    │
    ├─ focus(ctx, store) -> EvolutionContext             ← 【对外主入口】
    │   ├─ ctx.failure_evidence 为空（CAPTURED）→ 原样返回
    │   ├─ _read_judgment_notes(ctx, store)              ← 读 judgments 补充证据
    │   ├─ llm is None → _degrade_focus(ctx, notes)      ← 降级路径
    │   ├─ _llm_diagnose(ctx, skill_name, notes)         ← LLM 5 问诊断
    │   │     → (failure_class, fix_direction)
    │   ├─ IMPLEMENTATION → 计数 +1；达阈值 → 升级 FUNDAMENTAL + 提示
    │   ├─ FUNDAMENTAL → 重置计数
    │   └─ replace(ctx, failure_evidence=..., fix_direction=...)  ← frozen，返新对象
    │
    ├─ _degrade_focus(ctx, judgment_notes)               ← 【降级】LLM=None 路径
    │   -> EvolutionContext
    │   └─ fix_direction = "失败证据：... | SkillJudgment 偏差：..."
    │
    ├─ _read_judgment_notes(ctx, store) -> list[str]     ← 【读历史】D-L3-20
    │   ├─ store None / target_skill None → []
    │   └─ store.get_judgments(skill_id, limit=10) → deviation_note 列表
    │
    └─ _llm_diagnose(ctx, skill_name, judgment_notes)    ← 【LLM 诊断】5 问
        -> tuple[FailureClass, str]
        ├─ 构造 prompt（skill 描述 + 失败证据 + judgment 偏差 + 5 问）
        ├─ llm.invoke([HumanMessage])
        ├─ 提取 JSON → class / direction（非法 class → IMPLEMENTATION）
        └─ 异常 → ("IMPLEMENTATION", "")
```

```

    IVEFocuser(llm=llm, impl_fail_threshold=3)

              └─ replace(ctx, ...) → 增强后的 EvolutionContext
                    └─ 交给 mutator.mutate(ctx, llm)
```

## 1. 补充

- **它是 evolution 的第二环**：trigger 产 raw ctx → focuser 增强 ctx（补 failure_class + fix_direction）→ mutator 消费。
- **升级机制**：`_impl_fail_counts` 跨调用持久；implementation 累计达阈值升级 fundamental，fundamental 触发后重置计数（防保守分类导致无限重试）。
- **两条降级路径**：
  - `ctx.failure_evidence` 为空（CAPTURED）→ 原样返回，不做诊断。
  - `llm=None` → `_degrade_focus` 拼全量摘要，不修改 failure_class。
- **LLM 失败保守**：`_llm_diagnose` 异常或 JSON 缺失都返 `IMPLEMENTATION`——不轻易判 fundamental 杀掉 skill。
- **frozen 更新用 `replace`**：不修改原 ctx，返回新对象（符合 types.py 的 frozen 约束）。
- **D-L3-20**：读 store 的 `SkillJudgment` 历史作为失败证据补充，把 L3 eval 的产出反哺进 L2 聚焦。
