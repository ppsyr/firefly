---

name: 熔断器 — per-tool 健康状态机。

desvription: 

【
整体职责】
为每个工具维护一个健康状态机（closed / open / half_open），根据连续失败次数
和冷却时间决定是否放行调用，避免对持续失败的工具反复重试。

【内容摘要】
- _CIRCUIT_BREAKER_THRESHOLD / _CIRCUIT_BREAKER_COOLDOWN_SEC : 熔断阈值与冷却时长。
- CircuitBreaker.allow_call    : 是否放行本次调用（含状态转换）。
- CircuitBreaker.record_success: 记录成功（归零 + closed）。
- CircuitBreaker.record_failure: 记录失败（计数 + 触发 open / 重置 open）。

【职责边界】
- 只负责：维护单个工具的健康状态机、判定是否放行、记录成败。
- 不负责：工具的实际调用（handler）、审计与日志（McpAuditMiddleware）、
  熔断器实例的管理与查找（mcp/registry）。

## 0. 结构树

### 0.1. 静态结构树

```
circuit_breaker.py — 熔断器（per-tool 健康状态机）
│
├─ 模块级常量
│   ├─ _CIRCUIT_BREAKER_THRESHOLD = 3         ← 连续失败阈值（3 次 → open）
│   └─ _CIRCUIT_BREAKER_COOLDOWN_SEC = 60.0   ← open 后冷却（60s → half_open）
│
└─ CircuitBreaker                             ← 每工具一个实例，被动触发
    ├─ __slots__ = (failure_count, state, opened_at, _lock) ← 限制字段（省内存）
    │
    ├─ __init__()                             ← 初始化
    │   ├─ failure_count: int = 0             ← 连续失败次数
    │   ├─ state: str = "closed"              ← 当前状态
    │   ├─ opened_at: float = 0.0             ← 进入 open 的时间戳
    │   └─ _lock: threading.Lock              ← 状态转换锁
    │
    ├─ allow_call() -> bool                   ← 【判定 + 状态转换】
    │   ├─ closed → True
    │   ├─ open 且 cooldown 未过 → False
    │   ├─ open 且 cooldown 过 → 转 half_open → True
    │   └─ half_open → 放探针 → True
    │
    ├─ record_success() -> None               ← 【成功归零】
    │   ├─ failure_count = 0
    │   └─ state = "closed"
    │
    └─ record_failure() -> None               ← 【失败计数 + 触发 open】
        ├─ failure_count += 1
        ├─ half_open 失败 → state = "open" + opened_at = now
        └─ closed 且 count ≥ 3 → state = "open" + opened_at = now
```

### 0.3. 运行时调用树

```
① 装配（registry 构造时）
ToolRegistry
    └─ 每个工具创建一个 CircuitBreaker 实例
        └─ breaker = CircuitBreaker()

② 工具调用前（McpAuditMiddleware.awrap_tool_call）
McpAuditMiddleware
    ├─ entry = registry.get(tool_name)
    ├─ entry.breaker.allow_call()
    │     ├─ True  → 继续调用 handler
    │     └─ False → 返回 error ToolMessage + 记 "circuit_open"
    │
    ▼
③ 工具调用后
McpAuditMiddleware
    ├─ 成功 → entry.breaker.record_success() + 记 "ok"
    └─ 失败 → entry.breaker.record_failure() + 记 "error"
                 └─ sanitize_error（凭证脱敏）后 re-raise

④ 状态转换（allow_call 内部）
allow_call()
    ├─ closed → True
    ├─ open:
    │     ├─ now - opened_at >= 60s → state = "half_open" → True
    │     └─ 否则 → False
    └─ half_open → True
```

### 0.4. 补充

**`circuit_breaker.py` 是每个工具的"健康状态机"——用三个状态（closed / open / half_open）+ 连续失败计数 + 冷却时间，决定是否放行对某工具的调用。**

几条主线：

- **三态状态机**：`closed`（正常）→ `open`（熔断）→ `half_open`（探针）→ `closed`（恢复）/ `open`（再熔断）。
- **被动触发**：不主动 ping 工具健康——只在**实际调用**时由成败驱动状态转换（`allow_call` 判定 + `record_success/failure` 更新）。
- **两条转换规则**：
  - **打开**：`closed` 下连续失败 ≥ 3 → `open`；
  - **恢复**：`open` 冷却 60s 后 → `half_open`（放 1 次探针）；探针成功 → `closed`，失败 → 重置 `open`。
- **探针机制**：`half_open` 只放**一次**尝试（`allow_call` 返 True），避免一恢复就放全量流量。
- **线程安全**：`_lock` 保护状态转换——`allow_call` / `record_*` 均加锁。
- **内存优化**：`__slots__` 限制实例字段（每工具一个实例，量大时省内存）。
- **冷却是时间驱动**：`opened_at` 记录进入 `open` 的时间，`allow_call` 用 `time.time() - opened_at >= 60s` 判定是否可转 `half_open`——**恢复不需要外部触发，调用时自然判定**。
- **与 McpAuditMiddleware 的分工**：`McpAuditMiddleware` 是"调用者"（调 `allow_call` / `record_*` + 审计）；本文件是"状态机"（只管状态，不管日志）——**职责分离**。
- **命名与位置**：文件在 `mcp/` 下（`mcp/guards/` 或 `mcp/` 同级），但**机制通用**——任何需要"熔断"的工具都可复用它（不限于 MCP 工具）。
