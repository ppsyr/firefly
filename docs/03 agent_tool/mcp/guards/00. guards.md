---

name: MCP 安全层 — Protocol 基类 + 3 内置 guard。

desvription: 

【整体职责】
MCP 子系统的安全层出口：定义统一的 SecurityGuard 契约（3 接口），并提供 3 个
内置 guard 实现——分别负责 env 白名单过滤、凭证脱敏、描述扫描，由 loader 按顺序装载。

【内容摘要】
- SecurityGuard      : 安全检查 Protocol 基类（check_env / sanitize_error / scan_description）。
- EnvFilter          : env 白名单过滤（防宿主 secrets 泄露给 stdio 子进程）。
- CredentialSanitizer: 凭证脱敏（错误信息回 LLM 前清洗）。
- DescriptionScanner : 描述扫描（注册时检测 prompt injection）。

【职责边界】
- 只负责：定义安全契约、提供内置 guard 实现。
- 不负责：guard 的装载与调用（loader）、guard 的应用顺序编排（loader）、
  具体检查的调用时机（loader 的 _connect_server / _register_tools）。

### 0.7. 补充

**`guards/` 是 MCP 的安全层——1 个 `SecurityGuard` 契约（3 接口）+ 3 个内置 guard，分别覆盖 MCP 生命周期的三个安全节点：连接前、注册前、出错时。**

几条主线：

- **契约 1 个，实现 3 个**：`SecurityGuard` Protocol（`check_env` / `sanitize_error` / `scan_description`）+ `EnvFilter` / `CredentialSanitizer` / `DescriptionScanner`。
- **一 guard 一接口**：每个 guard 只实现关心的接口，其余 no-op——这是"可组合、可扩展"的关键。**不是"一个 guard 全实现"，而是"各管一段"**。
- **三节点覆盖**：
  - **连接前** → `EnvFilter.check_env`（防 secrets 泄漏给 stdio 子进程）；
  - **注册前** → `DescriptionScanner.scan_description`（防 prompt injection）；
  - **出错时** → `CredentialSanitizer.sanitize_error`（防密钥泄漏到 LLM / 日志）。
- **两类装载方式**：
  - `EnvFilter` / `DescriptionScanner` → `loader._guards` 列表（默认装载）；
  - `CredentialSanitizer` → `loader._sanitizer` 单独持有，暴露给 `McpAuditMiddleware`。
- **Protocol + runtime_checkable**：实现方无需继承；loader 用 `isinstance(g, EnvFilter)` 按类型取 guard。
- **fail-closed 原则**：`EnvFilter` 不在白名单的一律不传；`DescriptionScanner` 命中可疑即拒绝注册。
- **可扩展点**：新增安全检查只需实现 `SecurityGuard` Protocol，加入 loader 的 `guards` 列表——`loader` / `McpManager` 无需改动。
- **与 McpAuditMiddleware 的衔接**：`CredentialSanitizer` 不在 loader 默认 guards 里，而是通过 `loader.sanitizer` 传给 `McpAuditMiddleware`——因为**脱敏发生在工具调用时，而不是加载时**。

## 3. 契约：`SecurityGuard` Protocol（3 个接口）

```python
@runtime_checkable
class SecurityGuard(Protocol):
    def check_env(self, env) -> dict          # 过滤环境变量
    def sanitize_error(self, error_text) -> str  # 脱敏错误信息
    def scan_description(self, tool_name, description) -> bool  # 扫描描述
```

**关键设计**：**一个契约三个接口，各实现只关心自己那一个**——无关接口返原值（no-op）。

| 接口 | 语义 | 返回约定 |
|---|---|---|
| `check_env` | 过滤环境变量 | 返过滤后的 env dict |
| `sanitize_error` | 脱敏错误信息 | 返脱敏后的字符串 |
| `scan_description` | 扫描工具描述 | 返 **True=拒绝注册**，False=放行 |

**为什么用 Protocol 而不是 ABC**：
- 实现方**无需显式继承**——靠方法签名匹配（鸭子类型）；
- `@runtime_checkable` 允许 `isinstance(g, SecurityGuard)` 检查；
- loader 通过 `isinstance(g, EnvFilter)` / `isinstance(g, DescriptionScanner)` **按类型取特定 guard**——这是 Protocol 的实用场景。

## 4. 三个实现：各管一段

### 4.1. `EnvFilter` — 防宿主 secrets 泄露给子进程

```
职责：为 stdio 子进程构造"最小安全环境变量"

白名单：
├─ POSIX 基础：PATH / HOME / USER / LANG / LC_ALL / TERM / SHELL / TMPDIR
├─ Windows 系统：ALLUSERSPROFILE / APPDATA / COMSPEC / ... / USERPROFILE / TEMP
└─ 前缀：XDG_*

逻辑：
    safe = {白名单键 + XDG_* 前缀}（从 os.environ 挑）
    safe.update(config 声明的 env)   ← 显式声明优先，可覆盖

结果：宿主 AWS_KEY / GITHUB_TOKEN 等 secrets 不进子进程
```

**关键点**：
- **fail-closed**：不在白名单的一律不传；
- **显式声明优先**：config 里 `env:` 段的键值**覆盖**白名单结果（用户明确要传的就传）；
- **只对 stdio 有意义**：sse/http 模式子进程不继承宿主 env，所以这个 guard 只在 `transport=stdio` 时被调用。

### 4.2. `CredentialSanitizer` — 错误信息回 LLM 前清洗

```
职责：把错误信息里的凭证替换为 [REDACTED]

正则模式：
├─ ghp_[A-Za-z0-9]{36}        ← GitHub token
├─ sk-[A-Za-z0-9]{20,}        ← OpenAI key
├─ Bearer\s+[A-Za-z0-9._\-]+  ← Bearer token
└─ token=[A-Za-z0-9]+          ← token= 形式

替换为：[REDACTED]
```

**关键点**：
- **只作用于 `sanitize_error`**——不影响 tool result 正常内容；
- **时机**：错误信息**回 LLM 前**（McpAuditMiddleware 的 except 分支调用）；
- **防什么**：工具报错时把 API key / token 打进错误信息，经 LLM 泄漏到对话 / 日志。

### 4.3. `DescriptionScanner` — 注册前检测 prompt injection

```
职责：注册工具前，扫描描述文本是否含可疑模式

检测模式（大小写不敏感）：
├─ ignore (previous|above|prior) instructions
├─ system prompt
├─ you are now
├─ forget (everything|prior|all)
└─ reveal (your|the) (instructions?|prompt)

返回：命中 → True（拒绝注册）；否则 False（放行）
```

**关键点**：
- **时机**：工具**注册前**（loader 的 `_register_tools` 调用）；
- **防什么**：恶意 MCP server 在工具描述里塞 prompt injection（"忽略之前指令"），诱导模型行为；
- **返回语义特殊**：`True` = **拒绝**（与其他接口"返处理结果"语义相反）。

## 6. 设计要点

### 6.1. 三个接口 = 三个职责，而非三个 guard

**关键认识**：`SecurityGuard` 契约有 3 个接口，但**不是让一个 guard 全实现**——而是**各 guard 只实现一个**，无关接口返原值：

```
EnvFilter:           check_env ✅   sanitize_error ❌   scan_description ❌
CredentialSanitizer: check_env ❌   sanitize_error ✅   scan_description ❌
DescriptionScanner:  check_env ❌   sanitize_error ❌   scan_description ✅
```

**为什么这么设计**：
- **可组合**：loader 可以按需装载不同 guard（如只装 `EnvFilter`，不装扫描）；
- **可扩展**：新增 guard 只实现关心的接口，不影响其他；
- **职责单一**：每个 guard 只管一件事。

### 6.2. 按顺序应用（loader 决定）

```
loader.__init__ 默认：
    guards = [EnvFilter(), DescriptionScanner()]

loader 按类型取：
    _get_env_guard()          → 找 EnvFilter 实例
    _get_description_guard()  → 找 DescriptionScanner 实例
```

**注意**：`CredentialSanitizer` **不在默认 guards 列表里**——它由 `loader._sanitizer` 单独持有，暴露给 `McpAuditMiddleware` 用（`loader.sanitizer`）。

### 6.3. 三个 guard 的"数据流"

```
config（YAML）
    └─ server.env
          └─ EnvFilter.check_env → filtered_env → 传给子进程

MCP 工具描述
    └─ DescriptionScanner.scan_description → bool → 决定注册与否

工具调用异常
    └─ CredentialSanitizer.sanitize_error → 脱敏文本 → 回 LLM + 写日志
```

## 8. 总结

> **Guards 是 MCP 的安全检查层——1 个 `SecurityGuard` 契约（3 接口）+ 3 个内置实现**：
> - **`EnvFilter`** — 连接前，白名单过滤 env（防宿主 secrets 泄露给 stdio 子进程）；
> - **`DescriptionScanner`** — 注册前，扫描工具描述（防 prompt injection）；
> - **`CredentialSanitizer`** — 错误回 LLM 前，脱敏凭证（防密钥泄漏）。
>
> **每个 guard 只实现自己关心的接口，无关接口 no-op**——这是"可组合、可扩展"的关键。**loader 按顺序应用**（默认 `[EnvFilter, DescriptionScanner]`），`CredentialSanitizer` 则由 `loader._sanitizer` 单独持有，暴露给 `McpAuditMiddleware` 用。
>
> **三个 guard 覆盖 MCP 的三个安全节点**：**连接前**（env）、**注册前**（描述）、**出错时**（错误信息）——把"防泄漏、防注入、防密钥"三件事分散到三个时机，各司其职。
