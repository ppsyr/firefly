---

name: Leader Agent 工厂 — 装配 graph（middleware / tools / prompt / checkpointer）。

description:

【整体职责】
App 层工厂：按 expert_mode 参数化装配 Leader 的 LangGraph graph。负责
- middleware：_build_middlewares 全挂 + 参数化行为差异；
- tools：get_available_tools 按 expert 选 core / core+deferred，并补充 registry 与 specialist 工具；
- system_prompt：apply_prompt_template 按 expert 与 specialist_registry 条件注入；
- checkpointer：get_checkpointer() 单例，thread_id 跨轮 + 跨模式保留 state。

【内容摘要】
- _safe_get_specialist_registry : 安全取 specialist_registry，缺失返 None。
- _build_middlewares            : 组装全部 middleware，参数化控制行为差异。
- make_lead_agent               : 主入口，装配并返回 LeaderAgent。

【职责边界】
- 只负责：装配 graph 的中间件、工具、提示词与 checkpointer。
- 不负责：middleware 的具体实现（middlewares 模块）、工具定义（agent_tools）、
  提示词内容（prompts）、模型构造（config / model_router）、runtime 装配（bootstrap）。

## 0. 结构树

### 0.1. 静态结构树

```
factory.py — Leader Agent 工厂（装配 graph）
│
├─ _safe_get_specialist_registry(registry) -> Any | None ← 安全取 specialist_registry
│   └─ 缺失返 None（不抛 CapabilityMissingError）
│
├─ _build_middlewares(expert_mode, model, context_governance, summarize_model,
│                     sandbox_provider, artifact_server, mcp_audit_middleware,
│                     skill_injection_middleware, skill_metrics_middleware,
│                     orchestration_middleware, memory_provider, memory_config,
│                     memory_worker) -> list
│   │
│   └─ 挂载顺序（固定）：
│       ├─ ① 治理层（条件）        ← build_governance_middlewares(context_governance)
│       ├─ ② SystemContextMiddleware
│       ├─ ③ SkillInjection（条件）  ← skill_injection_middleware 非空
│       ├─ ④ SkillMetrics（条件）    ← skill_metrics_middleware 非空
│       ├─ ⑤ SkillActivation（条件） ← 同 ③ 条件
│       ├─ ⑥ TitleMiddleware
│       ├─ ⑦ RunJournalMiddleware
│       ├─ ⑧ MCP Audit（条件）       ← mcp_audit_middleware 非空
│       ├─ ⑨ Sandbox（条件）         ← sandbox_provider 非空
│       ├─ ⑩ Memory（条件）          ← memory_provider 非空
│       ├─ ⑪ MemoryConsolidation（条件） ← memory_worker 非空
│       ├─ ⑫ HelpRequestMiddleware
│       ├─ ⑬ DanglingToolCallMiddleware
│       ├─    （LoopDetectionMiddleware 已移除，保留注释）
│       ├─ ⑭ ToolCallMiddleware
│       ├─ ⑮ Orchestration（条件）   ← orchestration_middleware 非空
│       ├─ ⑯ EvidenceMiddleware
│       ├─ ⑰ StallDetectionMiddleware
│       ├─ ⑱ TodoMiddleware(enforce_completion=expert_mode)
│       ├─ ⑲ ReflectionMiddleware（策略按 expert_mode 选择）
│       └─ ⑳ ReportMiddleware（model 非空，auto_synthesize=expert_mode）
│
└─ make_lead_agent(expert_mode, capability_registry, middleware_manager,
                   runnable_config, context_governance, sandbox_provider,
                   artifact_server, mcp_audit_middleware, skill_injection_middleware,
                   skill_metrics_middleware, specialist_tools, orchestration_middleware,
                   memory_provider, memory_config, memory_worker) -> LeaderAgent
    │
    ├─ ① 解析 registry
    │   ├─ runnable_config.configurable.capability_registry 优先
    │   └─ 否则用参数 capability_registry
    │   └─ registry is None → raise ValueError
    │
    ├─ ② 解析 expert_mode
    │   └─ configurable.expert_mode 优先 → resolved_expert
    │
    ├─ ③ 取模型
    │   ├─ model = registry.get_model("researcher")
    │   └─ summarize_model ← context_governance.params.summarize_model（可配名取独立模型）
    │
    ├─ ④ 组装 tools
    │   ├─ groups = ["core","deferred"]（expert）| ["core"]（default）
    │   ├─ get_available_tools(groups) → 过滤 BaseTool 去重
    │   ├─ registry.tools 额外注册工具
    │   └─ specialist_tools（delegate_to_*）
    │
    └─ ⑤ 构造 LeaderAgent
        └─ graph = create_agent(
              model=model,
              tools=tools or None,
              middleware=_build_middlewares(resolved_expert, model, ...),
              system_prompt=apply_prompt_template(
                  expert_mode=resolved_expert,
                  specialist_registry=_safe_get_specialist_registry(registry),
                  skills_enabled=skill_injection_middleware is not None),
              state_schema=ThreadState,
              checkpointer=get_checkpointer())
              │
              └─ capability_registry=registry
```

### 0.3. 运行时调用树

```
① 装配（bootstrap 阶段）
bootstrap / AppRuntime
    └─ make_lead_agent(expert_mode, capability_registry, ...)
          │
          ├─ 解析 registry（configurable 或参数）
          │     └─ None → ValueError
          ├─ 解析 expert_mode（configurable 优先）
          ├─ model = registry.get_model("researcher")
          ├─ summarize_model ← context_governance.params.summarize_model（可选）
          │
          ├─ 组装 tools
          │     ├─ get_available_tools(groups)
          │     ├─ registry.tools 补入
          │     └─ specialist_tools 补入
          │
          └─ create_agent(
                model, tools,
                middleware=_build_middlewares(...),
                system_prompt=apply_prompt_template(...),
                state_schema=ThreadState,
                checkpointer=get_checkpointer())
                    │
                    └─ LeaderAgent(graph=..., capability_registry=registry)

② _build_middlewares 内部（按序挂载）
    ├─ context_governance 非空 → build_governance_middlewares（公共3 + StrategyMiddleware）
    ├─ SystemContextMiddleware
    ├─ skill_injection 非空 → SkillInjection + SkillActivation
    ├─ skill_metrics 非空 → SkillMetrics
    ├─ TitleMiddleware / RunJournalMiddleware
    ├─ mcp_audit 非空 → MCP Audit
    ├─ sandbox_provider 非空 → SandboxMiddleware(provider, artifact_server, sandbox_root)
    ├─ memory_provider 非空 → MemoryMiddleware(...)
    ├─ memory_worker 非空 → MemoryConsolidationMiddleware(worker, trigger_n)
    ├─ HelpRequestMiddleware / DanglingToolCallMiddleware
    ├─ ToolCallMiddleware
    ├─ orchestration 非空 → OrchestrationMiddleware
    ├─ EvidenceMiddleware / StallDetectionMiddleware
    ├─ TodoMiddleware(enforce_completion=expert_mode)
    ├─ ReflectionMiddleware(strategy 按 expert_mode, llm=model)
    └─ model 非空 → ReportMiddleware(model, auto_synthesize=expert_mode)

③ system_prompt 组装
apply_prompt_template(expert_mode, specialist_registry, skills_enabled)
    ├─ specialist_registry 非空 → 注入 <specialist_routing> 段
    │     └─ 缺失 → 不注入（保护 prompt caching）
    └─ skills_enabled → 条件注入技能相关段

④ 运行期（图执行）
graph.invoke / astream
    ├─ middleware 按挂载顺序介入 before_model / after_model / wrap_tool_call
    ├─ model = registry.get_model("researcher") 被调用
    └─ checkpointer 按 thread_id 存取 state（跨轮 + 跨模式）
```

### 0.4. 补充

**`factory.py` 是 Leader Agent 的装配中心——按 expert_mode 参数化组装 middleware、tools、prompt、checkpointer，最终产出可直接运行的 LeaderAgent graph。**

几条主线：

- **"全挂 + 参数化"是核心设计**：default 与 expert 挂**同一批中间件**，差异只靠参数控制（Todo 是否强制完成、Reflection 用哪种策略、Report 是否自动合成）——而不是"模式不同挂不同中间件"。
- **挂载顺序固定且有意**：治理层 → 上下文 → 技能 → 标题/日志 → MCP/Sandbox → Memory → HelpRequest/Dangling → ToolCall → Orchestration → Evidence/Stall/Todo/Reflection/Report。顺序影响中间件介入时机，注释里对 Memory 的位置（"Sandbox 后、HelpRequest 前"）有明确说明。
- **LoopDetection 被显式移除**：注释说明"用户要求取消循环上限约束"，保留 import 与恢复说明——这是一个有意的变更。
- **registry 是装配前提**：`capability_registry` 必填（从 `configurable` 或参数取），且 `registry.get_model("researcher")` 提供模型——这印证了你之前学的 `CapabilityRegistry` 是"运行期能力总容器"。
- **expert_mode 双来源**：`runnable_config.configurable.expert_mode` 优先于函数参数——支持运行时透传覆盖。
- **summarize_model 可独立**：从 `context_governance.params.summarize_model` 配名取独立模型，否则回退 research model（None 表示复用）。
- **tools 三层合并**：`get_available_tools(groups)`（按模式选组）+ `registry.tools`（额外注册）+ `specialist_tools`（multiagent 的 delegate_to_*），去重后注入。
- **specialist_registry 条件注入**：`_safe_get_specialist_registry` 缺失返 None，`apply_prompt_template` 据此决定是否注入 `<specialist_routing>` 段——**缺失时不注入以保护 prompt caching**（Bug B 修复点）。
- **checkpointer 复用**：`get_checkpointer()` 单例，`thread_id` 跨轮 + 跨模式保留 state——这正是 CLI 里"模式切换不丢上下文"的底层依据。
