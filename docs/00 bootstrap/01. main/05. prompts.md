---

name: Leader 提示词模板 — 按 expert_mode / specialist / skills 条件拼装 system prompt。

description:

【整体职责】
从 PromptManager 加载各段 .md 提示词，按 expert_mode 与启用状态条件拼装为 Leader 的
system prompt。expert 模式追加深度研究策略段；specialist 启用时注入 routing 段；
skills 启用时注入 Skill-First Principle 段。条件注入均以"空则不注入"保护 prompt caching。

【内容摘要】
- _build_specialist_routing_section : 条件构造 <specialist_routing> 段。
- apply_prompt_template             : 主入口，按条件拼装 system prompt。

【职责边界】
- 只负责：加载提示词段、按条件拼装 system prompt。
- 不负责：提示词文件的内容（prompts/system/leader/*.md）、提示词的加载与渲染机制
  （prompts/manager）、specialist / skill 的实现（multiagent / skill 模块）。

【INVARIANT】
- 拼装顺序固定：identity → constraints → decision_guidance →（expert）mode_expert
  →（条件）specialist_routing →（条件）skill_first_principle。
- 条件注入保护 caching：specialist_routing 仅在 specialist_registry 非空且有 specialist 时注入；
  skill_first_principle 仅在 skills_enabled 时注入；不满足则不注入（system prompt 不变）。
- 基础三段必含：identity / constraints / decision_guidance 始终拼装。
- mode 枚举已废弃：改用 expert_mode: bool 参数化。
- 异常容错：specialist 列表获取失败视为空，不注入 routing 段。

## 0. 结构树

### 0.1. 静态结构树

```
leader/prompts.py — Leader 提示词模板（按条件拼装 system prompt）
│
├─ _build_specialist_routing_section(specialist_registry) -> str ← 条件构造 routing 段
│   ├─ registry is None → ""                     ← 空串（不注入）
│   ├─ list_specialists() 异常 → ""              ← 容错
│   ├─ specialists 为空 → ""                     ← 不注入（保护 caching）
│   └─ 非空 → 构造 <specialist_routing> 段
│       ├─ 逐 specialist 一行："- delegate_to_{name}: ..."
│       ├─ 追加 "- delegate_to_subagent: ..."
│       └─ 附 Delegation Principles + When NOT to delegate
│
└─ apply_prompt_template(expert_mode, *, specialist_registry,
                         skills_enabled, **context) -> str ← 主入口
    │
    ├─ pm = get_prompt_manager()                 ← 单例
    │
    ├─ 基础三段（必含）
    │   ├─ pm.load("leader", "identity")
    │   ├─ pm.load("leader", "constraints")
    │   └─ pm.load("leader", "decision_guidance")
    │
    ├─ if expert_mode → pm.load("leader", "mode_expert")     ← 追加深度研究策略
    │
    ├─ routing_section = _build_specialist_routing_section(specialist_registry)
    │   └─ 非空 → parts.append(routing_section)              ← 条件注入
    │
    ├─ if skills_enabled → pm.load("leader", "skill_first_principle") ← 条件注入
    │
    └─ return "\n\n".join(parts)                ← 段间双换行拼接
```

### 0.4. 补充

**`leader/prompts.py` 是 Leader 提示词的 accessor 层——从 PromptManager 加载各段 .md，按 expert_mode / specialist / skills 三条件拼装为 system prompt。**

几条主线：

- **它是 `prompts/manager.py` 的第一个实际消费者**：`pm.load("leader", name)` 正是你之前学的 manager 接口——这里能看到"mid-level accessor"如何调用 low-level manager。
- **基础三段必含**：`identity` + `constraints` + `decision_guidance` 永远拼装，构成 system prompt 骨架。
- **三个条件段**：
  - `mode_expert`——仅 `expert_mode=True`（追加深度研究策略）；
  - `specialist_routing`——仅 `specialist_registry` 非空且有 specialist（Bug B 修复）；
  - `skill_first_principle`——仅 `skills_enabled=True`（F2 改造）。
- **条件注入的动因是"保护 prompt caching"**：注释反复强调"空时不注入，system prompt 不变"——因为 system prompt 变化会破坏 LLM 的 prompt cache，增加成本与延迟。
- **routing 段是动态构造的（非 .md 文件）**：`_build_specialist_routing_section` 按当前 specialist 列表**运行时生成**文本（含 `delegate_to_<name>` 工具名），而非从文件加载——这是唯一"代码内嵌提示词"的段。
- **容错设计**：`list_specialists()` 异常视为空；`specialist_registry is None` 视为空——保证 routing 段不会导致装配失败。
- **与 factory 的接口**：`make_lead_agent` 里 `_safe_get_specialist_registry(registry)` 与 `skill_injection_middleware is not None` 正是本文件两个条件参数的来源——两者在 factory 里取值、在本文件里使用，构成"装配 → 拼装"的衔接。
- **`**context` 预留未用**：签名保留 `**context` 以兼容未来扩展，当前实现不消费。
