---

name: app/bootstrap.py — 应用启动与运行时装配。

description: 

【整体职责】
Poirot 应用层的启动入口：加载配置、构造 LLM、装配工具（builtin / MCP / sandbox /
skill）、装配 multiagent、构造 CapabilityRegistry 与 LeaderAgent，产出 AppRuntime。
同时提供运行时热切换能力（expert 模式 / MCP 工具 / model），全部保持不可变语义。

【内容摘要】
- _PROJECT_ROOT / _CST                    : 项目根路径 + 中国时区常量。
- _resolve_relative_paths()               : 把 config 里相对路径锚定到项目根。
- _make_thread_id()                       : 生成 thread ID。
- _build_chat_model()                     : 按 provider 构造 chat model。
- _check_node_available()                 : 检测 npx 是否可用（MCP 前置条件）。
- AppRuntime                              : 运行时容器（config + registry + leader + setup）。
- AppRuntime.run_question()               : 执行一次提问。
- AppRuntime.switch_expert_mode()         : 热切换 expert 模式（保留 thread）。
- AppRuntime.reload_mcp_tools()           : MCP 工具变更后重建 Leader。
- AppRuntime.switch_model()               : 热切换 LLM provider/model。
- _load_sandbox_provider()                : 反射加载 sandbox provider。
- _load_memory_provider()                 : 反射加载 memory provider。
- _build_path_mappings()                  : 从 config 构造 PathMapping 列表。
- _build_evolution_manager()              : 装配 skill 自进化管理器（Layer 2a）。
- _build_eval_layer()                     : 装配 skill L3 评估层。
- bootstrap_runtime()                     : ★ 应用启动主入口。

【职责边界】
- 只负责：配置加载、组件装配、运行时容器构造、热切换。
- 不负责：Agent 内部逻辑（leader / middleware 负责）、具体工具实现（各模块负责）、
  CLI 交互（app/cli 负责）。
- 不持有可变状态：AppRuntime 用 replace 语义重建，不原地修改。

### 0.1. 静态结构树


### 0.2. 运行时调用树（bootstrap_runtime 内部）

```
bootstrap_runtime(expert_mode, provider, model, cli_overrides)
│
├─ ① config = load_config(...)
│   └─ logs_root 相对 → 锚定 _PROJECT_ROOT
│   └─ _resolve_relative_paths(config)
│
├─ ② thread journal
│   ├─ thread_id = _make_thread_id()
│   ├─ thread_dir = logs_root/threads/<thread_id>
│   └─ thread_journal.append("thread.started", ...)
│
├─ ③ LLM 构造
│   ├─ router = ModelRouter()
│   ├─ provider 非空 → router.build_single(provider, model)
│   └─ provider 为空 → router.build_model("researcher")
│                     + router.build_model("reporter")
│
├─ ④ builtin 工具
│   └─ get_available_tools(groups=["core"])
│       → tools["ddg_search"] / tools["read_snapshot"] ...
│
├─ ⑤ MCP 工具（_check_node_available）
│   ├─ build_mcp_manager()
│   ├─ load_startup()（兼容 running loop）
│   ├─ get_tools(["core", "deferred"])
│   ├─ select_search_tool → tools["web_search_mcp"]
│   ├─ get_audit_middleware → mcp_audit_middleware
│   └─ 注入 tool_metadata 到 config.context_governance.params
│
├─ ⑥ sandbox
│   ├─ _load_sandbox_provider(config)
│   │   └─ 非 None 时继续
│   ├─ make_sandbox_tools(provider, allow_host_bash)
│   ├─ register_sandbox_shutdown(provider)   ← atexit 收尾
│   └─ ArtifactServer().start()
│
├─ ⑦ skill
│   ├─ build_skill_manager()
│   │   └─ 非 None 时继续
│   ├─ load_startup(llm=researcher_model)
│   ├─ get_injection_middleware / get_metrics_middleware
│   ├─ evolve_enabled → _build_evolution_manager(...)
│   └─ eval_config.enabled → _build_eval_layer(...)
│
├─ ⑧ multiagent
│   ├─ ma_config = load_multiagent_config()
│   ├─ 定义 _subagent_factory（闭包捕获 registry / config / sandbox_provider /
│   │                      各 middleware；leaf-role：specialist_tools=None）
│   └─ ma_setup = setup_multiagent(ma_config, agent_factory=_subagent_factory)
│       ├─ enabled=false → _EMPTY_SETUP
│       └─ enabled=true → 反射加载 specialist + 凭证检测 + metrics + middleware + tools
│
├─ ⑨ memory
│   ├─ set_memory_config(config.memory)      ← 同步到全局单例
│   ├─ memory_provider = _load_memory_provider(config)
│   └─ memory_provider 非 None → start_memory_worker(...)
│                              + atexit.register(shutdown_memory_worker)
│
├─ ⑩ registry = CapabilityRegistry(
│       models={researcher, reporter},
│       tools=all_tools,
│       reporter=MarkdownReporter(),
│       artifact_store=LocalArtifactStore(),
│       sandbox_provider=sandbox_provider,
│       skill_store=skill_manager.store if skill_manager else None,
│       specialist_registry=ma_setup.specialist_registry,
│       subagent_provider=ma_setup.subagent_provider,
│       memory_provider=memory_provider,
│   )
│
├─ ⑪ leader_agent = make_lead_agent(
│       expert_mode=expert_mode,
│       capability_registry=registry,
│       context_governance=config.context_governance,
│       sandbox_provider=sandbox_provider,
│       artifact_server=artifact_server,
│       mcp_audit_middleware=mcp_audit_middleware,
│       skill_injection_middleware=skill_injection_middleware,
│       skill_metrics_middleware=skill_metrics_middleware,
│       specialist_tools=list(ma_setup.specialist_tools) if ma_setup.specialist_tools else None,
│       orchestration_middleware=ma_setup.orchestration_middleware,
│       memory_provider=memory_provider,
│       memory_config=config.memory,
│       memory_worker=memory_worker,
│   )
│   └─ thread_journal.append("agent.constructed", ...)
│
└─ ⑫ return AppRuntime(config, registry, run_manager, ..., leader_agent, ...)
```

### 0.3. multiagent 在 bootstrap_runtime 里的位置（聚焦）

```
bootstrap_runtime
    ...
    │
    ├─ ⑦ skill 装配完成后
    │
    ├─ ⑧ multiagent 装配
    │   │
    │   ├─ ma_config = load_multiagent_config()    ← multiagent/config.py
    │   │
    │   ├─ def _subagent_factory():                ← 闭包捕获 registry / config / ...
    │   │   └─ make_lead_agent(
    │   │         specialist_tools=None,           ← leaf 不能再 delegate
    │   │         orchestration_middleware=None,   ← leaf 不挂 OrchestrationMiddleware
    │   │         ...（复用 Lead 的全部其他装配）
    │   │     )
    │   │
    │   └─ ma_setup = setup_multiagent(            ← multiagent/bootstrap.py
    │         ma_config,
    │         agent_factory=_subagent_factory,
    │     )
    │     ├─ enabled=false → _EMPTY_SETUP
    │     └─ enabled=true → 逐个 _load_specialist(...)
    │         ├─ pi：PiInstaller + PiCredentialProvider
    │         ├─ codex：CodexCredentialProvider
    │         ├─ claude：ClaudeCredentialProvider
    │         └─ subagent：SubagentRuntime(agent_factory)
    │         → registry.register + make_specialist_tool
    │
    ├─ ⑨ memory 装配
    │
    ├─ ⑩ CapabilityRegistry 构造
    │   └─ 注入 ma_setup.specialist_registry / ma_setup.subagent_provider
    │
    └─ ⑪ make_lead_agent 构造
        ├─ 注入 ma_setup.specialist_tools      ← 工具进 Leader
        └─ 注入 ma_setup.orchestration_middleware  ← 中间件挂 Leader
```

**关键点**：`bootstrap_runtime` 是**装配期的最顶层**——`app.bootstrap` 调它，它调 `setup_multiagent`，`setup_multiagent` 调 `_load_specialist`。

### 0.4. 补充

**`app/bootstrap.py` 是应用的"装配总入口"——从 config 到 AppRuntime，串起 LLM / 工具 / 沙箱 / 技能 / multiagent / 记忆六大子系统。**

几点补充：

- **装配顺序固定且有依赖**：`config → journal → LLM → tools → sandbox → skill → multiagent → memory → registry → leader`。**后装配的组件可以引用先装配的**（如 multiagent 的 `_subagent_factory` 闭包捕获 registry）。
- **`_subagent_factory` 是 multiagent 接入的关键**：它定义一个"leaf-role lead agent"的工厂——**复用 Lead 的全部装配逻辑，但 `specialist_tools=None` + `orchestration_middleware=None`**，从工具层面杜绝无限递归。
- **三个 `switch_*` 方法保持不可变语义**：都返回新 `AppRuntime`，不原地修改。**checkpointer state 跨重建连续**——thread 不丢。
- **`switch_expert_mode` 必须传 `context_governance`**：否则治理层中间件不挂，budget / 压缩全部失效。**这是一个已知易错点，注释里特别强调。**
- **MCP 加载兼容 running event loop**：检测到 `asyncio.get_running_loop()` 成功时，用线程池跑 `asyncio.run(mcp_manager.load_startup())`。**避免在已运行的 loop 里再调 `asyncio.run` 报错。**
- **所有可选组件失败都记 journal 不抛异常**：MCP / sandbox / skill / multiagent / memory 装配失败时只 `thread_journal.append("xxx.load_failed", ...)`，不中断启动。**只有 LLM 构造失败会抛异常。**
- **`AppRuntime` 是 dataclass 而非 frozen**：三个 `switch_*` 返回新实例，但 dataclass 本身不是 frozen。**这是"不可变语义"靠约定而非类型强制。**
- **`bootstrap_runtime` 是"装配期"的最顶层入口**：在追踪 multiagent 全流程时，这里是起点——**从这里往下，依次是 `setup_multiagent` → `_load_specialist` → `registry.register` → `make_specialist_tool`。**
