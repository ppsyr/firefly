---

name: Leader Agent — 薄壳（调 graph + 收报告 + 存 artifact）。

description: 

【整体职责】
LeaderAgent 是编译后 graph 的薄壳：负责构造初始 state 与 graph config、调用
graph.ainvoke()、按 expert_mode 收集最终报告、按配置保存 artifact，并返回统一的
AgentRunResult。ReAct 智能（多轮决策、工具调用、退出逻辑）都在 graph 内部由
create_agent + AgentMiddleware 实现，本类不承载。所有日志由 graph 内的
RunJournalMiddleware 处理。

【内容摘要】
- _last_ai_message            : 取 state.messages 最后一条 AIMessage 文本（default 输出）。
- _resolve_actual_model_name  : 取实际 researcher 模型的 provider 名（FallbackChatModel.provider_names）。
- AgentRunResult              : 运行结果数据结构（frozen）。
- LeaderAgent                 : 薄壳类，run() 驱动一次研究。
- LeaderAgent.run             : 构造 initial state + config → ainvoke → 收报告 → 存 artifact。

【职责边界】
- 只负责：initial state 构造、graph config 组装、ainvoke 驱动、报告收集、artifact 保存、
  返回 AgentRunResult。
- 不负责：ReAct 决策与工具调用（graph / middleware）、报告合成逻辑（reporter）、
  artifact 存储实现（artifact_store）、日志事件（RunJournalMiddleware）、
  运行状态推进（run_manager）、runtime 装配（bootstrap）。

## 0. 结构树

### 0.1. 静态结构树

```
agent.py — Leader Agent（薄壳：调 graph + 收报告 + 存 artifact）
│
├─ _last_ai_message(state) -> str              ← 取最后一条 AIMessage 文本（default 输出）
│   └─ 倒序遍历 messages，匹配 AIMessage，兼容 content 为 str / list
│
├─ _resolve_actual_model_name(registry) -> str ← 取实际路由 provider 名
│   ├─ FallbackChatModel.provider_names → 逗号拼接
│   ├─ 回退：_identifying_params.model
│   ├─ 回退：model.model | type(model).__name__
│   └─ 异常 → "unknown"
│
├─ AgentRunResult(frozen)                      ← 运行结果
│   ├─ run_id: str                             ← 运行 ID
│   ├─ thread_id: str                          ← 线程 ID
│   ├─ final_report: str                       ← 最终报告文本
│   ├─ events_path: str                        ← 事件文件路径
│   ├─ artifact_path: str | None               ← 产物路径（未保存为 None）
│   └─ state: dict[str, Any]                   ← graph 终态
│
└─ LeaderAgent(dataclass)                      ← 薄壳类
    ├─ graph: Any                              ← 编译后的 LangGraph graph
    ├─ capability_registry: CapabilityRegistry  ← 能力注册表
    │
    └─ run(question, run_context) -> AgentRunResult ← 驱动一次研究
        │
        ├─ ① 构造 initial state
        │   ├─ create_initial_thread_state(question)
        │   ├─ initial["research_question"] = question
        │   └─ initial["metadata"] = {"expert_mode": ...}
        │
        ├─ ② 组装 config
        │   ├─ configurable: expert_mode / run_id / thread_id / journal /
        │   │                output_dir / plan_enabled / timezone / model
        │   └─ recursion_limit = max_loop_steps * graph_node_multiplier
        │
        ├─ ③ 执行图
        │   └─ asyncio.run(graph.ainvoke(
        │         {messages: [HumanMessage(question)], user_input, research_question},
        │         config))
        │
        ├─ ④ 按模式收报告
        │   ├─ expert:
        │   │   ├─ final_report ← final_state["final_report"]（ReportMiddleware 已写）
        │   │   ├─ 为空 → get_reporter().generate_report(final_state, run_context)
        │   │   └─ save_artifact 为真 → get_artifact_store().save_artifact(...)
        │   │         └─ journal.append("report.generated", {...})
        │   │         └─ artifact_path ← artifact.path
        │   └─ default:
        │       ├─ final_report ← _last_ai_message(final_state)
        │       └─ 不保存 artifact（靠 /report 触发）
        │
        └─ ⑤ return AgentRunResult(run_id, thread_id, final_report,
                                    events_path, artifact_path, state)
```

### 0.2. 运行时调用树

```
① 上层调用（CLI run 模式 / 其他消费者）
调用方
    └─ runtime.run_question(...)          ← AppRuntime 封装
          └─ LeaderAgent.run(question, run_context)
                │
                ├─ create_initial_thread_state(question)
                │     └─ 返回 ThreadState 初始值
                ├─ 组装 config（configurable + recursion_limit）
                │     └─ _resolve_actual_model_name(capability_registry)
                │           └─ registry.get_model("researcher") → provider_names
                │
                ├─ asyncio.run(graph.ainvoke(payload, config))
                │     │
                │     ├─ LangGraph 跑图（内部）：
                │     │     ├─ middleware 按挂载顺序介入
                │     │     ├─ model 调用（FallbackChatModel → ChatDeepSeek 等）
                │     │     ├─ 工具调用（ReAct 循环）
                │     │     ├─ RunJournalMiddleware 记录事件
                │     │     └─ ReportMiddleware（expert）写 final_report
                │     │
                │     └─ 返回 final_state
                │
                ├─ expert 分支
                │     ├─ final_report = final_state.get("final_report")
                │     ├─ 为空 → capability_registry.get_reporter().generate_report(...)
                │     ├─ save_artifact 为真：
                │     │     ├─ capability_registry.get_artifact_store().save_artifact(...)
                │     │     └─ run_context.journal.append("report.generated", {...})
                │     └─ artifact_path = artifact.path
                │
                ├─ default 分支
                │     └─ final_report = _last_ai_message(final_state)
                │
                └─ return AgentRunResult(...)

② 下游协作
LeaderAgent.run
├─ runtime/checkpointer        ← graph 内部按 thread_id 存取 state
├─ middleware 链               ← graph 内部（evidence / todo / reflection / report ...）
├─ CapabilityRegistry          ← get_model / get_reporter / get_artifact_store
├─ RunJournal                  ← journal.append("report.generated", ...)
└─ ArtifactStore               ← save_artifact（expert 模式）
```

### 0.3. 补充

**`agent.py` 是 Leader 的执行薄壳——它不承载智能，只负责"造 state、组 config、驱动 graph、收报告、存 artifact"。ReAct 决策与工具循环全部在 graph 内部由 `create_agent` + 中间件完成。**

几条主线：

- **薄壳定位明确**：类 docstring 直说"ReAct intelligence lives inside the graph"——本类只做 `graph.ainvoke()` + reporter + artifact + config wiring，日志由 `RunJournalMiddleware` 在图内处理。
- **必须异步驱动**：`asyncio.run(graph.ainvoke(...))`——注释说明 MCP 工具是 async-only `StructuredTool`，图须以 async 模式运行。
- **两种模式的收报告策略**：
  - **expert**：优先用 `final_report` 字段（`ReportMiddleware` 已写）；为空回退 `reporter.generate_report`；按配置保存 artifact + 记 `report.generated` 事件。
  - **default**：不自动报告，取最后一条 `AIMessage`，不保存 artifact（靠 CLI 的 `/report` 触发）。
- **`_resolve_actual_model_name` 是关键**：它从 `FallbackChatModel.provider_names` 取**实际路由链**，而非 config 静态 `researcher_model`（默认是 `fake-researcher`）——这就是 CLI 状态栏显示真实模型名的来源。
- **`recursion_limit` 由 config 推导**：`max_loop_steps * graph_node_multiplier`，不硬编码；注释明确"安全网是 `StallDetectionMiddleware`"——即放弃循环上限，改用停滞检测兜底。
- **两条 CLI 路径的汇合点**：
  - `run` 模式（`main.py` 的 `runtime.run_question`）→ **直接走 `LeaderAgent.run`（本文件）**。
  - 默认/`cli` 模式的流式研究 → 走 `PoirotStreamClient.stream`（**不经过本文件的 run()**，而是直接驱动 graph）。
  这两条路径都最终驱动同一个 graph，但收报告的方式不同：前者用 `run()`（一次性 ainvoke），后者用流式事件渲染。
- **`AgentRunResult` 是契约**：frozen，含 run_id / thread_id / final_report / events_path / artifact_path / state——`main.py` 的 `run` 模式打印的四个字段（final_report / run_id / events_jsonl / final_report_md）正来自它。
- **`state` 回传全量终态**：便于上层进一步消费（如 `generate_report_from_thread` 从 checkpointer 取 state，与此可对照）。

**一个关键对照**：`main.py` 的 `run` 模式走 `runtime.run_question` → **本文件的 `LeaderAgent.run`**；而交互模式的流式研究走 `PoirotStreamClient`（`app/services/stream_service.py`）**直接驱动 graph**，不经本文件的 `run()`。也就是说——**本文件是"非流式一次性运行"的收口，流式路径的收口在 `stream_service.py`**。这两个文件构成"同一 graph 的两种驱动方式"，是下一步值得对照读的一对。
