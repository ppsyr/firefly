---

name: PoirotStreamClient — 流式研究服务（仿 deer-flow DeerFlowClient.stream）。

description:

【整体职责】
"把图执行过程实时翻译成事件流"的适配器——它让 CLI 能边跑边显示，而不是等整个研究跑完再一次性输出。
用 graph.astream(stream_mode=["values", "messages", "custom"]) 消费 LangGraph 原生流，
把 token 级 delta（messages）、完整状态快照（values）、自定义事件（custom）标准化为
StreamEvent 供 CLI 渲染。流式消费归本 service，不在 LeaderAgent 内（LeaderAgent 只管 run()）。

【内容摘要】
- _StreamEventBase    : 流式事件标准化结构。
- StreamEvent         : 事件类型 + 可选 budget 字段。
- _extract_text       : 从 message content 提取纯文本（兼容 str / list[dict]）。
- _extract_reasoning  : 提取 reasoning_content delta（thinking token）。
- _truncate           : 截断文本。
- _is_skills_selector_output : 检测 SkillSelector 的 JSON 输出。
- _strip_skills_leak  : 渲染层兜底，剥离残留的 SkillSelector JSON。
- PoirotStreamClient  : 流式客户端，stream(question) 产出 StreamEvent。

【职责边界】
- 只负责：消费 graph.astream、标准化 StreamEvent、跨模式去重、done/error 检测。
- 不负责：渲染（stream_handler）、图执行与决策（leader/agent + middleware）、
  run 生命周期（run_manager）、budget 的展示（status_bar）。

## 0. 结构树

### 0.1. 静态结构树

```
stream_service.py — PoirotStreamClient（流式研究服务）
│
├─ _StreamEventBase(TypedDict)                ← 流式事件标准化结构
│   ├─ type: str                               ← 事件类型（thinking/answer/tool_start/...）
│   ├─ content: str                            ← 文本内容
│   ├─ tool_name / tool_args / tool_result     ← 工具相关字段
│   └─ msg_id: str | None                      ← 消息 ID
│
├─ StreamEvent(_StreamEventBase, total=False) ← 事件类型 + 可选 budget
│   └─ budget: dict | None                     ← budget_update 事件的预算快照
│
├─ 【工具函数】
│   ├─ _extract_text(content) -> str           ← 提取纯文本（兼容 str / list[dict]）
│   ├─ _extract_reasoning(chunk) -> str        ← 提取 reasoning_content（thinking）
│   ├─ _truncate(text, limit=200) -> str       ← 截断文本
│   ├─ _is_skills_selector_output(text) -> bool ← 检测 SkillSelector JSON 输出
│   └─ _strip_skills_leak(text) -> str         ← 剥离残留的 selector JSON（渲染层兜底）
│
└─ PoirotStreamClient                         ← 流式客户端
    ├─ __init__(graph, config)                ← 绑定 graph 与 config
    │   ├─ _graph: Any
    │   └─ _config: dict
    │
    └─ stream(question) -> AsyncIterator[StreamEvent] ← 流式产出事件
        │
        ├─ 初始化
        │   ├─ state = {messages: [HumanMessage(question)], user_input, research_question}
        │   └─ 去重集合：seen_ids / streamed_ids / seen_tool_call_ids /
        │               _internal_answer_ids / _answer_buffers / _answer_safe
        │   └─ first_values_frame = True
        │
        ├─ async for (mode, chunk) in graph.astream(stream_mode=["values","messages","custom"])
        │   │
        │   ├─ 【mode == "custom"】            ← middleware 用 get_stream_writer() 发的事件
        │   │   └─ yield StreamEvent(type=chunk["type"], ...)
        │   │
        │   ├─ 【mode == "messages"】           ← token 级 delta
        │   │   ├─ 过滤 internal_llm tag（summarizer/reporter/reflection/selector）
        │   │   ├─ AIMessageChunk / AIMessage：
        │   │   │   ├─ reasoning_content → yield thinking
        │   │   │   ├─ content delta → selector 缓冲检测 → yield answer
        │   │   │   └─ tool_calls → 按 id 去重 → yield tool_start
        │   │   └─ ToolMessage → yield tool_end
        │   │
        │   └─ 【mode == "values"】             ← 完整状态快照
        │       ├─ budget_update（过滤全零快照）→ yield
        │       ├─ sandbox_update → yield
        │       ├─ 首帧预填 seen_ids（checkpoint 恢复的旧消息）
        │       ├─ 逐消息去重（seen_ids / streamed_ids）
        │       └─ 未流式输出的消息（非 streaming 模型）→ yield answer/tool_start/tool_end
        │
        ├─ flush 残留 answer buffer（selector 检测未决）
        │   └─ yield answer（跳过 selector 与已 streamed）
        │
        └─ yield done（astream 结束信号）
```

### 0.2. 三模式消费视图

```
stream_mode             输入形态                   产出事件
──────────────────────────────────────────────────────────────────────────
"custom"               dict（含 "type"）          按 chunk["type"] 直出
                       （middleware 自造）        如 compaction_start/progress/end

"messages"             (message_chunk, metadata)  thinking（reasoning_content）
                       token 级 delta              answer（content delta，selector 缓冲）
                                                   tool_start（tool_calls）
                                                   tool_end（ToolMessage）

"values"               完整 state 快照             budget_update（governance.default.budget）
                                                   sandbox_update（state.sandbox）
                                                   answer/tool_start/tool_end（未流式消息）
```

```
          │

          │     │
          │     ├─ custom 事件 → yield StreamEvent（直接透传）
          │     ├─ messages 事件：
          │     │     ├─ internal_llm tag？ → 跳过
          │     │     ├─ reasoning_content → yield thinking
          │     │     ├─ content delta → selector 缓冲 → yield answer
          │     │     ├─ tool_calls → 去重 → yield tool_start
          │     │     └─ ToolMessage → yield tool_end
          │     └─ values 事件：
          │           ├─ budget → yield budget_update
          │           ├─ sandbox → yield sandbox_update

          │           └─ 未流式消息 → yield answer/tool_start/tool_end
          │
          ├─ flush 残留 buffer → yield answer（若有）
          └─ yield done
          
          │
          ▼
    renderer.render(event)         ← stream_handler（消费端）

    ├─ thinking → _render_thinking
    ├─ answer → _render_answer
    ├─ tool_start → _render_tool_start
    ├─ tool_end → _render_tool_end
    ├─ done → _render_done
    ├─ budget_update → _update_budget → cli_state
    └─ compaction_* → _render_compaction_*
```

### 0.4. 补充

**`stream_service.py` 是"图执行 → CLI 渲染"之间的翻译层——用 `graph.astream` 实时消费 LangGraph 的三模式流，去重、过滤、归一化为统一 `StreamEvent`。**

几条主线：

- **三模式消费**：`values`（状态快照）/ `messages`（token delta）/ `custom`（中间件自造事件）——各模式产出不同事件类型，最终统一为 `StreamEvent`。
- **跨模式去重**：`seen_ids` / `streamed_ids` / `seen_tool_call_ids` 三套集合解决"同一内容从多模式/多 chunk 重复出现"的问题。
- **首帧预填**：`first_values_frame` 跳过首帧含 checkpointer 恢复的旧 messages，防重复输出。
- **内部 LLM 过滤**：`metadata.tags` 含 `internal_llm` 的 chunk 跳过——summarizer / reporter / reflection / skill-selector 的输出不能泄漏到 CLI。
- **selector 输出拦截**：按 msg_id 累积缓冲（`_answer_buffers`），命中 `_is_skills_selector_output` 则丢弃；非 `{`/`` ` `` 开头或超 200 字符则确认非 selector 并 flush。
- **零值 budget 过滤**：`window == 0` 是 init_budget 独有签名，跳过以防 UI 占用率视觉闪烁。
- **done 靠结束信号**：LangGraph 无精确 done 事件，靠 `astream` 结束后 yield `done`。
- **两条驱动路径的对照**：`LeaderAgent.run()`（`ainvoke` 阻塞式）vs `PoirotStreamClient.stream()`（`astream` 流式）——**同一 graph 的两种消费姿势**。
- **与 `stream_handler` 的分工**：本模块负责"翻译 + 去重 + 过滤"（数据层），`StreamRenderer` 负责"渲染"（表现层）——一个管数据、一个管显示。
- **与 `runner` 的解耦**：流式消费不在 `LeaderAgent` 里，作为独立 service——让同一 graph 可被不同方式消费。
